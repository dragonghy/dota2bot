### 0b. 复发类别:「作者写的 desire ≠ 引擎看到的 desire」

#31 与上一轮的 #29 是**同一类缺陷的第二例**(#29 是 guard 链先命中先 return
把强 guard 永久遮蔽;#31 是下游 cap 把出价砍到设计意图之下)。两次都是
**作者在注释里推理的相对出价顺序,被一个下游变换悄悄摧毁**,而且两次都因为
"测试只测了 helper/触发,没测最终出价"而存活。**今后任何在注释里论证
"这个值要压过 X"的分支,验收必须断言最终出价(过完所有变换),不是 helper
返回值。** #31 的 `tests/test_lanekill_bid_reachable.lua` 是这类断言的模板。

**[2026-08-19T13:2xZ 总监扩写]** 这条规矩现在有**五例**,而且更一般的形式已经
浮现:**「helper 的推理被消费方的机制悄悄作废」**。出价只是被作废的东西之一。

| # | id | helper 推理的东西 | 消费方怎么作废它 |
|---|---|---|---|
| #29 | `tpwatch`/`pushguard` | 「我出 0.92 会赢」 | guard 链先命中先 return,根本没求值到它 |
| #31 | `l1trade`/`l5combo` | 「我出 0.92 压过 0.75」 | 下游 `CapForLanePush` 砍到 0.72(**低于** 0.75) |
| #32 | `capmono` | 「悬崖只影响过线的」 | 悬崖让有效出价对血量**非单调**,峰值在最不该打的 46% 血 |
| #34 | `cmrguard` | 「他有硬控,危险」 | 布尔包装丢掉 handle → **没做距离检查**,1326 码外照样否决 |
| **#37** | **`lf_rescue`** | **「他能活过 ~4s(3s 读条 + 一步)」** | **落点由 `GetNearbyLocationToTp` 定 = 最近的塔;「一步」实测中位 2289u ≈ 8 秒** |

**验收的通用形状因此是:断言这个决定在世界里的最终后果,不是 helper 的返回值。**
出价类 → 断言过完所有变换的最终 desire(#31 模板);
**动作类 → 断言动作真的达成了 helper 假设的那个状态**(#37 的教训:该断言的是
「落点到友军的距离 / 抵达时间」,不是「门返回了一个目标」)。

**第六例的通用预防**(#37 第 4 节顺带发现,值得全组扫一遍):**写死的时间常数是
按普通模式节奏写的**。`lf_rescue` 里 `DotaTime() < 8*60` 的核心豁免,在平均
**670s(11.2 分钟)**的 Turbo 局里只覆盖前 8 分钟,等于**核心在整局最后 1/3、
也是最值钱的那段时间是放开的**。CLAUDE.md 说得很清楚优化目标是 Turbo ——
**凡是 `DotaTime() < N*60` 这种常数,都该按 Turbo 局长重新审一遍。**
