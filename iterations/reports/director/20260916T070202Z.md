## 三、RULING 63 —— 把 #523 的第二条做掉

### 3.1 缺陷的形状(不是巧合,是构造)

`owed_executions.json` 的 `done_when: {kind: path_exists, path: P}` 的**定义**就是
「**P 是下一个工作单元要造的那个文件**」。于是:

- 登记那一行的那一轮,**P 按构造不存在**;
- 而那一轮的报告**必须**引用 P(否则那一行的验收句读不出来);
- ⇒ `claim_precheck.sh` 答 `MISSING path P` + **exit 3**,而 exit 3 的文案是 **`DO NOT PUBLISH YET`**。

**它对一份完全可以发表的报告说不许发,而且是对每一份这种形状的报告。**

⛔ **「等 push 完就好了」不成立,而这一点是立案那一发自己证明的**:09-05 那轮的现场逐字是
**push 之后复跑**,findings `2 → 1`,剩下的那一条就是它。

**暴露面不是一条**:2026-09-16 的活 registry 里 `kind: path_exists`(**登记本轮那一行之前**)共 **11 行**,其中 **7 行**的产物按构造不存在
(`a_evidence_lanekill.md` / `a_evidence_campbind.md` / `a_evidence_liondrainstop.md` / `a_evidence_outlatch.md` /
`write_shutdown_intent.sh` / `wave_reachable_delta.py` / `s3_attribution_under_ruling48.md`)。
⇒ 任何一份引用它们中任意一条的报告,今天都会被判 `DO NOT PUBLISH YET`。

### 3.2 交付

**`tools/agent/citation_audit.py` 新增路径判级 `FORWARD-REF`。**
判据是**机器可读的、不依赖谁诚实**:被引用的路径**逐字等于** trunk 的
`iterations/owed_executions.json` 里某一条**活着的** `owed` 行、且该行 `done_when.kind == "path_exists"` 的
`done_when.path` ⇒ 读 `FORWARD-REF`:**打印、不计入 findings、不抬退出码**。

判级顺序:`trunk OK` → `OFF-TRUNK` → `IGNORED-BY-DESIGN` → `FORWARD-REF` → `MISSING`。

**三条护栏,全部承重**(⛔ 少任何一条,这个类就是赦免):

1. **registry 读自 trunk**(`git show <trunk>:iterations/owed_executions.json`),**永不读工作树** ——
   只存在于本容器的一行**什么都不宽恕**。这是 `ignore_rules_certifiable` 为兄弟类提供的那道保险,
   在这里**由「读 trunk」这个动作本身免费买到**。⭐ 它在真实场景里**不要价**:立案那一发本来就发生在 push 之后。
2. **只认活行、只认 `path_exists`**。退休之后产物**应该**在,缺席是真 finding;
   其余 kind(`text_absent` / `path_contains_all` / …)**都要求它们的 `path` 存在**,缺席在那里也是真 finding。
3. **打印,一条路径一行,并点名是哪一行赚到的**。
   ⛔ **静默的宽恕与正确的宽恕,退出码完全相同;只有打印分得开它们。**
