## ① GH #402 乙案落地:`OVER-BROAD` 闸 —— 一个不需要常数的判据

上轮落地了甲案(minion→拥有者显式映射),把 `immguard` 的 128 载体压回 `brewmaster`
一条;**乙案留作接力棒**,因为甲案修的是这一例,乙案挡的是下一例。本轮把它做完了。

**issue 的原始提法是「一个析取 term 超过 N 个英雄就打 `OVER-BROAD`」。我没有按这个做,
理由是宽度不是那个性质。** 决定一条 term 能不能被漏掉的是**位置覆盖,不是英雄个数**:

- 池里 **12 个**英雄有中单(pos 2)资格;把这 12 个全算作载体,**每一局的两个中单位置
  都是载体** ⇒ 那道门恒真通过 —— **12 个英雄就冻死了**。
- 而本文件的 docstring 明确承诺要放行 `abilanc` 那种「reach a dozen hero_*.lua
  consumers」的正当宽 term。

⇒ **任何能抓住前者的宽度阈值都会拒掉后者。** 换成问抽签器自己的问题就一个常数都不需要:

> **存不存在一份合法的 draft,一个载体都不含?**

这是 Hall 条件在补集上的判定:对位置集合的每个子集 S,补集里「至少能打 S 中某个位置」
的英雄数必须 ≥ `PER_POSITION * |S|`(每个位置天辉夜魇各填一个,所以是 2)。
`S = {1..5}` 顺带覆盖了「剩不到 10 个人」这个平凡情形。

**`UNDRAFTABLE` 的镜像。** 一条**没有 draft 能带上**的 term 早就大声拒发;一条
**没有 draft 能漏掉**的 term 此前静悄悄通过 —— 而那是危险的那一侧,`immguard` 就是
这么读出 `satisfied=4/4` 的。现在两端都拦:`UNDRAFTABLE` exit 1,`OVER-BROAD` exit 2
(「什么都没查」,与 `unresolved` 同一姿态)。**`OVER-BROAD` 是对推导的判决,不是对波次的**:
要么这条 id 本来就是 generic 被误判成 hero-scoped,要么消费点游走像 `minion_lib` 那样
过度展开了。两种都在这个文件里修,**永远不靠重抽种子**。

**LIMIT 是被执行的,不是被假设的。** `draft()` 有一条死胡同回退(某位置的可用英雄取空时
改从全池任取)。上面的推理成立的前提是它不触发 —— 当前池 `{1:13, 2:12, 3:12, 4:15, 5:14}`
对 10 个坑,结构上取不空。**但我没有把它写成假设**:任一位置薄到 `<= DRAFT_SLOTS`,
`draft_can_miss` 就返回 `None`,判 `UNCHECKED`、exit 2。

**落地读数(全部经 `rc.sh` 裸读,不经管道):**

| 读数 | 改前 | 改后 |
|---|---|---|
| `tests/test_carrier_terms.py` | 52 checks / 0 failed | **66 checks / 0 failed** |
| 现役 52-id 成员串 + W36 四粒种子 | `CARRIER_GATE ids=10 exit=0` | **逐字不变,`exit=0`** |

**最后一行是刻意的验收项(测试 L)**:一道从今天起就开始拒发的门,正是本文件自己警告的
「永远说不的门」,代价是批测台每波手写覆盖。**本闸对现役树零影响,它是前瞻性的。**

**变异台 12/12 CAUGHT**(`tools/agent/mutstand_carrier_minion.sh`,N1–N5 + 新增 O1–O7;
文件副本 + `sha256sum -c` 复原,退出码裸读,`baseline after restore: exit 0`)。
新增的两条是按纪律 2「检查还在、但已不可能失败」专门补的方向:

- **O2:Hall 退化成纯宽度计数**(只查全集子集)—— **这正是 issue 提的那个设计**,
  而它在「一整个位置被覆盖」的用例上活不下来。台子因此同时是乙案选型的证据。
- **O4:判决照打、退出码不动** —— 门变成注释。**一道不可能失败的检查和一道通过的检查
  长得一模一样。**

⚠️ **fingerprint 必须先扩**:原台子只探 `derive_id`,不碰 `draft_can_miss`,
**所有 O 变异体都会被报成 `INERT`** —— 一个够不到被改代码的指纹分不清空操作和改动。
这是上轮 N5 那个教训的同族,先扩指纹再加变异体。

## ② trunk 红(python)修绿:`campsel is gated by exactly one soak id`

**不是本轮引入的,也不是「上轮那条」。** 上轮报的 python 腿红是
`test_carrier_terms.py`,上轮修掉了;**本轮这条是 `test_detector_source_constants.py`,
第一次出现在自检里**,起因是 21:xxZ 落地的 `slotarb`(GH #406)。

**现场:**

```
1 FAILED: campsel is gated by exactly one soak id   (got ['campsel','slotarb'], want ['campsel'])
```

**判读:断言的名字和它量的东西不是一回事。** `campsel_domain.gate_facts()` 自己的注释
写得很清楚,它防的是 GH #207 那个形状 —— **同一个合取里的第二个 `IsSoakCandidate`**:
`A and B` 在 B 被 promote 的那天整条门冻成 FALSE,而 `check_armed_wiring.py`
仍然叫它 WIRED。但它的实现是**扫整个实参表**。而 `slotarb` 是被穿成
**第二个、独立的实参**:

```lua
return J.Site.GetClosestNeutralSpwan(hBot, tCamps,
    J.IsModeTurbo() and J.IsSoakCandidate('campsel'),
    J.IsModeTurbo() and J.IsSoakCandidate('slotarb'))
```

**两个实参是两道门,各自可以单独 arm**(wrapper 自己的头注释就是这么写的),
**不是一个合取**。于是这条红是在一棵「什么都没跟什么合取」的树上报出来的。

**修法是把检查瞄准,不是把它放宽。** 按顶层逗号切分实参、**逐实参**判合取:

- `cands` = campsel **自己那个实参**里的 id ⇒ `['campsel']`,断言原文一字不改,
  而且现在名副其实;
- 新增 `conjoined`(任一实参里 ≥2 个 id)—— #207 的保护被保留而不是被删掉;
- 新增 `sibling_cands` 棘轮 ⇒ 断言 `== ['slotarb']`。**第三个 id 出现时仍然必须被
  承认一次,在测试里、指名道姓。** 这是上轮「改名要被承认一次」的同一条。

**「放宽成『一次调用里有两个 id 也行』会把 #207 的保护删掉」—— 这是没走那条路的理由。**

**并且新检查不是空的。** 现役树上已经没有合取了,`conjoined == []` 可以被一个
**产不出非空答案**的扫描满足 ⇒ 加了**三个合成 wrapper,每次都跑**
(`gate_facts(farm_src=...)` 本来就支持注源):合取被检出、两实参不算合取、
实参内部的嵌套逗号不被切开。

**读数(裸读):** `test_detector_source_constants.py` exit 1 ⇒ **exit 0**;
新增 6 项断言全 ok(见 `/tmp/rc.Nk43cA:176-181`)。
`campsel_domain.py --selfcheck` 同一条断言 exit 0。

**`strategy-34`(`slotarb` 入集)本轮不裁**:本轮我动的是**它撞红的那个量具**,
而入集裁定的条件 (a)/(b)/(c) 是另一件事;同一轮里既改量具又用改完的量具裁自己碰过的
