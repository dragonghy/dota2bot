## 一、⭐⭐⭐ 本轮最该被读的一条:两次假阳性,而它们都长得像发现

这条腿的**危险方向不是漏报,是误报** —— 漏报只是回到今天的状态(没人举手),
**误报是把一条活着的杠杆宣布成死的**。两次都真的发生了,都在 trunk 上,都跑出了字面的结论行:

1. **兄弟 `if` 被当成支配者。** 第一版的机制 (A) 收「调用点之前、缩进不更深的任何一个门」,
   于是打出 `fieldbuy needs 'fieldregen' <- NOT ARMED`。
   `item_purchase_generic.lua:776` 是 **fieldregen 自己的采购块**,一个在 `fieldbuy` 块**开始之前
   就结束了**的兄弟 `if`。⇒ 一条**785 episodes、昨天刚判 WORKING** 的杠杆被宣布成结构性死的。
2. **负向节流被当成门。** 第二版按「行里有 `not` + 门 + `return`」认守卫,于是
   `rotscope` 与 `pulldrag` 都报成挂在 `creepthink` 下面。而
   `mode_roam_generic.lua:264-266` 那三行是
   `if not (A and pullthink) and not (B and creepthink) and Z then return end`
   —— **arm `creepthink` 只会让那个 return 更不容易发生**,即它**加宽**后面的东西。方向反了。

⇒ **修法不是把模式写得更细,是把「支配」从匹配改成判定**:把门原子钉成 false,其余原子全自由,
问**结果是否被强制**。守卫要 `forced_outcome(cond, id, True)`(不 arm 就必然 return),
进块条件要 `forced_outcome(cond, id, False)`(不 arm 就必然进不去)。
两条都由同一个小布尔求值器回答,答不出就 **None ⇒ UNRESOLVED,永不静默 False**。

📌 **可迁移的一句**:*「这一行看起来像一道门」和「不 arm 它就过不去」是两个问题,
而在 `bots/` 里它们**经常**给出相反的答案。*

## 二、机制与验证(先对已知真值,再看新读数)

两条机制,**都是现场量出来的,不是想出来的**:

- **(A) 嵌套门** —— 被调函数只在另一个 id 的门下被调用(支配式 `if` 条件,或首行早返回守卫)。
- **(B) 字段中介** —— 调用点被 `bot.<field>` 守着,而该字段**一切非 nil 赋值**都来自带门的函数。
  **这正是 `pulldrag` 的形状**,也是「有没有调用点」这类检查结构上看不见的那一种。
