## 1. 缺陷:扁平 `replays/` 会拿另一局回答你

`soak_loop.sh` 的扁平镜像键是 `replays/<TAG>.dem`,`TAG = <时分秒戳>_slot1`;
一波里**每台实例都录自己的 slot 1**,两台同一秒开局就写**同一个 key**,后 PUT 的赢。
输的那局不是缺失,而是被**完整、可 dump、看起来完全正常的另一局**顶替。

**本轮把它量了**(把 `soak/**.dem` 按 basename 分组 —— 碰撞 = 一个 basename 归属多个 run):

| | 数 |
|---|---|
| 扁平 `.dem` 键总数 | **991** |
| 名不副实的键 | **21(2.1%)**,6 个日期,含 **GH #59 立案局** |
| 其中不可离线判定的 | **0** —— 每个扁平副本的字节大小**恰好只匹配一个** `soak/` 同名件 |

`dem_inventory.py` 现在把 winner/loser 逐行打出来(零支出、可枚举,正是 #95 §4 的验收口径)。

## 4. 修法

`replays/<TAG>__<run>.dem`(`dem_claim.sh:dem_flat_key` 铸键,`soak_loop.sh` 消费):

- **后缀不是前缀** ⇒ 现存语料 glob(`replays/<日期>_<时间>*`)逐字继续可用;
- **一次修两件事**:消灭碰撞,并让扁平镜像**第一次说得出自己来自哪个 run**
  (批测台 18:13Z 的「扁平前缀说不出这局是谁的」);
- **取不到 run id 就不写镜像**、并出声 —— 回落到裸 `$TAG` 等于**静默重建**本缺陷;
  「没有镜像」是缺失证据,「撞名的镜像」是错误证据,这正是 `dem_claim.sh` 自己的教条
  (`No claim => no upload`)往上提一层;
- **历史键不动**(重命名 991 个对象是有代价的写操作,而它们已被证明可按大小离线判定)。

流程侧写进 `tools/batch_test/behavioral/README.md` 新节
「Which prefix a corpus comes from」:**按文件名取某一局一律走 `soak/<run>/`**。
