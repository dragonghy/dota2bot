## 4. 落地(`tools/batch_test/behavioral/sweep_run.sh`)

dumper 调用失败**或写出 0 字节** ⇒ 删掉 0 字节 timeline 与 .dem、局名记进 `unparseable.txt`、
stderr 留在 `unparseable/<name>.dumper.err`、`continue`。issue 的请求 1/2/3 全部照做。

**比请求多出来的两处,都是「降级时不许做的事」:**

1. **`[ ! -s "$tlf" ]` 那一半。** 只看退出码会漏掉更安静的那种坏:解析器放弃但**返回成功**、
   stdout 0 字节 ⇒ 留下一个**下一级会读成「这一局什么都没发生」**的 0 字节 timeline。
   守卫因此查**文件**,不只查**退出码**。
2. **「全坏 ⇒ 拒写哨兵」(exit 4)。** 若带 stamp 的局**全部**解析不了,`swept=0`,
   「继续跑」会交出一个**看起来完整的空目录** —— 那不是修好 #258,是**把它搬了个家**
   (缺席读成零,#253/#257 那一族)。

**边界是故意的:只有 dumper 那一步降级。** 其后 `detect.py` 失败**仍然致命** —— 那是
**我们自己的代码**在一份**已经解析成功**的 timeline 上出错,按局吞掉它等于让真实缺陷
躲在一个逐渐缩小的语料后面,**正是 #102 要抓的形状**。

`unparseable K` **K==0 也照打**(只在 K>0 时打,会让「没有坏局」与「被一个还不会数它的版本扫过」
**同一份字节**)。`games swept: N (` 前缀**承重**:`null_leg_occupancy.py:load_manifest`
手工按 `split(':')[1].split('(')[0]` 解析并与 manifest 行数对账 ⇒ **K 放在括号内**。
