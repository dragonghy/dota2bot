## 1. 主件:GH #442 第 4 条

**病因(上一轮量出来的账)**:`tests/test_item_name_census.lua` 的棘轮把 11 个站点冻结成
`'<KIND> <name> <path>:<line>'`。**行号不是被钉站点的属性,是它上方一切的属性** ——
所以文件里任何更早的编辑(一条纯注释就够)都会把 pin 推出去,让棘轮在 `bots/` 完全正确
的情况下变红。文件自己逐条记着 **08-26 → 09-02 之间 14 次重锚**,对 11 个 pin,
其中六次来自**根本没有理由读 `bots/` 的轮次**。第 1–3 条(`chain_member_census.py`)
上一轮修完;**这一条是同一处修复的第二份,也是贵的那一份**。

### 1.1 键换成内容锚

- 新键 `KIND name path @anchor`,`anchor` = 该 pin 所在行**归一化代码文本**的 32 位摘要
  (先剥注释、再折叠空白 —— 重排缩进不是重写)。
- **上方插入不动它;改这一行会动它,而那是对的** —— 一条登记争论的就是那一行代码,
  改过的行就是没人判过的行,它该落到 `NEW` 上(§2d.2 + 变异台 M5 把这半钉住)。
- 摘要用**纯 Lua 5.1 算术**(两个累加器,最大中间量 `h*131 < 2^38`,在 double 里逐步精确)。
  不用 `sha1`/不 shell out:一个悄悄丢精度的摘要会让锚**依赖机器**,而那是冻结键
  **唯一不能有**的性质。
- 行号**保留但出键**,叫 `line_last_seen`,只是「去哪儿看」;漂了就在**绿色的运行上**
  打一行 `LINE NOTE`,不改任何退出码。

### 1.2 两道冲突门都必须红

内容键买到防插入,可能**卖掉**的东西比买到的更糟:两个不同的发现塌进一个键 ⇒
**真发现被吸进旧判决、永不打印**,把误报换成漏报。所以两个方向都是硬失败:

- (a) **两条登记行同键**(表自己坏了)⇒ `AMBIGUOUS ANCHOR … judged row written twice`;
- (b) **两条活的发现同键**(同一文件里同一条归一化行出现两次)⇒ `… two findings, one key`。

⛔ 为此登记表从 **dict 字面量改成行列表**:Lua 的 dict 字面量遇到重复键会
**留下最后一个、什么都不说** —— 那正是内容键要防的「静默吸收」**从正门走进来**的样子。
(与上一轮 `chain_member_census.py` 的同一条推理,同一个理由,不同的语言。)

### 1.3 重锚援助 `ITEM_CENSUS_ANCHORS=1`

内容键**唯一诚实的代价**是人眼算不出摘要。所以当某个 pin 的行真被重写时,修复不能是
「猜摘要」:`ITEM_CENSUS_ANCHORS=1 lua5.1 tests/run_tests.lua item_name_census`
把每条活发现打成**可直接粘贴的行**。只报告、不改文件、不动退出码。
本轮实测打出 11 条,与表里 11 条逐字一致。

### 1.4 变异台(七格,`tools/agent/mutstand_item_census_key.sh`)

每格从**文件副本**复原,`trap restore EXIT` 排在首次 apply **之前**,退出时 `sha256sum -c`
逐一核对(不用 `git checkout` —— 那会连带把树里无关的活悄悄还原)。裸读 `RC_EXIT=0`、
`MUTSTAND all cells behaved as specified`、`RESTORE ok (all 4 files byte-identical to the start)`:

| | 变异 | 期望 | 读数 |
|---|---|---|---|
| M0 | 未变异 | exit 0 | `10 tests, 0 failures`,无 `LINE NOTE`/`AMBIGUOUS` ✅ |
| M1 | **逐字复现 09-02**:`aiug:3406` 插 10 行注释 | **exit 0** | `LINE NOTE` + `6886 -> :6896`,无 `NEW` ✅ |
| M1b | **同一棵变异树,交给修复前的棘轮** | exit 1 | ✅ 修复前的棘轮把它叫 `MOVED` 并失败 |
| M2 | 一个**货真价实的新未知物品名**(无登记的站点) | exit 1 | `1 NEW unknown item name` ✅ |
| M3 | 两条登记行同键 | exit 1 | `AMBIGUOUS ANCHOR … judged row written twice` ✅ |
| M4 | 两条**活的发现**同键(把 pin 的那一行写两遍) | exit 1 | `AMBIGUOUS ANCHOR … two findings, one key` ✅ |
| M5 | **把 pin 的那一行改写**(同文件同种同名同行号,只改文本) | exit 1 | `1 NEW` + `1 registered site(s) no longer present` ✅ |

⭐ **M2 与 M5 是这台里值钱的两格。** M1/M1b 只证明「它能不红」;

`MOVED`。没有它,整台只能证明「新棘轮在我造的现场里不红」,**证明不了那个现场
真的是 08-26→09-02 那 14 次的现场**。
(⚠️ 本次落地之后 HEAD 携带的就是修复版,M1b 会自己打
`SKIPPED (…) — this is a SKIP, not a pass` 并说明该跟哪个 commit 比。)

### 1.5 一处**删掉**而不是保留的东西

旧棘轮有个 `MOVED` 配对段:pin 移位会同时产生一条 `NEW` 和一条 `GONE`,单看哪一半都不
说明「它移动了」,并排放才说明。**本轮把它删了**,理由写进源码:它诊断的那件事**已经
不可能发生** —— 内容键下,移位的 pin 就是**同一个键**、匹配上、只是一条绿色运行上的
`LINE NOTE`。今天再做配对就是**猜**:一个键变成两个键的唯一途径是**那一行本身被改写**,
而改写过的行不是被判过的行。**保留配对等于把锚要防的静默吸收当作启发式重新请回来。**
