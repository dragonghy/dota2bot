## 1. `[bug] #51` — 修复内容

### 1.1 缺陷形状(issue 报得准确)

`string.find` 是**多返回值**函数。TypeScriptToLua 把任何对它的**赋值或 `!== null` 比较**
编译成**表构造**,而表永不为 nil:

```ts
const result = string.find(unit.GetUnitName(), name);   // TS,读起来完全正确
```
```lua
local result = {string.find(unit:GetUnitName(), name)}  -- 生成的 Lua
return result ~= nil                                     -- 恒真
```

### 1.2 issue 没报的两处(自己扫出来的,`grep '{string\.\(find\|gsub\|match\)' bots/`)

全树 **11 处**,两个生成文件(`utils.lua` 2、`aba_defend.lua` 9)。issue 列的四个调用点
(`IsBear` / roam 的 tombstone 分支 / elder_titan、invoker 的 `MinionThink`)都属实,
但**没有一个带数字**。带数字的两处:

| 位置 | 作者写的 | 实际发生的 |
|---|---|---|
| `ShouldDefend`(`aba_defend.ts:502`)敌方小兵称重 | 普通兵 0.2 / 攻城 0.5 / mega 0.6 / 傀儡·守卫 1.0 / 熊 → 记作一个英雄 | 第一条判据 `siege and not upgraded` = `true and false` **永不成立**;第二条 `upgraded_mega` **恒成立** ⇒ **每只兵 0.6**,其余分支**死代码** |
| `WeightedEnemiesAroundLocation`(`aba_defend.ts:250`) | 可疑幻象 0(幻象不是 creep) | 幻象 **0.6/个** |

**可算的后果**:`nNearby = enemyHeroNearby + math.floor(creepWeights)` ⇒
**一波 4 只普通小兵 = floor(2.4) = 2 个「附近的敌人」,场上零个敌方英雄**;
基地威胁保持那条(`creepWeight >= 2` 续 1.5s)**4 个幻象就能续上**。

### 1.3 修法

`.includes()` → tstl 编译成 `__TS__StringIncludes`(nil 判断在 helper 内部、对单个值做)。
语义从 Lua **模式**匹配变成**纯子串**:11 处的针都是无魔法字符的字面量,**没有一处匹配结果改变**,
而纯子串对「名字包含」本来就是更安全的默认。

**TS 源与生成的 Lua 同改**(CLAUDE.md 硬要求)。**踩到的工具约束**:容器里 `typescript/`
**只有 `README.md` / `bots/` / `post-process/`,没有 `package.json`、没有 `tsconfig`**
—— `npm run build` 在这个仓库状态下根本跑不了(node/npm 本身是有的)。
生成物因此是**手写**的,但不是猜的:照抄**同一个文件里已经存在的** `__TS__StringIncludes`
调用形状(`aba_defend.ts:616` 早就在用 `.includes`,两个文件的 helper 也早已内联),
并补上 §1.4 的**双向棘轮**,让下一次真正的重生成既不会回退、也不会与手写结果分叉。
