## 1. 缺陷(GH #473 甲,批测台 W44 现场)

`tools/batch_test/soak/carrier_terms.py` 判一条 id 的「域」,读的是消费点所在的**文件**:
`bots/BotLib/hero_x.lua` ⇒ 英雄 x,其它 ⇒ `generic`。它看不见第二种形状 ——
**闸写在 generic 文件里,域却是一个英雄**,因为一句 `if botName == '...' then` 决定这行跑不跑:

```
bots/mode_roam_generic.lua:1038   if botName == 'npc_dota_hero_pudge' then
bots/mode_roam_generic.lua:1039       local rotscope = J.IsModeTurbo() and J.IsSoakCandidate('rotscope')
```

`generic` 是载体门**唯一豁免**的那一类 ⇒ 这道「抽不到载体就别发波」的门对 `rotscope`
一句话都说不出。W44 抽到 Pudge(96/207 局)是种子碰巧,门既没预测也没保证。
与 `check_armed_wiring.py` 的「有调用点 ≠ 谓词能为真」同族:**门查的那一层,不是缺陷所在的那一层。**

## 2. 修法,以及为什么不按 issue 自己的建议

GH #473 建议「从申请单的 acceptance 读域」。**不采纳,理由是那条路刚刚失效过**:
那句话**已经逐字写在 acceptance 里**(「只对 Pudge 可达 ⇒ 没抽到 Pudge 的波次读数恒为零」),
**而它照样没被读**。一条需要「有人当初把话说对」的规则,正是刚刚失效的那一条。

改成读源码:`Tree.hero_guard_scope(rel, lineno)` 从外层定义起、**按出现顺序**扫块令牌
(`if/elseif/else/function/for/while/repeat/do/then/end/until`),维护块栈,每个 `if` 帧
记住条件里**正向**锁定的英雄;`_resolve_site` 在 generic 那几条出口**之前**问它。
按出现顺序而不是按净增量,是因为同一行上的 `end`(关)与 `if`(开)**不可交换** ——
净增量算得对深度、算错**帧的身份**,而帧身份正是英雄门唯一活不过的东西(测试 D5 钉这一条)。
