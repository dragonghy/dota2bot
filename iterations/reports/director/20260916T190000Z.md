## 一 RULING 67 —— `NO-HANDOFF`:掉棒不是「没人能看」

### 1.1 现场(三行都是真的,合起来读是假的)

§1.5 那条腿本轮逐字读回:

```
corpus   : issue corpus …, fetched 2026-09-16T10:02:00Z (9.0h old), 6 issues
entry 2026-09-16T15:55Z: no『下次触发』segment
scanned  : 1 entry (of 86), 0 carry segment(s), 0 GH ref(s)
UNCERTIFIABLE -- zero GH refs extracted; a clean bill and an empty match print the same,
                 so this is exit 2 (anti-empty-match)
VERDICT  : UNCERTIFIABLE (exit 2)
```

**三行逐字属实**,而合起来读像「本轮没什么可查」。真相是:13:18Z 那份 **10 条**清单
(含 `GH #810 / #240 / #528`)**从此没有任何一条腿在看它** —— 包括本腿,因为
`LIMITS 3` 写着「默认只看最新一条 entry,旧清单已被下一轮取代」。

### 1.2 判词

⛔ **两件事共用了一个退出码,而它们的性质不同**:

| 读数 | 是什么 | 下一轮会怎样 |
|---|---|---|
| 没有语料 / 语料过期 / 正则零命中 | **这一轮没人能看**(环境) | 语料一刷新就自己好 |
| 最新 entry 没写清单 | **棒掉了**(在完全可读的语料上被正面观测到) | **不会自己好** |

⇒ **`NO-HANDOFF` 判 finding(exit 3)**,不判 UNCERTIFIABLE。
⭐ **并且回落**到最近一条写了清单的 entry 去交叉读,打上 `CARRY-FROM` 与距离。
**这不违反 `LIMITS 3`,是 `LIMITS 3` 的前提失效**:
**一份清单是被下一份清单取代的,不是被下一轮取代的** —— 下一轮没写,旧的那份**就是现役的棒**。
⛔ **`NO-HANDOFF` 与回落读到什么无关**:回落清单里每个号都 open 也照样 exit 3,
因为要被修的是**这一轮没交棒**,修法只有一个 —— **本轮把清单写出来**(本报告 §六)。
