## 4. ⭐⭐⭐⭐ 本轮最该被读的实现细节:**不剥注释的版本,从落地第一天就是红的**

朴素扫描得 **143** 个 id,剥注释后 **141**。差的两个是 `pullbeat` 与占位符 `X`,
**五处出现全部是警告这条陷阱本身的注释**
(`mode_roam_generic.lua:253/331/432`、`jmz_func.lua:1982/8483`)。

⇒ 一个不剥注释的检查器**在它落地的那一天就对着 trunk 喊 5 次假警报**,
而**从第一天就红的检查会被关掉** —— 那正是「手不再举起来」的机制。
所以 `tests/test_promote_atoms.py` 的**承重用例是诱饵用例,不是违规用例**:
case 3 钉「只出现在注释里 ⇒ 不算」,case 4 钉「剥注释没有把旁边那个**活的**也剥瞎」。

**case 3b 是变异台逼出来的**:单行 `--[[...]]` 证明不了块注释剥离(它自己就以 `--` 开头,
行注释腿已经杀掉它);**只有跨行块**能把两条腿分开 —— M3(删掉块剥离)在 case 3b 存在之前**存活**。

**同族第二处,自己咬自己**:行号最初是拿**剥后偏移**去数**原文**换行,
读出来的行**指向活调用点上方那条警告注释** —— 即**这个工具存在的理由所要分辨的那个诱饵本身**。
case 4 的第三条断言当场抓到。

## 6b. ⭐ 顺带捡到的一条 `[harness]`:**21/24 张波次记录钉的树不在 `origin/main` 上**

不是专门找的。核 §ED.5 那句话时要按每一波自己钉的树读 armed 串,把同一批 sha 过一遍
`claim_precheck.sh`,它把其中一个报成 **OFF-TRUNK**(解析在 `origin/claude/admiring-hawking-0gk9ek` 上)。
顺手全查:

```
git merge-base --is-ancestor <W*_wave.json:tree> origin/main
```

⇒ **ON_TRUNK = 3(W45/W46/W47),OFF_TRUNK = 21(W24..W44 连续)**。

- **读数不受影响**:commit 对象都在,`git show <sha>:<path>` 照常回答 —— 第 2 节那份 24 波普查有效。
- **可审计性受影响**:`AGENTS.md` 那条硬知识写着「批测实例启动时 clone `origin/main`,发波前先核实
  远端 tip 就是你要测的那棵树」,而波次记录的 `tree` 字段就是这句话的**凭据** ——
  对 W24..W44,**那个凭据不是 `origin/main` 上的任何一个点**。
- **失效方向是静默的**:会话分支被清理的那天,21 张记录的 `tree` 变成解析不了的 sha,
  **而不会有任何检查举手**(`stable_anchors.py` 只看两个 stable ref;`claim_precheck.sh`
  只看被评论引用到的 sha)。
- **成因是猜测,未证实**:Routine 落地路径是 `push 会话分支` + `push HEAD:main`,
  第二条被拒时 `pull --rebase` 重试 ⇒ **rebase 后 main 上那个 commit 的 sha 与会话分支那份不同**。
  W45 起三张连续在 trunk 上,说明**做法在那前后变过**。⇒ 已开 `[harness]` issue,
  **动作在批测台那一侧**(它写波次记录),总监不改 `tools/batch_test/`。
- ⚠️ 建议里写了一句自我约束:补的那条腿**对已有 21 张历史记录会立刻是红的** ⇒
  要么先回填,要么显式登记为 known-off-trunk,**而不是让它从第一天起就红**
  —— 第 4 节那条道理,同一轮内第二次用上。
