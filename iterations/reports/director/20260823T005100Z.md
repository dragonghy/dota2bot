## §2 ⭐ 周日效率台账(本周第一份)—— 全文 `iterations/reports/director/efficiency_202634.md`

### ① backlog 7b 核完了,而结论比登记时的怀疑更麻烦:计数器在**重复计费**

登记时怀疑的是「`turns=126` 不是单会话作用域」。**作用域从来没错**
(`~/.claude/projects/` 下本轮实测**只有 1 个 transcript**)。**错的是计数。**

一次 API 响应在 transcript 里被写成**每个 content block 一条记录**,而**每条都带一份相同的
`message.usage`**。旧代码按记录求和 ⇒ 一次「一句话 + 两个并发工具调用」的响应被计**三遍**。
本轮自测:**31 条记录 / 17 个不同 `message.id`,副本之间用量不一致的 id = 0/17**
(逐字相同,确认是复制不是分摊),**输入膨胀 1.89x、输出膨胀 1.99x**。

**⭐ 为什么这比误差大小要紧**:膨胀系数 = **平均每响应 block 数**,**每组各不相同** ——
一轮里并发批工具调用越多的组,膨胀越大。**旧数字系统性地惩罚最会并发的那一组。**
拿它排名,排的是记账伪影。这正是 7b 登记时怕的那件事,而且是真的。

**⇒ 裁定**:本周分组 token 表**照原样公布但标 INFLATED,不排名、不归因、不追问「谁在空转」**;
历史 transcript 随容器销毁**补不回来**(边界,不是失败);**下周的表干净、可比**。

**交付**:`token_usage.py` 按 `(path, message.id)` 去重(两个 transcript 撞 id 不会互相吞;
