### 1.1 ⭐ 立案句(§CG.1 的复述,因为它是这条腿的全部理由)

`fieldsip` 在 `test_set.md §CE` 里躺了 **8 小时、跨三轮**未裁,
而这三轮的自检**每一轮**都逐字打出:

```
RIDESHARE (§BB.4: rule this round): none
OTHER (routing/slot ruling still owed): none
```

**真话,不是干净现场** —— 这个工具扫的是 `queue.json`,而 `fieldsip` 在那里 grep 计数 0。
对比 §CF 的 `odbuild`/`wkqdmg`:它们**有**请求行,自检**连续两轮点名**,照样迟了三轮 ——

### 1.2 ⭐⭐ 本轮最该被读走的一条:「已裁」的判据是**跑出来的,不是挑出来的**

判「这条提议是不是已经有裁定」我一开始想用最省事的信号:**`state.json` 里有没有这个 id 的条目**。
拿founding case 一验就崩了 —— **在 §CE 落地的那个 commit(`351389e`),`fieldsip` 已经有完整的
`state.json` 条目了**(grep 计数 5),因为**提议方是把条目当提议的一部分写的**,
里面那行正是 `handoff: "director: rule on admission"`。

⇒ 用「条目存在」当已裁信号,**这条腿会在它唯一存在理由的那个案子上保持沉默**,
而其它每一条测试都会绿。这就是它现在被单独钉成一行断言的原因
(变异 M1:让 `ruled_in_state` 见条目就返回 True ⇒ 三条红)。

**最终判据是两个信号取或**,而两个都不能单独用,理由也是数据不是品味:

| 信号 | 单独够不够 | 反例 |
|---|---|---|
| id 在 `test_set.md` 第 2 行成员串里 | 不够 | `campexit` 已被**退集**,不在成员串里,但已裁 |
| `state.json` 条目带 `director_ruling*` 键 | 不够 | `aimguard` 已入集,**全树没有这个键** |

### 3.3 ⚠️ 收尾时 `claim_precheck.sh` 抓到一条,而它抓的是**工具自己**

按 GH #290 给本报告跑 `claim_precheck.sh`,报一条 `MISSING section` + `DO NOT PUBLISH YET`,
被点名的「小节」是 `§` 加两个大写占位字母。
第一反应是「我的行文写了一个占位符」—— 一半对。**另一半是这条腿的横幅本身**:
它原来的横幅里也带着**同一个 `§`+两个大写字母的占位符**,
而这行输出**注定会被粘进报告和 issue 评论**(本报告 §3.1 就粘了),
于是 `claim_precheck.sh` / `citation_audit.py` 每次都会把它解析成
**一个不可能存在的小节引用**。

⇒ **一个检测器的输出不许毒化另一个检测器**。横幅改成
`(test_set.md sections with no queue row)`,行文里的占位符改成 `§<字母>`;
改后 precheck 该项清零。这条是免费的:发现成本 = 例行跑一次 precheck,
而不发现的代价是**此后每一份引用它的产物都带一条恒假的 MISSING**。

**⚠️ 附带一条会咬人的性质**:`claim_precheck.sh` **自己那条 finding 的文字**,原样抄进报告,**会再次触发它自己**(本轮实测:改完横幅仍报 1 条,因为我把它的原话引进了上一段)。⇒ 写这类复盘时,占位符要**描述不要照抄**;真要照抄整段输出,先想好它会不会自我引爆。
