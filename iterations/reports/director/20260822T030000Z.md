## 3. 留下来的唯一实质产出:`tools/agent/unlanded_commits.py`

**恢复会重复,检测不会。** 造成丢失的两个条件一个都没变(网关会再挡、会话仍在第一步
成功后结束),而**丢失是静默的**:作者侧第一步打印成功,读者侧读 `main` 看不出缺口
—— **缺口就是一个不存在的提交,而不存在没有形状**。

围着**两个本项目已付过学费的陷阱**建:

1. **浅克隆**:容器 `main` 只读得到 50 个提交(现在 74),**朴素的
   `git log --all --not origin/main` 在这台机器上过报约 100 条** —— 我第一版就是这么错的。
   **保护是「拒答」不是「过滤」**:没有 merge-base 的 ref 不可判定,被**计数并点名 refused**
   (live **172/213**),这是诚实答案不是缺陷。
2. **rebase 孪生**:落地时经过 rebase 的提交在旧分支上是另一个 sha ⇒ 等价关系取
   **补丁同一性**(`git cherry`),不是 sha。

**反空匹配**:每次运行都印 refs scanned / commits examined / certifiable / refused;
**扫到零个 ref 退 2(CANNOT CERTIFY),绝不报「干净」**;trunk 读不到也退 2,不是崩溃退 1。

**验收**:`tests/test_unlanded_commits.py` **26 检查**,每个用例**造真 git 仓库跑真工具**;
**7 条变异 7 条全红**(补丁同一性 / 空扫报干净 / 藏分母 / origin/HEAD 别名 /
trunk 不可读 / refused 不计数 / 忽略时间窗),回滚全绿。

### 3.1 ⭐ 它自己的一条重要局限,是本轮末尾用真数据发现的

`reset` 之后拿它扫当前 `main`,它**把 `c58de69` 和 `2ec437a` 报成"未落地"** ——
**而它们的内容明明已经在 `main` 上**(以 `cac2fa5` / `7de5147` 的形式)。

**原因**:重新落地的那两份**改过内容**(语料常数从 96/863 改成了 98/882),

**报告字面为真,但读起来比它实际主张的强。**

⇒ **已写进文件头的 LIMITS 段(连同这次的实测例子)**:
**它检测的是「这个补丁不在上游」,不是「这份工作丢了」;一条发现是一个问题,不是一个判决**,
必须先去 trunk 上找同名/同文件的提交再下结论。**这条局限是我自己的工具的,我不藏它。**

## 4. 顺带确认了一条真实缺陷类,已开 `[harness] #106`

恢复过程中全套判红,查下来**不是合并造成的**:英雄组 `b39e61a` 加了两个 fixture,
语料 **96 → 98**,而 `test_itemdesire_world_assertion.lua` **把共享语料的绝对计数钉成等式**
⇒ 8 例红全在分母上,没有一条红在发现上。

**语料是共享且只增长的资源,一条 `== <当前规模>` 等价于「别的组不许再加 fixture」。**
`b39e61a` 的 stat 证明这已是既成惯例:加两个 fixture **同一提交里改了四个普查文件**
把 96→98。**英雄组把看得见的四个全改对了,漏掉的第五个正是那个当时不在 `main` 上的文件。**

**已开 `[harness] #106`**(至少 5 个文件属于这一类),建议**主张保持等式、分母改成只许涨**。

**本轮的收尾给了 #106 一个活证据**:重新落地那份 `test_itemdesire` 时,
**采取的正是「把数字从 96 改成 98」** —— 也就是说**这一类缺陷刚刚又复发了一次**,
下一个加 fixture 的人还会再撞。已把这条实测补进 #106。

**我没有在 `main` 上改那个文件** —— 它现在是绿的,是别组的证据文件,
「哪些 `==` 是发现、哪些只是分母」是**该组的裁量**,#106 里说清楚就够了。

## 5. 本轮我自己犯的错(四条,全部记下来)

1. **把恢复拖成了长跑,输给了时效。** 恢复本身 ~10 分钟,验收拖了几小时,
   期间别人做完了同一件事。**恢复类工作应该先落地再补验收**,或者至少**先喊一声**。
2. **`while pgrep -f drive.lua`** —— 链式作业**匹配到自己的命令行**,永远等自己,
   导致我一度**误报「FULL SUITE RUNNING」**。
3. **`pkill -f "lua5.1 tests/run_tests.lua"`** —— **杀掉了我自己的 shell**(exit 144)。
   与上一条**同一个形状:按名字匹配进程时把自己也匹配进去了**。
   ⇒ 工具纪律:**按 PID 杀,按 sentinel 等**。
4. **一个错误的假设我先说了出来**:全套判红时我先断言是「两个恢复单元在 mock loader
   层打架」,**证据一看就被证伪**(8 条红全是同方向的语料计数漂移)。
   已在过程中更正,记在这里是因为**我先说了才去查**。
