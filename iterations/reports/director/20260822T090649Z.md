## 2. ⭐ 第一条裁定:`--rec-slots` 定 **8** —— 「吞吐代价未测」这句话本身是错的

批测台 08:11Z §3.7 把这个决定上报给我(owner 07:23Z 指示「录像组选局核验、给 owner
做回放展示优先用全集波次的局」,而 `--rec-slots` 仍是 1 ⇒ ~280 局里帧级通道只拿到 ~1/16)。
`spot_run.sh:31-37` 用一句话挡了它好几个月:**「raise it only on instances that are
measuring the throughput cost of SourceTV」**,而那个代价从来没人测过,因为大家默认
测它需要一次付费波次。

**它不需要。而且语料已经在 S3 上躺了一个月。**

### 2.1 装置(为什么这份免费语料能回答这个问题)

每一波都写 `<TS>_slot<N>.analysis.json`,里面有 `wall_s` / `duration_s` /
`effective_timescale`(游戏秒 / 墙钟秒)。而在 REC_SLOTS=1 的波次里:

> **slot 1 是唯一的录制者,slot 2-16 是它的对照腿 —— 同一台机器、同一时刻、同一英雄池。**

录制的代价就是这两群之间的差。**这是一个现成的组内对照实验**,不是估算。

### 2.2 读数(12 run / 925 局;其中 4 个 run 带 claim sidecar = 305 局)

| 通道 | 读数 |
|---|---|
| **timescale**(局内速率:tv_enable 拖慢模拟了吗) | 录制槽 **1.983** vs 对照槽 1.848–1.962 |
| 对**只用对照槽拟合**的槽序趋势的残差 | **+0.150(+8.2%)**,即录制槽**更快** |
| 只用带 sidecar 的 4 个 run(305 局)重算 | **+0.146(+8.1%)** —— 同一档 |
| **去掉每槽第一局**(排除暖机伪影) | **+7.8%**,效应**存活** |
| **games/slot**(整个循环,含 `wall_s` 之外的 `.dem` 上传) | 录制槽 **60** vs 对照均值 **57.67**(**+2.33**) |

**逐波看更硬**:**录制槽在 12/12 个 run 里都是那一波最快的一槽**,差 +0.05 到 +0.14。

### 2.3 混杂:槽序是真的,而且方向对结论不利

对照槽的平均 timescale **随槽号单调上升**(拟合 **+0.0081/槽**)—— 启动错峰
(`soak_loop.sh:11` 的 `sleep SLOT*10`)+ 波尾争用变轻。**裸做「slot 1 减其余」会把
混杂算进信号**,所以工具**只在对照槽上拟合**,录制槽按自己的槽号取残差。

关键在于:**slot 1 起得最早,按这条趋势它本该是最慢的那一槽**,它却是最快的。
**混杂的方向对结论不利,结论仍然成立。**

### 2.4 归属正确性侧也有实证 —— 但边界要说清楚

4 个 run 的 **20/20** 局 claim sidecar:全部 `method=logname`,三种判据
(logname / hostname / mtime)**逐局一致**,`hostname_hits=1`。
`dem_claim.sh` 文件头承诺的「一次普通的 REC_SLOTS=1 波次就免费验证 logname/hostname
机构」**兑现了**。

**诚实边界(必须一起引用)**:这 20 局全是 **`candidates:1`** —— 池子里只有一份 `.dem`,
**多录制者之间的歧义从未被真正演练过**,三判据一致是平凡的一致。
**这正是裁定先上 8 而不是直接上 16 的理由。**

### 2.5 裁定与验收(事先登记,不许事后改判据)

**下一次全集默认波次起 `--rec-slots 8`,两臂同值;通过验收后再上 16。**
为什么是 8:**8 让那一波自带对照腿**(slot 1-8 录、9-16 不录,同机同时),
验收不必只靠跨波比较;16 没有对照腿;4 白白少一半帧证据。
单录制者的代价实测为零,但**16 个并发 SourceTV 的争用是超线性的,没测过就是没测过**。

```
python3 tools/batch_test/soak/rec_slot_cost.py <本波 4 个 run 目录> \
    --baseline tools/batch_test/soak/rec_slot_baseline.json
```
exit 0 = 通过(净损失 ≤5%)⇒ 下一波上 16;exit 1 = 有录制槽超差 ⇒ 退回 1 并重裁;
**exit 2 = 语料答不了(拒答,不是通过)**。

### 2.6 交付的工具(以及它的两条自带纪律)

`tools/batch_test/soak/rec_slot_cost.py` + `tests/test_rec_slot_cost.py`(**33 检查**)
+ `tools/batch_test/soak/rec_slot_baseline.json`(305 局基线剖面)。

- **谁录了是「读」出来的,不是推的**:录制槽集合来自 `.demclaim.json` sidecar,
  不来自目录名、也不来自「slot 1 总是录」的默认。**比 sidecar 老的语料一律 exit 2**,
  除非调用方用 `--assume-rec-slots` 明说,而那时 banner 打的是 `ASSUMED` 不是 `read from`。
- **空语料绝不打干净表**:无对照腿(全录)/ 语料太薄 / sidecar 互相矛盾 / `--assume`
  与 sidecar 冲突 / 基线无重叠槽 —— 一律 exit 2 **并打出触发它的分母**。
- **验收里也有基线腿**:整台机器比基线那天慢(吵闹邻居、不同 spot 池)会让所有槽一起掉,
  把那笔账算到录制头上就是「读 A−B 不看基线腿」。所以对照槽自身的漂移就是这里的
  **box factor**,录制槽只为**净损失**买单。

**变异测试四条四红**(还原走文件级备份,不走 `git checkout --`,遵 01:0xZ 那条教训):
M1 把拟合改成 pooled(倒退回裸读)→ 5 红;M2 去掉 box factor → 1 红;
M3 去掉「无对照腿」拒答 → 2 红;M4 无 sidecar 时静默假设 slot 1 → 2 红。
还原后 `diff -q` 逐字节相同、**33/33 全绿**。
