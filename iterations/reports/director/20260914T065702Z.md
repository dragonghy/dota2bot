### (B) 实质裁定:⛔ 不拆词 —— 而理由不是「它无害」

**1. 拆只能拆 queue 那一半,而那一半刚被裁过。**
EC2 那半不是我们的词:`wave_fence.py:304` `ACCRUING_STATES = ("pending","running","stopping","shutting-down")`
是 `ec2 describe-instances` 的实例状态常量。queue 那半的五词表是 **GH #317 裁定的**
(`pending_rulings.py:408` `OPEN_STATES = ("pending","running","harvested")`),
拆词要同轮改 `OPEN_STATES` + #317 正文 + `tests/test_pending_rulings.py` 的钉子 + 各流习惯。

**2. ⭐⭐ 而被看见的那个词不是最坏的那个 —— 这是本裁定的实际论据。**
实测:**`pending` 在同一对读者之间背三个意思,`running` 只背两个**。

| 词 | 意思 | 出处(现读) |
|---|---|---|
| `pending` | queue 行状态,**48 行** | `queue.json`(`running` 3 行,总 122 行;`2026-09-14T06:57:02Z`) |
| `pending` | EC2 实例状态 | `wave_fence.py:304`,**与 `running` 并列在同一个元组里** |
| `pending` | **一个美元数** | `wave_fence.py:797/896/947` 逐字 `pending=$0.000` |
| `running` | queue 行状态,3 行 | 同上 |
| `running` | EC2 实例状态 | 同上 |

`running` 之所以**先被看见**,只是因为那几轮 queue 里恰好有 3 行 `running`、
而围栏恰好打 `CERTIFIED ZERO`。⇒ **拆 `running` 而留下 `pending`,等于按「哪个词今天被撞见」
排序修词表。** 与铁律 4 (i-c) 的立法句同型:**分界线是缺陷的实际形状,不是它第一次被看见的地方。**

**3. 正确的修法在打印点,不在词表。** 两个词在各自命名空间里**都是对的**;错的是印出来时不带单位。
对批测台可执行的一条:报告里这两个词的计数**必须带它数的是什么**
(`3 个 queue 请求行` / `0 个 EC2 实例` / `$0.000 未入账支出`)。
裸写 `running: 3` 与 `CERTIFIED ZERO` 并排即为缺陷 —— **那正是连续五轮被报成「不相容」的成因**。
⛔ 本裁定不改 `OPEN_STATES`、不改 #317、不动 `wave_fence.py` 的任何数。
