## 2. `test_mutstand_restore_trap`:检测器只认一种写法,于是四条误报、两条漏报

它的 TRAP 正则 `trap\s+'?(\w+)'?\s+.*EXIT` **只能读「trap 体是一个裸词」**,
其余每种形状都读错,**而且两个方向都错**:

- `trap 'restore_all; rm -rf "$BAKDIR"' EXIT` —— 标识符后面是 `;` 不是空格,
  **整行不匹配**,于是 `dead_manacost` / `reason_read_76` 被报成「没装 EXIT trap」。
  **它们装了,而且是对的。**
- `trap 'cp "$SAFE/orig.py" "$SRC"; rm -rf "$SAFE"' EXIT` —— 匹配上了,
  **捕到 `cp`**,于是 `campbind_poke` / `slotwait_domain` 被报成「trap 了一个不存在的函数」。
  **它们会还原,只是内联写的。**

**四条误报盖住了两条真缺陷。** 把 trap 体当**命令表**读(按 `;`/`&&`/`||` 切,
取每段首词,问「是不是本文件定义的函数」),并且**读最后armed的那条 trap**
(后一条 `trap` 会替换前一条),真相才出来:

### 真缺陷(GH #418 同族,live 在树上)

`mutstand_outlatch_capture.sh` 与 `mutstand_structure_modifiers.sh`:

```
WORK="$(mktemp -d)"
trap 'rm -rf "$WORK"' EXIT      # ← 在效的就是这一条
cp "$TOOL" "$WORK/tool.orig"    # ← 唯一的原件,住在 $WORK 里面
restore() { cp "$WORK/tool.orig" "$TOOL"; ... }   # ← trap 从不调用它
```

被打断(^C / 超时 / OOM / 容器回收)时,trap **删掉 `$WORK`——也就是删掉唯一的原件**,
**同时把变异体留在工作树里**。这**比没有 trap 更坏**:没有 trap 至少原件还在。
这正是 GH #418 立案的那个形状(2026-09-02 `dist <= closestDist` 混进 main),
而旧检测器把它和「函数名拼错」评成同一个分。

修:在 `restore` 与备份都存在之后**重新 armed** `trap 'restore; rm -rf "$WORK"' EXIT`
——仍在第一次 mutate 之前,也就是这个 trap 存在的那个窗口之内。

### 修正正则后浮出的第三件事

`dead_manacost` / `reason_read_76` 之前**在第一条检查就 `continue` 了**,
所以「verifies its restore」**从来没跑过**。跑起来后红:两台**从不证明自己还原了**。
补了 `sha256sum` 清单 + `verify_restore`,并在收尾处 `restore_all; verify_restore || exit 1`。
实跑 `mutstand_dead_manacost.sh`:`KILLED=6 SURVIVED/WRONG=0` + `restore verified`,退出 0,树干净。

### 变异台核验(证据纪律 2)

给这个检测器建了变异台,**3/3 KILLED,restore verified**:

| 变异 | 结果 |
|---|---|
| M1 拆掉 outlatch 重新 armed 的还原 trap | KILLED |
| M2 拆掉 dead_manacost 的 sha256sum | KILLED |
| M3 campbind 的 trap 不再调用 restore | KILLED |

## 4. `test_wkqdmg_domain`:`_fn_body` 把 22 行读成 567 行

selfcheck 红在 `gate names exactly ['wkqdmg']`,实际读到
`['wkqdmg', 'wkbonefight']`。**表面看是英雄组 `34c9af91` 新落的 gate 撞进来了,
真因不是**:`_fn_body` 的深度计数**只把行首是 `end` 的行算作闭合**,
于是单行块

```lua
if not ( J.IsModeTurbo() and J.IsSoakCandidate( 'wkqdmg' ) ) then return nShipped end
```

**只加不减**,深度再也回不到 0,「函数体」一路吃进后面的函数。
`X.wk_GetBlastKillDamage` 实为 **22 行**,被读成 **567 行**,
**整个吞掉了 `X.ConsiderQ` 和 `X.ConsiderW`**——`wkbonefight` 是别的 helper 的 gate。

**这正是这个函数 docstring 里写着自己要防的那件事**(「Scope FIRST, findall second.
Feeding a whole hero file to a regex is how odaoe_domain.py matched a courier's
constant (GH #296)」)——防线写在了会失效的地方。

修:按行统计块开启(`function` / `do` / `if`;`for`/`while` 一律经 `do` 到达,
只数 `do` 免得重复计;`elseif` 是一个词所以 `\bif\b` 不匹配它;`repeat...until` 两边都不计)
与 `end`,先剥注释和字符串。**五个函数边界实测**,全部停在裸 `end` 且不外溢:

```
wk_GetBlastKillDamage  22   SkillsComplement  37   GetRoshanManaFloor  15
ConsiderQ             396   IsBoneGuardEnemyCountOk  8
```

selfcheck:**73 PASS / 0 FAIL**,退出 0。

> ⚠️ 交给英雄组/协同组的一句话:`wkbonefight` **本身没问题**,它只是踩响了一个
> 早就坏了的切分器。但**同一形状的 `_fn_body` 如果被别的 domain 工具抄过去,
> 那里的读数是可疑的**——见 §6 的 issue。
