## ① ⭐⭐⭐ GH #372:§22 的守卫**不能照抄到 `luacheck_gate.sh`**,照抄就是全仓停摆

### 立案

「给 `luacheck_gate.sh` 装管道守卫」在「下次触发」里**挂了四轮**,每轮都写
「已连续 N 轮故意不夹带」。本轮把它做了,**并且量出了那四轮的谨慎是承重的**。

缺陷是同一个(纪律 3):`bash tools/agent/luacheck_gate.sh 2>&1 | tail -5`
报的是 `tail` 的退出码,而 `tail` **在一个 RED 的门上照样 exit 0**。

### 为什么照抄 §22 是一次全仓停摆(本轮实测,不是推理)

`routine_selfcheck.sh` 的答法是:`/dev/stdout` 是 FIFO 就**拒绝**(exit 2)。
本容器用一个探针 hook + 一个一次性仓库量了:

```
git 跑 pre-push 钩子时 stdout 就是 FIFO     ->  /proc/self/fd/1 -> pipe:[11408]
```

而 `.githooks/pre-push` **裸调**这个门,并把**任何非零都映射成 `PUSH REFUSED`**。
⇒ 照抄 §22 会**拒掉每一个 stream、每一个容器里的每一次 `git push`**,
把铁律 6 的**门**变成铁律 6 的**封锁**,唯一出口是那个专门用来记录
「跳过而非通过」的 `RULE6_BYPASS`。

§22 当时可以诚实地写「这个假阳的实测代价:**ZERO call sites**」。
**在这个站点它不是零**:pre-push 钩子,外加 `tests/test_ensure_lua_toolchain.py`
与 `tests/test_push_gate_hook.py` 两个 `capture_output` 调用方(它们是**真读
退出码**的管道)。

**一般形(值得记进档案):判别式是「我的 stdout 是不是 FIFO」的守卫,
其安全性正比于该脚本有多少合法管道读者 —— 那是「调用站点」的属性,不是
「守卫」的属性。所以「把守卫移植过去」不是一个保正确性的变换。**
四轮不移植不是拖延,是对的。

### 落地的形状:**加一行判决,不改退出码**

门现在**永远以一行机器可读的判决收尾**,写在 **stdout**,**最后写**:

```
GATE_EXIT=0  CLEAN (iron rule 6 static half passed)
GATE_EXIT=3  RED (warnings above; iron rule 6 static half FAILED)
GATE_EXIT=2  UNCERTIFIABLE (the gate did NOT run; this is NOT a pass)
```

- `| tail -1` 与 `2>&1 | tail -1` ⇒ **活下来的那一行就是判决**;
- 钩子 / 两个测试 / `> file` / 裸跑 ⇒ **多一行,退出码逐字不变**。
- **无条件**是故意的:只在出事时才出现的行是**第四条提醒**(正是 §22 退役掉的
  东西),而每次 push 都报警的行会**把自己的读者训练成跳过它**。
  这一行**带的是答案,不是关于问题的警告**。

**它买不到什么(明写,不暗示)**:一个既不看退出码也不看最后一行的管道读者
仍然什么都学不到。这一条让真相**穿过管道活下来**,**不能让人去读它**。
§22 的拒绝形式仍然更强,**在它的调用站点允许的地方原样保留**。
