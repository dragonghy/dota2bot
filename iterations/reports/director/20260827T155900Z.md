## 3. ⭐ 主产出:`spot_run.sh` 的 AZ 分散(GH #252 请求 1 落地)

### 3.1 先证伪 issue 自己给的写法

#252 的请求 1 写的是「**或内置轮转:第 N 台取 AZ 列表的第 N 个**」。
**这个写法在本台的 4×1 拓扑下恒等于不修**:四粒种子是**四次独立的 `--count 1` 调用**,
四个进程里 `n` **全是 1** ⇒ 四台取同一个 AZ ⇒ **与 W17 逐字相同的失败**。

**这不是新坑,是同一个坑的第二次**:`spot_run.sh` 里 `RUN_TOKEN` 上方那段注释(GH #98)记的是
**`STAMP` 被四次调用共享 ⇒ run_id 唯一性只剩一秒**。
本轮把它写成一句可复用的话,放进源码注释:
**「四次调用共享的任何量都不能当分散键 —— 索引、时间戳、列表首元素都算。」**

### 3.2 落地的四种行为

| 调用 | 行为 |
|---|---|
| 默认(不传 `--az`) | 从 `aws.env:AZ_LIST` 取**每进程随机**起点(2 字节 `/dev/urandom`,读不到退回 `$$`),波内 `(offset+n-1) % len` 轮转 |
| `--az us-west-2c` | 本次调用每一台钉死该 AZ |
| `--az a,b,c,d` | 从 **offset 0** 走 ⇒ **确定性**;一次 `--count 4` 恰好铺满四个 |
| `--no-az-spread` / `AZ_LIST=` 空 | **逐字节回到 #252 之前的 `run-instances`**(不带 `--placement`) |

**概率**:四次独立调用 × 4 个 AZ ⇒ P(四台同 AZ) = **4⁻³ = 1/64**,P(≥2 个 AZ) = 63/64;
今天这个数是 **~1**。**但 1/64 不是零** ⇒ 批测台章程 §5 已写死「**每次调用显式点一个 `--az`,四次四个不同**」,
**那才是保证**;随机起点是**没人点时的地板**,不是天花板。

### 3.3 为什么不需要 issue 要的那张 subnet 表(三条实查,已写进 `aws.env` 注释)

- `SECURITY_GROUP=sg-044c4c8442366055e` 在 **默认 VPC `vpc-5ffb3d27`**;
- 四个 AZ **各有一个 `DefaultForAz` 子网**(4091 IP、`MapPublicIpOnLaunch=true`)⇒
  `--placement AvailabilityZone=<az>` **自己会去选那个 AZ 的默认子网**;
- 四个 AZ **全 `available` 且全提供 `c6i.4xlarge`**(`describe-instance-type-offerings`)。

⇒ **`aws.env` 只需要一行 `AZ_LIST`,不需要 subnet 表。**
注释里同时写明**脚本不在起飞时复查这三条**,某个 AZ 停售机型时**要手动从表里删**。

### 3.4 我加了 issue 没要、但比它要修的东西更贵的那一条

「没容量」是**按 AZ**的 ⇒ **钉死 AZ 会把「EC2 本来会放到别处」变成「这次调用直接失败」**。
所以钉住的调用失败时**自动回退一次到不带 `--placement` 的旧调用**(那一台不丢),stderr 打一行。
**一个分散措施绝不允许自己吃掉一台实例** —— 否则它买到的冗余小于它花掉的。
