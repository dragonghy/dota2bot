### 3.1 修法(两处不同,因为两处的正确语义不同)

**(A) `tests/test_axe_t15_in_domain.lua`:用这个仓库自己早有的写法。**
`test_corpus_existence_claims.lua` 的 **control 自己就是这么写的**
(`local DIR = 'tests/' .. 'fixtures/'`),注释里写明了理由:「判读代码不豁免于自己的规则」。
改成从 `FRAME` 派生、运行时拼装:

```lua
local sAdmitted = FRAME:gsub('tests/frames/', 'tests/' .. 'fixtures/')
```

**关键验证:这不是把检查器弄瞎,是让它不再把断言读成引用。**
往 `tests/fixtures/` 里**真的种下**那个文件后重跑:

```
axe-with-frame-ADMITTED BARE_EXIT=1
  tests/test_axe_t15_in_domain.lua:299: the staged frame has been ADMITTED to tests/fixtures/. ...
```

—— 拼装出来的路径**逐字解析到同一个文件,守卫照样开火**;删掉后 `BARE_EXIT=0`。
派生自 `FRAME` 而不是重写字面量,是为了它不能和 `FRAME` 漂开。

**(B) `tools/agent/citation_audit.py`:新增一个类 `IGNORED-BY-DESIGN`。**
gitignore 命中的路径**不在 trunk 上是设计如此**,判它 `MISSING`(=「你忘了 push」)
是在对一个**谁也 push 不了**的文件说这句话。**一道每次判对都要人工赦免一次的门,是人们会停止运行的门。**

两条守卫,防它变成静默赦免:

1. **trunk 平价守卫**(`ignore_rules_certifiable`):`git check-ignore` 读的是**工作树**的
   ignore 文件,而这个工具说的是 **trunk**。只有当每个 `.gitignore` 与 trunk 逐字节相同、
   且**没有未跟踪的 `.gitignore` 在加规则**时才降级;否则 `MISSING` **逐字保持旧含义** ——
   只存在于本容器的规则,对读者的 checkout 什么都不证明。
2. **逐条打印**:`IGNORED-BY-DESIGN  path  <p>` + 理由。
   **静默的赦免和正确的赦免在退出码里长得一模一样,只有打印能把两者分开。**

顺序也是断言的一部分:trunk 命中 → off-trunk → ignored → MISSING。
**被跟踪的文件即使被规则命中,仍然读 OK**(规则不能盖过 trunk 上实际有的东西)。
