## ① `[bug] #303`:`entities.canon()` 的 join 漏掉整个 Vengeful Spirit

### 1.1 立案读数(录像组 W24 `2d1024ee`,不是假想)

事件流写 `npc_dota_hero_vengefulspirit`,快照流写 `npc_dota_hero_vengeful_spirit`;

### 1.2 ⭐ 这不是新缺陷 —— 它是 **GH #82 的同一条缺陷,在第二个模块里没被修**

本轮查到 `tools/batch_test/behavioral/roam_conversion.py:142 canon_hero()`

事件流带的是**战斗日志名**,于是凡是引擎自己的 npc 名把两个词连写的地方,推导就**凭空造了一个分隔符**。
`tests/test_canon_hero_join.py` 连"必须是**规则**不是别名表"和"必须**无碰撞**"都已经论证过。

**而 `entities.py` 从来没拿到这份修复**,`blinkflee_domain.py` 本周又落了**第三份**本地拷贝(`hkey`)。
`entities.py` 自己的开篇注释写着「**a copied fix is a fix with a half-life**」——
这次是那句话的现场:**同一条规则三个实现,新的那个模块是漏的那个。**
⇒ 修法不是再写一份,是把规则**收回 `entities.py`** 并让 blinkflee 引用它。

## ② `#302` 的第三个文件:`test_gamemode_world_assertion.lua` 复绿(32/1 → **33/0**)

上轮**故意没关 #302**(它写 3 个文件,上轮修了 2 个)。本轮核了第三个:**确实还红**。

**红的原因不是那 8 条语料漂移那一族,是坐标当 key 的第四次现场** ——
`:1450` 的 pin 找的是 `"{ file = '…item_purchase_generic.lua', line = 228, op = '>=', n = 18"`,
而**今晨那一轮把 census 的 `line` 字段整个去掉了**(改用 `(file, 去空白源文本)` 当 key,
正是 GH #221「行号不是注册键」的药方)。
⇒ **这道门是因为它守护的东西被改好了而变红的** —— 这个失效方向最贵,因为它换来的
通常是把门关掉而不是修门。

**修法**:pin 重锚到该行的稳定身份(`file` + 该 gate 自己的 `op`/`n`),
并**补一条 `text` 断言**(一个 verdict 只是对它被读出来的那段源文本的 verdict —— 
行还在、verdict 还在、但已经是另一个 gate 的情况,现在也会红)。

**⚠️ 修的过程里这条 pin 又红了一次,而那次它是对的**:`at` 现在指到行首的 `{`,
从 `at` 起无界搜下一个 `{ file = ` **搜到的是本行自己**,`row` 成了空串 ⇒ **永远红的 pin**,
正是档案里 M15b「永远绿的 pin」的镜像。改成从 `at + #KEY` 起搜。**这一次是它自己在修它自己时抓到的。**

**变异台 2/2 红,控制绿**:M5 把该 census 行的 `verdict` 改成 `PAPER` → 红;
M6 把该行的 `text` 改一字(verdict 不动)→ 红(**这条正是本轮新补的断言**);
census 文件 `sha256sum -c` 逐字节还原。
