## 3. ⭐⭐⭐ GH #376:**自检说这两条「一行都没有」,而两行都在** —— 一条**照做就会把缺陷造出来**的假阳

本轮开工自检打的是:

```
ORPHAN_PROPOSAL (§CG.5: open a queue request row, then rule it): 2
  §CW   id=roamidle       no queue request row at all
  §CX   id=outlatch       no queue request row at all
```

**这句话是假的。** `strategy-27` / `strategy-28` 当时都在 `queue.json` 里,而且**正是提议方
自己按 §CG.5 建的**(§CW.7 白纸黑字写着「本行由提议方自己建」)。

**归因是链接键**:`tools/agent/pending_rulings.py` 的 `queue_rows_for()` **只在
`bundle` / `bundle_was` 里按整词找 id**,而**搭车请求的 `bundle` 按定义是空的** ——
它不申请波次,没有 bundle 可填。历史上能对上,靠的是 `strategy-23`/`strategy-25`/`hero-24`/`hero-25`
这几行**把候选 id 写进了 `bundle`**(一条从没写下来过的约定);
而**总监自己代建的 `strategy-26` 把 `bundle` 留空了**,提议方本轮**照着那个先例**建了两行。

**为什么这比一条噪声严重**:这条 finding 的**指令**是 “open a queue request row, then rule it”。
照字面执行的下一个总监会**建出重复行** —— 一个提议两行、两条裁定路径,
而 `queue_rows_for` 对重复行毫无意见。**它报的缺陷不存在,而照它做就会把缺陷造出来。**

**与 §23 同族但方向相反**:§23 是检查器把「断言不存在」读成引用(假阳,**照做无害**);
本条是检查器把「行不存在」读成事实,而**照做有害**。与 GH #317 同族但键不同:
#317 丢的是**开/闭判定**(`hero-20` 躺了两天),本条丢的是**行与提议的对应**。

### 3.1 处理(两半,缺一不可)

- **数据半**:`strategy-26` / `strategy-27` / `strategy-28` 的 `bundle` 回填成
  `rotscope` / `roamidle` / `outlatch`。**全仓只有 `pending_rulings.py` 读这个字段**(已 grep 过
  `tools/` 全部 `.py`/`.sh`),所以回填不动任何下游语义。
- **工具半**:`classify_proposals` 新增一类 —— 没有任何行用 `bundle` 链上、但**有 open 行在自由文本
  (`axis`/`question`/`acceptance`)里按整词提到这个 id** 时,报的是
  **「no row LINKS it (`bundle` empty) —— 去设 `bundle`,不要开第二行」并点名那些行**。
  **退出码不变(仍是 3,仍是 finding)**:改的是**指令**不是**严重性** ——
  一条链接键为空的请求确实还没被机器看见,它该红;它只是不该让人去开重复行。
  工具只说「候选行」不说「就是这一行」:自由文本里的整词命中是**证据不是对应关系**,
  这一点写进了函数 docstring 与 LIMIT 8。
