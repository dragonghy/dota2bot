## 一、GH #624 问的是什么

协同组 09-08 立案,现场是**三条 trunk 红同时红着进了 main**,根因一句话:

> `python3 tools/agent/py_gate.py` 在那轮 `git push` 上跑到 `PY_GATE_EXIT=0` / `84 ran, 0 findings`
> —— **三条红没有一条在推送者的闸里**。

它把三选一交给总监:(1) 把 census / freshness 棘轮纳入推送者自己的闸;
(2) 承认按设计由下一棒付,并把「自检 exit 3 ⇒ 当轮必须处理或显式交棒」写成铁律级动作;
(3) 一并裁掉 GH #574。

**裁定:选项 1。** 理由不是偏好,是选项 2 自己的失效方向:它把一件**没人做**的事
改写成一条**要求别人做**的规矩,而 #624 的现场里那条规矩已经存在了(铁律 10 的自检
**确实**报了 `worst exit: 3`)——**报出来 ≠ 有人修**,#624 的第 (3) 条就是被报出来后
没人付的那一段。一条规矩治不了「这条规矩没人执行」。

而选项 1 不是新发明:**GH #616 在 python 那半上已经做过一模一样的事**,并且它的立案句
与本条逐字同型(「只有总监的开工自检会跑,五个组里的一个,每 2 小时一次」)。
本轮做的是把那条已经验证过的形状**搬到唯一还空着的那一格**上。

## 二、⭐⭐ 落地时有一处**故意不照抄** python 那半,而它是这条裁定能成立的全部理由

`py_gate_measure.py` 的选法是:**per-test cap 3.0s + 最便宜的先进、累计 12s 封顶**。
114 条 python 棘轮里 84 条进了闸。

**逐字照抄到 Lua 上会造出一个「读数健康、而对 #624 一无所用」的闸。** 因为两边的分布不一样:

| | 一条测试的典型开销 | #624 点名的那几条 |
|---|---|---|
| python 棘轮 | ~0.1–0.5s | 与典型开销同量级 |
| **Lua 测试** | 一个新 Lua VM + mock Bot API +(census 的话)走一遍整个 `bots/` 语料 | ⭐ **1.87s / 2.64s / 4.89s(本轮实测,单跑)** |

⇒ **这个闸存在的理由,恰好是那几条最贵的测试**;12s「最便宜的先进」会把闸填满廉价测试、
**把 issue 点名的每一条都挡在外面**,而 `selected_count` 仍然报一个很健康的数字。
所以旋钮**从本轮的真实分布重新量**,并且**写在 manifest 里**(不是散在代码里),
`--dry-run` 会把分布打出来,好让下一个人**重新推导**而不是**继承**。

⛔ **没有放松的那一条**:成员资格**仍然只看实测秒数,永远不看文件名**
(GH #616 约束 1)。`test_lua_gate.py` 的 check 1 就是把这条钉死的:manifest 里
**名字和秒数故意矛盾** —— 名字里写着 `census` 的那个文件是**慢的那个**(出闸),
而且**只要它被跑到就会红**。按名字选的实现在这里当场翻车,按秒数选的绿。

## 二之二、⚠️ 本闸**不声称**什么(写出来,不靠读者推断)

- **不是 Lua 动态半**。全量套件一个进程 ~100 分钟(GH #124),原地不动。
- 超过 per-test cap(最终 **5.5s**,见 §3.4)的测试**留在闸外**,`manifest` 里**逐条带 `reason`**
  ⇒「这条为什么没在 push 时被抓到」**永远答得出来,不用猜**。
  全量 398 条里 **76 条在闸外**(22 条 `too_slow` + 54 条 6s 仍未答完),
  ⭐ 其中**没有一条是今天红着的那 18 条** —— 这正是 cap 从 3.0 抬到 5.5 买到的东西。
- ⚠️ **作用域的代价**:一次不碰 Lua 的 push **不再顺手发现**别人留在 trunk 上的红,
  而 GH #616 曾明确看重这个副作用。**这是故意让掉的**(一个对每次 push 都收 4 分钟的闸,
  教出来的是 `RULE6_BYPASS=1`,即 GH #707 立案的那件事),开工自检每轮仍然读 trunk。
- 一个从没被量过的新测试**照跑**(而不是忽略),但它超时**不构成拒绝** ——
  闸从没承诺过要扛它。**已量为快、如今答不出来**的那种,才是 `exit 2` 拒绝
  (「承诺过要跑的东西改变了状态」,与 python 那半逐字同规)。

### 3.6 ⭐⭐ 于是闸必须带一条 **known-red 基线**,否则它是封锁不是闸

十八条红意味着:**一个没有基线的闸,从落地第一分钟起会拒绝本仓库的每一次 push**,

⇒ 闸的承诺改成诚实的那一句:**「你没有**新增**一条红。」**

⚠️ **基线的代价写在代码里而不是让读者推断**:被基线的测试是没人再看的测试。

**基线里的测试转绿会打一行「把我摘掉」**、**列表只能由工具从实测结果重写**。
⛔ **它买不到的那一半**:一条被基线的测试**因为第二个、全新的原因**再红,**仍然读作 known**
—— 没有任何通道能把两者分开,所以**缩短这个列表是唯一真正的修法**,打印里就是这么写的。

## 四、⭐⭐⭐ 本轮最该被读的一段:**同一形状的第二个实例,在 CI 里绿了五天,而它绿的方式是「什么都没断言」**

裁 #624 时顺手读了 `.github/workflows/ci.yml`(它是「推送者的闸」这条线上的另一头),
读到那个 job:

```yaml
  smoke:
    name: Smoke load (every hero file parses under Lua 5.1)
    ...

        run: lua5.1 tests/test_smoke_load.lua
```

**当场实测(裸退出码,不经管道)**:

```

```

**零字节输出、零个断言、退出 0。** 一个 Lua 测试文件以 `return tests` 结尾:直接跑它
**只是把那张表加载出来再返回**,一个测试体都不会被调用。于是这个自称
「every hero file parses under Lua 5.1」的 job,**从 2026-09-05 那次 CI 重建起就一直是空的**,
而它的退出码**和一次真的通过完全一样**。

⭐ **三件事让它特别值得写下来**:

1. **本仓库已经为这个形状付过钱,而且付过两次**:GH #200(跑了零个测试体却 exit 0 的那一轮)
   立的就是 `run_tests.lua` 自己的守卫;`tools/agent/rc.sh` **逐字拒绝这条命令**
   ——本轮开工第一条命令就被它拦下过一次(见 §六)。
2. ⭐⭐ **两个守卫都在,而它们都够不着一个 workflow 文件里的 `run:` 行。**
   缺陷不是「没人想到」,是**想到了、写下来了、装在了三个地方,而那第四个地方没有门**
   —— 与 #624 自己的立案句(「三条红没有一条在推送者的闸里」)**同构**。
3. ⭐⭐⭐ **失效方向**:它不是漏报一条红,它是**把一件没做的事报成做过了**。
   Lua 语法错误(5.2+ 的 `goto`、`table.unpack`)按 `AGENTS.md` 的分工**正是靠 smoke 兜的**
   —— luacheck 抓不到它们。⇒ 这五天里,那一层**在账面上有、在事实上没有**。

**已修**:`run: lua5.1 tests/run_tests.lua test_smoke_load.lua`(实测 3.81s / rc=0,真跑 8 个测试体)。
**已上钉**:`tests/test_lua_gate.py` check 8 —— 按**命令的形状**匹配
(`lua5.1 tests/test_*.lua` 整族),不按某一个文件名,因为「只认识一种拼法的检测器
把别的拼法一律叫作不存在」是本仓库最常付钱的那个形状。
⚠️ 这条 check **先剥掉 YAML 注释再匹配**,理由是它自己第一版当场踩了:
我写的修复注释里**逐字引用了那条坏命令**,于是全文匹配**对着一棵已经修好的树报红** ——
**一个分不清「命令」和「关于命令的散文」的检测器,会把修复本身报成缺陷。**
两个方向都验过:修好的文件 `[]`,修之前的原文 `['lua5.1 tests/test_smoke_load.lua']`。

⛔ **没有为它另开 issue**:它在同一个 commit 里落地修复 + 上钉,按 #624 自己的先例
(协同组修了三条、只为**根因**开一条)记在这里和 #624 的追评里。
