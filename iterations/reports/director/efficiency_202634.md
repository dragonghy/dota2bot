## §0 ⭐ 方法学裁定:本周的 token 表**不可用于跨组比较**,原因是计数器在重复计费

backlog **7b**(08-22T23:30Z 登记:「`turns=126` 疑似不是单会话作用域,
周日台账用它做分组对比前必须先核」)本轮核完了。**结论比登记时怀疑的更具体,也更麻烦。**

**作用域从来没错**(一个容器 = 一次 run,`~/.claude/projects/` 下本轮实测**只有 1 个 transcript**)。
**错的是计数。** 一次 API 响应在 transcript 里被写成**每个 content block 一条记录**,
而**每一条都带一份同样的 `message.usage`**。一次「一句话 + 两个并发工具调用」的响应
⇒ 三条记录、三份相同的用量。旧代码按记录求和 ⇒ **那次响应被计了三遍**。

本轮自己的 transcript 实测(`tools/agent/token_usage.py` 的注释里写死了这组数):

| 量 | 值 |
|---|---|
| 带 usage 的记录数 | 31 |
| 不同的 `message.id` | 17 |
| 副本之间用量**不一致**的 id | **0 / 17**(逐字相同,确认是复制不是分摊) |
| 输入膨胀 | **1.89x** |
| 输出膨胀 | **1.99x** |

**为什么这比误差大小更要紧**:膨胀系数 = **平均每响应的 block 数**,
它是**每组各不相同的** —— 一轮里并发批工具调用越多的组,膨胀越大。
所以旧数字**系统性地惩罚最会并发的那一组**。拿它排名,排的是记账伪影,不是工作量。

⇒ **裁定**:
1. 本周 §2 的分组 token 表**照原样公布(它就是各组报告里 TOKENS 行的和),但标记为 INFLATED,
   本周不做跨组排名、不做归因、不追问「哪组空转」。** 历史 transcript 随容器销毁,**补不回来**,
   这是边界不是失败。
2. **已修 + 已钉**:`tools/agent/token_usage.py` 按 `message.id` 去重
   (键是 `(path, id)`,两个 transcript 撞 id 不会互相吞);
   `tests/test_token_usage_dedup.py` 驱动**真脚本**读**真产物**,11 检查全绿,
   **变异 M1/M2/M3 三红且红对地方**(去掉去重 / 把无 id 记录并成一个 / 只按 id 不按文件),
   三次还原 `cmp` 逐字节相同。**反空匹配守卫写在被它保护的断言之前**(语料里真有一个 3-block 响应,
   否则这测试对不去重的实现也会绿)。
3. **下周的表是干净的,可以比。** 本周的不行。

## §0b 第二条独立理由:`total_in` 量的是会话长度,不是工作量

即使去重之后,`total_in = input + cache_read + cache_creation` 里 **cache_read 占绝对多数**
(本轮去重后 in:out ≈ **190 : 1**)。cache 读随回合数**近似二次增长** —— 一轮做 60 个回合的组,
每个回合都重读一遍整个已缓存上下文。⇒ `total_in` 主要测的是**这一轮说了多久**。

⇒ **台账从下周起的常设指标是 `out/报告`(输出 token)**,`total_in` 只作为成本量级参考保留。
本周两个口径都列,好让下周有对照。
