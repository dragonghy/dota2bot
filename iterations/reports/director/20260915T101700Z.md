### 1.2 (甲) 时刻那条腿:病因是一个 **ASCII 标点表**,量是 5 行

逐字:`if not any(parse_utc(tok.strip("()[],;")) for tok in text.split())`。
`strip` 的表是 **`()[],;`**,而这个字段**全队都用中文 markdown 写**。现场三例:

```
late_epoch_corpus_reopen_list     …本行读 **OWED**(…),时刻 2026-09-12T22:06:20Z。
rule6_memo_fast_gate_membership   …本行判据读 **OWED**(…),时刻 2026-09-13T01:12:00Z。
aimguard_creep_schema_identity    …逐字:`… ,"idx"`,时刻 2026-09-…
```

⇒ 分词后拿到的是 `2026-09-12T22:06:20Z。`(**戳后面粘着一个中文句号**),`fromisoformat` 当然拒。
**五行带着满精度真戳,而检查器一个都看不见。** ⛔ 这不是口味问题:
**失效方向是 UNCERTIFIABLE,而 UNCERTIFIABLE 按自检自己的词表「不是通过也不是失败」**
⇒ 这些行**既不会被退休、也不会被当成红**,**每轮占一次注意力,永远**(批测台 §5.3 这句话是对的,
只是它说的是 3 行,真实是 **7 行**)。

**改法**:把「分词 + 砍五个 ASCII 标点」换成**在全文里扫**一个满精度戳的正则,
**并把 `parse_utc` 留作唯一裁判**(正则只负责提候选)。⇒ 引号、`**粗体**`、`。`、`、` 一律无关。

### 1.3 (乙) token 那条腿:`OWED` 是**一种拼写**,不是那个性质

该函数的 docstring 自陈买的是「**QUOTED READING**,不是一句 promise(`yes` / `checked` / `I ran it`)」。
`OWED` 是**这条腿自己打印的词**,所以抄它能证明作者跑过腿。但被卡住的两行抄的是**判据本身**,
而那**更直接**地回答了同一个问题:

```
hero27  2026-09-14T06:57:02Z 现读 `…/hero27_savemana_archive_scan.md` `present=False`
gh779   2026-09-14T10:02:13Z 现读 `check_costs.sh`:`accrual` `grep -c` = 0、`accruing` = 0
```

**改法**:除 `OWED` 外,再接受一种**带钥匙的实测**——证词必须 **(i) 点到本行自己 `done_when` 的主体**
(`path` / `basename` / `contains` 针脚 / json `key`)**且 (ii) 记下一个值**(`X = V` 的形状)。
⛔ **「带钥匙」这三个字是全部防线**:没有它,这一条就退化成「文本里有个等号就算」。

⭐ **一个差点写错的地方,靠语料当场拦下**:我最初想把 (乙) 写成「**读到零/假**」的词表
(`= 0` / `present=False` / `零命中`)。跑一遍语料就看见 **`gh806_lua_manifest_remeasure`**
的证词是 `` `no_manifest_row_count` = **50** `` —— 一条**非零**的读数,**而它的判据目标正是 0**,
所以 50 恰恰是「此刻未满足」的如实记录。**词表版会把它判死**。
⇒ 最终条款**不要求值为零**,只要求**记了一个值**。
📌 与 RULING 46 同一条通例:**建判据之前先在今天的树上跑一遍它 —— 不是看它能不能跑,是看它今天说的话对不对。**
