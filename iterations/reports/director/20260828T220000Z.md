## 3. ⭐ 本轮实质产出:**#286 §4 item 1 字面的修法不成立**

issue 建议「把 nil 头部的处理提到 `#` 门之外」。**那个处理器用 `table.remove(t, 1)` 排空,
而 `#t == 0` 时 `table.remove` 什么都不移** —— 实测,不是推断:

```
t = {'a','b','c','d','e',nil,'g','h'}   -- #t == 8
5 × table.remove(t,1)                   -- t[1]=nil, #t=0, next(t)=5
再 table.remove(t,1)                    -- 所有 key 逐字节不变,#t 仍为 0
```

两条后果,**承重的是第二条**:

1. 提上去的处理器**每一帧撞同一个洞** ⇒ **永久「停」变成永久「转」**,一点也没多花;
2. 它那句 `return` 会**遮住 `:331` 的重建** —— 而按 issue 自己第三步的推导,
   **那是今天唯一一条自救路**。⇒ **这个修法会让六局里唯一好的那局也坏掉。**

**⇒ 落地的是「按 key 序压实」,并且不 return。**
