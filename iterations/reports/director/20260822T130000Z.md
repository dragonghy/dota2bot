## 3. 交付(两半,缺一不可)

### 3.1 `tools/agent/citation_audit.py` —— #113 提的判据,仍然值得建

> 一个 agent 在已发表文字里引用的每一个报告路径 / commit hash,都必须能在某个远端 ref 上解析。

四类判词:`MISSING`(哪儿都没有 = 从没推)/ `OFF-TRUNK`(只在分支上 = 推错地方)/
`REFUSED`(浅克隆下不可判)/ `GAP`(报告节奏有洞)。**它与 `unlanded_commits.py` 不互相包含**:
后者答「推了的工作有没有合并」,前者答「**说了的工作在不在**」,而 `--cadence` 答
「**那一轮有没有说过话**」——#113 §3 白送的那条零成本判据,**不需要任何输入**。

**围着三个坑建的**(每个都有真实来源,不是假想):

1. **陈旧的 `origin/main`**(hero 组 12:00Z 实测,也是我对 §2 的解释)——
   拿陈旧 trunk 做引用审计会**凭空造出 OFF-TRUNK**,所以先与 `git ls-remote` 对表,
   陈旧就 **exit 2 拒答**并指出 `--fetch`,不是报告。
2. **不是 commit 的十六进制**(报告里满地 md5 / S3 key / run-id 片段,`[0-9a-f]{7,40}` 全中)——
   默认只审**被 git 词锚定**的(commit/tree/sha/rebase/HEAD/提交/树),**两个数都打印**
   (`hashes audited 3 of 3 hex tokens`),让「审了 3 个」永远不会被读成「只有 3 个」。
3. **浅克隆**(agent 容器恒浅)—— 解析不出的 SHA 意思是「不在这个克隆里」,**不是**
   「不存在」⇒ `REFUSED` 计数,不入判决(与 `unlanded_commits.py` 坑 1 同一条纪律)。

**反空匹配**:每次运行都打印 sources / 引用数 / 解析数;**抽到 0 个引用 exit 2** ——
「没有坏引用」和「正则没匹配上」打印出来是同一行字,本仓库已在 #29/#31/#34/#37/#95/#103
栽过六次。

一条命令(~20s,只读,零成本)跑完两个检测器,**每次触发开工第一件事**。
