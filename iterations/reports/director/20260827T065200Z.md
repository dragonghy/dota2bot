## 四、修法:两个独立缺陷,两个独立修法

**(1) 那个开关从来就不是语料。** 它 gitignored、farm-only、只装一个 table 字面量 ——
没有 guard、没有技能读、没有任何普查在问的东西。它对普查的**唯一**作用,
就是让答案取决于「某个 gate 测试是不是正在飞」。
新建 `tools/agent/lua_corpus.py`:**唯一的**语料列举 + **按名字**排除它。
**这是在源头上消掉竞态,不是让竞态可存活。**

**(2) 「读的时候没了」对其余每个路径仍然可能**(并发 checkout、编辑器、将来的生成文件),
而那里诚实的裁定是**「这次扫描没跑成」,不是「计数变了」**。
`read_lua()` 为这一种情况抛 `CorpusVanished`,`uncertifiable()` 把它变成**退出码 2 + 横幅**。

**⭐ 为什么是 2 而不是失败**:读不到输入的普查**没有答案**;计数变了的普查**有答案、并且说它错了**。
两者**授权相反的下一步**,而在本轮之前它们**打印得一模一样**。
0 干净 / 2 没跑成 / 3 有发现 —— 与铁律 10 的 `UNCERTIFIABLE`(#171)、
推送门的 could-not-run(#213)**同一套词汇**。

**⭐ `CorpusVanished` 故意不继承 `OSError`**:调用点里写着
`except OSError: continue`(`test_soak_cand_ref.py` 就有一处)——
让它能被吞掉,正是「没跑成」变成「数少了」的那条路。已钉成断言。

**迁移的 6 个调用点**(全部是 `bots/` 上的 walk-then-open):

| 文件 | 改法 |
|---|---|
| `tools/agent/ability_value_key_census.py` | `hero_files()` 委托 + `read_lua` |
| `tools/agent/guard_implication_census.py` | `--all` 目标 + `scan_file` 的 `read_lua` |
| `tools/agent/talent_name_binding_census.py` | 同上 |

| `tests/test_canon_hero_join.py` | roster 的内联 walk+open |
| `tests/test_guard_implication_census.py` | `ALL_LUA` 的自建 walk + `repo_scan` 的守卫 |

链路两端也接上了:`tests/run_py_tests.sh` 把退出码 2 计成
`UNCERTIFIABLE`(**不是 pass**,整体仍退 2);
`tools/agent/routine_selfcheck.sh` 的 python 腿对 2 打 `UNCERTIFIABLE` + `note 2`,
**不再打 `TRUNK RED`**;真失败仍然 `TRUNK RED` + `note 3`。

**⚠️ 一处逐字等价性是核过的不是假定的**:两处把 `readlines()` 换成
`splitlines()` / `splitlines(True)`。二者在 `\f`/`\v`/` ` 上行为不同,
所以**逐文件量过**当前 `bots/` 全部 `.lua`:**行数差异 0 个文件**。
