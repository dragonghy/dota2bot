## 1. GH #225 是什么(用它自己的数字)

标准收割是「把四个 run 的 `*.analysis.json` 拉下来喂给 `recover_verdict.py`」。工具 header 给的
用法是**单 run** 的,而每波是 **4 个 run(4×1,一台一粒种子)**,于是最自然的做法 —— 四个 run
`cp` 进同一个目录 —— **静默丢局**:

| 口径 | 落地文件 | `scored_games` | `mean gpm` |
|---|---|---|---|
| 平铺进一个目录 | **188** | **170** | **−40.38** |
| 加 `<run>__` 前缀 | **208** | **184** | **−36.81** |

根因:每局文件名是 `<YYYYmmdd_HHMMSS>_slot<N>.analysis.json`(`soak_loop.sh:76`),**不带 run
token**;四台同一秒发出、槽启动节奏一样 ⇒ 跨 run 撞名**是常态不是偶发**(W14 一波撞 20 个;
08-23 那波也撞过 22 个)。

**值得单修的理由是失效方向**:`recover_verdict.py` 只看得到落地的那些文件,少了 20 个照常算、
照常给 `suggested`,**没有任何东西举手**。`scored_games` 会跟着变小,但**没有期望值可比**
(排空局数每波都不一样:W12 23 / W13 24 / W14 24),所以 170 看上去和 184 一样正常。

## 2. 落地的修法:(A)+(B),按申请方推荐

### 2.1 (A) 池化不再需要重命名

收集改成**按路径递归**(`glob(root + "/**/*.analysis.json", recursive=True)`)。`**` 能匹配零层
目录,所以 header 里原来的**单 run 平铺用法逐字不变**;新增的推荐路径是给每个 run 一个子目录、
把工具指向父目录。

### 2.2 (B) 三条 REFUSAL(exit 2,`rec_slot_cost.py` 的房风)

| | 触发条件 | 逃生阀 |
|---|---|---|
| **R1** | 同一 basename 在 >1 路径上且**字节相同** ⇒ 同一局数两次 | 无(删掉多余那份) |
| **R2** | **一个目录**里出现 >1 个种子的**裸 tag basename** ⇒ 平铺的多 run 池 | `--allow-pooled-basenames` |
| **R3** | 文件解析不了(原来是 `except Exception: pass`) | `--allow-unparseable` |

**R2 的判据是「一个 run 一个种子」**(`mirror_ab.sh` 把 SEED 当参数、两个 wave 顺序跑),所以
同一目录里两个种子的裸 tag ⇒ 这些文件来自 >1 个 run ⇒ `cp` **已经有过覆盖的机会**。裸 tag 的
定义钉在 `soak_loop.sh:76`(`^\d{8}_\d{6}_slot\d+\.analysis\.json$`),**批测台现行的 `<run>__`
前缀不匹配它,不会被误拒** —— 这条临时纪律继续用也没问题,只是不再必需。

两个逃生阀按 #205/#213 的形状:`--allow-pooled-basenames` 往 stderr 打
`R2 SKIPPED, NOT PASSED. Losslessness ... is UNVERIFIED.`,并在 JSON 里留
`input.pooled_basename_dirs_overridden`。**拒答不是通过,跳过也不是通过。**

### 2.3 ⭐ R1 的谓词两半都是承重的 —— 第一版被自己的用例逮住

第一版 R1 写的是「**任何**两个文件字节相同 ⇒ 拒」。它当场把 `tests/test_verdict_winrate.py`
一起拒了(那份用例的语料是同一个模板重复出来的,**多局逐字节相同**)。收窄成
**(basename, 内容) 都相同**才算重复:

- 同 basename、**内容不同** = 正常跨 run,**正是 (A) 存在的意义**;
- 内容相同、**basename 不同** = 两局碰巧打成一样,合成语料的事,不是重复。

**一个把现有用例一起拒掉的修法不是修法。** 已把这半条写成用例 8。

### 2.4 输入普查,每次都打

```json
"input": {"files_seen": 24, "games_loaded": 24, "source_dirs": 4,
          "unparseable": 0, "pooled_basename_dirs_overridden": 0}
```

立这条的理由就是 §1 那句:`scored_games` 没有期望值可比,而 `files_seen` **可以**跟 S3 的对象数
对账,`source_dirs` 直说池化有没有被平铺。**能核的数强过要信的数。**
