## 2. 交付的是分母,不是命中数

这是本轮唯一要记住的一句。

条件 (a) 今天的答法:人从**一局**录像里挑**一个**瞬间,`make_fixture.py` 冻住它。
那回答的是「**这里**这个决定对不对」。它回答不了 promote 真正要问的那句:

> 在这条规则**适用**的那些帧里,它在多少帧上真的生效?

那句话要一个**人口**,而人口要一个**有人算过的分母**。

`tools/batch_test/replayscope/corpus_query.py`:跨多局扫 timeline,
对每个 (英雄, 快照) 帧求一个声明式谓词,报 matched/examined
并**把每一个被排除的帧按名字记账**,再把幸存帧成批喂给 `make_fixture.py`。

三条老规矩写进了**构造**,不是写进散文:

1. **复用不重造(GH #67)** —— Timeline 解析、英雄名 canon、赛后尾巴切除、pause span、
   **ancient-distance 深度**全部 import 自 `behavioral/detect.py`。
   x+y 深度启发式曾经差点把一个结论弄反;**本仓库只有一个 depth 函数,这个文件没有加第二个。**
2. **fail loud 不兜底(`source_constants.py` 的契约)** —— 未知 term / 未知算子 /
   参数个数不对 / 多余的键,全部 raise,**没有 `default=`**。
   一个把未知 term 静默判 False 的谓词会报出一个**干净、可信、错误的零**。
3. **不许有静默的截断** —— 够不到谓词的每一帧都归入一个**有名字**的桶,
   工具在打印任何东西之前**断言等式**,不平就 abort:
   `frames_total == postgame + out_of_window + paused + dead + examined`。

## 3. ⭐ 写的过程里被自己的规矩抓到两次

两次都是同一个形状,**而这个工具整篇散文都在讲这个形状**。

### (甲)我自己的分母一开局就低了 37%

第一版跑合成语料报 `frames_total=304`,而语料文件自己有 **484** 行。
差的 180 行是 `detect.Timeline` 在**上游**丢掉的 **GH #130** 赛后 ~25s 冻结尾巴。

⇒ 加 `postgame` 桶,`frames_total` 改为对齐**语料文件自己的快照行数**:

```
CORPUS frames_total=484 postgame=180 out_of_window=0 paused=0 dead=2 examined=302
```

**可推广的教训**:一个「上游已经过滤过」的输入,**它的过滤量必须由下游重新点出来**。
上游丢得对不对是另一回事 —— **分母里少了一块永远是错的**。

### (乙)写下的规矩和落地的代码差一行

叶子子句原本按全局 `examined` 计分,而 `all` 是**短路**的:
后面的子句只被喂到前面子句放行的帧 ⇒ 按 examined 计分会**系统性低估**它们。
改成每条叶子带**自己的** `reached`:

```
CLAUSE true=232/302 reached  hp_pct lt 0.95
CLAUSE true=47/232 reached  enemies_within(3000) ge 1
```

要紧的是**怎么被抓到的**:我在注释里写了
「the summary prints the reach denominator alongside it」,**然后并没有印它**。
和上一轮 §① 那个「批准只落在 header 上、没落进机器读的 §x.0」是**同一个病**。

### (丙)两种空谓词现在有名字

`VACUOUS` = 这条子句**一帧都不选**(物品名拼错、语料里从没点出来的技能、阈值方向反了);
`INERT` = 它**一帧都不排除**。
两种在纯命中数里都是隐形的,而两种都会让一份「人口」报告完全无意义。
