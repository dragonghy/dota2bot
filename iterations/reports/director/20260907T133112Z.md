## 1. 结论:**不是行为回归。`bots/` 在红出现的那条线上逐字节相同。**

`test_lf_rescue_final_action.lua :: [census]` 断言 `c.armed_none <= 1`,读到 2。
被点名的两帧里 **Lina 那帧本来就是那一个被枚举的例外**,真正新增的只有
`f_260820_043124_axe_blink_flee_529.lua/npc_dota_hero_axe` 一帧。

**它不是「变哑了」,它是新进了普查的命中集。**

元凶 commit 由录像组二分锁定为 `b4d5f01f`(总监 GH #492 执行:给 fixture loader
补 `GetExtrapolatedLocation` 桩),**`bots/` 零改动,动的是 `tests/mock/replay_fixture.lua`**。
录像组把机制标为「没锁定」,并明确排除了第一个看着解释得通的假设
(`J.CanEnemyInterruptTpChannel` 在这两帧上答 `false`,不是 `true`)。
**那个排除是对的,而它排除掉的是结论的后半段,前半段在另一个方向上。**

### 机制,一台文件拷贝还原台量出来的两个读数

台子:把 `tests/mock/replay_fixture.lua` 拷走 → 删掉 `b4d5f01f` 新增的那三行
`GetExtrapolatedLocation` 桩(**只删那三行**)→ 复跑 → 拷回。

| loader | `pcall(J.GetRescueTpTarget, axe)` | 该帧在普查里 | `test_lf_rescue_final_action` |
|---|---|---|---|
| 无桩(`b4d5f01f` 之前) | **`false`** — `jmz_func.lua:2908: attempt to index local 'sLoc' (a number value)` | **不是命中**(被 `pcall` 吞掉) | **12 tests / 0 failures** |
| 有桩(当前 main) | `true` → `npc_dota_hero_sniper` | **是命中**,且驱动后静默 | 12 tests / **1 failure** |

`sLoc` 那个 number 就是 `bot_api.lua` 的 `^Get -> 0` 兜底 —— 桩不在时
`GetExtrapolatedLocation` 落到兜底返回 `0`,消费者按位置索引 `sLoc.x` ⇒ **抛错**。
抛错发生在 `J.GetRescueTpTarget` **内部**,而普查的预筛是
`local okr, ally = pcall(J.GetRescueTpTarget, bot)` ⇒ **抛错帧被静默地从语料里删掉**。

⭐ **这正是 `b4d5f01f` 自己在低一层写下的那句话,原样适用于高一层:
「A raise is not a reading.」** 那个 commit 修的是「两个 sweep 用两桶 `pcall` 把抛错
记成『测过了,答否』」;它修完之后,**同一个缺陷在 `test_lf_rescue_final_action`
自己的预筛里原封不动地又发作了一次** —— 只不过这次抛错消失了,于是被审查掉的帧
回到语料里,普查的计数就动了。**修好一层的审查,会让上一层的计数移动,而移动的方向
只能是变多。**

### 驱动后为什么静默:**已经被枚举过的那条守卫,第二次出现**

同一台上直接读该帧:

```
nearby enemy towers (888, enemy) = 1
GetRescueTpTarget                = npc_dota_hero_sniper
GetNearbyLocationToTp            = (191.84, 182.64)   -- 不是 nil
drive actions                    = 0
```

`aiug` 的 `local nNearbyEnemyTowers = bot:GetNearbyTowers( 888, true )` /
`if #nNearbyEnemyTowers > 0 then return BOT_ACTION_DESIRE_NONE end` 在**救援分支两行之上**
就返回了。这与文件里给 Lina 写的理由**是同一条守卫**(GH #37 frame B)。
⇒ 按 #594 的验收提醒,这是「**枚举例外该扩**」那一侧,而且是带理由的那种。

## 2. 处置:**不是把 `<= 1` 改成 `<= 2`** —— 改成按名字枚举,两个方向都红

`<= N` 有一个 #594 恰好演示了的洞:**它允许一个例外被另一个例外悄悄换掉**,
而且 N 正是「loader 修好一点就会移动、原因完全在 `bots/` 之外」的那个量。

新增 `SILENT_ARMED`(帧 + 主语 + **理由**),普查断言改成两条:

1. **每个实测静默帧必须在名单上** —— 不在就点名报红,报错文本里直接写上
   「不要只放宽计数;先确定它是行为回归还是**被 fixture mock 审查过的帧**」。
2. **名单上每个帧必须仍然静默** —— 不静默就**点名说是哪一帧**(而不是只报两个数不等)。

配套把 `[census] the one silent armed frame ...` 改成 `... every silent armed frame ...`,
按名单逐帧**重新求证两半**:敌方塔在 888 内(读帧)+ 驱动后零动作(跑出厂链)。
⇒ 一个**因为别的原因**变静默的帧,即使计数仍然闭合,**也会在这里红**。

`b4d5f01f` 的整段来龙去脉(含上表两个读数)写进 `SILENT_ARMED` 上方的注释,
连同那句可迁移的一半:**fixture-mock 一落地,这文件里的计数就会因为与 `bots/` 无关的
理由移动 —— 先查 loader,再猎回归。**
