## 2. 裁定一:`zusult` 不 promote —— (b)「**未被测量**」

录像组 §4 交出 `zusult_gate.py` 的输出(armed 7 局 / base 5 局,`clean_opp_frames` 7:2,
`in_domain_casts` 1:0),写「(b) 同样不可测」。**我读了那份工具的源码**(不是转述),
结论比「不可测」更具体也更可修。

### 2.1 那份证据是结构性单向的(总监自己的核验)

`tools/batch_test/behavioral/zusult_gate.py` **docstring 第一行自称
`zusult (a)-evidence scanner`**。它 `totals` 里聚合的两个数:

- `opp`(L78-91)= 门**会拒绝**一次施法的帧数(R 就绪且不可负担 + calm 代理 + 900 内有健康敌英雄);
- `dom`(L109)= 域内**真的施法了** = 门**没拦住**的漏放。

**两个都在计量「门有没有听话」,没有一个在计量「门拿走了什么」。**
`unaff_frames` 虽然算了(L111),但**只逐局打印、不进 totals**,而且它是时长、不是「被扣下的出价」。

⇒ 条件 (b) 在这份证据上**任何方向都不成立**:不能发通行证(§A0 的老陷阱),也不能判有害。

### 2.2 为什么这次特别要紧

GH #59 已经证明该门的**有效域恰好是「储备已经花掉之后」**:它做的事就是**在 R 就绪但买不起时
扣住所有 chip 施法等回蓝**。**扣住才是它的主要产出**,而现有证据对主要产出的观测量是 **0**。

#59 自己那段逐帧(`20260820_042607_slot1`,t=463.5–491.5 **连续 57 帧扣住** → t=492.2 Zeus
攥着 116 蓝、R 就绪且仍买不起**死了**)**正是这个门按设计工作时的样子**,不是缺陷 ——
它究竟是好是坏,现有指标一个字也没说。

### 2.3 (b) 可判的最小口径(已交录像组;现有语料够用,**不需要新花钱**)

两侧**按种子配对 + 按局归一化**(批测台 12:08Z §3:本波 Zeus 候选侧局数 **+23.8%**,裸计数必假阳性):

1. **域内施法率** `dom/opp`,armed vs base —— base 的 `dom/opp` 是**反事实基频**,
   armed 相对它的下降 = **被扣下的出价量**。这是唯一能观测到「扣住」的办法。
2. **扣住的时长**:`unaff_frames` 进 totals + 门为真的连续段长度分布。
3. **扣住的兑现率(最关键,决定 (c) 还成不成立)**:每个扣住段之后 Zeus **是否真的攒到 R 并放出来**,
   以及**攒到之前先死的比例**。**这一条就是 `zusult` 的价值主张本身,至今一次没被量过。**

**处置**:留 eligible、可随集 armed(两臂常量),1/2/3 出来之前**不得 promote**。
`zusultx` 裁定不变(不与 `zusult` 同波 arm),且多一条理由:在 1/2/3 之前 arm 它,
只是把一个**未被测量**的门加宽。

## 3. 裁定二:`cmrguard` 不 promote —— (b) **有**双向证据,而证据说「现在这版不是该发布的版本」

与 `zusult` **相反**:`cmrguard_precision.py` 真的给否决侧定了价(帧级 lift 39.9% vs 8.5%,
episode 一票制 34/86=40%),#63 又量了封锁时长。所以本轮**不是**「测不出来」。三条理由:

### 3.1 事件率路线已经走到头,加局无用(采纳录像组 §3.2)

全语料 CM 开大 **11 次**(armed 5 / base 6),差值 = **1 次**。瓶颈是 **~1 次开大/局的基频**,
不是样本量;`ConsiderR` 本身还要 ≥3 敌,门与它的域**交集本来就稀**。

### 3.2 按「每次事件的账」读,现在这版是差的

精确率 **~40%** / 召回 **1/4**(#66)。**两个端都正在被改**:#63 收窄精确率一侧、
#66/`esaftershock` 补召回一侧(英雄组自陈只补得上一半)。
**promote = 把「我们已确知马上要改的那一版」冻成默认** —— 这正是 08-19T11:10Z 我把 `cmrguard`
第一次踢出 armed 集时用的理由(`[bug] #31` 的教训),**方向反过来同样成立**。

### 3.3 一条本轮自己从源码读出的机制事实(没人写过,它把「误否决」的定价改了)

`X.cm_IsRSafeToOpen` 的谓词是**瞬时**的,而它保护的是一次 **10 秒**自缚读条;门为假时
`ConsiderR` 直接 `return BOT_ACTION_DESIRE_NONE`(`hero_crystal_maiden.lua:958-965`)。

**在一场团战里,「1600 内有个手握就绪硬控的敌人」这个条件不会自己解除 —— 敌人是在靠拢,
不是在离开。** 所以**一次否决不是把大招推迟几秒,而是把它整场战斗地取消掉**。
⇒ 60% 的误否决,**每一次的代价是一整个冰封禁制**。

这同时解释了 #63 的一处表面矛盾:为什么能量到「78% 封锁时长可砍」而开大次数几乎不变 ——
**门大部分时间关着,只是 `ConsiderR` 大部分时间本来也不想开**。⇒ **「封锁时长」这个指标
本身高估了收窄的收益**;真正的收益要按**与 `ConsiderR` 想开的帧的交集**算。已要求 #63 补这条。

## 4. §0b 第十七例(新亚型:**检测器计量的是规则的服从度,不是规则的后果**)

前十六例讲「作者的推理被下游/环境作废」。这一例是**测量侧的对偶**:

> **抑制型规则(gate/veto/withhold)的执行检测器,天然只看得见「漏放」、看不见「扣住」——
> 因为被扣下的动作不产生任何事件。于是一个完美服从且有害的门在它自己的检测器上得满分。**

**推论 ①**:**(a) 的检测器 ≠ (b) 的检测器**。(a) 问「它跑了吗」(漏放率够用);
(b) 问「它拿走的东西值不值」,**必须显式计量被扣下的那一侧**。
用 (a)-scanner 的输出写 (b) 结论,就是本轮 `zusult` 踩到的坑
(**工具 docstring 第一行就写着 `(a)-evidence scanner`**)。

**推论 ②**:被扣下的动作**只能用对照臂反推**(同域**施法率**,按种子配对 + 按局归一化),
**不是任何单臂计数**。**任何抑制型 id 申请 promote 必须附这条反推的数字。**

**已提前知会各组**:`capmono` / `tpdying` / `tpdead` / `defstale` / `retnear` / `towerreach`
**全属抑制型**,(b) 都要按这条准备,别等到判定时才发现只有服从度数据(`test_set.md` §R.3)。
