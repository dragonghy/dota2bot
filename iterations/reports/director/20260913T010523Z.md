## 2. 量到的事实(§HI.1)

git **每一次 `git push` 调用**跑一遍 `pre-push`,而规定的推送路径是两条命令
(`git push -u origin <branch> && git push origin HEAD:main`)
⇒ **每次尝试在一棵逐字节相同的树上跑两遍三条腿。**

一次性 repo 实测(裸远端 + 计数钩子,同一 commit 推到两个 ref):

```
hook invocations: 2
HEAD=77f12e7421b4… TREE=c1943e26e89b…   (两次相同)
```

## 3. ⭐⭐⭐ 立案句:**理由不是浪费,是竞速 —— 而输掉竞速的恰好是那次冗余的运行**

09-12T22:2xZ 的现场:门 ~7 分钟(快 Lua 腿 380s,占 90%),main 每 ~7 分钟动一次,
`HEAD:main` 连拒三次(**全是 ref 竞态,没有一次是门红**),烧掉 ~21 分钟零产出,第四次走 `RULE6_BYPASS=1`。

📌 **输掉竞速的永远是第二次推送,而第二次推送在结构上不可能回答出与第一次不同的答案** ——
三条腿读的是工作树,两条命令之间没有任何东西碰过它。
⇒ **一道慢到输掉自己必须赢的那场竞速的门,会把人赶进它自己的逃生门。**

这也是为什么本轮选的是「消掉第二遍」而不是「降预算」:降预算要**减少被检查的东西**,
而消掉第二遍**一个测试都不少跑**,并且只动那处**可证明是重做**的工作。

## 4. ⛔ 它不是 `RULE6_BYPASS`,横幅也不许被读成那样

bypass **什么都不断言**;命中是**重放一次真实运行**在**这棵完全相同的树**上得到的读数。
「铁律 6 静态半在被推的这棵树上是绿的」这句话命中与未命中同样为真;
变的只有**是谁、在什么时候**做的那份工,而横幅两样都写:

```
RULE6_MEMO=REUSE  a green three-leg reading taken <UTC> on THIS EXACT tree.
  This is a REUSE, not a skip: all three legs really ran, on
  HEAD^{tree}=… with origin/main=… and a clean working tree.
```

四条 fail-closed:
键 = `HEAD^{tree}` + `origin/main`(快 Lua 腿用 `origin/main...HEAD` 定域,基线动了就是**另一个问题**)/
工作树必须干净(**含未跟踪** —— 腿 lint 的是磁盘上的东西,不是 commit 里的)/
**只有全绿才存**/ 任何异常一律**未命中**。
`RULE6_NO_MEMO=1` 强制跑满三条腿(买第二份独立读数的出口)。
