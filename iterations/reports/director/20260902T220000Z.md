## 1 GH #420 —— 缺陷不是「少一行」,是两个桶的键选错了粒度

### 1.1 现场,在本轮自己的树上复现

开工自检的 python 腿逐字打:

```
FAIL  tests/test_detector_source_constants.py
UNCERTIFIABLE  tests/test_rc_wrapper.py  (did NOT run -- this is not a pass and not a failure)
UNCERTIFIABLE  tests/test_selfcheck_lua_leg.py  (did NOT run -- this is not a pass and not a failure)
75 passed, 1 failed, 2 uncertifiable
```

而**同一次运行的**汇总块打 `UNCERTIFIABLE (exit 2): none`。
不需要构造,**本轮的工作树就是**(#420 的复现节逐字预言了这一点)。

### 1.2 为什么两个桶装不下它

`_sc_findings` / `_sc_uncertifiable` 是**按腿的 `note` 等级**分的,**而一条腿只有一个等级**。
一条既红又有没跑成的 python 腿 `note 3` ⇒ **整条**进 `FINDINGS`,
它**内部**那两个没跑成的测试**没有任何桶可以进**。

⇒ `UNCERTIFIABLE (exit 2): none` **在腿粒度上是对的**,
而**它被读的粒度是「这轮有没有东西没人看过」**。这一格落进 `none`,
而 GH #267 4b 立这个块的目的**恰恰**是让归因不再手做。

⭐ **同一句话,wrapper 自己在一年前就写下过 —— 写在腿体里,没写到汇总块**:

> `uncertifiable:` is in this alternation on purpose. A run can be BOTH red and
> un-run … The exit-1 branch reports the strictly worse tree, so it was the
> branch that named LESS of what was wrong.

腿体按这句话修好了,**汇总块保留了同一处遗漏,只是高了一层**。
