## ③ ⛔⛔ 头号:**读方向只是症状,写方向真的落到了生产上**

上一轮(和 #795)把这件事写成「memo 在干净树上把一份 CLEAN 发还给被测试故意弄红的树」。
**那句话是对的,但它描述的是这条缺陷的第二跳。** 第一跳是:

📌 **memo 的键 `(HEAD^{tree}, origin/main) + 工作树干净` 全部是关于「这个仓库」的,
而 `PY_GATE_ROOT` / `LUA_GATE_ROOT` 这一族改道变量把第 2、3 条腿真正读的东西**搬走了**,
键**看不见这件事**。** `test_py_gate_hook.py` 从**真仓库**驱动**真钩子**(它测的是钩子的接线),
于是它的**对照用例(全绿那个)**把一棵**两文件临时树**的读数,**存进了 trunk 自己的键**。

**12:55Z 在干净 trunk 上的第一手读数**(本轮开始时它就已经躺在那里,是开工自检刚写的):

```
.git/rule6_memo/4dcd50c7d0748ca1aaf7796cf17c4efb.json
  tree = 47de5248…  base = fdf5461c…   at = 2026-09-13T12:55:00Z
  readings = "GATE_EXIT=0  CLEAN …\npy gate: 1 ran, …, 0.0s\nlua gate: 1 ran, …, 0.0s"
python3 tools/agent/rule6_memo.py key → MEMO_KEY=4dcd50c7…   ← 同一个键,即当前树
bash tools/agent/rc.sh python3 tools/agent/rule6_memo.py get → RC_EXIT=0
  横幅逐字:"all three legs really ran, on HEAD^{tree}=47de5248… and a clean working tree."
```

⇒ **那一刻,这个容器上的 push 闸是关着的。** 任何一次 `git push` 都会拿到这条回放,
**三条腿一条都不跑**,并打印那句「真的都跑过了」。
📌 **立案句:一个为提速加的 memo,被一条测试喂了假读数,于是它替 push 闸说了一句它没有资格说的话 ——
而这比 `RULE6_BYPASS` 坏,因为 bypass 会打印「这是跳过不是通过」,它打印的是「跑过了」。**
⚠️ 同时这解释了**为什么没人举手**:`py_gate.py` 自己是绿的、钩子退出 0、push 成功,
**唯一会尖叫的那个测试,就是喂毒的那一个**。

## ④ 修法(commit `6c5d9f4e`)

`tools/agent/rule6_memo.py::memo_inputs()`:在**任何 git 调用之前**,
若 `PY_GATE_ROOT` / `PY_GATE_MANIFEST` / `LUA_GATE_ROOT` / `LUA_GATE_MANIFEST` 任一被设置,
返回 `unavailable` ⇒ **`get` 与 `put` 都 exit 2**。

- ⛔ **没有把它们加进键**:被改道的那次运行**根本不是对这棵树的读数**,没有任何键值得存。
- ⛔ **`RULE6_NO_MEMO=1` 不是替代**:它压住**读**,**留下写** —— 毒条目照样落地。
- ✅ **memo 对真 push 的提速一字未减**(真 push 不设这些变量);本轮 push 自己就是那条证据(§⑥)。
- ⭐ 两条 gate 本来就会打印 `PY GATE REDIRECTED -- … (not the repo's own)` ——
  **改道这件事一直在被说出来,只是 memo 从来没问过。**
