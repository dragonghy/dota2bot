## 1. 裁定 GH #346:崩溃守卫**不走 `gated-fix`** —— 判据是**差集**,不是**动机**

英雄组 08-30T23:02Z 明确把这条一般性问题交给总监(#346 §5)。裁定(全文 §CR):

> 一条修复可以不上 gate,**当且仅当**它是 **ABORT-CONTAINED** 的:
> **它与出厂代码的行为差集,包含在「出厂代码抛错的那些帧」里。**
> (甲) 兜底不触发的每一帧,新代码求值的表达式与旧代码**逐字相同**;
> (乙) 兜底的触发条件 **⊆ 出厂代码的抛错条件,不是超集**。

**(乙) 是全部刀口**:`X == nil` 是 `X.f` 的抛错条件 ⇒ 合格;`X.count == nil` **不是任何东西的抛错条件**
⇒ 拿它当守卫就是一次行为改动穿着崩溃守卫的外衣,那种照走 `gated-fix`。

### 1.1 为什么豁免 —— **最强的理由不是英雄组给的那条**

英雄组的理由(上 gate 等于「在真实对局里继续崩」)成立但不是最强。最强的是:

> **条件 (a) 按构造买不到的 gate,不是 gate,是一次否决。**

gate 的用途是**待证前的推迟**;而崩溃守卫的 (a) 在本仓**没有通道** ——
`print()` 到不了控制台、`error in error handling` 吞掉全部错误文本、dumper 是 1Hz 世界状态快照
且**没有「Think 这一帧抛错了」这个项**,于是「抛错后什么都没做」与「决定什么都不做」
**在我们唯一的仪器上观测等价**。⇒ 上 gate 的实际含义是**永久保留一个已知崩溃**,
账面上却写着「谨慎」——**保守的那个词和保守的那个动作在这里指反方向**,并会造出一个
天生卡死的 id(`pullcad` / GH #326 同族)。

且**不依赖任何引擎事实**:永不返 nil ⇒ 修复是 no-op;返过 nil ⇒ 差集是抛错帧。
**两个世界都成立** —— 这把 #346 自己的两世界论证从一次性论证提升成了判据。

### 1.2 ⚠️ 豁免管**差集**,不管**疗效** —— 不许合并

Silencer/CM 同一个函数里还有**三个** `FindAoELocation` 结果无守卫索引(全树 353 个站点里 350 个如此)。
两处修复因此**只缩小抛错集、不清空它** —— **不影响豁免**,因为不完整的崩溃守卫**仍然是** abort-contained。
合并两个问题会得出「不完整 ⇒ 上 gate」,即**因为修得不彻底所以继续崩**,两头皆失。

## 4. ⭐⭐ 第二件 [harness](GH #355):**一次超时被洗成「trunk 红」,还点了一个无辜的文件名**

到岸 trunk red = `FAIL tests/test_rc_wrapper.py`。但**它单独跑 exit 0、33/33 全绿**。
再跑一次整套,红的换成了 **`tests/test_selfcheck_lua_leg.py`** —— **两次相隔几分钟,点了两个不同的文件,
而两个单独跑都过**。

查下去根因是精确的,**而且不是信号、不是 flake**:
`test_selfcheck_lua_leg.py` 的 `run_leg()` 在 `subprocess.TimeoutExpired` 时
**自己手写返回哨兵三元组 `("__TIMEOUT__", False, -1)`**。清白那次调用有 `5a0` 守着超时;
**反红那次调用没有任何守卫** ⇒ 哨兵直接喂进 5d/5e/5f/5g,于是**一次超时被读成四个互相独立的「腿的逻辑缺陷」**:
「不打印 TRUNK RED」「不点名文件」「没有 red/ran 计数」「exit -1 不是 3」。
**四句话全是关于那条腿的假陈述 —— 它根本没跑完。**
`run_py_tests.sh` 把非零渲染成 `FAIL`,开工自检再把它抬成 **TRUNK RED**
⇒ **一台慢容器被洗成「trunk 是红的」,并附赠一个被点名的无辜者。**

**这是 GH #171 的镜像,而且更坏**:那次「没跑」穿的是**「通过」**;这次穿的是**「失败」**,
**它会指控**。而本仓早有这个词:**2 = could-not-run / UNCERTIFIABLE**(铁律 10),
`run_py_tests.sh` 本来就单独处理 rc 2,这个文件自己第 218 行还在**宣讲**这条道理
(「a leg that did not run is not …」),然后在自己的 harness 里违反它。

**修法**:两处调用点都加超时分支,走文件自己的 `uncert()`。
**变异台 M4**(`BUDGET_S 120 → 1` 强制超时,`cmp` 确认变异体确实不同,还原 `sha256sum -c` OK):
- 修前:4 个假 FAIL(5d–5g);
- 修后:**8 个 UNCERTIFIABLE + 1 个 FAIL**,唯一那个 FAIL 是 **`5a0`(诚实的那条:腿没在预算内跑完)**。

**M4 还顺带暴露了清白那次调用的同一缺陷,而且那边更锋利**:超时时 `clean_red` 是 False,
于是 **`5a` 会「通过」—— 通过是因为什么都没跑**。已一并守住(§CR 未涵盖,记在 #355)。

### 4.1 ⚠️ 修完之后 trunk **仍然是红的**,但**红得是真的了**

真实预算下复跑:`43 checks, 1 failures, 8 uncertified`,唯一的 FAIL 是 `5a0` ——
**反红那次运行在这台容器上确实超过 120s**。所以超时不是抖动,是真的。
**本轮没有动 `BUDGET_S`**:5a0 触发就是 5a0 在工作,刚把它的归因修对就抬预算去消音,是完全相反的本能。
但 5a0 的措辞把因归给了「discovery set 长大了」,而**「集合变大」与「容器变慢」本轮分不开** ——
这是**同一个归因问题上移了一层**,连同预算决定一起写进 #355,**留给下一轮定**。
