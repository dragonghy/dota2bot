## 1. 为什么这条待办的措辞本身是错的

`test_set.md` AJ.5 登记的原话是「把这个代理**收敛成一处带出处的常数**」,并列了四处副本。
**我按它做之前先去读了每一处到底在说什么,结论是它们不是一个东西:**

| 站点 | 它其实是什么 | 处置 |
|---|---|---|
| `roam_conversion.py:61` `VICTIM_HP` | **PROXY** —— 站在一个 dumper 看不见的谓词前面 | **定义点**,其余 import |
| `lanekill_commit.py:86` `VICTIM_HP` | 同一个 PROXY,手打的副本 | 改成 import |
| `find_kill_windows.py:28` 内联 `0.40` | 同一个 PROXY,**而且它不产读数、它选帧** | 改成 import + 提名 |
| `lanekill_commit.py:88` `ALLY_HP_MIN` | ⭐ **MIRROR** —— `J.GetHP( hAlly ) >= 0.4` 是**真的出货子句** | **登记到源站点** |
| `detect.py:945` `hp_pct < 0.40` | **INDEPENDENT** —— 「被打残到 45 秒干不了事」,另一个主语 | 提名 + 登记为不可合并 |
| `detect.py:608` `OVERCHASE_VICTIM_HP = 0.45` | **INDEPENDENT** —— 敌方视角的受害者挑选 | 登记 + 就地解释 0.45 vs 0.40 |

⭐ **`ALLY_HP_MIN` 是这轮最值钱的一条。** 它是六处里**唯一一处真镜像**
(`jmz_func.lua:7085` `ShouldInitiateLaneKill` 和 `:7050` `ShouldSupportComboKill`,两处都是 `0.4`),
而它**从来没进过 REGISTRY**。一个读者扫 `behavioral/` 看到四个一模一样的 `0.40`,
最顺手的动作就是合并;**一旦合并,后面任何一次对 Lua 盟友血量门的改动都会悄悄拖动
lethality 代理 —— 连带拖动 `find_kill_windows.py` 选哪些帧进 fixture。**
那就是 GH #90,只是多绕了两步。**所以本轮的交付是分类,不是合并。**

⭐ **顺手证伪了 AJ.5 自己的出处指针。** 它写「此处是 `jmz_func.lua:6932`」。
我去读了:**6932 在 `J.ShouldBodyBlockHarass` 里,是一条无关 helper 的 800u 敌人扫描。**
那个指针**写下来的当天就是错的**。这恰恰是 REGISTRY 存在的理由,也是「散文指针不算登记」
的现场证据 —— 已把这段如实写进 `roam_conversion.py` 的出处注释里,不藏。

**代理的诚实出处**(写进源码,不写进散文):它**不镜像任何出货字面量**。
出货门问的是 `GetEstimatedDamageToTarget(...) >= 受害者血 + 4s 回复`,是**绝对血量**比较,
而那个调用不在 dumper 流里。最接近「出处」的东西是算术不是字面量:
armed 出价 `min(0.92, 1.84*HP)` 只在 `HP > 0.75/1.84 = 0.4076` 时才压过它抢占的 `0.75` 兜底 ——
**但那说的是 actor 的血,不是 victim 的血**,是 `BID_FLOOR_HIGH`,**只是恰好落在同一个数附近。不许合并。**
