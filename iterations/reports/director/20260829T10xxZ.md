### 1.1 改法(照该模块自己的规矩,不是「少断言」)

- 求和量 → **`cs.ratchet`**。涨 = 语料长大(旧等式误报成回归);**跌仍然红** —— 那是这些
  pin 当初唯一想抓的方向。
- 「N 个里的 N 个」→ **`cs.universal`**。**比原来强**:`item_item_tpscroll == action_total`
  对**还没写的 fixture** 也成立,而 `== 2` 只谈论我们已有的那两个。
- **零保持等式**:`outer_and_F == 0`、`nEndToEnd == 0`。这是若干 INERT/SILENT 裁定的立论基础,
  语料一长出反例就**必须**红。
- 分区恒等式保留(`alive_H + alive_F == alive` 等),并**补了两条原本没有的**:
  `#c.mature == c.level15`、`nQop + nVs == aiug_load_fail`(**第三个加载失败的英雄**原本
  只有在它恰好也把 29 挪动时才会被发现)。

### 1.2 ⭐ 第 6 条不是数字,是结构缺陷 —— 而且这是第三次

两个崩溃点按 **`jmz_func.lua:<行号>`** 做 key。**行号是坐标**:上游任何插入都把 key 改名,
旧名走 default-0 metatable 读成 **0**(所以失败信息是 `moved: 0` 而不是某个邻近的数)。

本轮实测:**2704 → 2835、3432 → 3563,均 +131,两条语句逐字节没变**:

```
CRASHAT honest 178 local x2 = sLoc.x
CRASHAT honest  41 local nTopDesire = GetFarmLaneDesire( LANE_TOP )
```

2597→2704 是第二次。**三次红主干、三次重钉,三次都不是它要守的东西动了。**

⇒ **key 换成语句源文本**。sweep 新出一条记录 `CRASHAT <tag> <n> <去空白源码行>`
(源文本带空格,当不了原来 `C` 语法的 `%S+` key,这正是当初只能用行号的原因)。
与今晨 `test_level_gate_census.lua` 的 `(file, 去空白源文本)` 是**同一副药**。

顺带:`full[1]/[2]/[3]` 那三条 pin 的是**排序后的位置** —— 同族坐标缺陷
(一个名字排在 `f_2608…` 前面的 fixture 会把三条一起改号,并报成三个不相干的帧在动)。
改成**成员资格**,而下游那个测试本来就是按名字重新加载这三条。
