## 四、⭐⭐ 落地时撞出的第二件事:**我自己写的第一个针脚是死的**

欠条要一个自动触发器。自然的针脚是 manifest 里那一行的 `in_gate`,于是我写了

⇒ **平坦查表,没有任何嵌套解析** ⇒ 那个键**永远读作 `UNCERTIFIABLE`**。

⛔ **而 `UNCERTIFIABLE` 也正是一个"诚实地读不出来"的针脚的样子**
⇒ **死针脚和活着但暂时读不到的针脚,对下一个读者逐字节相同**。
📌 **一个永远不可能变绿的针脚,比 `kind: manual` 更糟** —— manual 至少自陈它是散文。
📌 **而整份 registry 当时是全绿的**:「这个键解析得出来吗」**不是任何一条检查的问题**。

**修法,以及为什么不是分隔符**:第一个需要它的就是 `py_gate_manifest.json`,
中间那一段字面是 `tests/test_bots_walk_farm_only.py` —— **自带点,还自带斜杠**。
任何分隔符拼法都会撞上某个真实键,**而撞上是静默的**。
⇒ `key` 改为**接受列表**(字符串形式逐字不变):

```json
"key": ["tests", "tests/test_bots_walk_farm_only.py", "in_gate"]
```

**现读(活的)**:

```

```

**阴性对照(仍然拒绝)**:

```
ABSENT KEY -> ('UNCERTIFIABLE', "... carries no key 'tests' -> 'tests/no_such_test.py' -> 'in_gate' (resolved 'tests', then 'tests/no_such_test.py' is not there)")
```

**棘轮**:`tests/test_pending_rulings.py` **+6 检查**(`951 → 957, 0 failed`),四条:
未满足读 OWED 且**不是** UNCERTIFIABLE / 满足读 DONE / 键真的不在仍读 UNCERTIFIABLE /
**中途走进标量**仍读 UNCERTIFIABLE(不得拿半路节点比 `equals`),外加一条「字符串形式没退化」。

**变异 M3**(还原旧的平坦查表):**红**,`M3_EXIT=1`。
⚠️ **诚实边界**:它是以 `TypeError: unhashable type: 'list'` **崩**掉的,不是干净的断言失败。
