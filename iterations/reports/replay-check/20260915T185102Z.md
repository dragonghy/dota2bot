## 三、⭐⭐ 头号产出:交棒里那个「现成的现场」自己是错的

上一轮交棒第 (2) 条逐字点名一个样例:

> 现成的现场是 09-12T12:54Z 报告 §5 的 `bbfight`(radiant armed 5/base 13、dire armed 7/base 5,
> **按局率算 arm ≈ −0.058/局**,而当轮按反号丢掉了)

**那个 `−0.058` 复现得出来,而复现它的算式是错的。**

原文(`20260912T125400Z.md:139-141`)逐字:

```
band 带的 leg 计数 armed 30 / baseline 36,物理侧 radiant 41 / dire 25;
bbfight 域 radiant armed 5 / base 13(δ −8)、dire armed 7 / base 5(δ +2)
```

**判别子是加法**:`30 + 36 = 66`,`41 + 25 = 66` ⇒ **两个是同一个 66 的两种拆法**,
而那 66 是 **`bbshort` band 的 episode 数**(报告 §开头:「开出的 [45,60) 带 **66 次死亡**」)。
⇒ **`41 / 25` 是 episode,不是局。**

穷举可能的分母,只有一个复现得出 `−0.058`:

```
  -0.05756  <- 41/25 (bbshort band episodes, physical split)   ← 交棒用的就是这个
  -0.50000  <- 12 swept games split evenly
  -0.13889  <- bbfight domain by side 18/12
  -0.25000  <- 12/12
```

⇒ 那个数有**两处错**,而它们**方向相同、都把 |arm| 压小**:
1. **分子分母不是同一个 population**:分子是 `bbfight` 域(30 次,`level>24` 的死亡),
   分母是 `bbshort` band(66 次,[45,60) 带)。
2. **单位错**:`pair_arm` 的 docstring 逐字要求
   *"Both must already be RATES (per game). Handing this raw counts silently reintroduces
   the games-weighting that (i-d) exists to forbid"* —— 而 41/25 是 episode 计数。

**正确的数是什么?——没有。** 该报告**从未登记分层局数**:
全文只有「域…30 次,**跨 11 局**,两腿都有(armed 12 / baseline 18)」(`:73`)和宽扫 **12/12 局**,
**`ab` / `ba` 的局数拆分一个字都没有**。⇒ **这个站点不可回算**,
要回算只能重扫语料(4 个 run 仍在 S3,见 §五)。

⭐ **可迁移的那一句(与 #329「读数不是局数」同型,方向相反)**:
#329 抓的是**把局数当读数登记**;本条抓的是**把 episode 当局数去除** ——
两者都是「**一个真数字被放进了它不属于的那一格**」,
而**两次都长得像一个普通的每局率**,单位那一格没人核。
⭐ **判别子最便宜的一种就是加法**:候选分母**加起来等于另一个观测量的总数**时,它是 episode 不是局。

### 8.2 机制:不是「红/绿翻转」,是**豁免被升级成拦路发现**

`tools/agent/lua_gate.py:298-340`:`known_red` 是 manifest 里的**静态**名单,
而豁免是**按用例**给的(`known_red_cases`)——
一个在 `known_red` 名单里的文件,**只有它基线里那几条用例**被豁免;
它若以**别的**用例失败(`new_cases`),或**一条用例名都没打出来**(`not seen` 分支),
就**不是 known-red,是 finding** ⇒ **拒推**。

⇒ `5 known-red + 1 finding` 与 `6 known-red + 0 findings` 的差,
**是同一个文件在两次运行里落进了两个桶**。
