## 二、顺序动为什么能被看见:全部经由幻象

`detect.py:62-68` 逐字:

```python
for s in d["snapshots"]:
    if s["t"] > self.t_end: continue
    self.snaps[s["hero"]].append(s)
for h in self.snaps:
    self.snaps[h].sort(key=lambda s: s["t"])
```

**`sort(key=t)` 是 Python 稳定排序 ⇒ 同 `t` 的多条保持发射顺序** ⇒ 最近时刻查找取到的是发射序的第一条。
**而 `detect.py` 全文 `idx` 出现 0 次** —— 它从不锁实体。

那 2,658 个重复 `(hero,t)` 键是谁?**逐条查过,全部是幻象**:

| hero/idx | 角色 | 记录数 | t 范围 | 1Hz 路径长 | 与 MAIN 时间重叠 |
|---|---|---|---|---|---|
| `drow_ranger/1505` | **MAIN** | 1,686 | −53.3 .. 1631.7 | 607,206u | — |
| `drow_ranger/1882` | other | 816 | **816.7** .. 1631.7 | 2,542u | YES |
| `drow_ranger/1915` | other | 816 | **816.7** .. 1631.7 | 4,290u | YES |
| `drow_ranger/859` | other | 454 | 1178.7 .. 1631.7 | **0u** | YES |
| `drow_ranger/2106` | other | 454 | 1178.7 .. 1631.7 | **0u** | YES |
| `luna/2089`,`luna/2477` | other | 各 524 | 各 1108.7 .. 1631.7 | 547u / 922u | YES |

⭐ **三条判别子,每一条都指同一个方向**:
1. **成对出现**:每个 `t_first` 上**恰好两个**实体、记录数逐位相同(816/816、454/454、524/524…)
   ⇒ **一次两只 = 幻象**(Manta 一类),不是引擎换了句柄。
   带幻象的恰是 `drow_ranger`/`luna`/`viper`/`pudge`,**不带的是** `crystal_maiden`/`lich`/
   `necrolyte`/`obsidian_destroyer`/`skeleton_king`/`sniper`(法系/辅助)。
2. **`t_last` 一律 = 1631.7(全局最后一帧)** ⇒ **幻象在 dump 里从不过期**,于是越到后期越多:
   drow 到终局是 **1 真 + 20 幻**。这正是 33,312 行里 **16,420 行(49.3%)是幻象**的来路。
3. **`moved_u = 0`** 的两只(`drow_ranger/859`、`/2106`)= 跨帧坐标逐位不变 ——
   **W78 用过的同一条判别子**,原样复现。

⛔ **要排除的那个更坏的可能已排除**:若某英雄中途**换句柄**(复活/重选),锁最早 idx 会**删掉它后半条命**。
**本局没有**:10 个 MAIN **每一个**都覆盖到全局最后一帧(`−68.3 .. 1631.7`),
且**每一个 other 都与 MAIN 时间重叠**(表内 `overlaps_main` 全 YES,零 `GAP`)。
⚠️ **诚实边界**:这是 **2 局**的证据,**不是对每局成立的证明**;换句柄的情形我没观察到,**也没能力排除**。

### A.1 `stream_det.py` —— 五条流的 (A) 内容 / (B) 顺序

```python
#!/usr/bin/env python3
"""Is each timeline stream deterministic across repeated dumps of ONE .dem?

Two separate questions per stream, deliberately NOT conflated:
  (A) CONTENT: is the sorted multiset of records identical across dumps?
      -> if yes, the dump carries the same information every time.
  (B) ORDER:   is the emitted sequence identical across dumps?
      -> if no, any consumer that reads "the first record matching X"
         is reading a coin flip (the GH #666 / #849 mechanism).
"""
import json, hashlib, sys, collections

DUMPS = ['/tmp/rc/tl/d%d.json' % i for i in range(1, 6)]
STREAMS = ['events', 'snapshots', 'creeps', 'buildings', 'wards']


def canon(rec):
    return json.dumps(rec, sort_keys=True, separators=(',', ':'))


def h(items):
    m = hashlib.md5()
    for s in items:
        m.update(s.encode()); m.update(b'\n')
    return m.hexdigest()


def main():
    loaded = []
    for p in DUMPS:
        loaded.append(json.load(open(p)))

    for st in STREAMS:
        rows = [[canon(r) for r in d[st]] for d in loaded]
        lens = [len(r) for r in rows]
        order_h = [h(r) for r in rows]
        content_h = [h(sorted(r)) for r in rows]
        print('=== %s ===' % st)
        print('  len          : %s' % (' '.join(str(x) for x in lens)))
        print('  ORDER  hashes: %d distinct %s' % (len(set(order_h)), '<-- ORDER MOVES' if len(set(order_h)) > 1 else '(stable)'))
        print('  CONTENT hashes: %d distinct %s' % (len(set(content_h)), '<-- CONTENT MOVES' if len(set(content_h)) > 1 else '(stable)'))
        # duplicate-key structure: how often does a consumer keyed on the
        # stream's natural key face >1 record, i.e. have a coin to flip?
        if st == 'events':
            key = lambda r: (r.get('t'), r.get('type'), r.get('actor'), r.get('target'))
        elif st == 'snapshots':
            key = lambda r: (r.get('hero'), r.get('t'))
        elif st == 'creeps':
            key = lambda r: (r.get('t'), r.get('team'))
        elif st == 'buildings':
            key = lambda r: (r.get('name'), r.get('t'))
        else:
            key = None
        if key:
            c = collections.Counter(key(r) for r in loaded[0][st])
            multi = sum(1 for v in c.values() if v > 1)
            print('  keys=%d  keys_with_>1_record=%d (%.1f%%)  max_per_key=%d'
                  % (len(c), multi, 100.0 * multi / max(1, len(c)), max(c.values())))
            # does the FIRST record under a multi-key differ between dumps?
            def first_map(d):
                fm = {}
                for r in d[st]:
                    k = key(r)
                    if k not in fm:
                        fm[k] = canon(r)
                return fm
            fms = [first_map(d) for d in loaded]
            shared = set(fms[0])
            for fm in fms[1:]:
                shared &= set(fm)
            moved = sum(1 for k in shared if len({fm[k] for fm in fms}) > 1)
            multi_shared = [k for k in shared if c.get(k, 0) > 1]
            moved_multi = sum(1 for k in multi_shared if len({fm[k] for fm in fms}) > 1)
            print('  FIRST-record differs across dumps: %d/%d keys overall; %d/%d of the multi-record keys (%.1f%%)'
                  % (moved, len(shared), moved_multi, len(multi_shared),
                     100.0 * moved_multi / max(1, len(multi_shared))))
        print()


if __name__ == '__main__':
    main()
```

### A.2 `d8_idxfix.py` —— 端到端:idx 锁前后,14 个检测器的计数

```python
#!/usr/bin/env python3
"""END-TO-END: does idx-locking remove detect.py's nondeterminism?

as-is    : Timeline over the dump verbatim        -> W76-W79 measured d8 moving
idx-lock : same Timeline, non-main-idx rows dropped BEFORE construction
           (the filter creeppull_domain.Game.__init__ already implements)

Nothing in detect.py is edited; the filter is applied to its INPUT, so this
measures the fix's effect, not a rewritten detector.
"""
import sys, json, copy
sys.path.insert(0, '/home/user/dota2bot/tools/batch_test/behavioral')
import detect

DUMPS = ['/tmp/rc/tl/e%d.json' % i for i in range(1, 4)]


def idx_lock(d):
    first_t = {}
    for s in d['snapshots']:
        k = (s['hero'], s['idx'])
        if k not in first_t or s['t'] < first_t[k]:
            first_t[k] = s['t']
    main = {}
    for (hero, idx), t0 in first_t.items():
        if hero not in main or t0 < first_t[(hero, main[hero])]:
            main[hero] = idx
    out = dict(d)
    out['snapshots'] = [s for s in d['snapshots'] if s['idx'] == main.get(s['hero'])]
    return out


def run(d):
    tl = detect.Timeline(copy.deepcopy(d))
    res = {}
    for fn in detect.DETECTORS:
        try:
            hits = fn(tl)
        except Exception as exc:
            res[fn.__name__] = 'ERR:%s' % type(exc).__name__
            continue
        res[fn.__name__] = len(hits) if hits is not None else 0
    return res


raw = [json.load(open(p)) for p in DUMPS]
asis = [run(d) for d in raw]
lock = [run(idx_lock(d)) for d in raw]

names = [f.__name__ for f in detect.DETECTORS]
print('%-42s %-22s %-22s' % ('detector', 'AS-IS (5 dumps)', 'IDX-LOCKED (5 dumps)'))
moved_asis = moved_lock = 0
for n in names:
    a = [r[n] for r in asis]
    b = [r[n] for r in lock]
    fa = '' if len(set(map(str, a))) == 1 else ' <-MOVES'
    fb = '' if len(set(map(str, b))) == 1 else ' <-MOVES'
    if fa:
        moved_asis += 1
    if fb:
        moved_lock += 1
    print('%-42s %-22s %-22s %s%s'
          % (n, '/'.join(map(str, a)), '/'.join(map(str, b)), fa, fb))
print('\ndetectors whose count MOVES across 5 dumps of ONE .dem:')
print('  as-is      : %d / %d' % (moved_asis, len(names)))
print('  idx-locked : %d / %d' % (moved_lock, len(names)))
```

### A.3 `idx_audit.py` —— idx 锁丢掉的是幻象还是真记录

```python
#!/usr/bin/env python3
"""Does idx-locking drop PHANTOMS, or does it drop real hero records?

The failure mode to rule out: a hero whose engine handle CHANGES mid-game
(respawn, re-pick). Locking to the earliest idx would then silently delete
the rest of that hero's real life -- a defect worse than the coin it fixes.
Discriminator: a phantom is stationary or short-lived and COEXISTS in time
with the main entity; a handle change would show the main entity STOPPING
where the other starts.
"""
import json, collections
d = json.load(open('/tmp/rc/tl/d1.json'))
snaps = d['snapshots']

first_t, byent = {}, collections.defaultdict(list)
for s in snaps:
    k = (s['hero'], s['idx'])
    byent[k].append(s)
    if k not in first_t or s['t'] < first_t[k]:
        first_t[k] = s['t']
main = {}
for (hero, idx), t0 in first_t.items():
    if hero not in main or t0 < first_t[(hero, main[hero])]:
        main[hero] = idx

print('%-28s %5s %7s %8s %8s %8s %7s %s' %
      ('hero/idx', 'role', 'n', 't_first', 't_last', 'span', 'moved_u', 'overlaps_main'))
for hero in sorted(main):
    ents = sorted([k for k in byent if k[0] == hero],
                  key=lambda k: -len(byent[k]))
    m = byent[(hero, main[hero])]
    mt0, mt1 = min(s['t'] for s in m), max(s['t'] for s in m)
    for (h, idx) in ents:
        rs = sorted(byent[(h, idx)], key=lambda s: s['t'])
        t0, t1 = rs[0]['t'], rs[-1]['t']
        moved = sum(abs(a['x'] - b['x']) + abs(a['y'] - b['y'])
                    for a, b in zip(rs, rs[1:]))
        role = 'MAIN' if idx == main[hero] else 'other'
        ov = '-' if role == 'MAIN' else ('YES' if (t0 <= mt1 and t1 >= mt0) else 'NO -- GAP!')
        print('%-28s %5s %7d %8.1f %8.1f %8.1f %7.0f %s'
              % ('%s/%s' % (h.replace('npc_dota_hero_', ''), idx), role,
                 len(rs), t0, t1, t1 - t0, moved, ov))

tot = len(snaps)
kept = sum(len(byent[(h, main[h])]) for h in main)
print('\ntotal snapshot rows %d ; kept by idx-lock %d (%.1f%%) ; dropped %d (%.1f%%)'
      % (tot, kept, 100.0 * kept / tot, tot - kept, 100.0 * (tot - kept) / tot))
# Does the main entity cover the whole game for every hero?
gend = max(s['t'] for s in snaps)
print('game last snapshot t=%.1f' % gend)
for hero in sorted(main):
    m = byent[(hero, main[hero])]
    print('  %-22s main covers %.1f..%.1f  (%d rows)'
          % (hero.replace('npc_dota_hero_', ''),
             min(s['t'] for s in m), max(s['t'] for s in m), len(m)))
```
