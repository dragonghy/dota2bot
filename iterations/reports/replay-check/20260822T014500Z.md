## 0. 结论(三条,第三条推翻 #101 自己的机制归因)

1. **#101 §5 的验收按原文不可判定。** 它问「三份语料的 r 是不是都在 0 附近」,
   但 **r 不是语料的属性**。存在性证明在**同一份语料内部**:`roamstale` 的**同一批
   16 vs 16 局、同两条腿**,只把 `roam_conversion` 的时间窗从 OUT 换成 IN,
   r 就从 **+0.47 走到 +0.89**。`lf_rescue` 更极端:同一份 32 局,`casts` 域读 **−0.22**、
   `opps` 域读 **+0.91**。r 跟的是**每英雄的 episode 数**(即样本量),不是装置。
2. **raw r 几乎不含超出它自己置换零点的信息。** 种子内置换「局→腿」5000 次,
   置换均值本身就是 −0.19 / +0.25 / +0.60 / −0.22 / +0.65 ——
   观测 r 在每个稠密域上都只高出置换均值 **+0.20 ~ +0.29(1.1–1.6 SD)**,
   **这个超出量在五个域上几乎是常数**。⇒ 若 #101 §4.1 要变成硬栏位,
   **必须是置换标准化后的超出量,不能是 raw r** —— 否则同一个统计状态会被写成
   「0.01 vs 0.91」两个天差地别的读数。
3. ⭐ **机制扛不动它被请来解释的量级。** 用标准化恒等式把 NULL 拆成
   `NULL_comp = Σ_h (s_A(h) − s_B(h))·r̄(h)`(构成项)+ 残差,在 **#101 自己的
   `capmono` 语料**上:观测 NULL **+3.21pp**、构成项 **−0.86pp**、残差 **+4.07pp**
   ⇒ **构成只解释 −27%,而且符号是反的**。五个域上构成项绝对值除 7 事件的
   `casts` 外**全部 ≤0.9pp**。⇒ #101 量到的现象(占用没被控住)**是真的**,
   但**它不是 NULL 腿的解释**;NULL 由「两份出厂代码之间普通的逐英雄行为方差」主导。
   **建议 #101 §4.1 改口径:报「构成可归因 NULL(pp,与效应量同单位可直接比)」,
   不要报占用重合度(无量纲 r,读数被域密度支配)。**

## 5. 对照 FAIL 挡住了一份静默残缺的语料(新踩,已开 [harness] issue)

第一次跑 `--selfcheck` 时对照 **FAIL**:`pooled (72,103)` vs 登记 `(86,103)`、
`seed906 Jaccard 0.00` vs 登记 `0.43`、臂 A **13 局**而非 16。

根因:我并行跑了两个 `sweep_run.sh`,两者共用 `get_dumper.sh` 的
`.dumper_cache/behav-dump`,其中一个在另一个重取/chmod 该二进制的瞬间 exec 它,
拿到 **`Permission denied`**。`set -euo pipefail` 让那次 sweep 就地退出 ——
**但 `games_manifest.jsonl` 已经写了 1 行**。

**危险不在于它失败,在于失败后的目录跟成功的目录长得一模一样**:
本目录里**所有**消费方(`roamstale_null_channel.py` / `lf_rescue_null_channel.py` /
`capmono_null_channel.py` / 本工具)都只认 `games_manifest.jsonl`,
于是语料静默变成 13 局,**没有任何一行输出提到这件事**。
我的驱动脚本里那句「`[ -s games_manifest.jsonl ]` 就跳过」还会把这个残缺目录**永久**跳过。

只有「拿登记先验做阳性对照」这一层挡住了它 —— 这是**第二次**逐字段自检当场救下
一篇建在错分母上的报告(上一次:16:55Z 的 `--selfcheck` 打掉 `lanekill_commit` 的 dedup 口径)。

**已在本工具落地机器守卫**:`load_manifest()` 要求目录里有 `sweep_summary.md`
(`sweep_run.sh` 最后才写,即事实上的完成哨兵),**并且**要求它的
`games swept:` 计数与 manifest 行数逐位相符,否则 `exit`。
两次变异测试全部咬住(藏掉 `sweep_summary.md` → fatal;`--corpus` 写错 → 臂守卫 fatal,
且在打印任何数字**之前**)。

**已开 issue `[harness] #102`**(总监):建议 `sweep_run.sh` 写一个显式
`sweep_complete.json`(expected/swept/skipped + 退出码),消费方一律拒绝没有它的目录;
并在 `get_dumper.sh` 上加锁,或至少在 README 写明**不要并行跑 sweep**。
