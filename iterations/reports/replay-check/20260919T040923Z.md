## (二)⭐⭐ 头号:这条读数差点买不到 —— 工具跑不到它自己印的那条门槛

`tpreach_bc4_cell_reread` 的验收句要求「粒种子数 **> 4**」,而 `tpreach_domain.py`
**在 8 粒种子上被 OOM 杀掉,三个 reach 模式全死,一行都没印出来**:

```
MODE=p50    Killed   EXIT=137
MODE=p90    Killed   EXIT=137
MODE=source Killed   EXIT=137
```

根因是 `main()` 把整个语料**物化成 list**(`timelines = []` / `.append(tl)`):
148 局 × ~28MB timeline JSON,解析后远超本容器 **15GB**。
⇒ **一个印着 `BC.4 re-entry bar: seeds = N, required > 4` 的工具,在 N > 4 时跑不动**
—— 这是「用不回答来回答否决权」,与本仓 `verify_coverage.py` / `pending_rulings.py`
那一族(印出来了 ≠ 被读了)同型,只是更硬:这次连印都印不出来。

**本轮修掉**(只动 `tools/`,⛔ `bots/` + `game/` 一行未改):

- 新增 `Corpus` 类:可重复迭代、**一次只驻留一局**;`n_games` 只由**完整**的一趟设置
  (半途 `break` 的消费者不许把分母改小)。`measure_ranges` / `range_items_held` /
  主循环各自走自己的一趟,代价是多解析一遍 JSON,收益是常数级内存。
- 修完实测:p50/p90/source **三个模式全部 EXIT=0**,148 局跑通。

**⭐ 变异台 2 死 0 活(证据纪律:断言要能红)**:

| M1 | `Corpus.__iter__` 改回缓存 list(即把 OOM 原样装回去) | **死** — `FAIL corpus-yields-fresh-objects-each-pass`,`61 PASS / 1 FAIL` |
| M2 | `n_games` 改成逐条递增(半途 break 会把分母改小) | **死** — `FAIL corpus-count-survives-a-partial-pass`,`61 PASS / 1 FAIL` |
