## 4. ⚠️ 本轮新踩的测量坑:**物品行闪断 —— 「不在九格里」不等于「离开了」**

```

518.5  B[flask|quelling_blade|blood_grenade]   d(fnt)=10040   ← 坐标也冻着
519.5  B[.    |quelling_blade|blood_grenade]   ← 药「不见了」
520.5  B[flask|quelling_blade|blood_grenade]   ← 又回来了(且 d 10040→69 = TP 回家)

```

同段里最近敌人距离在 11928 → 2024 → 2212 → 12048 之间跳,坐标 3 帧不更新
⇒ **同一快照里不同实体属性的更新是错开的**,物品行会在相邻采样间**在投递前/投递后两个版本之间来回**。
机制不主张,**观测到的只有交替本身**。

**方向要说清楚,因为它决定 #123 那个数怎么读**:出厂的
`fieldbuy_domain._stuck_in_backpack` 把「不在九格」读成「走了 ⇒ 不 STUCK」
⇒ **闪断只会让 STUCK 被少数,不会多数。#123 的 12.9% / 本轮的 11.0% 都是下界。**
本语料 166 行里 **16 行(9.6%)**出现过「消失又回来」。

新工具因此**不用缺席判定移动**:`moved` = 「药出现在 0..5 槽(一个位置)」
∨「`modifier_flask_healing` 上身(一个事件)」。两者都是正面证据。

## 5. ⭐ #123 §5 的 WARD 那一格:**这个代理量在本语料上测不了**(结论是方法级的)

`GetActiveMode() == BOT_MODE_WARD` 读不出来(dumper 无 mode 字段);
可读的是一个**必要条件** —— ward 模式是为了插眼,bot 必须**带着眼**。
一个只能证伪、不能证实的检验。三步读数,**每一步都改写上一步**:

1. **只看 run 1(50 局)**:STUCK 带眼 45.5% vs RESCUED 43.8% ⇒ 看起来**毫无富集,假说被证伪**。
2. **四个 run(205 局)**:STUCK **45.2%** vs RESCUED **18.0%** ⇒ 看起来**2.5 倍富集,假说活了**。
3. **按英雄分层** ⇒ **两个都不算数**:

```
tidehunter 42 行 带眼 0%      bristleback 21 行 0%     viper 12 行 0%   slardar 10 行 0%
spiritbreaker 19 行 84%       zuus 13 行 92%           sniper 9 行 100%  crystalmaiden 8 行 100%
```

**带不带眼在本语料里几乎是英雄身份本身**(要么 0%,要么 84-100%)。
**同时有两个分层且各 ≥3 行的英雄只有 spirit_breaker 一个**(带眼 3/11 = 27%,不带眼 0/3 = 0%,
样本远远不够)。⇒ 那个 2.5 倍**整个是「辅助 vs 核心」的差**,不是 ward 模式的信号。

**判读:WARD 假说 = UNTESTABLE(用库存代理),不是 refuted 也不是 supported。**
要测它需要**同一英雄有时带眼有时不带眼**的语料,或者一个 Lua 侧实验。
顺带:在**沉默**窗口里带眼率只有 **20.7%(6/29)** —— 比任一人口的基线都低,
即**带眼与「沉默」这件事本身不同向**,只与 STUCK 同向(而后者已被证明是英雄混杂)。

**这一格交回协同组时请连同这条方法结论一起收**:不要拿库存当 ward 模式的证据。
