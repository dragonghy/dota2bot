### 1.2 与之矛盾的那句话,以及它的出处


### 1.3 ⚠️ 为什么这不是一句可以放过的口误 —— 它删掉的是一份**已经买到手的语料**

那句话的作用是告诉未来的读者:**W60/W61 里没有 `ownhalf` 的读数**。
实际上 **W60 的 96 局全部 armed 了 `ownhalf`,而且是在旧边距 800 上**。
那是**目前唯一一份 `ownhalf`@800 的入库测量**,而它恰好是 W62 的 `ownhalf`@1600
**最自然的对照面**。一个信了这句注释的收割轮,会:

- 要么把 W60 的 96 局当成「与 `ownhalf` 无关」而不去对照;
- 要么把 W62 读成「`ownhalf` 的第一次测量」——而它其实是**第二个配置的第一次测量**。

⭐ **结论的方向要说准**:批测台 21:08Z 的裁定(`pooling_claim` = 不可并池、
`family_depth_at_launch` = 新家族深度 1)**是对的,本条不动摇它**。
被推翻的是**源码注释**,不是波次记录。两者在本轮之前**没有任何东西负责对账**。

### 1.4 那句话的**结论**碰巧仍然成立,但**理由**不成立

「no flying wave is disturbed」这个**结果**是对的 —— 但正确的理由是
**实例在起飞瞬间 clone 钉住的 40 位 SHA**(W62_wave.json:`tree_verified` 自己写着,
`--ref` 传的是全 SHA 而非移动的 `main`),**16:57Z 之后的 commit 结构上够不着已起飞的机器**;
**不是**因为「那个 id 没 armed」。
⇒ **对的答案配错的理由**,正是 `evidence-discipline` 第 4 条点名的形状。

```
VERIFY id=ownhalf verdict=INDETERMINATE episodes=0
```
**为什么是 INDETERMINATE 而不是别的**:本轮**没有**买它的执行状态(见第三节的限度),
只推翻了一句关于它 armed 与否的元陈述。**不许把本条读成「`ownhalf` 被核验了」。**
