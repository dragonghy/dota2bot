## 2. ⭐ 主交付:`itemtrip` 预登记契约的判决

### 2.1 判据是作者自己写在文件头里的,不是我事后挑的

`bots/mode_item_generic.lua` 只在 armed 时才定义 `GetDesire`,域内返回
`BOT_MODE_DESIRE_NONE`、域外返回 **nil**;头注明写 nil 那条腿**压在一个没人验过的引擎契约上**
(`docs/BOT_API_REFERENCE.md:52`,本仓库零使用者),并**预登记**了两个互斥后果:

> * nil 落穿 ⇒ armed == 出厂 bid 减去 wasteful 那些帧(设计中的杠杆);
> * nil 被读成 0 ⇒ **整局 item mode 关掉**。
> 「如果 item-mode 回家行程**只在 #120 的 wasteful 画像里**下降,契约成立;**如果掉到 ~0**,契约为假。」

本轮就是跑这个判别式。新工具 `tools/batch_test/behavioral/itemtrip_contract.py`
(`--selfcheck` **10/10 PASS**)把 `hometp_highhp.py` 的 `unexplained` 人口
(= `bots/` 里**没有一个可离线求值的分支**的必要条件成立 ⇒ 出厂 `BOT_MODE_ITEM` 的可观测影子)
按**杠杆能不能动**切两半:

| 桶 | 定义(逐子句抄自 `J.IsWastefulItemTrip`) | 含义 |
|---|---|---|
| **IN** | hp≥0.55 ∧ 1600 环内无敌人 ∧ 离泉 ≥5000 ∧ 归因伤害子句不可能否决 | armed 腿这里返回的是 NONE |
| **OUT** | 至少一条**确定为假**(1600 内有敌人 / 离泉 <5000) | armed 腿这里返回的是 nil |
| UNRESOLVED | 归因伤害子句离线判不了(`hit6` 为真且最近敌人 ≤3000) | 不进任何判决 |

## 5. 诚实边界(三条,写在结论旁边而不是脚注里)

1. **人口是 TP,不是「回家」**:`hometp_highhp.py` 只看回自家泉水的**传送**。item mode
   也可以**走**回去,走回家**根本不在这个人口里** ⇒ 本轮的下降是 **TP 那一半**的下降,
   沉默处**不能**读成「mode 从没跑」。
2. **mode 在录像里不可见**(第 13 条世界断言)。`unexplained` 是**必要条件归因**,
   意思是「`bots/` 里没有一个我能求值的分支的必要条件成立」,**不是**「这次是 item mode」。
   §2.2 的两个桶都建立在这个人口上,措辞照此。
3. **n 小**:域内一共 26 个事件 / 213 局。四个 run 方向一致(3 降 1 平、0 次反向)是本轮
   最强的那条,而不是那个 0.53 的比值本身。
