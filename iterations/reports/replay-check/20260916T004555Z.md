## 二、根因:三段,每一段都单独可证

### (1) dumper:同一个 `(hero, t)` 上有多条记录,53% 是 `hp=0`

一局(`212703_slot7`)逐条数:

```
snapshot 记录总数            33,312
distinct (hero,t)            16,892
(hero,t) 带 >1 条记录         2,658  (15.7%)
最大重数                        21
hp==0 的记录                 17,584 / 33,312  (53%)
(hero,t) 同时有 live+ghost    2,225      ← 这些 t 上英雄活着,却也有 hp=0 的记录
```

drow_ranger 一人:**1,813 条 live / 7,457 条 `hp=0`**,而那 7,457 条只落在 **25 个**
不同坐标上(最高的两个各重复 798 次)⇒ **陈旧/冻结的实体槽,不是运动轨迹**。

**身份逐字确认是 GH #586 的第 (2) 条**:同 `hero` 名、**同 `player_id`(7)**、只有 `idx` 不同:

```
t=1226.7  drow_ranger  idx=1915  pid=7  hp=0     level=14  items=[]
t=1226.7  drow_ranger  idx=271   pid=7  hp=0     level=16  items=[]

t=1226.7  drow_ranger  idx=1505  pid=7  hp=0     level=22  items=[… manta_style …]
t=1226.7  drow_ranger  idx=?     pid=7  hp=1039  (36.5%)              ← 本体
```

⭐ **`manta_style` 就在物品栏里** —— #586 说的「幻象与本体同名同 pid,只有 idx 区分」,
这里是它的实物。

### (2) `detect.py`:`state_at()` 在那一组记录里**取第一条**

`tools/batch_test/behavioral/detect.py:102-122`:

```python
i = bisect.bisect_left(times, t)
for j in (i - 1, i, i + 1):
    dt = abs(times[j] - t)
    if dt <= tol and (best is None or dt < best[0]):   # 严格小于
        best = (dt, self.snaps[hero][j])
```

同一个 `t` 上 `dt` 全是 0,`dt < best[0]` 恒假 ⇒ **永远返回该 `t` 的第一条**。
而 `:69` 的 `sort(key=lambda s: s["t"])` 是**稳定排序** ⇒
「第一条」= **dumper 发射顺序里的第一条**。
⛔ 这正是 GH #586 建议修法第 3 条明写的禁忌(「要某个 t 上的一行,就在该 t 的所有行上
取一个**与序无关的**归约」)—— `state_at` 违反的就是这一条。

### (3) 合起来:同一个 `.dem` 跑两遍,`alive_at()` 翻 775 次

同一个二进制、同一个 `.dem`(⚠️ **两个文件都先 `wc -c` 验非空**,W75 那条第五例的教训;
`32,747,756` bytes 逐位相等,`cmp` 报 **BYTES_DIFFER**):

两次 records / distinct (hero,t)   33,312 / 16,892   逐位相同
(hero,t) 多重度的 multiset          相同   ← 与 #666「same multiset, different order」吻合
两次「胜出记录」不同的 key          2,074
  …其中是重复 key 的                2,074  (100%)   ← 零误归因
  …其中 alive_at() 直接翻转的         775
```

逐字样本:

```

## 五、⛔ 一条会让缺陷更难被发现的警告(给总监 / 批测台)

GH #666 的硬验收是「**同一 `.dem` 连跑两次,timeline md5 逐位相同**」,
建议修法是「dumper 按 `(t, 实体 id)` 排序后输出」。

**这条验收会通过,而本轮这个缺陷一条都不会被它碰到。**
排序之后 `state_at` 仍然取该 `t` 的第一条,只是**从「随机挑一个幻象」变成
「稳定地挑 idx 最小的那一条」** ⇒ 读数变得**可复现地错**。
⛔ 而可复现正是全队用来判断「这个数可信」的那个信号
(#666 自己写:「同一份语料重跑读数应该一样,是全队每一次复核的隐含前提」)。

⇒ **消费侧那一修(§二(2))必须和 dumper 那一修一起做,或者先做** ——
它只改一个函数、不依赖 dumper、立刻让**全部 12 个**受影响检测器变确定且正确。
