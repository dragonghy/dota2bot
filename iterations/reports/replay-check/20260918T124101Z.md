## 七、⭐⭐ 收尾时撞出来的第二个缺陷(本轮实测,不是推断):**开工自检的处方会把铁律 6 的 python 闸染成假红,而闸自己的提示语会让你去赖别的组**

W94/W95 交棒把开工自检的取法钉成「当轮**第一条命令** `nohup … routine_selfcheck.sh … &`」。
它**跑得很久**(本轮到收尾仍停在 `=== trunk health (python test suite) ===`,`pgrep -c` = 3)。
于是**同一轮稍后的 `git push`** 与它**并发**,而钩子的第二条腿(`py_gate.py`)也在跑 python 测试。

**实测三步,同一棵树(markdown-only 改动),同一个测试:**

| # | 条件 | 命令 | 读数 |
|---|---|---|---|
| 1 | 自检在后台跑着 | `git push -u origin <branch>` | **`PUSH1_EXIT=1`**;`py gate: 134 ran, **1 findings**, 0 uncertifiable, 60.3s`;`FAIL  tests/test_tpreach_domain.py  (exit 1)` |
| 2 | 同上,直接单跑那个测试 | `python3 tests/test_tpreach_domain.py` | **`TEST_EXIT=0`**,全 PASS |
| 3 | **杀掉后台自检之后**重跑闸 | `python3 tools/agent/py_gate.py` | **`PYGATE_EXIT=0`**;`py gate: 134 ran, **0 findings**, 0 uncertifiable, 60.3s` |

⭐ **失效形状在闸的输出里看得见**:那份 FAIL 只打出**前 4 条 PASS** 就转成
`selfcheck exits clean  FAIL` + 一串 `battery still runs <name>  FAIL`

**不是断言判负**。⇒ 归因是**资源争用**,不是 trunk 红。

⛔⛔ **这条最危险的地方是闸自己的提示语**,逐字:

> `If the named test is not about your change, the red was ALREADY on trunk:`
> `say so in your report and tell the owning stream`
