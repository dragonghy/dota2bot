## 2. ⭐⭐ 主发现:`suptp` 的门被同集的 `midtp` **完全支配**

源码(`bots/FunLib/jmz_func.lua:8642-8644`,**全仓库唯一**读 `'suptp'` 的功能性位置):

```lua
local bSup = J.IsSoakCandidate( 'suptp' )
    and bot ~= nil and J.GetPosition( bot ) >= 4
if not ( J.IsSoakCandidate( 'midtp' ) or bSup ) then return nil end
```

`midtp` 一旦 armed,`midtp or bSup` **恒为真**,`bSup` 的取值**对结果没有任何影响**。
而 `midtp` 的注释自陈是「**the mid profile -- any position**」,即它**不带位置限定**
⇒ `suptp` 的域(pos ≥ 4)是 `midtp` 的域(全部位置)的**真子集**。

### 2.1 在**真代码**上跑出来的真值表(不是复述,是执行)

仓库自带的 `tests/test_mid_tp_support.lua` 的 stand **结构上只能 arm 一个 id**
(`J.IsSoakCandidate = function(id) return opts.armed ~= false and id == (opts.cand or 'midtp') end`,
第 111-113 行),所以它**永远表达不出波次的那个配置**。本轮照它的场景搭了一个
**能 arm 一个集合**的 stand(scratchpad,未进仓库),调的是**同一个 shipped helper**:

```
armed set              pos   ShouldTpSupportTowerFight
{}                     1..5  nil          (出厂默认,inert)
{midtp}                1..5  TOWER (fires)   ← 每个位置都开火
{suptp}                1,2,3 nil
{suptp}                4,5   TOWER (fires)
{midtp,suptp}          1..5  TOWER (fires)

positions where arming suptp CHANGES the outcome (midtp already armed): 0/5
positions where arming suptp ALONE changes the outcome (midtp off):     2/5
```

`STAND_EXIT=0`。**`{midtp}` 与 `{midtp,suptp}` 逐行相同**——这就是"不承重"的执行证据。

### 2.2 这个配置**不是偶发**:16/16 波次 + 243/243 版本

- **波次侧**:把每个 `W*_wave.json` 的 `arm_md5` 拿去和本地可达的每一版
  `test_set.md` 第 2 行的 md5 对表(md5 用 `printf '%s' <line> | md5sum`,
  **16 个波次记录逐个精确命中**,不是模糊匹配):
  **W34–W49 共 16 个带 `arm_md5` 的波次,每一个都解析到「`midtp` 与 `suptp` 同时 armed」的那一版**。
  (W24–W33 与 Y1 的记录里**没有 `arm_md5` 这个键**,故不在此读数内;Y1 是标尺波,不 arm 任何 candidate。)
- **版本侧**:本地可达的 `test_set.md` **243 个版本**(`git log --all`)里,
  **出现 `suptp` 的有 243 个,其中同时出现 `midtp` 的 243 个,`suptp` 单独出现 0 个**。
  ⚠️ **诚实边界**:本容器是 **shallow clone**(`.git/shallow` 存在,`rev-list --count HEAD` = **50**),
  所以「243」是**本地可达**的版本数,不是仓库全史。反证只需要一个反例,本地一个都没有。
- **本波实测(正交交叉验证,章程「工具坑」那条)**:不只读 `test_set.md`,
  还读**引擎实际跑的那个戳**——`.dem` 的 `cand=` 串。W49 的戳与钉住的臂串
  (`git show 066219d6:iterations/streams/test_set.md` 第 2 行,
  md5 `824ec284…` 与 `W49_wave.json.arm_md5` **逐位相同**)
  **作为集合完全相等(61 vs 61,双向差集为空)**,且**两个 id 都在里面**。

### 2.3 为什么没人发现:量具查的是**存在**,不是**承重**

`tools/batch_test/check_armed_wiring.py` 对 `suptp` 报 WIRED——**这是对的**,
它的 LIMITS 节自己就写着「WIRED means a call site EXISTS … It does not mean the
site is reachable, **that its predicate can be true**, or that the id does anything」。
问题不在这个工具,在于**「谓词能不能承重」这件事全体系里没有任何一个检查在管**。

这是 `AGENTS.md` 那条「promote 一个 id 会悄悄冻死点它名字的门」的**同族反面**:
- 已知那条:`A and B`,`B` 被 promote ⇒ 门恒 **FALSE**。
- 本轮这条:`A or B`,`A` 与 B 同集 armed ⇒ B **恒不承重**(门恒 TRUE 与 B 无关)。

两条的共同形状是:**臂串里一个 id 的"有没有效果"取决于同一个臂串里的另一个 id,
而登记裁定时是按单个 id 登记的。** 本轮扫了一遍 `bots/` 里所有析取形式的门,
**当前 59 个 armed id 里只有 `midtp`/`suptp` 这一对命中**
(`lanefix or lf_<sub>`、`lanefix or lf_support`、`tparrive`、`c3`、`c12`、`nopush`、
`esaftershock` 的另一半**都不在当前臂串里**,故那些析取不构成支配)。

### 4.1 落点里的一个**正指纹**(旁证,**不承重**)

`GetNearbyLocationToTp` 的非退化出口是 `GetLocationTowardDistanceLocation(tower, nLoc, **575**)`。
本轮 16 发里**有一发的落点距正面塔恰好 575u**(`(-4974,5546)`);
全语料 218 个 helper-shaped 事件里,按 `tpdefend_events.py` 自己的 `d_land`
**恰好 575 的也是 1 个**。这类落点只可能来自 `GetNearbyLocationToTp` 的
**另外 7 个出厂常活调用点**(`state.json` 已登记:9 个调用点只有 2 个带 gate),
因为它们喂进去的 `nLoc` **不是塔自己的坐标**,`(nLoc − tower)/dist` 才算得出来;
**`midtp`/`suptp` 那条接线在算术上产不出任何有限值,575 更不可能。**

⚠️ **这一条只是旁证,结论不依赖它,原因要写出来**:「落点」有两个不同的估计量——
`tpdefend_events.py` 取它自己判定的落地帧,本轮 `dive` 脚本取"按压后 12s 内首个
进入正面 1500u 的帧",**两者对同一个事件可以给出不同的 `d_land`**
(例:`20260905_212156_slot8` zuus t=1193.8,工具读 **626**,本轮 dive 读 **575**)。
承重的是 §4 那句**与估计量无关**的话:**有限 ≠ NaN**。

### 4.2 归属:`pos ≥ 4` 这条腿上,量具**同样没有分辨力**(与上一轮 `midtp` 同构)

`baseline` 腿上两个 id 都不 armed ⇒ helper 第二行直接 `return nil`,

(armed 腿 **47 个**),`d_land` 中位 **558 vs 598** 逐位靠拢,英雄集合**完全相同**
(crystal_maiden / jakiro / lich / lion / pudge / silencer / skywrath_mage /
spirit_breaker / zuus,九个,两条腿一字不差)。
⇒ **这不是假阳性率的估计,这就是假阳性的计数**;
**armed 腿那 47 不能当作 `suptp` 触发过的证据**(章程 4a)。

**但它买到了另一件同样必要的事:`suptp` 的域是"占着的",不是"空的"。**
72 局里 armed 腿有 **47 次** pos ≥ 4 的塔防响应场景成立 ⇒
**排除掉「SILENT 是因为场景稀缺」这个解释**,剩下的只能是**结构性遮蔽**。
