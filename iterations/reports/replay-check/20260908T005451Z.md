## 三、⭐⭐ 真的判据:`MODIFIER_REMOVE` 的 `value`

`outlatch_capture.py` 消费 ADD/REMOVE 只取时间戳,**其余字段全丢**;
四轮比的是**通道长度**,而战斗日志一直在隔壁一个字段里写着**结果本身**。

**W54(全新语料,84 个组,与 W53 不同家族)**

```
REMOVE value vs 易主(ground truth)      caster_s >= 5.8 vs 易主(同一语料)
             | flip   no-flip                        | flip   no-flip
  value==0   |   50       0                >= thresh |   50       0
  value!=0   |    0      34                <  thresh |    0      34
  一致 84/84(精确)                        一致 84/84
```

**W53 上一轮点名的那两局(4 个组)**

```
  value==0   |    1       0          >= thresh |    1       2
  value!=0   |    0       3          <  thresh |    0       1
  一致 4/4(精确)                     一致 2/4,分歧 2
```

**⇒ 阈值已知会错的地方,`value` 恰好是对的;`value` 至今没有一例分歧。**
两份语料合计 **88 个组、0 分歧**。

**它为什么会错:**W54 的 50 个易主组里 **33 个读作 5.9**、16 个读作 6.0、1 个读作 6.1 ——
也就是说**真实的 6.0 秒通道在这份 dump 里通常量成 5.9**。
一个在 5.95 秒被打断的通道**同样量成 5.9**。
**这不是阈值没选好,是这把尺子的刻度(0.1s)正好等于它要分辨的差** ——
上一轮那个 `[5.8, 5.9]` 夹逼卡在 0.1 秒反例上,不是巧合,是必然。

⚠️ **本轮不声称 `value` 的语义**(它是层数还是"是否自然结束"的标志,dump 说不了)。
声称的是**它与 ground truth 在 88 个组上逐位一致,而阈值不是** ——
这正是条件 (a) 需要的那种判据:**不需要阈值,也不需要知道机制。**
