## 2. 这个 gate 的形状(逐字取自源码,不是转述)

`J.IsClosestToDustLocation`(`bots/FunLib/jmz_func.lua:11591`),
唯一 gate 解析点是 `ClosestDustCarrier` 包装器
(`bots/ability_item_usage_generic.lua:59`):

```lua
for i, id in pairs(AllyPIDs) do        -- AllyPIDs = GetTeamPlayers(GetTeam())
    local nSlot = id                   -- 一个 PLAYER ID(0-4 / 5-9)
    if bSlotDust then nSlot = i end    -- gate:一个队伍 SLOT(1..5)
    local member = GetTeamMember(nSlot)
...
if closest ~= nil then return closest == bot end
```

`GetTeamMember` 收的是 **1..5 的队伍槽位**,越界答 nil ⇒ **未 armed 时被扫到的
名单由 player id 的数值决定,而且分侧**:

| 侧 | 未 armed 扫到的槽位 | 扫不到的槽位 |
|---|---|---|
| radiant(id 0..4) | 1,2,3,4(id 0 越界) | **槽 5 = pid 4** |
| dire(id 5..9) | 只有 5(6..9 越界) | **槽 1..4 = pid 5,6,7,8** |

`closest == bot` 只可能对被扫到的英雄为真 ⇒ **未 armed 时,一次走 gate 分支的
扔尘对上表右列的英雄是不可能的**。这就是零基线控制。

`X.ConsiderItemDesire['item_dust']`(`:7279`)是 `bots/` 里**唯一**的扔尘点
(已普查:其余 `item_dust` 命中都是采购表、`modifier_item_dustofappearance`
读取、以及 helper 自身),五条返回路径按序:

| 分支 | 条件 | 是否 gated |
|---|---|---|
| B1 | trees<5;敌人 0.2–0.5s 前最后可见;落点 <600u;**ClosestDustCarrier** | **是** |
| B2 | 自己带 `modifier_sandking_sand_storm_slow` | 否 |
| B3 | 1050 内无敌人;自己带 `modifier_item_radiance_debuff` | 否 |
| B4 | 1050 内无敌人;`WasRecentlyDamagedByPlayer(id,0.5)`;该敌落点 <1050 | 否 |
| B5 | 1050 内有敌人;它要隐身;**ClosestDustCarrier**;无反隐;非幻象;700 内无敌塔 | **是** |

## 4. ⭐⭐ 主要产出:两个**方向偏宽松**的仪器缺陷,都是零基线控制自己抓的

第一次真语料运行打出 **armed 23 / baseline 10**。基线本该恒 0,于是逐条回帧,
两个缺陷都**只在放宽那一侧失效**(与 GH #429 / #432 / #433 / #436 同族)。

### (甲) ⭐⭐⭐ 战斗日志与快照 `items[]` 的物品词表**完全不相交**(新 LIMIT 9)

抓到它的是最后那条基线泄漏:`20260902_221349_slot1` ba 层 baseline,
`crystal_maiden` t=1468.6,hp 0.291,最近敌人 **7191u**。它前 2 秒的伤害是

```
t=1466.7  actor=npc_dota_hero_skeleton_king  infl=item_radiance  val=31
t=1467.7  actor=npc_dota_hero_skeleton_king  infl=item_radiance  val=31
```

—— **战斗日志逐字写着 `item_radiance`**,而本工具对同一局的
`items[]` 辉耀普查答 **`none`**。这是一次教科书式的 B3(1050 内无敌人 + 辉耀灼烧
debuff),却被放进了排他列。

**全语料实测(64 局)**:

| 通道 | 不同名字数 | 交集 |
|---|---|---|
| `events[].inflictor` 里的 `item_*` | **87** | |
| `snapshots[].items[]` | **164** | **0** |

`items[]` 是**去前缀**的(`item_radiance` → `radiance`),而且对若干物品
**根本不是去前缀**:

```
item_dust           -> dustof_appearance
item_ward_observer  -> observer_ward
item_ward_sentry    -> sentry_ward
item_bottle         -> empty_bottle      (语料里唯一的瓶子拼法)
```

⇒ **一个带 `item_` 前缀的字面量拿去比 `items[]`,不是偶尔漏,是恒假**,
而且对任何「敌人**没有**带 X」形式的排除条件,**恒假 = 恒不排除 = 恒放宽**。
`item_radiance` 在本语料的战斗日志里有 **20,167 条伤害事件**,
而 `items[]` 里出现 **0 次** —— 缺陷因此**连一次可疑读数都不会产生**。

### (乙) `WasRecentlyDamagedByPlayer` 是**按玩家**不是按英雄(新 LIMIT 10)

B4 的排除原本只看 `actor_hero == True` 的伤害。但该 API 记的是**某个玩家**造成的
伤害,**包含他的召唤物与幻象**,而那些 actor 在战斗日志里不是英雄 ⇒
恰好在这些帧上 B4 仍然可达。已改为**任何**落在施法者身上的伤害都解除排他列
(顺带扔掉只有肉山/防御塔伤害的那些,富余在安全一侧)。

### 两个修法的效果(同一份 64 局语料,逐位对照)

| | armed | baseline |
|---|---|---|
| 修前 | 23 | **10** |
| 修后 | 14 | **9** |

`ab armed` 那一栏从 **8 掉到 0**(全部是敌方有辉耀的局)。
**修完基线仍然不是 0 ⇒ 见 §6。**

## 5. ⭐ 副产品:一个**现役工具**上的活缺陷(同一个 (甲) 词表)

普查全目录后,其余带 `item_*` 字面量的工具都是拿去比 **events**,是对的;
`fieldregen_supply.py` 比 `items[]` 时用的是裸名 `"flask"`/`"tango"`,也是对的。
**唯一一处踩中的是 `fieldsip_domain.py:496`**:

```python
for name, val in re.findall(r"(item_\w+)\s*=\s*(\d+)", m.group(1)):
    out[name[len("item_"):]] = int(val)     # 假定「去前缀」就是快照拼法
```

它把 Lua 的 `J.FIELD_SIP_HEAL` 逐字反解析,再**去前缀**当作快照名。
对 `flask` / `tango` / `tango_single` / `faerie_fire` 这样是对的,
**对 `item_bottle` → `bottle` 是错的**:本语料 64 局里瓶子的快照拼法
**只有 `empty_bottle`(86,023 次),`bottle` 出现 0 次**。

⇒ 该工具**从来没有认出过任何一个瓶子**。瓶子在它的分类里属于 `AMBIGUOUS_ITEMS`,
所以带瓶子的帧不是被误判成 CERTAIN,而是被当成**根本没有补给源**——
这会改变 `IsFieldRegenSituation ∧ HasFieldRegenSource` 那个合取的域。
**`fieldsip` 的 WORKING 裁定(§7079,15 episodes)就是这个工具给的**,
本组**不撤销该裁定**(方向未量、不在本轮范围),但**登记为待复算**,已开 issue。
