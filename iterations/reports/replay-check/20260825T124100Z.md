## 3. 判据 (4):校准判据到底接住了多少 —— **WORKING,但天花板是算出来的**

### 3.1 每条腿怎么读、误差朝哪边(这决定了结论的强度)

| 子句 | 读法 | 误差方向 |
|---|---|---|
| `botLevel <= 9` | **精确**(`snapshots[].level`) | 无 |
| `CanBeSeen()` | **不读,一律当真** | **偏向注释**(只会把接住率读大) |
| `#hAllyHeroList <= 1` | 几何,1600 u 内**活着的、非幻象**队友 | 近似精确;`J.GetAllyList` (`jmz_func.lua:3761`) 就是 `GetNearbyHeroes(bot,1600,false)` 减去死人与幻象,而 `:3767` 的 `<= 1` 短路**改不了 `#list <= 1` 的真值** |
| `GetAttackTarget() == bot` | **单向证人**:塔的 `DAMAGE` 事件打在他身上、且在 ±1 s 内 ⇒ 塔确实在打他;**没有事件不等于否定** | 有证人 = 下界 |
| 同上的**算术地板** | 塔的攻击距离 **700 u**。`d_tower > 700` 时 `GetAttackTarget() == bot` **不可能为真** | **无建模,纯算术** |

于是读数是一个**三明治**,不是点估计:
`UPPER = lvl≤9 且 alone`(两条不可观测子句全部无偿送给注释)、
`UPPER+r = UPPER 且 d≤700`(算术地板)、`LOWER = UPPER 且有证人`。

## 4. 判据 (3):反向判据「死亡数不许上升」—— **未触发**

窗口内(等级 6–10、150 ≤ t < 300)真实英雄死亡。**死亡按 GH #176 的教训加固**:
一条 `DEATH` 事件只有在**快照链确实断掉**(t 之后 2 秒内没有该英雄的活帧)时才算真死,
否则那是**幻象顶着英雄名死的**——这条守卫在 selfcheck 里有正反两个用例钉住。


armed − baseline,每英雄局:**W8 ab −0.032 / ba +0.033(均衡 +0.000)**;
**W9 ab −0.025 / ba +0.009(均衡 −0.008)**。
⇒ **两波都两层反号**,按 GH #148 (i) **不进结论**;能说的只有一句:
**在任何一波、任何一层上都读不出「死亡上升」,均衡估计压在 0 上。判据 (3):未触发。**

⚠️ **一个必须自己拆掉的假阳性**:`towerfear_domain.py` 的 `dth%`(以死亡收尾的塔环 episode 占比)
在 R_lever 上是 **+0.47 / +2.78 两层同号**,看着像「armed 腿死得多」的两层同号证据。
**它不是。** baseline 腿在两层里都恰好是 **0.0%**(0/64、0/100),分子总共 **3 个 episode**
(armed 1/214 与 2/72);两层同号**完全由「baseline 恰好为零」制造**。
这正是 GH #148 (ii) 那条立法的形状:**小值域计数量的「同号」可以是分母造出来的**。
**同一批 1–5 个事件,换个分母就换个符号** —— 本轮两个读数(`dth%` 与 `twr/hGm`)方向相反,
就是同一件事的两面。**两个都不读。**
