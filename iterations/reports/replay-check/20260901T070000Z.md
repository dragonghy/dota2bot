## 3. 交棒 (1):向后看窗口常数的审计 —— 三个答案,一个撤回

交棒原文点名 `bbfloor_domain.py` / `stayfield_domain.py` / `idletrip_domain.py`,
理由是上一轮量到「WK 在场时死→活的下界由 Reincarnation 决定(实测 3.2s),不由复活计时器」。

### 3.1 `idletrip_domain.py` / `stayfield_domain.py`:**不是宿主,但这句话是读来的不是量来的**

两者的向后看窗口(`RETURN_WINDOW_S=60`、`HORIZON_S=30`、`DEATH_BLANK_S=1.0`)
**都不以「死后多久能活」立论**:`idletrip` 的走位扫描按 docstring **在死亡/尸体帧终止而不是跳过**
(三个更早的版本正是死于跳帧,已记在它自己的 docstring 里),复活因此不可能被记成「走回家」。
**本轮没有为这一条买测量**,只做了代码阅读 ⇒ **按「论证不是测量」登记为未检验**,不写进结论。

### 3.2 `bbfloor_domain.py`:**常数的算术依据是假的,推翻它的是这个工具自己的输出**

`REINCARNATION_MAX_S = 8.0` 原注释逐字写着:

> "The shortest turbo respawn possible is 12 * 0.75 = 9s at level 1 ... so this
> threshold cannot eat a real respawn in the domain we read."

**W33 实测的 realised turbo respawn 表(这个工具自己打的)第一行就否掉它**:

```
level       n      min   median      p95      max
1           9      7.1      9.7     10.1     10.1
```

**level-1 的最短真实复活 = 7.10s,坐在 8.0s 阈值的下面,不是上面 1 秒。**
帧证据:`25b94f/20260901_035747_slot1` skeleton_king,DEATH **t=56.3**,level 1,
span **7.10s**,`jumped=True`。
(1Hz 采样让 span **高估**至多一格,而 DEATH 事件迟到会往反方向推 —— 本语料事件迟滞
median 0.0s / p95 0.9s / max 3.6s ⇒ **两个方向都够不到 9s**。
被推翻的是 jmz_func 头部引用的「level 1 = 12s」那一半;**0.75 那一半站得住**:
实测 max clean span **76.2s** vs 预测天花板 **75.0s**,差一格采样。)

⇒ **时长那一半不自足。** 真正把真实复活挡在 in-place 桶外面的是**位置那一半**(`jumped`),
`in_place` 是个合取式。本语料两族的实测间隔只有 **1.10s**(in-place max 6.00s < real min 7.10s)。

### 3.3 我的第一个缺陷假说是错的,**是变异台打红的,不是我看出来的**

我据 3.2 提的假说:「尸体锚被污染 ⇒ `jumped` 反转 ⇒ 一次 Reincarnation 混进复活表」。
写完断言跑变异台,**M4 SURVIVED** —— 按证据纪律 2 先怀疑断言,查出来我的 fixture
让两种锚**取到同一格**,那条断言什么都没测。改成能判别的形状之后,**它在 pristine 代码上就红了**,
逼我去读真码:

**`bbfloor` 的尸体锚是 `hp_pct <= 0.5` 的第一格,不是 `hp_pct <= 0.05` 的第一格。**
WK 那次死亡里,`1312.40 hp=0.065` 已经 ≤0.5 ⇒ **它锚在这一格,坐标 (1271.2, 1037.7),正是他倒下的地方**。
那个可疑的 (616.1, 64.3) 是**下一格**,`bbfloor` 根本不看。
⇒ **`bbfloor` 对这个形状免疫,而且这是量出来的不是论证出来的**(见 §3.5 的读数)。

### 3.4 ⛔ 撤回上一轮发表的一句读数:「尸体那两格报的是泉水坐标」

上一轮(章程 03:45Z 条、报告 §…)的副产品逐字写着
**「尸体那两格快照报的是泉水坐标 `(616.1,64.3)`」**,并据此说
「⇒『坐标回到死点』是干净判别器」。

**逐帧复现同一局同一段(直接读 timeline,不经过任何被检工具)**:

```

```

**同一局里两个泉心的质心**(各队自己开局前的首帧,与 `stayfield_domain` 同法):

**撤的是什么**:⛔ 「尸体帧报泉水坐标」这句话,以及**任何以它为前提的判别器论证**。
**不撤**:✅ 那次 in-place 的结论本身 —— 它还有**两个独立证人**(复活格与倒下格逐位相同;

### 3.5 留下的真东西:**两个尸体锚会互相不同意,而且量得出来**

不是「锚被污染」,而是**「尸体」不是一格是两格,它们不总是一致**:
`bbfloor` 用 `hp<=0.5` 的第一格,**兄弟工具用 `hp<=0.05` 的第一格**。落地成
`death_spans()` 的新字段 `anchor_slip`(两锚之间**超出一个英雄能走的距离**的那部分,

| 语料 | 两锚不一致 | 最坏 slip | 最坏**位移** |

| W33 5 局 | **0 / 234** | 0u | — |
| W32 `93546a` 3 局 | **1 / 136 (0.7%)** | **623u = 1500u 阈值的 42%** | **1173u = 78%** |

工具自己点名的那一行(`--dump-rows`):
`20260831_221121_slot1 skeleton_king 1312.2 slip=623.3 span=3.2 jumped=False in_place=True`
—— **span 3.2s 与上一轮的 `D min=3.2s` 逐位对上**。

**谁暴露在这个风险下**:**不是 `bbfloor`**(它锚在更早那一格,两次不一致里那一格都在死点上);
是**任何锚在真尸体上的兄弟工具** —— 那里 1173u 打进 1500u 的跳变阈值,只剩 **327u** 余量,
而且**落在 `skeleton_king` 身上,正是尸体锚当初被引进来保护的那个英雄**。
**哪一格在说谎,从 dump 里判不了**(没有第三个位置证人)⇒ **只报不修**。
