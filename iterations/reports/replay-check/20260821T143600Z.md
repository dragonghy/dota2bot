## 3. 主结果

### 3.1 承重子句引的是一个代码里不存在的数(#90 §1)

`capmono_refusal.py` 域注释:

> NEAREST ENEMY IN [850,1500] -- the load-bearing clause: **>850u guarantees
> `lanesurv`'s burst retreat does not fire on its own**

`J.ShouldRetreatLaneBurst`(`bots/FunLib/jmz_func.lua:4892`):

```lua
local tEnemies = J.GetNearbyHeroes( bot, 1100, true, BOT_MODE_NONE )
if tEnemies == nil or #tEnemies == 0 then return false end
```

买到那条保证的阈值是 **1100**;`850` 这个字面量**在 `jmz_func.lua` 里零出现** —— 不是抄错了某个门,
是检测器自造的数被当成了对一段真实代码的断言。

| 带 | 帧数 | armA(armed−base) | armB | DiD |
|---|---|---|---|---|

(armed 侧 radiant,seed 895),hp=0.476,最近敌 SK **852u**(比底线高 2 个单位),

### 3.3 判决不变,可引用范围收窄

收窄到真正可归因的 `[1100,1500]` 重算:**seed-paired DiD −11.90pp,SD 37.0,SE 18.5,|t| 0.64**,
per-seed `[+2.7, +20.6, −64.8, −6.1]`。比登记的 −7.70 ± 10.9 更负一点,但 **n 减半、噪声翻倍,
仍与零不可区分** ⇒ **#72 的 NOT-PROMOTE 不变**。

- 可以说:**「在 lanesurv 结构上够不着的带里,没测出 capmono 设计的拒扑签名。」**
- **不能**说:「capmono 对生存没用 / 无害。」**生存通道 92% 在域外,这个域从来没测过它。**

顺带一个 promote 讨论用得上的上界(与 #56 给 `axeblink` 的占空比上界同形):
**域内 12s 死亡率仅 3.2% ⇒ capmono 在这份语料上的生存收益天花板本来就很低。**

### 3.4 第二种耦合:帧级率是驻留加权的,而驻留时长由结局决定

出带方向(每 episode 末帧的下一帧去了哪):

| cell | CLOSED(<850) commit:retreat | BACKED OFF(>1500) commit:retreat |
|---|---|---|
| armA armed | 15 : 4 | 3 : 5 |
| armB armed | 22 : 3 | 3 : 9 |
| armB base | 18 : 3 | 3 : 3 |

方向如预期(扑上去从下沿出带,后撤从上沿出带),而**每 episode 帧数按结局分裂且逐 cell 反号**
(armA armed retreat 2.83 / commit 2.17;armB armed retreat 1.94 / commit 2.19)⇒ 两个估计量:

```
  frame   : armA  -7.9pp   armB  +0.2pp   DiD  -8.1pp
  episode : armA  -9.4pp   armB  +0.7pp   DiD -10.1pp
```

量级不大(与 10:51Z 登记的「帧级怕采样、episode 级不怕」同族),但**报 DiD 必须写明是哪一个**。
