## 3. ⭐ 新缺陷:`detect.py` 把地图镜轴写死成 `x+y == 0`,这张图的镜轴是 `x+y = −372`

### 3.1 先量尺子(54 局里 18 局逐局验,读数逐位相同)

`detect.py:343-362` 的注释与实现都假定 river/midline 是 `x+y == 0`。
从**建筑坐标**(不是英雄坐标,建筑是地图本身)算这张图自己的镜轴:

```
(2,'ancient') x+y = −11272        (3,'ancient') x+y = +10528   -> 轴 = (−11272+10528)/2 = −372.0
(2,'barracks') 六座 x+y = −10640,−10603,−10132,−10094,−9259,−9224
(3,'barracks') 六座 x+y =  +8519, +8526, +9394, +9440, +9919, +9984
   由内向外两两配对的中点 = −328.0 … −366.5,均值 −347.5,极差 38.5
```

**18/18 局逐位相同**(`ancient_axis=−372.0`,`barracks_axis mean=−347.5`)——这是地图常数,不是对局量。

⇒ 判定门槛不对称 **744u**:天辉要 `x+y ≥ 3000`(真实纵深 ≥ 3372)才算越线,
夜魇要 `x+y ≤ −3000`(真实纵深 ≥ **2628**)。**夜魇提前 744u 被判越位。**
