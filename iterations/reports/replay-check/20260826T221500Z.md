## 3. 直接观测量:`abilanc_domain.py`(新工具,`--selfcheck` **33 PASS / 0 FAIL**)

**为什么另起一个文件而不是往 `campfarm_target.py` 里再塞一档**(两条,都写进了文件头):

1. `cast_at_camp` 是**每 episode 一个布尔**(episode 由「英雄↔远古」的 DAMAGE 事件串成,
   再问窗口内有没有施法)。`abilanc` 改的是**一次目标选择**,所以**事件本身**才是观测单位;
   绑在 episode 上等于额外加了一层门**并不知道**的 episode 归属过滤。
2. 标题问题(§2)——一个工具服务两个 id 时,`under` 那一行的语义在两边**相反**。

**等级是阶梯函数,所以用 bracket,绝不插值。** `entities.interp` 会把两个采样混成 `10.4`,

「插值 `hp_pct` 让尸体通过 `hp>0` 过滤」是**同一形状**。判据:

```
certain_under : hi <  12   (bracket 两端都在门下)
certain_over  : lo >= 12
straddle      : 单独一行,绝不悄悄归档
```

本波 **straddle = 0**(1Hz 下没有一枚施法恰好卡在升级的那一秒里),所以这层保险这次没花钱,
但**它必须先在**,否则「按 `lo` 归档」这个省事选择会**同时**抬高两条腿的低等级计数。

## 7. ⭐ 顺带的发现:**「门够不着」的类别比注释里写的多两类**

`jmz_func.lua:1836-1840` 那段「WHAT IT DELIBERATELY DOES NOT COVER」点名了两类:
**54 处 `list[1]`** 与 **14 处 sweep 质心**。本轮逐帧又实测出**两类它没点名的**:

- **(γ) sweep 只被当计数,目标来自 `J.GetProperTarget( bot )`** —— `hero_phantom_assassin.lua:641`;
- **(δ) 目标来自 `bot:GetAttackTarget()`(过滤 `TEAM_NEUTRAL`)** —— `hero_tidehunter.lua:516`。

这两类与 `list[1]` **性质不同**:`list[1]` 至少**从这张表里取**,过滤表就能改变它;
γ/δ **目标根本不来自那张表**,所以**任何列表编辑在原理上都够不着**。
⇒ 这不是 bug,是**分母的形状**:`abilanc` 能定价的部分比注释隐含的**更小**。
(与上一轮 `tpgap` 的「天花板」是同一种交付:**先把这个杠杆的上限说清楚**,
