## 三、`stayattr` 是什么,以及它为什么**能**从 dump 侧买(与 `creepthink` 相反)

`bots/FunLib/jmz_func.lua:5115-5120`,读自源码:

```lua
if bot:WasRecentlyDamagedByAnyHero( 3.0 )
    and ( not J.IsSoakCandidate( 'stayattr' )
        or J.HasNearbyHeroDamager( bot, 3000, 3.0 ) )
then
    return false
end
```

未 armed 时第二个合取项是字面 `true`,整句退化为「最近被英雄打过 ⇒ 永不原地回」;
armed 后**额外要求打你的人还在附近**(3000 内、可见、3 秒内打过你)。
⇒ `stayattr` **只能移除否决**,armed 的 TRUE 集是 shipped 的**严格超集**,方向由构造固定。

**armed-only 域**(两个读法唯一分歧、且函数后面没有别的否决把它吃掉的帧):

```
DOMAIN := 活着 ∧ hp_pct∈[0.18,0.75] ∧ 3s 内被英雄打过
        ∧ 3000 内没有「打过我的敌方英雄」 ∧ 1200 内没有敌方英雄(:5121)
        ∧ 有可观测的回复来源
```

⭐ **09-05T09:38Z 那轮把 `creepthink` 判为结构性测不出,理由是它只决定 `Think()` 走不走到下命令
那一行、而命令流不在 dump 里。`stayattr` 是相反的形状**:它读的每一个子句都是 dump 里的量
(`hp_pct` / 带 `actor_hero` 的 `DAMAGE` 事件 / 快照坐标算的两个距离),
**它改变的那个决策也是**——「原地喝」与「走/TP 回家」十秒后是不同的坐标。
**分界线不是「检测器 vs 经济」也不是「位置量 vs 非位置量」,是这个门推动的量有没有落到某个被 dump 的字段上。**

**四处系统性少算,方向全部相同(只会漏,不会造)**:
① 引擎的 `GetNearbyHeroes(..., true, ...)` 只看**能看见**的敌人,dump 给的是**世界真值** ⇒
雾里的施暴者引擎看不见(armed 落空 ⇒ 是域帧)、本工具看得见(判成「否决成立」⇒ 丢帧);
② 1200 环同理;③ **`bot:GetGold()` 不在 dump 里**(快照只有 `net_worth`),而末句是
`bHasFlask OR gold>=90` ⇒ 无可观测回复源的帧记 **AMBIGUOUS 不计分**;
④ `IsItemAvailable` 够得到信使/储藏室,快照 `items` 够不到。
⇒ **计分域是引擎域的严格子集**。**空域 = DOMAIN-NOT-REACHED,永远不是「测了没效果」;
而出现的域帧是真的**。条件 (a) 是正向命题,子集足以买正向命题。
