### 1.1 A-排除:**成立**,本轮独立重算通过

`bots/ability_item_usage_generic.lua` 的阶梯,自上而下:

```
:614  if not bot:HasBuyback() then return end
:624  if J.IsAncientBadlyHurt( ancient ) then ... nRemainingRespawnTime > 20 ... end   <- rung 1
:639  if nFullRespawnTime < J.BuybackShortRespawnFloor() then return end
:645  if bot:GetLevel() > 24 and nRemainingRespawnTime > J.BuybackFightRespawnFloor()  <- rung 2
:659  if nRemainingRespawnTime < 40 then return end

```

读法 A 下 `nRemainingRespawnTime = R − 2e ∈ [20.5, 32.1]`,`:659` **必 return**。
⇒ 终端 rung 不可达。rung 1 / rung 2 由上一轮三条独立排除掉(本轮**未重跑**,遵交棒 (2))。

⭐ **补一条上一轮没写、但结论依赖它的**:这个排除
**不依赖 `bbshort` armed 与否**。`bbshort` 只动 `:639` 的 `nFullRespawnTime` 门槛
(`J.BuybackShortRespawnFloor()`:60 → 60×0.75 = 45),而卡死 A 的是 `:659` 上的
`nRemainingRespawnTime`。两个门读的**不是同一个量**(`:619` vs `:620`)。
⇒ ogre_magi 在 dire(= 本局 armed 侧,`analysis.json:players` 独立复验)这件事,
对 A-排除**不产生影响**。

### 1.2 但「⇒ 只与 B 相容」**over-reach**

「A 假 ⇒ B 真」只有在读法**恰好两种**时成立。那个枚举**没有被买过**,它是继承来的。
本轮把它找出来了 —— 它写在源码里,写了三遍,每一遍都以「读法无关」的口气:

| 位置 | 原话 | 它实际独立于什么 |
|---|---|---|
| `bots/FunLib/jmz_func.lua:13808-13811`(#215 `bbfight`) | 「false on every reachable turbo frame, **under EITHER reading** of the getter」 | 论证是 `remaining ≤ R ≤ 75 < 80` —— **前提是 getter 返回一个「时长」** |
| `bots/FunLib/jmz_func.lua:13835-13836`(#222 `bbshort`) | 「The finding **does not depend on which way** the getter is read」 | 同上:「60 是 SECONDS OF RESPAWN」 |
| `bots/BotLib/hero_zuus.lua:1683-1691`(`zusultstrand`) | 「⭐ THE FACT IS **READING-INDEPENDENT**」 | 逐字枚举了两种:「0 while alive」与「the full duration」 |

三处都是**在 {A, B} 上**读法无关,**不是绝对的**。这不是说它们错了 ——
`zusultstrand` 那条尤其稳(两个天花板 75 < 130,任何「时长」读法都成立)。
是说:**「只与 B 相容」这句话,和它想推翻的 #208 登记读法,站在同一个未买的前提上。**

⛔ **本组不主张存在第三种读法。** 只主张:
**那句判决应写成「排除 A;在 getter 返回时长这一(未买的)前提下选 B」。**
`docs/BOT_API_REFERENCE.md:1106` 自己给的单位(「**Seconds until** this hero respawns」)
支持「时长」,**但那正是同一句里「remaining」被帧否掉的那份文档** ——
一份文档的前半句不能拿来给它自己的后半句背书。

## 2. 一条查过的**否定**结论(登记下来,别再走一遍)

**结论:假设不成立,已排除。** 复位存在,在 `:602-604`:


三条支撑:
1. 复位确实排在 `:596` 那组早返回**之后**,所以理论上有窗口;但守卫是

## 3. 头号产出:#208 的钉帧**在构造上买不到**,而那个 [harness] 字段**也修不了它**

上一轮交棒 (1) 写的是:

> `0128b9/20260912_100236_slot1` `t=1510.5` ogre_magi,断言
> `X.GetRemainingRespawnTime()` 落 [40,50) 还是 [20,32),**一次结清读法之争**;
> ⛔ 先确认 fixture 供不供得出 `GetRespawnTime()`,供不出就并进新开的 [harness] 单。

**本轮的答案:供不出,而且「供上」也结不清。两条腿,第二条才是要命的。**

### 3.1 腿一(意料之中):字段不在,loader 也不装

- `tools/batch_test/replayscope/make_fixture.py`:`grep -ci respawn` = **0**。dump 无该字段。
- `tests/mock/`:`grep -rn GetRespawnTime` = **0 命中**。loader **完全不装这个 getter**。
- 仓库自己逐字记过 —— `bots/BotLib/hero_zuus.lua:1740`:
  「The left-hand 0 those frames report is still a **LOADER GAP (nothing installs
  GetRespawnTime)** and not frame data.」
- 两个既有测试**直接把这个洞断言出来**,做得对:
  `tests/test_bbfight_turbo_respawn_ceiling.lua:156` 与
  `tests/test_bbshort_turbo_respawn_floor.lua:188`,均为
  `assert(bot:GetRespawnTime() == 0, 'GetRespawnTime is absent from the dump; ...')`。

### 3.2 腿二(要命的):**fixture 能钉决策,永远钉不了 getter 的语义**

把字段加进 dumper 也不行。dumper 能落的是 **R(完整时长)** 和 **e(elapsed)** ——
这两个量本组**已经有了**(跨度 + DEATH 事件),读法之争**从来不是缺 R 和 e**。
争的是**引擎那个函数返回 R−e 还是 R**。

而 fixture 里那个函数的**函数体就是本组要写的**。写什么进去,就得到什么结论。
⇒ **fixture 回答的是「给定语义 S,哪条分支响」,它在原理上回答不了「S 是什么」。**

⭐⭐ **这不是假想 —— 树上已经有一份,而且它做得诚实,诚实到把问题暴露出来了。**
`tests/test_bbrespawn_double_subtract.lua:92-96`:

```lua
-- Declare the one field the dump lacks, on the real handle, at the value the
-- engine would report e seconds into an R-second death.
local function declare_respawn(bot, R, e)
    rawget(bot, '__spec').GetRespawnTime = R - e
end
```

⚠️ **必须连着读它的文件头(`:19-24`),否则会把它读成作弊 ——它不是**:

> R is therefore a **DECLARED stand-in**, and it is declared as a COUNTING-DOWN one
> ... **because a constant stand-in would model the very misreading under test and
> make every row below pass for the wrong reason.**

它**明确标注了这是替身**,并且说清了为什么选 A —— 完全合规。
它证明的是一个**蕴含式**:「**若** getter 是倒计时,**则** 出厂那行双减了。」

⭐⭐⭐ **而 W69 那一帧,否掉的正是这个蕴含式的前件。**

于是形成一个**没有人会举手的组合**:
- `bbrespawn` 的立项论证 = 那个蕴含式;
- 它的前件 = 读法 A;
- W69 承重帧**排除了 A**;
- 而那个测试**永远是绿的** —— 它的前件是自己声明的,不是量出来的,
  语料再怎么反对它也不会变红。

⛔ **这不是「测试写错了」。** 是**一个标注正确的条件性测试,它的前件被真帧否掉了,
而树上没有任何东西把这两件事连起来。**

⭐ **可迁移判别子(建议进工具坑)**:
**当一个 fixture / stub 必须「声明」某个引擎 getter 的返回值时,
那个声明就是被测命题的前件,不是它的证据。** 这类测试的正确读法是
「若 S 则 P」,而 **S 要另买**;凡是它买不到 S 的地方,
**加 dump 字段也买不到** —— 字段落的是世界状态,S 是引擎的函数语义。

### 3.3 那么 #208 到底能怎么结清

三条路,按本组能不能自己做排序:

1. **重写成真正读法无关的形式(本组推荐,可落地,不需要引擎)** ——
   `zusultstrand` 已经示范过怎么做成功:不去读那个有争议的 getter,
   改从**已知量**推。这里现成:`J.RESPAWN_TABLE_MAX` / `J.TURBO_RESPAWN_FACTOR`
   已经在 `jmz_func.lua:13822-13823`,而 elapsed 由 `fDeathTime` 正确维护(§2 已复验)
   ⇒ `remaining = R_table(level) × 0.75 − e`,**一次都不碰争议 getter**。
   这是 [strategy] 的活,本轮已提到 #208(见 §4)。
2. **权威 API 来源** —— `docs/BOT_API_REFERENCE.md:1106` 是本仓自己的转录,
   而**它的后半句正是被帧否掉的那半句** ⇒ 不能自证。需要外部权威。
3. **实机观察** —— AGENTS.md 本来就写着「some things can only be verified at runtime」,
   且「**No bot-side debugging**」(`print()` 到不了 server console)⇒ 只能靠 owner 实机看。

⛔ **本组不建议为 #208 向 [harness] 要 respawn 字段。**
GH **#781** 要的 `has_buyback` 是**另一件事、完全成立**(它买的是 `:614` 那条合取项,
是世界状态不是函数语义),**本轮不动它、不给它加范围**。
