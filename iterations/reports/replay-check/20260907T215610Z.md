## 三、第一版判据被一帧真帧证伪(归组键)

GH #609 正文里我自己写的修法是「按 `(target, round(t1,1))` 归组」——
**即「同一座塔 + 同一个移除帧」**。它在 W53 上立刻撞墙:

```
20260907_063731_slot4  #DOTA_OutpostName_South
  zuus            1544.3 -> 1549.2   dur=4.9
  skeleton_king   1547.0 -> 1548.0   dur=1.0      <- 搭完车先走
  watch_tower (-4096,-448): t=1544.4 team=2 | t=1549.4 team=2 | t=1554.4 team=3
```

**塔易主了**(2→3,在 1549.2 之后的第二个采样上),买下它的是 **4.9 + 1.0 = 5.9
施法者·秒**。而「同一移除帧」的键把这两条拆成 **1549.2 的 4.9** 和 **1548.0 的 1.0**
两组,**各自都低于任何阈值** ⇒ **一次成功占领被记成两次中断**。

⇒ **正确的单位是「连续覆盖区间」**:同一座塔上,**至少有一条 channel 开着**的极大区间,
量的是**开着的 channel 数对时间的积分**。落地的是这个,不是 issue 里写的那个。
(同族正面例:`064849_slot2` witch_doctor 5.3 + zuus 0.7 = **6.0**,North 3→2 于
1189.5→1194.5 之间;**WD 自己的 5.3 在旧地板下也是一次「中断」**。)

**接缝仍然要断开**,这不是可选的:
```
20260907_063637_slot3  #DOTA_OutpostName_South   viper,leg=base
  1362.2->1363.0 (0.8) | 1363.2->1366.1 (2.9) | 1366.2->1367.1 (0.9) | 1367.2->1369.3 (2.1)
  合计 6.7 施法者·秒;South (-4096,-448) 从 1353.5 到 1393.5 **每一个采样都是 team 2**
```
**6.7 秒的施法,零占领。** 跨 0.1–0.2 秒的重发接缝求和,会造出一次游戏说没发生过的占领。
