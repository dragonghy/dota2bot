### 3.2 为什么 stamp 就是门文件,不是对它的推断

`tools/batch_test/soak/mirror_ab.sh`:

```
:33  line=$(CAND_REF="$CAND_REF" bash "$HERE/write_soak_side.sh" "$1" "$CAND" "$SEED")   ← 门文件
:77  RS="mirror:$CAND:s$SEED:radiant"                                                    ← stamp
```

`write_soak_side.sh` 是 GH #141 立的**唯一渲染点**,直接
`printf "return { side = '%s', cand = '%s', seed = %s }"`。
两者读的是**同一个 shell 变量、同一次 `deploy()` 调用** ⇒ 从 stamp 读出 `cand='918'`
**就是**农场上那一行 Lua 的内容。

`jmz_func.lua:4740` `SoakStrArms( '918', sId )`:仅当 `sId == '918'` 或串为 `'all'` 才真;
树里没有叫 `918` 的 id ⇒ **全 false**。
且 `J.IsSoakCandidateSide()` 在 `bots/` 里**没有活的调用点**
(只有 `mode_farm_generic.lua:111` 一句注释提到它)⇒
**两条腿在配置上逐字相同**,「radiant 是 armed 侧」在 W17 里没有任何行为含义。

### 3.5 为什么现有的门一个都没拦住(本条真正要修的地方)

- **发波前的接线门** `check_armed_wiring.py --cand <40串> --ref …` 校的是**打算发的串**对树的接线,
  **不是真正落到实例上的串**。它 exit 0 是对的,**也是没用的**。
- **收割侧静默** —— `recover_verdict.py:207-208`:

  ```python
  seeds = sorted(set(re.match(r"mirror:%s:s(\d+):" % re.escape(cand), st).group(1)
                     for st in by_stamp if st.startswith("mirror:%s:" % cand)))
  ```

  没有一个 stamp 以 `mirror:<40串>:` 开头 ⇒ `seeds == []` ⇒ `per_seed: []`,**不报错、不警告**。
  同时 GH #225 的输入普查照常打印 `files_seen 128 / games_loaded 128 / unparseable 0`。
  **两行合起来读作「局都在,只是没产出可用种子」,而真相是「局都在,但一局都不是这个 cand 的」。**
- 于是零产出被整条归因给了同一轮里**确实发生**的 AZ 回收(GH #252),
  **第二个、独立的、更早的失效原因没有任何东西举手。**

**这与本组自己踩过的那一族(#171 / #213 / #207 / #230 / #234 / #241 / #246 / #247)同形**:
工具在、纪律在、门也在,**但那道门校的不是最后落地的那个对象**。
区别在于前几例丢的是读数或适用面,**这次丢的是一整波的性质**。

### 3.6 建议的验收(都不花钱,已写进 GH #253)

1. **收割侧出声**:`recover_verdict.py` 在 `seeds == []` 时**非零退出**并打印**实际观测到的 cand 串集合**
   (本例会打印 `{'918','921','924','926'}`)。最小、最靠后、最不可能被绕过。
2. **发波后立刻核对部署**:起飞后第一局落盘时把它的 `script_version` 与传给 `spot_run.sh` 的串**逐字比**。
   比 (1) 早约 40 分钟,能省掉整波的钱。
3. (可选)拒绝纯数字的 `cand`。挡得住这一类位置写反,**挡不住「传了另一个合法但错误的串」** ⇒ (1) 优先。
