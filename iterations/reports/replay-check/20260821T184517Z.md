## 2. §AF.3:劫持率 A vs B(逐 cell)

`roam_conversion.py` 的 `CREEP-ONLY<=4s` 列**就是**总监要的那个检测器
(机会窗口开着 → bot 接下来 4s 的伤害落在小兵而非英雄身上)。缺的只是**分臂 + 按种子配对 +
给自己的读数一个分辨率**,本轮补上(新工具 §5)。

```
                     A delta   B delta      DiD  DiD sd   |t|    ARMED A-B      NULL Abase-Bbase
IN   hit_creep_only    +0.7      -0.0     +0.7     1.8   0.84    -0.0 +- 1.4    -0.8 +- 1.5
OUT  hit_creep_only    -3.6      +0.0     -3.6     3.2   2.28    +0.0 +- 0.0    +3.6 +- 3.2
```

**读法(这一列是本轮方法上的东西,值得留下)**:
`DiD = (Aarm−Abase) − (Barm−Bbase) = (Aarm−Barm) − (Abase−Bbase)`。
右式的第一项 **ARMED A−B 是唯一含代码差异的对比**,第二项 **NULL 是 DiD 主动减掉的一项**。

- OUT 那个看着显著的 `−3.6pp`(|t| 2.28)**整项来自基线腿**:候选侧 `+0.0 ± 0.0`
  (两臂 4 个种子**全部**读 0.0%),臂 A 基线侧 3/89、臂 B 基线侧 0/111。
- IN 的 `−0.0 ± 1.4` 同样是零。

⇒ **劫持率上,`roamstale` 的效应量是 0.0,不是「小」。** §AF.3 的张力
(「劫持值 −28 但修它只换来 +5.48」)**不能**由「`roamstale` 没中和它」这一支解释:
在这个可观测通道里,两臂的候选侧本来就一样,而且都接近零。

## 3. ⭐ 主结果:承重那个窗口的 null 通道不读零,而干净的那个窗口读反号

**null 通道是什么**:两臂跑的是**同样的 4 个种子**,两臂的**基线侧 gate 全关**。
所以「臂 A 基线 vs 臂 B 基线」是**同一份出厂代码的两个样本**,它读出多少,就是这个指标在
16 局/臂 上的**自身分辨率**。比它小的候选侧差值不构成证据。

| 窗口 | 对比 | 读数 | Fisher p |
|---|---|---|---|
| **OUT** | **NULL**(A基线 vs B基线,**无任何代码差异**) | 72/89 = 80.9% vs 104/111 = 93.7% → **−12.8pp** | **0.0079** |
| **OUT** | **CAND**(A候选 vs B候选,**差 `roamstale`**) | 75/78 = 96.2% vs 92/104 = 88.5% → **+7.7pp** | 0.0997 |
| **IN** | **NULL** | 342/409 = 83.6% vs 416/500 = 83.2% → **+0.4pp** | 0.9287 |
| **IN** | **CAND** | 309/409 = 75.6% vs 345/417 = **82.7%** → **−7.2pp** | **0.0128** |
| **IN** | CAND `no_dmg` | 90/409 = 22.0% vs 62/417 = 14.9% → **+7.1pp** | **0.0091** |

**三件事同时成立:**

1. **(a) 承重的 OUT 窗口里,零通道比效应还显著**(p=0.0079 vs 0.0997)。
   种子配对分解:`DiD +15.2 = ARMED(+5.7) − NULL(−9.5)` ⇒ **登记 DiD 的约 63% 住在
   两条本该相等的基线腿之间**,那部分不可能是 `roamstale`(gate 全关)。
2. **(b) IN 窗口的零通道干净**(+0.4pp,p=0.93,n=909),**而且 episode 多 5 倍**
   (826 vs 182 候选侧)。**在这个干净窗口里,带 `roamstale` 的那臂对英雄的投递率低 7.2pp、
   零伤害率高 7.1pp,两项都显著。**
3. **(c) 这不是供给伪影**(GH #92 的教训本轮先查了):承重对比是**候选 vs 候选**,
   IN 窗口供给 **409 vs 417,比 0.98**。(臂 B 的**臂内**供给确有不对称 417:500 = 0.83,
   但我的承重对比不经过那条腿。)

**机制上这两个符号可以同时为真,而且不矛盾**:reset 只会**移除**一次陈旧的小兵攻击
(代码注释自己写的 "can only ever REMOVE a stale creep attack, never add one")。
移除掉的那一拍,laning 期本来**确实在打出伤害**(打的是小兵,但机会窗口的 4s 伤害判定
`hit_hero` 为假、`no_dmg` 也为假 → 落在 `hit_creep_only`);移除之后 bot 在那一拍**什么都不打**
⇒ `no_dmg` 上升。**out 窗口恢复的是远距投递,in 窗口付掉的是近距输出。**
条件 (a) 只引了前一半。

**⇒ `roamstale` 的执行核验状态由 `WORKING` 改判为 `WORKING(单向)/ (a) 证据窗口选择性`。**
我不建议直接回滚(IN 窗口的 −7.2pp 也可能正是「设计上要移除的那些帧」被移除后的账面代价,
录像不可判定它值不值);建议的是**条件 (a) 重读**,裁定权在总监。

## 4. 诚实边界(逐条,不藏)

1. **null 通道是「近似零」不是「认证零」**:镜像局的基线侧**对手是候选侧**,而两臂的候选侧
   差一个 `roamstale`,所以存在一条对手中介的路径。但这条路径若真值 −12.8pp,**它本身就是
   一条该登记的 `roamstale` 效应**;无论走哪一支,「DiD 的两条基线腿可交换」这条假设在 OUT
   窗口都不成立。
2. **保真度只对上一半**(§1),我未回滚工具版本重跑。
3. **视野**:录像是全信息,「800u 内有 ≤40% 血敌人」不等于 bot 看得见(本组既有登记缺口)。
4. **`hit_hero` 含被动光环**(16:55Z §乙):本轮承重对比是**同指标两臂相减**,光环在两臂对称,
   但绝对水平(75-96%)不能当「主动投递率」读。
5. **`#69` 第二个部署点本轮实测不咬**:`roam_conversion.load_game:220-223` 用「帧数最多」选主实体,
   章程 09:00Z 要求「最早出现时刻」。32 局里有 **25 例同名多实体**,两条判据**逐例一致(0 例分歧)**
   ⇒ 本轮结论不受影响。**代码仍是潜在错的**(低血壳帧数能到 656),该修,只是这份语料上没触发。
   这条关掉我上一轮登记的「下一轮优先 (5)」。
6. **OUT 窗口 n 小**(候选侧 78/104),`killed` 指标在两窗口都被噪声淹没(DiD sd 11.7 / 39.6)。
