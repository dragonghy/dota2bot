开工自检(铁律 10)读到 **3 条 python 红**,其中两条已立案、一条没有:

| 失败的用例 | 状态 |

**复现与归因(逐字,不是推测)**:失败的那条 check 是
`'the API reference still names GetNeutralSpawners().team/.type -- if this section
stops parsing, the audit above is reading nothing'`(`tests/test_detector_source_constants.py:1074`)。
解析器是 `tools/batch_test/behavioral/campsel_domain.py:302`:

```python
doc_fields = dict(re.findall(r'^-\s*`(\w+)`\s*\((\w+)\)', section, re.M))
```

`docs/BOT_API_REFERENCE.md § GetNeutralSpawners()` 的 `.type` 那一行今天 07:48Z 被
**`f0730537`(协同组 07:45Z)**从 `` - `type` (unverified): `` 改写成
`` - `type` (unverified -- **and the method that settled `.team` provably cannot settle it**): ``。
`\((\w+)\)` 要求括号里**一个词紧跟右括号**,新写法不满足 ⇒ **`type` 这一行不再被解析出来**。
亲手对拍:

```
doc_fields 现在  : {'team':'settled', 'speed':…, 'location':…, 'idx':…, 'min':…, 'max':…}
doc_fields 改之前: {'team':'settled', 'type':'unverified', 'speed':…, …}
```

**⭐ 而真正值得立案的不是这条红,是它的邻居**:紧跟其后的那条
`'the API reference no longer types .team/.type as int -- putting the int back
re-arms a refuter that was never a source (GH #241)'`(`:1077`)写作

```python
CS_PRE['doc_fields'].get('team') != 'int' and CS_PRE['doc_fields'].get('type') != 'int'
```

`type` 一旦解析不出来,`.get('type')` 是 `None`,`None != 'int'` 为真 ⇒ **这条 check 现在
真空通过**。也就是说:**同一次文档编辑让一条 check 变红、让它旁边那条护栏静默失效**,
而**只有变红的那一条会举手**。GH #241 那个「被退役的反驳者」的防回归护栏,
从今天 07:48Z 起**已经不在岗**,而 CI 只会报一条红。

**⚠️ 归属**:`.type` 那一行的改写**内容本身没有错**(协同组 07:45Z 的 §EB 结论是对的,
本组不打假它);错的是**解析器与文档之间没有契约**,一次正常的文档编辑就能同时
**弄红一条 check、弄哑另一条**。所以这是 `[bug]` 给总监,不是 `[strategy]` 给协同组。
