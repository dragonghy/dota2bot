## 三、交付二:⭐⭐ 还债时量到的 harness 缺陷 —— UNCOVERED 的分类对 46% 的文件是反的

### 3.1 立案句

开工自检对 `no_manifest_row` 这一类打出的是这两句(逐字):

```
UNCOVERED (no automatic reader runs these): 115 of 508 (23%)
A test nobody runs cannot refuse a push, so its red is found by the
NEXT desk to start work (GH #624, GH #806).
```

而 `tools/agent/lua_gate.py` 自己 **`:369-378`** 有一整个 `for rel in unmeasured:` 循环
(`unmeasured = on_disk - set(manifest_tests)`,即**恰好就是 `no_manifest_row` 那一类**),
跑它、并在 `rc != 0` 时 `findings.append(...)` ⇒ **`EXIT_FINDINGS = 3` ⇒ 拒绝 push**。
⛔ **两句话不能同时为真。**

### 3.2 不靠读源码下结论:搭台实测(证据纪律)

台子用的是 gate **自己提供的**重定向口 `LUA_GATE_ROOT` / `LUA_GATE_MANIFEST`
(它每跑必打一行 `LUA GATE REDIRECTED -- ... (not the repo's own)`,⭐ 一道**会自己喊出来**的旁路,
与 W75 那条坑同向)。台子 = 三个人造测试 + 一份两行的 manifest:

| 测试 | manifest 行 | 内容 |
|---|---|---|
| `test_stand_green_selected.lua` | `in_gate: true, 0.2s` | 恒绿(让 `selected` 非空,否则 gate 按 `:280` 判 COULD NOT RUN) |
| `test_stand_red_norow.lua` | **无行** | 恒红 |
| `test_stand_red_inrow_false.lua` | `in_gate: false, reason: too_slow, 9.9s` | 恒红 |

`--list` 先自证三者分类正确:`IN` / `NEW (never measured)` / `OUT (9.90s, too_slow)`。

**三次读数(退出码全部未经管道)**:

```
STAND_GATE_EXIT=3      FAIL  tests/test_stand_red_norow.lua  (exit 1)
                       lua gate: 2 ran, 1 findings, ...
                       1 new test(s) not in the manifest were run anyway, costing 0.00s:
                           tests/test_stand_red_norow.lua
CONTROL_EXIT=0         (把无行那条红移走之后)  lua gate: 1 ran, 0 findings, ...
DIRECT_EXIT=1          lua5.1 tests/run_tests.lua test_stand_red_inrow_false.lua
                       → 1 tests, 1 failures
```

⇒ 逐条:
- **无 manifest 行的红 → 被跑、被点名、`exit 3`、push 被拒。**
- **有行且 `in_gate: false` 的红 → 一次都没被跑**(对照轮 `1 ran`),gate `exit 0` 干净放行。
- ⭐ **对照轮证明它是 skip 不是 pass**:同一个文件直接跑是 `DIRECT_EXIT=1` / `1 failures`,
  **它是真红**,只是 gate 不看它。(⛔ 少了这一跑,`0 findings` 就会被读成「它是绿的」——
  又一个 did-not-run wearing a pass。)

### 3.3 缺陷在哪一行

`tools/agent/lua_gate_coverage.py:135-137`:

```python
def gate_covered(manifest):
    """Files the push hook actually runs -- `in_gate`, never a filename."""
    return {k for k, v in manifest.get("tests", {}).items() if v.get("in_gate")}
```

**docstring 逐字说「push hook actually runs」,而它算的是「manifest 里 `in_gate` 为真的」** ——
gate 真正跑的是 `in_gate` **∪** `unmeasured`。少掉的正是 `unmeasured`。

### 3.4 代价(今天 trunk 上的数)

`UNCOVERED 114 = {no_manifest_row: 52, timed_out: 60, too_slow: 2}`
⇒ **52/114 = 46% 被反着分类**:它们是**被 push 闸跑着的**。
真正没人自动读的是 `timed_out` + `too_slow` = **62** 个。

**⭐ 而且刀口朝着错的方向,不是只是数字不准 —— 自检开的药方会真的减少覆盖:**
药方第一条逐字是 `measure it under the cap and re-run lua_gate_measure.py`。
对一个**跑得完、但秒数超过 `per_test_cap_seconds`(5.5s)** 的测试,
re-measure 会给它写 `in_gate: false` ⇒ 它**从「闸在跑」变成「闸不跑」**
(台子里 `test_stand_red_inrow_false.lua` 就是这一格),此后**它的红再也拦不住 push**。
⇒ 照药方做,这一类**从被覆盖变成不被覆盖**,而覆盖工具此后**如实地**把它记成 UNCOVERED,
**两边都不会有人喊**。

### 3.5 ⛔ 三条限制,引用本节必须连着抄

1. **两类共享同一个前提**:Lua 腿只在 push 碰了 Lua 路径时才跑(`--if-touched`)。
   这一条对 `in_gate` 与无行两类**同样成立**,所以 §3.2 的对比是公平的;
   但「被 push 闸跑」**不等于**「每次 push 都跑」。
2. **无行的测试有一条逃逸口,而它是 `lua_gate.py` 自己文档过的**:无行的测试若**超时**,
   进 `new_over_budget`,源码 `:358-368` 逐字说它 `counted NOWHERE` ⇒ 不拒绝、不计数。
   所以本节的判词精确形式是:**无行 + 普通失败 ⇒ 拒绝 push;无行 + 超时 ⇒ 静默排除。**
3. ⛔ **本轮无法给这个行为定年份,因此不裁定它是不是"今天才变的"**:本容器是
   **shallow clone(`git rev-parse --is-shallow-repository` = `true`,深度 50)**,
   `git log -S 'for rel in unmeasured:'` 只回到**边界提交** `f0b5ea4e`,
   `f0b5ea4e^` 报 `fatal: invalid object name` ⇒ **那不是它的诞生点,是我的视野边界**。
   ⭐ 但**仓库里已有两条互相矛盾的记载**,不需要我来断年份就能看出这是笔糊涂账:
   - **GH #806**(2026-09-13T21:06)立案句逐字:`…earlyreturn_domain` **既不在 `known_red`,
