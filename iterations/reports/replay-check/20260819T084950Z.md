## 2. 核验结论

### `l1trade`: **SILENT**(无可归因行为差异)
### `l5combo`: **SILENT**(无可归因行为差异)

两者都不是"门从未为真"(离线无法证明),而是:**(i) 设计出价在其整个生效域内
结构上不可达;(ii) 333 个满足全部可观测门的窗口里,armed 侧与 baseline 侧没有

### 2.1 机制(代码级,可静态核对)

- 两分支出价 `RemapValClamped(GetHP, 0, 0.5, NONE, 0.92)`
  (`mode_team_roam_generic.lua:199` / `:212`),血量 ≥50% 即 0.92;
- `GetDesire()` 过 `CapForLanePush` → `_divecap_CapForLanePush`(同文件 L78-90):
  **laning phase 内 desire > 0.9 一律压到 0.72**;唯一豁免要求
  `bDefensiveCollapse` + armed `divecap` —— 这两个分支**都没设** `bDefensiveCollapse`
  (上面的 `punishDive`/`overchase` 设了),`divecap` 也不在 armed 集;
- 而两个 helper 都有硬性 `if not J.IsInLaningPhase() then return nil end`
  (`jmz_func.lua:6582`/`:6652`)—— **cap 条件是规则生效域的超集**。

推论(算术):有效出价恒为 **0.72 < `BOT_MODE_DESIRE_HIGH` (0.75)**,与
L184-189 注释按"要压过已 promote 的 lanesurv(0.75)"所做的推理直接冲突;
且有效出价对血量**非单调**(满血 0.72,~48% 血反而 ~0.90)。
armed 侧 **71.0% / 71.2%** 的 episode 里 actor 血量 ≥48.9%,即 cap 实际生效。
