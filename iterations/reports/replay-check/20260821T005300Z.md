### 2.1 出价算术(带的边界不是拍脑袋画的)

两条分支都 `return RemapValClamped(HP, 0, 0.5, NONE, 0.92)` = `min(0.92, 1.84·HP)` 并置
`bLaneKillCommit` ⇒ **整条豁免** `CapForLanePush`(GH #31 的修复)。而它们**抢在前面吃掉**的
东西在对线期是被夹的:下面那条 last-hit 分支 `return 1.5` → cliff 把 >0.9 拉到 **0.72**;
`CarryFindTarget` 的兜底是 `BOT_MODE_DESIRE_HIGH` = **0.75**。所以

```
1.84·HP > 0.75  ⟺  HP > 0.4076      armed 出价赢过它顶掉的东西
1.84·HP > 0.72  ⟺  HP > 0.3913
```

**HP < 0.408 时,这条分支是拿一个更低的出价去顶掉一个更高的出价** ——
门在它最想打架的帧上反而把 team_roam 的 desire 压低了。这是算术,不是假说。
**下面第 4 节把它当内生 placebo 用,而它恰好交出了本项目迄今最干净的一次 id 归属。**

## 7. 新踩的坑(登记,别再踩)

1. **`commit`(任意伤害)不是决策指标 —— 被动 AoE 会替不动的英雄打卡。**
   `_182322`(s896)t=80.5:检测器记 `zuus`(p4,armed)commit + 「靠近 791→195u」;
   逐帧真相是 **zuus 坐标 6 秒一动没动**(是 slardar 在靠近**他**),唯一落在目标身上的伤害是
   `zuus_static_field`(每次施法的被动 AoE),而 zuus 那 4 秒在对 **ogre_magi** 施法。
   ⇒ (a) **距离变化量是对称的,不能推断「谁在靠近谁」**;(b) 承重指标必须限定
   `inflictor == dota_unknown`(普攻)。`l5combo` 的 ACTIVE delta 从 +10.0(commit)
   变成 +8.0(commit_attack)就是这条在起作用。
2. **`.dem` 同名跨 run 撞车会在下游 join 时静默合并两局**:本波 8 个 run 里
   `20260820_182803_slot1` 出现两次;第一版按局名 key 的运动学 pass 得到 1264 行
   (真值 1188,76 行重复)。**行必须带 run 标签**(已写进检测器)。
3. **死亡/复活瞬移会污染「靠近/走开」判定**:受害者死后在泉水刷新,`d4` 读成 13.7k
   ⇒ 「62% 在走开」的第一版数字是假的。窗口必须在**受害者死亡时刻截断**,并加
   `step > 2500u` 的瞬移断点(与 §V.4 登记的 `movelen` 上限同源)。
4. **章程「事件里英雄名没有下划线」这条已过期**:当前 dumper 的
   `events[].actor/target` 是**全名带下划线**(`npc_dota_hero_skeleton_king`);
   `snapshots[].hero` 同样是全名。两处都 canon 化才安全(本轮第一版 kill 统计因此读出
   「32 局零击杀」)。**已在章程工具坑一节更正。**
