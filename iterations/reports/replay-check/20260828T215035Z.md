### 4.2 根因(源码推导,不是统计)

1. `aba_skill.lua:102-110` 只在 `IsUltimate() and slot >= 4` 时把大招写进**固定下标 6**;
   OD 只有 4 个技能、大招在 **slot 3 < 4** ⇒ 走 `table.insert` 落到**下标 4**,
   **`sAbilityList[6]` 恒为 nil**。而 `hero_obsidian_destroyer.lua:17-19` 的 build 表
   `{2,1,4,2,2,6,2,1,1,1,6,4,4,4,6}` **同时用了 `4` 和 `6`**。
   **帧里能把这两个下标分辨开**:大招确实被点过一次,而 build 里唯一能交付它的只有位置 3 的 `4`
   (值 `6` 全程没产生过任何一次加点)⇒ `4` = 大招、`6` = nil;
   `objurgation` 0 级也正因 build 表**从不引用下标 3**。
2. `ability_item_usage_generic.lua:198-202` **本来就写了 nil 处理器**,但它被包在
   **:192 的 `if #sAbilityLevelUpList >= 1`** 里。Lua 5.1 实测:

   ```
   t={"a","b","c","d","e",nil,"g","h"};  #t --> 8      (洞在中间,表还能用)
   5 次 table.remove(t,1);  t[1] --> nil,  #t --> 0    (洞挪到头部,长度塌成 0)
   ```

   ⇒ **洞一旦被消耗到表头,门为假,nil 处理器在它唯一该工作的那一刻不可达。**
   之后每帧从 :192 直接掉出去。(那句 `[WARN]` 的 `print` 到不了服务器控制台 ——
   AGENTS.md "No bot-side debugging" 又一次兑现。)
3. **唯一那局为什么正常,是同一段源码给出的内部对照。** `:331`
   `botLevel > 25 and botLevel < 30 and points >= 1 and #list <= 3` —— `#` 已塌成 0 ⇒
   `<=3` 恒真,**只差 `botLevel > 25`**。6 局 OD 等级 **26 / 23 / 23 / 25 / 25 / 21**,
   **恰好在 25 这条线上一分为二**:26 级那局恢复到 16 点,其余五局全卡死。
   分界不是我挑的阈值,是源码里的常数 ⇒ 它同时是**根因的证伪测试**。
   恢复后的 `[4,4,4,3,1]` 是 `GetAbilityList` 重建的形状,**build 表产生不出来**
   (它从不点 `objurgation`)—— 反过来证明走的确实是 `:331`。
