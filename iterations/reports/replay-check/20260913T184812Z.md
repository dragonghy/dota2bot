## 二、判别子(为什么技能加点能回答物品问题)

承重的是**一个 chunk 事实**,不是推测:

1. `bots/ability_item_usage_generic.lua:4` 在**模块作用域**(chunk 顶层,只跑一次)写:
   ```lua
   if bot == nil or bot:IsInvulnerable() or not bot:IsHero() or not string.find(botName, "hero") or bot:IsIllusion() then return end
   ```
2. 引擎真正调用的那几个全局——`ItemUsageThink`(**:8924**)、`AbilityUsageThink`(**:8933**)、
   `AbilityLevelUpThink`(**:8960**)——**全部定义在这条 `return` 之后**。
3. 全仓**没有任何一处在树内调用**它们:`grep` 全仓只剩 `hero_muerta.lua:152/153/155`
   三行**注释掉的**引用,和 `hero_skeleton_king.lua:1904` 一行说明性注释。
   ⇒ **调用者只能是引擎**。
4. ⇒ 若 :4 早退为真,这三个全局**全都不存在**,引擎对物品与技能**一起**回落到自带 AI;
   若加点跟着我们的表走,**chunk 必然跑到了底**,`ItemUsageThink` 也必然在。

**这正是「物品」与「技能」被同一条 `return` 绑在一起的地方** —— 所以一个**技能**读数
可以对一个**物品**假说下判决。

判别子的**确定性前提**(逐一核过,否则这把尺子不成立):
- 三个英雄的 `tAllAbilityBuildList` **各只有一条**(`GetRandomBuild` 无可选);
- `J.SetUserHeroInit`(`jmz_func.lua:39-56`)只在存在 `Customize/hero/<name>.lua`
  且 `Enable` 时改写;全仓该目录**只有 `viper.lua`** ⇒ 三个英雄**都不被改写**;
- `bDeafaultAbility = false`(shadow_shaman `:114` / jakiro `:134` / skywrath_mage `:145`)。

⚠️ **`bDeafaultItem = true` 是个红鲱鱼,已排除**:它**不是**物品总开关,
全仓只被 `:1394` 与 `:4064` 两处消费(两个单独的 `ConsiderItemDesire` 条目),
**不关闭 :1114 那个物品循环**。三个证人英雄都写着 `bDeafaultItem = true`,
