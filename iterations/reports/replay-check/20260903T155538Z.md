## 2. ⭐⭐⭐ 主发现:`arbheart` 的释放被它自己的重选撤销,除非 `slotarb` 同时 armed

### 2.1 结构(逐行,`bots/mode_farm_generic.lua:780-846`)

`arbheart` armed 时,1s 心跳里:

```lua
if J.IsModeTurbo() and J.IsSoakCandidate('arbheart') then
    ... 任一队友距锁定营地 <= 800 且 J.IsFarming ⇒
        preferedCamp = nil ; old = nil ; break
end
...
if old then  -- 现在是 nil,整段换营分支被跳过
elseif preferedCamp == nil then
    preferedCamp = ClosestCamp(bot, availableCamp)   -- ← 回填
end
```

**释放没有退役营地**:它**从不调用** `J.Site.UpdateAvailableCamp` —— 而那正是出厂反抢营
护栏(`:868`)在同样情形下走的退役路径。⇒ 刚被放掉的营地**仍在 `availableCamp` 里**,
唯一能阻止回填把它原样还回来的,是 `ClosestCamp` → `J.Site.GetClosestNeutralSpwan`
(`bots/FunLib/aba_site.lua:528`)里的 `IsTheClosestOne` 过滤器。

**而那个过滤器正是 `slotarb` 要修的东西**:不 armed 时它把**玩家 id** 喂给参数是**槽位**的
`GetTeamMember`,夜魇侧只有槽 5 被读到(`aba_site.lua:536-556` 的源码注释自陈)。

### 2.2 帧证据(真函数,不是重建)

同一帧:`tests/fixtures/f_260903_101254_cm_farm_stealcamp.lua` = 局
`20260903_101254_slot5` **t=850.1**,即 GH #455 §3 拍下的那一帧,也是 `arbheart` 自己钉的那一帧。
subject crystal_maiden(夜魇 pid 9),spirit_breaker(夜魇 pid 5)。

到蛙营 `(-592.9, 4840.6)` 的实测距离(真 fixture,`GetUnitToLocationDistance`):

| 英雄 | 距营地 |
|---|---|
| **spirit_breaker** | **574.8**(在 800u 释放窗内) |
| necrolyte | 3003.1 |
| **crystal_maiden(bot)** | **5991.9** |
| dragon_knight | 7752.9 |
| luna | 10485.2 |

出厂扫描**实际读到的队友**(`nSlot := 玩家 id`):

```
id=5 -> npc_dota_hero_crystal_maiden      <- 就是 bot 自己
id=6 -> nil    id=7 -> nil    id=8 -> nil    id=9 -> nil
```

⇒ **出厂扫描在这一帧只读到一个花名册成员,而它就是 bot 本人**(pid 9 排到槽 5)。
`slotarb` armed 时(`nSlot := 循环下标`)读到全部五个,包括 574.8u 处的 SB。

**跑真 `J.Site.IsTheClosestOne`**:

```
IsTheClosestOne(CM, 蛙营, bSlotArb=false) = true      <- 营地过不了滤 ⇒ 可以被原样还回
IsTheClosestOne(CM, 蛙营, bSlotArb=true ) = false     <- 被排除
```

**端到端跑真 `GetClosestNeutralSpwan`**(营地表 = {蛙营, 一个更远的营}):

```
slotarb 未 armed: 返回 蛙营   <- 就是 arbheart 刚放掉的那个,释放当场归零
slotarb   armed: 返回 nil     <- 两个营都被排除(见下)
```

### 2.3 顺带记下的第三种结局

armed 那次返回的是 **nil**,不是另一个营:更宽的扫描发现 dragon_knight 比 bot 更靠近那个远营,
于是**两个营都被排除**,`preferedCamp` 整个心跳保持 nil。
这是**出厂换营分支和 `arbheart` 自带测试的两营桩世界都造不出来的第三种结局**,原样登记。

### 2.4 ⛔ 为什么它自带的测试看不见

`tests/test_arbheart_farm_camp_heartbeat.lua` 把重选函数**打了桩**:

```lua
J.Site.GetClosestNeutralSpwan = function()
    ccCalls = ccCalls + 1
    if ccCalls == 1 then return CAMP_X end
    return CAMP_Y                       -- 第二次调用「就是」另一个营
end
```

并且**只 arm 了 `arbheart` 一个**(`if id == 'arbheart' ... return false`,即 `slotarb` 关着)。
⇒ 真函数(过滤器 + 距离排序)**一次都没跑**,「armed 落到另一个营」**由桩的构造保证成立**。
那个测试证明的是**释放发生了**;它**没有**证明**回填会给出不同的营**。

**这不是「测试写错了」,是「被测对象的关键一半被桩替换掉了」** —— 与本组 08-20 踩的
「离线重放引擎谓词时 `IsFullyCastable()` 含蓝」同族:**替身谓词比真谓词宽,结论就往一个方向偏**。

### 2.5 边界(必须连引)

1. **这不是「`arbheart` 恒等于 no-op」的论断。** t=850.1 那一刻 CM 距蛙营 5991.9u,
   夜魇野区多半有更近的营,回填**很可能**给出别的营 ⇒ 那一刻 `arbheart` 大概率是**起作用的**。
   受打击的是**偷营的收尾段**:bot 走到营边(#455 §3 记录 CM 在 t=868 已到 861u)之后,
   蛙营成为她最近的营,释放→回填→**原样锁回**,1s 一次,直到她真的开打。
   **本组没有 `availableCampTable` 的离线快照,因此「哪一刻它变成最近营」买不到读数。**
2. **`J.IsCampSwitchSafe` 目前是惰性的**(`jmz_func.lua:7187` 要 `campdanger` armed,
   而 `campdanger` **不在 57-id 串里** —— 当场按串核过,计数 0)⇒
   出厂换营分支在心跳上**根本不会换营**,这坐实了 #455 的「闩只问一次」诊断。
   ⇒ 「`arbheart` 的回填绕过了 `IsCampSwitchSafe`」这句话**今天是空的**(那个谓词本来就恒假),
   **但 `campdanger` 一旦入集或 promote,回填这条路仍然是不过安全谓词的那条。**
   **按前瞻风险登记,不按当前缺陷登记。**
3. `GetActiveMode` **不在 dumper 输出里**(`test_replay_004757_veno_ancient.lua:249` 有棘轮)。
   本轮把花名册所有成员设为 Farm,这是**最有利于排除**的设定 ⇒
   出厂那条读数(`= true`,即「排不掉」)是**安全方向上的下界**;
   armed 那条(`= false`)**条件依赖 SB 在实战里真的读 Farm**。已写进测试头部 LIMIT。
