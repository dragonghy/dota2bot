## 六、新缺陷:仪器的判决行与它自己的可达性判定是两套账([harness],编号推送后回填)

`abilanc_domain.py:478` 的 `verdict()` 拿**未扣除**的 armed 计数走分支:

```python
if a < b and a == 0:   return 'WORKING', ...
if a < b:              return 'WORKING-WITH-RESIDUAL', ...
return 'BUGGY-SUSPECT', 'armed fired MORE than baseline'
```

而**同一个文件** `:560-576` 的 `report()` 已经逐条算出了 `covered`(该英雄文件有没有选择器站点),
并把不可达的那些打上 `not reachable: no site in hero_%s.lua` —— **那个判定从不回流进 `a`**。

本波:`a=2`(两发都不可达)、`b=6`(5 可达 + 1 不可达)⇒ 打出 **`WORKING-WITH-RESIDUAL`**;
按可达域 `a=0 / b=5` ⇒ 应走 `a == 0` 那一支 = **`WORKING`**。

⚠️ **本例方向保守(少报),但这个盲点的一般形状不保守**:
armed 若有 3 发全不可达、baseline 2 发可达 ⇒ `a=3 > b=2` ⇒ **`BUGGY-SUSPECT`**,
而可达域是 **0 vs 2 = WORKING**。**那是一次凭空的指控**,
且**判决行是机器可读的那一行**(总监的 `VERIFY id=… verdict=…` 台账数的就是它),
**散文列里的理由对台账不可见**。
