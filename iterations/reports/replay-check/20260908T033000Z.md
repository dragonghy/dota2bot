## 二、落地:判据从 probe 搬进 `outlatch_capture.py`

上一轮把 `MODIFIER_REMOVE.value` 找出来时,它住在 `outpost_block_probe.py` 里,
`outlatch_capture.py` 自己仍然按施法者·秒阈值判完成。本轮:

- `read_game()` 的每个 attempt 现在带 `rmv`,**读的是结束这次 attempt 的那一条 REMOVE 事件本身**
  ——不是事后按 `(actor, t)` 查表,后者在两条 channel 同帧结束时会互换值(钉在 12l)。
- 组的完成 = **任一成员 `value==0`**(一根进度条一个判决;搭车者与主施法者同帧同拿 0)。
- **阈值降级为回退**,只在整组**一个 value 都没有**(旧 dump)时启用,并且
  `complete_via` 字段**自己报名**(`value` / `caster_s`),报表按两类**分别计数** ⇒
  一次回退读数**永远不能**被当成一次 value 读数。
- `verify_floor()` 新增「判据 vs ground truth」2×2 与分歧明细;施法者·秒那张表**保留为叙述量**。
- **缺失的 value 不是 0**(12j):混同会让一条丢失的事件读成一次占领 —— 方向恰好是**美化通道**的那一边。

## 三、⭐ 落地当天被真帧否掉的第一版:一次易主不许算给多个组

第一次跑 W52 `212ea5`,判据报了 **1 条分歧**:`20260907_003641_slot2` 的 3.0cs
`rmv=1,1` 组「未完成却易主」。逐帧查下去,**分歧是配对造出来的,不是判据错了**:

```
att chaos_knight South 1229.4-1230.2 0.8s rmv=1     ← 十二次重发,全部 rmv=1
    ... (共 12 次,合计 12.5s channel)
att chaos_knight South 1240.1-1242.9 2.8s rmv=1
att chaos_knight South 1243.0-1246.1 3.1s rmv=0     ← 唯一一次 value=0
FLIP pos=(-4096,-448) t=1248.5  2->3
```

易主在 1248.5,**同时落在** 1242.9 结束那组的 6s 窗口(Δ=5.6)**和** 1246.1 那组的窗口(Δ=2.4)。
旧写法「窗口里有易主就算这组产出了」把同一次占领算给了两组 ⇒ 中断的那组被记成
「判据说没完成、游戏说易主了」。改法:**一次易主只归它前面最近结束的那个组**
(占领发生在进度条填满的那一帧)。钉在 12p–12s + probe 13a–13c;变异台 M21/M22
(算给全部 / 算给最早的那个)双向 CAUGHT。

**这条同时决定了 docstring 里预登记的那两个 UNDECIDABLE。** 逐帧证据:

```
t=1230.5..1245.5  x=-4079 y=-308  hp_pct=1.00 level=23   ← 15 秒一动不动,距南哨塔 174u
t=1246.5          x=-4070 y=-299                          ← 完成那一帧后才起步
t=1247.5..1251.5  走开
```

3.1 秒**填不满一根 6 秒的新条**,所以**进度跨 0.1 秒重发接缝确实带过去了**;
但也**只带过去一部分** —— **15.6 秒 channel、16.7 秒站桩,买到一次 6 秒的占领**。
⇒ 给 #511 的那句话要比「重发白站」更准:**重发不是清零,是把 6 秒的事拖成 16.7 秒**,
且这 16.7 秒里英雄满血、场上什么也没变(23 级 chaos_knight,20:30 的 Turbo 局)。
