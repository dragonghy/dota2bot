## 1. `slotarb` 是什么 —— 一个循环的**域**和它的**取值器**用了两套数字

`bots/FunLib/aba_site.lua` 的 `IsTheClosestOne(bot, loc, bSlotArb)`:

```lua
for i, id in ipairs(GetTeamPlayers(GetTeam())) do   -- id 是 PLAYER ID(0-4 / 5-9)
    local nSlot = id
    if bSlotArb then nSlot = i end                  -- 闸:i 是 TEAM SLOT(1..5)
    local member = GetTeamMember(nSlot)             -- 参数是 SLOT
```

出厂扫描因此**按侧漏人**:

- **天辉**(id 0..4):`GetTeamMember(0)` 是 nil,1..4 有效 ⇒ **队伍槽 5(pid 4)从不被看**;
- **夜魇**(id 5..9):只有 `GetTeamMember(5)` 在范围内 ⇒ **只有槽 5(pid 9)会被看**。

`closestMember` 以 `bot` 自己起头 ⇒ **armed 的 TRUE 集是出厂 TRUE 集的严格子集**:
上闸只能**拒绝**一个出厂会接受的营地,**永远不会新增**。这条方向性是本报告每张表的读法。

**解闸点唯一**:`bots/mode_farm_generic.lua:64` 的 `ClosestCamp` 包装器,
作为 `J.Site.GetClosestNeutralSpwan` 的**第 4 个实参**(第 3 个是 `campsel`,
**同串 armed 的另一个独立 id**)。本轮检测器**在运行时从树上读出**这 11 条事实
并全部通过(§5 的 `source facts` 表):`call_sites=1`、`cand_arg=1`(即第二个闸参数)、
`conjoined=[]`(**没有与别的 id 合取 ⇒ 不是 GH #207 那个冻结形状**)、
`armed_slot_is_index=True`、`seeds_with_bot=True`、`strict_closer=True`、
`farm_mode_clause=True`。

## 4. 为什么判 `INDETERMINATE` 而不是 `SILENT`/`BUGGY`:仲裁只在**闩为空**时被问

`bots/mode_farm_generic.lua` 里 `preferedCamp` 是**文件级 local(:18)**,而**六个调用点
无一例外**是这个形状:

```lua
if preferedCamp == nil then preferedCamp = ClosestCamp(bot, availableCamp) end
```

(:382 / :403 / :461 / :585 / :618 / :804;另有 :799、:824、:902、:929 的重选路径,
其中 :784 的 `_farm_repick_at` 每 **1.0s** 只在「新营地近 800u 且 `IsCampSwitchSafe`」时换。)
⇒ **仲裁结果只在锁闩的那一 tick 进入行为**;此后英雄走多久都不再问。
`OnEnd()`(:631)与 :219 才清空它。

后果对本轮读数是**决定性的**:我在 `t0 − lead` 上重建的那一瞬间,**大概率不是仲裁被问的那一瞬间**。
§3 那一帧就是活证:CM 在 t=816 时距该营 3927u、SB 距 5003u —— **那一刻 CM 确实是更近的那个**,
armed 与 shipped 会**给出同一个 TRUE**。若闩在那时锁上,后面 SB 抢先开清、CM 仍走完全程,
**是「闩过期」而不是「闸失效」**。

⇒ 仪器无法分辨:
(i) 闸根本没咬(SILENT/BUGGY),与
(ii) 闸咬对了、但决策发生在一个更早、且当时**不分歧**的瞬间。
**两者在 `.dem` 上是同一张表。** 这就是 `INDETERMINATE` 的准确含义,不是「没测」——
上一轮 `roshdist` 的 `INDETERMINATE episodes=0` 是没测,本轮 `episodes=493` 是测了而分不开。
