## 2. 杠杆是什么(源码读,`bots/FunLib/jmz_func.lua:5878-5901`)

`J.CanEnemyInterruptTpChannel` 的候选名单是 `J.GetNearbyHeroes( bot, R, ... )`,每个候选过两条子句:

```
if nNow <= nReach                                          -- STRIKE
   or ( ( not bWide or nNow <= 700 ) and nSoon < nNow - 10 )  -- CLOSING
```

未 arm `R = 700`,两条子句都跑;armed `R = 1200`,而**加宽新纳入的敌人(700 < d ≤ 1200)只过 STRIKE**。
`nReach = GetAttackRange() + 150`,所以**新增域**是

> ADDED = 「700 内没有敌人触发旧谓词,且有敌人站在 700 < d ≤ reach(敌)」

`reach > 700` ⇔ `GetAttackRange() > 550` ⇒ **只有远程英雄有盲带,近战恒无**。
这是一个**纯否决加宽**:armed 拒绝的帧是未 arm 拒绝的帧的严格超集,所以它的 (a) 签名只能是
**ADDED 里的按下变少**,不该有别的变化。

**调用域(先说清楚)**:`tpsafe2` 包装的调用点被 `nMode ~= BOT_MODE_RETREAT` 圈住
⇒ **撤退 TP 从不查这个谓词**。dump 里没有 bot mode,所以 ADDED 只是**必要条件**,
armed 腿里残留 ADDED 按下是**预期内的**,读腿差不读残留。

## 4. ⚠️⭐ 两类静默污染(逐帧撞出来的,不是自检抓的)—— GH #176 [harness]

### 4.1 幻象:英雄名不是实体键

`20260825_061900_slot11` 里 `npc_dota_hero_lina` 是**三条快照流**(idx 1507 真英雄 t=[-54,719];
idx 857 / 2400 均 t=[490,719]、满血、会动 = **幻象**),三条同 `team`/`player_id`。
按名字建表 ⇒ 同一时间戳三行,插值二分到哪一行取决于排序,**静默**。

**造出来的假事实**:`spirit_breaker t=574.8` 被判成"lina 在 736 u 盲带里",
**真 lina 在 3,837 u 外朝反方向走**,736 来自站在 bot **486 u** 处的幻象。
这正是引擎侧谓词做、检测器没做的区分 —— `J.CanEnemyInterruptTpChannel` 先
`not J.IsSuspiciousIllusion( hEnemy )`;**把幻象算成盲带敌人 = 在量一个 bot 并不拥有的 guard**。
判别子不是 hp 也不是位移(幻象满血会动),**是出生时刻**:真英雄开门前(t<0)就被采样,幻象没有。
**覆盖面:抽 60 局 W9,18 局(30%)有重复 `(t, hero)` 行。**

### 4.2 尸体:在**插值后的** hp 上判生死会漏

`20260825_063640_slot6 lina t=376.4`:盲带敌人 viper **375.7 已死**,最后活帧 375.5 在 918 u,
下一帧 376.5 是死帧;在 376.4 插值 ⇒ **hp_pct ≈ 0.05 > 0 过了滤网**,位置插成 **768 u 正落在带里**。
**在插值结果上过滤抓不到它,因为混合本身就是正 hp 的来源** —— 必须改判**两端 bracketing 采样**。
修好后该行 `added` 由 True 变 **False**(p50 与 source 两种口径均已复核)。

### 4.3 影响面与对 #159 的连带(点名,不是判决)

`tp_channel_death.py` **两条都中**(按名字建帧表 + 插值 hp 判生死),而
**两类污染都恰好制造"贴脸"**(幻象站得近、尸体插值出一个近点)⇒
**#159 §1 的 12.6% / 17.2% 两个头条数字有暴露面,重跑前不宜当定值引用**;
即使重跑后读数没动,也请明确记一笔"未动",否则下一个人还要重查。
`grep` 命中"在插值 hp 上判生死"的共 15 个文件,但**命中不等于读数已错** ——
只有跨实体几何(敌我距离/最近敌人)才会翻转,纯自身量(dwell、经济)不受影响,**逐个判读别一刀切**。
