## 2. `slotwait` 是什么,以及为什么它的核验**不需要跨腿比较**

`bots/FunLib/utils.lua:2141`/`:2168`,同族缺陷的最后两处活的消费点
(`slotarb` #406、`slotdust` #411、`slotpush` #415 修了另外三处;#467 普查出其余五处零消费者):
`GetTeamPlayers` 给的是**玩家 id**(天辉 0–4 / 夜魇 5–9),`GetTeamMember` 要的是**队伍槽位**(1–5)。

- 天辉:`GetTeamMember(0)` 为 nil,槽 1–4 应答 ⇒ **五看四**,漏槽 5;
- 夜魇:只有 nSlot=5 在范围内 ⇒ **五看一**。

**这一对比 `slotpush` 好推理,而且这一点决定了要量什么**:守卫是
`teamMember:IsAlive()`,问的是**取值器刚递回来的那个成员**,没有 `slotpush` 那种
守卫/主体错位 ⇒ 循环对扫描集**单调**,出厂的 TRUE 集是 armed 的**真子集**,
**只存在 `armed TRUE / 出厂 FALSE` 这一个背离方向**。
⇒ 数它**根本不需要 armed vs baseline 的对比**,它是阵容算术的性质,
**在哪条腿的帧上都成立**(铁律 4(i-b) 管的是跨腿读侧偏估计量;本节没有跨腿量)。

消费者只有一个,`aba_push.ShouldWaitForImportantItemsSpells`(`aba_push.lua:284`),
TRUE ⇒ `nMaxDesire = min(nMaxDesire, 0.5)`,即**「先别推,队友的关键技能还没转好」**。
漏扫只能让 TRUE **更难**成立 ⇒ 出厂**系统性地提前开推,且只会多推**。

### 2.1 ⭐ 幻象与真身**共享 `player_id`** —— 逐帧抓到,方向是**压制发现**

按 `player_id` 建帧索引,第一版就在真帧上翻车:
`…_1bfa3d/20260904_190005_slot1` **t=739.4**,夜魇 **pid 6(chaos_knight)有 11 行快照** ——
1 个真身 + 10 个 `chaos_knight_phantasm` 幻象,**英雄名相同、`player_id` 也相同**。
谓词读的是**冷却**,幻象的技能表不是本体的 ⇒ 排序最后那行赢,**两个方向都能翻**。
这是 `entities.py:163` 那个 lina 案例**再下一层**(那次碰撞在名字上,这次连 `player_id` 都一样),
也和本组 09-04T21:56Z 记的「`idx` 也不是稳定实体键」是同一族。
落地规则照抄 `frames_by_hero`:**只留开门前(t ≤ 0)就存在的流**,幻象全生于开门后;
同一 pid 有两条开门前的流就留活得久的那条。

## 4. ⛔ 两个 `--duration` 读数**不是同一个数的上下界** —— 逐帧推翻了我自己写的那句话

docstring 初稿写「计数随 `nDuration` 单调下降」。**单调的是逐成员谓词,不是背离计数。**
背离 = `missed_true and not scanned_true`:抬高界既能关掉一个**漏扫**成员(减少背离),
**也能关掉一个被扫成员(制造背离)**。
现场就是上面的 ③:luna(**被扫**)eclipse cd **36.6**、CM(**漏扫**)freezing_field cd **66.0**
⇒ **界 0 时不是背离,界 40 时是**。
⇒ 两次运行是**两个问题**,两个都登记,**互不相减**。已改 LIMIT 3,并加成 pin(§5 检查 6b)。
