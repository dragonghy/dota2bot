## 3. 新缺陷 → **issue #59 [hero]**:门在储备**尚在**时全程失明

`X.zuus_ShouldSaveManaForUlt` 的子句 7 `if hBot:GetMana() >= nCost then return false end`
读的是**花之前**的蓝量 ⇒ 门的有效域恰好是「储备已经没了」:蓝 ≥ 225(储备完好,唯一还有东西可保的时刻)一律放行,
蓝 < 225 才开始压。**它保护的不是大招,是大招丢掉之后的那段回蓝。**

**跨线花费 → R 真正出手,隔了 58.1 秒。** 门尽职压了这 58 秒的 chip,而它本该拦的那一发**在门开着时走了**。

**这条论断不依赖 `J.IsRetreating`**:子句 7 排在子句 8(RETREAT 豁免)**前面**,蓝 ≥ 225 时门无论如何返回 false;
也不依赖 W2 走的是哪条分支(poke 分支有 target → 撞子句 7;retreat 分支 target 为 nil → 门本就 inert)。
**#47 那三帧离线分不开的歧义,在这一帧不存在。**
