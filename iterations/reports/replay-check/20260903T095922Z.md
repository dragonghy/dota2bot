## 1. `roshdist` 是什么 —— 它把一个**恒真的占位符**变成一个**真的条件**

`bots/mode_retreat_generic.lua:423`:

```lua
if botActiveMode == BOT_MODE_ROSHAN
    and not J.IsRoshanAlive()
    and J.IsAtRoshanPit(bot, vRoshanLocation)      -- 被闸的那一项
    and IsLocationVisible(vRoshanLocation)
then
    if not C.aegisNearby1200 then
        return BOT_MODE_DESIRE_MODERATE
    end
end
```

`J.IsAtRoshanPit`(`jmz_func.lua:12380`)在唯一一处解闸:

```
unarmed -> GetUnitToLocationDistance(bot, vRoshanLocation)   -- 一个 NUMBER(恒真)
armed   -> 该距离 <= 1600                                     -- 一个 BOOLEAN
```

⇒ **armed 是收紧的那一腿**:上 `roshdist` 只能**移除**这条撤退欲望,永远不会新增。
分歧域因此恰好是

```
{Roshan 已死的帧} × {dist(bot, 坑口) > 1600}
```

`dist ≤ 1600` 的帧两腿**逐位相同**。**方向要连读**:armed 腿上的一个域帧是
「闸**压掉**了一次 offer」,baseline 腿上的同一帧是「出厂树**放行**了一次」。

### 1.1 为什么这个 id 的条件 (a) 本来应该很好买

`ckpush` 的 `J.IsPushing` 是欲望谓词、`.dem` 够不到(上一轮 LIMIT 1)。
`roshdist` 不一样,**它自己的操作数是纯几何**:

- 坑口是**时钟的纯函数** —— `jmz_func.lua:11511`:`DotaTime() % 600 < 300`(白天)⇒
  `J.Utils.DireRoshanLoc`,否则 `J.Utils.RadiantRoshanLoc`。无引擎状态、无战争迷雾,
  本轮的检测器**逐字重算**了它。
- `not J.IsRoshanAlive()`(`jmz_func.lua:10065`)在 Turbo 里就是
  `DotaTime() - killTime <= 6*60`,而 Roshan 的 DEATH 带 `t` 落在 `events[]` 里。
- bot 自己的位置在 `snapshots[]` 里。

**正因为圆心是可算的,才必须先问一句:这个圆心对不对。** 这就是 §2。

## 2. ⭐ 本轮的主发现:**圆心是错的那个坑,77/77**

`tools/batch_test/behavioral/roshdist_domain.py` §A 的做法(**先逐帧**):
每次 Roshan 死亡,取**死亡前 20s 内真的对 Roshan 造成过伤害的英雄**,
在 `t_death ± 2s` 内取他们各自到两个坑的**最小**距离(LIMIT 4:幻象与本体同名,
本体一定在坑里),取中位数;中位数 > 900 就报 **UNRESOLVED,绝不猜**。

### 2.3 排除竞争假设:不是「每次死后换坑」(**后聚合**)

### 4.1 ⭐ 这条缺陷**不是 `roshdist` 引入的**,但 `roshdist` 把它**从无害变成有害**

出厂树里那个合取项是**裸距离**、恒真 ⇒ **圆心正确与否从来不进入行为**。
`roshdist` 做的修复(把占位符改回条件)本身在形状上是对的 —— §DP 的立案句站得住。
但它的副作用是:**它让一个此前从不被读的坐标第一次决定行为,而那个坐标是反的。**

这正是团队档案里那句「locally-correct ≠ emergently-good」的一个**新形状**:
不是「多个正确改动叠加出坏总和」,而是**一个正确的修复把一个沉睡的缺陷叫醒**。
⇒ **建议**:`roshdist` 在 `J.GetCurrentRoshanLocation()` 修好之前**不得 promote**;
修好之后**必须重新买条件 (a)**(本轮的检测器可整段复用,`--episodes` 直接出帧证据)。

### 4.2 诚实边界(明说买不到的)

- **LIMIT 1 — `botActiveMode == BOT_MODE_ROSHAN` 不可观测**。`.dem` 只有位置没有 mode。
  §3 的每个计数都是这一项上的**超集**。域非空只证明**其余合取项共现**,
  **不证明闸在某一帧真的开火**;域为零才会是反方向的决定性证据。
- **LIMIT 2 — `IsLocationVisible()` 不可观测**。dumper README「Vision / fog of war」记着
  录像里**根本没有分队可见性位**(无 `m_iTaggedAsVisibleByTeam`)。同向超集。
- **LIMIT 3 — `C.aegisNearby1200` 扫的是 `GetDroppedItemList()`**(**掉在地上**的不朽盾,
  `mode_retreat_generic.lua:33`),而 dump 里没有掉落物。手上拿着的盾**是**可见的
  (`snapshots[].items` 里的 `aegis`),上表 `held_aegis` 一列登记了它 —— 但**没有减掉**:
  拿在手上恰恰是 `scanDroppedForAegis` **看不见**的那种情况。
- **LIMIT 4 — 快照含幻象**(与上一轮 §2 同族)。§2 用「取最小距离」免疫;
  §3 的帧计数**不免疫**,`--dedupe-nearest` 提供每(英雄,秒)一行的读法。
- **§2 的结论本身不吃这四条 LIMIT**:它只用了 Roshan 的 DEATH 事件时刻、
  杀它的英雄的坐标,和两个写死的常量。
