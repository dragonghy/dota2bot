## 2. 更重要的是：**「两锚不同意」根本不是两个锚，是 1 Hz 把一条连续轨迹采成了两个点**

把同一个 `.dem` 用 `-interval 0.1` 重跑（10 Hz），上一轮那两格之间的「空白」全长出来了：

```
t= 1312.20 hp=  151 xy=( 1271.2, 1037.7) cell=(137,136) vec=(119.20, 13.70)   ← 倒下那格
t= 1312.60 hp=    0 xy=( 1003.2,  639.5) cell=(135,132) vec=(107.20,127.50)   step= 480.0
t= 1313.00 hp=    0 xy=(  645.8,  108.5) cell=(133,128) vec=(  5.80,108.50)   step= 640.1
t= 1313.40 hp=    0 xy=(  616.1,   64.3) cell=(132,128) vec=(104.10, 64.30)   step=  53.3
   ... 1313.40 → 1315.30 完全不动（20 格）...
t= 1315.40 hp= 2312 xy=( 1271.2, 1037.7) cell=(137,136) vec=(119.20, 13.70)   step=1173.3
```

三件事同时成立：

1. **是一条直线。** 三段位移的 `dx/dy` 分别是 **0.673 / 0.673 / 0.672**；
   非零步的方位角**极差 0.0008 rad**。不是抖动，不是哨兵值，是一条**有方向的连续轨迹**。
2. **回跳是逐位精确的。** `t=1315.40` 的 `(1271.2,1037.7)` / `cell=(137,136)` / `vec=(119.20,13.70)`
   与 `t=1312.20` **逐位相同** —— 复活把实体放回死点那一格，不是放回附近。
3. **1 Hz 采不到中间。** 这局 WK 实体的位置**更新间隔本身就是 0.4s**
   （全局 10 Hz 网格上的位置变化间隔直方图：`0.4s → 2843 次`，压倒性众数）。
   ⇒ 1 Hz 网格在对一个 **2.5 Hz 的信号**做欠采样，**混叠**是必然的。

⇒ **上一轮「两锚不可能都对」的结论要改写**：两个锚**都对**，它们是同一条 1173.3u 轨迹上的两个诚实采样点；
**制造矛盾的是采样率，不是数据。** 上一轮那句「本轮只主张两格不可能都对」**在此撤回**。

### 2.1 对 `anchor_slip` 的直接后果（不改代码，只改它的读法）

`bbfloor_domain.py:137` 用 `WALK_SPEED_MAX_U = 550.0` 当尺子，把「超出一个英雄能走的那部分」算作 slip。
**尸体不受走速约束。** 本局 10 Hz 全局普查（50 个死亡片段）：

- **12/50 片段**至少有一步 **快于走速**（>55u / 0.1s）。
- 单步最大 **640.1u / 0.1s = 6401 u/s**，是 `WALK_SPEED_MAX_U` 的 **11.6 倍**。
- 但只有 **1/50** 片段的尸体**停在**离最后活着那格 >200u 的地方 —— 就是 WK 这次。

⇒ `anchor_slip` 上一轮报的 `1/136`、`最坏 623u`、「只剩 327u 余量」**数字本身没问题**，
但**「余量」是拿错尺子量的** —— 550 u/s 不是尸体位移的物理上界，
所以那 327u **不是安全裕度**。这是对读数的重新解释，**不是对代码的指控**（本轮未改任何工具）。
