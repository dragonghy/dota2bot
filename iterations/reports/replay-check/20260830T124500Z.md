## 五、深查:`tpreach` 的 ADDED 域

### 5.1 域的定义(照抄工具头,不是我重述的)

armed 后扫描半径 700 → 1200,但**只有 STRIKE 那一支跟着变宽**;
所以候选**新增**的域是

```
ADDED = { 按下 : 700 内没有任何敌人触发老谓词,且某个敌人坐在 700 < d <= reach(它) }
```

`reach = GetAttackRange() + 150`,所以 `reach > 700` **要求 `GetAttackRange() > 550`** ——
**近战英雄永远不可能进 ADDED**(源码注释自己写的)。它是**纯否决型加宽**:
armed 腿应当**更少**落在 ADDED 里,别的什么都不变。

### 5.2 三张 reach 表,三个答案(**这本身就是读数**)

| reach 表 | 有盲带的英雄 | ADDED 总数 /1010 | radiant Δ/局 | dire Δ/局 |
|---|---|---|---|---|

| `p90`(修后) | 同上四个(宽度更大) | **24** | **+2.167** | **−2.250** |
| `source` | 源码注释点名的 8 个英雄 | **0** | +0.000 | +0.000 |

**三张表都不能落判**:
- `p50` 与 `p90`:**两个物理侧分层反号**(armed 在 radiant 更多、在 dire 更少)⇒
  **铁律 4(i) 明文:反号 = 噪声,不写进结论**。而且这是**否决型**候选,armed 腿本该**更少**,

## 六、⭐ 工具缺陷:`--reach-mode p90` 把近战英雄放进盲带(已修)

### 6.1 读数

修之前,`--ranges --reach-mode p90` 在本语料上给出:

```

```

- **45 行 ADDED 里 14 行(31%)的带内敌人是这四个近战之一** —— 按源码规则**不可能**。
- **`max` 是 14493u**,地图对角线量级。「攻击落点距离」不可能是这个数。
- 工具**自己的 ground truth 块已经把话说到嘴边**:p90 在三个可核英雄上误差
  **+94 / +243 / +260**,而 p50 是 **−55 / +6 / −16**。它**打印了这件事,然后照用 p90**。

### 6.2 机制(为什么既有的 `ability-not-an-attack` 拦不住)

`ATTACK_INFLICTOR = 'dota_unknown'` —— 它是**「没有具名 inflictor」**,不是「是普攻」。
于是**幻象、召唤物、攻击型技能**(混沌骑士 Phantasm、死亡先知 Exorcism、
主宰 Omnislash、灰烬 Sleight of Fist)的伤害**以英雄本人的名字入账、且没有 inflictor 可过滤**,
而距离是从**英雄本体的插值位置**量的。证据就在 n 上:**chaos_knight n=1474**,
是其他核心的 2–3 倍(dragon_knight 686 / skeleton_king 531)——多出来的正是幻象那几只。

**这是被污染的尾巴,不是被平移的分布** ⇒ **稳健统计量活得下来,尾部分位数活不下来**。

### 6.3 修法

1. **近战地板**:近战/远程一律用 **p50** 判(`MELEE_DECISION_PCT`),
   `RANGE_PCT` 只负责给**已确认有带**的英雄定宽度。
   门槛不是我调的参数,是**源码自己的规则**:`p50 + 150 <= 700` ⇒ 无盲带
   (即 `GetAttackRange() <= 550`)。`p50` 模式下**按构造是 no-op**(已钉测试)。
2. **两行强制表头**(空也要打):被地板剔除的英雄(带原始 reach)、
   `reach >= 1200` 的**退化**英雄 —— 因为带判据是 `d <= min(reach, 1200)`,
   一旦 reach ≥ 1200 它就**不再检验 reach**,ADDED 退化成「1200 内有敌人」。
   本语料 p90 下 **death_prophet 6868 / sniper 1277** 正在这一格。
   **看不到这两行的读者必须能断定「工具没查」,而不是「表是干净的」。**
3. `--ranges` 把 `MELEE FLOOR (p50 …)` 与 `FALLBACK (n<40)` **分开显示**(此前都是空白)。
