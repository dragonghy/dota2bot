## 2. **没停在"读不出"三个字上** —— 用战斗日志侧买到的两个单边界

Frostbite 自己的伤害行(`inflictor = crystal_maiden_frostbite`)的 `actor` 是英雄,
所以**过得了 dumper 的噪声过滤**;而且**一个施法者同时只可能有一发 Frostbite**,
所以这些行的归属是**精确的**(不像按名字归属的死亡行,见 §6 的限度)。

- **下界(无前提,恒成立)**:小兵挨过了除最后一跳以外的每一跳
  ⇒ `hp_at_cast > Σticks − last_tick`。它能**证明**一发不在浪费窗口
  `(2*ad, 460]` 里;**永远不能证明**一发在里面。
- **条件上界(前提明写在键名里)**:战斗日志**自己**把 `crystal_maiden_frostbite`
  记成致命一击、且决策窗口内没有第二个**英雄**伤害行时,`hp_at_cast <= Σticks`。
  ⚠️ **前提是**「没有别的**英雄**打它」,**不是**「没有别的东西打它」——
  友方小兵与防御塔的伤害被噪声过滤丢掉,看不见。所以它报在
  `hp_ub_if_frostbite_alone` 这个自带前提的键下,**不许被引用成血量**。

## 10. [harness] issue 正文全文(存档,便于事后核对)

标题:`[harness] dumper 的 creeps[] 只有 {t,team,x,y} —— 缺 name/hp/idx,同时卡死 hero-32/33/36 三条已裁定 queue 腿的价值列`

## 事实(本轮语料量到的,不是读源码猜的)

dumper 的 `creeps[]` 每一行**只有四个键**:`{t, team, x, y}` ——
没有 `name`、没有 `hp`、没有 `idx`。

本轮 180 局宽扫,**18,709,698 行小兵采样全部是同一个键形**
`t|team|x|y`(`creep_key_shapes` 单值,零例外)。源码侧对得上:
`tools/batch_test/behavioral/dumper/main.go` 的 `creepSnap` 结构体就是这四个字段,
`dumpCreeps()` 也只写这四个。

⇒ **一只小兵在位置流里连"是哪一只"都认不出来**,更谈不上读它的血量。

## 这不是一条便利性请求 —— 它卡死了三条已裁定的 queue 腿的**价值列**

| queue 行 | id | 它的价值列 | 现状 |
|---|---|---|---|
| `hero-32` | `zusboltdmg` | 小兵血量 + 远程/近战之分 | **BLIND**(2026-09-06 已登记) |
| `hero-33` | `cmcreepcap` | 最强敌方小兵的血量分布,按 Frostbite 等级分层 | **BLIND**(同上) |
| `hero-36` | `cmrangedhp` | 下单瞬间那只**远程兵的真实血量** —— 缺陷本体就是这个数被换成了常数 500 | **BLIND**(本轮) |

三条腿都被总监裁成 **APPROVED-SCAN**(零 EC2 归档只读),三条腿的
acceptance 都写着 METHOD-FAILED 分支(§CJ):读不出就是 **INSTRUMENT-BLIND
退回重裁**,**不得**自行套用「域接近 0 ⇒ 不入集」。于是三条腿现在都停在
同一堵墙前,而这堵墙是**一个结构体缺四个字段**。

## 建议的修法(与 `buildings[]` 已经在做的事逐字同形)

`buildings[]` 每一行已经带 `name` / `hp` / `hp_pct` / `alive`,读法就在
`main.go` 同一个实体回调里:

```go
if v, ok := e.GetInt32("m_iHealth"); ok { b.hp = v }
if v, ok := e.GetInt32("m_iMaxHealth"); ok { b.maxhp = v }
```

小兵那一支(`isCreepClass(cn)` 分支)现在只读 `m_iTeamNum` 与坐标。建议:

1. `creepState` 增 `name`(用现成的 `classToNPC(cn)`?**不行** —— 小兵的类名是
   `CDOTA_BaseNPC_Creep_Lane`,近战/远程/攻城/升级/超级兵**共用同一个类**。
   ⚠️ **这一条是本请求里唯一需要总监先定的技术分叉**:单位名得从
   `m_pEntity->m_nameStringableIndex` / `m_iUnitNameIndex` 这类字符串表取,
   不是从类名推。谁实现谁先在一局上打印验证,**不要拿类名当名字发出去** ——
   那会把四种小兵并成一种,而 `hero-36` 的整条杠杆就写在
   `string.find(name, 'ranged')` 上。)
2. `creepState` 增 `hp` / `maxhp`(`m_iHealth` / `m_iMaxHealth`,与建筑同一行写法)。
3. `creepSnap` 增 `idx`(实体索引)—— 没有它,跨采样点跟踪同一只兵仍然不可能,
   而 `hero-33` 的「最强敌方小兵」本质上是一个跨帧的选择。

## 体积代价,先说在前面(不说会被当成没想过)

本轮语料里 `creeps[]` 是**单局约 103,943 行**(默认 `-creep-interval 3.0`),
一个 timeline JSON 已经 ~11MB。加 `name` + `hp` + `maxhp` + `idx` 大致会把
文件翻倍。建议**不要默认全开**,给一个 `-creep-detail`(默认 off)开关,
或者只对 `CDOTA_BaseNPC_Creep_Lane` / `_Siege` 写详细字段、中立营地维持现状 ——
三条被卡的腿要的都是**兵线兵**,不是野怪。**缓存键会变**,`get_dumper.sh` 会
自动重建,已落盘的旧 timeline 不受影响(它们本来就没有这些字段)。

## 建议的验收方式

- 在**任意一局**已归档 `.dem` 上跑新 dumper,`creeps[]` 的键形普查里出现
  `hp` 与 `name`,且 `name` 至少能分出
  `npc_dota_creep_{badguys,goodguys}_{melee,ranged,siege}` 三类(**这一条是硬的**:
  只要 melee/ranged 分不开,`hero-36` 的读数就还是买不到)。
- 同一局上,`hp <= maxhp` 恒成立、`maxhp > 0` 恒成立(把「字段接上了但恒 0」
  这种形状钉死 —— 与 `MODIFIER_STACK_EVENT` 的 `value` 恒 0(GH #474 同族)
  是同一个坑,那次也是「字段在,量不在」)。
- 落地后本组重跑 `tools/batch_test/behavioral/cmrangedhp_domain.py`,把
  hero-36 的第 (2) 列从 INSTRUMENT-BLIND 升级成真读数;hero-32 / hero-33 同理。

## 本组这一轮不等它 —— 已经买到的替代读数写在报告里

本轮没有停在「读不出」三个字上:用**战斗日志侧**买到了一个**单边**下界
(`hp > Σticks − last_tick`,Frostbite 自己的伤害行,`actor` 是英雄所以过得了
噪声过滤)和一个**带前提的**上界(战斗日志自己把 `crystal_maiden_frostbite`
记成致命一击、且窗口内没有第二个英雄伤害行时,`hp <= Σticks`)。
**前提是明写的**:dumper 只保留「一端是英雄」的伤害行,所以友方小兵与防御塔
的伤害**看不见**,那个上界因此是条件性的,报在**它自己的键**下
(`hp_ub_if_frostbite_alone`),不许被引用成血量。
读数与逐帧证据见 `iterations/reports/replay-check/20260907T011415Z.md`。
