## 1. ⭐⭐ 先说仪器:PURCHASE 的 `value` 是**逐录像**的名字表下标

本轮的第一件事本来只是「把 TP 采购数出来」。dump 里 `events[].type == 'PURCHASE'` 的
`inflictor` 是 `dota_unknown`,物品只以 `value` 这个整数出现。第一版据此建了一张

| | 读数 |
|---|---|
| g1 能解出的下标 | 78 |
| g2 能解出的下标 | 86 |
| **两局共同的下标** | **21** |
| **其中指同一件物品的** | **1** |

点名两个:下标 **10** 在 g1 是 `magic_wand`、在 g2 是 `ancient_janggo`;下标 **94** 在 g1 是
`item_tpscroll`(patch 之后由引擎自己确认),而经验映射当时把 94 猜成了 `clarity`。

⇒ **`value` 是 `CombatLogNames` 这张表在这一份录像里的下标**(`dumper/main.go:258` 的
`name()` 走的就是它),**跨局聚合完全是噪声** —— 而它聚合得很干净、画出来也很正常。
这与上一轮 §5「零值那一格被裸 `Counter` 吃掉」是同族:**仪器伪影长得像读数**。

**修法(本轮落地)**:`dumper/main.go` 把 PURCHASE 的 `value` 过一遍同一张表,写进

同一次查表会**把一个数额变成一个像模像样的物品名**。

## 2. `tpdeathbuy` 是什么,以及为什么它的 baseline 腿是**算术上的空对照**

`bots/item_purchase_generic.lua:1014-1028`:

```lua
local bDyingWithDoomedGold = botHP < 0.08 and botHP >= 1
if J.IsModeTurbo() and J.IsSoakCandidate('tpdeathbuy') then
    bDyingWithDoomedGold = botHP < 0.08
end
```

`botHP = J.GetHP(bot)` 是 0..1 分数 ⇒ 出厂那个合取**对任何实数为假**(GH #168,总监已独立复核)。
所以 **baseline 腿不是「另一种行为」,是一个可以用算术保证为空的对照** ——
这一点是本轮判据的全部力量所在,也是为什么这个 id 比大多数 id **好核验**。
