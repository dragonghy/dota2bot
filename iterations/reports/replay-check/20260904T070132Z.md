### 2.1 先说量具:它此前跑不起来

`tools/batch_test/behavioral/zusult_gate.py:68` 读 `s['abilities']` 无保护。当前 dumper 里这个字段

`zusult` 从 W14 起每一波都在 armed 串里,却连续多轮没有 `VERIFY` 行 —— 记档时读起来像「排不上队」,
实际是**这条腿的量具是死的**。与 GH #205 / GH #171 同族:**丢的是门,不是读数**。全族清单
(另外 5 个同样无保护的文件)+ 建议的普适检测器 ⇒ **GH #478**。

**修法不是 `or []`**:缺列表时 `ready` 会算成 `False`,那一帧被归成真阴性,而这个方向
**偏向让 armed 腿好看**(落在缺失帧上的违例会静悄悄离开域)。实测不是理论顾虑:
4830 次 Q/W 施法里 **179 次(3.7%)**的 gate 帧正好是缺失帧。现在缺失帧带自己的状态,
输出成 **UNKNOWN**,既不算 in-domain 也不算 out-of-domain。

### 2.2 ⭐ 第二件量具事实:一个 `ABILITY` 事件不是一次施法

修好崩溃之后,12 条原始 in-domain 命中里 **6 条(50%)根本不是施法**。
Nimbus(`zuus_cloud`)的雷击**也记成 `actor=zuus / inflictor=zuus_lightning_bolt`**,
不花蓝、不动冷却。最刺眼的一条:`20260904_004903_slot2` t=453.4,被打的
spirit_breaker 在 **8300u** 外 —— Lightning Bolt 自己的施法距离的一个数量级之外。

判别子是**技能自己的冷却跨过那一瞬**:真施法把它从 0 抬到 `cd_len`;
`pre_cd > 0` 反向决定性(技能已经在转,这个事件不可能是它的新一次施法)。

**设计内豁免逐帧排除**(`hero_zuus.lua:986-989` 那三条「不报目标」分支):

  #2 帧确实有个 0.46 血的 bristleback 在 878u,但**它没被这次弹打到** —— 被打的是 1424 满血的 chaos_knight。

  三帧 Zeus 前 3 秒**零英雄伤害**,800u 内活着的队友 **1 / 1 / 0** ⇒ 两个析取项都假,这条分支进不去。

被 `GetActiveMode() ~= BOT_MODE_RETREAT` 挡住,加上撤退分支进不去 ⇒ `ConsiderW2` 整轮不出价,
这三次弹就只能来自 `ConsiderW`,而那条路径的 gate 只剩 `J.IsRetreating` 一个出口。
#2 帧 Zeus **满血、前 3 秒没挨过英雄伤害、离敌人 680u 主动开火** —— 把它读成撤退需要额外理由,本轮没有。

### 2.4 ⭐ 机制:不是 gate 有 bug,是它被绕过 —— 而且仓库里早写着

技能切分是决定性的:**3 次泄漏全是 W,Q 是 0**。这正是 GH #47 的签名;但这次两个 W 消费点
(`:673` 与 `:700`)**都已经上了 gate**,所以泄漏只能在 gate 的**上游谓词**。

`hero_zuus.lua:920-981`(GH #175,soak 候选 `zusboltcap`)已经把机制写完了,本轮只是
**第一次在真实对局里看到它对 `zusult` 的下游后果**:`GetBoltKillHealthCap` 未 armed 时返回
`abilityW:GetAbilityDamage()`,而 `zuus_lightning_bolt` 的 KV 顶层没有 `AbilityDamage`
⇒ **恒 0**;`FindAoELocation` 末位参数是 `nMaxHealth`,`docs/BOT_API_REFERENCE.md:1288`
记着「Pass 0 for no HP filter」⇒ `:1008` 那个名叫 `nCanKillHeroLocationAoE` 的局部
实际在问「射程内**有没有敌方英雄**」。那条分支 `return` **只给两个值** ⇒ `castW2Target` 是 `nil`
⇒ `zuus_ShouldSaveManaForUlt` 第一时间 `return false`。

⇒ **`zusult` 的条件 (a) 在 `zusboltcap` 未 armed 的前提下买不干净**,而 `zusboltcap`
**不在** W44 的 58-id 串里,也不在当前 60-id 串里。这是 AGENTS.md「promote 一个 id 会悄悄
掐死点它名字的 gate」那条教训的**镜像**:一个**没 armed** 的 id 让另一个 armed 的 id 持续漏气,
而 `check_armed_wiring.py` 两边都不会报警(它查调用点存在,不查谓词能不能为真)。
