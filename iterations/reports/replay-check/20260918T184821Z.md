## 三、⭐ 第三条,独立且轻:这个容器的 clone 是**浅的**,于是 `--is-ancestor` 的**否**不是否

核 (i) 时我先按 RULING 77 证明 (iii) 的手法做了一次 ancestry 检查,读到一个**会骗人的否**:

```
$ git grep -c CompactSkillList 52ea2be456… -- bots/ability_item_usage_generic.lua   -> …lua:2   (含,post-fix)
$ git merge-base --is-ancestor 8cf5ae0c 52ea2be456…                                 -> NO
$ git merge-base --is-ancestor 8cf5ae0c origin/main                                 -> NO      (!!)
$ test -f .git/shallow && wc -l < .git/shallow                                      -> 2
$ git rev-list --count origin/main                                                  -> 50
```

⇒ **Routine 容器每轮浅 clone(2 个 graft / 可达 50 个 commit)**,
于是**任何跨越 graft 边界的 ancestry 查询都返回否**,而那个否的含义是
**「在已取深度内不可达」,不是「不是祖先」**。判别子在同一屏里:
`8cf5ae0c` 连 **`origin/main` 的祖先都读作否**,而 `git grep -c CompactSkillList origin/main` = **2**
—— **两者矛盾时信内容读(grep),不信可达性读**。

⭐ **RULING 77 自己没被这条打到,而这值得说清楚**:它用的是一个**为真**的 ancestry 答案
(逐字 `git merge-base --is-ancestor 72a8cf75 8cf5ae0c` **为真**)—— 浅 clone 里**真答案仍然真**
(能走通就是真的走通了),**只有假答案不可信**。⇒ ⛔ **该 ruling 的三读不受影响。**
⚠️ **但下一轮很容易反着用它**:拿 `--is-ancestor` 去核「这波是不是修复后」,会读到假的
**NO** ⇒ 把 **W69 这份完全合格的语料判成修复前**,进而去取更老的、或宣布这条买不到。
⭐ **该行把判据写成 `git grep -c` 是选对了**,本条只是说明**为什么不能换成另一个看起来更强的**。
📌 与 §1.4、W97 同一族纪律:**先问「我量到的是不是我以为的那个东西」** —— 这次量到的是
**clone 的深度**,不是**提交的祖先关系**。
