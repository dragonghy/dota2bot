## 二、⭐⭐⭐ 头号产出:`analyze_log.py` 的 Lua 报错检测器恒读 0

去 1.2 那条路上顺手读了逐局 `.log.gz`(S3 里每局都有,`TURBO_QUALITY_RUNBOOK.md:31`
早写了它存在),于是看见:

### 2.1 缺陷

`tools/batch_test/soak/analyze_log.py:23`:

```python
RE_VSCRIPT_ERR = re.compile(r"\[VScript\].*(Runtime Error|Syntax Error|error)", re.I)
```

它**要求**行里有字面量 `[VScript]`。本轮把手上全部 **264 份**真实对局日志
(Sept-4 `…_fdfe8d` 48 份 + W67 四台 216 份)连起来数:

```
grep -c "\[VScript\]"            ->  0        # 264 份日志里一次都没有
grep -oP "^.*Script Runtime Error.*$" | sort -u
                                 ->  Script Runtime Error: error in error handling   # 唯一形态
```

⇒ **这条正则在本仓的语料上匹配不到任何东西,一次也没有。**

### 2.2 后果:它守着的那个 anomaly 从未被发出过

同一个 run 的 48 份 `analysis.json` 全量读(第一手,本轮下载):

| anomaly type | 局数 |
|---|---|
| `script_perf` | 48 |
| `feeder` | 28 |
| **`vscript_errors`** | **0** |

而**同一批 48 局的日志里有 46 次真实抛错,分布在 29 局(60.4%)**。

**W67(最近一波,四台分目录,216 局)**:**113 局(52.3%)至少一次**,合计 **194 次**,
**全部 194 次都是被吞掉文本的那一种**(`uniq` 只有一行)。
⇒ **不是历史遗留,是当下。** 两波相隔一周,量级一致(0.96 次/局 vs 0.90 次/局)。

### 2.3 为什么这次能数到,而「日志不完整」这条反驳不成立

`tools/batch_test/soak/soak_loop.sh:159-166`:整份 stdout `mv` 成 `$LOG` → 原样 `gzip -f` →
`aws s3 cp` 上传,**中间没有 head/tail/截断**;`analyze_log.py` 读的就是这同一份。
⇒ 计数是**精确值不是下界**(引擎自己印多少是另一回事)。

### 2.4 ⭐ 这条为什么比「一个正则写错了」更重

`iterations/streams/director.md:10589` 的裁定逐字写着:崩溃守卫的条件 (a)
**在本仓「没有通道」**,给的三条理由是 ①`print()` 到不了控制台
②`error in error handling` 吞掉错误文本 ③**dumper 1Hz 世界状态没有「Think 抛错了」这个项**
⇒「抛错后什么都没做」与「决定什么都不做」**在唯一的仪器上观测等价**。

**②成立(文本确实被吞),但「唯一的仪器」不成立** —— dumper 不是唯一仪器:
**逐局 `.log.gz` 自农场第一天起就逐局归档,每抛一次错就落一行**。
**文本买不到,发生次数买得到**,而且**回溯可得**(所有归档局都在)。
⇒ 通道一直在,**指着它的那个工具在读 0**。

同族还有 `docs/AUTONOMY_NOTES.md:56` 的「~20/game」——那是全仓**唯一**一个在案的速率,
与实测 **0.90–0.96 次/局**差约 **20 倍**;它当时大概是人眼看控制台估的,
此后自动那条路一直读 0,**没有任何东西举手说两者对不上**。

### 2.5 ⛔ 必须同时写下的边界(否则下一个人会拿它买错东西)

`Script Runtime Error: error in error handling` 这一行**不带英雄名也不带函数名**。
⇒ **这是局级计数,不是腿级计数**;而镜像波**一局里两条腿都在**
⇒ **按构造不能拆腿**。它能买的是**波级 / 臂串级的速率差**,买不到
「armed 腿比 baseline 腿多抛了多少」。
⇒ 崩溃守卫的 (a) 因此**部分**可买(守卫有效应当把局级速率压下去,跨波可测),
**不是**完全可买。**这一条请连同 2.4 一起引用,不要只引 2.4。**

⛔ 另一条诚实边界:**本轮没有证明这 194/46 次抛错改变过任何一个 gate 的读数**。
而且 §3.2 那一局(`20260904_065910_slot5`)自己的日志里 **0 次抛错**
⇒ **本发现不解释第一节那条矛盾**。两件事是在同一条路上撞见的,不是同一件事。
