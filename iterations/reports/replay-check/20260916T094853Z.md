## 四、机制:重复键 + 稳定排序 ⇒ 谁排在前面是抛硬币(= GH #666 验收第 4 条的答案)

把 5 份 timeline 的每条记录 `json.dumps(sort_keys=True)` 之后分别按**排序后**和**原序**取 md5:

| | dump1 | dump2 | dump3 | dump4 | dump5 |
|---|---|---|---|---|---|
| `snapshots` **排序后** | `68b47a3bbc3c` | `68b47a3bbc3c` | `68b47a3bbc3c` | `68b47a3bbc3c` | `68b47a3bbc3c` |
| `events` **排序后** | `86f7063e6750` | `86f7063e6750` | `86f7063e6750` | `86f7063e6750` | `86f7063e6750` |
| `snapshots` **原序** | `39a75bea1c5b` | `a4ae993590b4` | `f1ee32f454dd` | `7b9bc109dac9` | `19be1cba0f1a` |
| `n_snap` / `n_ev` | 33312 / 54185 | 同 | 同 | 同 | 同 |

⇒ **内容逐条相同,只有发射顺序变了**(与 #666 立案时的形状一致)。**新增的是下面这一步:**

**为什么顺序会变成读数。** `Timeline.__init__` 做的是
`self.snaps[h].sort(key=lambda s: s["t"])` —— **Python 的 `sort` 是稳定排序**,
所以**同一个 `t` 上的多条记录保持发射顺序**。而这一局:

```
(hero, t) 键总数                 : 16,892
其中带 >1 条记录的键             : 2,658  = 15.7%
单个键上最多的记录数             : 21
两次 dump 之间「第一条」不同的键  : 2,074  = 78.0% 的重复键
```

现场(dump1 vs dump5,逐字):

```
drow_ranger t=816.7  dump1 (-5581.8, 4161.1, hp 1550)   dump5 (-5351.4, 4315.0, hp 1550)
drow_ranger t=819.7  dump1 (-5351.4, 4315.0, hp 1550)   dump5 (-5632.1, 4174.6, hp 1550)
drow_ranger t=821.7  dump1 (-5531.3, 4256.3, hp 1450)   dump5 (-5351.4, 4315.0, hp 1550)
drow_ranger t=824.7  dump1 (-5739.6, 4766.9, hp 1580)   dump5 (-5531.3, 4256.3, hp 1229)
```

⇒ **凡是「取这个时刻的第一条」的消费者,读到的是一枚硬币**:
`state_at`(`bisect_left` 落在相等 `t` 的**最左**,`dt < best[0]` 用严格小于 ⇒ 取到并列里的第一条)、
`pos`、`alive_at`,以及 d8 取 `respawn_t` 的那个 `for s in snaps: if s["t"] > t and s["hp"] > 0` 循环。

⭐ **所以 `detect.py` 的「顺序敏感」不是散在各处的**:它从**重复键的并列**这一个口进来,
**而那条重复流就是 GH #849 的幻象流**。

## 五、零流逝这一族:尸体泄漏只是其中一半,而证据写在检测器自己的输出里

d8 的窗口判据是 `if s["t"] < respawn_t or s["t"] > respawn_t + RETURN_WINDOW: continue`
—— **`<` 把 `respawn_t` 那一帧本身放进了窗口**。于是命中可以发生在**零流逝**处。
检测器自己打出来的 `desc`(dump1,逐字,只取零流逝的 8 条里的 3 条):

```
lich died at t=596s (9:55) in the enemy half (depth 2012) and walked back to within
  0u of the death spot at t=596s (9:55), 0s after respawn, ...          <- 尸体泄漏族
necrolyte died at t=1226s (20:25) ... walked back to within 0u of the death spot at
  t=1226s (20:25), 0s after respawn, ...                                <- 尸体泄漏族
skeleton_king died at t=974s (16:14) ... walked back to within 1310u of the death spot
  at t=979s (16:18), 0s after respawn, with only 1 ally(ies) near ...   <- 原地复活族
```

⭐ **判别子在句子里**:`0u ... 0s after respawn` —— 检测器把「零秒走了零码」写进了自己的
证据行,然后叫它 `respawn-return feed loop`。

**两族的区别在 `respawn_t` 自己**:
- **尸体泄漏族**(379):`respawn_t − death_t` ≤ 0.3s、`hp_pct` 0.1%–22%、坐标就是死亡点
  ⇒ `respawn_t` **根本不是复活**,是将死者最后一条活人采样 ⇒ **GH #752 那一修管这一族**。
- **原地复活族**(105):`respawn_t − death_t` = 4.0–5.6s、`hp_pct` ≈ 99%–100%
  ⇒ `respawn_t` **是真的复活**(圣剑盾 / 冥魂大帝重生),只是英雄**在原地复活,没有走**
  ⇒ ⛔ **GH #752 那一修对这一族效果精确为零**;⛔ GH #849 的去幻象修法**也是零**。
  本局三例:`skeleton_king 974.4→978.7`(hp 0.991)、`luna 1116.1→1121.7`(hp 1.0,距 110u)、
  `skeleton_king 1597.7→1601.7`(hp 0.987,距 292u)。

⛔⛔ **于是本轮要写死一条给下游**:**只修 GH #752,d8 会从 47.9% 假阳掉到 10.4%,
而那 10.4% 正好是「看起来已经修好了」的那一族** —— 与 W78 §五 写死的那条同型
(那里的对照组是 #849,这里是 #752)。⛔ **而且 #752 + #849 两修加起来也只消掉第一族**:
#849 对原地复活族的效果**同样精确为零**(那一族的 `respawn_t` 是真记录,不是幻象)
⇒ **105 条原样留着**。
⭐ **两修都不需要**的那一条更便宜:**窗口在复活端改成半开**(`s["t"] > respawn_t`,
再要求一个最小流逝,比如 ≥ 3s),**一行,且对两族同时生效**。

## 六、修的顺序有讲究(给 #666 与 #849 的话)

- **#666 的验收(「同一 `.dem` 连跑两次,timeline md5 逐位相同」)可以在读数仍然全错的情况下达成**:
  dumper 把输出排序之后,并列的**哪一条**排在前面就固定了 —— 但如果排在前面的是幻象,
  那就是**把一个幻象钉死成确定值**。⭐ **确定不等于正确。**

  否则它会在一个「确定的幻象」上打勾。

```python
#!/usr/bin/env python3
"""Blood-measure for the `respawn_t` corpse-leak defect (GH #752's third
consumer, detect.py:462-466).

Per game, count:
  deaths            hero DEATH events with a target_hero
  leak              deaths whose "respawn_t" (= first hp>0 snapshot after the
                    death) is the dying hero's own last alive sample leaking
                    0.1-0.5s past the DEATH event, still at the death spot
  d8                d8_return_to_death_spot hits, as-is (shipping code)
  d8_leak           of those hits, the ones whose respawn_t is a leak sample
                    => the detector reports THIS death as "walked back to the
                    death spot"

Reincarnation (Wraith King) is split out: the next alive record is at the
death spot too, but at full hp -- "what counts as respawn_t" is genuinely
ambiguous there, so it is never counted as a leak.
"""
import json
import sys
import os

sys.path.insert(0, "/home/user/dota2bot/tools/batch_test/behavioral")
import detect as D

LEAK_GAP = 0.5        # a real respawn is >= the Turbo respawn timer away
LEAK_DIST = 400.0     # the leaked sample sits on the death spot
LEAK_HP_PCT = 0.60    # ... and at the hp the hero died with, not a fresh bar


def classify(tl):
    deaths = [e for e in tl.events if e["type"] == "DEATH" and e.get("target_hero")
              and e["target"].startswith("npc_dota_hero_")]
    rows = []
    for dth in deaths:
        hero, t = dth["target"], dth["t"]
        p = tl.pos(hero, t)
        snaps = tl.snaps.get(hero, [])
        r0 = None
        for s in snaps:
            if s["t"] > t and s["hp"] > 0:
                r0 = s
                break
        row = {"hero": hero, "death_t": round(t, 1), "kind": "none"}
        if r0 is None:
            row["kind"] = "no_respawn"
            rows.append(row)
            continue
        gap = r0["t"] - t
        row["respawn_t"] = round(r0["t"], 1)
        row["gap"] = round(gap, 2)
        row["hp_pct"] = r0["hp_pct"]
        d_spot = D.dist((r0["x"], r0["y"]), p) if p else None
        row["d_spot"] = round(d_spot) if d_spot is not None else None
        # A real respawn is at least the respawn timer away, so gap <= 0.5s can
        # only be (a) the dying hero's own last alive sample leaking past the
        # DEATH event, or (b) an on-the-spot full-hp reincarnation.
        # d_spot is RECORDED but not a predicate: it is computed from
        # tl.pos(hero, t), which is itself exposed to the phantom-read defect
        # (GH #849), so making it a predicate would import that bug here.
        if gap <= LEAK_GAP:
            if r0["hp_pct"] <= LEAK_HP_PCT:
                row["kind"] = "leak"
            else:
                row["kind"] = "reincarnate"   # full hp right away = WK ult
        rows.append(row)
    return rows


def main(path, tag):
    with open(path) as f:
        d = json.load(f)
    tl = D.Timeline(d)
    rows = classify(tl)
    leak_keys = {(r["hero"], r["death_t"]) for r in rows if r["kind"] == "leak"}
    reinc = sum(1 for r in rows if r["kind"] == "reincarnate")
    hits = D.d8_return_to_death_spot(tl)
    d8_leak = [h for h in hits if (h["hero"], h["death_t"]) in leak_keys]
    # The phantom-independent discriminator: the hit fires on the FIRST frame of
    # the scan window (t == respawn_t), i.e. the hero is credited with walking
    # back 0 seconds after respawning. Two families land here -- the corpse leak
    # (hp ~ 0) and an on-the-spot full-hp respawn (aegis / WK reincarnation).
    d8_zero = [h for h in hits if abs(h["t"] - h["respawn_t"]) < 1e-6]
    out = {
        "game": tag,
        "deaths": len(rows),
        "leak": len(leak_keys),
        "reincarnate": reinc,
        "no_respawn": sum(1 for r in rows if r["kind"] == "no_respawn"),
        "d8": len(hits),
        "d8_leak": len(d8_leak),
        "d8_zero": len(d8_zero),
        "d8_zero_lowhp": sum(1 for h in d8_zero if h["hp_pct"] <= LEAK_HP_PCT),
        "d8_zero_fullhp": sum(1 for h in d8_zero if h["hp_pct"] > LEAK_HP_PCT),
        "leak_rows": [r for r in rows if r["kind"] != "none"],
        "d8_hits": [{k: h[k] for k in ("hero", "t", "death_t", "respawn_t",
                                       "return_dist", "hp_pct", "depth")}
                    for h in hits],
    }
    print(json.dumps(out))


if __name__ == "__main__":
    main(sys.argv[1], sys.argv[2] if len(sys.argv) > 2 else os.path.basename(sys.argv[1]))
```

```bash
#!/usr/bin/env bash
# Blood-measure the d8 respawn_t defect across the whole 2026-09-11 wave.
# One game at a time: fetch .dem -> dump -> probe -> delete, so peak disk is
# ~60MB regardless of how many games are in the wave.
set -u
cd /home/user/dota2bot
source tools/batch_test/aws/aws.env
DUMP=/home/user/dota2bot/tools/batch_test/behavioral/.dumper_cache/behav-dump
OUT=/tmp/rc/per_game
mkdir -p "$OUT" /tmp/rc/dem /tmp/rc/tl
n=0
while read -r _d _t _sz key; do
  n=$((n+1))
  tag=$(basename "$key" .dem)
  leg=$(echo "$key" | cut -d/ -f2 | sed 's/.*_//')
  if [ -s "$OUT/${leg}__${tag}.json" ]; then continue; fi
  awsx s3 cp "s3://${S3_BUCKET}/${key}" /tmp/rc/dem/cur.dem --no-progress >/dev/null 2>&1
  rc_dl=$?
  if [ $rc_dl -ne 0 ]; then echo "DL_FAIL $key" >> /tmp/rc/failures.txt; continue; fi
  $DUMP /tmp/rc/dem/cur.dem > /tmp/rc/tl/cur.json 2>/tmp/rc/tl/cur.err
  rc_du=$?
  if [ $rc_du -ne 0 ]; then echo "DUMP_FAIL $key rc=$rc_du" >> /tmp/rc/failures.txt; rm -f /tmp/rc/dem/cur.dem /tmp/rc/tl/cur.json; continue; fi
  python3 /tmp/rc/probe_respawn.py /tmp/rc/tl/cur.json "${leg}/${tag}" > "$OUT/${leg}__${tag}.json" 2>>/tmp/rc/failures.txt
  rc_pr=$?
  if [ $rc_pr -ne 0 ]; then echo "PROBE_FAIL $key rc=$rc_pr" >> /tmp/rc/failures.txt; rm -f "$OUT/${leg}__${tag}.json"; fi
  rm -f /tmp/rc/dem/cur.dem /tmp/rc/tl/cur.json
  echo "[$n] $leg/$tag rc=$rc_pr"
done < /tmp/rc/w_dems.txt
echo "WAVE_DONE n=$n"
```
