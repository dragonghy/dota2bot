### 3.0 这个 id 的可观测量是什么(先说清楚,再看帧)

`bots/mode_team_roam_generic.lua:542-578`:armed 时,`Think()` 里对**超出自身威胁半径的英雄目标**
下的是 `Action_MoveToLocation(目标当前位置)`(**有限**命令),而不是出厂的
`Action_AttackUnit(target,false)`(**连续**命令)。**只要该 mode 继续赢拍,两者行为一样**
(每帧重下);差别**只在 mode 输掉拍卖之后的那一段尾巴**:连续命令继续拖着 bot 追活体目标,
有限命令走完剩下那一段就到期。⇒ **可观测量是尾巴,不是接近过程。**

### 3.4 ⭐ 否定结果:「停在陈旧点上」这个指纹在 1Hz 上不可识别

有限命令的**理想指纹**是:mode 输掉拍卖后,bot 走完那条 `MoveToLocation(旧位置)` 并**停在旧点上**,
而目标早已走远。我把它写成判据(t1+4s 时 `dist(bot, 旧点) ≤ 400` **且** `dist(bot, 活体目标) ≥ 1200`):

- **两侧都读 0**(候选 0/149,基线 0/142);
- **但两个边缘条件都会响**:`dist(bot,旧点)<400` 候选 **12** / 基线 **22**;
  `dist(bot,活体)>1200` 候选 **43** / 基线 **37**;中位数 `d_stale` 882/828,`d_live` 894/845。

⇒ **探针不是坏的**(marginal 有量),**是这个合取在真实对局里不出现**:目标走远到 1200u 以上时,
bot 通常要么还在动、要么已经调头(§3.2 里 bristleback 停的位置离旧点还有 **734u**,并未走到点上)。
**结论:执行核验不能走 stale-lock 这条路**,下一轮不要重新发明它。原因有两条可查:
(i) 1Hz 采样 + 300–400 u/s 移动 ⇒ 单帧 ±400u,判据本身就在噪声尺度上;
(ii) 有限命令到期后**还有别的 mode 接管**,bot 很少真的"停在点上不动"。

**同一原因说明为什么本轮 (a) 不能闭合**:快照里**没有 order 类型、没有 active mode**。
可闭合的两条路(留给下一轮/总监):
1. **收割全波 ~280 局**后重跑本表——`≥9s` 这条尾长上限如果在 20 倍样本上继续 0 vs N,
   那条就够硬了(**预登记**:阈值 9.0s、band `[700,1600]`、`-interval 1.0s`,别事后改口径);
2. **fixture 路线**:用本轮 §3.1 的基线帧 `20260822_062551_slot1 t=205.5 jakiro`
   (`make_fixture.py <timeline> --t 205.5 --hero jakiro`)**离线重放 `Think()`**,直接看
   armed 是否换命令——这才是"执行"的直接证据,且**不用等批测**。本轮没做,是**主动留下的缺口**
   (工作单元要小),明确交给下一轮。
