## 四、⭐ `ohnum` 会删掉已核验的 punish(本轮最该被下游读到的一条)

查 §3 的「`ShouldRefuseUnsupportedPunish` 一次都没拒」时撞上的:
**它在这一波里是结构性 inert 的。**
`jmz_func.lua:9134` —— `if not J.IsSoakCandidate('ohnum') then return false end`,
而 **`ohnum` 不在本波 armed 串里** ⇒ 它返回的 `false` 是 `and` 的**单位元,不是对 drow 的裁定**。

**这正是本仓库反复记的那个坑的形状**(量具/门自己制造了它随后被报出的那个结论)。
本组**第一版测试就写错了**:断言写成「两个离线不可求值的 clause 都通过」——
**对的答案配错的理由**。已改成两个用例分别断言,并把 inert 断言成 inert。

**反事实测量(同帧同世界,只多 arm 一个 id):**

```
ownhalf only    refuse(drow)=false   ShouldPunishDive=drow_ranger
ownhalf + ohnum refuse(drow)=true    ShouldPunishDive=nil
```

**7 帧样本:ownhalf 开火 4 次,`ohnum` 删掉 3 次(t=235 / t=45 / t=135),留 1 次(t=457)。**
被删的三次里**包含地面真相 2 杀 0 死的那一次**。

**机制(便宜且精确)**:`ohnum` 要的是**目标 1200 内的人数优势**,而
`SafeToCommitFight` 数的是**同一个圈**。t=235 时 lina 距 **lion 649u**、距 **drow ~1300u**
⇒ **一个真实的 2v1 被读成 1v1 平局**,`ohnum` 于是按「无优势」拒绝。
**同一个半径伪影也解释了 pudge 为什么被拒**:lion 距 pudge 1555.8u > 1200,
所以在 pudge 的交战点上**我方计 0 人**。

⚠️ **这是反事实,不是观测**:`ohnum` 本波未 armed,所以以上是「若 arm 会怎样」,
**不是它在真实对局里干了什么**。价值在于**它在花钱发波之前就给 `ohnum` 定了价**。
⇒ 已开 issue 交协同组(§6)。
