## 二、⭐⭐⭐ 头号:`arbheart` 的释放谓词与出厂守卫 `:615` **逐条等价**,而那条守卫在**同一 tick 更早**返回 `DESIRE_NONE`

### 2.1 两个谓词逐条对齐(不是「相似」,是**同一个集合**)

| | `arbheart`(`mode_farm_generic.lua:846-857`) | 出厂守卫 A(`:615-620`) |
|---|---|---|
| 名册 | `for i = 1, #GetTeamPlayers(GetTeam())` + `GetTeamMember(i)` | `J.GetAlliesNearLoc(...)` = `jmz_func.lua:480-489`,**同一个循环逐字** |
| 半径 | `GetUnitToLocationDistance(member, vCamp) <= 800` | `GetAlliesNearLoc(preferedCamp.cattr.location, **800**)` |
| 排己 | `member ~= bot` | `ally ~= bot` |
| 有效 | `J.IsValidHero(member)` | `member:IsAlive()`(reader 内)+ `J.IsValidHero(ally)` |
| 幻象 | `not member:IsIllusion()` | `not ally:IsIllusion()` |
| 行为 | `J.IsFarming(member)` | `J.IsFarming(ally)` |

⭐ **「守卫 A 多一个 `IsAlive`」不构成差别,这是查出来的不是让出来的**:
`J.IsValidHero` → `utils.lua:547` → `IsValidUnit`(`:537-541`)= `not IsNull() and CanBeSeen() and **IsAlive()** and not IsInvulnerable()`
⇒ `IsAlive` 被 `J.IsValidHero` **蕴含**,两侧同真同假。
⇒ **两个谓词在任意一帧上取值必然相同**(同一个 `preferedCamp`、同一个名册、同一帧状态)。

### 2.2 顺序:守卫 A 在同一帧**更早**,而且它的答案是**摘掉 mode**

- `GetDesire()`(`:130-186`)= `GetDesireHelper()` + 一个 cap,**三处缓存全部注释掉**
  (`:146-148`;`GetAlliesNearLoc` 自己的缓存同样注释掉,`jmz_func.lua:476-478/491`)⇒ **每帧现算**。
- 守卫 A 命中 ⇒ `return BOT_MODE_DESIRE_NONE`。
- **顺序不是我推的,是仓库自己的 API 文档逐字写的**:
  `docs/BOT_API_REFERENCE.md:63` 「`GetDesire()` is called **every frame for ALL modes simultaneously** …
  **Only that mode's `Think()` is then called**」;`:115` 「Execution order each frame: `TeamThink()` →
  each bot's mode `GetDesire()` → **the winning mode's `Think()`**」。

⇒ **凡是走到 `:613` 那条丛林营分支的帧,`arbheart` 的循环结构上不可能找到可释放的队友** ——
因为**同一个谓词**在同一 tick 早一步已经被求值为假(否则农场欲望已经是 0,farm mode 没被选中,
`Think()` 根本不会被调用,`arbheart` 的心跳也就不会跑)。

### 2.3 ⛔ **但它不是恒等 no-op —— 这一条必须连着读,否则会得出一个更强而错误的结论**

守卫 A 只坐在**一条**分支的头上(`:611-636`,注释逐字「Late game or dangerous lanes: farm jungle camps」)。
`GetDesireHelper` 另有 **6 条**返回正欲望的出口(`:383` / `:404` / `:462` / `:523` / `:606` / `:645`),
它们**都可能带着一个早先闩上的 `preferedCamp` 返回**,而**不经过守卫 A**;
`Think()` 随后在 `:912-1063` 照样朝 `preferedCamp` 走。
⇒ **`arbheart` 的有效域 = 农场欲望由这 6 条旁路出口给出、而闩指向一个队友正在打的营的帧。**
⭐ **而这恰好就是 GH #455 拍下的那种几何**(CM 距营 5744u、SB 已在营里 340u),
**所以「它是死的」这个更强的说法不成立,登记为域被卡窄,不是域为空。**

### 2.4 ⭐⭐ 连带:**gate 自己的注释对它点名的那条守卫说错了话**

`:821` 逐字:「the two anti-steal guards at **`:589`** / `:811` need **`IsFarming AND IsAttacking`** true at the CM tick」。
⛔ **对 `:811` 成立(今天的 `:919-923`,确实是 `J.IsFarming(ally) and J.IsAttacking(ally)`),对 `:589` 不成立。**
**行号漂移是从 git 买的不是猜的**:`git show ea4efee4:bots/mode_farm_generic.lua | sed -n '583,596p'`
(`ea4efee4` = 落 `arbheart` 的那个 commit)在 **589 行**上逐字就是
`local nCampAllies = J.GetAlliesNearLoc(preferedCamp.cattr.location, 800)` —— 即守卫 A,
**它只要 `J.IsFarming`,和 `arbheart` 自己用的是同一个谓词。**
⇒ 立项论证里「三条出厂守卫都没再响」那一句,对其中一条的理由是错的;
**修正后结论没塌**(2.3 的旁路域仍然成立),但**它骑在一条不成立的理由上**(纪律 4 的形状)。

### 2.5 为什么这件事此前没人举手

`check_armed_wiring.py` 读 WIRED(调用点在、可达);`verify_coverage` 读 `verify=1`;
`a_evidence_route` 读 `class=VERIFIED`。**三个工具一致地什么都没说** —— 这正是 §HB.0 的立案句,
本轮只是把「为什么这条 id 12 波无人看」换成了「**看了之后它的域长什么样**」。
⚠️ **与 `pullcad` 陷阱同族但第三个极性**:`pullcad` 是 promote 冻死点名它的合取;
§GW.2 是「后果被另一条 id 掐住」;**本条是「谓词被一条出厂代码在上游抢答,而抢答的方式是摘掉宿主 mode」**。
📌 *可迁移的一句:一个门若与上游某段出厂代码共用谓词,而上游的答案是「让这个 mode 别跑」,
