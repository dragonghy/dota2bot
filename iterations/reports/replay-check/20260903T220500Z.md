## 2. `slotpush` 是什么 —— 循环的**域**是玩家 id,取值器的**参数**是队伍槽位

`bots/FunLib/utils.lua:1708`:

```lua
for i, playerdId in ipairs(GetTeamPlayers(bot:GetTeam())) do   -- 0..4 / 5..9
    if IsHeroAlive(playerdId) then
        local nSlot = playerdId
        if bSlotPush then nSlot = i end            -- 闸:i 是队伍槽位 1..5
        local teamMember = GetTeamMember(nSlot)    -- 参数是 SLOT
        if teamMember ~= nil
           and #teamMember:GetNearbyHeroes(2000, false, BotMode.None) >= 2
           and (IsNearEnemySecondTierTower(teamMember, 2000)
                or IsNearEnemyHighGroundTower(teamMember, 3000)
                or GetUnitToUnitDistance(teamMember, enemyAncient) < 3000)
        then return true end
    end
end
```

出厂扫描按侧漏人(**本轮工具从数值推导,不抄表** —— `shipped_scan()`,selfcheck 逐条钉):

- **天辉**(id 0..4 → nSlot 0..4):`GetTeamMember(0)` 是 nil ⇒ i=1 整轮跳过;i=2..5 读槽 1..4
  ⇒ **五个成员看四个**,槽 5(pid 4)从不被看;而且从 i=2 起,**守卫问的是 pid i-1、
  取到的成员是 pid i-2** —— 守卫和被守卫的对象是两个不同的英雄。
- **夜魇**(id 5..9 → nSlot 5..9):只有 nSlot=5 在范围内(i=1)⇒ **五个成员只看一个**
  (队伍槽 5 == pid 9),守卫问的是 pid 5。

armed(`nSlot = i`)时 `list[i]` 与槽 i 是同一个英雄 ⇒ 五个全扫、守卫与对象一致。

**七个消费点**(唯一解闸处 `jmz_func.lua:12409` 的 `J.IsTeamPushingHighGround`)**全部用
TRUE 去压制一件分心事**:`mode_ward_generic.lua:37`、`mode_rune_generic.lua:135`、
`mode_outpost_generic.lua:45`、`mode_side_shop_generic.lua:33`、
`mode_secret_shop_generic.lua:28`、`mode_roshan_generic.lua:42`、
`mode_laning_generic.lua:187` —— 每一处都 `return BOT_MODE_DESIRE_NONE`。
⇒ **漏扫只能让 TRUE 更难成立,于是出厂树在围高地时把人放去插眼/买装/拿符。**

### ⭐ 本轮自己抓到的一个量具缺陷(新,可复用,已写进变异台的用法)

**Python 变异台在 `restore` 之后可能仍然读到变异体的字节码。**
第一轮变异台跑完时,`diff` 对源文件是**干净的**,而**还原后的基线却是 1**:
`__pycache__` 里的 `.pyc` 用 **(源文件 mtime 秒, 源文件字节数)** 判定新鲜度,
而 `N_HIGH_GROUND = 5` → `4` 这种**等长**替换 + 同一秒内完成的 `cp` 还原,
**两项都没变** ⇒ 陈旧字节码被判为有效。后果不只是收尾误报:
**跑变异台的过程中,某个变异体的判决可能是拿上一个变异体的字节码算出来的。**
⇒ 修法:`cp` 还原与每次运行**之前都清一次 `__pycache__`**;修后重跑
**15 CAUGHT / 0 SURVIVED**。与 `tests/test_mutstand_restore_trap.py` 同族
(那条盯的是**文件**没还原,这条是**文件还原了而读数没有**)。
