## 2. ⭐⭐ 本轮的自捉:**两次独立普查对不上,原因在量具不在游戏**,而且它压掉了价值列的一半以上

**这是连续第四轮由「逐帧核验自己递上来的候选清单」抓到量具而不是抓到游戏。**

第一版扫完 152 局后重扫一遍,**只有两个计数变了**
(`deaths_holding_castable_ult` **190 → 193**、`retreat_proxy_frames` **685 → 707**),
其余逐位相同。追下去是**两条独立的仪器事实**:

### 2.1 dumper 同一 tick 内的行序不确定

同一份 `.dem` 连跑三次:行**集合**逐行相同、`events` 逐字相同,
但**行序不同**,三次 md5 三个值。

```
rows 109866 109866
key sequence identical: False
sets identical:         True
events equal:           True
```

Go map 迭代序,不是 bug —— 但它意味着**任何依赖「某个 t 上的第一行 / 下一行」
的读数都不可复现**。(⚠️ 第一次核验时我只比了「行数 / null 行数 / 最早 null 的 t /
Zeus 行数」四个聚合量,四个全同 ⇒ 判成「串行确定」。**那是拿聚合量当逐行核验**,
正是铁律 4「先逐帧后聚合」在量具上的同一个坑;md5 一比就翻了。)

### 2.2 `hero` + `player_id` 不唯一标识一个单位 —— **幻象同名同 pid**

实测一局:`npc_dota_hero_zuus` 的
`idx 1534` **6,514** 行、`idx 1622` **326** 行、`idx 2084` **326** 行,
**位置不同、hp/mp 相同**。全语料 Zeus 幻象行 **71,512** 行。

### 2.3 代价不是「两个数抖了一下」

幻象行混进 Zeus 的时间序后,episode 被幻象帧**拖过真实死亡时刻**,
于是 `t1 <= death <= t1+6` 落空:

```
修好前  ep_died =  82
修好后  ep_died = 198        ← 同一份语料、同一个窗口,2.4 倍
```

**价值列 —— 这条腿唯一被预登记为强制项的那一列 —— 差点被自己的量具读成三分之一。**

### 2.4 修法与它自带的交叉验证

Zeus 实体按 `idx` 取(出现帧数最多的 idx = 本体,并对**并列**单独计数报警);
死亡改**从本体自己的 hp 序列**读(`hp>0 → hp<=0`),不再按名字从战斗日志取
—— 日志的 `target` 是**英雄名**,幻象的死和本体的死在日志里长得一样。

**⭐ 换法自带交叉验证**:两个互不相干的仪器(本体 hp 序列 vs 战斗日志 DEATH 行)
在 **152/152 局上逐局给出相同的死亡数(合计 741)**。

修好后**两次独立全量普查逐位相同**(`DIFFERING KEYS: NONE`)。
**本轮 published 的每一个数出自同一版本。**

## 6. 限度(一句都不许合并)

1. **域计数是上界** —— `J.IsRetreating` 是 bot 内部 mode,任何录像都没有。
   几何代理 `retreat_proxy_frames = 558/1,843 = 30.3%` **只放在自己的键下**,
   **不许当成 mode**:被围住的 bot 可以处在撤退 mode 却退不动。
2. **第 (4) 列 PARTIAL,而且几何这条路走不通**:`J.IsDyingUnderAttack` 的前两个
   条件被第 (1) 列自己蕴含,1200 环是几何 —— **80.5% 的域帧 / 96.1% 的 episode
   都在环里** ⇒ 几何**分不开**两根杠杆;唯一分得开的
   `GetEstimatedDamageToTarget` 是活 bot API 预测,录像里没有。
   回溯代理 `ultcash_retro_and_ring = 372 帧 (20.2%)` **不是那个谓词**
   (预测会对没落地的伤害开火,也会对没预测到的伤害沉默),**既不是上界也不是估计**。
   ⇒ `zusultstrand` 的收益里有多少是 `ultcash` 本来就该接的,**本轮买不到**。
   (`ultcash` 自己**仍然 gated**,本语料里两条路都没跑过。)
3. **152 局不是 5,785 局。**
4. **方向是 WIDENING**:arming 只能**增加**这条分支上的施放。负读数只能读作
   「多放的那些放错了」,**永远不能**读作「杠杆少放了 N 次大招」。
5. **幻象一列单独给**:`in_chase_radius_real_only` 与含幻象读数**逐位相同**
   (1,645)⇒ 本语料里没有一帧靠敌方幻象进环。哪个是杠杆读到的?**含幻象那个**
   (`J.GetNearbyHeroes` 无幻象过滤器);本轮两者相等,所以不影响任何结论。
