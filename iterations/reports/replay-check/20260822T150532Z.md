## 3. ⭐ 新缺陷(已开 issue):拉的是「最近的野点」,而触发条件保证 bot 站得靠前

### 3.1 读数

| 量 | 值(115 个 armed poke episode) |
|---|---|
| 开拉时离**自家泉水**距离 | **中位 10,708u**,p90 11,244u,max 12,036u |
| 两泉水间距 | 18,806u ⇒ **中位数在全图 57% 处,已越过中点** |
| 离家 >9,000u 开拉 | **67/115(58.3%)** |
| 离**敌方**泉水比离自家还近 | 6/115(5.2%) |
| 跟随小野最远离开野点多少 | **中位 742u**,p90 998u,**max 1,170u** |
| 跟随小野离最近一只线兵最近多少 | **中位 1,068u**,p90 1,943u |
| 拖拽真的够到一波兵 | **(i) 15/74(20.3%)** / **(ii) 9/74(12.2%)** |

**两个估计量都报,因为它们不一致而且不一致是真的**:(i) 是 episode 级、按 drag 帧那一刻的
跟随集合往前追;(ii) 每个采样重新求跟随集合。**两个都是下界**(小野在 dump 里没有 idx,
身份只能靠邻近;20s 之后的接触读不到)。**结论不依赖选哪一个:连接率 ≤20.3%。**

⭐ **边缘对照(章程要求:报低读数之前先证明探针会响)**:跟随小野**最远只走出 742u
(中位)/ 1,170u(max)**,而它们**离最近的线兵中位还有 1,068u**。
⇒ **失败的是拖拽的几何,不是估计量** —— 野点离兵线太远,小野在够到兵线之前就脱离了。

### 3.2 机制(源码级,不是推断)

`jmz_func.lua:7530-7544` 的选点逻辑:遍历 `GetNeutralSpawners()`,
只筛 `camp.team == GetTeam()`,取**离 bot 最近**且 `< 1500` 的那个。
**没有任何一条子句问「这个野点在不在我方半场 / 在不在我方兵线后面」。**

而同一个函数的**承重触发条件**是:「我方兵线前沿越过中点、压向敌方」
(`jmz_func.lua:7508-7519`)。**这两条互相拆台**:兵线被压出去的时候,
支援本人就站在靠前的位置,于是「离他最近的己方野点」**恰恰是深处的远野区营地**。
帧上可见的位置聚类印证了这一点 —— armed 侧 267 个 poke 帧里最集中的单点是
**(3994,−5137),95 帧(35.6%)**,即 radiant 远野区那一组营地;
它的 dire 镜像 **(−4007,4947) 另占 41 帧(15.4%)** ⇒ **两个远野区营地合计 51%**。

**教科书拉野拉的是自己兵线背后那个营**;这里拉的是**离 bot 最近的那个**。

### 3.3 附带的第二个门槛问题

`J.IsLanePullSafe` 的血量门是 `J.GetHP(bot) >= 0.5`,**这是唯一的血量条件**,
而且**没有任何「我打不打得过/扛不扛得住这个营」的判据**。实测代价:
开拉后 15s 内掉血**中位 19 个百分点、p90 40、max 61**;
**9/115(7.8%)的 episode 掉到 35% 血以下**;**2/115(1.7%)在 20s 内死亡**
(**邻近计数,不是归因** —— §2.4(丁) 那一例已逐帧写明归属边界)。
§2.4(丙) 的 CM 是最刺眼的一例:**54% 血入域,被一个 kobold 营打到 30%**。

⇒ **本组五个焦点英雄里的三个(Crystal Maiden、Zeus、Lion)都出现在拉野者里,
