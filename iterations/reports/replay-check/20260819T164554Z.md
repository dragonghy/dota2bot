### 2.1 机会 episode 差分(32 局,armed 侧 = 候选侧,baseline = 稳定版侧)

episode 定义 = 两个 helper 的**全部可离线观测门**(角色由 `analysis.json:team_slot`
% 5 + 1 还原;laning phase 取 turbo 硬地板 t ≤ 480s;排除尸体帧;同一
(规则, actor, target) 6s 内不重复计):

| rule | 侧 | n | **6s 内击杀** | 4s 内本人对目标伤害 | 4s 内零输出(对任何单位) |
|---|---|---|---|---|---|
| l1trade | **armed** | **228** | **30.7%** | 59.6% | 25.9%* |
| l1trade | baseline | 174 | **47.1%** | 64.9% | 20.0%* |
| l5combo | **armed** | **121** | 40.5% | **61.2%** | 24.4%* |
| l5combo | baseline | 81 | 40.7% | **76.5%** | 10.4%* |

`l1trade` 击杀转化 **χ²=11.32(p≈0.0008)**;`l5combo` 的「4s 内出手」
**χ²=5.22(p≈0.022)**。(*零输出率一栏是臂 B 16 局的子样本。)

**注意 n 本身就是症状**:armed 侧的机会 episode **更多**(228 vs 174)。
episode 之间隔 6s 才重新计数,所以「一个残血敌人在我身边活很久」会反复生成
episode —— 机会更多 + 转化更低 = 同一件事的两面。

## 4. 机制判断(代码级,与 `[strategy] #39` 完全对齐)

协同组 15:38Z 刚立案的 **`#39` / gated `roamstale`** 精确预测本轮观测:
`mode_team_roam_generic.lua` 的 file-local `hTargetCreep` 只有一个写点(L287,
补刀分支),**位于六个提前 return 的 desire 分支之下**,且从不重置;而 `Think()`
**第一件事**就是 `if J.IsValid(hTargetCreep) then bot:Action_AttackUnit(hTargetCreep) return end`
(L461-463)。于是**任何一帧只要有一个上层分支赢了出价,这个 mode 的动作就是
「打上一帧的小兵」**,`targetUnit` 根本走不到。

为什么这会在**候选侧更严重**(可证伪的预测,与 2.1/2.2 一致):
两侧都有 shipped 的 `ConsiderHelpWhenCoreIsTargeted`/`ConsiderHelpAlly` 吃这个 bug,
但**候选侧多了 4 个会提前 return 的分支**(`ownhalf`/`overchase`/`l1trade`/`l5combo`)
→ 候选侧「动作被吃掉」的帧更多 → 机会更多、出手更少、零输出率更高。
**`#31` 把出价修到了 0.92 能赢,但赢来的这一帧的动作被上一帧的小兵吃掉了。**

诚实边界:
- 本轮**不能**把赤字单独归给 `l1trade`。域内同时活跃的还有 `ownhalf`/`overchase`
  (同族分支、同一条 ACTION 缺陷)。`capmono` 已用对照 B 排除,侧偏置已用对照 C 排除。
- dumper 不落 `GetEstimatedDamageToTarget` → 致命性/self-risk 门离线不可判定,
  604 个 episode 是真实触发集的**超集**(与 #31 那轮同一条边界)。
- 3.1 那 8 秒**零输出**与「打一个远处/已死的陈旧小兵句柄」一致,但我没有小兵
  entity 级的攻击指令流,不能把它**逐字**证成 `Action_AttackUnit(staleCreep)`;
  这是 `#39` 需要用 armed 波次自己证的部分(见 5)。
