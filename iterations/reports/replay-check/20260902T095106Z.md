## 2. ⭐ 新缺陷:两个 punish 检测器把 finding 记在了**敌人**头上(**GH #421**,已开)

### 事实(代码)

```python
# detect.py:592     "detector": "unpunished_tower_dive", "hero": diver,       ← 冲塔的敌人
# detect.py:711-712 "detector": "enemy_overchase_unpunished", "hero": chaser, ← 追人的敌人
# sweep_run.sh:140-142
hero_team = teams.get(f.get("hero"))
f["on_candidate_side"] = (hero_team == side_team)
```

而这两个检测器的 docstring 自己写明,该被量的是**防守方**:

> `d20`:「This is the missed counter-punish the 'overchase' fix
> (`J.ShouldPunishOverchase`) is meant to convert into a kill;
> **a candidate side with the fix armed should produce FEWER of these findings**.」

armed 的是**防守方**(该收掉人头的那边),finding 却按**追击方**打标签 ⇒ **标反**。
`d6` 更直接:它**自带 `defender_team` 字段**,`sweep_run.sh` 没读。

### 逐帧(先逐帧后聚合)

`26717d/20260902_033328_slot7`,两条 `enemy_overchase_unpunished` 全部逐帧核对:

```
t=1491.4  chaser=vengeful_spirit  team 3(dire=baseline)  -> on_candidate_side=False
          defenders(没收掉人头的) = lich, obsidian_destroyer, witch_doctor  全部 team 2(radiant=ARMED)
          victim = phantom_assassin
t=1575.4  chaser=skeleton_king    team 2(radiant=ARMED)  -> on_candidate_side=True
          defenders(没收掉人头的) = sniper, vengeful_spirit                全部 team 3(dire=baseline)
          victim = lion
```

**两条都是:被打标签的队 = defenders 的对面队。** 不是偶然 —— 两队互补,
所以这是**恒等式**:修正后的 candidate 计数 **恒等于**现行的 baseline 计数。

### 聚合(这 3 局,radiant=ARMED)

| 检测器 | 现行(冲塔/追击方打标签) | 修正(防守方打标签) |

| `unpunished_tower_dive` | cand **7** : base **13** | cand **13** : base **7** |
| `enemy_overchase_unpunished` | cand 1 : base 1 | cand 1 : base 1 |

⇒ **`r = (cand−base)/局` 精确变号**,于是 `arm=(r_ab+r_ba)/2` 与 `side` **也精确变号**。
不是「偏一点」,是**符号反的**。

按 `"hero":` 字段逐个点名(`detect.py`):`tp_under_threat`/`tp_home_wasteful`/
