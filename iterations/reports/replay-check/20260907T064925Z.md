## 2. 上一轮新欠的「重扫 §9 / §6」—— **前提是错的,账退回,不是拖着**

上一轮交棒 (4) 逐字:

> 回头用新的幻象/行序修法重扫 §9(`cmrangedhp`)与 §6(`wkbonefight`)——
> 那两份读数是用**按名字取时间序**的老写法出的,`ep_died 82→198` 那个量级说明这**不是**理论风险。

**「按名字取时间序」这句对这两个模块不成立**,读源码就能翻,而且两处都比 `zusultstrand`
的修法**更早**:

- `cmrangedhp_domain.real_hero_streams()`(`:233`):`by_key[(s.get("hero"), s.get("idx"))]`,
  再用**出生时刻**判别本体(`rows[0]["t"] < 0`,horn 前采到才留)。
  它自己的 selfcheck 里有一条 **`PASS illusion_stream_dropped`**(65 PASS / 0 FAIL)。
- `wkbonefight_domain` 走 `entities.frames_by_hero()`(`entities.py:163`):
  `ent[s['idx']]` 分流 + `ss[0]['t'] > HORN_T` 丢弃 + 同名两条 pre-horn 流「留活得久的那条」
  ——**不让排序决定**。它的立案帧就是 08-25 那次 `lina` 三条流的现场。

⚠️ **这一条本身只是「读法」的结论,不是行为结论**,所以下面把它变成读数。

### 2.1 行序那一半:`(idx, t)` 逐行唯一 ⇒ 按 idx 取的读数**碰不到**它

上一轮 §2.1 的仪器事实(dumper 同一 tick 内行序不确定,**行集合相同**)只能通过一条路
到达读者:**同一个实体在同一个 t 上有两行**。量了 4 局:

| 局 | rows | `(idx,t)` 唯一? | `(hero,t)` 的重数直方图 | `index_by_t` 0.1s 桶碰撞 | 同名多流的英雄 |
|---|---|---|---|---|---|
| `20260827_091703_slot12` | 25,135 | **是**(`{1: 25135}`) | 1:14,956 / 3:1,192 / 5:96 / 7:162 / 9:252 / 11:42 / 13:60 / 15:34 / **17:57** | **0** | luna **17 流**、necrolyte 3 |
| `20260824_181344_slot1` | 7,970 | **是** | 1:7,073 / 3:299 | **0** | earthshaker 3 |
| `20260827_182136_slot4` | 16,310 | **是** | 全 1 | **0** | 无 |
| `20260902_153311_slot1` | 28,529 | **是** | 1:14,678 …… **25:58** | **0** | drow_ranger **25 流**、skywrath 3、sven 3 |
| **合计** | **77,944** | **77,944 / 77,944** | —— | **0** | —— |

读法:
- **按 `idx` 取 + 按 `t` 排序 ⇒ 每个实体的时间序是全序,行序不确定性无处可入**。
  这对 `cmrangedhp.bracket()`(二分找 `t<=T` 的最后一行)和
  `wkbonefight.index_by_t()`(0.1 秒桶,后写覆盖)都成立——后者**实测 0 次碰撞**。
- **按名字取就完全是另一回事**:同一时刻最多叠 **25 行**。
  上一轮 `ep_died 82→198` 那个量级在这里**看得见来源**,它只是没落在这两个模块上。

### 2.2 事件流那一半:`death_times` 按英雄名取,**但这 4 局里没被幻象污染**

`entities.death_times()` 用的是 `DEATH` + `target_hero`,key 是 **`canon(target)` = 英雄名**
——正是上一轮点名的那个形状(「日志的 `target` 是英雄名,幻象的死和本体的死在日志里长得一样」)。
所以单独量了它:**每一个事件死亡,拿本体自己的 hp 序列(`hp>0 → hp<=0`)在 ±2s 内对**。

```
g(4 局合计)   ev_deaths = 170   hp_deaths = 170   uncorroborated = 0
```

**40 个「局 × 英雄」格子逐格 `ev == hp`**,包括 luna(17 流)、drow_ranger(25 流)、
necrolyte / skywrath / sven / earthshaker(各 3 流)。
⇒ 在这批语料上,**幻象的死不进 `DEATH`+`target_hero` 行**;
`death_times` 与 `frames_by_hero` 是**两台互不相干的仪器**,这是它们的第二次逐局吻合
(上一轮是 Zeus 152/152 局 741 对 741,那次是 hp 序列 vs 战斗日志)。

**变异台(不然 `uncorroborated=0` 可能只是量具太松)**:往 g1 注入一行**假幻象死亡**
(`npc_dota_hero_luna`,t=300.0,真 luna 当时活着),当场:

```
luna  streams=17  ev_deaths=4  hp_deaths=3  uncorroborated=1  <-- UNCORROBORATED
      at t= [300.0]
```

⚠️ **诚实边界**:4 局不是全集,只有 2 局带**大量**幻象流;
这条读数说的是「这批语料里没找到污染」,**不是**「dumper 保证不会发幻象死亡行」。
`GH #586` 的验收里该加的是**这一条能自动跑的对照**,不是这句结论——见第 4 节。

### 2.3 结论(带上判据,不只带结果)

| 上一轮欠账 | 本轮判定 |
|---|---|
| 重扫 §9 `cmrangedhp` | **不需要**:实体按 `(hero, idx)` + 出生时刻取,`(idx,t)` 唯一 ⇒ 幻象与行序两半都进不来。**已有的读数不作废。** |

⚠️ 有一处**本来就登记过的**限度不受本轮影响、也没被本轮洗白:
