### 4.2 臂 B —— **两条路都被容量堵死,4/4 全部失败**

先试 `--on-demand`(与臂 A 一致):

```
VcpuLimitExceeded: You have requested more vCPU capacity than your current vCPU limit of 64
allows for the instance bucket that the specified instance type belongs to.
```

**这是本轮的新运维事实**:on-demand Standard 系列的**账户 vCPU 配额是 64**,
c6i.4xlarge = 16 vCPU/台 → **on-demand 最多同时 4 台**,臂 A 正好把它占满,
臂 B 一台都放不下。(`servicequotas:GetServiceQuota` 本用户无权限,配额值直接引自
错误消息本身。)这解释了为什么 12:12Z 那波 8 台**只能**走 spot —— 当时不是选择,是唯一可能。

改试 spot(独立配额桶):

```
InsufficientInstanceCapacity (reached max retries: 4):
There is no Spot capacity available that matches your request.   ← 4 个种子全部
```

c6i.4xlarge 在 us-west-2 当前**无 spot 容量**。这与 12:12Z 臂 B 三台被
`instance-terminated-no-capacity` 回收是同一个容量紧张的延续,只是这次连拿都拿不到。
