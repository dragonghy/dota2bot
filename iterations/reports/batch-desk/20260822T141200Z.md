## 3. ⭐ 本轮最硬的发现:`--rec-slots 16` 的事先登记验收 **exit 0 从一开始就不可达**

事先登记的命令**原样执行,判据一个字没改**:
```
python3 tools/batch_test/soak/rec_slot_cost.py run_121209 run_121214 run_121219 run_121224 \
    --baseline tools/batch_test/soak/rec_slot_baseline_merged.json
```
```
runs            : 4
games           : 308  (recording 308 / control 0)
recorder set    : [1..16]   [read from 16 claim sidecar slot(s)]
CANNOT CERTIFY: every slot recorded: no control leg exists in this corpus
  denominator: control slots=0 of 16
```
**真实 exit code = 2。**

### 3.1 一个差点被吞掉的操作坑:管道会把 exit code 偷走

我第一次跑的是 `… | tail -40; echo "EXIT=$?"`,打印出 **`EXIT=0`** —— 那是 `tail` 的退出码,
不是工具的。**屏幕上同时写着 `CANNOT CERTIFY` 和 `EXIT=0`**,而事先登记里 exit 0 = 通过、
上 16。**这正是「exit 2 是拒答不是通过」这条纪律最容易被绕过的方式:不是有人改口,
是管道替你改了口。** 重跑成 `> acc.txt; echo $?` 才拿到真值 2。
**新纪律:凡是判据挂在 exit code 上的验收,命令末尾不许接管道,退出码要单独取。**

### 3.2 为什么这不是「16 太贵」,而是「这把尺子量不了 16」

读 `rec_slot_cost.py`:`die('every slot recorded: no control leg exists in this corpus')` 在
**第 219 行**,而 `--baseline` 那一整块从**第 272 行**才开始。即:

- **rec-slots 16 时 `recording=308 / control=0`,工具在读 baseline 之前就拒答了**;
- 更下游还有第二道同形的门(第 298 行):`no control slot overlaps the baseline: the box factor
  is unknowable` —— **box factor 本身就要靠对照槽算**。

⇒ 12:10Z 写下的「16 槽没有波内对照腿,**只能跨波比**」这个预期**在工具里没有对应实现**:
`--baseline` 只提供 box factor 的参照剖面,**它替代不了缺失的对照腿**。
**换句话说,给 16 槽波次登记的那个 exit 0,结构上不可能出现。** 这不是本波的失败,
是**验收装置和被验收配置不匹配**——而且是登记时没人查出来的。
