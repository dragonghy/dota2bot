## 四、⭐⭐⭐ P4.1 标尺波在 `aws_run.sh` 上发不出去(本轮头号,已修)

### 4.1 机制(不是症状)

`OWNER_PRIORITIES.md` P4.1 逐字要求:`stable(当前 main,gate 全关) vs upstream(74727e4a)`,
并**点名用 `aws_run.sh`**(老的 old-ref-vs-new-ref 脚本)。而该脚本的 user-data 里:

```
sudo -u ubuntu python3 tools/batch_test/make_ab_build.py --old 'origin/$OLD_REF' --new 'origin/$NEW_REF' ...
```

`origin/` 是**硬贴上去的字面量**。对分支名这是对的;对**一个 commit SHA 或 tag 这是
范畴错误** —— `origin/<sha>` 根本不是 ref。`make_ab_build.py:50` 用
`git archive <ref> bots` 解析 ⇒ 直接 fatal。

### 4.2 阳性对照(⛔ 不让"结论对得上"冒充"机制对")

在本容器的真仓库上两跑,⛔ 无管道:

```
git archive <bare sha> bots   ⇒ BARE_EXIT=0      ,8,192,000 字节
git archive origin/<same sha> ⇒ PREFIXED_EXIT=128,fatal: not a valid object name: origin/a89aa6c…
```

⭐ **这对照把浅克隆排除在外**:同一个 commit、同一个仓库、同一次调用,**只差 ref 的形状**。
⇒ ⛔ 本台**不**主张「upstream 提交不可达」—— 本容器是 `is-shallow-repository = true`,
`merge-base --is-ancestor` 在这里给的 `no` **按章程那条硬知识不构成证据**,不写进结论。

### 4.3 失效方向(诚实边界)

⭐ **数据侧是安全的,钱侧不是。** build 失败后三个 bots 目录缺失 ⇒ 踩中
`ab_guard`(Y1,2026-09-05)⇒ 上传日志并自毁,**不会**把一局 stock-vs-stock 的
A/A 当成结果传上来。⇒ 代价是**一波的机器钱 + P4.1 再欠一个周期**,不是脏数据。
⚠️ 但 `ab_guard` 报的是 `A/B build failed`,**指向错误的原因**,下一个读者会去重查
build 而不是 ref —— 本轮的修复因此把死点**提前到 ref 上**并改了报错文本。

### 4.5 修复(⛔ 一行 `bots/` 未改)

`tools/batch_test/aws/aws_run.sh`,三处:

1. **`resolve_ref()`**:分支名 → `origin/<name>`(clone 的 checkout 可能是旧的);

## 十三、⛔⛔ 本轮的自我更正 + 一条比 §四 更要紧的新发现

**这一节推翻本报告 §四 的框架句,并留痕不抹。** 触发它的是 `claim_precheck.sh`
在发表前拒绝了草稿(`PRECHECK_EXIT=3`),逐字:

```
OFF-TRUNK commit  74727e4a
          resolves on origin/claude/admiring-hawking-0d1qd3
DO NOT PUBLISH YET -- the citations above do not resolve on origin/main.
```

⭐ **那道闸抓到的不是格式问题,是两条实质错误 —— 一条是本台的,一条是全队的。**

### 13.1 ⛔ 本台错了:「发不出去 / 四十九轮零发现」是假的

本章程**自己**在 `iterations/streams/batch-desk.md`(2026-09-05 那轮,§「头号产出:
P4.1 标尺波认领了」)逐字写过同一个根因:

> 根因确实在(`aws_run.sh` 把 `--old` 硬编成 **`origin/$OLD_REF`** ⇒ 40 位裸 SHA
> 按构造解析不了),⭐ 但 `git ls-remote origin` 一行就看见 `refs/heads/upstream-baseline`
> 早已存在且恰好指向 `74727e4a…` ⇒ `--old upstream-baseline --new main` **直接可用,
> 零 harness 改动、零新推 ref**。

**现读复核**(本轮,只读):`git ls-remote origin upstream-baseline` ⇒
`74727e4a66ab38d16fdb09800a19ab6c0c82c6b9  refs/heads/upstream-baseline` —— **ref 在。**

⇒ ⛔ **不是「发不出去」**:传**分支名**的那条路一直可用,`origin/<branch>` 正是硬编码
期待的形状。⇒ ⛔ **不是「四十九轮零发现」**:它被发现过、被写进本章程、还据此真发射过一次
(那次失败花了 ~$0.03,并促成了 `ab_guard`)。⇒ ⛔ **不是「一条从未被执行过的路径」**。

**本台的归因(不推给别人)**:§四 的阳性对照是对的,机制描述是对的,**错的是从
「这条形状不work」跳到「所以 P4.1 发不出去」** —— 中间少问一句「有没有别的形状能work」,
而答案就在本章程里,`grep` 一次就有。⚠️ **失效方向**:它把一个**真命题**(裸 SHA 解析不了)
用来满足**另一个问题**(P4.1 为什么没发),与铁律 1 §RULING 48 和铁律 4 §CL (i-a)
点名的手法**同型**,只是这次犯的是本台。

**修复本身仍然成立,但降级登记**:`resolve_ref()` 让**裸 SHA / tag** 也能用、
并把死点提前到 ref 上给出正确报错 —— 它是**一处真实改进 + 一道棘轮**,
⛔ **不是「解除了 P4.1 的阻断」**(阻断本来就有可用旁路)。本轮 commit message 与
章程条目里的框架句同样错,一并以本节更正,⛔ 不改写历史提交。

### 13.2 ⭐⭐⭐ 新发现(比 §四 要紧):`upstream-baseline` 指的不是 upstream

全队十余处文档(`iterations/streams/README.md:38`、`OWNER_PRIORITIES.md:121`、
`state.json:5103`、`DECISIONS_NEEDED.md:959` 等)都写 `74727e4a` = **「仓库初始 OHA 快照」**。
**它不是。** 两条独立证据,⛔ 都不依赖本容器的浅 clone:

**(甲) GitHub 侧的提交本体**(`mcp__github__get_commit`,第一手):
标题 **`TP trio fix E: shipped defend TP shares the tpcommit landing commitment`**,
日期 **`2026-07-23T04:46:17Z`**,作者 `Claude`,正文提到 `tpRespondLoc/tpRespondUntil`
与 **`(gated) tpcommit`** —— **这是本项目自己的 gated 改动**,OHA 上游不可能有。

**(乙) 该 commit 的树**(`git ls-tree --name-only`,浅 fetch 该 ref 后现读):
顶层含 **`iterations/`、`.claude/`、`CLAUDE.md`** —— 三样**本项目特有**的东西。
上游 OHA 快照里**不会有** `iterations/`(本项目的实验台账)。

⇒ **`origin/upstream-baseline` 指向的是本项目 2026-07-23 的自己。**

⚠️⚠️ **后果,按本项目最在意的那种失效形状**:P4.1 被 owner 定为最高优先,它要回答的是
**「这个项目到底有没有把 bot 变强」**(对照 upstream)。按现状发出去,它实际测的是
**「main vs 我们自己两个月前的树」** —— 一个**两个月的自比**,冒充**累计总进步的标尺**。
⭐ **而这份读数会长得完全正常**:有胜率、有 gpm 差、有局数,没有任何一行会举手说
「基线选错了」。这与本章程自己登记的
「`run_batch.sh` 在 bots 目录不存在时照常开打 ⇒ 一个失败长得跟数据一模一样」**同族**。

⛔ **本台声明的边界**:
- ⛔ **不主张本仓库的真正初始 OHA 快照是哪个 commit** —— 本容器是浅 clone,找根提交要么
  深拉要么翻 API 分页,**本轮没做**,⛔ 不猜。
- ⛔ **不动 `refs/heads/upstream-baseline`**(改一条被十余处文档引用的基线 ref 是
  测量语义变更,归总监;本台只报不改)。
- ⛔ **不主张十余处文档是何时、被谁写错的**,只主张**现读与它们不符**。
- ⭐ **可证伪**:任何人跑 `git ls-tree --name-only upstream-baseline | grep iterations`,
  有输出即本节成立。

⇒ **这条挡在 P4.1 前面,且 §四 的修复不解决它**:ref 形状对了,基线内容仍然是错的。
交棒见 §十一 补充条 ⑦。
