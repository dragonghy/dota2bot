## 四、⭐⭐⭐ P4.1 标尺波在 `aws_run.sh` 上发不出去(本轮头号,已修)

### 4.1 机制(不是症状)

`OWNER_PRIORITIES.md` P4.1 逐字要求:`stable(当前 main,gate 全关) vs upstream(74727e4a)`,
并**点名用 `aws_run.sh`**(老的 old-ref-vs-new-ref 脚本)。而该脚本的 user-data 里:

```
sudo -u ubuntu python3 tools/batch_test/make_ab_build.py --old 'origin/$OLD_REF' --new 'origin/$NEW_REF' ...
```

`origin/` 是**硬贴上去的字面量**。对分支名这是对的;对**一个 commit SHA 或 tag 这是
范畴错误** —— `origin/<sha>` 根本不是 ref。`make_ab_build.py:50` 用
`git archive <ref> bots` 解析 ⇒ 直接 fatal。

### 4.2 阳性对照(⛔ 不让"结论对得上"冒充"机制对")

在本容器的真仓库上两跑,⛔ 无管道:

```
git archive <bare sha> bots   ⇒ BARE_EXIT=0      ,8,192,000 字节
git archive origin/<same sha> ⇒ PREFIXED_EXIT=128,fatal: not a valid object name: origin/a89aa6c…
```

⭐ **这对照把浅克隆排除在外**:同一个 commit、同一个仓库、同一次调用,**只差 ref 的形状**。
⇒ ⛔ 本台**不**主张「upstream 提交不可达」—— 本容器是 `is-shallow-repository = true`,
`merge-base --is-ancestor` 在这里给的 `no` **按章程那条硬知识不构成证据**,不写进结论。

### 4.3 失效方向(诚实边界)

⭐ **数据侧是安全的,钱侧不是。** build 失败后三个 bots 目录缺失 ⇒ 踩中
`ab_guard`(Y1,2026-09-05)⇒ 上传日志并自毁,**不会**把一局 stock-vs-stock 的
A/A 当成结果传上来。⇒ 代价是**一波的机器钱 + P4.1 再欠一个周期**,不是脏数据。
⚠️ 但 `ab_guard` 报的是 `A/B build failed`,**指向错误的原因**,下一个读者会去重查
build 而不是 ref —— 本轮的修复因此把死点**提前到 ref 上**并改了报错文本。

### 4.4 为什么四十九轮没人看见

自 W15 起每一波都走 `spot_run.sh --validate`(arm 候选),**那是另一条路径,
一次都不碰这两行**。`aws_run.sh` 的 old-ref/new-ref 腿**只有 P4.1 用**,
而 P4.1 从未真的发出去过。⇒ **它不是回归,是一条从未被执行过的路径。**

### 4.5 修复(⛔ 一行 `bots/` 未改)

`tools/batch_test/aws/aws_run.sh`,三处:

1. **`resolve_ref()`**:分支名 → `origin/<name>`(clone 的 checkout 可能是旧的);
   SHA/tag → **裸用**;都解析不了 → 非零退出。
2. **两条 A/B 腿**(fwd 与 `--swap` rev)改吃 `$OLD_ARCHIVE_REF` / `$NEW_ARCHIVE_REF`。
3. **解析失败在 ref 处就死**(上传日志 + 自毁),并逐字打 `cannot resolve --old ref '<ref>'`。

顺带一条**结构性**的(⚠️ 只做结构断言,见下):user-data 在解析前先判
`git rev-parse --is-shallow-repository`,为真才 `git fetch --unshallow origin`
(对完整 clone `--unshallow` 是错误,故必须带守卫)。**理由**:P4.1 的基线是本仓库的
**第一个** commit,浅 clone 结构上没有它。

### 4.6 钉子 + 变异复核

`tests/test_aws_run_ref_form.py`(新,python 快棘轮,实测 **1.78s** 内,已被 `py_gate` 自动纳入)。
**行为覆盖,不是文本覆盖**:它把 `aws` 打桩后**真的跑一遍 `aws_run.sh`**(⛔ 零 AWS 调用、
⛔ 什么都没启动),抓下渲染出来的 user-data,再把其中的 `resolve_ref` **提出来在一个真的临时
git 仓库上执行**(分支 / 裸 SHA / tag / 不存在的 ref 四例)。

⭐ **变异复核(证据纪律 1)**:把**修复前的原文件**放回去 ⇒ `MUTANT_EXIT=1`,
逐字顶红四条 —— `user-data does not paste origin/ in front of --old` / `… --new` /
`make_ab_build.py is handed the RESOLVED refs` / `both A/B legs (fwd and --swap rev) use the resolved refs`;
随后在 `resolve_ref()` 提取处以具名断言中止(`resolve_ref() not found in the rendered user-data`)。
⛔ **它不是静默通过**。恢复后 `RESTORED_EXIT=0` 且 `RESTORE_IDENTICAL=yes`(逐字节)。

⚠️ **诚实边界,逐条**:
- 4.5 第 3 点(浅 clone)**只有结构断言**。AMI 里 `/opt/dota2bot` 到底是不是浅 clone,
  **在开发容器里读不到**,⛔ 本台不主张任一侧;它是**朝安全侧加的守卫**,不是已证实的修复。
- 本修复**未在真实实例上跑过**(刹车持有,发不了波)⇒ ⛔ **不主张「P4.1 现在能发了」**,
  只主张「**已知的那一条阻断已去掉,并有棘轮挡住它回来**」。
- 一次测试跑通**不等于** P4.1 的其余部分可用(见 §五 两条未测项)。
