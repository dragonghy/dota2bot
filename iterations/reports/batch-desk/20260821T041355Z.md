## 3. 本轮主要发现:**#75 的 21 天过期从来就不会生效**

### 3.1 事实

`tools/batch_test/aws/setup_aws.sh` 里 runner 角色的 `s3-results` 内联策略逐字是:

```
"Action":["s3:PutObject","s3:GetObject","s3:ListBucket"]
```

**没有 `s3:PutObjectTagging`。** 而我 00:17Z 落的 `soak_loop.sh` / `dem_claim.sh` 都是
`s3 cp` 之后再 `aws s3api put-object-tagging ... >/dev/null 2>&1` —— 这一步在实例上**必然 AccessDenied,
而且被 `2>/dev/null` 吃掉**。桶上那条 `soak-dem-expire-21d` 规则的 filter 是
`And(Prefix=soak/, Tags=[lifecycle=dem21])` ⇒ **实例写上去的 `.dem` 永远没有那个 tag ⇒ 规则永远匹配 0 个对象。**

⇒ **我 00:17Z 报告里「存储前置(#75 §4.3)已实际落地,不是建议」这句话是错的**,现予更正。
总监 §Y.5(甲) 担心的「两步的第二步失败会留下永不过期的对象」是对的,但**量级不是边角**:
在当前权限下**每一个** bulk `.dem` 都是那种对象(16 槽满跑 ≈ 2.8 GB/波,永久)。
`iam:GetInstanceProfile` 本用户无权限,所以这条是**读仓库里创建角色的源码**核出来的,不是猜的。

### 3.2 为什么不走「把两步并成一步」

`aws s3 cp` **没有** `--tagging`(实测本容器 aws-cli 1.46.0 的 help 里无此选项);
`s3api put-object --tagging` 有,我用自己的凭据对桶实测通过(`PUT_WITH_TAGGING_OK` +
`get-object-tagging` 读回 `lifecycle=dem21`,随即 `delete-object` 清掉探针)。
**但那是我的用户,不是实例角色** —— 带 `x-amz-tagging` 的 PutObject 需要 `s3:PutObjectTagging`,
实例角色没有 ⇒ 改成原子写会让**整个 PUT 被拒**,从「对象永不过期」恶化成「录像根本传不上去」。
**换句话说:凡是依赖打 tag 的修法,在不改 IAM 的前提下都不成立;而我没有 IAM 权限,也不该自己动。**

### 3.3 采用的修法:**保留期由 key 承担,不由 tag 承担**

新函数 `dem_bulk_prefix <s3_prefix> <rec_slots>`(`dem_claim.sh`):

- `REC_SLOTS=1`(**shipped 默认**):**原样返回** ⇒ `.dem` 仍写 `soak/<run>/<TAG>.dem` + `replays/<TAG>.dem`,
  **仍然永不过期,与 #75 之前逐字节相同**(严格非回归)。
- `REC_SLOTS>1`:返回 `s3://<bucket>/dem21/<run>` ⇒ **claimed `.dem` 与 `unattributed/` 抢救件都落在
  `dem21/` 树下**。桶上新加一条 **`dem21-expire-21d`:`Filter={"Prefix":"dem21/"}`,21 天过期,不看 tag** ——
  **纯前缀规则,不需要上传方任何额外权限,也没有「第二步」可失败。**
- `soak/<run>/` 里只剩**逐局档案**(`.analysis.json` / `.log.gz` / `.demclaim.json`,全档案 0.25 GB / 29,446 对象),
  **结构上不可能被任何过期规则碰到** —— 这正是章程「千万别删逐局数据」那批东西。

**总监 §Y.5(甲) 原文建议的「只按 `soak/*/unattributed/` 前缀、不看 tag 的过期规则」不可实施**:
S3 生命周期的 `Prefix` 是**字面前缀,不支持通配符**(与 08-21 00:17Z 记的「不支持后缀匹配」同族)。
`soak/<run>/unattributed/` 里的 `<run>` 在中间,表达不了。**把 key 挪到 `dem21/` 是实现该意图的最省事写法。**
另一条可表达的写法是 `And(Prefix=soak/, ObjectSizeGreaterThan=N)`,**我没有采用**:它会连带扫掉
`soak/` 下 **1,015 个历史 `.dem`(8.79 GB)** —— 那是录像组的语料,删不删不是批测台能定的。**若总监想回收那 8.79 GB,
这条规则是现成的,一句话即可,但要总监明确点头。**

桶上现状(实测 `get-bucket-lifecycle-configuration`):

| ID | Filter | 过期 |
|---|---|---|
| `dem21-expire-21d` | `Prefix=dem21/` | 21 天 |
| `soak-dem-expire-21d` | `And(Prefix=soak/, Tag lifecycle=dem21)` | 21 天 |
| `abort-incomplete-mpu-7d` | 全桶 | MPU 7 天 |

`soak-dem-expire-21d` **保留但已知对实例写入的对象恒不命中**(只有拥有打 tag 权限的会话手工打了 tag 才会命中)。
留着零成本、零风险;**但它不再是任何保证** —— 记在这里以免下一个人把它当成保证。
`dem21/` 当前对象数实测 **0** ⇒ 新规则今天扫不到任何东西,**上线即零回归**。
