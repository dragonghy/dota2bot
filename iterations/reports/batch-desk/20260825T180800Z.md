## 4. ⭐⭐ 本轮最硬的一件事:裁判的收局机制会拆遗迹,分类器认它

### 4.1 机制(读的是当前树的源码,不是上一波的产物 —— 15:19Z 那条教训照办)

`referee.py:172-181` 的注释写得很清楚,收局**不是** `dota_dev forcewin`(该 build 上是 no-op),
而是:

```python
rc.cmd("dota_surrender_on_disconnect 1")
rc.cmd("dota_auto_surrender_all_disconnected_timeout 1")
```

**引擎执行「投降」的方式就是拆掉投降方的遗迹** ⇒ 日志里出现一个**货真价实的 `_fort` 事件**。
而 `analyze_log.py:96`:

```python
fort = next((t for t in base.get("towers", []) if str(t.get("building","")).endswith("_fort")), None)
natural_end = fort is not None
```

`natural_end` 为真就直接 `winner_by = "engine_natural"`(:99-102),**在任何时间判据之前**。
`analyze_log.py:92-94` 的立法理由是「**遗迹被拆就是记分牌,不许用经济推理覆盖它**」——
这句话在 cap=10 下成立(裁判那时的机制拆不出遗迹,`engine_natural` 恒 0),
**在 cap=25 下不成立,因为裁判自己会拆遗迹**。

### 4.2 证据(210 局全量,三条互相独立)

以 `cap−0.5min = 1470s` 切开:

| | 局数 | 遗迹侧 | `winner == econ_winner` |
|---|---|---|---|
| **cap 以下结束** | **12 (5.7%)** | goodguys 7 / badguys 5 —— **近乎均分** | **12/12 = 100%** |
| **cap 上/后结束** | **198 (94.3%)** | goodguys **193** / badguys 5 —— **97.5% 同一侧** | **96/198 = 48%** |

1. **时间**:cap 上那 198 局,`fort_t − cap` 中位 **52 s**、p90 **91 s**、max **150 s**
   —— 紧贴裁判的估时误差,不是比赛节奏。整波遗迹时刻直方图:25 分 **119** 局、26 分 **68** 局。
2. **侧别**:真实对局不可能 97.5% 拆同一座遗迹,**尤其在金钱侧偏偏向 Radiant 的前提下**
   (真要有偏,该是 Radiant 更常拆掉 badguys_fort,方向正相反)。
3. **独立性**:cap 上那 198 局 `winner` 与 `econ_winner` 一致率 **48%**,即**掷硬币**;
   而 cap 以下 12 局是 **100%** 一致 —— 后者正是真实对局该有的样子(领先的一方拆遗迹)。
   **⇒ 那 198 局的胜负与「谁在赢」统计独立,它不是 gold-independent 的信息,是 gold-irrelevant 的噪声。**

另:`duration_s − fort_t` 全 210 局 = **0**(游戏在遗迹落地那一刻结束),
每局**恰好一个** `_fort` 事件 —— 这两条对两种解释都成立,**不能**用来区分,故不作为证据。
