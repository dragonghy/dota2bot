## 6. ⭐⭐ 本轮发现的 harness 缺陷:`spot_run.sh` 起飞失败时**退出 0 并打印 `launched`**

级 (1)(2) 的失败调用里,脚本打出的是:

```
launched dota2bot-soak-spot-1  id=  run_id=spot_20260831_212007_1_…_0f5de1  az=<ec2-chose>  actual=<unreported>
   S3: s3://dota2bot-batch-results-4924/soak/spot_20260831_212007_1_…_0f5de1/
```

**`id=` 是空的、`actual=<unreported>`,但那一行的动词是 `launched`,而 `BARE_EXIT=0`。**
四次 c6a 调用**全部** `BARE_EXIT=0`,而实际创建的实例数是 **0**。

**为什么这条重要**:它与章程反复点名的那族缺陷**同型且失效方向朝危险那侧** ——
一个只读退出码、或只 grep `launched` 的调用者,会认为四台已在飞,
于是**去收割一个永远不会出现的 S3 前缀**,而 verdict 会「照常产出、照常合理」地少四粒种子。
本轮之所以没被骗,只是因为本台按纪律用 `describe-instances`(独立证据源)核对了地面真相。

**本台按章程不自己改 harness** ⇒ 开 `[harness]` issue(见 §9)。
