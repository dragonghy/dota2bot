### 5.1 那一例分歧:`slot1` 被 `slot10` 前缀吃掉

```
run …_998b48 (seed 906) / claim_180943/20260823_181816_slot1.demclaim.json
  method       logname
  path         /opt/soak/slot1/20260823_181816_slot1.dem
  candidates   9
  by_logname   auto-20260823-1818-dota-soak_20260823_181816_slot1.dem     <- 对
  by_hostname  auto-20260823-1818-dota-soak_20260823_181816_slot10.dem    <- 错
  by_mtime     auto-20260823-1818-dota-soak_20260823_181834_slot12.dem
  hostname_hits 1     <- 仍然报「无歧义」
```

**机制(已在源码定位,不是猜)**:`dem_claim.sh:131-133` 用
`head -c $DEM_CLAIM_HDR_BYTES "$f" | grep -aqF "$tag"` 做 hostname 判据,`$tag` = `20260823_181816_slot1`,
而 slot10 的 demo header 里写着 `soak_20260823_181816_slot10` —— **`slot1` 是 `slot10` 的前缀**,
`grep -F` **无锚定** ⇒ 假阳性。**只有 slot 1 受影响**,且只在 `rec_slots ≥ 10` 时出现
(`slot2` 不是任何 `slot2x` 的前缀,因为槽号最大 16)。

**本波未造成任何错误归属**:`logname` 判据优先级更高且给对了,`method=logname`,
落地 `path` 是 slot1 自己的 `.dem`。**风险是在 fallback 上**:若某局 slot 1 的 console log
没能命名自己的 `.dem`(`logdem` 为空),就会**静默落到 hostname 分支、抢走 slot10 的录像**,
而两边的 sidecar 都会写 `hostname_hits: 1`。

### 5.2 第二个缺陷:`hostname_hits` **结构上封顶 1**,报不出歧义

`dem_claim.sh:131` 的条件是 `[ -z "$by_host" ] && head … | grep -aqF "$tag"` ——
`by_host` 一旦被赋值,**短路使后续候选根本不参与判断**,`host_hits` 因此
**永远 ∈ {0,1}**。⇒ 此前每一份报告里那句「`hostname_hits=1` = 无歧义」
**是同义反复,不携带任何信息**。这一点在 `candidates:1` 的年代无害;
本波是**第一次**真正演练多录制者(见 §5.3),缺陷才显形。
