两条 FAIL 的**内容不是断言失败**,是同一句设置错误(逐字):

```
bots/Customize/soak_side.lua is already there and this process did not write it,
so arming would clobber someone else's switch (and deleting it afterwards would
make THEIR failure unattributable). Contents: return { side = 'radiant', cand = 'wardcomma' }
```

命中的是 `tests/test_pipetower_backup_tower.lua`(2 例)与 `tests/test_pollyhp_getter_axis.lua`,
而后者的报错自己点名了病因:「…**or in a concurrent lua5.1 process** -- armed a candidate and did not remove it」。

**机制**:`bots/Customize/soak_side.lua` 是**按设计 gitignored 的单一路径**,
全仓所有 arm/unarm 的测试共用它。本轮容器里当时有**两组** lua5.1 在跑:
(甲) 铁律 10 自检的 Lua 探测腿(144 个探测器),(乙) 铁律 6 推送闸的 Lua 腿(438 个测试)。
⇒ 一方 arm、另一方在同一毫秒读到,后者按设计**拒绝继续**(它拒绝得对 —— 那正是它该做的)。

**⭐ 受控对照(同一棵树、同一个闸、同样 438 个测试,唯一变量是自检在不在跑)**:

| 推送 | 自检 Lua 腿 | 读数 | 结果 |
|---|---|---|---|
| PUSH3(分支) | **在跑** | `438 ran, **2 findings**, 657.2s` | **REFUSED** |
| PUSH4(main) | **已结束** | `438 ran, **0 findings**, 669.0s` | 通过,`a745bbd5..8bcce944` |

⇒ ⛔ **不是代码红,是并发红**。`git diff` 只动了 `tools/agent/citation_audit.py` 与
`tests/test_citation_audit.py`(纯 python),**在算术上不可能**改变任何 Lua 测试的判决。

⚠️ **为什么这条要上报,而不是「知道了、重跑一次就行」**:
