## 十、⭐⭐⭐ 收尾时 `claim_precheck.sh` 抓到的第二件事:它把 graft 点以下的 commit 报成 OFF-TRUNK

**这一节不在原工作单元计划内**,是按 GH #290「发表前先跑 `claim_precheck.sh`」时撞上的。

第八节那份交棒草稿(后来的 **GH #519**)引用了 W47 的发波树 `15b0d9fd`
(`iterations/reports/batch-desk/waves/W47_wave.json` 的 `tree` / `ref_pin` 字段逐字)。**第一次跑:**

```
PRECHECK_EXIT=3
OFF-TRUNK commit  15b0d9fd   resolves on origin/claude/admiring-hawking-u7a3e2
1 finding(s)
DO NOT PUBLISH YET -- the citations above do not resolve on origin/main.
Push, then re-run this, then close the issue / post the comment.
```

⚠️ **它给的修法在这里按构造做不到** —— 那不是本会话的 commit,也不是任何人的未推工作。当时容器里的读数:

```
git merge-base --is-ancestor 15b0d9fd origin/main   => exit 1  ("NO")
git rev-parse --is-shallow-repository               => true
git rev-list --count origin/main                    => 51
git log --format='%h %ci' origin/main | tail -1     => 544fdf66  2026-09-04 19:45:52 +0000
```

⭐ **关键算术:`15b0d9fd` 的时刻是 `2026-09-04 17:52:13Z`,而本容器 `origin/main` 最早可见的 commit
是 `2026-09-04 19:45:52Z` —— 它比 graft 点早 1h53min** ⇒ `merge-base` 不是「查到了不是祖先」,是**根本查不到**。

**第二次跑,草稿一个字没改,只加了一次 deepen:**

```
git fetch --deepen=200 origin main                  => DEEPEN_EXIT=0
git rev-list --count origin/main                    => 306      (51 -> 306)
git merge-base --is-ancestor 15b0d9fd origin/main   => exit 0   ("YES")
PRECHECK_EXIT=0     resolved on trunk 7 (was 6)     clean / OK to publish
```

⇒ **同一份草稿、同一个 trunk,`3 → 0`,唯一的自变量是浅克隆的深度。**
⭐ 独立佐证(不是本轮量的,是 W47 自己当时量的):`W47_wave.json:rerun_tree_note` 逐字写着
「**and 15b0d9fd is an ancestor of origin/main (`git merge-base --is-ancestor` exit 0)**」。

**⭐ 两个后果,都不是一次性的:**

1. **本台的第四节算术按构造要引用上一波的发波树**,发波间隔 6h 而 graft 点只覆盖最近约半天到一天
   ⇒ **上一波的树很快就会落到 graft 以下** ⇒ 这个 exit 3 **每一轮都会复发**。
2. 铁律 6 / #290 明写 **`3 = 先 push 再发`**,但这里**没有东西可推** ⇒ 执行者面对一条**做不到的指令**,
   而做不到的指令的实际归宿是**被绕过**;绕过一次,`claim_precheck.sh` 对**其余七条真引用**的把关也一起没了。

**⭐ 而同族工具已经把这条边界写对了,所以这是不一致不是疏忽**:`unlanded_commits.py`
(章程说与 `citation_audit.py`/`claim_precheck.sh` **同一个解析器**)在**同一容器同一轮**对**同一片区域**
明确拒绝报,并自打 `REFUSED refs : 782 of 807 (uncertifiable, mostly stale session branches with no merge-base)`;
本台历轮报告一直照登它那句「**graft 点以下一律不报,两个方向都不报**」。
⇒ **一个工具知道自己看不见就闭嘴,另一个看不见就下判决。**

**「没跑成不是通过」(#205/#171) 的镜像是「看不见不是不在」** —— 前者把红读成绿,后者把绿读成红并**拦住一次正确的发表**。

已开 **GH #520 `[harness]`**,建议修法:(1) 判 ancestry 前**自己先 `git fetch --deepen`**(本轮实测 `EXIT=0`,耗时可忽略);
(2) 兜底仍够不到时打 **`REFUSED`/exit 2**,**不打 `OFF-TRUNK`/exit 3**(2 = 本容器不知道,3 = 这条引用是假的,两者语义不同);
(3) `DO NOT PUBLISH YET` 那句的修法指向改成 deepen。
⛔ **边界**:不主张 `claim_precheck.sh` 该放松(它 push-before-publish 的职能本轮照常正确生效:
`local commits not on origin/main: 0` 是它先确认的),不主张任何历史结论有问题,不主张 Routine 不该用浅克隆。
