## 五、⭐⭐⭐ 本轮新发现:`recover_verdict.py` 的静默零(已开 **GH #631**)

**怎么撞上的**:章程 §2 的散文写「臂串取 `test_set.md` **第 3 行**」,而该文件的**第 2 行**才是臂串,
第 3 行是一句以 `**成员串 44**(上一行,…` 开头的**散文**。本台照散文取了第 3 行。

**工具的反应**:

```
RV_EXIT=0            ← 干净退出
stderr: (空)          ← 一个字节都没有
games_loaded: 204    ← 语料全在,读着像一切正常
unparseable: 0       ← 没有坏文件
thin_arm_seeds: []   ← 读着像「没有一粒被排除」

```

用一个**彻底不像臂串**的字符串(`NOT_AN_ARM_STRING_AT_ALL`)复现,**逐字相同**。

**为什么这条重要**:`hold_or_reject` 是一个**看着像结论的东西**。一轮会话若照散文取错了行,
拿到的是「exit 0 + 零告警 + 204 局 + 一个 reject 建议」,而**真实情况是零粒种子参与了计算**。
它与本仓库反复吃过的那一族**同构**:`shallow clone 的空输出被读成无漂移`、
`0/231 被读成「独立性小」`、`113 passed 被读成 GREEN`——**空集穿着读数的衣服**,
且**失效方向朝危险那一侧**(它压 promote,不放行,所以不会有人因为被拦而来查它)。
顺带:本轮用**正确**臂串跑时 stderr 有 GH #352 那行 DEGENERATE 警告,
**于是「有没有 stderr」看着像个信号,其实是巧合,不是门。**

**建议的验收**:`per_seed` 为空(或 `scored` 粒数为 0)时 `recover_verdict.py`
**按 `refuse()` 的家法退 2 并且不打 `suggested`**;`tests/` 里钉一个用错臂串的用例。
