## 二、⭐⭐⭐ 按需波的终止码:结构上读不到,而闸不会举手

### (甲) 读不到 —— 而且不是「这轮手慢了」,是**时序上不可能**

章程 `W60_wave.json:harvest_instructions (b)` 逐字:
> read EC2 `StateReason.Code` per machine from describe-instances, and do it in the
> harvest round -- terminated instances age out of the API in ~1h (GH #375).

本轮逐台去读,四台**全部**:

```
=== i-06b4c4aba46b61c97 RC=0 BYTES=26   { "Reservations": [] }
=== i-0bb3cf07d2a3e7f85 RC=0 BYTES=26   { "Reservations": [] }
=== i-07de3698e808dcba9 RC=0 BYTES=26   { "Reservations": [] }
=== i-085094e48cd50d9d3 RC=0 BYTES=26   { "Reservations": [] }
```

⚠️ **空输出不许直接读成「没有」** —— 跑了对照:

```
=== fake id control ===
CTRL_RC=255
An error occurred (InvalidInstanceID.NotFound) ... The instance ID 'i-00000000000000001' does not exist
```

⇒ 编造的 id 得到 **`NotFound` / rc 255**;这四个真 id 得到 **rc 0 + 空 `Reservations`**。
**两种形状不同** ⇒ id 仍可解析、记录已消失 = **老化掉了**,不是「查错了」也不是「没终止过」。
账号级 `terminated,shutting-down` 普查同样返回空(§六),互为独立佐证。

**为什么这不是手慢,是算术**:

| 时刻 | 事件 |
|---|---|
| 09:23:20–09:23:33Z | 四台起飞 |
| 10:15:15–10:22:27Z | 四台最后一次上传 S3(自终就在其后) |
| ~11:15–11:22Z | GH #375 的 ~1h 老化窗**关闭** |
| **12:13Z** | **本收割轮才被 cron 唤醒** |

收割轮比窗口关闭**晚了约 51–58 分钟**。而波次节奏是固定的:
发波轮与收割轮相隔 ~3h,机器自终在起飞后 ~0.9h ⇒ 老化窗在起飞后 **~1.9h** 关闭。
**3h > 1.9h 恒成立** ⇒ 只要机器正常跑完自终,**按需波的 `StateReason.Code` 在当前节奏下永远读不到**。
spot 波没这个问题(SIR 记录活得久,这正是本条从没被看见的原因)。
⚠️ **归因边界**:这条推的是「正常跑完」的情形;一台**跑满 2h 看门狗**才被杀的机器,
老化窗会关在起飞后 ~3h,**可能**赶得上——本轮没有这样的机器,所以这句是推理不是读数。

### (乙) 而闸不会为它举手 —— `reclaim_blind.py` 的按需分支接受任何字符串

本台在 `W60_wave.json` 里把 `status_code` 如实写成一整段 `LOST -- EC2 aged this instance out ...`
的散文(**因为那才是真的**),然后闸 (iv) **照样 `exit 0`**,并把那段散文**原样印在终止码那一列**上:

```
  seed 9911   51.9 min  LOST -- EC2 aged this instance out of describe-instances BEFORE this
                        harvest round could run. ...  ab42 /ba16   PAIRED   [on-demand, depth-checked]
```

跑了**最小对照**(`/tmp/ctrl.json`,两台按需):

```
CTRL_EXIT=0
  seed 1   52.0 min  banana pancakes    ab30 /ba14   PAIRED   [on-demand, depth-checked]
  seed 2   52.0 min                     ab30 /ba14   PAIRED   [on-demand, depth-checked]
```

⇒ **`"banana pancakes"` 通过;`""`(空字符串)也通过**。
源码即原因(`tools/batch_test/soak/reclaim_blind.py:288-302`):按需分支只拒两件事 ——
`code is None`,以及 `code in KNOWN_CODES`(写成 SIR 词汇表算自相矛盾)。
**除此之外一律 `return code`**。spot 分支有 `KNOWN_CODES` 白名单,**按需分支一条都没有**。
`""` 是最锋利的那个形状:**字面上零读数**,却认证成了一个终止码。

### (丙) 两条合起来的形状

(甲) 让这个字段**永远缺**,(乙) 让**永远缺的字段永远过**。
单独看,(甲) 是运维时序问题、(乙) 是校验松一点;合起来是
**按需波的归因子句(clause 2)在结构上不可能出声地失败**。
⭐ 与章程硬知识里 `pullcad`「promote 一个 id 会静默冻死引用它的 gate」**同族**:
门在、被调用、退出码是 0,**只是它守的那个东西已经不在了**。
失效方向照例是危险那侧:**不报错、不缺读数,只是安静地把「没读到」记成「读到了」**。

⚠️ **本轮的 verdict 不靠这个字段**:clause (1) 的 yield = **4 paired ≫ 1**,
按 `reclaim_blind.py` 自己的真值表,**yield > 1 单独就足以判 not blinded**,

否则本报告就成了自己刚点名的那种「用一个洗白过的字段得出的结论」。
