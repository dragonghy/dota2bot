## 四、⭐⭐⭐ 本轮工作单元:台账的 `stamp_kind` 缺陷(GH #847)

### 4.1 立案句:上一轮的测试语料是它自己造的

上一轮把 `recover_verdict.py --ledger` 落了地,并附 `tests/test_verdict_ledger_write.py`
(20 checks,变异台 4/4)。本轮发现那份证据有一个**结构性**的洞:

`tests/test_verdict_ledger_write.py:96` 的 `write_run()` 用
`"mirror:%s:s%s:%s" % (CAND, seed, side)` **造出每一个 stamp**,
而 `recover_verdict.py:617` 用 `^mirror:(.*):s(\d+):(radiant|dire)$` **读回它**
—— **同一个假设既当输入又当判据**。于是「真实语料里 stamp 长什么样」这个问题
**在那份测试里不可能出现**,`m` 为假的那条分支(`cand`/`seed`/`arm_side` 全 `None`)
**一次都没被执行过**。

### 4.2 花 12 个对象买到的事实

从 `soak/spot_20260912_092629_1_main_b920b0/`(W69)按名字序取前 12 个 `.analysis.json`:

| stamp 形状 | 个数 | 逐字 |
|---|---|---|
| 裸 git SHA | **5** | `'52ea2be4'` |
| mirror 串(27 id) | **7** | `'mirror:lf_rescue,…,arbheart:s13052:radiant'` |

- 那 **5 个是暖场局**:它们跑在 `validate_onspot.sh` 写 `soak_side.lua` **之前**,
  **不属于任何一臂**;槽位 1/2/3/4/6,时间戳全在两个 wave 之前。
- 按本 run 56 个对象算,暖场约占 **9%** ⇒ **这个桶从来不是空的**。
- ⭐ 真 27-id mirror 串**能被现有正则读对**(本轮已钉,见 4.4)—— 正则本身没坏。

### 4.3 缺陷的形状:一个永不为空的桶,谁掉进去都不显眼

`recover_verdict.py:606` 的台账块遍历 `sorted(loaded)`,而 `loaded`(:214)收下
**每一个** `*.analysis.json`,**不按 stamp 过滤**(过滤发生在下游评分路径)。
于是暖场局也进台账,带 `cand/seed/arm_side = None` 且 `finished = True`
(实测那个 slot3 暖场局 `winner='dire'` —— 它**是一局打完的局**)。

⛔ **要害不是暖场局进了台账**(进去是诚实的),**是 `None` 有两个互相看不出来的成因**:

1. 暖场局 —— 本来就没有 stamp,`None` 是**正确**的;
2. stamp 形状变了 —— 正则读不出来,`None` 是**故障**的。

两者在行上**逐位相同**。而 (1) 恒占约 9%,⇒ 一次 harness 回归会**落进一个永远有人的桶里**,
读回来像是「这波暖场多了点」。**失效方向是危险那一侧**,与 MTD 对 EC2 的滞后、
与「shallow clone 空输出被读成无漂移」**同族**。

⚠️ 信息其实**在**行里(`script_version` 原样留着),但要区分就得在**读的时候**
再解析一次 stamp —— 那正是上一轮 (乙) 条款明令禁止的**第二份会漂移的拷贝**。

### 4.4 落地(⛔ `bots`/`game` 一行未改)

**(甲) `recover_verdict.py`:每行新带 `stamp_kind`,由**同一次**解析在写入时定出四值**:

| 值 | 含义 |
|---|---|
| `mirror` | 正则读通,在某一臂里 |
| `warmup` | 有 stamp 但不以 `mirror:` 开头(暖场,不属任何一臂) |
| `mirror_unparsed` | **以 `mirror:` 开头却读不出来 ⇒ harness 回归,不是暖场** |
| `absent` | 没有 stamp |

⛔ 不是布尔。**朝吵的那侧失效**:没见过的形状永远不会被静默归进良性那个值。

**(乙) 两行 stderr**:一行 `stamp_kind` 普查;`mirror_unparsed > 0` 时**另起一行 WARNING**
—— ⛔ 不折进普查行,一个要在四个数字里找出来的数就是没人找的数。
verdict JSON 的 `ledger.stamp_kind` 同步带上普查。

**(丙) `tests/test_verdict_ledger_write.py` 新增 case 7**,两个 stamp 字面量
**逐字节抄自真实语料**(⛔ 不是测试自己造的),外加 `mirror:somecand:sABC:radiant`
(形状变了的构造例)与空串。

### 4.5 ⭐⭐⭐ 顺带撞出第三件,比前两件更硬:**`script_version` 对真正要紧的那些局根本不记树**

`append_ledger.py` 的 docstring 把 `script_version` 称作
**`git describe of the code the game RAN — the key field`**。本轮的取样说明它**两头都不成立**:

   对唯一参与评分的那些局,回答的不是「跑的是哪棵树」。**
2. **对暖场局(`warmup`),它确实是个 SHA —— 而 W69 那个 SHA 不在 main 上。**

第 2 条是 `claim_precheck.sh` **替本台撞出来的**(它把引文里的 `52ea2be4` 当成 git 引用去解析,

⛔⛔ **本台到此为止,不下结论。** 这条正对着 `AGENTS.md` 那条用真金白银买来的教训

⛔ **两者本台都证不了**,⇒ ⛔ **不写进任何结论、不据此否定 W69 的任何读数**。

### 10.3 归因:⛔ 不是 trunk 红,⛔ 不是本轮改动 —— 是**本台把自检放后台又同时 push**

### 10.4 ⭐⭐ 为什么这不只是本台的操作失误(交棒 ①)
