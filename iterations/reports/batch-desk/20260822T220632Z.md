## 6. ⭐ 本轮的真发现:预置的 `--rec-slots 16` 升级,**验收侧结构性不可能**

20:09Z 按 §AL/§AN 的事先登记写下:「8 槽验收 `rec_slot_cost.py` **真 exit 0 = 通过**
⇒ **下一波上 `--rec-slots 16`**;16 槽没有波内对照腿 ⇒ **收割时必须把本波并进 `--baseline`**」。
**这条升级路径走不通,而且不是语料问题,是工具的设计。** 三条独立证据:

1. **`rec_slot_cost.py:218-220` 是一条无条件拒答**:
   ```python
   if not ctrl_slots:
       die('every slot recorded: no control leg exists in this corpus',
           'control slots=0 of %d' % len(prof))
   ```
   16-of-16 的波次 `ctrl_slots == []` **按构造成立** ⇒ **exit 2**。
   工具自己的 header 把它列为五条**永久 REFUSALS** 之一:
   *"every slot recorded: there is no control leg, so nothing can be certified"*。
2. **这条 die 在 `--baseline` 那一段之前**(baseline 逻辑在 ~260 行起)⇒
   **「把上一波并进 `--baseline`」根本到不了比较那一步**;拒答针对的是**新语料**没有对照腿,
   不是参照系不够好。
3. **就算绕过 (1),box factor 那一腿也是空的**:
   `box = [ratios[s] for s in ratios if s not in rec_set]` 在 16 槽下必空 ⇒
   `die('no control slot overlaps the baseline: the box factor is unknowable')`。
   **两条独立拒答,不是一条。**

**⇒ 12:12Z 那次 `--rec-slots 16` 的 exit 2,现在有解释了,而且它会原样复发。**
20:09Z 把那次 exit 2 读成「语料答不了」;实际是**这个配置永远答不了**,
因为「16 槽全录」和「验收需要同波对照腿」是互斥的。

**顺带一处口径更正**:20:09Z 写的「工具收多个 run 目录」对 `--baseline` **不成立** ——
`--baseline` 收的是**一个 JSON profile 路径**;收多个 run 目录的是位置参数 `runs` 和 `--emit-baseline`。
真正的合并路径是 `--emit-baseline` 先产 JSON 再喂 `--baseline`;
但那份 JSON 的 slot 1-8 **本身就是录制槽**,不是干净的 REC_SLOTS=1 剖面 ⇒ 即便流程跑通也不该那么用。
