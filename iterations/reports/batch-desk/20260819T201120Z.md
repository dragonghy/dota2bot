## 2. 一个必须记下来的坑:**`origin/main` 的本地 remote-tracking ref 是陈的**

章程步骤 5 的核树动作(`git ls-remote origin main`)**照做了并且救了这一轮**:

| 来源 | 值 |
|---|---|
| `git ls-remote origin main`(直接问远端) | `b2ea1e6` ✅ 真值 |
| 本地 `git log origin/main`(未 fetch) | `46d381d`(2026-08-18 23:17Z)❌ **落后 43 个 commit** |

如果只用本地 `origin/main` 做「臂 A 那棵树到现在有没有漂移」的判断,会算出一个
**完全虚假的巨大 diff**(645 行删除,横跨 9 个 `bots/` 文件)—— 那不是真的漂移,
是拿今天的树去和昨天的 remote-tracking ref 比。**教训:核树必须
`git fetch origin main` 之后再比,或者一律用 `git ls-remote` 的值;
`git log <sha>..origin/main` 在没 fetch 的会话里是不可信的。**

附带发现:`git fetch origin claude/cool-hopper-d4270m` 报
`fatal: couldn't find remote ref` —— 本 stream 的分支在远端已不存在(工作都直推
main 了),而 `git fetch` 是原子的,**这个失败会让同一条命令里的 `main` 也不更新**。
本轮就是这样先吃了一次静默的 no-op fetch。
