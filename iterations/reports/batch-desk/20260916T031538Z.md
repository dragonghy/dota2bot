### 4.4 ⭐⭐⭐ 分不开的原因是结构性的:**记录这件事的那条日志,在正常跑完的波上从不上传**

`spot_run.sh:246` `exec > /var/log/soak_farm.log 2>&1` + `set -x`
⇒ **§4.3 那四行 git(含 `git log --oneline -1` 打出的「实例最终在哪棵树上」)确实被记下来了**,记在 `/var/log/soak_farm.log`。

而这个文件在整个 `spot_run.sh` 里**只有一个上传点**:

```

```

**它在 `spot_watch.sh` 的「收到 spot 抢占通知」分支里面。**
⇒ **只有被抢占的波才会上传这条日志;正常跑完自终的波,它随实例一起消失。**

**真语料复核(⛔ 不只读代码)** —— W69 的一个正常完成 run 目录:


⇒ **120 个对象里没有 `soak_farm.log`。实测与代码一致。**

**这就是交棒 ⑥ 的答案**:(甲)/(乙)(以及新的 (丙))**不是本台没去取那个对象,
是能把它们分开的那个对象从来没被上传过**。

### 4.5 ⭐⭐ 顺带撞出的那条缺陷,比 W69 本身重要得多

把 §4.3 的 `|| true` 和 §4.4 的「不上传」放在一起:

1. `git fetch` / `checkout` / `pull` **三行全是 `|| true`** ⇒ 任一行失败**静默**,
   实例就停在 **AMI 那棵 07-18 的树**上继续跑整波。
2. 唯一能事后看出这件事的记录(`git log --oneline -1`)只进 `/var/log/soak_farm.log`。

4. verdict / `analysis.json` 一切正常,**没有任何东西会举手**。

📌 **这正对着 `AGENTS.md` 里那条用真金白银买来的教训**
(「Batch instances clone `origin/main` at launch — verify the remote tip **BEFORE** launching」):
那条教训教的是**发波前**核 `git ls-remote origin main`,而它核的是**远端**,
