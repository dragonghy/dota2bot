## 附录 A:§四 普查的复现配方(⛔ 有意不落进 `tools/`)

⛔ **没有把它写成 `tools/` 下的脚本**,理由是结构性的:`py_gate.py` 的覆盖普查本轮实读
`UNCOVERED 0 of 149 (0%)`(见 §〇 的分腿),**一个新的 `.py` 会顶红下一个开工的组**
(README 铁律 6 里 GH #624 逐字点名的那种失效)。**一次性读数不值这个代价**;
配方本身四行,任何一轮可以照抄重建:

```bash
# 1. 列桶(零下载)
awsx s3 ls s3://dota2bot-batch-results-4924/soak/ --recursive > /tmp/soak.txt
grep analysis.json /tmp/soak.txt | awk '{print $4}' | sort > /tmp/all_keys.txt
# 2. 按 run 分层取首/中/末 3 局 -> /tmp/sample_keys.txt
#    (run = key 的第 2 段;len<=3 全取,否则 ks[0], ks[n//2], ks[-1])
# 3. 并行取(单流 0.35 obj/s -> -P 24 实测 4.2 obj/s)
xargs -a /tmp/sample_keys.txt -P 24 -n 1 /tmp/fetch1.sh    # fetch1.sh = 一行 awsx s3 cp
# 4. 逐局取 winner / winner_by / natural_end / script_version / duration_s,按 gdate 分桶
```

⚠️ **`winner_by` 必须和 `winner` 一起读** —— §4.2/§4.3 的全部内容就是这一句:
**只读 `winner` 的普查会把 08-26 那条线读成一次退化。**
