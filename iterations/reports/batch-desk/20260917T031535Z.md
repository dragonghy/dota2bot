## 三、⭐⭐⭐ 实质工作单元:交棒 ⑦(k) —— `rule6_memo` 为什么不 replay,答案在代码里

⛔ **先划清楚这是什么**:这是**读代码得到的机制**,不是一次实验。
本轮**没有**跑一次带钩子的孪生 push 去计时(那要 ~12min 且上一轮实测不返回),
⇒ 下面 (丙) 是**本轮现取的输入读数**,(甲)(乙) 是**源码逐字**,
⛔ 两者都不构成「第二推真的跑了全集」的计时证据。

### (甲) memo 的键里有 `origin/main`,而 `HEAD:main` 先推会移动它

`tools/agent/rule6_memo.py:150-157` 逐字(键的第三个输入):

```python
    rc, base = _git("rev-parse", "origin/main")
    if rc != 0 or not base.strip():
        # The Lua leg's scope is computed against origin/main. Without it we
        # cannot say two runs asked the same question.
        return None, "cannot resolve origin/main"
```

`memo_key()` 逐字 `raw = "rule6-memo-v1\ntree=%s\nbase=%s\n"` ⇒ **键 = (HEAD^{tree}, origin/main)**。

`git push` 成功后 git **更新本地的远程跟踪引用** `origin/main`。⇒ 在
**「先 `HEAD:main`,后分支」**这个顺序下:

| | 第一推(`HEAD:main`) | 第二推(分支) |
|---|---|---|
| 钩子跑时的 `base` | **旧** `origin/main`(钩子在 ref 更新**之前**跑) | **新** `origin/main`(= 刚推上去的 commit) |
| memo 键 | `key(tree, 旧base)` ← **存**在这里 | `key(tree, 新base)` ← **在这里找** |
| 结果 | 存了 | **MISS,恒定 MISS** |

⇒ ⭐ **这不是概率事件,是恒等式**:只要第一推改的是 `main`,第二推的键就必然
换了一个输入,⇒ **它永远命不中第一推刚存的那条**。

### (乙) 同一个移动**也**打掉 Lua 腿的 scope,而空 scope 按设计 = 跑全集

`.githooks/pre-push:215` 逐字:

```sh
changed=$(git diff --name-only origin/main...HEAD 2>/dev/null) || changed=""
```

同一段的设计说明逐字(`pre-push:210-214`):

```
# `git diff --name-only <base>..HEAD` against the remote's main; ANY failure or
# empty answer leaves `changed` empty, and lua_gate.py's --if-touched treats an
# empty list as RUN EVERYTHING.  The fail-open direction is the one that has
# cost this repo real reds, so it is not available here: skipping needs a
# positive answer, never the absence of one.
```

⇒ main 先落地之后,`origin/main` **就是** HEAD ⇒ 该 diff **恒为空** ⇒
第二推的 Lua 腿**跑全集**。
⭐⭐ **这一条本身是对的、也不该改**(fail-closed 是它立案的理由);
⛔ 它只是在**这个顺序下**被喂了一个**假的空**:空的原因不是「这一推没碰 Lua」,
而是「参照物刚被这一推的孪生兄弟推成了自己」。

git rev-parse origin/main               ->  0eb03ee6...   (开工时)
git rev-parse HEAD                      ->  7d4d9a95...   (开工时)

### (丁) ⭐⭐ 判词:这不是 `rule6_memo` 的缺陷,是两条规矩对撞

`rule6_memo.py` 自己的头注**逐字引用的是文档顺序**:

```
    git push -u origin <branch> && git push origin HEAD:main
```

在**那个**顺序下:第一推(分支)**不移动** `origin/main` ⇒ 第二推(main)的键
与第一推**逐位相同** ⇒ **HIT**,三行 replay,scope 也仍是真实改动集。
⇒ **memo 在它被设计针对的那个顺序下是工作的。**

打掉它的是交棒 ⑦(i) 的**反序**(先 main 后分支),而那个反序**另有立法理由**
(GH #290:引用必须先在 `origin/main` 上可解析,再发表)。

⇒ ⭐ **两条规矩各自都对,合起来产生第三种行为**:
第二推既拿不到 memo(甲),又被喂了假空 scope(乙),⇒ **它比第一推更贵**,
而它测的是**同一棵树**。这正是 `rule6_memo.py` 头注说它要消灭的那件事
(「the second push ... is exactly the run this file removes」)。

⛔ **本台不代修**:这三处(memo 键、hook scope、⑦(i) 顺序)分属钩子与流程规矩,
写入权在总监。本台只交出机制 + 现读的输入(见 §九 / 补记 (C) 已发表的评论)。
⭐ 供裁的三条**互斥**候选,按对 fail-closed 的破坏从小到大:
1. **只改顺序**:回到文档顺序(分支先、main 后),GH #290 的引用要求改由
   `claim_precheck.sh` 保障(它本来就按 `origin/main` 解析)。**零代码改动。**
2. **键里换参照物**:memo 键的 `base` 改用**钩子自己算 scope 用的那个 diff 的哈希**
   而不是 `origin/main` 的 sha ——「同一个问题」由**问题本身**定义,不由参照物的名字定义。
   ⚠️ 这条会让「main 移动但改动集不变」也命中,**是否可接受本台不裁**。
3. **什么都不改,把代价写明**:⑦(i) 的第二推恒定用 `--no-verify` 并逐轮声明
   「这一推不携带任何闸主张」。**这是现状**,代价是**每轮一条无主张的推**。
