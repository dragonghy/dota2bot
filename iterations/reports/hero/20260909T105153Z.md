## 4. ⭐ 那条不是计数的判读:hero-10 的 n=1 → n=2,以及一个代理被退休

这枚帧带**全树第二个** 12 级以上、**活着**的 Wraith King:
`npc_dota_hero_skeleton_king`,**20 级**,`alive = true`,`hp 2142 / max_hp 2575`,
**`mp 556 / max_mp 735`**。

**两个读数,只有第一个是计数:**

- **(甲) 池**:735 与 26 级那位的 855 一样在出货 600 绝对下界**之上**。两个活体后期位,两个池过 600。
- **(乙) ⭐ 当前蓝量 —— 这才是 hero-10 问题 (2) 问的量,而本树此前答不了:556 < 600。**
  上一位活体在 `mp == max_mp`(满条),**结构上只能演示下界被越过,演示不了下界卡人**。
  这一位在池的 **75.6%** 上,出货那条绝对 600 **拒绝**它 —— 而同一帧上地狱火爆轰是 rank 3、
  **耗蓝 125**,英雄身上带着 **556**,是成本的 **4.5 倍**。
  hero-10 `question` 里那句「600 绝对下界 = 交叉池 603 的 **99.5%**,而法术只要 95/110/125/140」
  **第一次有了实例**。

**⚠️ 1 / 2 仍然不是率,`status` 不动,我没动 director 裁定 / 路由 / 优先级 / 状态。**
两局两帧不构成本条要的归档 timeline 分布。**变的是可读性不是结论**:本轮之前,
一个零和一个一**分不出**「下界真的不卡人」与「我们只冻过满蓝的 Wraith King」;
现在两个方向各有见证,未来那次扫描的读数才读得动。

**⭐ 顺带退休一个代理(与 GH #357 row 3 同族,同一个「代理零冒充承重零」的形状):**
2026-09-07 那块把 `hp == max_hp` 当成「池可引用 vs 被标记」的分界。**它不是。**
分界是 `alive == true` 且容量字段**非零**;`hp == max_hp` 是 n=1 那个样本的偶然(那位恰好满血)。
本位活着、**83.2% 血**、`max_hp = 2575` 与 `max_mp = 735` 都没被归零。
⇒ 断言改成对**每个**活体行取 `max_hp > 0`,并且**不再取 `live[1]`** ——
两行之后那是顺序相关的选择子,**正是本文件已经付过一次的那个缺陷**(它自己的注释:
「Partitioned, not last-wins」)。

读数写在断言里不是散文里:`test_wk_level_supply_horizon.lua` §2(全树 4→5)、
§6(staged ≥13 为 4;≥13 分区 **2 死 / 2 活**;「几个活体当前蓝量 ≥ 600」= **1,分母 2**,
