## 一、头条:哨兵被拼成了一个伤害值,而且拼在这个量自己值域的**地板上**

```lua
local npcMostDangerousEnemy = nil
local nMostDangerousDamage = 0
...
    if ( npcEnemyDamage > nMostDangerousDamage ) then ... end
```

`GetEstimatedDamageToTarget` 永不返回负数 ⇒ 种子 `0` **不是「低于定义域」,它是定义域
的第一个合法值**。一个投射恰为 0 的合法候选**永远过不了严格 `>`**。

后果**不是排序错了,是否决**:当所有合法候选都读 0 时,`npcMostDangerousEnemy` 停在
nil,**整条团战腿返回空** —— Lion 在团战里攥着一个硬控,而射程内站着可施法的敌人。
从函数外面看,这与「本来就没有候选」**不可区分**。

### ⭐⭐ 而 0 是常态,不是特例

那块表是**回溯的**:它只对「**实打实打到过本体身上的伤害**」答 ground truth
(准确说法树里本来就有,`tests/test_chasering_target_in_ring.lua:48`;另外四处写
「answers 0 on every fixture frame」的散文是错的,GH #873)。

⇒ 对**还没打到本体**的敌人读 0,而那在团战里**正是每一个正在打别人的敌人的常态**。
⇒ **这颗种子咬得最狠的,恰好是一个辅助最想 Hex 的那些人。**

修法:`X.nWFightArgmaxSeedShipped = 0`(出货字面量,唯一一处)+ gated helper
`X.lion_FightArgmaxSeed()`,armed 返回 **-1**(严格低于地板)。
⛔ **行为差正好只有「全零」那一种情况**:只要有任一候选投射为正,0 在 `>` 下永远赢不了
它,胜者与出货**逐位相同**(§5.4 把这两半都驱动了)。
