## 2. 缺陷

`bots/BotLib/hero_crystal_maiden.lua`,`X.ConsiderR` 分支 1(出货):

```lua
if ( #nEnemysHeroesInRange >= 3 or aoeCanHurtCount >= 2 )
```

`aoeCanHurtCount` 是同一个函数**往上六行**自己算出来的量:一个敌人被数进去,当且仅当他
**被控住**,或者近到 `nRadius * 0.82 - GetCurrentMovementSpeed()` 还够得着他 —— 也就是
**走不掉**。右边那条析取项读它;左边那条读**同一张表**,但把这个测试整条丢掉。
而且 `or` 从左往右求值 ⇒ **三个人头一到,质量测试连算都不算**。

**这与本流之前六条到达项(`lionrreach` #617 / `wkqlane` #621 / `cmlaneband` #630 /
`zusjumpland` #634 / `lionqkill` #640 / `axebhreach` #643)不同族**,承重的区别写清楚:
那六条错在**选靶列表比技能射程宽**(收错了搜索集);这一条的列表是对的(就是场里那三个人),
错的是**释放判据比它自己隔六行算出来的判据松**。

## 3. 修法(gated,turbo-only,未 armed)

* 新常量 `X.nRCrowdHurtFloor = 1`;
* 新 helper `X.cm_IsFieldCrowdReleaseOk( nAoeCanHurtCount )` —— 闸关时对任何输入返回
  `true`,逐字是出货谓词;
* 调用点:人头那条析取项末尾加一条合取。`aoeCanHurtCount >= 2` 那条**逐字不动**,
  所以一对真被钉住的敌人照样能在没有队友的情况下释放大招。

armed 时人头那条路额外要求 `aoeCanHurtCount >= 1` —— **一个**走不掉的敌人,不是两个。

**方向由形状保证(cullthresh 的教训)**:armed 谓词 = 出货谓词 ∧(只加在其中一个析取项上的
一条合取)⇒ 对每一个 (人头数, hurt 数) 格子,armed 释放集 ⊂ 出货释放集。**只能删除释放,
永远不能新增一次。** 负读数只能读作「被扣下的那几次开大是值得开的」。
⭐ 只断言「子集」是不够的 —— 一个恒 `false` 的变异体也是子集,所以 §3.2 **同时断言被删掉的
格子集合恰好是 `3:0 4:0 5:0`**。

### 条件 (c),论证而不是假设

`crystal_maiden_freezing_field` 是 `AbilityChannelTime 10` + `AbilityCooldown 100/95/90`
(KV,镜像在 `tests/mock/special_value_shapes.lua`):放它等于把 CM 变成一个**站着不动、
可被沉默**的目标十秒,而它的伤害是在这十秒里按 0.1s 一跳付出来的,**不是落地一次性结算**。
标准打法因此是对**已经被留住**的敌人开(被控住,或深到走不出去);这一点**这个文件自己已经
写下来了** —— 人头那条路是例外,不是规则。三个能走的敌人在 300 移速下 ~1.5s 就能穿出 735u
半径,所以这种帧上的出价换到的是几跳伤害,代价是一条 90–100s 冷却的技能,在 Turbo
(全局 ~20 分钟)里。

1. **`GetAOERadius` 不是 loader 供的七个 getter 之一**,离线答 **0**;本轮所有距离读数都骑在

   最近的敌人要到 movespeed **56.5** 以下才会被数进 hurt,英雄移速永远不会那么低(§6.2 把这个
   余量算出来并断言 < 60)。**但别的帧的 hurt 数不能继承这份稳健性** —— 一帧的最近敌人若落在
   `[nRadius*0.82 − ms, nRadius*0.82]` 这条带里,它的 hurt 数是 mock 定的不是游戏定的。
3. **1 帧不是频率。** 10 个 CM fixture 里 1 个带这个形状,那是**域**;每局出现几次要一波
   (`iterations/queue.json` `hero-52`,本轮登记)。

   **只被分支 2 读**;钉帧上 1200u 内 0 个队友这一条是**记录下来解释这帧读起来像什么**,
   **不是**这条 lever 测的东西。「单人该不该对着一群人开大」是另一个问题、另一个 id。
