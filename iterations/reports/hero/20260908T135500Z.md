## 0. 一句话

**这不是又一个「环太宽」——这是一个大小正确、圆心错误的环。**
`X.ConsiderE` 的「进攻」落单点用 `J.IsInRange( bot, targetHero, nCastRange )` 批准一次
Heavenly Jump,而 `nCastRange` **是落地冲击波的搜索半径,不是施法距离**(函数自己的注释就
是这么写的)。跳跃是**无目标位移**:英雄沿自己的朝向跳 `hop_distance`,冲击波从**落点**搜。
于是这个落单点在**起跳点**量一个从**落点**量的量。gated `zusjumpland` 把量的位置搬到落点。

## 2. 缺陷

`bots/BotLib/hero_zuus.lua` `X.ConsiderE` 只有**两个**落单点:

```
撤退   J.IsRunning + tableNearbyEnemyHeroes[1]
       + not bot:IsFacingLocation( targetHero:GetLocation(), 120 )     <- 唯一的朝向项
进攻   J.IsGoingOnSomeone + J.GetProperTarget
       + J.IsInRange( bot, targetHero, nCastRange )                    <- 本轮的落单点
```

Heavenly Jump 的形状(KV,`tests/mock/special_value_shapes.lua`):

| 键 | 值 | 是什么 |
|---|---|---|
| `hop_distance` | 375 / 450 / 525 / 600 | 沿**自己朝向**跳多远 |
| `range` | 700 / 800 / 900 / 1000 | 落地冲击波从**落点**搜多远 |
| `duration` / `move_slow` | 1.4s / 80% | 打中的回报 |

`X.ConsiderE` 里的 `nCastRange = 600 + nSkillLV * 100` **就是 `range` 阶梯**,函数自己的
注释写着「the radius the landing shockwave searches, NOT a cast range」。⇒ 进攻落单点用
**起跳点**到目标的距离,去判断一个从**落点**量的半径。两点最多差 `hop_distance`:rank 1 是
**375 / 700,超过半径的一半**。

⭐ **承重的不是算术,是那条不对称**:撤退落单点是本文件里**唯一**推理朝向的地方,而它推理
朝向正因为方向就是它买的东西(往外跳)。所以这个函数**已经知道**跳跃有方向。缺这一项的,
恰恰是那个**回报由方向决定**的落单点。

⭐⭐ **与 `lionrreach`(#617)/`wkqlane`(#621)/`cmlaneband`(#630)同族但不是同一个缺陷。**
那三个是环**太宽** —— 错在一个方向,修法是收窄。这一个的环**大小是对的**,错的是**圆心**,
而且它**两个方向都错**:真实帧上 360 个朝向里约一半打得中、一半打不中,而出货那一项对这
360 个**给同一个答案**。

## 4. 改动

`bots/BotLib/hero_zuus.lua`,新 helper + 一个落单点改一行:

```lua
function X.zuus_IsJumpTargetInShockwaveReach( hBot, hTarget, hAbility, nSearchRadius )
	if not J.IsInRange( hBot, hTarget, nSearchRadius ) then return false end
	if J.IsModeTurbo() and J.IsSoakCandidate( 'zusjumpland' )
	then
		local nHop = hAbility:GetSpecialValueInt( 'hop_distance' )
		if type( nHop ) ~= 'number' or nHop < 0 then nHop = 0 end
		local vLanding = J.GetFaceTowardDistanceLocation( hBot, nHop )
		return GetUnitToLocationDistance( hTarget, vLanding ) <= nSearchRadius
	end
	return true
end
```

四件事值得单独说:

1. **`J.GetFaceTowardDistanceLocation` 是树里已有的 helper**(`jmz_func.lua:2937`),不是
   本轮发明的几何。
2. **`nHop` 是读出来的,不是再抄一条阶梯。** 文件里已经有一条手抄的 `range` 阶梯;再抄一条
   就是第二处会各自漂移的常数。
3. **先求出货谓词** ⇒ armed 只能把 true 变 false,**严格子集,由形状保证**。⭐ 这也是
   `J.IsInRange` 自己那条 `CanBeSeen()` 前提留在**两条腿**上的原因 —— 在 helper 里重算
   距离会把它悄悄丢掉,armed 就不再是子集。
4. **`nHop == 0` 时落点塌回本体**,armed 与出货逐字等价 ⇒ handle 绑错(`zusbind` 的世界)
   时本 id **自动站下**,不需要第二条分支,也就没有一条测不到的分支。

⚠️ **与 `cmlaneband` 的一处诚实差别**:那条出货答案是无条件 `true`,所以「变宽」变异体
**不可表达**。本 id 的出货答案是个真谓词,**所以变宽是可表达的** —— 变异台 **M4** 就是它。

   与 GH #611(出向伤害恒 0)、#613(三条析取里两条恒假)同族,也与本组**上一轮**的
   `GetCurrentMovementSpeed = 300` 同族。
   ⇒ 本文件**没有任何一个数**是「armed 在真实对局里多久拒一次」。§1 数**几何**(不需要
   朝向),§3 把朝向当**注入参数**扫(用例名里就写着 `[injected facing]`),§4 注入一个
   朝向并**断言注入生效**。
2. **§1 是分支域的上界,不是分支域。** `GetActiveMode` 不在任何 .dem 里 ⇒
   `J.IsGoingOnSomeone` 在整份语料上恒假,分支自己一次都不会开。
3. **登记未修:撤退落单点。** 故意不碰 —— 它买的是位移本身,且它已带着本文件唯一的朝向项。

4. **登记未修:`nCastRange = 600 + nSkillLV * 100` 是 KV `range` 键的手抄阶梯。** §2 证明

   (手抄阶梯正是 handle 绑错时函数还能工作的原因)。谁做谁退役这条限度。

## 7. 本轮最值得带走的三条

1. ⭐⭐⭐ **一条前置断言的措辞可以吃掉整个诊断。** M10(pullcad 陷阱)第一版被记成
   「**红但消息不对**」—— 不是因为断言没抓住,而是因为 §5 那条 standalone 用例的**第一条
   前置断言**写的是无信息的 `'the stand is not set up'`,而在合取闸下它**恰好是第一条会
   失败的断言**。把那句话改写成它自己的判据(「`zusjumpland` 单独 armed 不开火 ⇒ 它被
   合取了 ⇒ pullcad 陷阱」)之后才变 caught,10/10。**教训:前置断言不是脚手架,它是这个
   用例在最常见的失败路径上说的第一句话。**
2. ⭐⭐ **两把量具在同一轮里、朝同一个方向、都答「什么也没发生」,而且都不抛异常。**
   `GetFacing` 的兜底 0(限度 1),以及本文件初稿在 `rf.record_actions` 上**读错了参数下标**
   (日志不含 `self`,技能是 `args[1]`;初稿读 `args[2]`,于是在一个**确实下了施法单**的帧上
   报告「没有施法」)。两个都不会变红。这就是 §4 为什么**断言每一条注入生效**,而不是从结果
   反推 —— 结果长得跟「杠杆没接上」一模一样。
3. ⭐ **一次自己检查掉的错误方向。** 本轮第一个候选缺陷是 `X.ConsiderD`(Nimbus):它遍历
   队友、用**队友到队友目标**的距离(1200)批准一次 Zeus 自己的施法,而 Zeus 到落点的距离
   一次都没量 —— 看起来是同一族的「量错了一对单位」。**查 KV 之后作废**:`zuus_cloud` 的
   `AbilityCastRange` 是 **0**,而 `tests/test_wk_q_castrange_meter_domain.lua:110-113`
   已经写明「Nimbus 的真实答案就是 0」(全球施法)。**无界到达在那里是设计,不是缺陷。**
   写进报告是因为下一个读到 `X.ConsiderD` 的人会看到同样的形状。
