## 2. ⭐ 结论:立案句预设了一个答案,而现实给了五个

`-75` 把九个 `local nManaCost = ability:GetManaCost()` 记成一类(CM 2 / Zeus 4 / Axe 1 / Lion 2),
并预判接线的下游是 `J.IsAllowedToSpam` 与 `J.GetManaAfter( c ) > 0.3`。**分类是对的,归并是错的。**

**先是那条把「显然的读法」摁死的事实:九个**全部**坐在自己函数的 `IsFullyCastable()`
早退之下。** 引擎的 `IsFullyCastable` 已经是「不在冷却 **且** 学过 **且** 蓝 ≥ 价」——
⇒ **付不付得起这件事在上游就答完了**,这个绑定**从来不是**它名字暗示的那次「我付得起吗」。

而树里那两个活的惯用法问的是**另一个**问题 —— 付完之后**还剩多少**(储备):

```
J.GetManaAfter( cost ) > 0.3        -- (mana - cost)/maxmana
J.IsAllowedToSpam( bot, cost )      -- 同一个比率 vs fKeepManaPercent
```

⇒ 「把死绑定接到活惯用法上」**不是修一次漏读**,是**给一个本来没有储备的决策加一道逐次施法的储备**。
该不该加**完全取决于站点**,而站点分成五类,**每一类的判别式都是源码里量得到的东西**:

| 类 | 站点 | 判别式(可量) | 处置 |
|---|---|---|---|
| **甲 已有一个竞争的储备** | CM `X.ConsiderQImpl`、CM `X.ConsiderW`、Zeus `X.ConsiderW2` | 函数内 `bot:GetMana() > nKeepMana`(CM ×3 / ×3、Zeus ×2) | 接线**不是填空**,是在既有储备上**再叠一道**。两道储备是设计题,不是清理 |
| **乙 储备在,但被闸冻死** | Zeus `X.ConsiderW` | 唯一储备是 `J.ShouldConserveManaInLane`,而它第一句是 `if not J.IsLaneFixOn('mana') then return false end` | **出货 trunk 上恒 false ⇒ 这个函数其实没有储备**;而它的 armed 域正是 **`lanefix`,终局门拒过两次** |
| **丙 它是大招** | Zeus `X.ConsiderR`、Axe `X.ConsiderR` | 接收者是 `abilityR` | 为了给小技能留蓝而扣住大招 = **储备指反了**。Zeus 那根指对方向的杠杆本来就在:`X.zuus_ShouldSaveManaForUlt`(焦点五里少数**活**的 `GetManaCost` 绑定之一) |
| **丁 这个技能是回蓝的** | Lion `X.ConsiderE` | 函数读 `mana_per_second`(Mana Drain) | `GetManaAfter(cost) > 0.3` 会**恰好在蓝低的时候拒绝去吸蓝** —— **符号相反** |
| **戊 什么都没有** | Lion `X.ConsiderW`(Hex)、Zeus `X.ConsiderE`(Heavenly Jump) | 无任何储备谓词、非大招、不回蓝 | **九个里只有这两个**,死绑定点名的空缺与活惯用法指的是**同一个方向** |

**⇒ `-75` 的交付是一次收窄:九个站点,最多两根杠杆,而这两根离落地还差一个
gated turbo 候选 + 一帧真帧(`-75` 自己的纪律)。** 把另外七个一起接了,就是七处各自可辩护
的改动一起落地 —— **`lanefix` 的形状,而那个 bundle 被拒了两次**(AGENTS.md)。

同 `-93` 的「残量不是队列」、`-85` 的「46 笔不是 46 笔杂账」:**看着像一条待办的九分之九,
它是五个不同的处置。**

## 3. 域价钱(树规模,量出来的不是估的)

## 4. 为什么是登记而不是清零

`-85` 把焦点五的未读**数字字面量**删干净了,理由是那些是**假前提**(Zeus 大招那个从不存在的
1600 施法距离)。**这九个不是假前提**:每一个都持有一个**真**的价钱,只是没人读。
删掉它们会抹掉「此处缺一道储备策略」的**唯一标记** ⇒ **留着,改成登记**。
树规模那半只上单调棘轮(`<=`,**不是 `==`** —— GH #457 刚修过那个形状)。
