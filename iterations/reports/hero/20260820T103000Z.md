## 结论先说

**#50 §2 把这一处记成了「有活调用点的 nil 崩溃」。它不是,而且从来不是。**
那条分支**结构性不可达**,`J.Unit` 这个 nil 引用一次都没被求值过。

修还是要修 —— 但修的是**引信**,不是崩溃。

## 1. 为什么不可达

```lua
-- bots/BotLib/hero_invoker.lua  X.ConsiderCmToTarget
if (J.IsValidHero(target)
    or (J.IsValidTarget(target) and (J.Unit.IsUnitWithName(target, "roshan")
                                  or J.Unit.IsUnitWithName(target, "boss"))))
```

```lua
-- bots/FunLib/jmz_func.lua:2992 / 2997
function J.IsValidTarget(nTarget)
	-- NOTE: return J.Utils.IsValidUnit(nTarget) -- ideally it should be IsValidUnit, ...
	return J.Utils.IsValidHero(nTarget)
end
function J.IsValidHero( nTarget )
	return J.Utils.IsValidHero(nTarget)
end
```

两者是**同一个 delegate**(`IsValidHero = IsValidUnit && IsHero()`,纯函数,同帧同参必同答)。
于是闸门是 `A or (A and X)`,**就是 `A`**:Lua 只在 A 为假时求值 `or` 的右边,
而那时 `and` 又在**同一个假 A** 上短路 ⇒ `J.Unit` 永远不被索引。
英雄走左支;非英雄两个合取项全假。**没有第三类目标。**

**从另一头独立成立的第二个理由**:两个调用点都只可能递英雄 ——
`hero_invoker.lua:1246` 遍历 `GetUnitList(UNIT_LIST_ENEMY_HEROES)`,
`:1259` 用 `J.IsValidTarget(botTarget)` 把门(而它就是 `IsValidHero`)。

## 3. 那还改它干什么

因为 `jmz_func.lua:2992` **自己的 NOTE**(「ideally it should be `IsValidUnit`」)
是**一条一行就能点燃这条分支的引信**。点燃那天它会以**抛异常**的形式活过来,
而按 #50 §2 自己的账:没有任何地方 `pcall` 包 `X.SkillsComplement`
(`ability_item_usage_generic.lua:8520` 裸调),⇒ 吞掉 Invoker 当帧**整个技能层**,
且在游戏里**看不见**(`print` 不到控制台,引擎错误处理器把文本吞掉)。

所以本轮的改动是:`J.Unit.` → `J.Utils.`,**加上把上面这套推理写进消费点头注释**,
免得下一个人靠**放宽闸门**来「修」它 —— 那才是真的会出事的改法。

修完之后这个引用还是**前向正确**的:#51 落地后 `IsUnitWithName` 是真的子串判定,
不再是那个恒真的表包装。这一点在「谓词被人为改成不一致」的世界里单独钉了(§4)。

## 4. 局部验证

`tests/test_invoker_cm_target_guard.lua`,**11 例**:

- **ground truth**:帧身份、10 个英雄;
- **谓词同一性**:10 个真实单位 + 3 个非英雄类,`J.IsValidTarget(u) == J.IsValidHero(u)`
  —— 整个证明就压在这一条上,所以它用真实单位断言,不从源码读;
- **源码 tripwire**:两个谓词仍然 delegate 到 `J.Utils.IsValidHero`,
  **失败信息直接告诉下一个人**:这一条红了意味着 invoker 那条分支**刚刚活了**,需要一个真正的行为决定;
- **行为式不可达性**:计数器 == 0(§2);
- **非空绿**:同一次驱动里 pudge / shadow_shaman 的 HIGH、juggernaut 的 NONE;
- **意图未实现**:合成肉山/百解 ⇒ 出价 NONE;
- **旧写法从不 raise**:在真实帧上重建**修改前**的表达式(`J.Unit` 保持 nil),逐个 `pcall`,全过;
- **正向对照(关键)**:把 `J.IsValidTarget` 人为改成恒真(**正是那条 NOTE 造成的世界**),
  于是**旧写法当场 raise `attempt to index field 'Unit'`,新写法不 raise 且答 true**
  —— 没有这一条,「它从来没崩过」也可能只是复现写错了;
- **`#51` 跨层 tripwire**:在那个世界里 `roshan`→true、`miniboss`→true(含 "boss")、
  两种小兵→false;`IsUnitWithName` 一旦退回恒真,小兵那两例立刻翻;
- **闸门形状 tripwire**:那一行必须还是 `IsValidHero(target) or (IsValidTarget(target) and ...)`
  且两处都读 `J.Utils.IsUnitWithName`,全树不许再有 `J.Unit.`;
- **调用点 tripwire**:两个调用点的形状 + `X.ConsiderCmToTarget(` 全文**恰好 3 次**
  (一处定义两处调用)—— 新增一个可能递非英雄的调用点会让分支变活,这里就红。
