## 2. ⭐ 缺陷:一个函数、一个技能、三套到达约定,而最松的那套挂在门槛最低的分支上

`bots/BotLib/hero_lion.lua` `X.ConsiderR` 先画两条名单:

```
nInRangeEnemyList = J.GetNearbyHeroes( bot, nCastRange,       true, BOT_MODE_NONE )
nInBonusEnemyList = J.GetNearbyHeroes( bot, nCastRange + 400, true, BOT_MODE_NONE )
```

然后在同一个函数里对**同一个技能**用了三套互相矛盾的到达约定:

| 分支 | 用的名单 / 距离判断 | 进入这条分支的前置条件 |
|---|---|---|
| **击杀** 循环(最先跑) | `nInBonusEnemyList`(`nCastRange + 400`),**一个距离判断都没有** | **没有任何前置** |
| **打架** 分支 | `J.IsInRange( botTarget, bot, nCastRange + 200 )` | `J.IsGoingOnSomeone( bot )` |
| **撤退** 出口 | `nInRangeEnemyList`(`nCastRange` 整,零松弛) | `J.IsRetreating` + `nHP < 0.3` + 3 秒内被英雄打过 |

**最松的那一套,挂在门槛最低、且排最前的那条分支上。** 「打架」要 `IsGoingOnSomeone`、
「团战/撤退」要 `IsInTeamFight`/`IsRetreating`,而「击杀」循环**什么都不要**
⇒ 对线、打钱、走回家的路上都可能开火。

它交给引擎的是 `ActionQueue_UseAbilityOnEntity( abilityR, target )`,而对**射程外**目标
那条指令**先是一条移动指令**:Lion 走过去。本轮钉的真实帧上那段是
**345.8u / 300 移速 ≈ 1.15s**;而 `X.SkillsComplement` 在排完 R 之后**立刻 `return`**,
所以这段时间里 Q(大地之缚)、W(变羊)、E(法力汲取)**一个都不会被考虑**。

**这句话不是本组的新意见,是隔壁杠杆自己写过的。** `X.lion_ShouldCashUltAtWeakest`
(上一轮 `lionultcash`)的第三条合取带着这样一条注:

> inside nCastRange -- npcWeakestEnemy is picked from nInBonusEnemyList
> (nCastRange + 400), so without this term the armed leg could order a cast on a
> target Lion must **WALK 400 units toward, which turns "cash the ult before dying"
> into a dive**. This lever does not import that problem.

**出货的「击杀」循环正带着这个问题。** 本 id 就是那条合取被搬回它当初被写来说明的那条分支。

### 为什么「拒绝」不等于放掉这个人头(理论依据,验证哲学条件 (c))

`X.ConsiderR` **每帧重入**。拒绝不是放弃目标,而是**不让技能层去当移动决策**:
走位归模式(attack / roam / retreat)管,目标一旦真的进 `nCastRange`,
同一个循环下一帧就用同样的实参开火。被放弃的只有「Lion 自己发起的那段接近」——
一个 5 号位辅助朝敌方英雄走 400 码,而他在本仓语料里的血量是 354-607。

## 3. 改动(gated,turbo-only,未 armed)

新 `X.lion_ShouldCommitUltKill( hBot, hTarget, nCastRange, bShippedLethal )`:

- 出货致命性由**调用点先算**并作为实参传入;
- helper 除 armed 那一条外**每条路径都原样返回 `bShippedLethal`**,armed 只能把
  true 变 false ⇒ **NARROWING,严格子集,目标不变**(目标在调用之前就选好,helper 不重选)。
  ⇒ 归因边界:任何读数都**不能**读作「杠杆增加了一次施法」或「杠杆换了目标」。

### ⭐ 两个调用点,一个谓词 —— 第二个是承重的

只过滤「击杀」循环会把 dive **搬家**而不是移除:被它拒掉的 band 目标带着**为真的**
出货致命性答案继续走到三十行下的「团战对最弱的敌人」出口,而那个出口正是因为
「击杀」循环先吞掉一切致命成员才**不可达**(上一轮 `lionultcash` 的闭式证明)
⇒ **单点版本会把死代码复活**,并对同一个射程外目标开火。

这一条不是论证出来的,是**调用**出来的:`tests/test_lion_ult_reach.lua` §3 把
「团战」出口自己的谓词 `X.lion_ShouldCashUltAtWeakest(bot, silencer, 900, nHP, true)`
喂上**未过滤的**出货致命性答案 —— 它答 **true**。

**不在本 id 里**(刻意):「打架」分支自己的 +200 松弛(另一个列表、另一条分支,
且它至少问了)、蓝杖 AoE 分支的 `nCastRange + 150`(价值分支不是击杀主张)、
以及 `nCastPoint + 0.25` 这个延迟本身(把走路时间计进致命性估计是**另一条、
小得多的**杠杆;合取两个 id 是 pullcad 陷阱)。
