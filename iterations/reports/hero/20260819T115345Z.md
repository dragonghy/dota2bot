## 改动

### `bots/BotLib/hero_crystal_maiden.lua`

```lua
X.nRGuardCloseBuffer = 400

local hCc = J.GetReadyHardCc( e )
if hCc ~= nil
and GetUnitToUnitDistance( hBot, e ) <= ( hCc:GetCastRange() or 0 ) + X.nRGuardCloseBuffer
then return false end
```

形式照 `ccburst` 已验证的收窄写法(**自身半径类技能 cast range 报 0 →
必须贴脸**,这正好正确处理 `hoof_stomp`)。gate 关闭时函数第一行仍然 return
true,线上行为字节级不变。

**阈值 400,不是 ccburst 的 250** —— issue 把这个数留给本组定,理由是
**消费点不同**:250 是给 **3 秒对线换血窗口**定的("他能不能在我走开之前放
到我身上");这里守的是 **10 秒自缚频道**,威胁只要在这 10 秒里**够到一次**
就够。400 码 ≈ 300 移速下 1.3 秒位移,比频道时长小一个量级,门仍然是窄的。
两帧把它夹在 **[139, 1001)**,400 落在区间内,**区间本身写成了断言**(以后
谁调这个数,测试会自曝)。

## 经验(写给下一次触发)

- **单局、已知帧号的取帧自己做,不要委托。** 全链路(AWS 自举 →
  `awsx s3 cp` 一个 `.dem` → `get_dumper.sh` 命中 S3 缓存 →
  `behav-dump -interval 0.5` → `make_fixture.py`)**约 6 分钟**,而历史上
  两次委托 replay-analyst 分别跑满 51 分钟没返回。委托的价值在**扫全库找帧**
  (帧号未知时),不在**已知帧号的取帧**。
- `behav-dump` 的用法是**位置参数 + stdout**(`behav-dump [-interval N]
  X.dem > out.json`),不是 `-in/-out`。
- 时间线里同名实体会有多个 `idx`(幻象/旧尸体,`hp_pct==0`),按距离/存活
  过滤,`make_fixture.py` 已经处理。
