## 1. 事实

`X.ConsiderE` 在**三处**挑 Mana Drain 的目标,而它们对魔免的说法不一致:

| 分支 | 谓词 | 与 KV 一致? |
|---|---|---|
| 补蓝那圈(缺蓝时抽小兵) | `J.CanCastOnNonMagicImmune( nCreep )` | ✅ |
| **团战吸蓝** | **`J.CanCastOnMagicImmune( npcEnemy )`** | ❌ |
| 打架抽蓝 | `J.CanCastOnNonMagicImmune( botTarget )` | ✅ |

两个 helper 的差**正好一项**(`bots/FunLib/jmz_func.lua`):

```
J.CanCastOnMagicImmune     = CanBeSeen ∧ ¬IsInvulnerable ∧ ¬IsSuspiciousIllusion ∧ ¬HasForbiddenModifier
J.CanCastOnNonMagicImmune  =  同上 ∧ ¬IsMagicImmune
```

后者是**给能穿魔免的技能用的**。而 `lion_mana_drain` 穿不了:

```
lion_mana_drain
    AbilityBehavior   = UNIT_TARGET | CHANNELLED | IGNORE_BACKSWING
    SpellImmunityType = SPELL_IMMUNITY_ENEMIES_NO      <-- 这一行
    AbilityChannelTime = 5.1
    AbilityCastRange  = 850
```

(dotabuff/d2vpkr 的 `npc_dota_hero_lion.txt`,2026-09-06 读 —— 与
`tools/agent/cast_shape_census.py` 读 `AbilityBehavior` 是**同一份文件、同一层字段**。)

顺带一条**否定结果,值得登记**:`lion_impale` / `lion_voodoo` / `lion_finger_of_death`
**也全是 `SPELL_IMMUNITY_ENEMIES_NO`** —— **Lion 一个穿透技都没有**。所以这不是
「哪一支该用哪个 helper」的判断题,是**三支里有一支声称了一个游戏不给的权限**。

## 2. ⭐ 代价不是「白放一次」,是「白清一次动作队列」

`X.ConsiderE` 是 `X.SkillsComplement` 派发链的**第一臂**,它的消费方是:

```lua
castEDesire, castETarget, sMotive = X.ConsiderE()
if ( castEDesire > 0 ) then
    ...
    bot:Action_ClearActions( false )                       -- <-- 先清
    bot:ActionQueue_UseAbilityOnEntity( abilityE, castETarget )
    return                                                 -- <-- 下面 R / Q / W 三臂当轮不跑
end
```

而这一支本来就在 `if X.IsOtherAbilityFullyCastable() ... then return 0 end` **下面**,
只有在 Impale / Hex / Finger **全都不可施**时才跑得到 ⇒ **被清掉的那个动作,正是他当时仅剩的那个**。
BKB 一开就是 5-10 秒,这个状态**每 tick 复发**,不是一次。

§3d 把这句话量成了两行读数(见下)。

## 3. ⭐⭐ 方向由构造保证,而这一根是 NARROWING

```lua
function X.lion_IsDrainTargetCastable( hTarget )
	local bShipped = J.CanCastOnMagicImmune( hTarget )
	if not bShipped then return false end
	if J.IsModeTurbo() and J.IsSoakCandidate( 'liondrainbkb' )
		and hTarget:IsMagicImmune()
	then
		return false
	end
	return bShipped
end
```

出货谓词**先算并绑定**,armed 那条路**只能把 true 变成 false**,函数最后一条语句返回
`bShipped` ⇒ **armed 放行的目标集合是 shipped 的严格子集**。

⇒ 负读数**只能**读作「那些抽蓝本来该放」,**永远不能**读作「杠杆把抽蓝指到了新的地方」。

这个形状在新测试 §5 里写成三条源码断言(出货谓词必须先算并绑定 / shipped 为 false 必须先短路 /
函数体内**不许出现裸 `return true`**),在 §4 里还额外**被驱动地**验了一遍
(逐个敌方英雄实例断言 `armed ⇒ shipped`,反向允许失败 —— 那就是 NARROWING 的定义)。

与 `axecallbkb` 正好互为镜像:那个能力**穿**魔免却**多**了一条否决;这个**不穿**却**少**了一条。

## 5. ⚠️ 覆盖边界与限制,不许被引用时省略

1. **`SpellImmunityType` 是 RECORDED,不是 network-verified。** 仓内 KV 快照
   (`tests/mock/special_value_shapes.lua`)**不带这个字段**(与 GH #516 的 `GetAOERadius` 同族)。
   §KV 把这个**缺席**钉成断言:快照哪天长出这个字段就红,并要求把结论从 RECORDED 升级。
   带 KV 对照的是另外四项(cast range 850 / cooldown `15 12 9 6` / `mana_per_second`
   `20 40 60 120` / duration 5.0),它们保证「记下来的能力形状」和「出货数据」之间不会静默漂移。
2. **8 个主体帧的魔免数 0 是语料的零,不是世界的零。** 那份语料切自 10 分钟封顶的对局
   (GH #108),对「有人做出 BKB」的时段**结构性偏薄**,误差方向**对本改动不利**
   (真实频率只会更高)。这个 0 写成**单向绊线**:语料里哪天出现一个开着 BKB 的敌人,
   §2 就红并点名那一帧 —— 那就是这根杠杆真正想要的 (a) 证据。
3. **「唯一一帧」也是绊线。** §2 第二条断言「分支前提成立的帧恰好 1 个、且就是这一帧」;
   出现第二帧就红,免得后来的轮次引用「语料只给得起这一帧」这句已经过期的话。
4. **全量套件本轮没跑完**(~100min,GH #124)⇒ **「全量绿」本轮没有人说**。

`bash tools/agent/routine_selfcheck.sh` —— **worst exit 3**。

```

```

三条如实登记:

1. **`trunk-red(python)` 是 UNCERTIFIABLE 不是红。** 卡住它的是
   `tests/test_selfcheck_lua_leg.py`(84 文件 / 120.1s,骑在 120s 预算刀口上)——
   **就是 01:23Z 已立的 GH #548**,先于本轮、且本轮不碰那条腿 ⇒ **不认领**。
   「没跑成」不是「通过」,也不是「trunk 红」——这一轮**python 那一侧没有人看过**。
2. **`FINDINGS` 两条**(queue-rulings / owed-executions)都是别的组的待办登记
   (registry 里 7 行 OWED,executor 分别是总监 / 批测台 / 录像组),**没有一行点名英雄组**。
   本轮**没有对它们逐条做 stash 差分**,如实登记,不假装。
3. **⚠️ 自检被自己 REFUSED 一次,又被我截断一次。**
   第一次调用写成 `... | tail -40` ⇒ 脚本自己拒绝并打
   `stdout is a PIPE ... this is NOT a pass`(**证据纪律 3,本仓第 7 次复发,而且又是当轮第一条命令**)。
   第二次改成重定向,但我给它套了 `timeout 400` ⇒ 在 python 腿上被砍断、
   **`=== trunk health (python test suite) ===` 之后一个字都没有**,而外层 bash 的退出码是 **0**
   ——**与 GH #514 同形:截断长得跟「跑完了没发现」一模一样。**
   第三次不带 timeout、后台跑到底才拿到上面这份读数。
   ⇒ **可复用的一条:自检的超时不归调用方设。** 它自己知道每条腿的预算(#548 就是那个预算),
   外面再包一层 `timeout` 只会把「没跑完」伪装成「跑完了」。
