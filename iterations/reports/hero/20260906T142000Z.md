## 2. 事实

```lua
	if J.IsInTeamFight( bot, 1400 )
	then
		local tableNearbyEnemyHeroes = J.GetNearbyHeroes(bot, 1400, true, BOT_MODE_NONE )
		local nInvUnit = J.GetInvUnitCount( false, tableNearbyEnemyHeroes )
		if nInvUnit >= 5 then
			return BOT_ACTION_DESIRE_MODERATE
		end
	end
```

* 一方五个英雄 ⇒ `nInvUnit` 的值域是 `[0, 5]`,而 `>= 5` **要的是整队**。
* 它前面的两道过滤器**只会做减法**:`J.GetNearbyHeroes` 扣掉死的和视野外的
  (loader 与引擎一样受视野限制),`J.GetInvUnitCount` 只留下过
  `J.CanCastOnNonMagicImmune` 的(可见、非魔免、非无敌、非可疑幻象、无禁用 buff)。
  **一个死了、一个在雾里、一个开了 BKB、或者一个站在 1401u,都足以让它为假。**

**⚠️ 措辞比上一轮弱一格,这是故意的**:上一轮 `zusultstrand` 的合取项是
**结构性恒假**(两个常数上界之间的算术)。这一条**不是**恒假 —— 五个英雄挤进
一个 1400 圈是可能的。所以本轮**不写「恒假」**,写的是一个**测量**:

| 读数 | 值 |
|---|---|
| 语料里最大的一方 | **5** 个英雄(`C teamcap`,语料自己数的) |
| 真实帧视角数 | **1012**(109 个 fixture × 每个活着的英雄) |
| `nInvUnit` 分布 | `0:542  1:251  2:203  3:11  4:5` |
| **观测最大值** | **4** |
| `>= 5` 命中 | **0 / 1012** |
| `>= 3` 命中 | **16 / 1012 = 1.6%** |
| 十个 **Zeus 主体**帧 | 最大 **2**(`0,1,1,1,1,1,1,2,2,2`) |

## 3. ⭐ 本轮最值钱的三条

**⭐ 前提是一次测量,而且它可以失败。**
本轮**没有**从「Dota 一般怎么打」论证。`tests/_zusfightquorum_sweep.lua` 在
**每一个 fixture 的每一个活着的英雄**身上重跑那条 shipped 表达式,§2 断言
**观测最大值严格小于 shipped 法定人数**。语料哪天真出现一个 1400 圈内的五连站,
这个文件**当场变红**并说明原因。「5 是关掉的开关、3 是过滤器」因此是**读数**不是信念。
同一批行还量出 armed 侧的**窄度 1.6%** —— 这是这个 widening 与空头支票之间
**唯一**站着的东西:变异 **M8**(armed 降到 1)⇒ **46.4%**,**只有这一条断言看得见**。
**半径也是同一根杠杆的一部分**:变异 **M6** 把半径吹到 16000,于是每个视角都看见整队、
shipped 法定人数不再出界 —— 而**只有扫描看得见它**,因为扫描**从英雄源码读半径**、
不重打(M13 教训)。

**⭐⭐ 缺陷的另一半是「从哪儿量」,本轮故意不动。**
雷神之怒是**全球**技能(该 ability 连 `AbilityCastRange` 键都没有 —— 上一轮已在
KV 快照上钉过),所以用**施法者**的位置去量团战规模,量的是一个后排法师
**最不该站的位置**。语料把这个偏差直接摆出来:`f_260819_222052_zuus_w2_leak` 里
Zeus 的两个敌人(centaur、shadow_shaman)**各自数到 4**,而**同一帧**的 Zeus
**只数到 2**。§6 把这条不对称**钉成断言**(下一个杠杆的前提),而不是写成散文。
但**换计数中心是第二个杠杆、要自己的 id** —— 一个杠杆一次,本轮的杠杆是**法定人数**。

**⭐⭐⭐ 「够不到的阈值」和「根本没被读的阈值」从外面看一模一样。**
与 GH #560(不能失败的断言不是证据)、GH #564(恒假与不看输入外观相同)同族的
第三格。§3 在 10 个真实 Zeus 帧上记的每一个 `false`,都能由一个**不看输入的计数**
产生。所以 §4 打了一次**贴标签的几何注入**:真实句柄、真实谓词,**只注入「谁算
nearby」**,注满五个必须翻真;并且**先断言注进去的五个真的全部通过
`J.CanCastOnNonMagicImmune`**,否则这次注入控制的头数比它声称的少。
变异 **M7**(把 `nInvUnit` 常量化为 0)**只有这一条断言看得见**。

加的**只是**「架够大,即使此刻没人处在斩杀线内也值得放」这一类。

## 5. ⚠️ 方向:这是 WIDENING 不是 NARROWING

armed 只把法定人数从 5 降到 3 ⇒ **只能增加**这条分支上的大招施放,
**不可能减少一次**。负读数**唯一**能读作的是「多放的那些放错了(浪费了 250-500 蓝
和 130s 冷却)」,**绝不能**读作「少放了 N 次大招」。
gate-off 等价是**结构性**的(shipped 比较是函数第一条语句、达到就短路返回,
armed 是唯一绕道,GH #162 house rule);§5 用注入矩阵(**0..5 个敌人 × turbo/非
turbo**)逐个头数断言 `gate-off == shipped`,并单独断言 armed 答的是**armed 的**
法定人数而不是 shipped 的(变异 **M9/M10** 是这条的两种死法)。

## 6. 覆盖边界(⚠️ 两句不许合并)

**买到的:**
* **计数本身,在 1012 个真实帧视角上**。那是英雄**位置、队伍、存活标志、按队可见性**
  —— 全部是 dump 的帧数据(`tests/mock/replay_fixture.lua` 从 roster 复原
  `GetNearbyHeroes`,并且像引擎一样受视野限制)。
* **语料自己报的一方人数上界 5**,不是我打进去的常数。

**没买到的:**
* ⚠️ **那 1012 个视角里绝大多数不是 Zeus。** 非主体视角是**从别人脚下读的真实几何**,
  它**不是这条分支的创造帧**;它只授权关于计数**值域**的那一句,别的什么都不授权。
* ⚠️ **十个 Zeus 主体帧最多只数到 2**,连 armed 的 3 都没到 ⇒
  **「armed 分支在真实 Zeus 对局里会触发」本轮没有人说。** §6 钉成单向绊线 ——
  红了是**好消息**。域的真实大小是 `queue.json:hero-38` 的问题,不是这次扫描的。
* ⚠️ **`J.IsInTeamFight` 不在本轮测试范围内。** 它是 shipped 条件的另一半,而它读
  **友军 bot 模式**,`.dem` 切片不带这一列。§1 只断言调用点把**同一个半径常数**
  交给它,让两半不能各自漂移;**没有**对它的取值下过任何判断。
