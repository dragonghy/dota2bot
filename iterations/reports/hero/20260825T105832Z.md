## 1. 机制

`bot:Action*_UseAbility( h )` / `...OnEntity( h, u )` / `...OnLocation( h, v )`
是**三条不同的指令**,一个技能接受哪一条由 KV 的 `AbilityBehavior` 位决定,而
`DOTA_ABILITY_BEHAVIOR_PASSIVE` **哪一条都不接受,永远**。形状错了的指令**不会报错**
(AGENTS.md:`print()` 到不了服务器控制台,引擎错误处理器是坏的),**它只是不发生** ——
而发出它的那条分支通常带 `return`,于是**整个调度 tick 跟着一起没了**。

`hero_crystal_maiden.lua:223`(`ArcaneAura` 绑字面量 `'crystal_maiden_brilliance_aura'`):

```lua
ArcaneAuraDesire = X.ConsiderArcaneAura()
if ( ArcaneAuraDesire > 0 ) then
    J.SetQueuePtToINT( bot, false )
    bot:ActionQueue_UseAbility( ArcaneAura )   -- 被动技能
    return                                     -- 后面四条技能今天都不用问了
end
```

而该技能的 KV 行为位**全文只有一个**:`"AbilityBehavior" "DOTA_ABILITY_BEHAVIOR_PASSIVE"`。

## 3. 改动(为什么 gate-off 等价是结构性的)

新 helper `X.IsArcaneAuraCastable()` + `X.HasPassiveBehavior( hAbility )`,
gated **`cmaurapassive`**(turbo-only):

- **出厂谓词 `J.CanCastAbility( ArcaneAura )` 是第一句且自己 `return false`**
  ⇒ gate-off **结构上**就是出厂表达式,不是测出来的
  (同 `lionhexaoe`/GH #166 的形状,是 GH #154 那个放宽形状的**对偶**);
- **方向单一**:armed 腿只有一个出口 `false`,测试按 `return true` 的**处数**钉住 ——
  一个 armed-only 的 `true` 就是「放宽搭着收紧的门上车」(GH #166 的教训);
- **行为位读到 0、或这个 VM 没有那个常量 ⇒ 落回出厂**,不发明 flag 值
  (GH #162 的规矩:**静默的 0 不是一个值**);
- `.luacheckrc` 加 `DOTA_ABILITY_BEHAVIOR_PASSIVE`(货真价实的引擎常量)。

**有意没做的两件事**:① 没有删掉这条死分支 —— 删死代码是**另一个方向**的清扫,
不混进本单元(#170 同样的处置);② 没有碰其余 10 处 PASSIVE-DISPATCH ——
九个非焦点英雄,各自要各自的 id 和各自的依据(#168 的规矩)。

### ⭐ 三条留给后来人的(每条都花了真时间)

1. **一个 mock 默认值悄悄声明了世界事实,并把一份正确的实现判红。**
   `tests/mock/bot_api.lua` 给每个不认识的 ALL_CAPS 全局发**顺序整数**(1001, 1002, …)
   ⇒ mock 里的 `DOTA_ABILITY_BEHAVIOR_*` **不是互不相交的 2 的幂**。
   `bit.band( NO_TARGET, PASSIVE ) == PASSIVE` 当场读出 **true**。
   测试改成用 `bnot` **清掉 PASSIVE 位**造反例。同 #133/#145 族。
2. **逃逸先复核语义再改测试**(#162 立的规矩,本轮又用上一次)。变异
   `band(m,f) == f` → `~= 0` 逃逸;复核确认 **PASSIVE 在引擎里是单个 bit**,
   两种写法逐位等价 ⇒ **真 no-op,不是盲区**。
3. **一条关于行为的测试不该被一次纯改名判红。** 对照变异(纯局部变量改名)
   **第一版被抓住了**,因为一条源码断言点了局部变量的名字;已改成**数两条
   fall-back 守卫的处数**。源码棘轮要钉的是**结构**,不是**拼写**。

### 一条工具侧的 bug,顺手修在工具里(记下来免得后人重踩)

KV 解析器第一版沿用 `ability_damage_census.py` 的「`{` 必须独占一行」写法,
在 brewmaster 上**当场失步并静默丢掉该文件后面的全部技能** ——
`brewmaster_liquid_courage` 明明在文件里、下一行就写着 PASSIVE,普查却读作「没有」。
改成**逐行数括号**后该处回来了(11 而不是 10)。
**一个会对文件后半段静默沉默的解析器,比一个会报错的更坏**:普查读起来像「那里没东西」。
