### Fact 2:`ConsiderR` 击杀分支跑 1300~1550 环但不断言 range

`bots/BotLib/hero_lion.lua:846-970`(相关段落):

```lua
local nCastRange = abilityR:GetCastRange() + aetherRange       -- 900 + 0 / 250
if nCastRange > 1200 then nCastRange = 1200 end                -- 上限 1200(实际最大 1150)
local nInRangeEnemyList = J.GetNearbyHeroes(bot, nCastRange, true, BOT_MODE_NONE )
local nInBonusEnemyList = J.GetNearbyHeroes(bot, nCastRange + 400, true, BOT_MODE_NONE )  -- 1300 / 1550

-- 击杀
for _, npcEnemy in pairs( nInBonusEnemyList )
do
    if J.IsValidHero( npcEnemy )
        and X.CanCastAbilityROnTarget( npcEnemy )              -- 无 range 检查
    then
        if J.WillMagicKillTarget( bot, npcEnemy, nDamage, nCastPoint + 0.25 )
        then
            return BOT_ACTION_DESIRE_HIGH, npcEnemy, 'R击杀'...
```

`X.CanCastAbilityROnTarget` → `J.CanCastOnTargetAdvanced`(validity/immunity/AM shield)+ `J.CanCastOnNonMagicImmune`(视野/魔免/幻象),**都不看距离**。团战最弱分支同理(line 891-912),weakest 直接从 `nInBonusEnemyList` 里挑,没有 range 断言。

对照同函数的另外两条分支:
- aghs-AoE(line 923):`J.IsInRange( bot, npcEnemy, nCastRange + 150 )` **有** range;
- `IsGoingOnSomeone`(line 960):`J.IsInRange( botTarget, bot, nCastRange + 200 )` **有** range。

后果:目标在 1200-1550 时 return HIGH desire,`ActionQueue_UseAbilityOnEntity` 要么让 Lion 走过去(0.3s cast point + 数百码脚程,窗口关掉),要么静默失败。这种「Finger 被请求但结构性够不着」在聚合 casts/game 上看不见,但会把「大招应该开的窗口」用掉。
