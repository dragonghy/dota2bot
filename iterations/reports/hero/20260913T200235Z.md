## 2. 缺陷:一个函数里唯一一条不把自己的环挂在施法距离上的分支

`bots/BotLib/hero_lion.lua` `X.ConsiderE` 的第一条 working line 就算出了环:

```lua
local nCastRange = abilityE:GetCastRange() + aetherRange      -- :1338
```

同一个函数的其它分支全都测它:团战腿 `J.IsInRange( bot, npcEnemy, nCastRange )`、
打架腿同样、幻像腿**故意**开到 `nCastRange + 300`。
**最后这条是本缺陷成立的关键**:作者在同一个函数里**有意**放宽过一次环,
⇒「把环挂在施法距离上」不是没想到,是这一条分支漏了。

「缺蓝的时候抽蓝」那条不这么做:

```lua
local nEnemyCreepList = bot:GetNearbyCreeps( 1600, true )
for _, nCreep in pairs( nEnemyCreepList ) do
    if J.IsValid( nCreep )
        and ( nCreep:GetMana() > nManaDrain * 0.8 or nCreep:GetMana() > 349 )
        and J.CanCastOnNonMagicImmune( nCreep )
    then
        return BOT_ACTION_DESIRE_HIGH, nCreep, 'E-补篮'
```

从列表到 `return` 之间**一个距离项都没有**。

**差距有多大,读的是 KV 快照不是记忆**(`tests/mock/special_value_shapes.lua`):
`lion_mana_drain / AbilityCastRange` 是**逐级恒定的 850**。

| | 值 |
|---|---|
| 搜索环 | **1600** |
| 施法距离 | **850**(带秘法胶 1100) |
| 裸差 / 带胶差 | **750** / **500** |
| 该技能自己的 `break_distance` | **1100** |

⇒ 这条分支能挑一个**比引导会被打断的距离还远**的兵。

**代价**:对射程外单位下施法令 = **先下移动令**,而这一注是
`BOT_ACTION_DESIRE_HIGH`,整段走路都压过把 Lion 放在原地的那个 mode。
而分支的准入条件(`#hEnemyList == 0` 且 1000 内无敌方塔)**恰恰**是
「此刻地图上没人跟他抢」的时刻 —— 也就是一个辅助的**站位**本身
(眼位 / 线 / 烟)是他握着的那件东西的时刻。

**条件 (c)**:pos 4/5 Lion 的 Mana Drain 是**从已经站在旁边的东西上**顺手回蓝,
它是一段多秒的**站桩引导**;Turbo 里蓝是会自己长回来的那个约束,站位不是。
为了开一段引导走最多 1600 码,把这个关系倒过来了。

## 3. 修法与方向

gated helper,出货答案由调用点算好传进来:

```lua
function X.lion_IsDrainCreepInReach( hBot, hCreep, nCastRange, bShippedInReach )
    if not bShippedInReach then return bShippedInReach end
    if not ( J.IsModeTurbo() and J.IsSoakCandidate( 'liondrainreach' ) ) then return bShippedInReach end
    if hBot == nil or hCreep == nil then return bShippedInReach end
    if type( nCastRange ) ~= 'number' then return bShippedInReach end
    return J.IsInRange( hCreep, hBot, nCastRange )
end
```

唯一调用点、唯一闸解析点(§1.3 / §1.4 断言,并按 pullcad 陷阱断言闸的条件里
**不出现任何兄弟 id**)。

⚠️ **方向 NARROWING,按构造单向**:除 armed 那条外每条路径原样返回
`bShippedInReach`,armed 那条只能把 true 变 false ⇒ armed 在出货帧的**严格子集**
上开火,且**从不重选目标**(循环已经选好了)。
⛔ **负读数只能读成「这道否决删掉了 N 次抽蓝出价」**,绝不能读成
「避免了 N 次白走」,更不能读成本 lever 增加或移动了一次施法。

## 4. GH #799 的「排序」那一半:不是缺陷,是层级约束的算术

线索原文(`-167`):「队列 slot 18 装 t20、slot 19 装 t25,而它们最早分别在
18 级 / 20 级成为队头 ⇒ 天生卡住」。**卡住是真的,缺陷不是。**

`X.GetSkillList` 通用腿:`totalSlots = 15 + 8 = 23`,天赋落在
`i >= 10 and (i % 5 == 0 or ability_idx > 15)` ⇒

| 槽 | 1–9 | **10** | 11–14 | **15** | 16–17 | **18** | **19** | 20–23 |
|---|---|---|---|---|---|---|---|---|
| 内容 | 技能 | **t10** | 技能 | **t15** | 技能 | **t20** | **t25** | 四层各自的**另一半** |

把每个槽跟引擎的等级要求对齐(基础技能 rank N 要 2N−1 级;大招 **6/12/18**;
天赋 10/15/20/25):

* **17 级时可花上限 = 14 个技能点**(大招 rank 3 要 18 级)**+ t10 + t15 = 16 < 17**
  ⇒ **必然攒一点**,与顺序无关;
* 18、19 级同理(t20 要 20 级);21–24 级同理(t25 要 25 级);
* 槽 20–23 是**同层另一半**,第一半点掉之后永久不可点 —— 而那时也已无点可花。

⇒ **顺序在这条约束下是紧的**,任何重排只会更差或等价。

⭐ **反过来还有一条承重发现**:**t10 / t15 两个槽是垫片,不是杂物** ——
正是它们把六条焦点 build 的**大招 rank 2**(ability idx 11)顶到槽 12 = **恰好 12 级**,
也就是引擎对大招 rank 2 的要求。「把天赋全挪到技能之后」这个直觉修法会让 idx11
落到槽 11 = 11 级,**低于要求** ⇒ **打坏大招节奏**。

⭐ **一条真实的 off-by-one,但它不是缺陷**:六条焦点 build 的**大招 rank 3**
(idx 15)都落在槽 **17**,引擎要 **18 级**。它解释了为什么终局 `else` 在
**每一局、每一个英雄**身上都至少被进入一次 ⇒ **`[WARN] Skipped to level up
ability` 不是异常信号**。这一条直接影响 `queue.json:hero-78` 那次日志扫描
**怎么读分母**,已写进 state.json。

⛔ **诚实边界**:这是从两份 build 表 + 引擎公布的等级要求**推**出来的,
**不是从帧上量的**,本轮**没有**给它写断言。登记为**推导不是判决**;
把它钉成断言是下一轮的自足小单元。
⛔ **它不结掉 #799**:#799 量到的墙在槽 **15**(13 技能点 + ≤1 天赋),
那是**消费**缺陷(`skillstall` 的域),与排序无关 —— 按 `-167` 的要求**不合并**。

## 6. ⛔ 本轮自己抓到的两条错误,都写在这里而不是被抹平

### 6.1 「死代码」那句话是反的,查 KV 后当场改正

第一稿的 helper 抬头写着:准入测试的第二个析取项 `nCreep:GetMana() > 349`
**每一级都是死代码**(理由:`nManaDrain` 最大值远低于 349)。
**那是错的。** KV:`mana_per_second = 20 40 60 120`、`duration` 恒 `5.0`
⇒ `nManaDrain * 0.8` = 80 / 160 / 240 / **480**。

⇒ 前三级 349 确实被第一项吞掉;**第四级 349 是更弱的那个测试**,
放进持有 350–480 蓝量的兵。它是一条**四级里三级空、第四级承重**的析取项。

抬头已改成写**算术**而不是写结论,§5 用 KV 自己算出 3/1 这个比并钉住:
比变了要去**改抬头**,不许放松断言。
**这一项本轮不修**(与射程是两个问题,合并会让波读数无法归因)。

同一次查 KV 还改掉了抬头里另一个凭记忆写的数:施法距离不是「~600」,是 **850**。

### 6.2 ⭐ 变异台抓到自己:一个改了注释的 mutant

M11 = 「不 gate 就把 1600 直接改小」,应当 CAUGHT。
第一版锚在裸的 `bot:GetNearbyCreeps( 1600, true )` 上 —— 而**同一个 needle
更早地出现在本 lever 自己的抬头注释里**(抬头在引用缺陷)⇒ perl 改的是**散文**,
mutant **SURVIVED**。

改成锚 `local nEnemyCreepList = ...` 后 CAUGHT。
**一个改了注释的 mutant 不是一个结果** —— 这句话连同原因写进了台子里。
(测试那侧本来就没这个毛病:§1 全部走 `fn_body()` 按**函数体**切,
不按 needle 切 —— 那正是 `-167` 记下的两条散文锚事故的修法。)
