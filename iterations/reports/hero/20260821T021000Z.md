## 4. 成因(在代码里,不是采样问题)

分支自己已经写着(`bots/ability_item_usage_generic.lua:1610`):

```lua
if (#nInRangeAlly >= nNearbyEnemyHeroCount and bWeAreStronger) then
```

两边都在 `botTarget` 的 1200 环里数人。门要求「**落点** 315 内 >= 2 敌」,而落点在 cast range
内**就等于目标位置**(`nDistance = Min(nCastRange, dist)`),所以那 2 个敌人必然也在目标的
1200 环里 ⇒ `nNearbyEnemyHeroCount >= 2` ⇒ 分支要求 `#nInRangeAlly >= 2`,**至少还要一个队友**。
实测 **1 / 21 帧全是 1**。

⇒ **门的域是分支既有否决的一个子集。** 门每一个想否决的帧,分支已经用一个**严格更弱**的
条件否决过。armed 与 shipped 端到端逐帧相同 —— `axeblink` 陷阱,发生在它自己的同名 id 上。
(`J.WeAreStronger` 还在后面再收一道,只会更窄。)

## 5. 顺带一条量测事实(给全队,已写进工具 docstring 与 #79 §5)

**跳刀的位移出现在 ITEM 事件之后的第一**或**第二个 0.5s 采样,不固定。**
第一版按「事件后第一个快照」取落点,把 `20260820_043124` t=529.6 读成 **77 码走路**
(cos +0.167),真值是 **1309 码 cos +0.999**。改成「在 `[t-0.5, t+2.0]` 窗口里取相邻快照的
最大位移」后,**与 GH #71 独立测出的几何完全对上**(1309 @ +0.999、1139 @ +0.999)——
两份读数互为交叉校验。任何按「事件后下一帧」定位瞬移的检测器都要按这个改,否则**分支归属会错**。

## 6. 可复用先验(建议进全队 §V.7)

> **上机一个「新增否决」的门之前,先看它所在的那条分支是不是已经用一个更弱的条件否决了。
> 是的话,新门的域就是一个已有否决的子集,必然是空的。**

与 `wkreincarnmp` 那条(「只改『读』的那一侧,先看『写/花』的那一侧」)同族,低一层:
那条讲**同一个量的另一侧**,这条讲**同一条路径的外层**。两条都是**不用拉任何语料的桌面检查**
—— 本轮若先做这一步,约 14 分钟即可得出同样裁定,不必拉 18 个 `.dem`。这是本轮最该被
其它组拿走的东西。
