## 一、⭐⭐ 头条:要定价的量不是距离,是符号

GH #873 §四 交代的是「先给 WK 那 43u 超伸定价,43u 值不值一个 id 没量过」。
定价做完了,而**它把修法换了个分支**。

`X.ConsiderQ` 的 `nEnemysHerosInRange = J.GetNearbyHeroes(bot, nCastRange + 43, …)`
是一个**搜索环**,被**四个**出货点消费(团战 / 撤退 / 受伤 / 兜底),四个**都没有
自己的距离项**。逐条问下来:

| 消费者 | 43u 的含义 | 值不值 |
|---|---|---|
| 团战 argmax | WK 已经在打,多走 0.13s | ❌ |
| 受伤自保 | 同上 | ❌ |
| 兜底 | 同上 | ❌ |
| **撤退自保**(`J.IsRetreating( bot )`) | **方向** | ✅ |

`X.SkillsComplement` 把 `ActionQueue_UseAbilityOnEntity( abilityQ, target )` 交给
引擎;**目标在射程外时那条指令先是一条移动令**(机制不是本轮发现的 —— `wkqlane`
的抬头 2026-09-08 就写着「melee 的 WK 会朝敌方英雄走最多 330u」)。把它读到撤退腿
上,这条腿给引擎的指令逐字是:

> **朝着你正在逃离的那个英雄走。**

而且 `X.ConsiderQ` 每帧重进,desire 还在就**每帧重下**。⇒ **43 units 作为距离可以
忽略(325 移速下 0.13s),作为撤退时的方向不能** —— 同一个 43u,两条腿上不是同一
件事。这就是 §四 问的那个「值不值」的答案:**分腿回答,不是整体回答**。

## 二、⭐ 43 是下界不是那个数(本轮新买的,#873 没写)

环上方有一个 clause:

```lua
if #nEnemysHerosInView == 1 and … then nCastRange = nCastRange + 260 end
```

它**改写 nCastRange 本身**,于是下游每个环整体右移。唯一可能把它与撤退腿互斥掉的
谓词是 `J.IsInTeamFight` —— 而它数的是 **`BOT_MODE_ATTACK` 的盟友,从不数敌人**
(`jmz_func.lua:1719`)。⇒ **本函数里没有任何东西让那条 extension 与这条腿互斥**,
带上它时带宽是 `(nCastRange, nCastRange + 303]`。

⇒ helper 的射程**由调用点传入而不是重读**,于是它与 extension **组合**而不是悄悄
忽略它(这条与 `wkqlane` 抬头写的是同一个理由)。**M7 为这条定价**:把 helper 改成
硬编码 525,在钉住的那帧上**行为完全相同**,只有 +260 触发或 Q 升级后才不同 —— 它
被 §5.3 的第二条断言抓住。

## 五、方向 + 理论依据(验证哲学条件 (c))

- **方向按构造**:armed 判据对一切输入是 shipped(`true`)的**真子集** ⇒ arming 只能
  **减少**撤退出货,**不可能**新增或挪动一次出货。负面波读数可归因于「那些 <43u 的
  步子是值得走的」,**永远不可能**归因于本 lever 造出来的一次施法。
- **为什么不是 `+80`**:`+80` 是本函数自己的**承诺**额度(击杀确认 / 打架先手)——
  而承诺正是撤退**不该花**的那一样。族里「搜索环 == 施法环」的参照实现就在本仓:
  `hero_crystal_maiden.lua:1761`,GH #873 §二 记为**正确**的那一份。
- **标准打法**:撤退中的近战英雄用一个 1.0–1.6s 的硬控**自保**是标准操作;为了这个
  硬控**掉头朝追击者走**不是 —— 这与 owner 优先项 **P2**(低血不回家、少送无谓人头)
  同向。⛔ 本轮不申请入集也不申请波次,所以这只是 (c),**不冒充 (a)/(b)**。
