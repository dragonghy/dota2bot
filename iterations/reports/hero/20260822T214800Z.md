## 6.5 全量套件抓到一件真事:**写在注释里的一行代码,把那行代码的位置挪走了**

第一次全量跑 **1311 tests / 1 failure**,红的不是本轮新写的测试,而是本组
2026-08-19 留下的绊线 `test_replay_260819_lion_drain.lua:317`:

```
the refill and illusion branches sit above the shipped early-out
```

**成因**:那条绊线用 `src:find('if X.IsOtherAbilityFullyCastable() or nSkillLV <= 1', 1, true)`
在**原始源码**里找地标 —— 而本轮写在文件**顶部**的理由块**逐字引用了这一行**
⇒ 找到的第一处落在注释里,于是「早退在补篮分支之上」被判成真。
**出货代码一个字没动,红的是绊线自己。**

**处置:修绊线,不是改措辞。** 地标改成**按行**定位,且两个**代码**地标
**只在非注释行上算数**(两个中文地标本身就是注释,保留原样)。
`prose about a line must not be able to move that line` 已写进那个测试的注释里。
**修完立刻反向验证它还抓得住它该抓的东西**(4 次变异 4 抓):

| 变异 | 抓? |
|---|---|
| N1 把 guard 挪到早退**上面**(这条绊线存在的理由) | ✅ |
| N2 把早退提到补篮分支**上面** | ✅ |
| N3 删掉 guard | ✅ |
| N4 helper 不再挂在 `liondrain` id 后面 | ✅ |

**可复用的一条**:**用字符串在源码里找「代码地标」的测试,必须排除注释行**
—— 否则任何人写一段引用该行的说明文字都会让它变红,而且红的信息是**假的**
(它会说出货代码的顺序变了,其实没变)。本仓已有 `live_lines()` 这个现成写法
(`test_focus_talent_anchor.lua` / 本轮的 `test_lion_t10_payoff.lua` §5 都在用),
但绊线类测试普遍是裸 `src:find` —— **建议总监按全仓扫一遍同型**。
