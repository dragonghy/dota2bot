## 2. 缺陷,闭式

`X.ConsiderQ` 的第十条、也是最后一条开火点:

```lua
--通用消耗敌人或受到伤害时保护自己
if ( #nEnemysHerosInView > 0 or bot:WasRecentlyDamagedByAnyHero( 3.0 ) )
    and ( bot:GetActiveMode() ~= BOT_MODE_RETREAT or #allyList >= 2 )
    and #nEnemysHerosInRange >= 1
    and nLV >= 7
then
    -- 打 nEnemysHerosInRange 的第一个 = 最近的那个
```

上面九条各自说得出理由:打断引导 / 确认击杀 / 团战里点最高威胁 / 对线借自家兵线换血 /
已经决定的先手 / 撤退自保 / 清野 / 打肉 / 刚挨过打。**第十条说的只是「有人、够近、我 7 级」。**

⭐ **而它并不是天生不看人数。** 第二条合取项里就写着 `#allyList >= 2` ——
一个人数判据,已经在这条支路里了。它坐在一个 `or` 的**右边**,左边是
`bot:GetActiveMode() ~= BOT_MODE_RETREAT`。**除撤退以外每个 mode 都让左边为真**,
于是右边只有撤退时才会被求值 ⇒ **其余所有 mode 下,这条支路从不看双方人数。**

与 `cmqpoke`(GH #698)同族、不同形:
- `cmqpoke`:合格判据是**另一条支路**,被上面那条钱包支路永远抢先;
- `wkqodds`:合格判据**就在本支路里**,结构性不可达。

两条的共同点是**armed 一侧不发明阈值**——用的是出货代码自己已经写下的那个数。

## 5. ⭐ 顺手买到的一条读数,而它属于**另一个**候选

`tests/test_wk_q_aim_preflight.lua` §1 是一条**故意写成 tripwire 的全称命题**:

> 语料里凡是有活体 Wraith King 且 568u 内有 ≥2 个活体敌人的帧,Wraithfire Blast
> 必定未学或在 CD —— 这条支路一帧都没被走到过。

该文件自己写着:红了是**好消息**,因为红的那一帧正是 `wkqaim`(queue `hero-1`)需要的真实帧。

**它现在在语料外已经假了。** 那个 tripwire 只扫 `tests/fixtures/`,而
`tests/frames/` 里有**两帧**满足它说没有的配置:`lane_121` 与 `sb_1052`
(Q 可施放,568u 内 ≥2 个活体敌人)。它至今是绿的,**因为它看不见暂存目录**。

⭐⭐ **但可达 ≠ 可分辨,而这才是能带走的那一半。** `wkqaim` 的提议是「打血最少的,
不要打最近的」。唯一同时过了 7 级门的那帧(`sb_1052`)里:

| 环内敌人 | 距离 | 血量 | 比例 |
|---|---|---|---|
| slardar | 203u | 1037 | 0.31 |
| spirit_breaker | 224u | 1522 | 0.63 |

**最近的恰好就是血最少的**(按绝对值和按比例都是) ⇒ **`wkqaim` 在这一帧上一个目标都不改。**
这正是 `bots/` 里 `wkqdmg` 那条注释区分的**「算术域 vs 决策域」**,换一个候选重演一次:
域非空是**必要**条件,不是充分条件。**`wkqaim` 的可分辨帧仍然欠着**,而 queue `hero-1`
要的那次归档扫描(153 局 `.dem`)**仍然是买它的唯一路子**。

这条读数写进了 `test_wk_q_catchall_odds.lua` §6(两例),而不是只写在报告里 ——
理由是 §6.1 的断言会在「某天有一帧进了 `tests/fixtures/`」时自己红,并指着
`test_wk_q_aim_preflight.lua` 说「先读那个文件」。
