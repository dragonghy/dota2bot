## 2. 主体:`cmcreepclock`(`bots/BotLib/hero_crystal_maiden.lua`)

### ⭐ 本轮的形状:**一条被正确地 scope-out 的读数,和一条从来没有人问过的问题,是两件事**

`X.cm_IsTeamfightClockOpen`(`cmtfclock`)的抬头**明确**把 `X.ConsiderW` 里另外两处
`DotaTime()` 读数排除在外,理由是**形状**:那两处各是一个 DISJUNCT
(`DotaTime() > 10 * 60 or <这只小兵不是基础兵>`),时间在那里**放宽一条目标类规则**,
而不是**门住一次施法**。

**那个 scoping 是对的,本轮一字未动**,而且我在源码和测试里都写清楚了它没变。
它没有回答、也没打算回答的是**另一根轴**:`10 * 60` 是一个**普通模式常量**
(GH #157:全仓 381 处时钟比较,只有 18 处 turbo 感知),而**一个普通模式常量在 Turbo 里
错不错,跟它坐在合取里还是析取里无关**。

⇒ 同一个字面量上的**两个问题**。故意**不合并**:合并会让一次波读数无法归因到任何一个。

### 缺陷与修法

时钟是「对线期结束了」的**代理**,而外层块的**第一个合取项**已经直接测了同一件事
(`bot:GetActiveMode() ~= BOT_MODE_LANING`,旁边还有 RETREAT / ATTACK)。
普通模式下 10:00 与 mode 翻转大致重合,代理几乎免费;
**Turbo 下 mode 远早于 10:00 就离开 LANING,那段间隙里时钟是唯一还在拒绝的项。**

```lua
X.nWCreepClockShipped = 10 * 60
X.nWCreepClockTurbo   = 5 * 60      -- 出货数减半

function X.cm_IsCreepClockOpen()
	if J.IsModeTurbo() and J.IsSoakCandidate( 'cmcreepclock' )
	then
		return DotaTime() > X.nWCreepClockTurbo
	end
	return DotaTime() > X.nWCreepClockShipped
end
```

两处调用点各换成 `X.cm_IsCreepClockOpen()`;**未 armed 时逐字节就是出货表达式**(§5.2 钉住)。
2x 用的是本仓自己写下的 Turbo 节奏比(~20min vs ~35-40),也是 `cmtfclock` 在 6*60 上
用过的**同一个比** —— 复用而不是再发明一个,两次读数才可比。

### 方向:WIDENING,**按构造**不是按单调性

`TURBO < SHIPPED` ⇒ 出货接受的每一个 t,armed 也接受 ⇒ armed 是出货的**严格超集**。
arming 只能**增加**小兵施法,窗口 (5:00, 10:00],**永远不会移除或移动**一次施法。
§4 在整份语料上断言,不靠论证。

### 域:两个数,而且第二个是零

* **GATE 层域 = 15 个语料瞬间**。70 个存活 CM 瞬间里,32 个通过外层块**可测的**三个
  非时钟合取项(1600 内无敌方英雄 / 1200 内友军 < 3 / 等级 >= 5),其中 **15 个**落在
  (5:00, 10:00];另有 **17 个**已过 10:00(出货本来就放行)。
  对照:`cmtfclock` 的 gate 层域是**单帧**。
* ⛔ **端到端域 = 0,而且是结构性的 0 不是运气**:该分支需要一只小兵**单位**,
  而这份语料一个都没有 —— `bot:GetNearbyCreeps` 在 **70/70** 个 CM 瞬间上答空表
  (`state.json:CORPUS_HAS_NO_NONHERO_UNITS_20260912`,与 `cmfarcreep`/`cmrangedhp`/
  `cmcreepcap` 记录的是同一个阻塞)。
  ⇒ **没有任何语料帧能展示本 lever 增加的施法,谁也不许报一个。** §3.4 是**单向 tripwire**。

### ⛔ 本轮最该被别人拿走的一条自我约束:**差点把一条五周前的世界断言当成新发现**

我量到 `GetActiveMode()` 在 **1314/1314** 个语料英雄句柄上答 **0**,而
`BOT_MODE_NONE/LANING/ATTACK/RETREAT` 是 **1001/1002/1003/1005** ⇒ 通用 `^Get` 默认值,
谁也不匹配。当时的第一反应是「这是一条新的世界断言,该开 issue」——
**收尾前查了一次注册表,它五周前就在**:`state.json:activemode_WORLD_ASSERTION_13_20260821`
+ `tests/test_activemode_world_assertion.lua`。**已改成引用,不是发现。**

它对本 lever 的后果是精确的、而且**是坏消息**:那个 mode 合取项**离线恒真(空洞地真)**,
所以**上面那个 15 不包含任何「mode 项成立」的证据**。
抬头里「块自己已经直接测了对线期」那一段是**从源码读的,不是从帧读的** ——
§5.3 把这条钉住,防止后来的读者把它升格成帧证据。

### ⭐ 棘轮开火了,而那正是它存在的理由

本轮改动把 `tests/test_cm_w_teamfight_clock.lua` **§5.1 顶红**:它原本钉
`count(ConsiderW, 'DotaTime()') == 2` 与 `count(..., 'DotaTime() > 10 * 60') == 2`,
两处字面量搬进 helper 后**双双归零**。
⇒ 棘轮在它守着的普查**真的变了**的那一刻开火。
**已重新推导,不是把数字改成对得上**:现在断言 `X.ConsiderW` 问时钟**恰好三次、
三次全走具名 helper、一次裸 `DotaTime()` 都没有**。
`cmtfclock` 抬头里引用旧字面量的那一段同步更正,并写明
**scoping 未变、变的只是字面量住在哪里**。
