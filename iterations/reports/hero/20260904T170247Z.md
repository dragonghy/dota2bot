## 3. 结论一:**cast point 接上了,但它是死的** —— 而这是量出来的,不是免责声明

`GetCastPoint()` 的读数确实动了(Culling Blade 0 → 0.3,Zeus 大 0 → 0.4),
**但语料里没有任何一个击杀判定跟着动。**

原因是 `nDelay` 在 `J.WillMagicKillTarget` 里只以

```
HealthBack = npcTarget:GetHealthRegen() * nDelay
```

这一个形状出现,而 **`GetHealthRegen` 自己也没上规格** —— 它在
`tests/mock/replay_fixture.lua` 里**一次都没出现**,任何 dump 里也**没有 health-regen
字段**,于是它落在 `mock/bot_api.lua` 的通用 `^Get` 默认值上答 0。
⇒ 这个乘积是 **`0 × 任何东西`**。

**实测(§7d,Lion 食指扫描):13 帧、58 个活着的敌方英雄对、
`nDelay = 0 + 0.25`(改前)与 `nDelay = GetCastPoint() + 0.25`(改后)
两腿各 5 个击杀判定,**0 次翻转**,`GetHealthRegen() > 0` 的目标 **0 个**。**

**这是 backlog `-88` 那条教训的同一个形状**(`max_skeleton_charges` 答 0 时
`nStack == maxStack` 是 `0 == 0` 恒真,于是那两个数测的是两者的合取):
**一个读数,如果它下游还有一个恒 0 的因子,它量的是合取**。区别是这次是**动手前先量了**,
不是事后发现的。

**而且这一格本快照关不掉**:health regen 是**逐帧的单位状态**(基础 + 装备 + 天赋),
不是技能 KV,不在 `special_value_shapes.lua` 的定义域里。
**要 dumper 出这个字段 ⇒ 球在录像组**(下一棒见 §7)。

**顺带一格,免得下轮有人误读**:`crystal_maiden_freezing_field` / `lion_voodoo` /
`zuus_lightning_hands` 三个技能的 `AbilityCastPoint` **KV 本身就是 0**。
它们改前改后都读 0,而这**是引擎的答案,不是「没装规格」** ——
**光看读数分不出这两件事**,所以 §7b 去看快照,那是唯一存在这个区别的地方。
`hero_crystal_maiden.lua` 的 `X.ConsiderW` 正是把这个读数当 `nDelay` 传进
`J.WillMagicKillTarget` 的 ⇒ **一个 CM 冰封禁制的读数不能拿来说明本撮动了或没动任何东西。**

## 4. 结论二(本轮最硬的一格):**同一个 0 把同一个文件里相邻的两个守卫推向相反方向**

`GetCooldown()` 不是死的,而且它**没有单一的失效方向** —— 因为那个 0
**坐在比较式的两边**(`remaining >= ultCD / 2`):

| `jmz_func.lua` 里的守卫 | `ultCD = 0` 时它变成什么 | 方向 |
|---|---|---|
| `J.CanUseRefresherOrb` | `remaining >= 0`,**按构造恒真** ⇒ 冷却这一项**整条蒸发** | **过于宽松** |
| `J.CanUseRefresherShard` | 额外要 `0 - remaining >= 2`,即 `remaining <= -2`,**算术上不可能** | **结构性死分支** |
| `J.GetMostUltimateCDUnit` | `ult:GetCooldown() >= maxCD` 对所有人都是 `0 >= 0` | 退化成「**队列里最后一个合格队友**」,不是冷却最长的那个 |

**实测(§8,194 个带非被动大招的焦点英雄帧):**

| | `ultCD = 0`(改前) | 真冷却(改后) |
|---|---|---|
| `CanUseRefresherOrb` 通过 | **36 帧** | **3 帧** |
| `CanUseRefresherShard` 通过 | **0 帧** | **6 帧** |

⇒ 那 36 帧里 **33 帧(92%)是纯粹的空条款**;而 Shard 那 0 **不是「碰巧没有帧命中」,
是那个表达式唯一可能取的值**。

**可迁移的一条:**「未上规格的 getter 会让守卫变宽松」(或变严格)这类**顺口的方向规则,
在这里无论怎么写都有一半是错的**。分界不在「宽松/严格」,在**那个 0 落在比较式的哪一边**,
而这要**逐个消费者**去看。第一撮(cast range)的方向规则是「缩小搜索环 ⇒ 低估可达 ⇒
制造『这条分支到不了』」;**照搬到第二撮会把符号读反**,§7/§8 各自钉住了自己的符号。

**还有一条没消掉的偏**:条件项仍然不折。但对**冷却**来说条件行是**减免**
(`special_bonus_unique_zeus_6` = `-20%`、神杖行、Octarine),**不折 = 高估冷却** ——
与数值键那边(不折 `+N` 天赋 = 低估)**符号相反**。§8f 钉这一格。
`GetCooldown()` 与 dump 给的 `GetCooldownTimeRemaining()` 是**两个量,互不核对**,
所以某一帧的 remaining **可以合法地大于**这个 base;**不要去断言
`remaining <= GetCooldown()`**(loader 注释里写了)。
