## 2. 缺陷:量纲,不是调参

`X.ConsiderR` branch 1 的 `aoeCanHurtCount` 累加环:

```lua
J.IsInRange( bot, enemy, nRadius * 0.82 - enemy:GetCurrentMovementSpeed() )
```

左边是**单位**。`GetCurrentMovementSpeed()` 是**单位/秒**。位移 = 速度 × 时间 ⇒ 这个表达式携带一个**恰好 1.0 秒**的隐含因子,而这个 1.0 全文件没有人写过。

⚠️ **诚实的那一半,写进产物而不是抹平**:这个技能 KV 里**确实**有一个 1.0 —— `slow_duration` —— 那是爆炸施加的减速**持续时间**,不是「决策到伤害」的时间。所以声称的是 **1.0 在这里是什么意思**,不是「KV 里没有 1.0 这个 token」。`§2.3` 把两半都钉住:既断言 `slow_duration` 仍是 1.0,也断言 helper **不得**从它读时间。

### 这个没写出来的秒值多少

按本文件测试已有的 **835 AoE 锚**(GH #502),底环 = `835 × 0.88 × 0.82` = **602.536u**:

| 移速 | 准入环 `602.536 − speed` | 占底环 |
|---|---|---|
| 300 | 302.5u | 41% |
| 400 | 202.5u | 34% |
| 500 | 102.5u | 17% |
| **≥ 602.6** | **负数** | **`J.IsInRange` 恒假** |

⇒ 超过 ~602 移速这条合取项**不是过滤器是关断器**;在一切**普通**英雄移速上,准入带的大小由**量纲残余**决定而不是由技能几何决定。Turbo 是这条咬得最狠的一半(鞋 / 位移装落地早得多)⇒ gate 是 turbo-only。

## 3. 修法:不发明数字

新 helper `X.cm_GetFieldHurtRing( nBaseRing, nSpeed, hAbility )`:

* 出厂环 `nBaseRing − nSpeed * X.nRHurtHorizonShipped`(`= 1.0`)**先算先绑定先返回**;
* armed 腿把时间**从技能自己身上读** —— `explosion_interval` = **0.1s**。

**依据(验证哲学条件 (c))**:`crystal_maiden_freezing_field` 的 `AbilityCastPoint` 是 **0**、引导期间每 `explosion_interval` 引爆一次 ⇒ 「最早的一次伤害」就在一个 interval 之后,而那正是 `aoeCanHurtCount`(**按它自己的名字**)要问的位移。技能另带 `movespeed_slow` −40 ⇒ 裸速度读数**高估**了对方实际走得多远。

`0.82` 仍然只在**调用点**出现,helper 不许自己再打一份(§1.2 + 变异台 M10)。
