## 1. 结论:`X.ConsiderQ` 的最后一条分支让上游任何收窄都近似空操作

`X.ConsiderQ`(`bots/BotLib/hero_skeleton_king.lua`)按顺序有 8 条返回点,最后一条是:

```lua
--通用消耗敌人或受到伤害时保护自己
if ( #nEnemysHerosInView > 0 or bot:WasRecentlyDamagedByAnyHero( 3.0 ) )
    and ( bot:GetActiveMode() ~= BOT_MODE_RETREAT or #allyList >= 2 )
    and #nEnemysHerosInRange >= 1
    and nLV >= 7
then ... return BOT_ACTION_DESIRE_HIGH, npcEnemy end
```

`nEnemysHerosInRange` = `nCastRange + 43` 内的敌方英雄。于是 **7 级起,任何走进 568 码的敌方英雄
都会在技能一冷却好就吃到 Wraithfire Blast**,不看血、不看击杀判据、不看它是不是团战里最危险的那个。

跑在出货代码上的读数(全部由 `tests/test_wk_considerq_level7_dominance.lua` 从代码里**扫出来**,
不是断言我的算术):

| 量 | 读数 | 来源 |
|---|---|---|
| 击杀判据自称能杀的血量(按 Q 等级) | **126 / 176 / 226 / 277** | 在**5 级**(兜底之下)扫目标血量的开火上界 |
| 落地伤害(魔抗后) | 60 / 75 / 90 / 105 | datafeed 80/100/120/140 × 0.75 |
| 落地 + 整段 dot(魔抗后) | 90 / 135 / 180 / 225 | datafeed 120/180/240/300 × 0.75 |
| **满血敌人**下第一个开火的英雄等级 | **7** | 扫 1..12 级 |
| 兜底分支的射程 | **568** = cast range + 43 | 扫距离 |
| 击杀分支的射程 | **605** = cast range + 80 | 扫距离 |

**四个等级上,自称值同时超过落地值和"站满整段 dot"的上限** —— 虚报是真的,方向也是真的。
但:

- **7 级、568 内**:目标血量从 1 扫到满血,**没有一个值让它闭嘴**(测试断言 silent 集合为空)。
  ⇒ 击杀判据对"这一发放不放"**零影响**,把它改诚实**省不下这个冷却**。
- **5 级、同一条扫描**:有开火也有沉默 ⇒ 上面那条不是空断言,**低等级上判据确实在决策**。

## 2. 更糟的一半:收窄不是"不放",是"改瞄"

两敌帧(满血 sven 在 300 码、列表第一;25% 血 lion 在 400 码):

| 帧 | 出货代码瞄谁 |
|---|---|
| 7 级,lion 在自称带内(250 血) | **lion**(击杀分支答的) |
| 7 级,lion 也满血(900) | **sven** —— 兜底分支答的,取的是**列表第一个** |
| 5 级,lion 在带内 | lion |
| 5 级,lion 满血 | **不放**(底下没有兜底) |

⇒ **在 7 级以上把击杀判据改诚实,等于把同一发停晕从"血最少的那个"挪到"引擎列举的第一个"。**
冷却和蓝一样花掉,目标更差。这是 Lever A 的**代价侧**,§104 §5 没有记录它。

（诚实边界:"更差"这里只按血量说。真实团战里谁是更好的停晕目标本文件判不了 —— 而兜底分支
也没判,它取的是列表顺序。）
