## 2. ⭐ 本轮最该被人读到的:一句价值论证整句都在讲比率,而它实现出来的代码里一个比率项都没有

`X.IsReincarnationReserveIdle`(soak id `wksaveidle`,2026-09-07 落地)的抬头这样论证自己:

> 「等级 6–9 时储备是**池子的大半**(220 对 272–399 的上限),所以『永远扣住』≈『永远不放』。」

**这句话整句是一个比率。** 而它实现出来的释放条件只有两项:血量 `>= 0.95`、1600u 内可见敌方英雄数 `== 0`。
**没有任何比率项,也没有任何 rank / 等级项。**

这一段之所以过关,是因为它**同时**给了自己一条边界:

> 「Note the reserve already collapses on its own at R rank 3, where Reincarnation is FREE
>  (220/110/0)… this lever is about the rank-1/2 window, **not about the late game**.」

**那条边界是假的。** KV 读数(220/110/0)是对的,**结论不对**:

- 本文件**两套 build 行**把 Reincarnation 的**第三点**放在**第 15 位**
  (`{2,1,2,3,2,6,2,3,3,3,6,1,1,1,6}` 与 `{2,1,3,3,1,6,3,3,2,2,6,2,1,1,6}`;第 6、11 位是前两点);
- `tests/test_skill_point_stall_frame.lua` 已把 **GH #366 判成 (a)**:十个英雄(17–22 级)
  **全部**停在 **13 加点 + 至多 1 天赋**,**第 15 位是一堵墙**,
  「其后的一切在任何 26 级以下结束的对局里都到不了」。

⇒ **Reincarnation 永远是 rank 1 或 2,储备是常驻 220 或 110,它从不自己塌掉。**
「不管后期」是**那一段文字的性质,不是代码的性质**——
armed 的 `wksaveidle` 在**每一个**英雄等级上释放这份储备,而它的论证**只在储备是池子大半时成立**。

**`wkidleshare` 补的就是那个缺掉的项,别的什么都不动。**

function X.IsReserveShareHigh()
    if not ( J.IsModeTurbo() and J.IsSoakCandidate( 'wkidleshare' ) )

        return true                      -- 未 armed:不收窄,宿主逐字节不变

## 7. ⛔ promote 这条 id 的动作与惯例**相反**(下一个人最容易踩的坑)

这是 pullcad 陷阱的**反向**版本:pullcad 是「promote 冻死一个 gate」,这里是「promote 删掉一个行为」。
