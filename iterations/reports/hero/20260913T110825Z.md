## 4. `cullthresh` 的域:两带,不是三带(P4.4 (ii) 的那块证据)

queue `hero-2` / `X.IsCullThresholdOn` / `tools/batch_test/behavioral/cullthresh_domain.py`
三处都把域写成三条带 `[250,275) / [350,375) / [450,475)`。

Axe 的 Culling **第三点是 build 行第 15 位**(上表)⇒ **全局 rank ≤ 2** ⇒
**`[450,475)` 是空层**。

- **扫描器本身安全**:它从 dump 读 rank 并打 `rank_hist`,空层只会报 0。
  错的是**预期**:按三带估 power,有三分之一押在取不到的层上。
- ⭐ **第二处收窄压在一个「风险」上**:抬头写着「把 talent8 那一项加进 armed 值会 double-count
  ——**那一天**」。那一天到不了:`talent8` 既被**同层取舍**杀死(一层一个天赋,本行取 [7]),
  又被**本墙**杀死。⇒ **armed 与出货的差是两个可达 rank 上无条件的 +25**(275/375 对 250/350),
  不存在出货值反而更大的状态。

这是**不花钱就能结清的域问题**,已写进 `hero_axe.lua` 抬头(棘轮钉住)与
`queue.json:hero-2`(一行 append,缩进对齐,diff 1 行)。
