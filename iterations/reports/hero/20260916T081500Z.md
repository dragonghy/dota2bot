## 3. 改了什么

新 helper:

```lua
function X.zuus_IsJumpChipHeldForUlt( hBot, hTarget, hAbility )
	if not ( J.IsModeTurbo() and J.IsSoakCandidate( 'zusulte' ) ) then return false end
	return X.zuus_ShouldSaveManaForUlt( hBot, hTarget, hAbility ) == true
end
```

调用点是 `X.ConsiderE` **进攻支路**(`J.IsGoingOnSomeone`)的**最后一个合取项**:

```lua
	and not X.zuus_IsJumpChipHeldForUlt( bot, targetHero, abilityE )
```

闸关或非 turbo ⇒ helper 恒 false ⇒ `not false` ⇒ **出货条件逐字节不变**。

⭐ **方向是收窄**:armed 唯一可达的效果是 HIGH→NONE,**没有任何一帧会因此多出一次
jump** ⇒ 负面波读**只能**读作「被拿掉的那些 jump 比它们在替之攒的大招更值钱」,
不许读作「jump 落点变差」。

⭐ **撤退支路双重豁免,而两条都不是本 helper 自己的功劳**:
(1) 合取项**只落在进攻支路** —— 那是 `X.ConsiderE` 里唯一**有英雄目标**的一条;撤退
支路逃离一个威胁,不向任何人交出目标(§4.2 从源码切片驱动:撤退块里既没有这个 helper,
也没有 `targetHero` 这个名字);
(2) `X.zuus_ShouldSaveManaForUlt` 自己在 `J.IsRetreating` 下返回 false —— 「逃跑优先于
囤积」是那个函数自己的句子,本杠杆碰不到它(§4.1 在真实帧上驱动:先把蓝放进窗口证明
hold 是活的,再翻 `J.IsRetreating`)。

⛔ **不写成 `X.SkillsComplement` 派发点上的一条**(即 `zusultd` 的形状):那需要让
`X.ConsiderE` 多带一个返回值,而 `tests/test_zuus_jump_landing_reach.lua` 有两处按
**字面量** `castEDesire = X.ConsiderE()` 锚着派发行。把合取项放进 `X.ConsiderE` 自己
既避开那两处,又把守卫钉在**唯一有目标的那条支路**上 —— 位置比形状一致更重要。

## 4. ⭐⭐ 本轮最要紧的方法学一条:一个扫了 19 帧的断言,**由构造不可能失败**

初稿的 §5 是一条「对每一帧,armed 的出价 ≤ shipped 的出价」的全语料扫,并在注释里
把自己称作「the direction tripwire」。**它是一个扫了十九帧、而十九次都在比 `0 <= 0`
的循环。** 原因是端到端那一侧在这份语料上**问不出来**(见 §5),两条腿在每一帧都答 NONE。

发现它的是变异台的 **M5**/**M5b**,不是读代码:一个把 `not` 删掉(**杠杆整个反向**,
armed 之后 Zeus **只**跳储备想让他跳过的那些目标)的变异体,**能从那条扫里直接走过去**。

⇒ §5 拆成两半,而且两半都把自己的地位写在自己身上:

- **§5.1 按录制原样**:19 帧,两条腿全 NONE,**它自己写明这是 0 ≤ 0 扫十九遍、
  M5 会从它身上走过去**;它保留下来的理由是它记录了 §6.2 那个零。
- **§5.2 声明式反事实**:注入 `J.IsGoingOnSomeone` 与 `J.GetProperTarget`(两者都是
  loader 按构造答不了的),**目标取该帧自己最健康的可见敌方英雄** —— 一具**真实身体、
  真实血量**,不是造出来的。其余一切(蓝、大招 rank、大招 CD、jump 可施放性、距离、
  那个敌人的血)全部原样来自帧。

**§5.2 的读数(⚠️ 反事实,引用必须带这三个字)**:

| 量 | 值 |
|---|---|
| shipped 出价 HIGH 的帧 | **2** |
| armed **翻转**的帧 | **1** — `f_260819_222052_zuus_w2_leak`(Zeus **152/812** 蓝,大招 rank 1 就绪、价 250,shadow_shaman **满血**) |
| 不翻转的那一帧,**理由具名** | `f_260909_215227_zeus_bolt_od_1084`:Zeus **1496/1496** 蓝 ≥ 大招价 375 ⇒ **储备自己让路**(「nothing is being denied」) |

⭐ **第三行是负对照,不是余数**:没有它,「2 里翻 1」同样可以是 helper 在乱答。
**M12**(把注入的目标换成 nil)专打 §5.2 自己的 liveness,证明它不会**悄悄地**变回
和 §5.1 一样空。

**不是反事实的是那条不等式本身** —— 「armed ≤ shipped」在 §5.1 与 §5.2 两处都断言,
它是本杠杆「只收窄」那句话的全部内容。

## 5. ⛔ 端到端域 = 0,而这是 **UNASKABLE 不是读数**(`-185` 的裁定原样适用)

`J.IsGoingOnSomeone` 读 `bot:GetActiveMode()`。该 getter 在 `tests/mock/` 下**没有 spec**,
于是落进 `bot_api.lua` 的 `key:find('^Get') then return 0` 兜底 —— 而 **0 根本不在
BOT_MODE 名字空间里**(loader 里 `BOT_MODE_NONE=1001` / `ROAM=1004` / `ATTACK=1003` /
`GANK=1170` / `TEAM_ROAM=1016` / `DEFEND_ALLY=1018`)。

⇒ **这台仪器在整个语料上没有任何一个对象能给出阳性对照**,所以它的 0 不是读数。
这与 `-185` 在 `J.IsFarming` 上立的那条**是同一条**,只是这次证明更便宜:不需要 1314
个 subject 的横扫,**loader 服务的那个值根本不在被比较的那个集合里**。§6.2 驱动这条,
**M13**(把 mode 读数换成一个真的 `BOT_MODE_ROAM`)反向钉住 —— 它存在的理由是:哪天
loader 学会回答这个 getter,这个文件必须**自己举手**,而不是继续把一个已经可读的零
叫作 UNASKABLE、继续让 hero-95 去买一个已经变便宜的问题。

**helper 层域(真实帧,非反事实)**:

| 量 | 值 |
|---|---|
| Zeus-subject 帧 | **19**(11 个 `tests/fixtures/` + 8 个 `tests/frames/`) |
| helper 扣住 ≥1 个敌人的帧 | **3** |
| 被扣住的 (帧, 敌人) 对 | **12** |

⛔ **这 3 / 12 不是频率。** 这批 Zeus 帧多半就是为储备本身采的(`ult_denied` /
`ult_manalock` / `ult_hoard` / `reserve_cross` / `reserve_safe` / `w2_leak` 六个文件名
自己就写着),**按构造富集在本杠杆关心的状态上**。把「这份样本里 3/19」写成「游戏里
16%」正是 `hero-27` 那份归档扫描量出来的 5.3× 高估。频率是 `hero-95`。
§6.1 把两个数都写成**一路走的绊线**(⛔ 不是达标线),**M10**(把
`X.nUltSaveHealthFloor` 从 0.6 挪到 0.3)与 **M11**(把 §6.1 的循环喂一个空语料)
从两侧钉住 —— 后者是因为**空 `for` 一个 assert 都不执行**,一个「驱动」了零个对象的

## 11. ⚠️ 一条容器层面的教训,记下来免得下一轮重学

**`until ! pgrep -f 'lua_gate.py'; do sleep; done` 是一个永不结束的等待,因为它匹配到自己。**
本轮为了守 GH #229 / #848(多个读者共用 `soak_side.lua`,并行造假红)而等闸腿跑完,
用了这个写法 —— `pgrep -f` 匹配**整条命令行**,而等待循环自己的命令行里就写着
`lua_gate.py` ⇒ **它把自己数进去,于是永远认为「还在跑」**。三个这样的等待挂在那里,
`ps aux` 里**一个真正的 gate 进程都没有**。

⇒ 用 `pgrep -af` 打出**匹配到的是谁**再信它。这与本轮 §4 的头条是**同一个形状**:
一个断言/守卫看起来在守某件事,而它实际读的是它自己 —— 前者是 `0 <= 0` 扫十九遍,
后者是「等一个只有我自己的进程集合变空」。**两者都只有把读数打印出来看一眼才会露馅。**
