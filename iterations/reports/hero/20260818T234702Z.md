## What I found
`bots/mode_retreat_generic.lua`'s WK-specific teamfight retreat-suppression
("Reincarnation is armed, don't flee, stand and fight") used a **hardcoded**
`bot:GetMana() >= 160` check:

```lua
if bTeamFight and botName == "npc_dota_hero_skeleton_king" and bot:GetLevel() >= 6 then
    local abilityR = bot:GetAbilityByName("skeleton_king_reincarnation")
    if abilityR:GetCooldownTimeRemaining() <= 1.0 and bot:GetMana() >= 160 then
        return BOT_MODE_DESIRE_NONE
    end
end
```

Reincarnation's real trigger cost is level-dependent and **decreasing**
(skill level 1/2/3 ≈ 220/110/0 mana, per Liquipedia, checked 2026-08-18).
At skill level 1 — which covers hero levels 6-11, most of WK's midgame — the
real cost is **220**, well above the hardcoded 160. So the check falsely
reads "armed" with only 160 mana: WK holds a losing fight believing it has a
free life, dies for real without reincarnating, and feeds. This lines up
exactly with the backlog's framing and with `hero_skeleton_king.lua`'s own
`X.ShouldSaveMana`, which already uses `abilityR:GetManaCost()` correctly for
the same ability — the retreat-logic copy just never got the same treatment
(inherited upstream code, not something this project added).

The unused `nKeepMana = 160` local in `hero_skeleton_king.lua` appears to be
the origin of the same magic number, declared but never read in that file —
left alone (out of scope; not a behavior bug on its own).

## Fix (gated, `wkreincarnmp`)
- New `J.IsWkReincarnationArmed(bot)` in `bots/FunLib/jmz_func.lua`: default
  path stays the literal 160 (byte-identical to shipped behavior); the
  corrected path (`bot:GetMana() >= abilityR:GetManaCost()`) only runs when
  turbo **and** soak-candidate `wkreincarnmp` is armed.
- `mode_retreat_generic.lua`'s inline check now calls the helper instead of
  repeating the magic number.
- Registered in `iterations/state.json` (`wkreincarnmp_20260818`) and in
  `iterations/streams/hero.md` backlog/当前状态.
