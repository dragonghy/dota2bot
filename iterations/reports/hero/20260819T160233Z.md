## 4. 修复(gated `zusult`,turbo-only)

`bots/BotLib/hero_zuus.lua` 新增 `X.zuus_ShouldSaveManaForUlt(hBot, hTarget)`,
消费点在 `X.SkillsComplement` —— 就是 `castQDesire` / `castWDesire` 变成**最终
出价**的那一行(总监 §0b 的要求)。全部满足才压住这次施放:

- turbo + `J.IsSoakCandidate('zusult')`;
- 大招**已学**、**冷却 0**、耗蓝 > 0;
- `hBot:GetMana() < 耗蓝` —— 大招**确实被蓝卡住**。已经放得起就什么都没被剥夺,
  门当帧无效(这条让门在"够蓝"的绝大多数帧上结构性沉默);
- **不在撤退**(`J.IsRetreating`)—— 逃命大于攒蓝;
- 目标是**敌方英雄**(小兵走线上原有规则,**不碰补刀/farm**);
- 目标血量比例 **>= `X.nUltSaveHealthFloor` = 0.6** —— 只挡 chip,不挡斩杀。

门关闭时函数**第一行** return false,线上字节级不变。

**理论依据(验证哲学条件 c)**:Thundergod's Wrath 是 ~130 秒冷却的全图终结技,
也是 Zeus 手上**唯一够得到走不过去的目标**的东西 —— 它的耗蓝是**储备**,不是零钱。
往满血目标身上打 chip 是这笔储备最差的用法:本局里那 143 蓝造成的伤害被对方
20 秒内回满,而储备本身花了 83 秒才靠回蓝重建。"给大招留蓝"是标准打法。
两个豁免口保证这道门永远不会挡住比储备更值钱的东西:已经在斩杀线下的目标是
**到手的人头**(大于以后的一次 snipe),撤退时生存大于囤积。

## 6. 顺带补的共享管线(dev-only,非行为改动 —— 总监 §F 那一类)

`tests/mock/replay_fixture.lua` 两处保真度缺口,**都是"验收世界本身是退化的"**:

1. **`IsTrained` / `IsCooldownReady` / `IsFullyCastable` 之前是加载时冻结的布尔,
   而且 `IsFullyCastable` 完全不看蓝** —— 于是一个 246 耗蓝的大招在只有 190 蓝
   的手里读作"完全可施放",**而这正是线上 `ConsiderR` 掉头就走的唯一原因**。
   现在改成对活的 spec 求值的函数(等级、冷却、以及持有者的蓝 vs `GetManaCost`)。
   mock 里 `GetManaCost` 默认 0,所以**46 个既有 fixture 行为不变**(已验证)。
2. **`bot:FindAoELocation` 返回通用 `Get*` 默认值 0**,而每个调用方都要索引
   `.count` / `.targetloc` → 完整跑一遍英雄脚本(`SkillsComplement`)会在到达
   被测决策**之前**崩掉。现在返回**保守形状** `{count = 0, targetloc = 自己位置}`
   ——宁可少报 AoE 机会,不凭空造一个。需要簇的测试自己覆盖 spec。

第 1 条如果没修,本轮全部端到端断言都会是**假绿**。

   `J.IsGoingOnSomeone` + `J.GetProperTarget`,也就是 `GetActiveMode()` 和当前
   攻击目标,**dumper 两个都不记**;未经改动的帧上每个技能都出价 NONE,门对
   最终决策的影响**不可观测**。所以那三例把 Zeus 置于 `BOT_MODE_ATTACK`、目标
   设为**他当时确实在打的** dragon_knight,并锚定两个骚扰施法距离
   (Arc Lightning 900 / Lightning Bolt 700,Liquipedia)。**门自己读的每一个量
   都仍是真实帧数据**,并由 ground truth 那几例直接断言。同 `cmrguard` 撞的
   离线缺口,GH #27 家族。
3. **本地验证只回答"这个决策对不对",不回答"整体是否更好"** —— 饿着 Zeus 的
