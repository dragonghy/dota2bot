## 2. 缺陷:两个列表,读错一个,而且错的方向是**唯一那条**

`bots/BotLib/hero_axe.lua` `X.ConsiderR`:

```lua
local nCastRange = abilityR:GetCastRange()                              -- 实测 175
local nInRangeEnemyList = J.GetAroundEnemyHeroList( nCastRange )        -- 175  ← 死局部
local nInBonusEnemyList = J.GetAroundEnemyHeroList( nCastRange + 200 )  -- 375  ← 循环读它
...
for _, npcEnemy in pairs( nInBonusEnemyList ) do          -- 循环体里没有任何距离项
    ... return BOT_ACTION_DESIRE_HIGH, hCastTarget, sCastMotive
end
```

三条证据,合起来说明 `+200` 是失误不是策略:

1. **正确作用域的那个列表就在上一行,而且是死的。** 作者两个都算了,读了错的那个。`luacheck` 看不见它(`.luacheckrc` 只开 `only = {"1"}`,即全局访问类),这就是它活到今天的原因。
2. **这个文件里其它每一处到达都比原值更紧。** `X.ConsiderQ` 的打断循环 `nRadius - 50`、先手分支 `nRadius - 90`、带线嘲讽 `nRadius - 50`、打野嘲讽 `nRadius - 50`。**`hero_axe.lua` 里只有这一处加。**
3. **兄弟绊线自己写过这句话。** `tests/test_axe_culling_threshold_preflight.lua` §3 的原文:「the bare cast-range list is computed and never read … registered here, not fixed: **it is a separate lever with its own domain and its own cost side**」。本轮写的就是那条 lever。

### 代价的机制是**压制**,不是那段路本身

`X.ConsiderR` 是 `X.SkillsComplement` 的**第一臂**,而且出价 > 0 就无条件 `return`:

```lua
castRDesire, castRTarget, sMotive = X.ConsiderR()
if castRDesire > 0 then ... bot:ActionQueue_UseAbilityOnEntity( abilityR, castRTarget ); return end
castQDesire, sMotive = X.ConsiderQ()     -- 嘲讽,半径 315
castWDesire, castWTarget, sMotive = X.ConsiderW()
```

⇒ 只要 band 里站着一个低于斩杀线的敌人,**整段接近过程中** `X.ConsiderQ`(Berserker's Call,半径 **315**,把 (175, 375] 这个 band 几乎整个包住)与 `X.ConsiderW` **一次都不被问到**。被压掉的问题恰好是「**我正走过去的这个目标,要不要先嘲讽住**」—— 而 Call → Cull 是这个英雄的标准顺序。

⚠️ **回血那条论证本轮不采用,理由写在这里以免后人捡起来**:循环给目标 `GetHealthRegen() * 0.8` 秒的回血余量,而 200 码的路 + 0.3s 出手前摇 ≈ 1.0s > 0.8s。**但差额只有 ~0.2s**,Turbo 里换算成血量是个位数;更要紧的是语料里 `GetHealthRegen()` **恒为 0**(§9 断言),所以这条离线**根本量不了**。它是脚注,不是理由。

## 3. 修法:`axecullreach`(turbo-only,未 armed,STANDALONE)

```lua
function X.IsCullReachOn()
	return J.IsModeTurbo() and J.IsSoakCandidate( 'axecullreach' )
end

function X.CullTargetPool( tInRangeEnemyList, tInBonusEnemyList )
	if X.IsCullReachOn() then return tInRangeEnemyList end
	return tInBonusEnemyList
end
```

`X.ConsiderR` 的循环改成 `pairs( X.CullTargetPool( nInRangeEnemyList, nInBonusEnemyList ) )`。**目标选择规则、血量判据、免疫/Aegis/特殊 modifier 各条否决一个字没动。** 闸关时返回 `tInBonusEnemyList`,**逐字等于出货**。

- **方向(函数内部):NARROWING,严格子集,由构造保证不是由今天的数据保证** —— 两个池由**同一个** `J.GetAroundEnemyHeroList` 用**更小的半径**建 ⇒ armed 池 ⊆ 出货池。§5 在语料 **33** 个 Axe 帧上逐帧驱动断言了这件事(不是论证)。⇒ 本 id **只能删掉一次 Culling,永远不可能新增一次**。
- ⛔ **英雄层面不是纯 narrowing,这一条必须一起引用**:被拒的那一帧接着落到 `X.ConsiderQ` / `X.ConsiderW`,它们**可能开火** —— 这**正是杠杆的目的**。⇒ **「armed 的 Axe 施法更少」不是本 id 的预测**,按这个量读数是读错了东西。已写进 `hero-46` 的 `acceptance` 预登记。
- **STANDALONE**:`X.IsCullReachOn` 里只有一个 `IsSoakCandidate`,**不与 `cullthresh` / `axecull` 合取**(pullcad 陷阱)。变异台 **M10** 就是把 `cullthresh` 合取进来那一条,§8 抓住。

### ⭐ 搬家陷阱:这次是最干净的一种

`lionrreach` 的教训是「只过滤一个落单点会把 dive 搬家而不是移除」。这里**不成立,而且是查过的**:`X.ConsiderR` 全函数**只有一条开火分支**,其后直接 `return BOT_ACTION_DESIRE_NONE` ⇒ 函数内部**没有任何下游落单点**能接住被拒的 band 目标。§6 把「恰好一条」钉成**计数断言**(不是位置比较 —— wkqaim 那轮学过:「cast 排在 guard 后面」被任何追加分支满足);变异台 **M7** 在源码里插入第二条开火分支,被它点名抓住。

## 7. 两条限度,写成**断言**而不是散文

1. **「嘲讽会改为开火」这一半本轮没有被帧驱动。** `X.ConsiderQ` 的每条分支都挂在 mode 谓词(`J.IsGoingOnSomeone` / `IsPushing` / `IsFarming`)后面,fixture 世界结构性恒假 ⇒ 三帧上 `X.ConsiderQ` **armed 与否都答 0**。能机器核验的只有**压制**这件事:§7 读 `X.SkillsComplement`,断言 R 臂排在 Q 臂之前**且无条件 `return`** —— **源码级,并且如此标注**。断言写成「哪天 fixture 长出 mode 状态,这里就变红,**退休这条限度、不要删断言**」。
