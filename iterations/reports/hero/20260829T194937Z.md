## 2. ⭐⭐ 候选 1 是真的,而且是**三条**过滤器不是一条

`X.lion_ShouldStopDrain`(`hero_lion.lua:1390`)的域判据只有一句
`#J.GetNearbyHeroes( hBot, 500, true, BOT_MODE_NONE ) > 0`。展开:

```
J.GetNearbyHeroes            jmz_func.lua:2755   bot:GetNearbyHeroes(...)   ← 引擎侧本身按视野给敌人
  └ J.IsValidHero            jmz_func.lua:3262

          └ Utils.IsValidUnit utils.lua:541
```

⇒ **检测器的谓词是全知的,门的谓词不是。** 两者是不同的集合,差集恰好是
`{我方看不见的、无敌的}`(死的那一条两边都有)。

## 3. ⭐⭐ 为什么 issue 提议的验收方式判不了它

`tests/mock/replay_fixture.lua:89` 的 fog 模型是**对的**:

```lua
local function visible_to_team(u, team)
    if u.seen_by == nil then return true end   -- v1 fixtures omit seen_by: fully visible
    ...
```

`make_fixture.py:307` 从快照的 `vis` 键填 `seen_by`。**问题在生产端:**

- **dumper 不写 `vis`。** `dumper/main.go:794` 自己的 `vision_note` 就是理由:
  「Source2 录像里不存在 per-team fog bitmask(没有 `m_iTaggedAsVisibleByTeam`),
  视野必须从视野**来源**重建」。
- 于是 `s.get("vis") or []` 永远是空,`seen_by` 永远不写进 fixture。
- **实测:107 枚 fixture,带 `seen_by` 的 = 0。**
- ⇒ 每一枚 fixture 都是**全可见世界**,`CanBeSeen()` **按构造恒真**。

**所以在 t=200.4 钉一枚 fixture、断言 `lion_ShouldStopDrain == true`,一定会绿——
不论那一瞬间 bot 到底看没看见那个 spirit_breaker。** 那个绿是量具给的,不是挣来的。

**这是 -45(`ZERO_TRUE`,GH #306)那条教训在一个新地方原样重演**:
决定断言的那个 mock 数据**在帧的上游**。区别只在上一次是「恒 0 的伤害」,
这一次是「恒真的可见性」。

`vis` 这个键现在是 **两个消费者、零个生产者**
(`make_fixture.py:307`、`build.py:356`,后者的 `has_fog` 因此恒 False)。
另有两个检测器的注释(`cmrguard_counterfactual.py:62`、`es_aftershock_domain.py:77`)
**已经写着这件事**并挂在 GH #27 上——`lion_drain_census.py` 没有那句注释,
而它是本轮这条读数的出处。

## 4. ⭐ 候选 2 被算术排除掉了

issue 的候选 2 是「`X.SkillsComplement` 在那些 tick 上根本没被调到」。
从 tick 到 `X.ConsiderStopDrain`(`SkillsComplement` 的**第一句**,
刻意排在 `J.CanNotUseAbility` 早退之前)之间,**唯一的节流**是

```lua
-- ability_item_usage_generic.lua:8641  AbilityUsageThink
if DotaTime() > 30 and (DotaTime() - bot.lastAbilityFrameProcessTime
    < (bot.frameProcessTime * (1 + Customize.ThinkLess))) and bot.isBear == nil then return end
```

两个因子在本树里都是常量:

- `FrameProcessTime = 0.06`(`utils.lua:873`),`SetFrameProcessTime` 再加
  `fmod(playerID/1000, 0.006) * 3 < 0.018` ⇒ 每 bot **≤ 0.078**;
- `Customize.ThinkLess = 1`(`Customize/general.lua:127`;各 mode 文件再写一遍
  `Customize.Enable and Customize.ThinkLess or 1`,**两条路都是 1**)⇒ 乘子 = 2。

⇒ **最坏间隔 < 0.16s**。而 GH #314 的两条 channel 从谓词首次成立到自然结束是
**3.7s**(199.4→203.1)与 **1.8s**(462.4→464.2)。**差一个数量级以上。**
「那几个 tick 没被调到」**不可能**是这两条的故事。

候选 3(`Action_ClearActions( true )` 对该 channel 无效)**本轮没碰**:
它要引擎(AGENTS.md 铁律:no bot-side debugging)。
