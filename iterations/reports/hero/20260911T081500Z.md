**归族**:GH #724 `anyhero` / GH #731 `lvlany` / GH #741 `zusjumpany` 的**全称方向**。
那三条是「**存在**量化被交给最近的那个」,这一条是「**全称**量化被交给最近的那个」。
与 GH #731 同款,**名单是正确排序的**(`GetNearbyLaneCreeps` 按距离升序),
所以**「把名单排好」修不好它**。

⭐ **而距离序在这里是对抗性的,这是本轮买到的那半**:圣坛只保护**施法瞬间在场**的兵、
持续 5s。所以一个环里**混着两拨兵**的情形,恰恰发生在**有一只新来的兵贴到 bot 身上**的
时候 —— 而 `[1]` 按定义点名的就是**最近**那只,也就是**最可能是那只新来的**。
出厂代码把全称问题交给了环里**最可能和其余成员答得不一样**的那一个成员。
「多数情况下圣坛是整队一起上、所以 `[1]` 约等于全体」是真的,**它只是把这个缺陷的域压小,
不改变它的方向**。

## 2. 修法与安全论证

`bots/FunLib/jmz_func.lua` 新增 `J.IsGlyphVetoClear( tUnits )`:

- gate off:**逐字节**是出厂的 `return not tUnits[1]:HasModifier( 'modifier_fountain_glyph' )`
  —— 同一次调用、同一个实参、同一个顺序。
- armed(`J.IsModeTurbo() and J.IsSoakCandidate('glyphany')`):对整张名单量化。
- **只命名一个 id**(pullcad 陷阱),§4 钉住。

**方向有保证,这就是全部安全论证**:`not any(P)` 蕴含 `not P(tUnits[1])`(只要 `[1]` 在)
⇒ armed **只能撤回**一次出厂会做的施法,**永远不会新增一次**。与 `wkqdmg` 同形,纯收窄。

⛔ **只接了三个焦点站点。** `[1]` 这个子类全树约 **22 个活站点**(`§1` 的方向安全下界),
其余在别组的文件里,**故意不动** —— 一个杠杆,本组作用域。第四个调用方会**悄悄扩大这个
gate**,所以 §4 把调用方集合钉死。

## 3. ⛔ 域离线量不出来 —— 两个独立的量具原因,两个都写成了会红的断言

全 141 个冻结帧(`tests/frames/` + `tests/fixtures/`),每文件驱动一个活体英雄主体,
2026-09-11 实测:

1. **`GetNearbyLaneCreeps` 不在 `tests/mock/replay_fixture.lua` 的任何 spec 上**
   ⇒ 落进 loader 的默认兜底,**141/141** 个主体答**空表** —— **包括那 32 个确实带
   `creeps` 采样的文件**。两条腿因此在每一帧上都静默,而且**静默得一模一样**。
2. **就算把 (1) 修好也还是问不出来**:一条兵采样是 `{ team, x, y, dt }` ——
   **没有名字、没有血量、没有 modifier 列表** ⇒ 圣坛谓词无处可读。
   **只修 (1),会把一句诚实的「看不见」变成一句自信的、错的「没有兵被保护过」。**

⭐ 这是 `-147` 那条教训(GH #741「假 0 也要写成会红的断言,不能写成脚注」)的直接应用:
`§3` 把**两个**读数都断言住(`nWithCreeps == 0` / `nWithModifiers == 0`,并各配一条
「量具还在工作」的下界),哪天任一量具长出来,**它自己红并点名**,而不是让那个 0 被读成
一个测出来的域。

**另有一条硬约束,写在 `admission` 里**:三条支路全部坐在**正向 mode** 闸后面
(`J.IsPushing` / `IsFarming` / `IsDefending`),而 mock 的 `GetActiveMode()` 答 0
⇒ **离线一帧都跑不到**。(a) 只能靠真实对局买。
