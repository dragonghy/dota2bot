## 3. 钉法:一个数字只有一个来源

`tests/test_focus_level_claims.lua`。每条 claim 带一个 **needle 模板**,`%d` 由
`rank_ladder` 填,填完要求在文件里**逐字出现且恰好一次**:

```lua
{ name = 'axe t10: Battle Hunger is rank 4 from level 11, not 10',
  file = 'bots/BotLib/hero_axe.lua',
  fmt  = "rank 4 from level %d (the row's 10th entry",
  parts = { { AXE, 2, 4 } } },
```

于是两个方向都堵死:**手改散文** ⇒ 对不上;**改 build row** ⇒ 等级变了、散文对不上,
逼人回去重读那段定价。形状同 `test_gate_claim_consistency.lua`(不许注释声称一个不存在的 gate)。

顺带给 `tests/skill_level_map.lua` 加了两样(不改既有语义,三个老消费者原样绿):
* `build_row(src, which, sTable)` —— 第三参可读 WK 那张**gated 的** `tKillBuildList`
  (它的定价散文同样在做等级声明,以前没有任何读者够得到);
* `rank_ladder(hero, row, talents)` —— slot → {每一 rank 的英雄等级},驱动一次得全表。

**两条 LIMIT 写在文件头**:
1. 只钉**等级**那一半。slot → 技能**名**只在英雄文件自己用 `abilityQ/W/E/R = sAbilityList[n]`
   绑定的地方能断言(axe/lion/zuus,已断言);
2. **WK 完全按硬编码名绑,slot → name 离线没有任何证据** —— 且**故意不从 fixture 语料重建**
   (dump 顺序 ≠ slot 顺序,GH #151 + `gen_ability_meta.py` 的常设 LIMIT)。
   所以 WK 的 claim 钉成**关于 build-row 下标**的 claim —— 这也正是那个文件自己的措辞
   ("Wraithfire Blast (index 1, the only lockdown)")。第三个用例把"WK 现在还是按名绑"
   这件事**也**断言了:哪天有人改成按下标绑,测试会红并提示**补上**那条腿,而不是删用例。

## 5. ⚠️ 本轮的量测事故(如实记)

变异脚本的判定写成 `case "$out" in *"0 failures"*)` —— 而 **"10 failures" 里含子串 "0 failures"**,
于是 M8 被打成 **ESCAPED**,实际是 **CAUGHT(10)**。改成 `sed` 取数后复跑确认。
两个 no-op 对照第一次也没跑成:`grep -qF "$from"` 的模式以 `--` 开头被当成选项,要 `grep -qF --`。
**留给后来人**:变异脚本的**判定语句本身**要先在一个已知红/已知绿上验一次;
子串匹配在计数上是错的工具。
