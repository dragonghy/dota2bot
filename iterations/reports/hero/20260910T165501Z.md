## 2. 缺陷:合格判据在同一个 `if` 里,被同一个 `if` 自己短路

`bots/BotLib/hero_lion.lua` `X.ConsiderQ` 的 `--常规` 兜底支路,第一行:

```lua
--常规
if ( #hEnemyList > 0 or bot:WasRecentlyDamagedByAnyHero( 3.0 ) )
    and ( bot:GetActiveMode() ~= BOT_MODE_RETREAT or #hAllyList >= 2 )
    and #nInRangeEnemyList >= 1
    and nLV >= 15
```

第一个括号里的两半**不是同一个想法的两种写法**:

* 右边是**交战判据** —— 三秒内真的有人打过 Lion;
* 左边是**纯粹的距离计数**。

而左边**被同一个 `if` 的第三条合取项蕴含**:

| 名字 | 出处 | 半径 |
|---|---|---|
| `hEnemyList` | `X.SkillsComplement`:`J.GetNearbyHeroes(bot, 1600, true, BOT_MODE_NONE)` | 1600 |
| `nInRangeEnemyList` | `X.ConsiderQ`:**同一个 helper**、同一套过滤器 | `nCastRange` |

同一个 helper ⇒ 同一套过滤器(`J.IsValidHero` / `not J.IsMeepoClone` /
`not bot:HasModifier('modifier_arc_warden_tempest_double')`,最后一项还是对 **bot** 自己判的,
两次一模一样)⇒ 只要 `nCastRange <= 1600`,
`#nInRangeEnemyList >= 1` **强制** `#hEnemyList > 0`。
`or` 从左边短路 ⇒ **那条交战判据对任何输入都不会被求值一次**。

⭐ **这个括号恒真。这条支路开火的理由只剩「附近有人」。**

### 同族第三形

| id | 合格判据在哪 | 为什么问不到 |
|---|---|---|
| `cmqpoke`(GH #698) | **另一条支路**,排在下面 | 上面那条钱包支路永远先赢 |
| `wkqodds`(GH #708) | **本支路里**,mode 析取式右边 | 只有撤退时才被求值 |
| **`lionqfight`(本轮)** | **同一个 `if` 里** | 被本 `if` 自己的另一条合取项**结构性短路** |

前两条是「很少问」,这一条是「**一次都不问,对每一个输入**」。
**合格的判据不是从文件里缺席,是从这条支路里缺席** —— 这次连「缺席」都不对:
它**写在那儿**,只是永远轮不到它说话。

## 3. ⭐ 蕴含关系是算术,而余量比看上去小

「`nCastRange <= 1600`」不是拍脑袋,是从技能自己的 KV 阶梯上算出来的,
而且它**没有想象中宽**:

```
nCastRange = abilityQ:GetCastRange() + aetherRange + 20
```

| 项 | 值 | 出处 |
|---|---|---|
| `AbilityCastRange` 基值 | 650 | `lion_impale` KV |
| `special_bonus_unique_lion_2` | **+600** | 同一条 KV 的 bonus |
| `aetherRange` | **250** | 本文件交给 `J.GetAetherLensRangeBonus` 的数(比物品 KV 的 **225 多 25**) |
| 本函数自己的 `+ 20` | 20 | `X.ConsiderQ` |

**全阶梯最坏:650 + 600 + 250 + 20 = 1520 —— 距 1600 只有 80 个单位。**

按**出货天赋树**则完全不接近:`tTalentTreeList['t25'] = {0, 10}` 取的是**奇数项**
(+250 AoE 变羊),**永远不取那个 +600 施法距离** ⇒ 真实上限 **920**,余量 **680**。

两个数都钉在 `tests/test_lion_q_field_engagement.lua` §1.3 / §1.4:
补丁动了 Impale 的施法距离、动了那条天赋、或者把 t25 换成偶数项,**这里就红**,
而且红的是「蕴含关系还成不成立」这句话本身,不是一个装饰性的常量。

## 4. 改动:`lionqfight`(gated,turbo-only,未 armed)

```lua
X.nQFieldDamageWindow = 3.0

function X.lion_IsFieldImpaleEngagementOk()

	if J.IsModeTurbo() and J.IsSoakCandidate( 'lionqfight' )
	then
		return bot:WasRecentlyDamagedByAnyHero( X.nQFieldDamageWindow )
	end

	return true

end
```

调用点只**追加一条合取项**,出货那一行(含那个恒真的括号)**一字未动** ——
删掉它会是另一件事、另一批读者(本文件被若干按源码文本读的普查扫描)。

* **不发明阈值**:谓词和 `3.0` 都是**这条支路第一行自己写着的那一项**;
* **不点名任何兄弟 id**(pullcad 陷阱:合取一个别的 id,那个 id 被 promote 当天本闸恒假);
* **方向是代码属性不是数据属性**:armed = 出货条件 **AND** 一项 ⇒ armed 的开火集
  对**任何**输入都是出货集的子集。**只能少放一发 Impale,永远加不出一发。**
  负向波次读数只能归因于「被扣下的那些控值得放」。

**条件 (c)(逻辑依据)**:`lion_impale` 是 14/13/12/11s 冷却的直线控(1.3–2.2s),
90–150 蓝,是 Lion 打出「变羊 → 手指」这条链子**唯一可靠的起手**。
`X.ConsiderQ` 里其余每一条对英雄的开火点都说得出这一发是**为了什么** ——
确认击杀、三人 AoE、团战、自己宣告的目标、撤退时刚打过我的那个人。
只有这一条说的是「我 15 级了,射程里有人」。长冷却的位移型控在辅助手上**留给一次接团**
是标准打法;而这条支路的作者**把这句话写下来了**,只是它永远不会被读到。
