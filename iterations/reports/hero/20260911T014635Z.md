## 1. 缺陷:为什么它能活这么久

```lua
local nEnemyLaneCreeps = bot:GetNearbyLaneCreeps(888, true)
local nEnemyTowers     = bot:GetNearbyTowers(888, true)
local nEnemyBarracks bot:GetNearbyBarracks(888, true)      -- ← 少了 `=`
local sEnemyTowers bot:GetNearbyFillers(888, true)         -- ← 同样
```

Lua **不拒绝**这一行。它读成**两条语句**:一条声明(`nEnemyBarracks = nil`)+ 一次
**独立的函数调用,返回值丢掉**。于是:

| 推送路径上的工具 | 它说了什么 |
|---|---|
| Lua 加载 / `tests/test_smoke_load.lua` | **绿**(文件加载得动) |
| `luacheck`(铁律 6 静态半) | **绿** —— 名字确实在下面被用到,既不是 unused 也不是 undefined |
| 引擎 | **照常收费**:两次 `GetNearby*` 查询每帧照跑,答案照扔 |
| 读它们的两个析取项 | `nil ~= nil` ⇒ **自打字那天起,每一帧都是 false** |

⭐ **这个缺陷的全部签名,就是「一条支路比它的源码读起来更安静」** ——
而那正是本组花了好几轮买真实帧才看得见的那个形状(`cmqpoke` / `wkqodds` / `lionqfight` 同族)。
区别在于:前三条是**判据问不到**,这一条是**赋值根本没发生**,而且**没有任何工具会提一个字**。

**行为后果**(可检索的标准打法佐证条件 (c)):Arc Warden 的磁场(W)给范围闪避 + 攻速,
标准用法就是**攻城时开在队伍身上**让大家安全地拆建筑。当前这条支路只为
`creeps >= 3` 或**活着的塔**开火 ⇒ **T3 一倒、攻城真正开始的那一刻,磁场正好闭嘴**。
Turbo 里塔更脆、抱团推进收益更高,这个洞在 Turbo 下比在正常模式下更贵。

## 2. 类关闭:17,548 条声明,命中恰好 2 条

全称扫描(`bots/` + `game/`,全部 `.lua`),判据是**对每一条 `local` 声明**的性质:
名字列表之后**只能**跟 `=` / `,`(名单换行续写)/ 行尾 / `;` / `--`;
跟别的任何东西,就说明 `=` 掉了。

```
scanned 17548 local declarations, 2 with a dropped `=`
BAD bots/BotLib/hero_arc_warden.lua:412: local nEnemyBarracks bot:GetNearbyBarracks(888, true)
BAD bots/BotLib/hero_arc_warden.lua:413: local sEnemyTowers bot:GetNearbyFillers(888, true)
```

⇒ 本轮**不是**「维护一个已知 bug」,是**类关闭 + 站岗**。
下一个实例的代价不是「一条支路错了」,而是「一条支路错了,而推送路径上没人会提它」。

## 3. 改动:赋值无条件落地,加宽那半 gated

`bots/BotLib/hero_arc_warden.lua`,`X.ConsiderMagneticField`:

  `bStructuresCount = J.IsModeTurbo() and J.IsSoakCandidate('awraxfield')`,

**gate off 与出厂逐字节等价,而且是算术不是论证**:
出厂那两项求值 `nil ~= nil` ⇒ false;gate off 求值 `false and ...` ⇒ false。
**同一个值、同一次短路、同样的调用次数与顺序**(两次引擎查询在两个版本里都无条件执行,
只是一版把答案扔了、一版存进局部)。出厂就活着的 creeps / towers 两条析取项
**一字不动,且仍排在前面**。

⚠️ `sEnemyTowers` 装的是 **fillers 不是 towers**。名字是错的,但**本轮不改** ——
issue 正文按这个名字引用它,同一个改动里静默重命名会让那条引用解析不了。已在源码注释里点名。
