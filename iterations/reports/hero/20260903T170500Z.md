## 2. 缺陷:一个数,两个答案,而少数派是对的

活 KV(**2026-09-03 读**,镜像与 `tools/agent/item_name_census.py` 取物品名的**是同一个**):

```
https://raw.githubusercontent.com/dotabuff/d2vpkr/master/dota/scripts/npc/items.txt
  "item_aether_lens" / "AbilityValues" / "cast_range_bonus"   "225"
同一棵树 dota/steam.inf: VersionDate = Sep 02 2026, ClientVersion 6921
```

`bots/` 里的写法全仓同形:`if aether ~= nil then aetherRange = N end`。**N 的分布**
(本轮改动**之前**,`lua_source_scan.bots_files()` 全树扫描):

| N | 站点数 | 谁 |
|---|---|---|
| **250** | **29** | 28 个英雄文件 + `ability_item_usage_generic.lua` |
| **225** | **2** | `hero_axe.lua`、`hero_dazzle.lua` —— **与 KV 一致** |
| 120 | 1 | `hero_bane.lua`(无条件初值,**另一个量**,本轮不主张) |

⇒ **形状说「有两个抄错了」,域价钱说「另外 29 个才是缺陷」。**

**代价是什么(写出来,不假设)**:消费者全都是
`abilityX:GetCastRange() + aetherRange`,喂给「在不在射程内」的判断或 `J.GetCastLocation`。
多出来的 25 **不会浪费一次施法** —— 单位目标指令超出射程时引擎会先**把英雄走进射程**再放 ——
所以买到的是**一次没计划的贴近**,加上路上的时间,而且恰恰发生在**决策层以为可以原地出手的那些帧**上。
对一个 5 护甲的辅助,那一步就是「有施法距离」这件事本身的意义。
修法方向是**收窄**:上闸之后,机器人要么在真的够得到的位置出手,要么不出手。

## 4. 落地(闸的形状,以及为什么是这个形状)

`bots/FunLib/jmz_func.lua`:

```lua
function J.GetAetherLensRangeBonus( hItem, nShipped )
	if hItem ~= nil and J.IsModeTurbo() and J.IsSoakCandidate( 'aetherlens' )
	then
		local nKv = hItem:GetSpecialValueInt( 'cast_range_bonus' )
		if type( nKv ) == 'number' and nKv > 0 and nKv < nShipped then return nKv end
	end
	return nShipped
end
```

四个设计点,每个都有先例:

1. **读句柄,不重新硬编码**。`hItem:GetSpecialValueInt(...)` 是既有形状
   (`hero_morphling.lua:958` 等 11 处),而重新写一个 225 只是把今天的漂移换个位置存。
   变异 **M5** 就是把这一行换成 `local nKv = 225`,被点名打红。
2. **构造上单向**:只在 `nKv < nShipped` 时返回 —— 未来任何补丁都不可能让 armed 腿
   声称**比 shipped 更远**。这条闸的全部主张是「这个数太大」;能把它调大的腿测的是没人论证过的东西。
   (同 `wkrosh` / `wkqdmg` / `zusboltcap` 的写法。)
3. **key 读到 <= 0 就回落 shipped**,不发明一个 0 射程的世界(GH #162 的家规)。
4. **shipped 常量由调用方传入**,helper 自己不持有 —— 这样那两个已经写 225 的站点将来接进来时
   是**算术上的 no-op**,不是**豁免**。用例 `[shape] a 225 caller is a no-op by arithmetic` 钉的就是这一格。

**接线范围(SCOPE,严格,理由是 lanefix)**:只接**焦点英雄里有活消费者的两个** ——
`hero_crystal_maiden.lua`(2 个消费者:`ConsiderQ` / `ConsiderW`)、
`hero_lion.lua`(4 个:Q/W/E/R)。

- `hero_axe.lua` **已经是 225**,不动;
- `hero_zuus.lua` / `hero_skeleton_king.lua` **一个活消费者都没有** ——
  zuus **给 `aetherRange` 赋值然后从不读它**(死局部)。这不是「顺手放过」,
  §6 的用例把它钉住了,所以这条豁免将来只能被证伪,不能被当成疏忽。
- **其余 27 个站点 + `ability_item_usage_generic.lua`(1 个字面量、42 个消费者、
  下游是全部 128 个英雄)本轮不动**:31 个站点一次性改行为**就是 `lanefix` 那个 bundle 的形状**,
  而那个 bundle 在终局门上**被拒了两次**(gpm −74.5,再 −88.7,0/4)。

**gate-off 逐字节等价**:helper 原样返回被传入的 250。
