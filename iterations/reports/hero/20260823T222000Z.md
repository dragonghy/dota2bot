## 2. 转做的题:那句话的两半

|---|---|---|---|---|
| skeleton_king | `skeleton_king_vampiric_spirit` | **0/31** | `skeleton_king_INNATE_vampiric_spirit` | **31/31** |
| lion | `lion_to_hell_and_back` | **0/22** | `lion_INNATE_to_hell_and_back` | **22/22** |
| axe | `axe_one_man_army` | **0/26** | 技能数组里**根本没有** | — |

## 3.5 ⭐ 不再是纸上推理:index 4 上**真的**坐着东西,而且比预测的多一个

§3 是纸上论证。本轮**把它驱动了一遍** —— 用 `tests/mock/replay_fixture.lua`(它按 GH #36 重建引擎槽位)
在真实帧上跑出货的 `J.Skill.GetAbilityList`。回来两件事,**两件都是关于工具的事实,不是关于引擎的**:

| 帧 / 主体 | `sAbilityList[4]` | `[5]` | `[6]` |
|---|---|---|---|
| WK | **`skeleton_king_innate_vampiric_spirit`** | nil | reincarnation |
| Lion | **`lion_innate_to_hell_and_back`** | nil | finger_of_death |
| CM(带天赋行的帧) | **`special_bonus_h_p200`** | nil | freezing_field |
| Zeus(同帧) | `zuus_lightning_hands` | **`special_bonus_h_p200`** | thundergods |
| CM(不带天赋行的帧) | nil | nil | freezing_field |

1. **预测兑现**:WK / Lion 的 innate **就在 index 4** —— 因为 mock 的 `IsHidden()` 是 `false`,
   而丢弃要它为 `true`。「innate 会不会落到 4」在 fixture 世界里的答案是**会**。
2. **没预测到的第二个占位者**:mock 的 `ability:IsTalent()` **对一切都返回 false**(对
   `special_bonus_h_p200` 和对普通技能一样)。dumper 又会把 `special_bonus_*` 行放进技能数组
   (CM 14/50、Zeus 9/47)⇒ `GetAbilityList` 的 `elseif not ability:IsTalent()` **不过滤**,
   天赋行被当技能 `table.insert` 进去。**于是在那些帧上,CM 的 `CrystalClone` 和 Zeus 的
   `abilityAS` 绑的是一个天赋句柄。**
3. **而且 fixture 世界连那个 nil 都演不出来**:不带天赋行的 CM 帧上 `sAbilityList[4]` 是 nil,
   但 mock 的 `bot:GetAbilityByName(nil)` **仍然返回一个 table** ⇒
   「`X.ConsiderCrystalClone` 会在 nil 句柄上崩」**在这里构造性不可复现**。
   **绿色的 fixture 跑不能读成「守卫不必要」的证据** —— 已写成断言钉住。

⇒ 这是 GH #36 / #27 / #133 / #145 那一族:**一个驱动 `X.ConsiderCrystalClone` 的 fixture 测试,
碰的不是出货的那个句柄。** 归 harness,已写进 GH #151 §3;`bots/` 一行没动。

## 4. ⭐ 一条 LIMIT:不许从 fixture 语料推 index map

`GetAbilityList` 只在 `IsUltimate() and slot >= 4` 时才强制 index 6。而 **Axe 与 CM 的语料数组
恰好 4 条、大招在最后一条** ⇒ 若 dump 的数组顺序 = `GetAbilityInSlot` 顺序,他俩的大招落在 slot 3,
`slot >= 4` 不成立,`sAbilityList[6]` 会是 **nil**,`abilityR` 整条路径全死。

**语料直接证伪**:两人的大招都有**正在冷却**的帧 —— Axe **1/26**、CM **10/50**,而冷却只有放过才有。
⇒ **dump 顺序 ≠ slot 顺序。**

**⚠️ 归属更正,本条不是本轮的发现。** 写完才查到 `tools/agent/gen_ability_meta.py` 的 docstring
(GH #36,早就在树上)已经写了「the dump is **flattened** ... so a dump index is not the engine slot」。
本轮加的是**证明方式**:那份 docstring 是从「知道 dumper 怎么写的」断言出来的,本条是**从语料内部量出来的**
—— 两者结论相同,但后者在 dumper 改写之后仍然成立。**没查就先写,是本轮第二个该记的流程失误**
(第一个见 §1),下次「我发现了一个 LIMIT」之前先 `grep -rn` 一遍 `tools/` 的 docstring。

两条诚实边界,引用时必须一起带:
- **Axe 那条腿 n=1**;
- **Lion / WK 是 5 条、大招在末位 ⇒ 他俩与 slot 顺序自洽**,别拿他俩去「确认」slot 顺序。

## 5. ⚠️ 一次自己的量测事故,如实记

第一版普查用 `abilities = \{(.*?)\} \}` 这种**惰性整块捕获**。它**吞掉每个数组最后一条技能的
右花括号**,而最后一条**恰好就是大招** ⇒ 第一次读出来是:

```
axe   ult_learned=0  ult_on_cd=0      (真值 22 / 1)
lion  ult_learned=0  ult_on_cd=0      (真值 11 / 9)
zuus  ult_learned=9  ult_on_cd=7      (真值 36 / 16)
```

Zeus/CM 之所以还有非零,是因为那几帧尾部**恰好挂了一行 `special_bonus_h_p200` 天赋**,把大招顶到了
倒数第二位。**一个系统性解析错误,伪装成一条关于英雄行为的读数。**

已改成**按条目逐个匹配**,并在测试文件里写成注释钉住。
**教训**:凡「某某从来没有过」,先问一句是不是解析吃掉了它 —— 尤其当那个「某某」在数据结构里**总是排在最后**。
