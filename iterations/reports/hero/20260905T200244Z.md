## 1. 事实(全部可在仓内交叉核对,不靠网络)

`CAbility:GetAbilityDamage()` 读的是能力的**顶层 `AbilityDamage`** KV 字段,不是
`AbilityValues/damage`。现代 Dota 多年前就把逐级伤害搬进了 `AbilityValues`。

- `tools/agent/ability_damage_census.py`:全树 **128 个英雄**里,声明 `AbilityDamage` 的能力
  只有 **30 个**,其中**非零的只有 16 个**;**Zeus 一个都没有**。
- 该普查的判据是**单向且无需句柄解析**的:`hero_<h>.lua` 里的一次 `GetAbilityDamage()`
  只可能落在英雄 `<h>` 自己的能力上,所以「`<h>` 的能力没有一个声明非零 `AbilityDamage`」
  **就是**这个读数恒零的证明。
- `tests/mock/special_value_shapes.lua` 的 `zuus_lightning_bolt` 块:**没有** `AbilityDamage`,
  `damage` 的 base 是 **`140 220 300 380`**。

⇒ `X.ConsiderW` 的 `local nDamage = abilityW:GetAbilityDamage() * ( 1 + bot:GetSpellAmp() )`
**在引擎里就是 0**,不只是在 mock 里。

## 2. 缺陷:这不是「小了一点」,是**另一个谓词**

分支本体:

```lua
local targetRanged = X.GetRanged( bot, nCastRange )
if targetRanged ~= nil
    and targetRanged:GetHealth() < targetRanged:GetActualIncomingDamage(
            nDamage + targetRanged:GetHealth() * abilityASBonus, DAMAGE_TYPE_MAGICAL )
```

`nDamage = 0` 时它退化成 `h < m*b*h`,即 **`1 < m*b`** —— **与血量无关**。
Static Field 的 `b` 出厂是 **0.09**、`m <= 1` ⇒ **`m*b <= 0.09`**,分支在
**任何等级、任何小兵血量、任何魔抗**下都为假。盈亏平衡要求 `b >= 1.0`(Static Field 吃掉
目标当前血量的 100%),是出厂值的 **11.1 倍**。**闭式为死,不是边际为死。**

## 4. ⭐ 方向由构造保证,不由数据保证

新 helper:

```lua
function X.GetBoltRangedKillDamage( hAbility )
    local nShipped = hAbility:GetAbilityDamage()
    if J.IsModeTurbo() and J.IsSoakCandidate( 'zusboltdmg' )
    then
        local nKvDamage = hAbility:GetSpecialValueInt( 'damage' )
        if type( nKvDamage ) == 'number' and nKvDamage > nShipped then return nKvDamage end
    end
    return nShipped
end
```

两条,**各写成一条独立断言**,而不是让第二条藏在第一条的论证里:

- **(i) `max` 形状**:armed 答案 `>= ` shipped 答案,对**每一个**输入成立
  (新文件 §3 扫 `6 x 7` 组合验证,不是举例)。
- **(ii) 单调性**:判据对平伤**单调不减**(§3b 扫 `b x m x h x D` 全格,用**真的** mock
  `GetActualIncomingDamage` 驱动,不是复述代数)。

(i)+(ii) ⇒ **armed 的狙杀集是 shipped 的严格超集**,arming **只能增加**释放,永远不能
静默删掉一次。⇒ 负读数只能读作「**狙小兵狙多了不好**」,**永远不能**读作
「杠杆吃掉了一次释放」—— 后者**没有任何计数器报得出来**。

这是 `cullthresh` / `wkbonefight` 那条教训的**第三次跨英雄复用**,也是**第一次把单调性
单独立成一条断言**:前两根靠的是整数蕴含(`n==1 ⇒ n>=1`),这一根的超集性要经过一个
**函数**(`GetActualIncomingDamage`),所以「谓词单调」必须自己被验,不能顺带假设。

变异台的 **M4 就是这个方向的守卫**:把 `>` 改成 `<`(一个字符,读起来像笔误),
`max` 变 `min`,armed 就能答**低于** shipped —— 被 §3 抓住并打出
`armed answer 0 is BELOW the shipped 1`。

## 8. 覆盖边界(⚠️ 两句不许合并成一句)

- **分支的选择器不可帧驱动。** `X.GetRanged` 需要**小兵单位**,而 `tests/fixtures`
  **没有任何一帧带小兵**(`make_fixture.py` 记的是英雄快照)。第二条**独立**堵点是
  `GetActiveMode` 在 fixture 帧上恒 **0**(GH #474 家族),而 `X.GetRanged` 按
  `BOT_MODE_LANING` 和四个模式抑制项分支。
  两条堵点**各写成一条断言**(新文件 §5 / §5b),语料哪天带上小兵或模式,它红并打出
  **「这是好消息不是失败,去重写 §4」**。
- **改动的那一项本身是真实帧读数。** §2d 在真实帧的 Lightning Bolt 句柄上量到
  shipped 腿 **= 0**、armed 腿 **= 380**(rank 4 的 KV 值)。
- **§4 的小兵是声明过的伪造**,与 `test_zuus_static_field_second_consumer.lua` §4 用的是
  **同一个 `make_creep` 形状**(两个文件不许给不同的小兵定价)。
- **⚠️ 端到端读数的一个诚实限制,登记在这里**:那一帧上 `abilityASBonus` 实测 **= 0**
  (Static Field 是隐藏内在技能,`.dem` 不带它的句柄 —— 同一条限制写在兄弟文件里),
  所以量到的阈值是**纯 `h < 380*m`**:`m=1.00` 狙到 **300**(400 不狙)、
  `m=0.75` 狙到 **250**、`m=0.25` 狙到 **50**(血量阶梯分辨率)。
  ⇒ 这是 armed 阈值的**下界**,真实对局里 Static Field 只会把它抬高。
