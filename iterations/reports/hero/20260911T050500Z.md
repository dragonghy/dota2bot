## 1. 缺陷(`bots/BotLib/hero_zuus.lua`,`X.ConsiderE` 撤退落单点)

出货:

```lua
local tableNearbyEnemyHeroes = J.GetNearbyHeroes(bot, nCastRange, true, BOT_MODE_NONE)
...
local targetHero = tableNearbyEnemyHeroes[1]
if J.IsValidHero( targetHero )
    and J.CanCastOnNonMagicImmune( targetHero )
    and not bot:IsFacingLocation( targetHero:GetLocation(), 120 )
then return BOT_ACTION_DESIRE_HIGH end
```

分支要买的是**存在量化**的东西 ——「**有没有**一个敌人在我背后、我正在从他那儿逃」。
Heavenly Jump 是无目标位移,沿**自己的朝向**跳。这个问题被问给了 `[1]`,问完就不问了。

### ⭐ 名单**不是**无序的,而这正是要点

`docs/BOT_API_REFERENCE.md:1229` 把「按距离升序」写成了整个 `GetNearby*` 家族的**承诺**,
`J.GetNearbyHeroes`(`jmz_func.lua:2856`)只过滤、**从不重排** ⇒ `[1]` 就是**最近**的敌人,可靠地是。

⇒ 这**不是** GH #724 `anyhero` 那一族(名单无序,把名单排好就修好了)。
这是 **GH #731** 那一族,而且是更难的那个:**名单排序是正确的,而排序正确恰恰帮不上忙**,
因为分支的判据是**方向**,排序键是**距离**。「最近的敌人」和「我背后的那个敌人」是两个问题,
出货用第一个问题的 handle 回答了第二个问题。

**任何一帧,只要最近的那个敌人正在我身前(我正朝他走/打),而追我的那个稍远一点在我背后 ——
逃生跳就被否掉,而否掉它的理由是一个关于别人的读数。**

## 2. 改动(gated,turbo-only,**未 armed**)

新增两个 helper(`bots/BotLib/hero_zuus.lua`):

- `X.zuus_IsRetreatJumpThreat( hBot, hEnemy )` —— 出货那三条合取项,**逐字、原序、原短路**搬进来;
- `X.zuus_FindRetreatJumpThreat( hBot, tEnemies )` —— 闸**关**时只对 `tEnemies[1]` 求值(出货行为逐字);
  闸**开**时遍历同一个环,返回第一个满足的成员。

落单点改成 `if X.zuus_FindRetreatJumpThreat( bot, tableNearbyEnemyHeroes ) ~= nil then`。

**方向 = WIDENING,而且是由循环的形状保证的**:index 1 在扫描里 ⇒ 出货腿开火的每一帧 armed 腿都开火。
**它只能多加跳,不能少加跳。**

**⛔ 只点一个 id**:`J.IsModeTurbo() and J.IsSoakCandidate( 'zusjumpany' )`,
**不与 `zusjumpland` / `zusbind` 合取**(pullcad 陷阱;M7 就是它,见 §4)。
两个跳跃杠杆是正交的 —— `zusjumpland` 在「进攻」支路上**收窄几何**,本 id 在「撤退」支路上**放宽成员**。

### 代价那一半(写出来是为了可以被反驳)

跳跃沿**自己的朝向**走。armed 之后,授权这一跳的可能是背后那个,而**更近**的那个正好在朝向的
120° 锥内 ⇒ **这一跳可能在拉近与更近那个敌人的距离**。这在下面那一帧上**不是假想**
(最近 237.6u / 授权者 306.3u)。这就是它 ship dark 的原因,也是 §5 验收判据里**点名要买的那一半读数**。

买到的是什么:Heavenly Jump 是逃生 —— 375–600u 免费位移 + 落地 1.4s / 80% 减速 ——
而出货把它**扔在自己那个环的一个单成员抽样上**。
