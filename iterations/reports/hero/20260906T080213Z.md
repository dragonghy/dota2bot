## 2. 事实

`X.cm_GetStrongestUnit`(`hero_crystal_maiden.lua`)的远程兵**早退出口**:

```lua
if string.find( unit:GetUnitName(), 'ranged' ) ~= nil
    and unit:GetHealth() > GetBot():GetAttackDamage() * 2
then
    return unit, 500            -- <-- 这个字面量
end
```

两个挑选器(`cm_GetWeakestUnit` / `cm_GetStrongestUnit`)的**其他每一个出口**返回的都是
这只单位自己的血量(`nWeakestUnitLowestHealth` / `nStrongestUnitHealth`)。
而 `X.ConsiderW` 把第二个返回值**当血量用了五次**:

```lua
if ( ...Health2 > 460 or ( ...Health1 > 390 and nMP > 0.45 ) )
    and ...Health2 <= nCreepCap
if ( ...Health1 > 410 or ( ...Health1 > 360 and nMP > 0.45 ) )
    and ...Health1 <= nCreepCap
```

**⇒ 这就是 `cmcreepcap`(GH #541)修的那个缺陷,从比较式的另一侧进来的 ——
而 `cmcreepcap` 结构上够不着它**:那根修的是**上限**;在这个出口上,
**被限的那个量本身是常数**,于是一个正确的上限被拿去比一个编造的血量。
新文件 §3 有一条断言把「两个 gate 可分离」钉住(单独 arm `cmcreepcap`,本出口仍报 500)。

## 3. ⭐ 500 同时朝两个方向撒谎 —— 这不是一个带符号的错误,是两个

- **对残血兵撒谎撒高。** 出口从 `2*ad` 起就收件,然后一律报 500,而
  **500 越过全部四个下界**(500 > 460 / 410 / 390 / 360)。谎言窗口 `(2*ad, 460]`,
  只要攻击力低于 230 就非空。代价:125-155 蓝(CM 缺蓝是本仓常设稀缺,GH #126)
  + 6-9s **她唯一单体控**的冷却,换一只两下平 A 就掉的兵。
- **对满血兵撒谎撒低。** `500 <= nCreepCap` 在**每一级都成立**(600/800/1000/1200)
  ⇒ 上限存在的那个「打不打得死」检查**在这个出口上从来没跑过**。谎言窗口
  `(nCreepCap, 1100]`(1100 是挑选器自己三行外的血量门),1-3 级非空、4 级为空。

## 4. ⭐⭐ 方向由构造保证是 NARROWING —— 但 certify 它的那个扫描是**恒等式不是第二意见**

armed 只改**报告的数**、不改**返回的单位**;五个消费项对这个数全是单调的
(四次 `> floor`、一次 `<= cap`),而出厂的 500 **满足其中每一项**
⇒ 任何别的值只能把 true 变 false:**arming 只能减少一次冻结,不可能凭空增加一次,
也不可能换一个目标。**

**而这正意味着逐点的子集检查对任何 armed 值都不可能失败。**
一旦「500 越过每一个下界和每一级上限」成立,`bShipped or not bArmed` 恒真 ——
它是恒等式,不是诊断(README 铁律 4 (i-c) 对 swap-average 估计量作的是同一个区分)。
所以**载重的是那一条前提断言**,而且它是**可证伪的**:`consumer_floors()`
**从源码里读**那四个下界,谁把某个下界抬到 500 以上、或哪个补丁把 1 级上限压到 500 以下,
前提**当场变红**,而不是留下一句过期的「by construction」。

变异 **M6** 就是这条:把 `> 460` 抬成 `> 560`。
**它是本台九个变异里唯一能让 header 那句窄化变成假话的,而任何对 armed 值的断言都看不见它。**

## 6. ⚠️ 覆盖边界 —— 买得到的那一半和买不到的那一半,两句不许合并

**买不到的(改动的那一项)**:全仓 fixture **没有任何一个 creep 单位** ——
creep 只作为战斗日志 `recent_damage` 行出现,**没有血量也没有 handle**;
`bot:GetNearbyCreeps` 在 **10/10 个 CM 主体帧上、对两个队伍**都返回空表。
⇒ 远程兵出口在 fixture 上**结构上到不了**。两条都写成**单向绊线**(新文件 §5):
哪天 loader / dumper 接上 creep,这个文件**变红并说出来**,不会安静地继续绿。

**买得到的**:`lies low` 窗口的**宽度**,从 10 个 CM 主体 fixture 上**真实的 Frostbite handle**
读出来 —— 真实 rank + 真实 `dps * creep_multiplier * duration`,
**10 帧里有 3 帧**(caps **800 / 1000 / 1000**)坐在挑选器自己 1100 血量门**以下**,
窗口宽 **300 / 100 / 100**。语料 rank 偏高(**7/10 已是 4 级**,那里窗口为空),
这**对本改动不利**,所以 3/10 是**下界不是频率**。

⚠️ **`lies high` 窗口的宽度不是真实帧读数,这句必须单独说。**
它要 `GetAttackDamage`,而**一份 .dem 切片既不带攻击力也不带攻速**
(mock 自己写着,`tests/mock/bot_api.lua:134`)⇒ 全 10 帧读 **0**,
出口的收件条件退化成 `GetHealth() > 0`。§2b 把这个 0 钉成单向绊线,并明写
**不许**把它读成「窗口最大」—— **那是量具不是游戏**。

**登记不认领**:同一个出口的 `return` 还**中断了搜索**,于是挑选器返回的是列表序里
**第一只**合格的远程兵而不是**最强**的那只,和它自己的名字矛盾。那是**目标身份**改动,
本杠杆**故意不做** —— 「不动目标」正是第 4 节方向论证成立的原因。
