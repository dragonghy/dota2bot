## 2. 缺陷(闭式的源码事实,不是推断)

`X.ConsiderW` 画一个搜索环:

```lua
local nInBonusEnemyList = J.GetNearbyHeroes( bot, nCastRange + 300, true, BOT_MODE_NONE )
```

然后把它交给**同一个 `if` 体里的两个打断子支路**:

```lua
if npcEnemy:IsChanneling()                                  -- 一个距离项都没有
if npcEnemy:IsCastingAbility()
    and J.IsInRange( bot, npcEnemy, nCastRange + 50 )       -- 十一行之外,带界
```

**存活的两个词项都不是距离项**,这是从 `bots/FunLib/jmz_func.lua` 读出来的:

| 词项 | 是什么 | 有没有距离项 |
|---|---|---|
| `J.CanCastOnNonMagicImmune`(:988) | CanBeSeen + 魔免 + 无敌 + 幻象 + 禁止 modifier | 无 |
| `J.CanCastOnTargetAdvanced`(:1006) | linken / antimage / 宝石那张表 | 无 |

`tests/test_lion_hex_interrupt_reach.lua` **§2 逐个读源码断言**这两条,
所以「没有第二道防线」不是一句话,是一次会自己报红的检查。

**第三个读者站在兄弟那边,不站在它这边。** 那个 `+300` 环在本函数里恰好有三个读者
(§2 把这个 `== 4`(一次定义 + 三个读者)钉成绊线),第三个是团战最危险目标搜索,
它也写 `J.IsInRange( bot, npcMostDangerousEnemy, nCastRange + 50 )`。
⇒ **三个读者,两个按 +50 收口,只有这一个不收。**
函数里其余每个英雄出价点都更紧:攻击 `+150`;保护自己 / 撤退 / 肉山 读 `nCastRange` 零余量。

**引擎拿到的是什么。** `X.SkillsComplement` 发的是
`bot:ActionQueue_UseAbilityOnEntity( abilityW, castWTarget )`(魔晶下是 `...OnLocation`),
射程外的这条指令**先是一条移动指令**。而这是函数里的**第一个**出价点 ⇒
一个射程外的引导者不只是「多走一段路」,它**挤掉**了同一个函数本可以在射程内找到的那发团战控。

## 3. 修法与方向

```lua
X.nWInterruptReachSlack = 50

function X.lion_IsInterruptTargetInReach( hTarget, nCastRange )
    if not ( J.IsModeTurbo() and J.IsSoakCandidate( 'lionwreach' ) ) then return true end
    return J.IsInRange( bot, hTarget, nCastRange + X.nWInterruptReachSlack )
end
```

接线**一处**(`IsChanneling` 子支路)。闸关返回 `true` ⇒ 出货逐字节不变。

⛔ **一个阈值都没新造。** 界的形状和那个 `50` 都是从**十一行之外的兄弟子支路**抄来的;
`nCastRange` 是**传进来的**不是重读的,所以 aether lens 项
(`X.SkillsComplement` 对持镜的 Lion 给 250,本文件 pos_4 / pos_5 两张购买表都带这件)
与其余出价点看到的完全一致。

**方向是代码的性质,不是今天的数据。** first-match 循环上只再 AND 一个合取项 ⇒
该出价点的 armed 释放集是出货集的**严格子集**,永不新增一发。

⭐ **重定位是可能的,而且有界 —— 这是 `lionrreach` 陷阱的诚实写法,不是绕过它。**
被否决的候选让循环与下方支路继续跑,而下方**每一个**出价点都把自己的目标收在
`nCastRange + 150` 或更紧 ⇒ armed 只能产出「不施法」或「施法到一个**严格更近**的目标」,
**永远不会把一发挪得更远**。负向读数只能读成「那些走位值得走」,
**永远不能读成「本 lever 多开了一发」**。
