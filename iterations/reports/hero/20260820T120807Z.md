## 1. 先说结论,包括那半个「不是结论」的部分

`J.tHardCcAbilities`(`jmz_func.lua`)是回答「这个敌人现在能不能把我定住」的策展名字表。
Earthshaker 在里面只有 `earthshaker_fissure` 一条。但**点了 aftershock 的 ES,每放一个技能
都会在自身 300 半径炸一次硬控** —— 于是 fissure 进冷却之后,他手里的 `enchant_totem`
仍然是一发硬控,而表把他读成无害。GH #66 量到的代价:12 局里 CM 的 11 次开大有 4 次读条
在 3 秒内被打断,门只拦住 **1** 次。

**修好了的那一半**:加表项(gated),**帧 A** 从放行翻成拦住。
**没修好、而且本轮证明它修不好的那一半**:GH #66 §2 把两次漏报记成「同一个根因」,
**按真实几何只有一个是**。`enchant_totem` 是无目标技能 ⇒ `GetCastRange()` **= 0** ⇒ 否决环
就是 `0 + X.nRGuardCloseBuffer` = **400**;而**帧 B 的 ES 站在 536.1 码**。加表项对它**毫无作用**,
这一帧在测试里被**钉成「仍然放行」**。它属于**环的形状**(#63 在削的那个 `cast_range + 常数`
形式,#66 §3 自己也论证过该形式对自身半径类欠冲),**不属于表**。一次一个杠杆。

## 3. 修法

```lua
J.tHardCcAbilitiesCandidate = {
    earthshaker_enchant_totem = 'earthshaker_aftershock',
}
```

三个设计选择,每一个都有理由:

1. **值是「必需的被动」而不是 `true`**。没点 aftershock 的 ES,`enchant_totem` 就是个自增益,
   谁也定不住。被动本身**永远不可能**成为返回的句柄(它过不了 `IsFullyCastable`),
   所以它只能当**前置条件**,不能当表项。
2. **单独一张表 + 第二遍扫描**,不是往 `J.tHardCcAbilities` 里加一行。那张表是**共享的**:
   消费者有 `cmrguard`(CM)和 `ccburst`(`J.ShouldRetreatLaneBurst`)两个,直接加行等于
   **同时挪两个域** —— `lanefix` 的形状。第二遍**排在 shipped 扫描之后**,所以 arm 之后
   只可能在 shipped 找不到句柄的地方**多出**一个,永远不会**替换**它已经找到的那个(有测试)。
3. **`esaftershock` 单独一个 id + turbo-only**。关着的时候 `J.GetReadyHardCc` 与上线**逐字节相同**。
   而且**各消费者仍各守各的门**:只 arm `esaftershock`(不 arm `cmrguard`)⇒ 表变大了,
   **游戏里什么都不会变** —— 这条也写成了测试。

## 4. 局部验证(24 例,`tests/test_replay_260820_cm_es_aftershock.lua`)

- **缺陷写成正向断言**:帧 A 只 arm `cmrguard` ⇒ `J.GetReadyHardCc(ES) == nil` 且门**放行**
  —— 这正是 GH #66 量到的那次漏报,在测试里被复现而不是被叙述。
- 修复:两个 id 都 arm ⇒ 门**拦住**,且返回的句柄就是 `earthshaker_enchant_totem`。
- **只 arm `esaftershock`** ⇒ helper 看得见、决策**不变**(爆炸半径围堵)。
- 非 turbo ⇒ 不变。
- **每条子句一个标注变异**:aftershock 未点(⇒ 放行)、totem 进冷却(⇒ 放行)、
  totem 蓝不够(把耗蓝锚到 600,对他真实的 534 ⇒ 放行)。
- **shipped 优先级**:把 fissure 的冷却还给他 ⇒ 返回的句柄变回 `earthshaker_fissure`。
- **帧 B 的环被两向钉死**:把 ES 沿真实方位挪到 **400 码** ⇒ 拦住;**401 码** ⇒ 放行。
  于是「帧 B 放行」是**距离**造成的,不是「表项没生效」造成的。
- **锚点敏感性显式化**:若引擎把 `enchant_totem` 的 cast range 报成 **300**(aftershock 半径,
  宽松上界),帧 B **会翻成拦住**。所以另有一例断言**两局的 ES 都没有阿哈利姆神杖**
  (全游戏唯一能给 `enchant_totem` 加施法距离的东西)。
- **4 例端到端**驱动真的 `X.ConsiderR`:**帧 A 不需要任何 mutation 就能走到门**
  —— 真实帧上就有两个敌人站在大招圈里(ES 195.9 / Zeus 268.0),所以 shipped 在那里**真的出价 HIGH**
  (她真的开了那一发、1.0 秒后死了);arm 之后变 NONE;非 turbo 维持 HIGH;
  帧 B armed 与 shipped **逐技能相同**,且**把「为什么都是 NONE」的真实理由断言出来**
  (圈里只有 2 个敌人、`aoeCanHurt` 一个都不数),不留空绿。
- **3 处源码 tripwire**:表项**不许**出现在 shipped 表里(挪过去 = 未过 (b) 就上线);
  候选表必须仍是「技能→被动」的一条对;`'esaftershock'` 恰好一次;
  **`ccburst` 的消费点必须仍在它自己的 `bCcAware` 门内**。

**8 次变异 7 抓**。唯一没抓到的是「删掉候选分支里的 `GetLevel() >= 1`」——
`IsFullyCastable` 本来就蕴含已学习(引擎与 mock 都是),**这条子句可证冗余**。
保留它是为了和上面一行 shipped 扫描**保持对称**,并新加一条**跨层 tripwire**
断言让它冗余的那个性质(未学习的技能不许读作 fully castable),这样哪天某一层不再提供该性质,
是**报告**出来而不是被假设掉。(shipped 扫描里有同一条冗余,不是本轮的杠杆。)

**门**:`luacheck bots game --formatter plain` **0 警告**;`lua5.1 tests/run_tests.lua`
**769/769 绿**(干净 stash 实测基线 **745**,+24)。

## 6. 诚实边界

- 两帧、一个 ES、一个波次。aftershock 的归属靠的是**泛型 `modifier_stunned` + actor=earthshaker +
  当帧 fissure 不在 cd=0 列表**(#66 §6 同款),不是直接读到 aftershock 的 modifier —— dumper 分不开。
- 三个帧外锚:`enchant_totem` cast range 0、Freezing Field 一级耗蓝 200、AoE 半径 835。
  后两个**是承重的** —— 半径取 mock 默认的 0 会让 `J.GetNearbyHeroes` 返回空,四个端到端例**全是空绿**。
- 「拦住更多次开大在总量上是不是更好」是**涌现问题**,只有批测能答(lanefix 教训)。本轮不作任何声明。
