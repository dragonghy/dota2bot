## 1. ⭐ 缺陷:不是梯度,是一个穿着梯度衣服的开关

`bots/BotLib/hero_crystal_maiden.lua` `X.ConsiderR` **branch 3**(撤退释放路)问:

```lua
and nHP > 0.38 * #nEnemysHeroesFurther
```

`nHP` 在同一文件 **`:325`** 被定义成 `bot:GetHealth()/bot:GetMaxHealth()` —— **一个 [0,1] 的分数**。
`nEnemysHeroesFurther` 是该支路自己的 **1300u 敌方英雄环**。把可达的档枚举出来:

| `#further` | 合取项要求 | 状态 |
|---|---|---|
| 0 | `nHP > 0` | **不可达**:branch 3 要求 `nEnemysHeroesNearby[1]` 是有效英雄,而 500u 表是 1300u 表的**子集**(同锚点、同过滤器、更小半径)⇒ 有一个近敌就有一个远敌 |
| 1 | `nHP > 0.38` | **空操作**:与**十一行之上**的外层守卫 `J.IsRetreating( bot ) and nHP > 0.38` **逐字相同** |
| 2 | `nHP > 0.76` | **唯一干活的一档** |
| ≥3 | `nHP > 1.14` | **恒假**(`nHP ≤ 1` 由构造) |

⇒ 这个合取项**只有一档干活**,从**三个可见追兵**往上是**永久拒绝**。
而该支路其余的合取项是 `J.IsRetreating(bot)`、`nHP > 0.38`、
`not abilityQ:IsFullyCastable()`、`not abilityW:IsFullyCastable()` ——
**「被追、Q 和 W 都在 CD、三个以上追兵」正是这条支路存在的理由**,
也正是它静默删掉的状态。

⭐ **没有人写下「三个就拒绝」。** 它是把一个**有界量**乘以一个**无界量**的副产品,
关断点(3)在整个文件里一个字都没出现过。这是本轮登记的形状:
**一条读起来像「人越多要求越健康」的梯度,在它自己的定义域里其实是一个开关,而开关位置无人署名。**

## 2. 修复:夹在该规则**自己**最后一个可满足的档上(不发明数字)

新 helper(gated **`cmrflee`**,turbo-only),`X.ConsiderR` 之上:

```lua
X.nRRetreatCrowdCap = 2

function X.cm_IsFieldRetreatCrowdOk( nHp, nStep, nCrowd )
	local bShipped = nHp > nStep * nCrowd        -- 出厂表达式,逐字
	if bShipped then return true end
	if not ( J.IsModeTurbo() and J.IsSoakCandidate( 'cmrflee' ) ) then return false end
	return nHp > nStep * math.min( nCrowd, X.nRRetreatCrowdCap )
end
```

调用点(`0.38` 仍然**只在这里**出现,出厂分支原本就在这里写它):

```lua
and X.cm_IsFieldRetreatCrowdOk( nHP, 0.38, #nEnemysHeroesFurther )
```

⭐ **为什么 cap 是 2 而不是一个新数字**:armed 新增的状态**恰好**是
`(crowd ≥ 3, 0.76 < nHP ≤ 1)`,而其中**每一个**,出厂规则在 **crowd 2 的同一血量上已经同意**。
⇒ 它**不发明**这条支路尚未显示的任何意愿,是出厂规则的**单调闭包** ——
与 `hero_skeleton_king.lua` `X.wk_IsBoneGuardBankCommittable` **同一构造**。
测试 **§2.3 从阶梯重新推导**这个 2(`max{n : 0.38·n < 1}`),而不是断言它。

**方向:WIDENING,按构造单向。** 出厂谓词**先绑定、为真先 `return true`**,
