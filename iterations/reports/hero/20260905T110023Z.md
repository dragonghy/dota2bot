## 2. 落地:新 gated 候选 `cullthresh`,turbo-only,未 armed

```lua
function X.IsCullThresholdOn()
	return J.IsModeTurbo() and J.IsSoakCandidate( 'cullthresh' )
end

function X.CullKillThreshold( nSkillLV )
	local nKillDamage = 150 + 100 * nSkillLV
	if talent8 ~= nil and talent8:IsTrained() then nKillDamage = nKillDamage + talent8:GetSpecialValueInt( 'value' ) end
	if X.IsCullThresholdOn() then
		local nLive = abilityR:GetSpecialValueInt( 'damage' )
		if type( nLive ) == 'number' and nLive > nKillDamage then return nLive end
	end
	return nKillDamage
end
```

`X.ConsiderR` 那一行变成 `local nKillDamage = X.CullKillThreshold( nSkillLV )`。

- **改了什么**:斩杀线从哪里来。
- **没改什么**:分支的其余守卫(aegis / 无敌 / `HasSpecialModifier` / 魔免 /
  `IsKillBotAntiMage`)、375u 的环、比较式本身,一个字没动。
- **闸关时逐字复现出厂算术,含那条 talent 项** —— 所以未 armed 的树与落地前
  行为相同,而且这句话**读源码就能查**(§7 两条棘轮钉的就是它)。

### ⭐ 本轮最值钱的一格:第一版守卫是错的,而它错得**看上去显然够用**

第一版写的是 `nLive > 0`。它通过每一条 gate 接线检查,通过每一条行为用例
(今天的 loader 答 275)。**它让一个小的正读数把斩杀线收窄** —— 这条杠杆
**唯一被禁止的方向**,而且是**静默的**:没有任何 in-domain 计数器会报出
「Axe 不再斩杀了」,那是一件**没发生的事**。

抓住它的是本文件 §3 那条**扫读数阶梯**的方向用例(`{0,1,100,249,250,251,275,475,1000}` × 三个 rank),
不是任何一条单值断言。改法是**把出厂值当地板**(`nLive > nKillDamage`)⇒
armed 的施法集是 shipped 的**严格超集**,
**「只能加不能减」从一句关于数据的断言变成一条关于代码的性质**。

- 同族:`zusboltcap`(GH #175)的静默 0 —— 一个 getter 悄悄答 0,
  把「血量上限」变成「有没有人」。
- **⚠️ 代价已登记,不藏**:若某个补丁把 KV 阈值调到**低于**手写值,本 helper 会
  保留旧的高值,Axe 会去斩一个斩不死的目标。拦它的是**两处 25 点棘轮**
  (本轮新文件 §1 + preflight §1):它们先红并点名新阶梯,该改判时会自己举手。

### 第二个陷阱:talent 重复计数

`special_bonus_unique_axe_5` 的 +150 **住在 KV 的 `damage` 里**,由引擎折叠。
出厂那行 `talent8` 又加了一遍 —— 只因为 hero-unique talent 没有 KV block、
句柄答 0,才**无害而不是不存在**。armed 早退在 talent 行**之下**,所以 armed
返回的是引擎自己的值,不是那个和。

**⭐ §4 是在引擎真会给出的世界里钉的**:句柄答 150 **且** 能力读数答 425
(折叠后)。只动句柄不动能力读数的世界**引擎不会产生**,对着它写测试就是在钉一个人造物。

## 4. ⭐ 那为什么现在写?过期的是**另一半**,而且过期在一个**供给事实**上

preflight 的结论是两句话,本轮只有一句过期:

1. 「25 点的带,帧语料量不了」——**仍然成立**。
2. 「所以到**事件侧**去量」——`tests/test_axe_culling_band_power.lua`(2026-08-30)
   已经把这条定价好了:一次**穿越**在 1Hz 时间线上被抓到的概率是
   `p = min(1, band/(v·dt))`,**式子里没有血池项**;按语料自己的 burst 中位数
   58.3 HP/s 算是 2.3 次穿越/命中。
3. 挡住穿越计数的从来不是方法,是**载体供给**:批测台 2026-08-23 量到
   **`npc_dota_hero_axe` 出现 0 / 306 局**,于是「没有东西可数」。

**这第三句今天为假。** `tests/fixtures/tl_260905_010226_axe_outchan.json` 是
**逐字切自 dumper 归档时间线**的一段(`run spot_20260905_003250`,**seed 4763**,
180 个 0.1s 快照),**它的 subject 就是 `axe`**。⇒ 不必再等 GH #46 的
`--find axe` 种子集。§6 把这三件事(seed / run id / subject)钉住,免得它退回成散文。

⇒ **这根杠杆从「量不到」变成「还没量」,而「还没量」正是 gate 的用途** ——
它骑在分支上、在每一局出厂游戏里 inert,等一波来 arm 它。

**⚠️ 诚实边界**:本组只证明了归档里**存在**含 Axe 的对局,**没有**量它有多少局。
那个数正是 `hero-2` 要买的,不是它的前提。

## 5. 三条按名字响了的兄弟棘轮,**全部重新对准而不是放松**

改动一落地,三个文件按名字红了。**它们是被写来注意到这件事的**,所以逐条读了再动:

1. **`tests/test_axe_culling_threshold_preflight.lua` §1 两例。**
   它的失败文案早就写好了指示:「如果你刚把它换成 `GetSpecialValueInt('damage')`,
   那正是本 preflight 推荐的修法 …… **删掉本文件 §1 和 §2**」。
   **这条指示只执行了一半,而不执行的那一半有理由**:它假设这个修法会**不带闸**落地
   (「ships on the source-correctness argument … not on a measured frame」)。
   实际落地是**带闸**的 ⇒
   - §1 **重新对准**:不变式(「一个修复不能悄悄落地」)现在**更需要**,因为
     gate-off 那条路必须逐字保住出厂常数,否则「未 armed 时 inert」这句话就**读不出来**了。
     顺带加了第三条:`ConsiderR` 必须真的走 helper(否则闸被绕过)。
   - §2 **逐字保留**:它的绊线在带被占用的那天**点名那一帧**,而一根 gated 杠杆
     **比不带闸的更需要那一帧**。
   - 第二例从「`ConsiderR` 里已经在用这个 API」(那是**推荐修法的论据**,已兑现)
     改成「**落地的就是那次读**」—— 并断言 armed 路径里**不出现 275/475 字面量**
     (闸后面的常数还是常数)。
2. **`tests/test_axe_culling_band_power.lua` 的源码绊线**,原文写着
   「if a gate appeared, hero-2 landed —— **retire this file** rather than editing the numbers」。
   **一个数都没编**,但文件**没有退休**:它的穿越模型(§1–§5)不是被作废的证据,
   **它正是下一棒要用的方法**,退休它等于在它变得承重的那一刻删掉它。
   只把绊线移到 helper 上,并加一条「`ConsiderR` 必须经过 helper」。
3. **`tests/test_axe_bkb_supply_staged_frame.lua` §3**:`150 + 100*nSkillLV` 现在是
   **gate-off 值**,而本文件所有读数都是在不 arm 任何东西的情况下取的 ⇒
   到它现在住的地方去查,不是放松。
