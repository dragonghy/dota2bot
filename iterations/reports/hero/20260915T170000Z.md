## 1. 缺陷,一句话

`bots/BotLib/hero_skeleton_king.lua` 的 `X.ShouldSaveMana`(**出货、无闸**,被 `X.ConsiderQ` 与
`X.ConsiderW` 的**第一行**读)拒绝一次施法的条件是五项合取:

```lua
nLV >= 6
  and nAbility ~= nil and abilityR ~= nil
  and abilityR:GetCooldownTimeRemaining() <= 3.0
  and ( bot:GetMana() - nAbility:GetManaCost() < <储备> )
```

⛔ **五项里没有一项问 Reincarnation 学了没。** `nLV >= 6` 替它站岗,而这不是等价物:
英雄 6 级以上、R 仍在 rank 0 是真实状态(GH #407 的归档扫描在 W34 上量到 **42 帧**)。
而且第四项也救不了——**未学的技能剩余冷却读 0**,于是「R 快好了」那一项同样放行。
规则于是为一个**不存在的死亡触发**扣住蓝,而 Wraithfire Blast 是 Wraith King **唯一**的控制技能。

## 2. ⭐⭐ 第一条产出:那个「录像买不到的裁读」不必被买 —— 它被**界住**了

GH #407 归档扫描结案时逐字写着:

> ⛔ 但 `GetManaCost()` 那一半录像答不了,而且是原理性的……要答那半需要**一个 bot 侧 fixture**。

backlog 把这句当阻塞项交了三轮。**它不必被回答,因为两个答案都让杠杆成立:**

| 引擎对**未学**技能的 `GetManaCost()` | 后果 |
|---|---|
| 返回 **0** | 出货那一项在这些帧上**算术不可达** ⇒ 本杠杆是**字节级 no-op** |
| 返回**一级价** | 规则为一个**放不出来的大招**扣住 220 蓝 ⇒ 本杠杆删掉的正是这一条 |

上面那个「算术不可达」是可以逐步走完的,**而且它对真引擎成立不只对 mock 成立**:

1. 两个调用点都把 `not ability:IsFullyCastable()` 排在 `X.ShouldSaveMana` **之前**的 `or` 链里
   (§4.1 从源码取这个顺序,不靠记忆);
2. Lua 的 `or` 短路 ⇒ **进得来就蕴含 `IsFullyCastable()` 为真**;
3. `IsFullyCastable` 的蓝量项蕴含 `GetMana() >= GetManaCost()` ⇒ `GetMana() - GetManaCost() >= 0`;
4. 储备 = `abilityR:GetManaCost()` = 0(`X.GetReincarnationReserve` 救不了它:armed 时它返回那个价的
   **最小值**,同样是 0);
5. ⇒ 末项是 `>= 0 < 0`,**恒假**。

⇒ **那个未决读法移动的是域的大小,从不移动对错。**
§4 把两条分支都**驱动**而不是选一条:§4.2 把 R 定价按成 0 后逐帧验证出货规则确实沉默(并在同一循环里
验证 `GetMana() >= 价` 这条蕴含**在真实帧上真的成立**);§4.3 走 loader 自带的分支 B;
§4.4 证明两条分支下 armed 都**不新增拒绝**。

⭐ 这与上一轮 GH #833 的形状是同一族,但**不是同一句话**:那次是「争议点不存在」(`axe_culling_blade`
根本没有斩杀线这个键);这次争议点**存在且确实买不到**,被处理掉的方式是**让两种答案给出同一个裁定**。

## 6. 改了什么

新 helper `X.IsReincarnationReserveUnlearned()`(定义在 `X.ShouldSaveMana` 之前):
未 armed / 非 turbo **恒返回 false**;armed 时返回 `not abilityR:IsTrained()`。

⭐ **用 `IsTrained()` 而不是 `GetLevel() < 1`,而这不是口味。** 两者对每一个引擎答案都等价
(loader 与引擎都把 `IsTrained` 定义成 `GetLevel() > 0`),但只有前者是**本树自己的约定**:
`mode_retreat_generic` 的 huskar 块与 `axeblink` 都先问 `IsTrained()` 再相信一个技能句柄,
`J.IsWkReincarnationArmed` 的 `wkreinctr` 合取项也是。**一个只被大多数实例遵守的约定就是 GH #235 的形状** ——
源码级「谁在定价之前问过所有权」的普查只能看见约定的那一种拼法。变异体 **M13** 打的就是这一条:
它把两者对调,**每一条行为读数都不动**,只有 §1.1b 看得见。

调用点是 `X.ShouldSaveMana` 末尾**新增的一条独立语句**:

```lua
if bShipped and X.IsReincarnationReserveUnlearned()
then
    return false
end
```

⛔ **刻意不写成兄弟那条语句的第二个析取项**(`A() or B()`):折进去会让 arm 任一 id 同时释放两个帧集,
正是 GH #798 的形状(bundle 读数归因给不了任何一个成员)。分开写让三条储备杠杆
(`wksavecap` / `wksaveidle` / `wkrank0`)**各自可独立 arm**、**互不点名**(pullcad 陷阱,§6.2 逐条驱动)。

方向由**形状**保证而不是由今天的算术保证:`bShipped` 先绑定、释放只在它已经为真时被咨询
⇒ 只能把答案从 true 改成 false。§4.4 / §5.1 在两条引擎分支下逐帧验证「armed 从不拒绝一次出货允许的施法」。
