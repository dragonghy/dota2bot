## §2 缺陷

`X.ConsiderQ` 返回的是一个**施法点**(`X.SkillsComplement:458` 直接喂给
`bot:ActionQueue_UseAbilityOnLocation( abilityQ, castQLocation )`),所以它每一个落单点都是
一句承诺:我返回的点是 Earth Spike 打得到的点。**十二个落单点里十一个证得出这句话**:

| 落单点 | 为什么在射程内 |
|---|---|
| Aoe / 团战 / Farm×2 / Push / Farm-neutrals | `bot:FindAoELocation( ..., bot:GetLocation(), nCastRange, ... )` —— targetloc 按构造就在 base 的 `nCastRange` 内;`J.GetAoeEnemyHeroLocation:299` 包的是同一个调用、同一个 `nCastRange` |
| 攻击 | `J.GetDelayCastLocation( ..., nCastRange, 260, ... )` —— 超过 `nCastRange + 244` 返回 nil,否则钳到 `nCastRange + 8`(`jmz_func.lua:3036-3046`) |
| 撤退 / 常规 / 肉山 / Tormentor | 读 `nInRangeEnemyList`(`nCastRange`)或直接 `J.IsInRange( ..., nCastRange )` |
| **击杀** | **没有。** 遍历 `nInBonusEnemyList`(`nCastRange + 200`),零距离项,原样 `return npcEnemy:GetLocation()` |

### ⭐⭐ 承重的不是那段路,是 Hex 被逐帧续锁

`X.SkillsComplement:459` 在 **出价** 时(不是在法术离手时)盖 `lastCastQTime = DotaTime()`,
而 `X.ConsiderW:791` 的第一条守卫是 `lastCastQTime > DotaTime() - 0.8`。

* **射程内的出价**:法术真的施放 ⇒ Q 进 CD ⇒ 下一帧 `abilityQ:IsFullyCastable()` 转假 ⇒
  `X.ConsiderQ` 返回 0 ⇒ 锁一帧后自动解除。
* **射程外的出价**:引擎先走位,**什么也没施** ⇒ Q 仍 castable ⇒ 下一帧同一个循环再出价、
  **再盖章** ⇒ **整段路上 Hex 被一次没发生的施法逐帧续锁。**

这个失效模式**只存在于那个能在射程外出价的分支上**。这就是为什么到达项属于击杀循环,
而不属于「攻击」分支自己的 `+300` slack(那条下游已被钳住,见 §6 限度 2)。

## §7 与 `lionrreach`(#617)的关系,说清楚

同一条论证落在**另一个函数、另一个技能**上 —— `lionrreach` 收的是 `X.ConsiderR` 击杀循环的
`+400`。**不是同一个缺陷**:R 那条是 unit-target 施法,代价是走位;Q 这条是 location 施法,
代价里多出一条 R 根本没有的 —— **`lastCastQTime` 把 Hex 逐帧续锁**。

⚠️ 两个 helper 的四条守卫行**逐字相同**是故意的(一致性),但这让变异台的锚点有了**真实的
歧义风险**:`if not bShippedLethal then return bShippedLethal end` 在这个文件里有**两处**。
脚本头部因此写死一条规矩:**每个锚点都必须跨过带 id 的那一行**。锚点歧义会 `exit 3` 中止
而不是打分 —— 一个中止的变异体不是一个存活的变异体。
