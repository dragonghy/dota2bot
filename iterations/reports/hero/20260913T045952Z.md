## 2. ⭐ 归因被证否,而这改变了答案

两条,都是**驱动出来的**,不是论证出来的:

**(i) 没有 abilities 的行答 `0`,不是 `nil`。** 语料里现存 3 行这样的 WK,逐行驱动:

```
f_073148_zuus_lina.lua    Q:GetManaCost=0  R:GetManaCost=0  GetMana=224  level=7   ShouldSaveMana -> false
f_080225_wk_lane.lua      Q:GetManaCost=0  R:GetManaCost=0  GetMana=279  level=1   ShouldSaveMana -> false
f_080225_wk_revive.lua    Q:GetManaCost=0  R:GetManaCost=0  GetMana=375  level=7   ShouldSaveMana -> false
```

**三行全部不崩**。机理已经在树上写着(`tests/test_wk_rank0_absence_join.lua` 抬头):
loader 把每一个 ability reader 装在 `for i, a in ipairs(u.abilities or {})` 里,没有列表
就循环零次,于是所有读落到 `tests/mock/bot_api.lua` 的通配默认 —— `^Get` 答 **0**。
本轮**重新驱动**了它,因为 #794 建立在它的否定上。

**(ii) nil 是 `nLV`,在链的第一个比较上。** 暂存一行死 WK 后复现:

```
./bots/BotLib/hero_skeleton_king.lua:1781: attempt to compare number with nil
    1781:  local bShipped = nLV >= 6
```

**为什么 issue 会看错**:Lua 把跨行表达式报在**出错算符所在的那一行**,而
`local bShipped = ... and ... and ...` 是**一个**表达式;issue 引的是它的**最后一行**
(`… GetManaCost() < abilityR:GetManaCost()`),不是报错行。
⇒ 断言**不引行号,现场解析源码**(`tests/test_wk_dead_row_precondition.lua` §4
同时钉「报错行 == `nLV >= 6` 的行」与「报错行 ≠ `GetManaCost` 那行」)。

**变量是 liveness,不是 abilities 列表**:上面三行没有 abilities、**活着**、不崩;
死行才崩。

## 3. ⭐⭐ 裁定:(乙) 驱动侧 —— 而且不是口味问题

出厂代码把这个前置条件**自己声明了两遍**,两处都不是本组为这次写的:

1. `bots/ability_item_usage_generic.lua` 的 `AbilityUsageThink`:
   `if ... or not bot:IsAlive() ... then return end` **排在**
   `BotBuild.SkillsComplement()` **之前** ⇒ 死英雄在真实对局里**根本进不了这个文件**;
2. `X.SkillsComplement` 的第一条语句是
   `if J.CanNotUseAbility( bot ) or bot:IsInvisible() then return end`,而
   `J.CanNotUseAbility` 的**第一个析取项**就是 `not bot:IsAlive()`
   (`bots/FunLib/jmz_func.lua:114`);这个文件所有逐帧状态(`nLV`/`nMP`/`nHP`/
   `hEnemyHeroList`)都在那条 return **之下**赋值。

⇒ 在调用点加 nil 守卫,是**替出厂代码防一个它结构上拒绝进入的状态**;
更糟的是它会把**一次响亮的崩溃换成一个安静的答案** —— 而那答案的每一项读数都是**缺席**,
正是那六条被顶红的计数第一次会**悄悄**变掉的方式。

裁定写进了**它被问到的那个位置**(`X.ShouldSaveMana` 抬头,`bots/` 唯一的改动,注释,
零行为),并钉在 `tests/test_wk_dead_row_precondition.lua`(5 绿):

| 节 | 钉的是 |
|---|---|
| §1 | 引擎侧前置条件:`AbilityUsageThink` 里 `not bot:IsAlive()` 排在调用之前 |
| §2 | 文件侧前置条件:liveness 闸在 `nLV` 赋值之前;`nLV` 全文件**只有一处**赋值 |
| §3 | #794 §2 证否:**活着**且无 abilities 的行答 0、不崩 |
| §4 | 复现:死行 ⇒ 报错行 == `nLV >= 6` 的行,且 ≠ `GetManaCost` 那行(**行号解析,不引**) |
| §5 | 四个普查文件**都**带 liveness 谓词(源码断言),计数用可升不可降的 ratchet |
