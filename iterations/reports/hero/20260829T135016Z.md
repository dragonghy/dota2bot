## 1. ⭐⭐ 主发现:那次量具修复**在 fixture 帧上一个绿都没变红** —— 上游还各有一个没建模的 0

普查(-44)写下的警告是:那两个 `ZERO_TRUE` 站点是量具修复**唯一的绿→红方向落点**,
所以「断言这一帧退撤欲望 0.9 / 下颚想出手」的绿**可能是 mock 给的**。

驱动之后,这句话要改一个方向,而**结论比原文更强**:

> **极性的读法是对的**(§2/§5 驱动坐实),**但在 fixture 帧上这个修复什么也没翻转** ——
> 因为两个站点**各自还有一个上游的 0**,而那个 0 **属于量具不属于帧**,
> 于是它原样活过了那次修复。

| 站点 | 上游那个 0 | 为什么帧答不出来 |
|---|---|---|
| `X.RetreatWhenTowerTargetedDesire()` | **主角自己的** `GetEstimatedDamageToTarget` 恒 **0** | `replay_fixture` 只有「敌人**打到**主角」的地面真相(`observed.burst`),**没有**「主角**打出去**」的任何来源,于是它把 burst reader 发给每个英雄,主角自己那个就是 0。`nDamage` 在到达 `GetActualIncomingDamage` **之前**就已经是 0 |
| metamorphic_mandible consider | 每个敌人的 `GetAttackDamage()` / `GetAttackSpeed()` 恒 **0** | .dem 切片两个都不带,于是 `dmg * speed * duration` 这个和在到达那个调用**之前**就是 0 |

⇒ **普查那句「可能是在读 mock」今天仍然成立**,只是**发绿的那个 mock 数据换了一个**。
§3 / §6 就是把这件事钉住的:它们**在修好的默认值在位的情况下**断言 0.9 / `DESIRE_HIGH`,
并且**在失败信息里写明这个值是上游给的、不是挣来的**;§7 把两个上游 0 钉到它们的源码行上,
所以**谁把其中任何一个建模了,这个文件会红**,而不是让这条 caveat 悄悄过期
(红的那条信息直接写着「这是好消息,并且它作废本条断言:去重读所有已发表的相关说法」)。

**这是 GH #221/#207 的同族但换了一层**:那两族说的是「注册键会漂」,
这条说的是「**修好一个未声明的世界假设,不等于那条路径变得可判**」——
上游还有第二个未声明的假设时,可判性并没有回来,而**中间没有任何东西会举手**。
