## 1. 结论(四个读数,按可信度从高到低)

对象是 `X.ShouldSaveMana`(`bots/BotLib/hero_skeleton_king.lua:1163`),
它是 `X.ConsiderQ` 的**第一条语句**的第二个析取项:

```lua
if nLV >= 6 and nAbility ~= nil and abilityR ~= nil
   and abilityR:GetCooldownTimeRemaining() <= 3.0
   and ( bot:GetMana() - nAbility:GetManaCost() < abilityR:GetManaCost() )
```

| 读数 | 值 | 分母 | 归属节 |
|---|---|---|---|
| 语料里的 WK 帧 | **36**,其中**可定价 33 / 必须排除 3** | — | §1 |
| 结构闸内(`nLV≥6` 且 `R cd ≤3`) | **11** | 33 | §2 |
| 保蓝**开火** | **6** | 11 闸内 / 33 可定价 | §2 |
| **边际域**(开火 **且** Q 本来就 fully castable) | **4** | 6 | §3 |
| **构造性**(**max** mana < Q价+R价) | **1** | 6 | §4 |
| 保蓝改变了多少次 Q 决策 | **0**,而且**这个 0 不能当代价读** | 33 | §5 |

### 1.1 ⭐⭐ 最重要的一条是 §5 的**拒答**,不是 §2 的 6

#407 问的是「锁掉多少 Q」。语料**答不了**,而且这次是**量出来的不是猜的**:
出货的 `X.ConsiderQ` 在 **33/33 可定价帧上返回 0**,
- 在**出货量具**下(`GetCastRange` 未 spec ⇒ 答 0,GH #391)是 0;
- 把 Q 的 KV 射程 **525** 喂回去之后**仍然是 0**;
- 把保蓝**强制按成 false**、别的一个字节不动,**33 帧没有一帧的决策发生变化**。

⇒ **DOMAIN-EMPTY**(GH #400 那一类:一个只能证伪的读数)。这条本身是好消息:
它把「保蓝在语料上锁掉了 N 次施法」这句**任何人都可能顺手写下的话**提前钉死为 **不可写**。

**而这个 0 之所以是读数不是空转,靠的是 §5 的那个控制**:
在 4 个边际帧上分别数 `abilityQ:GetCastRange()` 被调用了几次 ——
**出货腿 0 次**(保蓝确实在那一行之前短路了),**解锁腿 ≥1 次**(函数体真的跑了)。
没有这个计数器,「0 个决策改变」和「反事实压根没执行」**长得一模一样**。
变异 **M4**(把保蓝从守卫里挪到读射程之后)**只红这一节**,证明计数器测的就是那个短路。

### 1.2 §3 是 6 和「6 都有代价」之间的那道差

保蓝开火的 6 帧里,**2 帧的 Q 本来就不是 fully castable**
(`f_225947_wk_trade_kite`、`f_260725_105305_wk_reincarn_gap`)——
`not abilityQ:IsFullyCastable()` 是**排在保蓝前面**的析取项,那两帧**没有保蓝也一样被拒**。
⇒ 能谈代价的只有 **4** 帧。把 6 当成代价的分子是这一格最容易犯的错。

### 1.3 §4:构造性那一帧仍然是 1,而 315 是**读**出来的

`f_232320_wk_od_burst`:Q价 95 + R价 220 = **315**,该帧 WK 的 **max mana 272**。
本轮补了刀口:把蓝直接填到 **max(272) 仍然开火**;**315 静默 / 314 开火** ——
门限就是 Q价+R价 本身,不是别的常数。语料里**只有这 1 帧**是构造性的,
即「满池也放不出 Q」在这份语料里**罕见**,不是普遍状态。

### 1.4 ⭐ 新发现(§6):这条规则**从来不问 R 学没学**

守卫的操作数是**英雄等级** `nLV >= 6` 和**句柄非 nil**;它**不问 `abilityR:GetLevel()`**。
句柄对未学的技能同样非 nil,冷却读 0(≤3 成立)⇒ 只剩价钱一项在决定行为。
- 语料**说不了**这件事:33 个可定价帧里 **0 帧**是「lv≥6 且 R rank 0」。
- 因此写成**条件式而不是发现**:引擎若对**未学**技能返回一级价(mock 的阶梯就是这么答的,
  本轮用降级 rank 的反事实核过),那么 bot 会为一个**放不出来的大招**扣住 220 蓝;
  引擎若返回 0,则 `mana − Q价 < 0` 恒假,这条永不开火。**我们手上每一帧都跟两种读法相容。**
- 这个形状**不是假想**:GH #366 / #374 量到过十个英雄大招卡级、技能点没花完。

## 2. 计量纪律:三个「0 不是 0」的坑,本轮各堵一次

1. **`max_mp` 缺失 → mock 默认 300**(`tests/mock/bot_api.lua:220`),而 **300 < 315**。
   一个缺字段的帧会**凭空制造**一个「构造性放不出 Q」。§1 断言 **36/36 帧都自带 `max_mp`**,
   并把那个 300 的默认值本身也钉住(变异 **M8** 把默认改成 400,**只红这一节**)。
2. **3 个 v1 fixture 没有 `abilities` 列表** —— 它们的 rank/cd/价钱**全读 0**,
   而 0 和「未学、就绪、免费」是同一个整数。
   `f_073148_zuus_lina` / `f_080225_wk_lane` / `f_080225_wk_revive` **逐个点名排除**,
   **其中 2 个正好是 lv≥6** ⇒ 把它们当成「保蓝没开火」会直接稀释 §2 的分子。
   分母因此是 **33 不是 36**,这是本轮所有比例的第一件事。
3. **`GetCastRange` 未 spec ⇒ 答 0**(GH #391):
   §5 的「解锁后仍是 0」如果只在出货量具下取,那是在**半径约 0 的圈**上量的,什么都不说明。
   两种量具**各跑一遍**才敢下 DOMAIN-EMPTY。
