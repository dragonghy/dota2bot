## 1. 问题:门保护的不是大招,是丢掉大招之后的那段回蓝

`X.zuus_ShouldSaveManaForUlt` 的第 7 条子句是

```lua
if hBot:GetMana() >= nCost then return false end   -- "already affordable"
```

它读的是**这一次花费发生之前**的蓝量。于是这个门的**有效域恰好是「储备已经没了」**:

| Zeus 蓝量 | 语义 | 门的行为 |
|---|---|---|
| `>= nCost` | 大招**买得起** —— 唯一还有东西可保的状态 | **一律放行** |
| `< nCost` | 储备**已经花掉了** | 才开始压 chip |

它从来不是在守大招,它守的是**丢掉大招之后的那段回蓝**。一发把蓝量**从线上打到线下**
的技能,门连一次都看不到 —— 而 Zeus 的大招蓝就是这样丢的。

**这条论断不依赖 `J.IsRetreating`**(GH #47 的那个结构性盲点):子句 7 排在子句 8
**前面**,蓝 >= nCost 时无论什么 mode、无论 W2 走哪条分支,结果都是放行。

## 3. 修复:把问题问在它真正关心的那一刻

门收第三个参数 —— **出价方自己的技能句柄** —— 并把子句 7 从「现在够不够」改成
「**花完之后还够不够**」:

```lua
local nSpend = 0
if bPostSpend and hSpell ~= nil then ... nSpend = hSpell:GetManaCost() ... end
if hBot:GetMana() - nSpend >= nCost then return false end
```

三个消费点(`ConsiderW` / `ConsiderW2` / `ConsiderQ`)各自把自己的句柄传下去。

### 为什么必须是**单独一个 id**(`zusultx`),按 #59 §2.2 的建议

post-spend 可负担性**严格蕴含** pre-spend 可负担性(`nSpend >= 0`),反之不成立
⇒ 这是**扩大**一个**尚未过条件 (b)** 的门的生效域,正是 `lanefix` 那类「单点正确、
整体变差」的高风险面。所以:

- 只 arm **`zusult`** ⇒ `nSpend` 恒 0,子句与上线版**逐字节等价**(窄域);
- arm **`zusultx`** ⇒ 跑扩大后的域。
- **两个 id 都不存在「arm 了却什么都不发生」的组合** —— `zusultx` 单独 arm 就跑整条
  规则(这一条**写成了测试**,防的是 `axeblink` 那种 arm 等于测空气的陷阱)。
- 增量 = **两波之间的一次减法**,不是两条规则的和。

**扩大的幅度是有界且小的**:post-spend 与 pre-spend 只在蓝量落在
`[nCost, nCost + spend)` 时才不同 —— 对一发 Bolt 是 **~130 宽**的一条带。
