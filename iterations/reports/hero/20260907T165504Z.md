## 1. 矛盾是什么(`-118` 的原句),以及先做的那道减法

树里两个文件读**同一批** Wraith King 帧,对「Reincarnation 的 ability level 0」
给出相反的读法:

- `tests/test_wk_save_mana_lock_census.lua` §1 把 3 个「没有 abilities 表」的 WK 帧
  **排除**,并写明「其中 **2 个是 level >= 6**,这正是它们必须被排除而不是被记成
  『储备没开火』的理由」—— 即把 rank 0 读成**缺席**。
- `tests/test_wkreinctr_untrained.lua` 头注把同一形状读成**数据**:
  「36 个活体 WK 帧里 24 个答 TRUE,其中 **14 个坐在 ability level 0 上**,
  **两个在英雄等级 7**」。

两个「2」在套件里都是**被断言的数**(那边 `at_six == 2`,这边
`C.ship_true_untrained_lv6 == 2`)。**一个计数说不出自己是不是同一个计数** ——
所以本轮先做的不是新读数,是把两句话**按 fixture 名对上号**。

### 结论一:是同两帧,而且是**集合相等**不是计数相等

新文件 §2 把两侧各自按**它自己文件的措辞**构造成集合:

| 集合 | 定义(照原文) | 成员 |
|---|---|---|
| A(census 侧) | 无 abilities 表 ∧ 英雄等级 ≥ 6 | `f_073148_zuus_lina`, `f_080225_wk_revive` |
| B(wkreinctr 侧) | 出货答 TRUE ∧ `IsTrained()` 假 ∧ 英雄等级 ≥ 6 | `f_073148_zuus_lina`, `f_080225_wk_revive` |

**A ≡ B,逐名相等。** 断言写成集合相等而不是 `#A == #B == 2`:两个碰巧相等的计数
只相等一轮,而计数**恰恰是**本轮立案时那个答不了问题的量具(铁律 4 (ii) 同族)。
红字直说「B 里出现而 A 里没有的帧 = 这条杠杆终于在本语料上有域了,去量它,别重新基线」。

⭐ 顺带钉住一件本轮之前没人说出口的事:`f_073148_zuus_lina` **正是
`tests/test_wkreinctr_untrained.lua` 自己的 PIN 帧**(`local PIN = ...`)。

## 2. 哪一种读法对:答案在 loader 里,不在数里

`tests/mock/replay_fixture.lua:725` 把**每一个** ability reader 装在
`for i, a in ipairs(u.abilities or {})` **里面**。一个没有 abilities 表的 unit
让这个循环跑 **0 次** ⇒ `GetAbilityByName` 交回的句柄上**什么都没装**,
四次读全部落到 `tests/mock/bot_api.lua` 的通配:
`^Get` → **0**(:184)、`^Is` → **false**(:167)。

于是 `GetLevel() 0 / IsTrained() false / GetCooldownTimeRemaining() 0 / GetManaCost() 0`
—— **和一个真正没点的大招逐位相同**,由一个什么都没记的 unit 产生。

**⇒ census 的读法对:那 3 帧的 rank 0 是缺席,不是 0。**

新文件 §1 把这条**驱动**下来而不是论证下来,三例:

1. **loader 只有一个安装点,而且在循环里面**(源码断言,注释已剥离):
   `sp.GetLevel` / `sp.IsTrained` 各自**恰好一处**赋值,且位置在循环头**之后**。
   第二个安装点会让「没有 abilities 表的 unit 拿不到真 reader」从 loader 的性质
   降格成巧合。
2. **缺席帧上句柄的 `__spec` 里 `GetLevel`/`IsTrained`/`GetManaCost`/
   `GetCooldownTimeRemaining` 全是 `nil`,而四次读照样答 0/false/0/0**;
   同时该帧 fixture 里**根本没有** Reincarnation 那一行(`raw_rank == nil`,
   与 `raw_rank == 0` 是两个值)。
3. **对照**:在一个**计价**帧上读一个树里没有的技能名
   (`skeleton_king_no_such_ability`),四个答案**逐位相同** ——
   这条把「这是 R 的答案」与「这是通配默认的答案」分开
   (GH #386 / #391 那个「没上规格的 getter 答 0」的老形状)。

## 3. ⭐⭐ 判读的代价:那 14 个 flip 的拆分,和一条没人报过的第二道闸

这才是本轮值得开文件而不是改一句注的地方。`wkreinctr` 在 **helper** 上翻 14 帧;
它的调用点(`bots/mode_retreat_generic.lua:198-200`,**出货、无闸**)自带
`bot:GetLevel() >= 6`。本轮把这 14 帧拆开:

| | 帧数 | rank 0 是什么 | 调用点的 `GetLevel() >= 6` |
|---|---|---|---|
| 计价帧(有 abilities 表) | **12** | **真实记录的数据** | **全部被拒** —— 12 帧的英雄等级是 1..5 |
| 缺席帧 | **2** | **缺席** | 通过 |

**12 个真实的 rank 0,一个都不在等级 6 以上。** 而在 Dota 里,
Reincarnation 在英雄等级 6 之前**根本不能点** —— 那 12 帧的 rank 0 不是缺陷,
是规则。唯二越过调用点自己那道等级闸的,正好是两个缺席帧。

**⇒ 这份语料里,这条杠杆存在的那个形状(等级 ≥ 6 且大招点真的没花)一帧都没有。**

`tests/test_wkreinctr_untrained.lua` 与 `bots/FunLib/jmz_func.lua` 的出货注
(honest bounds (2))把调用点的 0 **全部**归给 `J.IsInTeamFight(bot, 1200)`
在 36 帧上恒假,并称那两帧是「**real replay frames, not a constructed case**」。
前半句是真的,**但不是唯一的障碍**:把 team-fight 那一项强行置真,域也只有 2,
而这 2 帧都是缺席。「real replay frames」里**真实的是英雄等级 7,不是「no point in
the ultimate」**。

断言的写法(全部避开计数脆性,GH #106/#127):
- 「每一个**记录**了 rank 0 的帧都在等级 6 以下」写成**全称**而不是 `== 12`
  —— 它对还没写的 fixture 继续成立,而它变红那天正是语料终于拿到这条杠杆
  真正要的那一帧(GH #366/#374 让这个形状本身是真的)。
- census §6 的那个零(计价 ∧ 等级≥6 ∧ rank 0 = 0)在新文件里**从 raw rank
  重算了一遍**,不走 loader ⇒ 两个文件不可能读的是同一个人造物。
  这是 `-118` 点名要一起对号的**第三条读数**,它也对上了。
- 新增 **raw ↔ driven 一致性**一例:凡 fixture 记了 rank 的帧,loader 必须原样端出
  (rank / IsTrained / 英雄等级三项)。没有这一例,§3 的 raw 那一半就是一份
  没被校验的平行读数,`raw_rank == nil` 也就不再等于「loader 无米下锅」。
- **反真空**:等级 ≥ 6 的 WK 帧 **23** 个(ratchet),即「没有帧越过这道闸」
  与「没有帧到达这道闸」分得开。
- **顺带一条把「同一批帧」这个前提也钉住了**:本轮的独立遍历(不复用
  `tests/_wkreinctr_sweep.lua`)在同一份 fixture 目录上重现了它的四个数 ——
  WK 帧 **36**、出货 TRUE **24**、等级≥6 **23**、未学 **15**。
  与 census 的 33/3 拆分放在一起也自洽:`21 (计价, lv≥6) + 2 (缺席, lv≥6) = 23`。
  ⇒ 「两个文件读的是同一批帧」不是假设,是复现出来的。
  剩下那 1 帧的差(未学 15 对 flip 14)也对得上:`f_260820_181711_wk_l1trade_333`
  的蓝是 **158 < 160**,出货那一项先把它拒了 —— 与 sweep 自己写的
  「15 untrained but only 14 flips」逐字同源。
