## 1. 事实(两半都是从源头读出来的,不是抄的)

**(a) 战斗饥饿是纯伤。** `axe_battle_hunger` 的 `AbilityUnitDamageType` =
`DAMAGE_TYPE_PURE`,`TooltipSummaryProperties` 里写着 `DPS_Pure`
(游戏自己的英雄 KV,走 d2vpkr 镜像 —— `tools/agent/gen_ability_meta.py` 读的同一个源,
2026-08-24 取)。`duration` **12.0**、`damage_per_second` **12/16/20/24**、
本文件 t15 选的 `special_bonus_unique_axe` **+8** ⇒ 裸 144/192/240/288,
带天赋 **240/288/336/384**。

**(b) 判据只认魔法。** `J.WillMagicKillTarget`(`jmz_func.lua:1110`)首行
`local nDamageType = DAMAGE_TYPE_MAGICAL`,末行
`npcTarget:GetActualIncomingDamage( EstDamage, nDamageType ) >= npcTarget:GetHealth()`。

纯伤不吃魔抗,而每个英雄基础 25% ⇒ **满级带天赋的 384 被读成 288**,
带魔抗装更低。方向是**少放**(漏杀),不是乱放。

## 2. 它不是全仓习语 —— 同一个文件的 `X.ConsiderR` 就是对的

`X.ConsiderR` 声明 `nDamageType = DAMAGE_TYPE_PURE`,再拿**裸血**比
(`GetHealth() + GetHealthRegen() * 0.8 < nKillDamage`),**没有任何减伤项**。
同文件、同伤害类型、相反的算术 ⇒ 疏漏,不是设计。旁证:`J.CanKillTarget` 专门
给 `DAMAGE_TYPE_PURE` 开了旁路,仓库知道纯伤这回事。

**普查(按 KV 的 `AbilityUnitDamageType` 机器分类)**:焦点五里非 MAGICAL 的技能只有
Axe 三个(battle_hunger / culling_blade / counter_helix,全 PURE)与 WK 的
bone_guard(PHYSICAL);其中**只有 battle_hunger 把伤害喂进了只认魔法的击杀判据**
——culling_blade 走裸血比,bone_guard 没有击杀判据,WK 的 hellfire_blast 走
`J.CanKillTarget` 且**显式传类型**。CM / Lion / Zeus 的技能**全是 MAGICAL**,
它们的判据没有类型错误。**⇒ 唯一的一处。**

## 4. 落地的改动

`X.WillBattleHungerKill`:**先跑出货的 `J.WillMagicKillTarget`,它说 true 就 true**
⇒ **gate-off 逐字节等于出货谓词,这是结构性的不是量出来的**(测试里就按这个结构断言)。
只有它已经答 false、**且** armed(且 turbo),纯伤算术才有第二次发言权:

```lua
nDamage * ( 1 + bot:GetSpellAmp() ) - npcEnemy:GetHealthRegen() * nDelay >= npcEnemy:GetHealth()
```

= 出货公式**只把两个魔法项中和掉**。**一根杠杆**:法强系数留着(出货 helper 有它)、
12 秒回血项留着(12 秒是很长的窗口,4 hp/s 就回 48,足以把 250 血的目标推出 288 的带外
—— 已写成测试)。**对出货 helper 有特殊意见的目标一律弃权**:美杜莎魔法盾 /
昆卡幽灵船延迟 / TA 折光 / 刚背(按单位名)。那四个里**三个照吃纯伤**,弃权是安全的那侧,
也避免了把四个特例复制一份再让它漂移。

## 7. 留给后来人

1. **写一个「击杀判据」之前,先去 KV 里读一眼这个技能的 `AbilityUnitDamageType`。**
   仓库有三个类型正确的 helper(`J.CanKillTarget` 带类型参数并给 PURE 开旁路、
   `J.WillKillTarget`、`J.WillMixedDamageKillTarget`),而 `J.WillMagicKillTarget`
   **名字里带 Magic 却是最常被随手用的那个** —— 它是唯一算法强的,于是所有人都用它。
2. **「同一个文件里另一处怎么写的」是最便宜的判别式**:本轮判定这是疏漏而非设计,
   靠的不是外部资料,是 `X.ConsiderR` 就在同一个文件里把同一种伤害类型写对了。
3. **放宽型的门,可以写成「出货判据先跑一遍」的形状** —— gate-off 等价性就从
   「测出来的」变成「结构上的」,而且测试能对结构本身断言(M6 就是这么被抓的)。
4. **一个 mock 默认值可以让整整一族分支离线消失,而且方向可能是反的**:
   这里 0 让活人永远判「杀不掉」、让尸体永远判「杀得掉」。
   **凡是「某某分支在语料里从不开火」,先去问那条分支读的引擎函数在 mock 里返回什么。**
