## 2. ⭐⭐ 主发现:那个 0 有两个极性,写下来的只有一个

普查把 `bots/` 下每一个调用表达式按「**旧的 0 让它所喂的谓词变成什么**」分类:

| 类 | 数量 | 含义 |
|---|---|---|
| `ZERO_FALSE` | 30 | 分支**永远不开火**(击杀确认不确认、威胁闸门不触发)——**已被写过的那一半** |
| `ZERO_PURE` | 2 | 同上,但**递进来的是 PURE 伤害**(见 §4) |
| **`ZERO_TRUE`** | **2** | **分支无条件开火** —— **本轮新点名** |
| **`ZERO_NOBODY`** | **4** | 选人循环**一个都不选**(见 §3) |
| `ZERO_VALUE` | 3 | 返回给调用方的估算值 |

两个 `ZERO_TRUE` 站点(都是「调用结果 `<` 某个血量」,所以 0 天然满足):

1. `bots/mode_retreat_generic.lua` — `X.RetreatWhenTowerTargetedDesire()`:
   `nDamage / botTarget:GetHealth() < 0.88` ⇒ **无条件 `return 0.9`**。
   ⚠️ 这里的 `<` **在调用的下一行**,这正是"只看调用那一行"的读法会漏掉的形状 ——
   普查因此把比较式**单独钉成 `cmp` 字段**并在语句窗口里找,而不是在行里找。
2. `bots/ability_item_usage_generic.lua` — `X.ConsiderItemDesire["item_metamorphic_mandible"]`:
   `bot:GetActualIncomingDamage(enemyDamage * 1.5, ...) < bot:GetHealth()`
   ⇒ **无条件 `return BOT_ACTION_DESIRE_HIGH`**。

**为什么这条重要,不只是补全历史**:在 `ZERO_FALSE` 那一半上,修默认值只能**把红变绿或不变**;
在这两个站点上它能**把绿变红**。任何断言"这一帧退撤欲望是 0.9""这一帧下颚想出手"的测试,
**可能读的是 mock 而不是帧**。这是 08-29 那次修复的**唯一一个绿→红方向的落点**,
而上一棒的写法(以及 mock 头注、`state.json`)**没有描述过它存在**。

## 3. ⭐ 第二个形状:不是"拒绝开火",是"一个都不选"(4 个站点,其中 1 个已驱动证明)

`hero_largo`、`hero_morphling`(两处)、`FunLib/minion_lib/utils.lua` 是**按入伤打分的 argmax/argmin 循环**:
0 让**每个候选都得 0 分**,而擂主初值也是 0,`>` 从不成立 ⇒ **看完一整张名单、返回 nil**。

最锋利的是 `minion_lib/utils.lua` 的 `U.GetWeakest`,它**除以**那个调用
(`unit:GetHealth() / unit:GetActualIncomingDamage(3000, ...)`)⇒ 每个候选得 `inf`
(尸体是 `0/0 -> nan`),`killUnitTime < minKillTime` 因**算术原因**恒假。

**这一条是驱动出来的,不是读出来的**(普查 §5,跑真实模块、无 J.* 桩):

```
修好后:  U.GetWeakest({900血, 300血})  ->  300 血那个   ✅
旧的 0:  同一张非空名单              ->  nil          ❌
```

`minion_lib/` 在全仓**没有第二个测试**,所以这个行为**一次都没有被观察过**。

## 4. 顺带订正两处措辞级事实

**(a) 「42 call sites」是行数不是调用数。** 它是 `grep -c` 的输出,即**提到这个标识符的行数**。
真实的数是:**41 个调用表达式,分布在 40 行**上 —— 那 42 行里**有 2 行是散文**
(`hero_axe.lua` 的两条头注在讨论这个调用而没有调用它),而 `hero_silencer.lua`
**一行上有两个调用**。方向是无害的那一边(多算 1),但**本普查是按调用计的**,
两个数必须先分开才谈得上核对。普查 §1 **推导**这三个数(行=代码行+注释行;调用≥代码行且严格大于),
而不是断言那个坊间数字。

**(b) `J.CanKillTarget` 的 PURE 短路没保护住两个站点。** 「every **non-PURE** kill-confirm」
这个措辞来自 `J.CanKillTarget` 里 `if dmgType == DAMAGE_TYPE_PURE then` 的提前返回。
但 `hero_silencer.lua` 的 `X.sil_RealDamage` 和 `jmz_func.lua` 的 `nRealPureDamge`
**把 PURE 伤害直接递给引擎调用** ⇒ 那个 0 照样吃掉它们。普查把这 2 个站点单列成 `ZERO_PURE`。

## 6. 普查自己的不变量(它不是一张手抄清单)

- **每个调用表达式必须被恰好一条普查行认领**;总数不对就红,报错文本直接写着
  **「A NEW CALL SITE MUST BE CLASSIFIED」**并指向分类说明 —— **这条断言就是设计来在增长时炸的**
  (与 GH #273 那条「被 `eq` 钉死、合规增长就打红」不同族:那里增长是合法的,这里增长**必须**被分类)。
- **认领用的是内容子串,不是行号**(GH #221:在人人可编辑的文件里钉行号,当天应验过两次)。
  两条字节相同的 `jmz_func` 行用 `n=2` 显式声明。
- 每条普查 key **必须自己包含 `GetActualIncomingDamage`**,否则普查可以靠一个不相干的子串"认领"一个调用。
