## 1. 事实:`GetAbilityDamage()` 只读一个 KV 字段,而几乎没人声明它

`docs/BOT_API_REFERENCE.md:1526` 把它写成 "base damage of the ability at current
level"。它读的是技能的**顶层 `AbilityDamage`** 字段,**不是** `AbilityValues/damage`。
现代 Dota 早把逐级伤害搬进了 `AbilityValues` ⇒ **不声明该字段的技能静默返回 0**
(无报错;`print()` 到不了控制台、引擎错误处理坏掉,AGENTS.md)。

新工具 **`tools/agent/ability_damage_census.py`**(每英雄一次 GET,零 AWS,与
`gen_ability_meta.py` / `special_value_key_census.py` 同一个 d2vpkr 镜像)
+ 冻结快照 **`tests/mock/ability_damage.lua`**(测试不上网,同 #166/#170 的做法):

```
abilities declaring AbilityDamage: 30, of which nonzero: 16
GetAbilityDamage() call sites: 58
  PROVEN-ZERO      : 46
  UNRESOLVED       : 10
  UNRESOLVED-GLOBAL:  2
```

**判据单向,而且不需要解析句柄** —— 这是它比 #162 那把 key 尺子**强的一处**
(#162 自认「不解析句柄→技能」,所以「key 在」什么都不证明):

> `hero_<h>.lua` 里的一处读数,**只可能**取在 `<h>` 自己的技能上;所以只要 `<h>`
> 一个非零 `AbilityDamage` 都没有,那处读数就是 0 —— **无论句柄指向谁**。

反向照旧什么都不证明(`<h>` 有一个 ⇒ UNRESOLVED)。

**焦点五**:zuus 2 处、lion 3 处,**全部 PROVEN-ZERO**;axe / skeleton_king /
crystal_maiden **一处都没有**。

## 2. 核心发现:同一个 0,在同一个文件里往**两个相反方向**切

`zuus_lightning_bolt` 的 KV 里**那一段是空的**(`// Damage.` 底下什么都没有;
数值在 `AbilityValues/damage` = 140 220 300 380)。

### (A) `X.ConsiderW2` —— **放宽**

```lua
local nDamage = abilityW:GetAbilityDamage()                       -- 0
local nCanKillHeroLocationAoE =
    bot:FindAoELocation( true, true, ..., nRadius, 0.3, nDamage )
if nCanKillHeroLocationAoE.count >= 1 then ... DESIRE_HIGH ...
```

`FindAoELocation` 的最后一个参数是 `nMaxHealth`,引擎规则在
`docs/BOT_API_REFERENCE.md:1288`:**"Pass `0` for no HP filter (target any HP)."**

⇒ **那条自己取名 `nCanKillHeroLocationAoE` 的斩杀分支,实际问的是
「施法距离内有没有敌方英雄」**,并以 `DESIRE_HIGH` + 120–135 蓝回答「有」。

### (B) `X.ConsiderW` / Lion `X.ConsiderQ` —— **收紧**

同一个 0 喂给 `J.WillMagicKillTarget` ⇒ **把击杀分支整条杀死**。

> **⭐ 这是 #162 那把尺子答不了的那一半:一个静默的 0 往哪边切,必须逐个调用点读。**
> 普查能给「读数是 0」;给不了「所以这个分支死了」。

**与 GH #173 是同一个蓝去哪了的第三条线索**:#173 是「花在一个不存在的击杀上」
(静电场高估 ~2 倍),本条 (A) 是「花在一个**根本没问过能不能杀**的施法上」,
而 backlog §4 量的是「斩杀窗口来的时候没蓝」。三条都指向 Zeus 的同一笔账。

## 3. 落地

**只修了 (A)**,gated `zusboltcap`:新 helper `X.GetBoltKillHealthCap( hAbility )`。

- **gate-off 等价结构性**:出厂表达式 `hAbility:GetAbilityDamage()` 是函数的
  **最后一句**,armed 分支是唯一绕行。
- **armed 不可能比出厂更宽**:`<= 0` 的 key **落回出厂表达式**,不发明默认值
  (GH #162 的规矩)。
- **方向单一**:出厂 0 = 不过滤,armed 正数 = 有限上限 ⇒ **纯收紧**。
  **收紧与放宽不写进同一个谓词**(GH #166)。

  加上去是**另一个放宽搭着收紧的门上车**。
- **顺带核对为正确、有意没动**:`nRadius = 325` 与 KV `spread_aoe = 325` 逐位相符
  (注释已写进源码,免得后人重查)。

**(B) 一族有意不修**:救活一条死掉的击杀分支是**放宽**,各自要各自的依据和 id
