## 4. ⭐⭐ 一行算术:有一局盖着 armed 章,跑的是出厂行

两张 build 表**各只有一行**,所以 `J.Skill.GetRandomBuild` 在两条腿上都是**确定性的** ——
腿内的 stall/非 stall 分裂**不可能**来自「随机选行」。这一步必须先钉死,否则后面全是空话。

```
出厂    {2,1,4,2,2,6,2,1,1,1,6,4,4,4,6}   四点花在 [4],从不点名 [3]
odbuild {2,1,3,2,2,6,2,1,1,1,6,3,3,3,6}   [4] -> [3] = objurgation
```

`[3]` 是 objurgation,而 armed 行的**第三点就花在它身上** ⇒

> **凡是跑了 armed 行的局,英雄 3 级起 `objurgation` rank ≥ 1。**

这是一条单行证伪器,**W25 有一局不满足它**:`20260829_124418` 盖的章是
`s1603:radiant`,**OD 就在 radiant —— armed 侧**,却以 `objurgation` **rank 0** 收场,
且技能表与出厂行的预测**逐位相同**(orb 1 / astral 4 / objurgation 0 / eclipse 1 = 6 点)。
**armed 行在任何等级都产不出 rank 0。⇒ 那一局跑的是出厂行,而它自己的章说它那侧 armed。**

**不是部署顺序**:同 run、同种子(s1603)、同侧的**前一局** `20260829_123208`
objurgation 到了 **rank 4**(出厂行永远产不出 4)。两局一armed一不armed,中间没有换侧。

**这条约束的不是 odbuild,是读数本身**:它给「任一 id 的 armed 腿里有多少真的 armed」
压了一个上界,**对本波每一个 id 成立**。⇒ 已开 **GH #320([harness])**,不归本组离线判。
