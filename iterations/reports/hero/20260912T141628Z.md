## 2. 缺陷

`bots/BotLib/hero_crystal_maiden.lua` `X.ConsiderR`,branch 1(群战释放路):

```lua
local nAllies =  J.GetNearbyHeroes(bot, 1200, false, BOT_MODE_NONE )   -- 函数第三行
...
if ( ( #nEnemysHeroesInRange >= 3 and X.cm_IsFieldCrowdReleaseOk( aoeCanHurtCount ) )
     or aoeCanHurtCount >= 2 )

    return BOT_ACTION_DESIRE_HIGH

```

两条析取项**都不含任何队友项**。`nAllies` 在这个函数里唯一的读者是 branch 2
(单杀路),而且方向**相反**(`#nAllies <= 2`,「队友够少,这个人头是我的」)。

⇒ 这个函数里唯一一条「对着一群人开 10 秒引导」的路,恰恰是唯一一条
**不问引导跑的时候身边有没有人**的路。

**条件 (c),论证而不是假设。** `crystal_maiden_freezing_field` 是
`AbilityChannelTime 10` + `AbilityCooldown 100/95/90`(KV,镜像在
`tests/mock/special_value_shapes.lua`)。开引导把 CM 变成 10 秒的**静止、可打断**
目标,伤害按 0.1s 一跳摊在**整个窗口**里 ⇒ 这一发值不值它的冷却,取决于
**引导被不被允许跑完**。而让引导跑完的不是 CM 自己(她没有解控、没有自净、
没有位移),是别人的身体 / 控制 / 治疗。1200u 内一个友方英雄都没有时,没有这个
「别人」。标准打法是把团队引导大招开在**队伍已经在打的团里**,而不是一个人开一个团。
⚠️ 注意这个论证讲的是**引导活不活得下来**,`cmrcrowd` 讲的是**伤害落不落得到**
—— 对同一条支路的两个不同主张,这是它们必须是两条 id 的第二个理由。
