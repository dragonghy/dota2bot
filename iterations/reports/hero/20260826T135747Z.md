## 2. ⭐ 承重读数:落后一个 patch 的是 odota,而这是**裁出来的**不是猜的

`npc_heroes.txt` 里,一个英雄的天赋是一段**连续的** `"AbilityN" "special_bonus_*"`,
N 就是 `bot:GetAbilityInSlot` 的槽位(上游 1 基)⇒ 这一段的**第 N 条就是 `sTalentList[N]`**,
与 #209 对技能用的是同一套算术。

全 127 英雄:

| 读数 | 值 |
|---|---|
| 天赋段长度 | **每个英雄恰好 8 条且连续**,127/127 |
| 段的起点 | **不总是 Ability10**:123/127 是,**kez / rubick 从 12、largo 从 15、invoker 从 17** |
| odota 顺序 == KV 段 | 106 / 127 |
| **Valve datafeed == KV 段** | **22 / 22 英雄、176 行,逐行相同** |
| odota 与那两者都不同 | 22 个里 **18 个** |

裁判是仓库**已经在用**的 `https://www.dota2.com/datafeed/herodata`(`test_focus_talent_anchor.lua`
的名字本来就抄自那里)⇒ **不是引入第三个信仰,是让已有的那个开口说话。**

**⚠️ 「段起点不总是 10」不是理论**:parser 第一版写死 Ability10,把 invoker 的天赋报成
`invoker_emp` / `invoker_alacrity` / … —— **八个看着很像技能名的技能名,零报错**。
(那 4 个英雄在下面的槽位里装着真技能。)

## 4. ⭐ 本轮最该被拿走的一条:「两个源都这么说」里的第二个源**说不出话**

仓库**同时持有两个答案两天**,没有任何东西发现:

| 文件 | 说 | |
|---|---|---|
| `bots/BotLib/hero_skeleton_king.lua:271` | `hp_300` | **对的** |
| `tests/mock/talent_slots.lua` | `hp_350` | 错的 |
| `tests/test_focus_talent_anchor.lua:127` | `hp_350` | 错的 |

08-24 那次改动把理由记成 **「odota + the hero KV read hp_350」——两个互相印证的源**。

**它不可能是两个**:`npc_dota_hero_skeleton_king.txt` 装的是 `AbilityValues` 的覆盖键,
**一个天赋名字都没有**(`grep hp_300\|hp_350` 命中 **0**)。像 `special_bonus_hp_300` 这样的
**通用**天赋永远不会出现在里面 —— 而**这句话就写在 `talent_slot_census.py` 自己的 docstring 里**,
在引用它的那一行往上三段。

⇒ **写「两个源一致」之前,先确认第二个源有没有能力不一致。**
与 #209 的「找新数据源之前先数一遍仓库已经在读什么」同族,只是早一步:
那一条问「有没有更好的源」,这一条问「我说的那个源**是不是源**」。
