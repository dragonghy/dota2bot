## 4. ⚠️⚠️ 险些登记一个**根本不存在**的发现(本轮最该记的教训)

第一版 header 里我写了一条「sister 文件记录的供给数**在无声地向下漂移**,而它的
单边 ratchet 报不出来」——**证据是我自己量到语料的魔免 instants = 0(记录是 3)**。

**那个 0 是我的 scratch 脚本造出来的,不是语料的。** 根因:

```lua
local b = src:sub(src:find('function CDOTA_Bot_Script:IsMagicImmune%(%)'))
```

`string.find` 返回**两个**值,于是 `src:sub(i, j)` 截出来的是**匹配到的那行签名本身**,
不是函数体;`gmatch` 因此一个 `HasModifier` 都找不到,**免疫名单是空集**,
于是每一帧都读作「不免疫」。

**一个由空谓词产生的 0,和一个由空语料产生的 0,是同一个整数。**
而这个 0 长得**特别像一个发现**——它甚至有个现成的机制解释(单边 ratchet 报不出下降)。

**抓住它的是我自己写的测试**:`n ~= 11` 那个检查,和 §4 的计数节点。所以两件事定下来:

1. §4 的免疫计数**故意做成双边**(`~= 3`),与 sister 那条单边 ratchet 不同 ——
   **本文件每一条经过 IMMUNE 的读数,都同时断言 IMMUNE 是满的**;
2. 变异台加了 **M7**:把 override 体里的 `HasModifier(` 全改名(谓词变空、函数体照样解析),
   **四个节点见红** —— 第一版缺的正是这一个。

这与 sister 文件自己那条「断言 ABSENCE 的扫描在干净的树上没有活的正向路径」是同族,
也是一周内**第四次**同形状(`k=4 读成 1157.0`、§4 手算 829.4、facet 名单当分类器)。

另一处第一版红:§2 的「不读物品」探针里我放了裸的 `black_king_bar`,而它是
`modifier_black_king_bar_immune` 的**子串** ⇒ 探针在**正好证明论点的那一行上开火**。
**子串不是 reader。** 已改成:物品读 API 名单 + 「体内出现的每一个 `black_king_bar`
