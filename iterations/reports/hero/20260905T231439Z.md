## 2. 事实

Frostbite 的 KV(仓内快照 `tests/mock/special_value_shapes.lua`,不是网上引的):

```
crystal_maiden_frostbite:
    damage_per_second  100
    creep_multiplier   4
    duration           1.5 2 2.5 3
    AbilityManaCost    125 135 145 155
    AbilityCooldown    9 8 7 6
```

⇒ 对**小兵**的总伤害 = `100 × 4 × duration` = **600 / 800 / 1000 / 1200**。

出货源码(`X.ConsiderW`,两条独立分支,「先远」与「再近」):

```lua
if ( nEnemysStrongestCreepsHealth2 > 460 or ... )
    and nEnemysStrongestCreepsHealth2 <= 1200      -- 先远
...
if ( nEnemysStrongestCreepsHealth1 > 410 or ... )
    and nEnemysStrongestCreepsHealth1 <= 1200      -- 再近
```

**缺陷不是「这个数错了」,是「对的数被当成了常数」。** 1-3 级各多放行 **600 / 400 / 200** 血的
小兵,而且多放行的那一段**正好落在挑选器偏好的那一端** —— `X.cm_GetStrongestUnit` 取的是
**最强**的那只,所以被多放行的恰恰是最先被选中的。

代价:**125-155 蓝**(CM 缺蓝是本仓常设稀缺,GH #126)+ **6-9s** 她唯一单体控的冷却,
换一只走出根定的小兵。出货加点行 `{1,2,3,2,2,6,2,1,1,1,6,3,3,3,6}` 在 **2/4/5/7 级**点 W
(10 级以下没有天赋行,所以这些下标就是等级)⇒ **咬合区间是 2-6 级** —— 对线期,
也正是该块自己的门 `nLV >= 5` 刚打开、她蓝最紧的时候。

## 3. 改动(gated,turbo-only,未 armed)

新 `X.cm_GetFrostbiteCreepCap( hAbility )`:armed 时读活 KV 三项相乘;读到 `<= 0`
**回落到出厂 1200**;否则逐字返回出厂 1200。`X.ConsiderW` 加一个
`local nCreepCap = X.cm_GetFrostbiteCreepCap( abilityW )`,两处 `<= 1200` 改成 `<= nCreepCap`。
血量下界(460/390/410/360)、其余每一项判据、其余所有分支**一个字没动**。

**SHAPE(GH #162 house rule)**:出货表达式是函数的**最后一条语句**,armed 分支是唯一的绕道
⇒ gate-off 等价是**结构性的**;armed 读数 `<= 0` 落回出货字面量而不是发明一个 0 —— 因为
**上限 0 不是窄化,是关闭**:每只小兵都过不了 `<= 0`,整块在每一场 armed 对局里静音。
§7 就是为这条写的,变异 **M5** 就是它。

## 4. ⭐ 方向:这一根是 NARROWING(前三根都是超集,这根是子集)

`dps*mult*duration <= 1200` 对每一级成立,**4 级取等** ⇒ armed 放行的小兵集合是 shipped 的
**严格子集**,arming 只能**减少**释放。
⇒ 负读数只能读作「那些小兵本来该冻」,**永远不能**读作「杠杆凭空多冻了一只」。
