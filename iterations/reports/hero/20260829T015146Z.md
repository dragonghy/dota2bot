## 1. ⭐⭐ 主产出一:#287 §3 那句「离线读不出来」是错的,而这正是这轮便宜的原因

issue 原文:「**这个判据离线读不出来**(要引擎的 `GetAbilityInSlot`)⇒ 请英雄组按它筛一遍」。

仓库里**已经有**那两块数据,而且都是为别的事买的:

| 需要的东西 | 已有的来源 | 谁买的 |

有这两块,**shipped 的 `J.Skill.GetAbilityList` 就能在每个英雄的真实槽位上离线跑**:
造一个合成 bot,`GetAbilityInSlot(n)` 按槽位表发牌,让**出厂代码**自己走一遍。
不用 `.dem`、不用批测、不用引擎、零成本。

真正读不出来的只有 `IsHidden()`(`test_focus_innate_index_anchor.lua` §2 早已立此),
而 walk 只在 `NOT_LEARNABLE` **且** `IsHidden()` 同时成立时才丢弃一个技能。
处理方式**照抄 `test_hero_slot_order_anchor.lua` §3**:对每个英雄的**可选槽位**
(innate / 神杖・魔晶授予)枚举 **2^k 个 drop-world**,命中写成「**N 个世界里中了 k 个**」。
`k == N` 是关于这个英雄的事实;`k < N` 是关于一条本仓读不了的谓词的事实。**不猜**。

## 3. ⭐⭐ 主产出三:#287 §2 的**两条候选修法都打在一个 KV 说不是 OD 的机制上**

§2 原文给了两条:(a) 让 `GetAbilityList` 对 `slot < 4` 的大招也写 `[6]`;
(b) 把 OD 的 build 从 `6` 改成 `4`。KV 读出来的 OD 槽位行是:

```
slot 0  obsidian_destroyer_arcane_orb
slot 1  obsidian_destroyer_astral_imprisonment
slot 2  obsidian_destroyer_objurgation        ← build 从不引用的那个,索引 3
slot 3  generic_hidden                        ← 索引 4,build 引用 4 次
slot 4  obsidian_destroyer_equilibrium
slot 5  obsidian_destroyer_sanity_eclipse     ← 大招,slot >= 4 ⇒ [6] 已经写了
```

- **(a) 对 OD 是空操作** —— 它的大招在 slot 5,`[6]` 本来就写得上;
- **(b) 会把四个 build 位从大招挪到占位符上**,比现在更差。

同时**证实 issue 的行为读数、只是归因换了**:`objurgation` 确实一级不点,因为它是**索引 3**
而 build 表从不引用 3。#287 §2 那句「大招下标 `4` 仍被引用四次」里的「大招」是**误认**:
索引 4 是 slot 3 的 `generic_hidden`。

**⇒ `odbuild` 该写的是「索引 4 → 意图中的技能」,不是 §2 的任何一条。**

## 5. 诚实边界(引用前必读)

- 这是**静态读**:KV 槽位序 + 出厂 walk。它说「哪个下标指向什么」,**不说**消费端拿到这个
  名字之后干什么。`bots/ability_item_usage_generic.lua:310` 有一条 **`generic_hidden` 逃生口**
  (丢掉该条、去点**下一个**),所以占位符引用在这里是**浪费掉的 build 位**,
  **不是被证明的停摆**。9/12 局的停摆是 **GH #290** 的读数(来自录像),
  **本轮没有一句解释那个停摆,也不该被引用成解释**。
- `tests/mock/hero_slots.lua` 是 d2vpkr 镜像的**快照**。一个挪动槽位的补丁会让上面每个读数过期
  —— 先重生成再读。
- build 行是从 hero 文件的 `tAllAbilityBuildList` **字面量**里解析的(注释掉的行跳过)。
- **焦点五全部干净**(任何世界里都不碰 nil 也不碰占位符),单独立了一节 —— 顺带记一条:
  Axe 和 Earthshaker **各带两个占位符**(slot 3 和 4),干净只是因为它们的 build 除了 `6`
  从不索引超过 3。
