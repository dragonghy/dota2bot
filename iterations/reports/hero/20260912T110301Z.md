## 2. 缺陷:`zusarcimm` 把作用域写死在一个调用点上,而那个选择器有三个读者

`bots/BotLib/hero_zuus.lua` 里 `J.GetVulnerableWeakestUnit` 有**三个**调用点:

| 调用点 | 施法形态 | 状态 |
|---|---|---|
| `X.ConsiderQ` 撤退支路 | Arc Lightning,单体 | 已由 `zusarcimm` 修(2026-09-12 早些时候,GH #768) |
| `X.ConsiderW` 撤退支路 | Lightning Bolt,单体 | ⭐ **本轮** |
| `X.ConsiderW2` 击杀 AoE 支路 | Lightning Bolt,**地面** | ⛔ 刻意不动(§3) |

它委托给 `J.GetAttackableWeakestUnitFromList`,筛的是**攻击免疫**族
(`IsAttackImmune` / `IsInvulnerable` / forbidden modifier / illusion),
**从不问法术免疫**。`zusarcimm` 的头注释自己写了
「⛔ THE FIX IS SCOPED TO THIS CALL SITE」——**这是第二个调用点**。

支路后面唯一的守卫是 `J.CanCastOnTargetAdvanced`,它在域帧上对一个带 BKB 的
目标**答 true** ⇒ **缺项后面没有第二道防线**。

### ⭐ 为什么另开一个 id 而不是把 `zusarcimm` 改宽

**同一个错误在 Bolt 上不是同一个数。** odota/dotaconstants
`build/abilities.json`(2026-09-12 读,与 `axecull`/`axecallbkb` 同一个锚):

```
zuus_arc_lightning    bkbpierce No   Magical   cd 1.6   mana  85-100
zuus_lightning_bolt   bkbpierce No   Magical   cd 6     mana 120-135
```

⇒ **~1.4 倍蓝、3.75 倍冷却**,而且花在 Zeus 最付不起的那一帧(撤退)上。
两个 id 也让两份波读数各归各的射击点;合成一个 id,任何一份读数都会变成两个
射击点的混合。

## 3. 改动(gated,turbo-only,方向是**收窄**)

新 helper `X.zuus_IsBoltTargetSpellVulnerable`(id `zusboltimm`):

- **闸关 = `true`**,出货支路逐字节不变;
- **闸开 = `J.CanCastOnNonMagicImmune( hTarget )`**;
- **方向是代码的性质不是数据的性质**:它只往一条已经答过的谓词上再 AND 一个
  合取项 ⇒ 只能**删**一次施法,永远不能加。

### ⭐ t25 豁免(刻意的,不是遗漏)

`X.SkillsComplement:716` 把**同一个 bid** 按 `talent7:IsTrained()`
(t25 [7] = AoE Lightning Bolt,+325)派成两种施法:已学 →
`ActionQueue_UseAbilityOnLocation`,未学 → `...OnEntity`。
**地面施法世界里一个法免的瞄点照样把 325 圈的伤害交给别人**,拒绝就变成一个
没人量过的 splash 主张。armed 腿因此**豁免 talent7 世界**。

这是**把收窄再收窄**,保证 armed 在**每一个**世界都是 shipped 的真子集 ——
方向论证正是靠这条。语料上该词项几乎恒假(≥25 级只有 8/263 焦点实例),
所以它是**按代码的派发**论证的,不是按频率。

### 刻意不动的两件(各自是另一根杠杆)

1. `X.ConsiderW2:1353` —— 地面施法,上面那段论证在那里**无条件**成立;
   在那儿拒绝需要一份没人取过的 splash 读数。测试 §4 有一条断言钉住
   「它仍然没有被这条 helper 守住」。
2. **重排**。最弱的那个法免时 armed 腿**拒绝**,不往下走到次弱 —— 那是**加**
   施法,方向相反。⇒「armed 的 Zeus 会去电别人」**不是**本改动的预测;
   「armed 的 Zeus 不电 BKB」才是。
