## 2. ⭐⭐ 本轮的主发现:#451 的「活的,不是死代码」那一节是错的

#451 断言这 8 处是活代码,依据是读了它们外层的 `if`。**外层 `if` 不是可达性。**

### 2.1 引擎只调三个成员

BotLib 模块被三个 generic 脚本装载,它们对模块**只调三个函数成员**
(另有五个数据字段 `sBuyList` / `sSellList` / `sSkillList` /
`bDeafaultAbility` / `bDeafaultItem`):

| 调用点 | 成员 |
|---|---|
| `bots/bot_generic.lua:20` | `BotBuild.MinionThink(hMinionUnit)` |
| `bots/ability_item_usage_generic.lua:4215` | `BotBuild.CanUseRefresherShard()` |
| `bots/ability_item_usage_generic.lua:8667` | `BotBuild.SkillsComplement()` |

`bots/item_purchase_generic.lua` 只读数据字段,不调函数。

**⚠️ 第一版根集漏了 `MinionThink`,读数因此是 14 orphan 而不是 13。**
是自己起疑复查抓到的(「`X.MinionThink` 怎么会是孤儿」),不是门抓的。
根集不全 ⇒ 整个结论作废,所以新测试里根集是**从三个 dispatcher 里解析出来的**,
再跟登记值比对 —— 上游多出第四个 dispatch 会**点名报红**,而不是悄悄把
128 个英雄文件的可达集一起放宽。

### 2.3 ⭐ 这解释了 bug 为什么能活这么久,也**反转了修法**

一条**每次执行都抛错**的语句,在一个上线好几个月的英雄里活着 —— 这本身
就是「它没在执行」最响的提示。#451 也确实注意到「引擎错误处理器坏了所以
无声地炸」,但那解释的是**没人看见**,不解释**为什么没人受害**。

⇒ **不上闸。** 上闸是为了「行为改动在验证前保持 dark」;**不可达的语句没有
行为可以 hold dark**,给它套 `J.IsSoakCandidate` 只是给死代码加一层永远
不被求值的判断。#451 验收 2 说「修完之后下游分支第一次可达」——
**修完之后它们仍然不可达,因为函数不可达。**

**真正的改动是把这一层接进 `SkillsComplement`。那个才需要 soak candidate +
真实帧 fixture,而它不是本轮。** 已在 `hero_tinker.lua` 的注释里和新测试的
`GH451_UNREACHABLE` 常量头上逐字写清这个分工。

## 3. 落地了什么

### 3.1 `bots/BotLib/hero_tinker.lua`

8 处 `J.Utils.GetItem('item_x')` → `J.Utils.GetItem(bot, 'item_x')`,**逐处同型,
无其它行为改动**。另在 combo 层开头加一段注释,说明这以下全部不可达、
点名三个 dispatcher 调用点、以及「修参不上闸 / 接线要上闸」的分工,
**指向被 COUNT 的测试而不 restate 数字**(#447 那一轮的教训)。

### 3.2 `tests/test_utils_getitem_arity.lua`(新,常设普查)

判据:`bots/` 全树(走 `lua_source_scan.bots_files()`,不读 gitignored 的
farm-only 开关,GH #438)里 `GetItem` / `GetItemFromFullInventory` /
`GetItemFromCountedInventory` 三个 wrapper 的调用点,**第一个实参是字符串字面量**
= 违规。第二条断言钉住**非空**(wrapper 改名或走查断了 ⇒ 报「vacuous 不是 clean」)。

**为什么必须是常设普查而不是那 8 笔编辑**:这个形状**现有的门一个都看不见** ——
Lua 不查参数个数;`.luacheckrc` 是 `only = {"1"}`(全局访问族);跨模块 arity
普查把声明侧的 `____exports.GetItem` 跟调用侧的 `J.Utils.GetItem` 当两个**永不相等**
的名字,这一对**从它的扫描里掉出去**(GH #452 是协同组在修的那一半)。
**每一道现有的门都结构性看不见的缺陷类会回来。**

**失效方向是窄的**(第一个实参是变量时读作合法),这是故意的:这是钉一个
**已经发生过的形状**的棘轮,不是类型检查器。

### 3.3 `tests/test_hero_export_reachability.py`(新,常设普查 + 棘轮)

- 根集**从三个 dispatcher 解析**,与登记值比对(§2.1 的教训)。
- `ORPHAN_CEILING = 34`,**单向朝下**(接线或删除都会降它)。
  ⚠️ 这不是人质:修好缺陷让它变绿,不变红。
- `GH451_UNREACHABLE` = 那 7 个外层函数,**登记读数**,头上逐字写清两个方向:
  **红是因为它们变可达 = 有人把这层接上了 = 那是真修法,但它需要 soak
  candidate + fixture,而未上闸的 #451 修参从那一刻起失去依据 ⇒ 把读数挪进
  归档行并在报告里说明,不许删断言求绿。**
