## 2. 为什么 1600 量出来是恒真:共线,不是数字选坏了

`X.ConsiderR` 的外层合取项是

```lua
if J.IsRetreating( bot ) and bot:WasRecentlyDamagedByAnyHero( 2.0 )
```

**2 秒内打过 Zeus 的英雄,在那 2 秒里必然进过它自己的攻击距离。**
于是「1600 内有敌方英雄」几乎被**上一行**蕴含。

`hero-37` 第 (3) 列的**帧/episode 裂口就是这件事的指纹**:

- 帧尺度:1600 内 **1,645 / 1,843 = 89.3%**,外 198 = 10.7%;
- episode 尺度:**252 / 257 = 98.1%**。

⭐ **切掉 10.7% 的帧却只切掉 1.9% 的 episode,意味着它删的是「同一个 episode
里还有别的帧被放行」的那些帧。** 而这条分支**只开火一次**(`return
BOT_ACTION_DESIRE_HIGH` ⇒ 大招出手),**按 episode 不动 = 一个决策都没改。**

这正是铁律 4(iii)(「登记过的效应量,连用哪种切法得到的一起登记」)要防的
形状:同一份读数,按帧切像个 10% 的过滤器,按决策切是个恒真项。

## 3. 为什么是 700:本仓自己的环,不是一个新数

问题是「**现在还有没有人够得着他**」,这棵树已经**量过**这条界:

- `bots/FunLib/jmz_func.lua` 的 `J.CanEnemyInterruptTpChannel` 未 armed 时
  搜 **R = 700**,判据就是「一个敌人这一瞬间能不能打到我」;
- `tools/batch_test/behavioral/tpreach_domain.py` 把同一条界**从语料里量出来**
  而不是从记忆里抄:它的 reach 表最高是 skywrath **700**,并逐字写着
  `reach(enemy) > 700` 需要 `GetAttackRange() > 550`,即一个远程英雄。

⇒ **700 是「池子里任何英雄都够得着」的环。**

**⛔ 故意没做的那个更锋利的写法**:逐敌人的
`hEnemy:GetAttackRange() + 150`。`tests/mock/` 下**没有任何东西**从帧数据装
`GetAttackRange`(dump 里没有这一列,`tpreach_domain.py` 自己的抬头写着),
所以 loader 会用通配默认 **150** 回答它 —— 那一项在每一个真实帧上会读成
「距离 ≤ 300」,**同时长得像是在读引擎**。那正是 GH #656 编目的那一族
(14 个 armed id 压在一个 loader 用静默 0 回答的 getter 上)。
**这里常数是诚实的,getter 不是。**
