## 1. 选题:一条新的 axis

前五轮用掉的线索(cast_shape / item_name / facet / call_arity / 穿魔免权限审计 /

> **一个守卫式的合取项,它的两端各自被一个上界钉死,而两个上界的大小关系
> 让它恒假。**

它比前五条都便宜,理由是**两端的上界本仓都已经有别的轮次钉过了**:

## 2. 事实

```lua
	if J.IsRetreating( bot ) and bot:WasRecentlyDamagedByAnyHero( 2.0 )
	then
		if bot:GetRespawnTime() > abilityR:GetCooldown()
			and nHealthPercentage <= 0.28
		then
			return BOT_ACTION_DESIRE_HIGH
		end
	end
```

* **右端是常数 130。** `zuus_thundergods_wrath` 声明 `AbilityCooldown 130`,
  **没有等级阶梯**(KV 快照;loader 自 2026-09-04 起就是从这里供 `GetCooldown`)。
* **左端至多 75。** 英雄重生表 25 级封顶 100s,turbo 把每一次重生乘 0.75
  ⇒ **75s**。这两条不是本轮新立的:`jmz_func.lua` 为买活阶梯(GH #215)
  已经把它们写成一句可读的算术 `100 * 0.75 = 75 seconds`。
* 75 < 130,**在每一个英雄等级、每一个大招等级上**。
  ⇒ 该合取项**从来没有真过**,它不是过滤器,是**关掉的开关**。

**连带的一条**:同文件下方那个 `[ultcash]` 分支的注释写着「上面那条撤退分支
漏掉了没进撤退模式就要死的 bot」—— 它是**在「撤退分支管用」这个前提下**写的。
那个前提从来不成立,所以 `J.IsDyingUnderAttack`(HP ≤ 45% + 1200 内预估 3s
伤害 ≥ 当前血量)这条**严格得多**的路,是 Zeus 目前**唯一**的低血兑现路径。

## 3. ⭐ 本轮最值钱的三条

**⭐ 这条事实是「读法无关」的,而这正是它被写成两个上界之间的算术、
而不是写成对某个 getter 的断言的原因。**
`Unit:GetRespawnTime()` 文档写的是「距离复活还有几秒」;它对一个**活着**的
英雄返回什么,是本台离线 **settle 不了**的引擎问题(AGENTS.md:没有 bot 侧
调试)。**不需要 settle**:按「活着时返回 0」读是 `0 > 130`;按能想到的
**最宽容**的读法(这次死亡**将会**持续的完整时长)读,turbo 里也至多是
`75 > 130`。两种读法都假。把结论挂在一个我判定不了的 getter 语义上,
是这一轮本来最容易犯的错。

**⭐⭐ 「恒假」和「这个比较根本不看输入」从外面看是同一个样子。**
这正是一个结构性死分支的外观 —— 也是 GH #560「不能失败的断言不是证据」的
下一格:§3 在 8 个真实帧上记下的每一个 `false`,同样能由一个**忽略输入**的
比较式产生。所以新文件 §4 打了一次**贴标签的注入**:把 respawn 注到 **131**
(不可能的值)必须让该项**翻真**。变异 **M7**(把 `bShipped` 改成常量 false)
**只有这一条断言看得见**。

**⭐⭐⭐ 前提被单独钉成可证伪的一句。** §2 **从来源读**两个上界 —— KV 快照的
`AbilityCooldown`、`jmz_func.lua` 里 `100 * 0.75 = 75 seconds` 那一行 ——
**不重打 130,也不重打 75**。变异 **M5**(把声明的冷却压到 70)是九个变异里
**唯一**能让 header 的「恒假」句变成假话的那个,而**任何对 helper 返回值的
断言都看不见它**。

## 4. 改动

`bots/BotLib/hero_zuus.lua`:

* 新 `X.zuus_ShouldCashUltBeforeDeath( hBot )`:**第一条语句就是 shipped 表达式,
  真则短路返回**;gate 关时逐字返回那个布尔;armed(turbo + `zusultstrand`)时
  额外要求 `X.nUltCashChaseRadius`(新常数,1600)内有敌方英雄。
* 新常数 `X.nUltCashChaseRadius = 1600`。
* `X.ConsiderR` 撤退分支那一项改为调用它。**其余一个字没动**:
  `nHealthPercentage <= 0.28`、`J.IsRetreating`、`WasRecentlyDamagedByAnyHero( 2.0 )`、
  `IsFullyCastable`,以及下方 ultcash / 团战 / 低血各分支。

**为什么 armed 侧换了问题而不是修了 getter。** shipped 那一项字面的意思是
「现在放不亏,因为我回来之前冷却就转好了」。**修 getter 救不活它** —— §2 的
算术说,在 turbo 里,不论用哪个 getter,答案都是「不」。所以杠杆换成 turbo
真正在问的那个问题:**握在手里死掉的大招价值恰好是零**,而 275/425/575 点
魔法伤害打满全场敌方英雄 + 3 秒全球视野,落在**正在杀他的那场架**里,比一个
在架打完 55–118 秒后才回来的大招值钱。给一个必死的 Zeus 兑现大招是标准打法,
同文件的 `[ultcash]` 已经为更严格的那一半这么说了。

**收窄项**:追兵半径。它**不是射程项** —— 雷神之怒是全球的,连
`AbilityCastRange` 键都没有 —— 它是「这次死亡到底会不会发生」的代理。
没人在旁边时,一个两秒前被蹭了一下的 28% 血 Zeus 经常活下来,而兑现要花
250–500 蓝 + 两分钟冷却。

## 5. ⚠️ 方向:这是 WIDENING 不是 NARROWING

shipped 合取项**结构性恒假** ⇒ arming **只能增加**这条分支上的大招施放,
**不可能减少一次**。负读数**唯一**能读作的是「多放的那些放错了」,
**绝不能**读作「少放了 N 次大招」。gate-off 等价是结构性的(shipped 表达式
第一条语句 + 真则短路,armed 是唯一绕道,GH #162 house rule),
新文件 §5 用**注入矩阵**(7 个 respawn 值 × turbo/非 turbo)逐值断言
gate-off == shipped。

## 6. 覆盖边界(两句不许合并)

**买到的:**
* **比较式的右端**:8 个 Zeus 主体 fixture 里**携带该技能句柄的 7 个**上
  `GetCooldown()` 全部读出 KV 的 **130**。这是**读数**不是假设 ——
  loader 自 2026-09-04 起从 KV 快照供这个 getter;变异 **M6**(把句柄指向
  不声明 AbilityCooldown 的 `zuus_static_field`)是这一条的仪器对照。
* **armed 的半径项在真实帧上不空转也不放行一切**:8 帧里 **6 帧**最近敌方
  英雄在 1600 内、**2 帧**在外。位置**是**帧数据。(§5 两边都要求为正:
  admit 全部 = 空头支票,admit 零 = 第二个关掉的开关。)

**没买到的:**
* ⚠️ **那些帧报出的左端 0 是 loader 缺口,不是帧数据。** tests/mock 里
  **没有任何东西**装 `GetRespawnTime`,走的是 `bot_api.lua:182` 的通用
  `^Get` 默认 0。§6 把它钉成**单向绊线**:哪天 dumper/loader 接上了,
  这个文件当场变红并说明原因,而不是安静地绿着。
* ⚠️ **全语料没有这条分支的创造帧** ⇒「armed 分支会触发」**本轮没有人说**。
  唯一一帧 HP 低于 28%(`f_181441_zuus_lowhp_limbo`,15.8%)**同时**在另外
  两个合取项上落空:大招还有 **2.2s** 冷却、最近敌人 **2017u**(在半径外)。
  §6 把这两条都钉成绊线 —— 红了是**好消息**。域的真实大小是
  `queue.json:hero-37` 的问题,不是这次扫描的。

## 7. 登记不认领

* `bots/BotLib/hero_zuus.lua` 里唯一另一处 `GetRespawnTime` 读法族的兄弟
  在 `bots/ability_item_usage_generic.lua:619`(`nFullRespawnTime`),
  那处**在死亡时求值**,和本轮的活体读法不是同一个问题,而且 `bbrespawn`
  / `bbshort` 已经在管那条线。一个杠杆一次,本轮不动。
* 撤退分支下方 `J.IsInTeamFight( bot, 1400 )` 那一支要求
  `J.GetInvUnitCount( false, <1400 内敌方英雄> ) >= 5` ——「1400 内数到 5」在
  5v5 里是**全队挤在一个圈里**,形状上像本轮 axis 的近亲。**但本轮没有核实
  它是不是恒假**(`J.GetInvUnitCount` 的语义和它在真实帧上的取值都没读),
  所以这里**只登记不认领**:下一轮 Zeus 的第一个候选就是它,不要拿本报告
  当成它已经被判过。
