⭐ **(2) 语料同意,而且在每一个量词下都同意。** 见 §2。

⚠️ **(3) 那个接受 3 的 fallback 只在 `nHP < 0.46` 时接受。** ⛔ **本轮不说那一句是错的** ——

## 3. ⭐⭐ 为什么 `bots/` 一行行为都没改 —— 这是本轮最要紧的一句

那个出口在**出厂默认下是死的**,而且是**两个互相独立、都与 quorum 无关**的理由:

1. `nRadius = X.GetAbilityRSplashRadius()` 读的是 `splash_radius_scepter`,
   一个**本 patch 的 KV 里不存在**的键(现名 `splash_radius`,`special_bonus_scepter = 325`)
   ⇒ 静默返回 0 ⇒ 内层 `J.IsInRange( npcEnemy, nEnemy, 0 )` 只数得到候选自己
   ⇒ `nAoeCount <= 1`,而 `nMaxAoeCount` 的种子就是 **1**、比较是**严格 `>`**
   ⇒ `nBestAoeEnemy` 永远是 nil。**GH #162,id `lionsplash`。**
2. `bot:HasScepter()` 在语料 42 个存活 Lion 帧上**全 false**。

⇒ 在这上面单独落一个 id,**在任何一波里都动不了一个决策**。
`check_armed_wiring.py` 会照样叫它 **WIRED**(它查的是调用点存在,不是谓词能不能为真),
波次读回**「测过了没影响」而没有任何东西举手** —— **GH #606 的形状,AGENTS.md 点名的那个失败模式**。

⇒ **DO-NOT-ARM。** quorum 必须与 `lionsplash` / `lionraoe` **在同一个 atom 里一起定**。
⛔ 也**不许**写成 `IsSoakCandidate('lionraoe') and IsSoakCandidate('lionsplash')` —— 那是 pullcad 陷阱
(任一 id 被 promote 的那天这个合取式冻结成 false,而所有自动读者仍读 WIRED)。
依赖登记在 `queue.json`,**不是代码**。测试 §4 把**两个缺席**都钉住了。

**本轮 `bots/` 的全部内容**:把这段裁定写在**它被问到的那个位置**(出口上方的注释),
与 GH #794 那次 `881a4729` 的做法同型。
