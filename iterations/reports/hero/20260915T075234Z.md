## 2. ⭐⭐ 缺陷:储备接了真子集,而没接的那个是最贵的

`X.zuus_ShouldSaveManaForUlt` 挂在三个派发点上:

| `X.ConsiderQ` | `:748` | ✅ |

## 3. ⭐⭐ 本轮最锋利的一条:rank 1 上 `zusult` 腿的域是**空的**,而这是算术不是读数

这一条值得单独一节,因为它决定**波次怎么读**:

- `X.ConsiderD` 不出价,除非 Nimbus `IsFullyCastable` ⇒ **蓝 ≥ 275**;
- 储备不扣住,除非蓝 < R 当前价 ⇒ rank 1 上 **蓝 < 250**;

窗口只在更高 rank 上开:

| R rank | R 价 | `zusult` 腿窗口 | 宽 | `zusultx` 腿窗口 `[275, 价+275)` | 宽 |
|---|---|---|---|---|---|
| 1 | 250 | **∅** | 0 | [275, 525) | 250 |
| 2 | 375 | [275, 375) | 100 | [275, 650) | 375 |
| 3 | 500 | [275, 500) | 225 | [275, 775) | 500 |

**六条界全部在 §3/§3b 驱动**(不是断言):`holds_at()` 在真实帧上逐点问 helper,
上下界各一次,外加一条**活性守卫**——helper 在该帧上必须**两种答案都给得出**,
否则下面每一个 "does not hold" 都是空洞而不是读数(M12 专打这条)。

⛔ **因此「arm `zusultd`」与「arm `zusultd` + `zusultx`」在 rank 1 上不是同一个实验**,
读了一个的波次**不许拿来说另一个**。这条同时钉进了
`tests/test_gated_helper_nesting_census.lua` 的 `zusultd|…|zusultx` 那一行(见 §6)。

## 4. 改动

### 4.1 `X.ConsiderD` 带出第三个返回值

`X.ConsiderD` 打的是**落点**(`ActionQueue_UseAbilityOnLocation`),所以这次落点
**关于**哪个英雄从来没有被带出函数——而 `X.zuus_ShouldSaveManaForUlt` **没有它就是惰性的**
(它在 `J.IsValidHero( hTarget )` 上拒绝一切非英雄目标)。⇒ 队友助攻支路返回 `target`。

### 4.2 闸

```lua
if ( castDDesire > 0
    and J.IsModeTurbo()
    and J.IsSoakCandidate( 'zusultd' )
    and X.zuus_ShouldSaveManaForUlt( bot, castDTarget, hCloudHandle ) )
then
    castDDesire = 0
end
```

`hCloudHandle` 是**在 `castDDesire > 0` 时解析一次**的 `X.GetBoundAbility( abilityD, 'zuus_cloud' )`
——**出价定的价与下单 cast 的必须是同一个句柄**。提取它不是风格选择,是两条既有测试的要求
(见 §11.1),而且它顺带把 `test_replay_260820_zuus_reserve_cross` 的 `[^)]*` 参数解析
从「被嵌套调用截断」里救了出来。

⭐ **方向是收窄**:armed 唯一可达的效果是 `HIGH → 0`,**没有任何一帧会因此多出一次 Nimbus**
(§5 把闸体逐字钉成 `castDDesire = 0`,M5 专打)。⇒ 负面波读**只能**读作
「被拿掉的那些 Nimbus 比它们在替之攒的大招更值钱」,**不许**读作「Nimbus 落点变差」。

⭐ **句柄是 Nimbus 的不是别人的**:`zusultx` 会 `hSpell:GetManaCost()` 减去本次支出,
所以喂错句柄会**悄悄给另一笔支出定价**而闸照样读 WIRED(M7 专打)。

### 4.3 ⭐ 撤退支路双重豁免

`X.ConsiderD` 的撤退支路(把云丢在自己脚下躲追兵)返回的第三个值**故意是 `nil`**:

1. `nil` 撞 helper 的 `J.IsValidHero( hTarget )` 被拒;
2. helper 自己的「逃跑优先于囤积」条款在该支路上**先**触发(支路整个在 `J.IsRetreating( bot )` 里)。

**任一条单独成立**。§4 **两条都断言**——因为「这条支路豁免」正是后来的人最想引用的那句话,
而单一理由离「被重构掉」只有一次改动。M8 把第三个值改成 `npcEnemy`,必须死。

## 7. ⚠️ 限度:本语料上的域是 0,而这个 0 有**两个必须分开写**的原因

**(1) 仪器。** `bot:HasScepter()` 在 `tests/mock` 下**没有任何 spec** ⇒ 落进
`bot_api.lua:167` 的 `^Has -> false` 兜底 ⇒ `X.ConsiderD` 在**每一帧**都在第一个分支就 return
(GH #656 族)。§6 写成**单向绊线**:哪天 loader 接上这个 getter,这个文件就红,
**而那一天正是这根杠杆第一次可以端到端驱动的日子**。

**(2) 世界,而这一半是读数不是仪器产物。** 按帧自己的 `items` 数组(那个 getter **不看**它)
驱动:`tests/fixtures` + `tests/frames` 的 **71 具 Zeus 身体里 5 具带 `item_ultimate_scepter`
(7.0%)** ⇒ 这个分支**在游戏里不是不可达**。但 5 具**全在英雄 23–28 级、蓝 1120–2745**,
对 rank-3 的 500 而言**全部在储备自己的 `GetMana() >= nCost` 早退之上**
⇒ **本语料不含任何一帧让出货树与 armed 树不同**。

⛔ **不许把 (1) 引成「turbo Zeus 不买杖」**:这个文件**四行角色出装全部列着
`item_ultimate_scepter`**,而 `ZeusSupportAghsFirst` 还**故意把它往前挪**给 pos_5——
**更早 = 更小的池子 + rank-2 的 375**,那是本杠杆窗口的**正中间不是边缘**。

⚠️ **第二道仪器墙,本轮才撞到:** 该帧的 Nimbus 句柄 `GetManaCost()` 答**静默 0**
(帧的技能数组不点名 `zuus_cloud` ⇒ 装不上 spec)⇒ `zusultx` 在离线台上对这个点
**无法定价**(不是「空」,是「买不到价」——两句话不是同一句)。§3b 因此把 275 作为
**声明过的注入**喂进去,并配一条「哪天答了真值就红」的绊线。

⚠️ **UNRESOLVED_HAND_READ(GH #803)**:5/71 那次普查是**本机一次** python 扫同一批文件,
写成**可达性下界 + 本语料可用域上界**,**不是等式**。
