## 2. ⭐⭐ 主读数:第二个消费方的域是**空的**,而且**目标血量被约掉了**

站点是一条表达式(`hero_zuus.lua:793-795`):

```lua
local nDamage = abilityW:GetAbilityDamage() * ( 1 + bot:GetSpellAmp() )
...
targetRanged:GetHealth() < targetRanged:GetActualIncomingDamage(
    nDamage + targetRanged:GetHealth() * abilityASBonus , DAMAGE_TYPE_MAGICAL )
```

记 `m` 为 `GetActualIncomingDamage` 施加的抗性乘子、`D = nDamage`、`b = abilityASBonus`、
`h` 为创兵血量。开火条件是

```
h < m * (D + h*b)        ⟺        h * (1 - m*b) < m*D
```

而 `abilityW` 是 `zuus_lightning_bolt`,它的 `GetAbilityDamage()` 读数
**是被证明过的零**(GH #175 的普查,`tests/mock/ability_damage.lua`:
`zuus` 根本**不在** `NONZERO` 里;`zuus_lightning_bolt` 的 140/220/300/380 住在
`AbilityValues/damage`,**那个调用看不见**)。`D = 0` 把判据塌成

```
h < m*b*h        ⟺        1 < m*b
```

**目标血量被约掉了。** 这才是读数:它**不是一个变悲观了的击杀估计,而是一个与血量无关的常数**。
对**每一个创兵、每一个血量、每一个 rank** 为假。

**平衡点是 `b ≥ 1/m ≥ 1.0`** —— 静电场要打掉目标**当前血量的 100%**:

| 腿 | b | 距平衡差 |
|---|---|---|
| 出厂 | 0.09 | **11.1×** |
| armed(KV 上界,31 级 4.95%) | 0.0495 | **20.2×** |
| armed(KV 下界,1 级 3.45%) | 0.0345 | **29.0×** |

**这是天花板不是余量** —— 和 GH #328 里 WK t25 那条同形。
⇒ **本 id 能带的任何百分比都救不活这条腿**,所以 **arm `zusstatic` 动不了这个消费方,
退回它也动不了**。

## 3. ⭐⭐ 预登记的期望被**双向**推翻,照实记下不修剪

-50 白纸黑字预登记的是「带在创兵血量尺度上,**可能宽一个量级**」。两句都不成立:

**(1) 今天它是零,不是宽。** 见 §2。

**(2) 反事实里也不是「宽一个量级」,而是同一个量级。** 两个消费点**代数同形**,
各自解出开火阈值都是 `h < m*D/(1-m*b)`,于是两腿之间的**带宽**是

```
W(D) = m*D * [ 1/(1 - m*b_出厂) - 1/(1 - m*b_armed) ]
```

—— **只正比于 D,与本站点其它一切无关。创兵血量尺度从不进入这个式子。**
⇒ 即使有朝一日 GH #175 的另一个方向被修好、`D` 变成雷击的 KV 伤害,
这条带也只是大招那条的 `D_bolt / D_ult` 倍:**140/575 到 380/275 = 0.24× 到 1.38×**,
**骑在 1 上**。绝对值(spell amp = 0,声明在明面上):
**4.81 HP**(m=0.75 / rank 1)到 **24.00 HP**(m=1.00 / rank 4)。

**「创兵血量尺度」这个直觉定价了错的量**:定带宽的是**平伤项**,
而雷击的平伤在四组 rank 配对里有**三组比大招小**。
