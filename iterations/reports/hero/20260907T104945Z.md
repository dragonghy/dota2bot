## 7. ⚠️ 变异台逼出两个**真缺陷**,而且都是我的测试错不是变异错

第一轮 **5/10**。三个 SURVIVED 全部来自 `sub()` 正确地报 `ANCHOR AMBIGUOUS` ——
追下去发现的不是锚点没写好,是**测试本身的定位方式是错的**:

### (i) M4:所有「调用点在下游」的断言,其实在跟一条**注释**比大小

`hero_lion.lua` 的**文件头 t10 天赋注(第 88 行)逐字引用了那行早退**:

```
--     BELOW `if X.IsOtherAbilityFullyCastable() or nSkillLV <= 1 then return 0 end`,
```

于是 `src:find(...)` 命中的是**第 88 行的注释**,不是第 1070 行的代码。
`callsite > line` 因此**恒真** —— 把打架抽蓝的调用点**上提到早退之前**,断言照样通过,
而那正是 11% 上界唯一的结构前提。已改成按**制表符缩进**解析代码行,
并断言这样的代码行**恰好一条**(零 = 断言失效,>1 = 又回到歧义)。

### (ii) M6:检测「有没有人上闸」的断言,在**它唯一该响的变异上消失**

原写法按**原文**定位那行(`'\n\tif X%.IsOtherAbilityFullyCastable%(%)'`),
但**上闸就会改写那行文本**(`if ( X.IsOther... and not J.IsSoakCandidate( 'lionearly' ) )`),
于是断言找不到锚点 ⇒ 报「早退不见了」,**不报「有人给它上闸了」**。
一条防复活的断言,在复活发生时说不出发生了什么。已改成定位
**「调用 helper 的那条代码行」**,与行内还写了什么无关。

### (iii) M9 顺带修一处可读性

去掉 `bot_api` 的通配默认后,`GetNearbyCreeps` 落到通用 `^Get` 回退返回**数字 0**,
`#(0 or {})` 直接抛 `attempt to get length of a number value` —— **七个测试同时**报这个错,
把 §7 那句唯一能解释成因的话埋掉了。已把读数收进 `count_creeps()` 并在类型不对时**说出成因**;
同时把 §7 的接线断言排到 `funnel()` **之前**(顺序是承重的,不是风格)。

**修完重跑:10/10 CAUGHT,exit 0,`sha256sum -c` 校验树已还原。**

(另修一处 stand 自身的 bug:`rm -rf "$WORK"` 排在 EXIT trap 之前,导致 trap 第二次
