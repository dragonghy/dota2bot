## 一、缺陷:搜索环 ≠ 准入环,而那个测试坐在 argmax **之后**

`X.ConsiderW` 在顶上把候选表建好一次:

```lua
local nCastRange        = abilityW:GetCastRange() + aetherRange
local nInBonusEnemyList = J.GetNearbyHeroes(bot, nCastRange + 300, true, BOT_MODE_NONE )
```

团战腿在这张表上跑 "most dangerous enemy" 的 argmax,而**准入只测胜者**:

```lua
if npcMostDangerousEnemy ~= nil
    and J.IsInRange( bot, npcMostDangerousEnemy, nCastRange + 50 )
```

搜索环 `+300`、准入环 `+50` ⇒ 中间 **250u 的圆环**里的候选**够不着却能赢 argmax**,
而赢了之后**不回落到次优的近处敌人**,直接把整条分支否掉。Lion 站在团战里、Hex 就绪、
射程内有合法可施法敌人,却一个法术都不出 —— 只因为稍远一点的那个投射伤害更高。
**否决是静默的**:不出价,于是下游无法把它与「没有候选」区分开。

### ⛔⛔ 而这条腿是一个**正在被改造的环**的第三个消费者,改造没找到它

兄弟 lever **`lionwreach`**(`hero_lion.lua:1008`,2026-09-12 落地)的抬头**自己写着**:
`X.ConsiderW`「画了**一个**宽搜索环 `nCastRange + 300`,交给**两条**打断子分支」,
并给两条都补上了 `nCastRange + 50`。本腿读的是**同一个** `nInBonusEnemyList`
(`:1391`)、想要**同一个**界,**却不在那次清点里**。

⭐ **为什么「找缺失的距离项」会从它旁边走过去**:两条打断腿的失效是**超伸**
(对够不着的英雄出价)⇒ 找法是「哪个发火点**没有**距离测试」。**本腿有距离测试** ——
`J.IsInRange( bot, npcMostDangerousEnemy, nCastRange + 50 )` 就在八行之下 ——
它的失效是**自我否决**,因为那个测试坐在 argmax **之后**而不是**之内**。

⇒ ⛔ **对这一族,「这条分支测距离吗」是错的问题。** 对的问题是
**「它搜索的环,是不是它愿意接受的环」**,而这**一个函数的三条腿给出三个不同的答案**。
