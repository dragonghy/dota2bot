## 1. 缺陷

`X.ConsiderW` 有八个出货点,**七个**把目标绑在函数第一行算出的 `nCastRange` 上
(`kill loop` / `先手` / `团战`(= `axebhreach`)/ `lane harass` / `retreat` /
`roshan` / `tormentor`)。打野支路是剩下的那一个:

```lua
local neutralCreepList = bot:GetNearbyNeutralCreeps( nCastRange + 100 )
local targetCreep      = J.GetMostHpUnit( neutralCreepList )
```

列表到 `return BOT_ACTION_DESIRE_HIGH` 之间**没有任何距离项**。

### ⭐ 100 不是这个错误的大小

首命中循环搜宽 100 的环,代价至多是多走 100。**这不是首命中循环,是选举规则**,
而它选的轴恰好与「近」反相关:**最高血量**。

- Axe 贴脸清野约 **128u**,所以 band 里的野怪基本不是他正在打的那一营,是**隔壁营**;
- `J.GetMostHpUnit` 偏好的正是隔壁营那只**没被磨过的大野**(golem / centaur khan / ancient)。

⇒ band 成员**不只是多走一段路,它把同一张表里已经合法的近处野怪挤掉** ——
就是 `axebhreach` 的 swap 论证,落在它当年明写「故意不碰」的那条支路上。

出货是 `BOT_ACTION_DESIRE_HIGH`,而射程外的施法指令**先是一条移动指令**⇒
这段路上它盖过把他放在营地里的 farming 模式:他丢下清到一半的营,
走进一个他没选过的野点的仇恨半径。

### band 的大小(读数,不是猜)

`axe_battle_hunger / AbilityCastRange` 是 **`600 700 800 900`**。
§1.3 在 **40 个真实 Axe 帧**上用真实 handle 把这个阶梯**逐帧核对**过
(rank 1:15 帧、rank 2:4、rank 3:7、rank 4:14;cast range 恰好 600/700/800/900)。
⇒ band `(nCastRange, nCastRange+100]` 在 rank 1 是 600→700 —— **它的外沿恰好是
rank 2 的施法距离**,即该支路已经在按 Axe 下一个技能点之后才有的射程搜索。

### ⭐ 残差的载体是被算术找出来的,不是被我写对的

初稿把「可以多出一发」记在 `not J.CanKillTarget` 上。**那是错的**:要经它加出货,
必须 far 死于一次挥击(shipped 拒发)而 near 活下来(armed 出货),即

```
far > near   (选举:MostHpUnitOf 取最大)
far <= s     (shipped 拒发)
near > s     (armed 出货)
⇒ near > s >= far > near   矛盾
```

`J.CanKillTarget` 在固定伤害与伤害类型下**对血量单调**,两个候选用**同一个** swing 打分,
⇒ **没有任何血量分配满足三条**。§3.5a 驱动这个不可能(并把单调性本身钉成可红的断言)。

真正的载体是 **`modifier_axe_battle_hunger_self`** —— 它**不被选举排序**,
于是远处那只可以已带 debuff 而近处那只干净:shipped 拒发,armed 出货。§3.5b 驱动。

⇒ 残差**比初稿说的窄**,而且窄在一个可以用算术证明的地方。
