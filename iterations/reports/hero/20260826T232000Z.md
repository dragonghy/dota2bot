## 2. ⭐ 承重读数(8 处站点,7 个技能,6 个 GET,零 AWS)

技能的 special value **按 `AbilityValues` 里的条目名取键**。现代写法是长形式:

```
"avalanche_damage"
{
    "value"                     "90 180 270 360"
    "special_bonus_unique_tiny" "+90"
}
```

`value` 在这里是**条目 `avalanche_damage` 的内层键**,**不是技能的条目**。
⇒ `Avalanche:GetSpecialValueInt('value')` 问的是一个不存在的条目,拿到的是
`BOT_API_REFERENCE` 写明的**静默 0**。技能只有**自己拥有一个字面叫 `value` 的条目**
才答得出 —— 而那**正是通用天赋块的写法**,这就是同一个字符串在一族句柄上答得出、
在另一族上答不出的原因。

**7 个技能,一个都没有那个条目。8 处站点,8 处 READS-ZERO。**

## 4. ⭐ 而在那唯一的 OVER 站点上,「显而易见的修法」**又是错的,错在第二个方向**

它想要的键是 `health_cost_pct`,KV 值是 **20 —— 是二十个百分点,不是分数**;
而那一行**直接乘当前血量**(`bot:GetHealth() * <读数>`)。
⇒ **只换键**会把代价从 0 变成**血量的 20 倍**,闸从**恒真**翻成**恒假**:
这个技能会从「永远放行」变成「永远不放」。**修法是两处编辑(`health_cost_pct` **和** `/ 100`),
绝不是一处。**

这和 #228 那条同族反号:那边「显然的修法」会**重复计数**,这边会**把闸反过来**。
只读「想要的键」那一栏的认领者会**恰好**发出错的那一半 —— 所以源码里写死了这句话,
`tests/test_ability_value_read_anchor.lua` §4 钉住它**继续**写着。
