## §2 找到的东西

`bots/BotLib/hero_crystal_maiden.lua` `X.ConsiderW`(Frostbite)从**一个** cast range
建**两个**环,然后从**八个**落单点出价。

| 落单点 | 到达约定 |
|---|---|
| 击杀确认 | `nEnemysHeroesInRange`(`nCastRange`) |
| 团战最强 | `J.GetNearbyHeroes( bot, nCastRange, ... )` |
| 保护自己 | `nEnemysHeroesInRange` |
| 对线期最后一条 | `nEnemysHeroesInRange` |
| 进攻 | `J.IsInRange( npcTarget, bot, nCastRange + 50 )` |
| 撤退 | `J.IsInRange( npcEnemy, bot, nCastRange - 80 )` |
| Roshan | `J.IsInRange( botTarget, bot, nCastRange )` |
| **TP 打断** | **`nEnemysHeroesInBonus`(`nCastRange + 200`),零距离项** |
| **对线期消耗·骚扰** | **`nEnemysHeroesInBonus`,零距离项** |

`nCastRange` 实测 **630**(KV `crystal_maiden_frostbite/AbilityCastRange = 600` + 文件自带
`+ 30`),所以 bonus 环是 **830** —— 比技能真正到得了的地方宽 **200 码**。

**本 id 只收第二个,理由与 `wkqlane`(GH #621)逐字同一条**:打断值回票价(它让对面
整个 TP 作废);骚扰的回报只是一次 harass,而**击杀**那一档是这个函数的**第一个**落单点,
**并且它是绑距离的**。⇒ 函数里**最松的到达压在最小的回报上**,而且压在**对线期的辅助**
身上 —— 全场最脆的位置之一。

**代价的机制**:`X.SkillsComplement` 把 `ActionQueue_UseAbilityOnEntity( abilityW, target )`
递给引擎,对射程外目标那**先是移动指令**:CM 朝敌方英雄走最多 200 码,花 125-155 蓝,
而排完 W 就 `return` ⇒ 那段路上 `X.ConsiderR`(Freezing Field)**一次都不被考虑**。

与 `lionrreach`(GH #617)、`wkqlane`(GH #621)同族,**第三个英雄、第三个技能**。

## §3 改动

新 `X.cm_IsLaneHarassTargetInReach( hBot, hTarget, nCastRange )` +
`X.ConsiderW` 对线期消耗第二条分支多一条合取。

```lua
if not ( J.IsModeTurbo() and J.IsSoakCandidate( 'cmlaneband' ) ) then return true end
return J.IsInRange( hTarget, hBot, nCastRange + 50 )
```

- **`+50` 不是本轮发明的,是这个函数自己的门**:「进攻」落单点 —— 同函数里另一个
  **对一个选定英雄做承诺**的地方 —— 写的就是 `J.IsInRange( npcTarget, bot, nCastRange + 50 )`。
  armed 之后骚扰分支只能在进攻分支也会承诺的地方承诺。
- **`nCastRange` 作为参数传进来**,所以与调用方折进去的三样东西正确复合:文件自带的
  `+ 30`、`aetherRange`、以及分支上方那条「视野里只有 1 个敌人时把 nCastRange 抬到
  攻击距离 + 60」的延长块。变异台 **M10** 就是把参数冻成今天正确的常数 680,被 §5 的
  nCastRange 阶梯抓住。
- **方向单一**:闸关是**无条件 `true`** ⇒ armed 只能删掉施法,**永远不可能新增或移动
  一次施法**。⛔ 负读数只能读作「那些 ≤200 码的接近本来值得走」,**绝不能**读作
  「杠杆让 CM 开始打它本来不打的目标」。
- ⚠️ 同 `wkqlane` 的诚实登记:**正因为出货是无条件 true,「变宽」这个变异体在本 id 上
  不可表达**。变异台没有假装做一个,M3 写成**把门反过来**。**形状决定了哪些变异体存在。**

**搬家陷阱查过了,而且是在真实帧上驱动的**:被本门拒掉的 band 目标没有任何别的落单点
能接住 —— 另外六个 committing 落单点全都更紧(`nCastRange` / `+50` / `-80`)。
`tests/test_cm_w_lane_band.lua` §3 **问的是三个环本身**,不是读源码。
