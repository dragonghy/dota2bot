## 2. ⭐ 缺陷:节拍看不见的那一行

`bots/mode_roam_generic.lua` 的营地拉野节拍(wave13 那段)是:

```lua
if bCampHere and (bot.campPullAttackTime == nil or now - bot.campPullAttackTime > 3.0) then
    bot:Action_AttackUnit(tNeut[1], true)      -- 每 3s 戳一次
    bot.campPullAttackTime = now
elseif bCampHere then
    ... Action_MoveToLocation(朝 lane 的 500u 一步) ...   -- 中间的帧往外拖
```

而 `Think()` 的**第 2、3 行**是:

```lua
if J.CanNotUseAction(bot) then return end
if J.Utils.IsBotThinkingMeaningfulAction(bot, Customize.ThinkLess, "roam") then return end
```

`utils.lua` 的 `meaningfulActivities` 逐字是
`{ ACTIVITY_RUN, ACTIVITY_ATTACK, ACTIVITY_ATTACK2, ACTIVITY_ATTACK_EVENT, ...cast/channel... }`,
谓词把它与 `bot:GetAnimActivity()` 比。**刚戳完营的英雄按构造就在 `ACTIVITY_ATTACK` 里**,
而营里的野怪一直在反击、英雄一直重新锁定它们 —— **节流恰好吃掉必须下拖拽指令的那些帧**。
节拍再正确也没用:它**没被调用**。

英雄于是站在营里挨打,这正是这段节拍当初写出来要消灭的
**wave13「站桩 TANK 营地」指纹**,从节拍自己看不见的一行里绕了回来。

**为什么是 42% 而不是 100%**:动画状态是有窗口的,英雄偶尔会落到一个空档帧上,
那一帧 `Think` 跑到、拖拽指令下出去、随即进 `ACTIVITY_RUN`(**也在名单里**)
⇒ 节流反过来保护这一步走完 500u。录像组的正对照 jakiro
(`d_lane 1525 → 974`,一步 551u)就是这个空档帧的样子。
**同一行既造成了 42% 的站桩,也造成了另外 58% 的正常拖拽**,这是它难被看见的原因。

## 3. ⚠️ 判据一(本轮主产出):**一个「两把锁」的解释里,可能只有一把是真的锁**

第一版写下的世界断言是两条:
(W1)`GetAnimActivity()` 在语料上恒读伪造的 **0**;
(W2)mock 里 `ACTIVITY_*` 全是**未定义全局** ⇒ `meaningfulActivities` **建成空表**。
两条都能独立解释「本地永远读不到这条节流」,写起来非常顺。

**W2 是错的,而且是当场被自己的用例打红的。** `tests/mock/bot_api.lua:404` 给 `_G`
装了 `__index`:**任何没见过的全大写全局都自动解析成一个从 1000 起递增的、稳定的、互不相同的数**。
所以 mock 下 `ACTIVITY_ATTACK` **不是 nil,是 1175**,`meaningfulActivities`
**是满的**,只是装了十六个伪造 id。

⇒ **真正的锁只有一把,而且它是一个数**:`GetAnimActivity()` 的默认 **0**
——`0` 结构上**不可能**出现在一个从 1000 起编号的集合里(GH #133 `GetPowerTreadsStat`
的同型:一个不在被比较值域内的默认值,让比较**永远只有一个答案**)。

**这把锁按住的不是一个谓词,是九个调用点**:`mode_roam` / `mode_farm` / `mode_ward` /
`mode_outpost` / `mode_secret_shop` / `mode_side_shop` / `mode_team_roam` +
`aba_defend` + `aba_push`。**一个伪造的数,让本仓大部分 mode `Think()` 的头两行
在我们拥有的每一个用例里永久敞开。** `tests/test_replay_pullbeat_attack_cancel.lua`
能在**同一个 `Think`** 上驱动 46 帧而一次都没撞上它,原因就在这里。

**教训的形状**:「两条独立理由」听起来比一条更稳,但它让人**不去查第二条**。
把两条都写成会红的断言,第二条当场自曝。**冗余的解释要么验,要么别写。**

## 4. ⚠️ 判据二:**没被执行到的分支,和执行了但没效果的分支,证据长得一模一样**

录像组 §4 给了三个方向,前两个都假设**分支跑了**
(「攻击指令与移动指令互相取消」/「3.0s 那支是不是每帧都命中」)。
两者都会产生同一份可观测证据:**坐标不动 + POKE 事件连续**。
第三个方向(「更像自动攻击在持续,而不是节拍在轮转」)是对的,但它指向的是**症状**。

判别器**不是位移也不是 POKE**,是**指令日志**:分支没被执行到 ⇒ 那一帧
**一条指令都没有**(`.`),而不是「有一条被取消的指令」。本轮的用例就是照这个判别器写的:
出厂腿在整整一个 3s 节拍上打印 **91 个 `.`**,一个 `A`、一个 `M` 都没有。

**这条已经写进 `queue.json:strategy-18` 的预登记反向读法**:波次读数不动时,
第二嫌疑是「那 42% 根本不是攻击动画,而是寻路卡住 / 别的 mode 抢帧」——
**指令日志同样是判别器**,因为本修复**不可能**让一条移动指令出现在
`Think` 压根没被调用的帧上。

## 5. 修法:一个 id,两个**不可分**的半边

gated **`pullthink`**(`state.json:pullthink_20260825`),turbo **结构性**成立
(`bot.roamCampPull` 只在 `J.ShouldPullNeutralCamp` 返回非 nil 时存在,而那里开头就是
`IsModeTurbo()` + `pullcamp` 门):

1. **有拉野计划时跳过节流**
   `if not (bot.roamCampPull ~= nil and J.IsSoakCandidate('pullthink'))
   and J.Utils.IsBotThinkingMeaningfulAction(...) then return end`
   ——未 armed 时多出来的只有**一次对一个在非拉野帧上恒 nil 的字段的比较**,
   `IsSoakCandidate` 连叫都不叫。
2. **给营地分支补上起手动作 hold**(戳完 0.5s 内不下任何指令),
   即它姊妹小兵分支**早已出厂**的那一条(promoted `pullbeat`)。

**半边 2 是半边 1 的结构性前提,不是第二根杠杆。** 营地分支当初不需要 hold,是因为
**节流本来就在吃那一帧**;把那帧还回来而不带 hold,等于把 GH #143 在小兵侧量到的缺陷
原封不动搬到营地侧(戳完下一帧下移动指令 = 取消还没起手的攻击 ⇒ 不掉血 ⇒ 野怪不仇恨;
那边 46 帧的日志读作 `A` + 36 个连续 `M`)。**只放半边 1 不是「更小的改动」,
是一个已经被量过的坏配置。** 所以两个半边读**同一个 id**,并有源码用例钉住「恰好两处」。

**刻意没写成 `IsSoakCandidate('pullthink') and IsSoakCandidate('pullbeat')`**:
`pullbeat` 08-23 已 promote,**promote 掉的 id 不在任何 armed 串里** ⇒ 那样写当天冻结成
FALSE,而 `check_armed_wiring.py` 仍会报 WIRED(它查的是调用点存在,不是谓词可为真)。
**`pullcad` 陷阱逐字重演**,已由源码用例断言这种写法不存在。

**域刻意收窄到营地拉野**。小兵拉野撞**同一行**节流,但它的节拍**已经有 hold**,
所以那是**下一格**,不在本轮(一次一根杠杆)。已交总监,见 §7。
