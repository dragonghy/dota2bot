## 二、缺陷

`bots/ability_item_usage_generic.lua`,`X.ConsiderItemDesire['item_smoke_of_deceit']`:

```lua
if (nInRangeEnemy ~= nil and #nInRangeEnemy == 0)
or (nInRangeTower ~= nil and #nInRangeTower == 0)
then
    for _, allyHero in pairs(nInRangeAlly) do ...
        isThereEnemyNearby = true          -- 这个循环体是旗标唯一的写入点
end
if not isThereEnemyNearby then ... return BOT_ACTION_DESIRE_HIGH ... end
```

读出来这句闸是「我自己的圈干净,那去问问队友」。「干净」是 `#enemy == 0` **AND**
`#tower == 0`;写下来的是 `OR`,而两个 `== 0` 的析取**恰好在两张表都非空时为假** ——
即施法者 1200 内**同时**有敌方英雄和敌方塔。那一格上扫描根本不跑,旗标保持出生时的
`false`,底下的读者于是在一个走一步就把雾拆掉的英雄面前放雾。

## 三、⭐⭐ 本轮买到的可迁移句

**跳过一个单调的循环不是省事,是作答。**

一个守卫能不能安全地略过一段代码,取决于**被略过的那段是不是可能改变答案**。
这段循环体对旗标唯一的语句是 `isThereEnemyNearby = true` —— 它**只能**把答案往
一个方向推。于是「不跑它」并没有在一个已有答案的问题上省时间,它把那个问题
**答成了 FALSE**,而且是朝着「多放雾」的方向。

📌 **判据:读到一个闸挡在一段代码前面,先问【被挡住的那段能不能改变答案】。
能,它就不是优化,它是那个答案的另一半。** 与 0NEXT49(审读定价的是哪一个问题)、
0NEXT47(解释契约的注释 ≠ 文件遵守契约)、0NEXT45(已登记 ≠ 已处理)同族:
**一句看起来只是「省一趟」的代码,可能是唯一那趟。**

## 四、修法(一个杠杆)

`J.ShouldScanAlliesForSmokeBreaker( tEnemyHeroes, tEnemyTowers )`
(`bots/FunLib/jmz_func.lua`,`J.IsSmokeBreakerNearSelf` 正下方):

- armed(**turbo-only** + `smokescan`)返回 `true` —— 扫描无条件跑;
- disarmed **逐字是出厂那个表达式**,两个 `~= nil` 守卫在内、在同一条合取的同一个位置
  ⇒ 短路顺序与出厂对局逐字不变。

⭐ **传表不传 bot**:helper 收的是调用点用 `nRadius` 建好的那两张表,于是
「同一个圈、同一个 getter」由构造为真(`roamring`/`tormring` 的账)。

**不碰**:1200 半径、旗标的种子(那是 `smokeself`)、扫描体本身、
`DotaTime() < 0` 的早返回、ROAM/GANK/ROSHAN 三支、任何别的 `ConsiderItemDesire`。
⛔ **不与 `smokeself` 合取**:两个 gate 写在同一函数的两个表达式上、互不读对方
(`pullcad`,GH #606/#576),测试 §7 两边都断言了。

### 方向(闭式,不是实测)

armed 的「跑扫描」集合是出厂集合的**严格超集**;被闸掉的循环体只写 `true`;
旗标唯一的读者是 `if not isThereEnemyNearby then`,其下**每一支都是放雾**
⇒ **armed 只能收回一次放雾,永远不能放出一次出厂树拒绝的雾**。
**批测读数若反向,不能读成「这个杠杆让 bot 放雾更多」。**
