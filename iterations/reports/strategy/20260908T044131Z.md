## 1. 缺陷:一个函数里的四条回城分支,三条挂了守卫,第四条什么都没有

`X.ConsiderItemDesire["item_tpscroll"]`(`bots/ability_item_usage_generic.lua`)里
有**四条**分支把 `tpLoc` 设成 `J.GetTeamFountain()`:

| 分支 | 触发 | 回复守卫 | 要求刚被英雄打过? |
|---|---|---|---|
| `撤退:1` | `botHP < 0.19` | `not J.ShouldStayAndRegen` — **PROMOTED,每局在跑** | 是(8.0s,或 HP<0.12) |
| `撤退:2` | `botHP < 0.15 + 0.24*nEnemyCount` | **无** | 是(6.0s) |
| `撤退:3` | `botHP < 0.34 或 sum < 0.43`,lvl≥9 | `not J.ShouldRegenNotTpHome`(`stayfield`,gated) | 否 |
| **`回复状态`** | `sum < 0.3 或 botHP < 0.2`,lvl≥6 | **无** | **否** |

`撤退:2` 的空缺是**对的**,不动它:它要求有敌人**且**刚被英雄打过,属于 owner
「危险时撤退合法」,拦它就是拦逃命。**第四条不是**。它自己的合取项就在说这一点:
`J.GetProperTarget(bot) == nil`、`bot:GetAttackTarget() == nil`、`X.CanJuke()`、
1600 内至多 1 个敌人,而且——与上面两条 `撤退` 不同——**完全不问最近有没有被打过**。
这正是 owner P2 点名的那种「没人追你的时候低血回城」。

而它是语料里**真的会到达**的那条:1021 个 live 英雄帧里 **31 帧**满足它的触发。

## 2. ⭐ 主判据(可复用):明显的修法按**闭式**是 no-op,不是抽样问题

最自然的修法是把 `撤退:1` 的 `not J.ShouldStayAndRegen(bot)` 抄进第四条。**量了,不行,而且
理由是闭式不是样本量**:

- gold 不进 `.dem`(GH **#495**)⇒ 全部 1021 帧上 `bot:GetGold()` 恒 0;
- 于是 `J.ShouldStayAndRegen` 唯一能为真的路是它的 `bHasFlask` **三项析取**:
  主槽 `item_flask` / `modifier_flask_healing` / `modifier_tango_heal`;
- **而这条分支自己把三项全否定了**:`itemFlask == nil` + 那两个 modifier veto。

⇒ **在这个调用点,那个已发布的守卫化简成 `bot:GetGold() >= 90` 而已** —— 与 2026-08-29
对 `撤退:1` 的更正**逐字同一个闭式、同样的三个合取项**。

量出来的对照(尺子 `tests/_tprecov_sweep.lua`,驱动的是真函数不是复刻):

```
sar_true_any            13   ← 独立复现了 J.ShouldStayAndRegen 自己源码里记的 13
sar_true_in_trigger      1
sar_blocked_by_branch    1   ← 那唯一一帧靠 modifier_tango_heal 为真,而分支已经 veto 了它
S f_260902_154755_cm_wandbleed_residue zuus branch_vetoes_tango_heal
```

**这是 `tests/test_stayfield_callsite_domain.lua` 那条判据的第三个实例:
「一个守卫的域 = 它的谓词 ∩ 它被丢进去的那个合取式」。**
前两个实例是同一族的 `stayfield`(`fieldsip` 把它的 TP 腿清空)与 `撤退:1`。

## 3. 于是**算术挑了谓词**,不是口味

能在这里改变任何东西的守卫,必须读一个**分支尚未否定**的补给源。分支否定的是:大药
(物品 + modifier)与 tango 的 modifier;**没有**否定**携带着**的 tango / tango_single /
faerie_fire / 有充能的 bottle —— 正好是 `J.HasFieldRegenSource` 的集合减去大药。

⛔ 并且**刻意不走** `J.ShouldRegenNotGoHome`,两条理由都是数字、都在测试里断言:

1. `J.IsFieldSipEnough`(`fieldsip`,**当前成员串里 armed**)要求
   `FieldRegenSipValue >= 0.25 * GetMaxHealth`。大药被分支自己的 `itemFlask == nil` 排除后,
   可达上限是 `item_bottle` 的 **135** ⇒ 要求 `MaxHealth <= 540`,在本分支自己的
   `GetLevel() >= 6` 下**不可能**。走它就是发一个**在实验室当前串上域为空**的杠杆 ——
   正是那份文件为 `stayfield` 记录下来的陷阱。
2. `J.IsFieldRegenSituation` 的 **0.18 地板**把本分支 31 帧触发里的 **29 帧**排除在外。
   地板本身**逐字照抄进新谓词、不动共享的那份**:改共享地板会在同一次编辑里移动
   `stayfield` / `stayfield2` / `fieldbuy` 三个 id,那是 lanefix 捆绑的错误。
