## 2. ⭐ 主判据(可复用,超出本主题)

**一个保守近似,只有在「让它成立的东西仍然是这个谓词讲的那件事」时,才真的是保守的。**

「敌方拿过辉耀」**被**「这个人正在挨烧」**蕴含**,所以**逐条施法看,方向是安全的** ——
它只会少算幸存者。这也是为什么它六轮都长得像一层 slack。

它**不是**的那个性质是:**与侧别无关**。它的真假由**牌序**决定,而牌序是真谓词
**从不咨询**的变量;**镜像牌序按构造把这个变量钉死**。#445 实测:W40 全部
**20,167** 条辉耀伤害**全部出自夜魇自己的 skeleton_king,天辉 0 条**
⇒ 这个子句对**每一个天辉施法者在 46/64 局里恒为真**、对**每一个夜魇施法者恒为假**。
读数于是成了

```
radiant   1 幸存 / 51 次扔尘  ( 2.0%)
dire     50 幸存 / 93 次扔尘  (53.8%)
```

**27 倍的差跟 armed 腿无关、只跟物理队有关**;而 `ba/baseline/radiant` 的 `0/11`
被当作「天辉槽位够不到」的证据引用过 —— **那是一行被擦白的表,不是一个测出来的零**。

⇒ **一个恰好在某一侧恒真的必要条件,就是一个侧别过滤器**;
它会**删掉表里的一整行,而全程不打印任何一个看起来不对的数**。

与 GH #431 / #437 同族(一个偏小的、自洽的、带分母的读数),**但这次错的既不是查询词
也不是解析器,是「近似」与「被近似者」之间的一个隐藏自变量**。

## 3. 载体的选择 —— 以及为什么不用那个更好的

- **用来挡的载体**是 `item_radiance` 的 DAMAGE tick,因为 #445 数过它:这份语料里
  **20,167 条**,是**唯一已知存在**的辉耀证据。
- **更好的载体**是 `modifier_item_radiance_debuff` 的 `MODIFIER_ADD`/`MODIFIER_REMOVE`:
  那会给出**区间**,直接让窗口退休。**这份语料到底发不发这两个事件,没有人买过。**
  ⇒ 脚本把它们**数出来**(`radiance_debuff_add` / `_remove`)、**两个都不用来挡**,
  并在报告里打一行「计数非零 ⇒ 窗口可以退休」。
  **假设它存在会让窗口的正确性不可证伪;数它,则由下一轮来裁。**

## 4. 窗口就是那层 slack,方向要说清楚

`B3_BURN_WINDOW = 1.5`,两侧各 1.5s。辉耀按 **1.0s** 一跳灼烧,1.5s 是**一个 tick 周期
的 50% 余量**,覆盖两个边缘(刚上 debuff、第一跳还没落;以及刚走出光环、debuff 残留)。

**更宽 = 挡得更多 = 幸存者更少 = LIMIT 6 的安全方向。**
一个**带着 debuff 却在 3s 跨度里一跳都没有**的施法者会被误算成幸存者;
**这份语料没有已知的东西能造出这种情况 —— 而这是一句被写下来的假设,不是一个测量。**
两个边界都钉了(`t±1.5` 挡、`t±1.6` 不挡)。
