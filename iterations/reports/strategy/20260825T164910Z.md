## 2. ⭐ 撞出来的类:本仓的门看不见「只写不读的 local」

`.luacheckrc`:

```lua
only = { "1" }   -- 只启用 1xx(全局访问)
```

luacheck 的 unused 家族是 **2xx** ⇒ **关掉了,全仓、永久**。
这条设置本身是**对的**(继承来的 OHA 树满是无害的未用参数,1xx 才是抓 typo 的那条线),
但副作用是:一个 local **被赋值、从不被读**,能**静默通过铁律 6 的门**。

工具 `tools/agent/write_only_local_census.py`(默认扫本组九个决策文件,`--all` 全仓),
棘轮 `tests/test_write_only_local_census.py`(**已进 `run_py_tests.sh` ⇒ 已进每轮
`routine_selfcheck.sh`**;新写一个当天红,扫掉一个必须删 allowlist 行 ⇒ **名单只能缩**)。

**读数**:九个决策文件 **1,677 个 local**,单名只写 **13**、多名 **5**;
全仓 `--all` **307**(单名 **285**)。

**健全性是构造出来的,不是分析出来的**:一个名字在**整个文件里零次读** ⇒
**该文件任何作用域都读不到它**。所以工具**不解析作用域、不建符号表**,
结构上**不可能**把一个活的 local 判死。代价是**漏报**(在 A 函数被读、在 B 函数只写的名字不报),
**这条写在头里,不藏着**。

### ⚠ 判据一(本轮主产出):**名字不是身份 —— 这类工具最诱人的那一列最不可靠。**

「同名在别的文件里被读」看上去正是 (i) 死代码 与 (ii) 掉了消费方 的分界线。
**实测 18 条里错 17 条**:`Customize` / `Localization` / `attackRange` /
`botHealthRegen` / `_` 满树都在被读,而**没有一处是同一个计算**。
真正把一条提升为 (ii) 的判据**更窄、而且只能由人读出来**:
**别的文件那处读,坐在同一个块的逐字拷贝里**。
⇒ 该列在工具里被命名为 `same-name-elsewhere` 并**在输出里标着 HINT ONLY**;
谁把它当 "dropped consumer" 引用,引的是错的那一列。

### ⚠ 判据二:**「只写」不等于「死」——`require` 就是反例,而且占了 13 条里的 3 条。**

`local Customize = require(GetScriptDirectory()..'/Customize/general')`:
值没人用,**`require` 的加载副作用是承重的**。顺手扫掉 = 一个模块不再被加载。
棘轮里为此专门有一条断言(「三条是 require,LOAD SIDE EFFECT 才是要点」)。
连带修掉工具第一版的一处误导:`GetScriptDirectory()` 被 engine-call 计数器数进去了,
让**每一行 `require`** 都读作「花了一次引擎调用」——正好是该列想说的反面。

**13 条全部逐条判过并写进 `ALLOWLIST`**(每条一句理由)。**一条都没删**:
`0IMPL`(`mode_attack_generic:8`)与 `0SAT`(`hero_earth_spirit:500`/`hero_phoenix:774`)
已经立过同一个判断 —— **无害的死代码不值得一次带行为的编辑**。

## 3. ⭐⭐ 唯一的 (ii):`mode_retreat_generic` 的阶梯掉了第一级

```
mode_farm_generic:1192  「前期谨慎冲塔」            mode_retreat_generic:875  同名块
  1级 (lvl<=2 或 t<2:00) + 1200 环(中路 1100)      ── 消失(nLongEnemyTowers 只写不读)
  2级 (lvl<=4 或 t<3:00) +  898 环(中路  980)      2级 (lvl<=5 或 t<nFearClock) + 898(中路 980)
  3级  lvl<=9 + 校准判据                            3级  lvl<=9 + 校准判据
```

`nLongEnemyTowers` 在 retreat 里**被赋值两次(普通环 + 中路覆写)、被读零次**
⇒ **每次求值白花两次 `GetNearbyTowers`**,而**阶梯是平的**:到 10 级为止**一个环通吃**。
这与 GH #160 是**同一族的第三份拷贝**,但轴是正交的 —— #160 说的是**时间**分级塌成常数,
这里塌的是**环半径**。

### 判据三:**拒绝把它补回去,而拒的理由是量出来的域不是品味。**

`tools/agent/tower_band_domain.py`(棘轮同上,§4):

| 读数 | 值 |
|---|---|
| 塔坐标 | **22 座**,**61 枚**带 `buildings` 的 fixture **逐个完全一致**(复现 `0GEO`:地图是实测常数) |
| 存活英雄帧 | **563** |
| **任意**帧离敌方塔最近 | **173 u** ⇒ 语料**确实**含贴塔帧,零不是采样问题 |
| 该级自己的带(`lvl<=2 或 t<2:00`)帧数 | **72** ⇒ 分母不空 |
| **该带最近的一次逼近** | **1,310 u** |
| 该带中位 | **2,086 u** |

**1,310 > 1,200**(那一级会用的环)且 **1,310 > 898**(这份拷贝现有的环)
⇒ **补回去买到零帧**,而且不是差一根头发。
两个"零不是因为语料薄"的反问**都各自有分母答过了**。
机制也不是采样:`lvl<=2` 的英雄站在自己那条线的兵线交汇点,
大致在两座一塔之间 ⇒ 中位 2,086 u **正是这个几何预测的数**。

**⇒ 处理:钉住,不补也不扫。** 补 = 买零帧的加宽;扫 = **抹掉「阶梯掉了一级」这条证据本身**。
棘轮 §3 把这条钉死(两次赋值 / 两次引擎调用 / 姊妹拷贝仍在读),
**谁将来要补或要扫,红的是它并来要论证**。
