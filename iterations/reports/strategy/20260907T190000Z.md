## 3. 修法(gated,一次一个小杠杆)

新 helper `J.ShouldRefuseUnsupportedPunish( bot, target )`,turbo-only + `J.IsSoakCandidate('ohnum')`,
TRUE = 拒绝这个 punish 目标。三条释放:

1. **目标 1200u 内有我方活着的建筑** ⇒ 那是出厂域,本条一律不管;
2. **LETHAL 仍然放行** —— 和一屏之上 `depthnum` 的豁免同形、读同样两个数;
3. 否则要求 **ADVANTAGE(+1)**,即 `depthnum` 用在敌方半区的那个不对称,这里用在镜像的理由上。

方向按构造是**严格收窄**:调用点以 `and not <this>` 加入,armed 只能**移除**目标,不能新增。

### ⭐ 调用点为什么落在那里(这是本轮最该被复用的一条)

调用点落在**共享的** `bInDomain and J.SafeToCommitFight` 提交行上 —— **出厂 PROMOTED 路径** ——
**不在** `nInvadeDepth >= 800` 那个 `ownhalf` 分支里;并且 helper 的第一条释放读的是**世界**
(1200 内有没有建筑)而不是**另一道闸**。

于是单臂 arm `ohnum` 的波**真的够得到**这个调用点:

```
ohnum_alone_fires 28    ohnum_alone_changed 0
```

**这个 0 是语料事实**(出厂域按构造贴着建筑),**不是结构上的不可能**。
如果把调用放进 `ownhalf` 分支 —— 那是「收窄一个 `ownhalf` 域」时最自然的位置 ——
同一个 0 就**不可读**,而 `check_armed_wiring.py` 照样答 **WIRED**(GH #606:它验闸址不验可达性),
verdict 会读回「测过了,无效应」而没有人举手。那正是 GH #576 / #600 / #607 一直在立的案。

**这条替代写法不是靠注释挡住的**:`tools/agent/mutstand_ohnum.sh` **M4 真去做那次搬移**,
`tests/test_ohnum_refusal.lua` 的 placement 钉把它抓住。
