## 1. 主判据(闭式,可复用)

### 1.1 算术

两个 wrapper 委托同一个谓词:

```
J.ShouldRegenNotGoHome = IsFieldRegenSituation ∧ HasFieldRegenSource ∧ IsFieldSipEnough
J.ShouldRegenNotTpHome   = IsSoakCandidate('stayfield')  ∧ 上式     ← 调用点 A(TP 腿)
J.ShouldRegenNotWalkHome = IsSoakCandidate('stayfield2') ∧ 上式     ← 调用点 B(走路腿)
```

`fieldsip` armed 时第三个合取项是**量级**判据:`FieldRegenSipValue(bot) >= 0.25 * GetMaxHealth()`。
`FieldRegenSipValue` 是 `J.FIELD_SIP_HEAL` 上的一个 max,而表里 `item_flask = 400`
比第二名 `item_bottle = 135` 大 **2.96 倍**。

**调用点 A 自带 `and itemFlask == nil`**,其中 `itemFlask = J.IsItemAvailable("item_flask")`,
而 `J.IsItemAvailable` 的返回条件是 **`slot >= 0 and slot <= 5`** —— 正是
`FieldRegenSipValue` 默认扫的那一段。⇒ 在**每一帧这个否决能改变结果的地方**,
主槽里没有大药,能够到的最大一口是

```
sup{115 tango, 115 tango_single, 85 faerie_fire, 135 bottle} = 135
135 >= 0.25 * H   ⟺   H <= 540
```

同一分支另有 `and bot:GetLevel() >= 9`。⇒ **`fieldsip` armed + `bagsalve` 未 armed
(= W27/W28 的串)时,`stayfield` 的反事实域为空。**

**方向是保守的**:上式把分支的**其余全部合取项一律当成已满足**
(`X.CanJuke()`、`#nAttackAllyList == 0`、`GetAttackTarget() == nil`、七个 modifier、
`DistanceFromFountain()`、英雄名排除、外层 `nMode == BOT_MODE_RETREAT`),
在全部给定下仍然为空,**比按真实取值算严格更强**。

### 1.2 ⭐ 可复用主判据(本族的**下一条**,不是已有那条)

`test_tphome_tp_leg_counterfactual` 钉过的是:**一个守卫的域 = 它自己的谓词 ∩ 它被塞进去的那个合取式**
——两份文件之内就能算完的交集。本轮是它的**外一层**:

> **第三个 id,晚三个月入集,在第三个文件里,带着自己独立的裁定,可以把那个交集清空,
> 而它跟前两者互不点名。**

`fieldsip` **不是**「撤退:3」的合取项,源码里**一次也没提过** `stayfield`;它只是把一个
两跳之外的 helper 里的阈值挪了一下,而分支自带的、看上去毫不相干的 `itemFlask == nil`
把那次挪动**翻译成了一个零**。失败方向是最贵的那一种:**没有任何东西变红**,两个 id
的成员资格照旧,arm 串照列,`check_armed_wiring.py` 照样把调用点判成 WIRED
(它查的是「调用点存在」,不是「谓词在那里可能为真」),而录像组继续花轮次去买一个
**树已经让它买不到**的条件 (a)。

与 `pullcad` 陷阱(promote 一个 id 会冻死点名它的门)**同形,外一层**:
**这里两个 id 从头到尾没有互相出现过。**

### 1.3 第二半(有用的那半):两个 wrapper 的域不一样大

调用点 B(`mode_retreat_generic:236`)从 mode 入口到调用之间**没有任何 flask 合取项**
(`item_flask` / `itemFlask` / `IsItemAvailable` 三个 token 在 `GetDesireHelper()`
开头到调用点之间**一个都不出现**,已写成断言)⇒ 主槽大药可达 ⇒ 天花板是
`400 / 0.25 = 1600` maxHealth,而不是 540。

⇒ **「同一个谓词的两个 wrapper」在当前串上不是一个域;其中一个没有域。**
本族的 (a) 只能从**走路腿**读,而且读法要按「**身上带主槽大药**」分层 —— 物品是 dumper
已经在出的列。

### 1.4 第三半:`bagsalve` 不再是搭车的

它自己的入集说明写着,单独 arm 是「**逐字节 no-op**」,理由是它widen 的那个谓词的两个消费方都 gated。
在调用点 A 上、`fieldsip` armed 时这句话**反过来了**:背包腿是**唯一**一条
`itemFlask == nil` 杀不掉的腿(`IsItemAvailable` 停在 5 槽,大药在 6–8 槽时那个合取项**仍然为真**)
⇒ **`bagsalve` 是 540 maxHealth 以上唯一能让 `stayfield` 开口的东西**,不是免费乘客。
已在**真实背包大药帧**上驱动(不是建模):`f_260822_182012_sb_backpack_rescue_372`
(spirit_breaker,maxhp 1378,slot 6 真大药,主槽全干)——
未 armed `FieldRegenSipValue = 0`;armed `= 400`,`400 >= 0.25*1378 = 344.5` ⇒ `IsFieldSipEnough` 翻真,
**而 `IsItemAvailable('item_flask')` 两边都是 nil**(两者读的是**不同槽段**,这就是全部机制)。
