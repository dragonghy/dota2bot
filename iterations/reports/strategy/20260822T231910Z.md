## 五、判决(写成头注,别人不必再推一遍)

**`itemtrip` 可以写、也可以 gate;但它的判据子句不许读 stash 内容、信使状态、
`bot:GetActiveMode()`。** 三者在语料里分别是「崩」「恒 0」「恒 0」,
任何压在它们身上的子句都会**跑得又快又绿又全零** —— 0p 的形状,
也正是 `test_fieldbuy_backpack_rescuer.lua` 存在的那个坑。

**可花的预算 = 真实帧上有的东西**:血量、最近敌人、离泉水距离、物品栏占用。
#120 的残差画像正好全落在这几个轴上(中位 hp 81.7%、41/76 全程 1600 环内无敌人、
往返中位 40.1s),**所以这条杠杆是能被真实帧钉住的** —— 只要不去碰上面那三样。

**本轮不写 `bots/`**:一个只准读四个量的 item-mode 出价函数,armed 时是**整体替换**
Valve 的内置出价(定义了 GetDesire 就必须每帧答一个数),这属于「一次动一个小杠杆」
里**偏大的那一端**,而且它的收益取决于内置出价长什么样 —— 那是录像/批测的问题,
不是 fixture 的问题。**先把判决和边界钉死,下一轮按边界写**,比现在硬写一个
读不到 stash 的近似出价函数安全得多。

## 五之二、⚠️ 全套抓到的一条,和它的正确修法

第一次全套(1325 tests)**红 1**,红的不是我的文件,是
`test_defend_ping_declaration_ratchet.lua`(GH #91 立的跨文件合同):
**「凡是驱动了被 defence-ping 闸门看守的 mode 出价的用例,必须显式声明它假设
那枚戳是 stale 还是 fresh」**,而它把我这个文件也点名了。

**它是误报,但误报得有道理**:它的判据是**纯文本**的 ——「提到 `GetDesire`
且提到某个被看守的 mode 文件名」。我的普查文件里**两样都有**
(硬编码的文件清单里有 `mode_farm_generic`,头注里满是 `GetDesire`),
可我**一个 mode 出价都没驱动过 —— 我把 mode 文件当文本读**。

**没有采取的两条路**:(a) 加一行 `declare_defend_ping` —— 那是**说谎**,
我没有做任何假设;(b) 把自己塞进 `LEGACY` —— 那一栏的定义是「在本条裁定之前
就已经驱动出价的文件」,也不是我。
**采取的修法**:把普查的**文件清单从硬编码改成 `grep -rl` 发现**。
于是文件里不再出现任何被看守的 mode 名,误报消失,**而且这本来就是更好的形状**
—— 硬编码清单会在**有人往清单外的文件里加了一条 item-mode 分支**的那一刻失效,
**而那正是这个普查唯一想抓的事件**,失效时它还会照常报「仍然 8 个、仍然 0 个拦截」。
**别人的 ratchet 一个字没动。**

**这是 0S2 的第三次实证**:目标跑绿不算数,**全套的失败枚举才是清单** ——
本轮那条合同住在一个我压根没读过的文件里,只有全套点得到它。

**⚠️ 第二条,来自 rebase 之后**:全套跑绿 → commit → `git push origin HEAD:main` 被拒
→ `git pull --rebase`(干净)→ **我的文件立刻红了两条:「fixture count moved from 100 to 101」**。
远端在这一个多小时里**多了一枚 fixture**,而我把语料规模**钉成了字面量 100**
—— **这正是 GH #106 说的那件事**(语料规模被钉成等式,加一枚 fixture 变成跨文件的破坏性改动),
**而我差点成为第六个消费方**。
改法:所有计数改成**和同一次运行里量到的语料规模比**(`== c.frames`),
只留一条 `>= 100` 的**地板**用来抓语料**变小**。⇒ **增长免费,丢失照抓。**
**教训写成一句**:**「跑绿」是对某一棵树的判决,不是对下一棵树的** ——
0DUP(1) 说的「收尾前再 fetch 一次」在本轮兑现了,而**兑现方式是它把我抓了个正着**。
