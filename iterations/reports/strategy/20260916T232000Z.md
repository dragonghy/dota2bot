## 1. ⭐⭐ 头条:一个 4 只兵的满波,在 `ShouldDefend` 眼里是 **0 个敌人**

`bots/FunLib/aba_defend.lua` 的 `____exports.ShouldDefend` 这样造它的威胁计数:

```lua
local nNearby = enemyHeroNearby + math.floor(creepWeights)
```

小兵的单价是 **0.2**(`creepWeights = creepWeights + 0.2`)。Dota 的一波小兵是 **4 只**。
`4 × 0.2 = 0.8`,`math.floor(0.8) = 0` ⇒ **这个计数的小兵那一半,要到第 5 具尸体才开始计数。**

这个截断**原本是无害的**:它唯一的下游是 `nNearby == 1 / 2 / 3 / >= 4` 的角色阶梯,
而阶梯拒掉的一切都落进下面那条**没有任何威胁前提**的兜底
`pos == GetClosestAllyPos({2,3}, building)` —— 兜底照样指派一个防守者,所以**截断被兜底挡住了**。

**而上一轮(19:27Z)落地的 `defquiet` 恰好拆掉了那块挡板**:它在「安静」的建筑上关掉兜底,
而它问「安静吗」用的正是 `nNearby >= 1`。

⇒ **两者合起来,把防守者从正在被拆的那座塔上撤走。** 一座塔被一波兵推着、附近没有英雄,
读数就是 `nNearby == 0`,也就是「安静」。

📌 **这是 `defquiet` 自己的域缺陷,不是它旁边那个 id 的** —— 上一轮把 `nNearby` 当成
「这儿有没有人」的**测量**来用,而它是一个**带截断的**测量;
差值恰好是「一整波兵」这一档,也恰好是防守这件事最常见的触发原因。

### 1.1 修法:**一个析取项,原地,同一个 id**

```lua
-- 旧:if (not bDefQuiet or nNearby >= 1)              and not result and pos == ...
-- 新:if (not bDefQuiet or nNearby >= 1 or creepWeights > 0) and not result and pos == ...
```

- ⛔ **不开新 gate id,而且这是刻意的**:`defquiet` **从未入集**(P4.2 冻结),所以原地收窄
  **不作废任何已测的东西**;而写成 `IsSoakCandidate(X) and IsSoakCandidate(Y)` 就是 **pullcad 陷阱**
  (`Y` 被 promote 那天整条合取**永久冻成 FALSE**,`check_armed_wiring.py` 仍答 WIRED)。
- ⛔ **截断本身一个字节没动**:它喂着上面那条角色阶梯,**动它就动了每一级**。
  这是本轮**刻意没做**的那个改动,并且**被变异 N5 明码标价**(`math.floor` → `math.ceil` = CAUGHT)。
- 收窄**只可能把行为拉回出货侧** ⇒ `defquiet` 的单向性(armed 相对 shipped **只减不增**防守者)
  **逐字仍然成立**,并被重新断言。
- **`.lua` 与 `.ts` 一起改**。
