## 2. 头条:`躲血魔大` 那条分支,发车用的是**别人算出来的塔坐标**

`X.ConsiderItemDesire["item_tpscroll"]`(`bots/ability_item_usage_generic.lua`)里的落点
`tpLoc` 是**整个 Consider 函数共用的一个函数级 local**。`tpstale`(09-14 落地)已经把
**回复状态** 那条分支的泄漏堵上了。本轮的读法是 0NEXT34 那条判据的直接应用
——「**修一个已登记的缺陷之前,先问它上游/下游还有没有同一个洞**」——
把这个函数里**所有**读 `tpLoc` 的消费点数了一遍:**还剩一个,rupture 分支**。

**缺陷,闭式**:
- 上游两个写入方**前往守塔**(← `X.GetDefendTPLocation`)与**前往推塔**(← `X.GetPushTPLocation`)
  先写 `tpLoc`,再要求一个**距离测试**才发车;**距离那一半失败时它们既不发车也不清空**。
  函数里唯一的出厂清空是守塔分支自己的 `J.ShouldAllowDefendTp` 那一处,而它跑在距离测试**之前**
  ⇒ 清不掉一个「败在距离上」的落点。(这三句是 `tpstale` 立的,本轮逐条重新棘轮过,没有引用了事。)
- rupture 分支自己在一个**内层合取**(1000 内至多 1 个队友 **且** `X.CanJuke()`)里写 team fountain;
  **内层合取失败时它同样不 return**,直接落到一个对共用 local 的**裸非空测试**
  ⇒ 它带着塔坐标发车,打上**自己的逃命动机**,出价 `DESIRE_HIGH`。

**⭐ 为什么这不是 `tpstale` 的重复件 —— 是两个 OUTER head 的算术,不是口味**:
- `tpstale` 守的 回复状态 坐在 `( botHP + botMP < 0.3 or botHP < 0.2 ) and GetLevel() >= 6` 下面。
  **满血的 bot 那个 head 为假**,于是该分支**自己的非空测试根本不被求值** ⇒ 泄漏**不在那里被消费**,继续往下走。
- rupture 分支的 head 只读 modifier、剩余时间、敌人数 —— **没有任何血量项**。
- ⇒ **`tpstale` 因为 bot 健康而够不到的每一帧,这一条都够得到。**
  测试 §2 是**解析两个 head** 来断言这件事(⛔ 不复述常数:复述常数的测试在常数变了以后报「世界没动」)。

**后果按分支自己的话说**:这条分支存在的理由是**躲开血魔大**,它自己的落点是泉水。
泄漏帧上它把一个**刚刚被守塔/推塔算出来又被它们自己否掉**的塔坐标当成逃命落点,烧掉卷轴,
把一个被 rupture 挂着的英雄送到线上 —— 而 rupture 惩罚的正是「接下来必须走路」。
连带地,分支自己写的队友数与 juke 两个条件在那种帧上**答什么都不算数**(`tpstale` 那条「守赋值的否决
够不到由别人赋值满足的发车条件」,在这里第二次成立)。

## 3. 修法:一个 id `tprupt`,turbo-only,单独 gate

`J.ShouldDropUnownedRuptureTp( bOwnsDestination )`:gate 在 **helper** 里(调用点**一个候选 id 都不出现**,
这样同一条分支上的杠杆各自可 arm)、**单独一个 id**(⛔ 绝不与第二个 soak id 合取 —— pullcad 陷阱)、
**gate 先、turbo 后**(未 armed 一个引擎调用都不碰)、**不读 bot**(它只回答「这个落点是不是调用方自己选的」)。

调用点:`local bRuptureTpIsOurs = false` → 内层合取里紧跟自己的落点赋值置 `true` → 一个**只会 `tpLoc = nil`** 的 gated 块。

**方向由构造固定**:flag 恰好在**分支自己的合取已经通过**的那些帧上为真
⇒ armed 只能把这条分支的 TRUE 变成 FALSE,**永远不能**给一个本来不走的 bot 发车。
未 armed 时 flag **写了但没人读**,出厂答案逐字节不变。
