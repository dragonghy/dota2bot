## 2. ⭐ 主判据:一条不等式,不是一个百分比

拉线节拍是一个 `if / elseif / else`,而**三条臂全部**坐在 Think 开篇那道节流阀后面:

```lua
if <没有旁路> and J.Utils.IsBotThinkingMeaningfulAction(bot, Customize.ThinkLess, "roam") then return end
...
if     now - creepPullAttackTime > nBeat then  POKE               -- 那个 `if`
elseif now - creepPullAttackTime < 0.5   then  hold(不发指令)      -- 已 promote 的 'pullbeat'
else                                            DRAG               -- 那个 `else`
```

节流阀拿 `bot:GetAnimActivity()` 匹配 `utils.lua` 的 `meaningfulActivities`,
**表头就是 `ACTIVITY_RUN` / `ACTIVITY_ATTACK`**。刚右键完对线英雄的 bot
**按构造**在 `ACTIVITY_ATTACK` 里待满一个攻击周期。

记 **R** = 节流阀重开间隔(实际就是攻击周期)。节拍**只在重开帧上被问到**,
而那种帧上「距上次 poke」已经 **≥ R**:

> **R > nBeat ⇒ `if`(POKE)在每一个能问到节拍的帧上都为真 ⇒ `else`(DRAG)到不了任何一帧。**

**不是「drag 走得少」,是空集。** 出厂 `nBeat = 1.2`,前期攻击周期 ~1.4–1.7s
⇒ **出厂配置站在不等式的错误一侧**。这就是 wave13「站着 TANK」指纹,
在**节拍自己修好之后**从**节拍看不见的那一行**长回来 —— 与 GH #186 同族,
那次是营地(`pullthink`),这次是兵线。**那条注释自己写着「Scoped to the CAMP pull only …
one lever at a time」—— 本轮兑现的就是它明写的那半。**

## 4. 落地:一条并列子句,一个独立的门

```lua
if not (bot.roamCampPull  ~= nil and J.IsSoakCandidate('pullthink'))
and not (bot.roamCreepPull ~= nil and J.IsSoakCandidate('creepthink'))
and J.Utils.IsBotThinkingMeaningfulAction(bot, Customize.ThinkLess, "roam") then return end
```

- **未 armed 逐字节惰性**:多一次对 `bot.roamCreepPull` 的 nil 比较,该字段在每个非拉线帧上都是 nil。
- **Turbo 结构性、不靠断言**:`roamCreepPull` 只在 `J.ShouldCreepPullLane` 非 nil 时存在,
  而它开篇就是 `J.IsModeTurbo()`。
- **为什么是自己的 id**:打包由**包含关系**决定不由强弱决定(本组 `0FOG` 主判据乙)。
  `pullthink` 管 `roamCampPull ~= nil`,本条管 `roamCreepPull ~= nil`,而 GetDesire
  **设一个就把另一个置 nil** ⇒ 两域**按构造互斥**;合成一个 id 会让两边 (a) 读数
  **谁也不归属谁**(本组 GH #319)。已写成断言 `[gate G3]`。
- **绝不合取**:`IsSoakCandidate('creepthink') and IsSoakCandidate('pullbeat')` 会在
  promote 当天冻结 FALSE 而 wiring 仍报 WIRED —— **`pullcad` 原案**;`[gate G1]` 钉住,M2 抓得住。
