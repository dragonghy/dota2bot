## 二、缺陷

`bots/FunLib/jmz_func.lua` `J.WeAreStronger(bot, nRadius)` 以 `local res = nOurPower > enemyPower` 收尾。
英雄循环与那个比较之间,**只有一个建筑项**:

```lua
local nAllyTowers = bot:GetNearbyTowers(600, false)
if J.IsValidBuilding(nAllyTowers[1]) then
    ... ourPower = ourPower + power ; ourPowerRaw = ourPowerRaw + power
end
```

**全函数没有任何敌方建筑项。** 于是:

- 站在**自家**塔下 ⇒ 那座为我们开火的塔被计入(**对的**);
- 站在**他们**塔下 ⇒ 那座正在打我们的塔**在比较里不存在**。

⛔ 不对称不在某个常数、半径或算符里 —— **是两栏之一压根没有这一项可漂**。

## 三、为什么这不是 `helpring`(同日 07:55Z、同组、**没发船**)

⭐⭐ **分得开它们的不是数字,是缺陷的种类。**

`helpring` 问的是「一个比较的两半该不该数同一个圆」= 两个都站得住的数之间的**选择**,
所以它需要一个够大的域来支撑「值得动」,而它的天花板是 2。

本条不是选择:出厂表达式把**一个单位的火力只计入一个对称比较的其中一栏**,
而「我们是不是更强」的任何读法都不会让**敌方的塔**变成我方资产或非战斗单位。
⇒ 与 `pipetower`(把他们的塔放进我们那一栏)、`bbancient`(域实测 **0**,仍 gated 落地)同判据:
**一个算术遗漏不需要域来证明它错。**

⛔ **这句话仍然不是「薄域可以发」的通行证** —— 它只在「谓词自己的算术是错的」那一格成立。

## 四、修法(一个杠杆)

`J.GetFightPowerEnemyTowers( hBot, nRadius )`,放在 **`J.WeAreStronger` 正上方**:
armed(turbo-only)返回 `hBot:GetNearbyTowers( nRadius, true )`;disarmed 返回 `{}`,
于是调用点的 `J.IsValidBuilding(nEnemyTowers[1])` 守卫让 `enemyPower` **逐字**是出厂那个数。

调用点把半径 **命名一次**(`local nFightTowerRing = 600`),**两半都读它** ——
于是两个圆再漂开就会把测试顶红(`roamring`/`tormring` 的代价)。
敌方那一项的算式**逐项镜像**出厂的我方那一项,glyph 支在内。

**不碰**:半径、glyph 因子、英雄循环、幻象项、团战 ×1.20 加成、比较读哪个累加器(`fightstate` 的杠杆)。
⛔ **不与 `fightstate` 合取**:后者换**我方**读哪个累加器,本条加**敌方**那一栏,
两个 gate 互不相交、永不 and 在一起(`pullcad` 教训,GH #606/#576)。

**方向是闭式的,不是实测的**:加数 `#t * math.sqrt(Max(0, ...))` 非负、加在严格 `>` 的**右**边
⇒ armed 只能 TRUE→FALSE。56 个调用点都把 TRUE 读成「可以打/可以压」
⇒ **armed 只能收回一次交战,永远不能发起出厂树拒绝的那一次**。
⛔ **批测读数若反向,不能读成「杠杆让 bot 过度激进」。**
