`tests/fixtures/f_260819_222030_jugg_tp_start.lua`(`20260819_222030_slot1`,t=437.1,subject juggernaut):

## 3. 那还剩什么可做 —— 最窄的那个子集

TP 是 **~3 秒站着不动**。如果**看得见的带内敌人**在通道长度内就能打掉我的**全部血量**,
那么通道**救不了我**,它只保证我在它失败的过程中站着不动;这时**走**比**站**强 ——
走是唯一还能改变几何的动作。

这正好是 `tpsafe` 自己那条 fall-through 的**镜像**:它写着「贴脸爆发会杀我 ⇒ 别赌走位,
赌通道」,而同一份 W7 语料显示**那个赌注在 ≤350 带上实测在输**(`walk_guard` 带致死 15.9%)。
**本条不把那个赌注延伸进空档带**,但也**不去动 ≤350 带**(那是 `tpsafe` 的地盘,
它自带的 fall-through 是刻意的,本 id 一律不碰)。

### 3.1 落地

新 helper `J.ShouldNotTpUnderLethalPressure`(`jmz_func.lua`,紧跟 `CanEnemyInterruptTpChannel`),
唯一调用点接在撤退块**顶部、紧挨 `tpsafe` 之后**:

```
turbo ∧ IsSoakCandidate('tpgap') ∧ 活着
  ∧ 350 内无敌            -- tpsafe 的地盘,一律不碰
  ∧ 能走                  -- 未定身/未被减速到 285 以下(与 tpsafe 的 fall-through 同形)
  ∧ 700 内有可见敌
  ∧ 带内估计伤害(窗口 3.0s) ≥ 当前血量
```

**窗口取通道长度 3.0s,刻意不复用 `J.GetTotalEstimatedDamageToTarget`(它硬编码 5s)**:
问的是「通道走不走得完」,定价的就该是站着的那 3 秒;问 5 秒会拒掉那些其实走得完的按下
—— **正是 §2 那一帧记录的错误**。

**孤立性**:门是它自己那一条,**无合取依赖** ⇒ 不踩「promote 一个 id 会把点名它的门
永久冻成 FALSE」那条教训(`pullcad` 的那次)。**单独 arm 即有意义。**

### 3.2 域(实测)

`tests/_tpgap_band_sweep.lua`,104 枚 fixture × 每个存活英雄各驱动一遍 = **966 个真实帧**:

| 桶 | 数 |
|---|---|
| 空档带 (350, 700] | **161 / 966 = 16.7%** |
| `tpsafe` 自己那带 (≤350) | 96 / 966 |
| 两者皆无 | 709 / 966 |

三者正好划分语料(**已写成断言**,否则某个桶可能在悄悄重复计数)。
**⇒ 这不是边角情况,改这里的爆炸半径很大** —— 也正因如此本轮只落**最窄的子集**,
而不是整条带。

## 4. ⭐⭐ 一条会影响别人的 harness 事实:射程型修法在本地结构上不可证伪

`GetAttackRange` 在**每一枚 fixture 英雄**上都读 mock 默认 **150**(GH #145)
⇒ `nNow <= GetAttackRange() + 150` 只能在 **300** 以内为真 —— **严格低于**本 issue
讨论的这条带。实测:空档带 161 帧上 `CanEnemyInterruptTpChannel` 命中 **0/161**
(两个方向都数了)。

**后果不是「测不了」,是「测出来会全绿而什么都没证」**:任何把射程写进谓词的修法,
在这份语料上写出来的用例都是同义反复。所以:

- 本轮的谓词**刻意不含射程腿**(700 扫描 + 伤害估计已经覆盖它要表达的东西);
- §2 那条用例**显式声明** Lich 的真实 500,并在声明**之前**先断言 mock 的 150 ——
  **这样它就不能悄悄变成同义反复**,而且 GH #145 一旦被修,该断言当天红。

同族的第二条,本轮新量到并写成断言:**mock 的 `GetEstimatedDamageToTarget` 对 duration
不敏感**(问 3.0 和问 5.0 返回同一个 observed 数)⇒ **3 秒窗口这个决定在本地一帧都验不了**,
它只能从**源码**断言。这一条差点漏掉,见 §5。
