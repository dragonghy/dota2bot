## 1. 换的这根轴:合取的可满足性

`0CLK` 问常数的**值**,`0TERN` 问表达式的**解析**。两条都问「这一条腿对不对」。
本轮问的是**两条腿之间**:`bots/` 里每个 `if/elseif` 条件,按顶层 `or` 拆成析取项,
每个析取项按 `and` 拆成合取项,把落在**同一个左值**上的数值比较收在一起判可满足性。
纯算术,零 AWS,一次扫描 < 1s。

同一把扫描器另外两问都跑了,**都是空的**,一并记账(空结果也是产出):

## 2. 缺陷

`bots/item_purchase_generic.lua`,注释锚点「死前如果会损失金钱则购买额外TP」:

```lua
if botGold >= tpCost
    and bot:IsAlive()
    and botGold < ( tpCost + botWorth / 40 )   -- 我手上这点钱本来就要没
    and botHP < 0.08                          -- 快死了
    and botHP >= 1                            -- ……而且满血
    and bot:WasRecentlyDamagedByAnyHero( 3.1 )
    and not HasSufficientTp()
    and Item.GetItemCharges( bot, 'item_tpscroll' ) <= 2
then bot:ActionImmediate_PurchaseItem( "item_tpscroll" ) end
```

`botHP` 是同文件 `botHP = J.GetHP(bot)` 的 **0..1 分数**(已写成断言,并在一枚真实帧上
实测 `J.GetHP` 落在 0..1)。⇒ 两个界**互斥**,合取**对任何实数为假**,约 12 行是死代码。
**不是「几乎不触发」,是结构上不可满足。**

**它不是我们写坏的**:这一对逐字出现在初始 OHA 快照 `74727e4a:957-958`
⇒ 该块在本仓库历史上**一次都没有执行过**,我们过去任何一次批测都不含它。

**为什么判它是杂散合取项而不是某种约定**:同文件往下约 35 行的**姊妹块**(辅助死前买粉)
是同一个想法 —— 同样的 `botGold < (cost + botWorth/40)`、同样的
`WasRecentlyDamagedByAnyHero(3.1)`、同样的充能上限 —— 而它的 HP 腿写的是
`botHP < 0.06`,**没有配对的下界**。两个块一个有那行一个没有。
**这个不对称已经写成 `[reverse]` 断言**:哪天有人给买粉块也补一条下界,用例红着来要求
重新论证「杂散」这个判读,而不是让它悄悄变成一条约定。

## 3. 杠杆(一个,最窄)

写成**选择**而不是析取(`0TERN` 的处方):

```lua
local bDyingWithDoomedGold = botHP < 0.08 and botHP >= 1
if J.IsModeTurbo() and J.IsSoakCandidate('tpdeathbuy') then
    bDyingWithDoomedGold = botHP < 0.08
end
```

- **门关着与出厂逐字相同**,而且这条同一性在这里是**算术**不是承诺:门关着的谓词
  仍然是那个处处为假的合取,已在网格上证掉。
- **阈值一动不动**(`ARMED_LO == LO` 是断言):本条只去掉那条杂散下界,移动阈值是**第二根杠杆**。
- **门无合取依赖 ⇒ 单独 arm 即有意义**,不踩 `pullcad` 那条「promote 一个 id 会冻死
  任何点名它的门」的教训。

### ⚠ 方向:这是**加宽**,与本组以往每一条相反

以往每一根杠杆的 armed 谓词都是出厂谓词的**子集**(只可能少开火)。本条 armed 是
**空集的真超集** —— 它**严格增加**出厂树从不发生的采购。两个推论,已写进入集提议与 queue 单:

1. **一份「armed 与 baseline 无差别」的读数不能验证本 id**;无差别 = 没 armed,或域为零。
2. **反向哨兵不是「TP 采购数不许塌」,是「TP 花费不许暴涨」。**

### 为什么值得 arm(验证哲学条件 (c),标准打法不是偏好)

Dota 里英雄死亡会把身上未花的金钱按比例赔给击杀者、其余蒸发,**死前把钱花掉**是教科书习惯。
块自己的金钱子句正是一条**带**而不是一个下限(`botGold >= tpCost` 且
`botGold < tpCost + botWorth/40` = 「我买得起,而且我手上这点钱本来就要没」)。
TP 卷轴是那里最该买的东西:便宜、**用掉而不是掉落**、且块只在**手上 TP 不够**时开火。
Turbo 里论据更强而不是更弱:复活快,回场第一件事就是想 TP 回战场。

## 5. ⭐ 一条会影响别人的 harness 事实(`0DIR`:带错符号的谎话)

**这个块的两条金钱腿在 fixture 上读 TRUE,而且是错的那种 TRUE。**

- `GetGold()` **不在 mock 里** ⇒ 落 `^Get` 默认 **0**;
- `GetItemCost()` 答 **0**(已由 `tests/test_fieldbuy_backpack_rescuer.lua` 钉过);
- ⇒ `botGold >= tpCost` 是 `0 >= 0` = **TRUE**;
- ⇒ `botGold < tpCost + botWorth/40` 是 `0 < 净值/40` = **TRUE**(净值 > 0 时)。

**后果不是「测不了」,是「端到端驱动这个块会全绿,而那份全绿对金钱带一无所证」** ——
`0DIR` 说的正是这一种:读不到的量答「假」只是静静地什么都不做,答「真」会让杠杆
**看起来大获全胜**。两个方向都已断言:mock 哪天学会金钱,该用例**红着**来要求重测,
而不是继续看起来「已验证」。

**因此本轮不主张端到端钉帧,也没有假装钉。** 可买到的本地验证是四件:
(1) 死代码的**算术证明**(含两个常数的边界邻域点);(2) **门关着逐字同一**;
(3) **方向**(armed ⊋ 出厂);(4) 语料可读的那一半域(4 帧,点名)。
