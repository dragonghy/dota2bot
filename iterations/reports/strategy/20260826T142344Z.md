## 2. ⭐ 缺陷(GH #215)

`ability_item_usage_generic` 的自动买活是三段阶梯,中间那段:

```lua
if bot:GetLevel() > 24 and nRemainingRespawnTime > 80 then <buyback>
```

**80 是普通模式的时长。** 两条有据可查的引擎事实:复活表 1 级 **12s** → 25 级 **100s**(以上保持最大);**turbo 复活快 25%**。
⇒ **turbo 复活时长天花板 = 100 × 0.75 = 75 秒**,比阈值低 **5 秒**。而 `nRemainingRespawnTime` 两种读法(出厂 `R−2e` / GH #208 修好后的 `R−e`)**都 ≤ R ≤ 75**。

⇒ `> 80` **在任何可达 turbo 帧上都是假,两种读法都是**。**STRUCTURAL-ZERO。**

**这一条的刀口在于它写的就是 `GetLevel() > 24`** —— 复活表上那个 100 秒的最大值本人。规则是为「复活最久的人」写的,而缩放把**连那个最大值**都压到阈值下面。「域太小」是一个统计判决;这是一个**算术判决**,在这条分支唯一为之而写的那个等级上成立。

## 3. ⭐⭐ 修法:gated `bbfight`(turbo-only)

```lua
J.RESPAWN_TABLE_MAX    = 100
J.TURBO_RESPAWN_FACTOR = 0.75
J.BUYBACK_FIGHT_FLOOR  = 80

function J.BuybackFightRespawnFloor()
	if J.IsModeTurbo() and J.IsSoakCandidate( 'bbfight' ) then
		return J.BUYBACK_FIGHT_FLOOR * J.TURBO_RESPAWN_FACTOR
	end
	return J.BUYBACK_FIGHT_FLOOR
end
```

- **未 armed 返回出厂那个字面量 80**;armed 返回 60。
- 阈值是普通模式的时长 ⇒ 用**同一个有据可查的系数缩放**,不重新猜一个数。
- **三个常数具名 + 各带棘轮** —— 它们是**本容器无法核验的外部引擎事实**,具名让漂移变成红测试(§5 说明为什么这件事非做不可)。
- **armed 值是算出来的,不许写字面量 60**(`[source]` 断言函数体里没有 `60`)。
- **GH #207 预检通过**:单合取,另一半是 `J.IsModeTurbo()` 模式谓词,不是另一个 soak id。
- **一次动一个小杠杆**:同段阶梯的 `> 20` / `< 40`,与 GH #208 登记为「下一格」的姊妹误读 `nFullRespawnTime < 60`,**都故意没动**,`[limit]` 两条用例原样钉住。
