## 一、⭐⭐ 本轮的正题:一个「同形缺陷」不等于一个「同形论证」

`slotarb`(§DI.4)的全部安全论证是一句**严格子集**:
armed 扫的是超集,而扫得更宽只可能找到更近的人 ⇒ armed 的 TRUE 集是出厂 TRUE 集的严格子集。
它成立,是因为 `IsTheClosestOne` 的第一行是

```lua
local closestMember = bot        -- 调用者天然在候选集里
```

`J.IsClosestToDustLocation` 的第一行是

```lua
local closest = nil              -- 调用者只有被扫到才算数
```

**两个函数只差这一个初值。** 而它足以把结论翻过来:调用者若不在出厂的扫描集里
(dire 除 pid-9 外的四个、radiant 的 slot-5 那个),出厂**永远答不了 TRUE**,
armed 却可能答 TRUE。于是缩域**两个方向都切**:

| 方向 | 含义 | 真实帧 |
|---|---|---|
| 出厂 FALSE → armed TRUE | **站在原地、包里有粉**的 bot 今天被拒,只因为它的 player id 不是一个 slot 号 | `[decision D3]` a |
| 出厂 TRUE → armed FALSE | **3,938 码外**的持有者今天拥有决定权,扫得到更近的人之后让出 | `[decision D3]` b |

两个方向都量到了(`[not-subset]`:一帧 35 个格子,两向计数各 > 0)。
⇒ **本轮不主张严格子集。** 把 §DI 那句话抄过来,会是一个**形状正确、对象错误**的声称 ——
这正是本档案连着三轮在变异台上抓到的那一族(用错误理由达成的正确结论),
只不过这一次它出现在**跨条目复用论证**的位置上,而不是在断言里。

**这也正是它必须 gated 上路的理由**:armed 让 dire 侧**四个原本结构性用不了粉的 bot**
开始用粉。「局部正确 ≠ 集体涌现好」在这里不是套话,是这条改动的实际风险面。

## 三、⛔ 量具:这条谓词在本轮之前**在任何 fixture 上都跑不动,而且不报错**

**这一节是留给总监的,而且它比本轮的杠杆更值钱。**

### 三.1 `GetItemSlotType` —— 而**第一版诊断是错的,拆穿它的是变异台**

本轮第一版写的是「三个 `ITEM_SLOT_TYPE_*` 常量不在 `_G` 里,所以每一处
`== ITEM_SLOT_TYPE_MAIN` 都在和 nil 比」,并据此在 `replay_fixture.lua` 里装上了
`_G.ITEM_SLOT_TYPE_MAIN = 0` 等三行。**那是错的。**

变异台的 **M15**(删掉刚加的那一行)**活了下来**,而它活下来的理由就是那句话是假的:
`api.install` 会把**任何未知的全大写全局**解析成一个 **≥1001 的互异哨兵**
(本轮在真实帧上量到 `ITEM_SLOT_TYPE_BACKPACK == 1174`,
正好是 `tests/test_fieldbuy_backpack_rescuer.lua:50` 那句注释里引的那个数)。
真正的机制是**那个 getter**:没 spec 时 `^Get` 默认答 **0**,于是

```
GetItemSlotType(slot) == ITEM_SLOT_TYPE_MAIN   ⇒   0 == 1174   ⇒   FALSE
```

**在全语料每一帧上都是 FALSE**,闸后面的分支**构造性不可达**,**朝「关」静默失效**。
这是 GH #89 第十三号世界断言的**复发**,而 `test_fieldbuy_backpack_rescuer.lua` 已经在
**另一个站点**把它记下来过。

**⭐ 值得单独读一句**:变异台这次抓到的**不是一个错误的决策,是一个错误的声称** ——
文件里每一条测试都是绿的,而那句解释已经不成立了。

**修法也因此换了**:只补 **getter**(按 dump 真实的 0-5 主背包 / 6-8 副背包布局),
**三个常量故意不钉成 0/1/2** —— 把 MAIN 钉成 0,会让**每一个不是由 loader 造出来的单位**
默认答「主背包」,**把一次静默的 fail-closed 换成一次静默的 fail-OPEN**。
`[decision D3]` 因此断言三个常量**非 nil、互异、且非 0**。

### 三.2 fixture 的物品名**不是**引擎的物品名

dumper 写的是 `snakeFromClass(GetClassName(), "CDOTA_Item_")` —— **实体类名**;
`replay_fixture.lua` 一直给它加个 `item_` 前缀就当作 `FindItemSlot` 要的那个名字用。
两者**大多数时候恰好相同**(`power_treads`),**不同的那些则一声不响**:

| fixture 里的名字 | 引擎物品名 | 证据 |
|---|---|---|
| `dustof_appearance` | **`item_dust`** | `item_purchase_generic.lua` 拿这个名字买;仓库里 12 处 `modifier_item_dustofappearance` 佐证类名拼法 |
| `sentry_ward` | `item_ward_sentry`(bots/ 里 15 处) | 未加进映射表(**只登记**) |
| `empty_bottle` | `item_bottle`(69 处) | 同上 |
| `boots_of_elven` | `item_boots_of_elves`(5 处) | 同上 |

⇒ **凡是按名字查背包的谓词,在每一份 fixture 上都查不到东西,而测试读起来是干净通过。**
本轮**只加有仓库双向证据的那一条**(`CLASS_TO_ITEM`,**1 条**),
并把**未核验的天花板棘轮化**:**114 个 fixture 物品名里 23 个**在 `bots/` 里解析不到。
那 23 个**混着真分歧和「bot 代码本来就没提过的物品」**,所以它是**上界不是缺陷清单** ——
但它不许再悄悄变大。**补全那张表是中心件动作,球在总监。**

### 三.3 连带:一条设计得很好的棘轮当场响了

`tests/test_fieldbuy_backpack_rescuer.lua` 有一条 `[premise]` 断言**「mock 答不了
