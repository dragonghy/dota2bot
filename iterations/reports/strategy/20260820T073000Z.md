## 1. 缺陷:被提前 return 钉死的那个操作数

`aba_defend.GetDefendDesireHelper` 在函数上部写:

```lua
ds.nInRangeEnemy = jmz.GetLastSeenEnemiesNearLoc(bot:GetLocation(), 1600)   -- 1062
...
if #ds.nInRangeEnemy > 0 or ... then return BotModeDesire.VeryLow end       -- 1069
```

**紧接着的这一句就把它钉死了**:从 1069 往下的每一行,只在这张表**为空**时才会跑。
可是下面有三个消费方照读不误,当它是个会变的量:

| 行 | 写下来的比较 | 实际含义 |
|---|---|---|
| 1139 | `#ds.nInRangeEnemy > #ds.nInRangeAlly` | `0 > n` —— **恒假,整块死代码** |
| 1196 | `#ds.nInRangeEnemy >= #ds.nInRangeAlly` | `0 >= n` —— **「我身边有没有队友」**,不是「我是不是被人数压制」 |
| 1418(`DefendThink`) | `#ds.nInRangeAlly >= #ds.nInRangeEnemy` | `n >= 0` —— **恒真**,作者写的「被压制就别攻击移动进去」这条否决**近乎死掉** |

第四个消费方是**已经 gated 的 `defstale`**:它的 `#pathEnemies > #ds.nInRangeEnemy`
因此就是 **`#pathEnemies > 0`** —— 比写在它上面的「陈旧拷贝」论证**更强**(不是陈旧,是常数)。
**这条更正已经留在 GH #55**,对总监的 promote 判断直接有用:那条闸门的真实语义是
「**5 秒内挨过英雄打 + 1600 内有任何 last-seen 敌人 ⇒ 往泉水退一步并作废该帧其余所有 defend 分支**」。

本轮**只动 1196 一条**(一次一个小杠杆)。

### 1196 到底在做什么

```lua
if recentlyHit then
    nDefendDesire = nDefendDesire * 0.4
    if #ds.nInRangeEnemy >= #ds.nInRangeAlly and not ds.weAreStronger then
        nDefendDesire = math.min(nDefendDesire, BotActionDesire.Low)   -- 0.25
    end
end
```

写的是「敌我相当且我们不更强 ⇒ 压到 Low」。读出来是「**我 1600 内没有队友 ⇒ 压到 Low**」,
而且触发时**我 1600 内一个敌人都没有**(1069 保证的)。注意顺序:这个 `min` 排在
panic 地板(0.94/0.96)与 ping 地板(0.95)**之后**,所以它也是把那些地板抹掉的那一半
(backlog 第 0a 条记的顺序缺陷;0a 本身仍缺基地攻防语料,未动)。

## 4. 头号发现:第七条世界断言 —— 「两队三路的前线都在河道正中」

`tests/mock/replay_fixture.lua` **从来没有接过 `GetLaneFrontLocation`**,于是
`tests/mock/bot_api.lua:285` 的桩生效:**任何 team、任何 lane、任何 frontOffset 一律返回 (0,0,0)**。

实测(`f_260820_043120_viper_defend_poked`):

```
GetLaneFrontLocation(team, top/mid/bot, 0) = (0,0)
ds.defendLoc                               = (0,0)
ds.distanceToLane[top] = [mid] = [bot]     = 2040     <- viper 到原点的距离
真实的「viper 到自家上路一塔」                = 8084
```

- **`bots/` 里 125 个调用点**读这个函数(`mode_laning_generic`、`mode_farm_generic`、
  一堆英雄文件,还有带负 offset 的用法)。
- 在 `aba_defend` 内部它决定 `ds.defendLoc`,进而决定 `ds.distanceToLane[lane]` ——
  **三条路同一个数**,「我离这条路多远」**结构上分不出三条路**;
  而这个数就是 1102 的提前 return 与 1156 的 `dist > 4000` 衰减的判据,
  正是本候选下游那一层。

**故意没有伪造它。** 从录像重建一个前线不是「还原 ground truth」而是**建模**:
creep 流每 **3 秒**才采样一次、不带路别、不带存活位,`frontOffset` 参数更是无从还原。
前面几次 loader 修复(建筑 / last-seen / modifier / 挨打史)都是**从 replay 还原事实**,
这一条不是同一类东西。所以**上报,不动**,由总监决定要不要做、怎么做。已开 `[harness]` issue。

**它翻掉了什么(实测,不是推断)**:把桩挪到一个别的固定点,
**上一轮 `defclose` 的 3 条用例当场 FAIL**。这只证明那几条断言**对 lane front 的取值敏感**、
**不是桩无关的**,不证明真实取值会推翻它们;`defclose` 的**机制层**(`GetClosestAllyPos` 的
1-based 扫描)完全不受影响。已在 **GH #58** 如实留言。
