## 1. 主判据(可复用)

> **一个自带 `IsSoakCandidate` 的 helper 是一个合取项,不是一个谓词。**
> 把它从另一个 id 的门里调用,新杠杆就是**两个 id 的合取**;隔离波只 arm 外层 id,
> 于是**杠杆是 no-op,而每一层单独看都在按自己的声明工作**——没有任何断言会红,
> `check_armed_wiring.py` 判 WIRED,verdict 回来是「tested, no effect」。
> **这是 `pullcad` 一族,但吃亏的时刻从「promote 那天」提前到「调用落地那天」。**

**判别便宜**:**grep 被调用者的函数体**。本轮把它跑完了。

**安全的三种理由(全仓 45 条嵌套对逐条读完,此前一条都没写下来)**:

| 类 | 含义 | 例 |
|---|---|---|
| **(P) 参数门** | 未 armed 返回**出厂值**,不是杀掉调用方分支的常量 | `J.IsInLaningPhase`(`c2`/`c4` 只挪分钟阈值)、`J.SafeToCommitFight`(`depthnum` 只换更深的余量) |
| **(A) 只增不减** | armed 只能**多**返回一个 true / 抬高一个值 | `J.HasFieldRegenSource`(`bagsalve` 只多认背包一格) |
| **(I) 单位元** | 未 armed 是**第一行的字面量 `true`**,即所在 `and` 的单位元 | `J.IsFieldSipEnough`(`fieldsip`)—— 全仓唯一一处**有意**这么写的 |

⇒ **§CE.6 次序问题的一般形式**:**要么同腿 arm 被调用者的 id,要么让被调用者未 armed 的取值
是它所在合取式的单位元。** 两者都不满足时,那个 id 买不到读数。

**读数**:`bots/` 共 **1668** 个顶层函数,其中 **91** 个是 gated helper;
嵌套对 **45** 条;**live 违例 0 条**。当前 armed 集(44 个 id)里,
作为**内层**出现的有 `stayfield2` / `towerfear` / `fieldbuy` / `fieldcreep` / `tpreach` / `pulldrag`
六个,它们的外层此刻**也都 armed 或不 armed 到无所谓** ⇒ **W26 没有在为一个 no-op 付钱。**

它**钉的是集合不是判决**。理由写进文件头:自动判定 (P)/(A)/(I) 等于自动判定一个任意 Lua 函数

**故意过收(over-inclusive by construction)**:「嵌套」= 调用出现在调用方函数体内的任何位置,
不要求它落在外层门自己的分支里。`mode_roam_generic.lua` 的 `Think` 有好几个互不相干的门,
所以有些行**根本不是合取**。**这是 ratchet 该错的方向**:网宽一点漏不掉要紧的那一条,
一条假行的代价是读一遍;**按缩进决定作用域,等于用缩进去回答一个由算术回答的问题。**

**按内容锚定、不按位置**(`0ADDR` 的教训):行是 `(外层 ids | 调用方 | 被调用者 | 内层 ids | 调用方文件)`,
**没有任何行号**;`CTL A` 在 `jmz_func.lua` 最前面插 20 行纯漂移,census **一行不动**。

## 4. 本轮的两条自伤(都在同一工作单元内被抓住并修好)

### 4.1 ⚠️ 量具把两个独立站点池化成一行 —— 删掉其中一个,它还是绿的

`X._nopush_ShouldSuppressWaveShove` **在两个文件里各定义了一次**
(`hero_crystal_maiden.lua` 与 `hero_jakiro.lua`),**两侧 id 完全相同**。
第一版行 key 是 `(外层 ids | 调用方 | 被调用者 | 内层 ids)`——**不带文件** ⇒ 两条真实的嵌套对
**塌成一行**,**删掉任意一个调用点,census 照样绿**。

**抓住它的方式很便宜,而且是在钉任何东西之前**:把**带 key 的集合**和**不带 key 的集合**
各数一遍,**45 vs 44**。差 1 就是被池化掉的那一条。
⇒ **这是铁律 4(ii) 那条池化教训在源码普查上的同形**:**看起来正常的那个读法,正是把差别藏起来的那个。**
修法是把调用方文件放进 key(`bots/` 的路径由「永不改名」规则冻结,耦合零成本),
并补 **`C7`**:两个文件里同名的 caller/callee 必须读出**两行**。**`M8` 证明这条钉子承重。**

### 4.2 ⚠️ 一个控制用例让被它保护的代码变成不可证伪

`C2`(注释里的调用不算调用)第一版用的是**单行** `--[[ J.Inner( bot ) ]]`。
**单行长注释已经被逐行的 `--` 剥除干掉了** ⇒ **长注释那条 gsub 从落地起就没有任何东西能证伪它**:
`M3b`(删掉 gsub)**第一轮活了下来**。`bots/` 里有 **202 个**长注释块,其中 **3 个**已经含调用形状的文本,
所以这不是死代码,是**没被测到的活代码**。改成**多行**块注释后 `M3b` 立刻被抓。
**与 `0SIP` 自伤(甲)同族**:那次是「让常数不承重的空隙同时让它的边界测不出来」,
这次是「让控制用例通过的那条捷径同时让它保护的分支测不出来」。
⇒ **一个 CONTROL 如果走了和被测分支不同的路径,它证明的是那条路径,不是那个分支。**

## 5. 被仓库自己的检测器挡下一次 —— 而这次它是**假阳性**,修法是**收窄机制,不是放松模式**

新文件落地后 `tests/test_defend_ping_declaration_ratchet.lua`(GH #91)**打红**:
「这些测试驱动了一个挂在 defence-ping 戳上的出价,却没说它假设了哪一边」。

**它是假的**:那个检测器的 `drives_guarded_mode` 是**词元匹配**——源码里同时出现 `GetDesire`
和某个被守卫的 mode 文件名就算「驱动」。本组的 census **把这两样都当成数据行携带**
(`GetDesire | J.ShouldCoreKeepFarming | corefarm | bots/mode_farm_generic.lua`),
而它**一行代码都不执行**。

**两条现成的逃生门都不能诚实地用**:`LEGACY` 的语义是「本裁定之前就在驱动出价」;
而 `declares()` **只要源码里出现 `defendPings` 这个词就算**——写一句注释就能满足它,
**那正是 GH #300 已经付过钱的「注释冒充调用点」**。

**⭐ 主判据乙(可复用,本轮踩出来的)**:**要收窄一个过宽的检测器,先量一遍收窄会丢掉谁 ——
最显然的那个收窄往往是一次伪装成收紧的放松。**
这里显然的收窄是「要求 `GetDesire` 以**调用形式**出现」:**实测会丢掉 6 个 LEGACY 里的 4 个**
(它们都是间接调用),**即把 ratchet 放松了,而读起来像收紧了**。

**采用的收窄按机制而非模式**:**一个从不 `require` / `dofile` / `loadfile` / `loadstring` 的文件
够不着任何 mode 的 `GetDesire`,不管它的文本里有什么词元。**
**落地前实测**:该豁免**恰好**放过 census 形状的文件,**LEGACY 6 条一条都不放过**(6/6 仍 loads_code)。
并补一条 `[ratchet]`:**这条收窄不许赦免登记表里的任何人**(登记表是工作队列,不是赦免名单)。
**收窄自己的 battery:N1 / N2 / N3 三个变异 3/3 全抓。**

**两个数从来没有在量同一个东西。** 总监可以直接在这个基础上裁 §5.2,不必再花一轮去对数。
