## 1. ⭐⭐ 头条:三条子句都锚在 rune 上,而它们求值的那张表锚在 bot 身上

`bots/mode_rune_generic.lua` 的 `X.IsEnemyPickRune` —— 「这个 rune 会不会被敌人抢走」——
逐字如下(出货代码):

```lua
if GetUnitToLocationDistance(bot, vRuneLocation) < 600 then return false end

for _, enemy in pairs(nEnemyHeroes) do
    if J.IsValidHero(enemy)
    and not J.IsSuspiciousIllusion(enemy)
    and (enemy:IsFacingLocation(vRuneLocation, 30) or GetUnitToLocationDistance(enemy, vRuneLocation) < 600)
    and (GetUnitToLocationDistance(enemy, vRuneLocation) < GetUnitToLocationDistance(bot, vRuneLocation) + 300)
```

**三条子句每一条都以 `vRuneLocation` 为原点**,而 `nEnemyHeroes` 是 `GetDesire` 里的
`bot:GetNearbyHeroes(1600, true, BOT_MODE_NONE)` —— **以 bot 为原点**。

### 域是推出来的,不是感觉出来的

能满足这个合取的敌人必在 rune 的 `dist(bot,rune) + 300` 内 ⇒ **站在 rune 上**的敌人离 bot
恰好 `dist(bot,rune)`。配上守卫**自己**那条 `< 600 → return false` 早退:

> 这个守卫能看见一个蹲 rune 的人,**当且仅当 `600 < dist(bot,rune) ≤ 1600`** —— 一个 **1000u 的环带**。

而它守的 desire 缩放到 **3500u(赏金)** 与 `nProximityRadius * 2.5` = **4000u(强化)**。
⇒ **超过 1600u,`GetDesire` 自己那行注释点名的东西**

> `-- This prevents bots from walking into 5-man ambushes at rune spots.`

**按构造不可见**,而且**恰恰在路最长、最该避的时候不可见**。

### 语料定价(能买到的那一半)

112 个 fixture / **1039 活英雄帧**(与上一轮独立数到同一个 1039):

| 量 | 读数 |
|---|---|
| 活的跨队英雄**有序对** | 4840 |
| 其中相距 **>1600u** | **4034(83.3%)** |
| 主体帧中**所有**活敌人都在 1600u 外 | **521 / 1039(50.1%)** |

第二行的意思是:**一半的帧上,这个守卫的候选表在任何一条子句跑之前就是空的。**

⭐ **两个计数器都被第二次调用、腿对调**(0NEXT20 未):把环开到全图 ⇒ 盲对 **0**、空表帧 **0**;
把环关到 0 ⇒ 盲对 = 全部、空表帧 = 全部。空走的普查、解析不出名字的映射、谁也不放进来的环,
**给出的都是同一个「0」**,所以那个 0 必须从反方向再买一次。

## 2. 落地:gated `runecamp`(turbo-only),**只动一个 token**

```lua
local tRuneContest = nEnemyHeroes
if J.IsModeTurbo() and J.IsSoakCandidate('runecamp') then
    tRuneContest = J.GetEnemiesNearLoc(vRuneLocation,
        GetUnitToLocationDistance(bot, vRuneLocation) + 300)
end
```

- **半径不是新常数**(0NEXT20 寅:先问文件自己已经出货的答案)。`dist(bot,rune) + 300`
  **就是最后一条子句自己在测的那个界** ⇒ armed 的候选集**恰好是这个合取自己的域**,
  没有放宽任何一条子句,也没有让今天过不了的帧因为几何而过。
- **循环体逐字未动**(测试里把三条子句**逐字**钉住)。
- **不与任何别的 id 合取**(`pullcad` 陷阱;断言钉住,变异 M4 就是把它种进去)。

### ⭐ 不买雾,而且这是结构不是承诺

循环第一条子句是 `J.IsValidHero(enemy)` → `utils.IsValidUnit` → **`CanBeSeen()`**。
队伍看不见的候选,**不管它来自哪张表**都被这一条丢掉;`J.GetEnemiesNearLoc` 出门时再过一次
同一个 `J.IsValidHero`。变异 **M8**(把 `CanBeSeen()` 从 `IsValidUnit` 里拿掉)**被抓**——
这句话靠的就是那一条,别的什么都不靠。

### 声明的代价(写在正面)

1. `J.GetEnemiesNearLoc` 还会丢 **Meepo 分身**与 **Arc Warden 的 tempest double**,
   bot-centric 那张表不丢 ⇒ armed 时蹲在 rune 上的这两种东西**不再算抢 rune 的人**。
   (幻象那一半是 no-op:循环第二条子句本来就丢 `IsSuspiciousIllusion`。)
2. **单向**:armed 的候选集是「出货集合 ∩ 子句能接受的东西」的**超集** ⇒ 这个守卫
   **只会拒更多 rune,永远不会去抢一个它今天就拒的 rune**。
