## 1. 缺陷:同族的下一个站点,而且比 `cutoff` 强一档

`bots/FunLib/jmz_func.lua`,`J.ShouldTpSupportTowerFight`:

```lua

...

-- the nearest tower enemy.                       <- 这句是假的
```

「这波 collapse 打不打得赢」是关于**塔下那一群敌人**的问题,被问给了**名单里的一个成员**。

⭐⭐ **本站点值得单独一行的理由是结构性的。** 四根 `lvl*` 兄弟读的表都**继承一个距离序**,

```lua
function J.GetEnemiesNearLoc(vLoc, nRadius)
	local enemies = {}
	for _, enemyHero in pairs(GetUnitList(UNIT_LIST_ENEMY_HEROES)) do
		... 只按半径 / 幻象 / Meepo 分身 / tempest_double 过滤 ...
```

## 3. ⭐⭐ 为什么**没有**落地 —— 两条理由,都是量出来的

### 3.1 「照注释修成 nearest」在本语料上是**零行**,即一个装成修复的 no-op

42 个**响应形状**的站点(塔够远 + 有敌人 + 有个挨打的友军)上,四种读法:

| 读法 | 通过的站点 |
|---|---|
| `[1]`(出货) | **19** |
| 「存在某个成员」 | **19** |
| **「离塔最近的成员」** | **19** |
| 「每个成员」(全称) | **16** |

前三个**互相蕴含且计数相等 ⇒ 是同一个集合**。所以把注释那个词兑现成代码,**一行都不动**
—— 这种改动在报告里读起来像是发生了什么。**它没有。**

### 3.2 唯一动得了的那个读法,是**另一个问题**,而且它**捆绑了另外两个候选**

`J.SafeToCommitFight(bot, e)` **不是**一个「按敌人问」的谓词:它两个分支
(a) 「e 周围 1200 内的友军能不能把 e 秒掉」和 (b) `#allies near e >= #enemies near e`
**都锚在目标自己的位置上**,而且 **`bot` 这个参数它一次都没读**。
⇒ 换个成员问,是**换了一片邻域**,不是「同一个问题问对了」。

落地一轮之后,它把**两个文件**顶红:

- `tests/test_tparrive_collapse_gate.lua` —— `parity` 那帧(引擎点 **2v2**)本来是 `tparrive` 的
  **对照帧**(「already fine, unchanged」),全称把它的响应**撤掉了**;
- `tests/test_midsupyield_core_yields.lua` —— **NODROP** 那帧(「a response is never DROPPED」)
  的前提「midtp 单独能答出一个 front」不再成立。

⇒ 一个宣称「一次一个杠杆」的改动,**悄悄改写了另外两个未 promote 候选的含义**。
**那就是捆绑。** AGENTS.md 里 `lanefix` 这笔学费已经交过两次(gpm **−74.5**、**−88.7**,0/4)。

⭐ **本轮最该被下一轮读到的一句**:**方向干净不够**。谓词层和函数层的
`DIR_VIOLATION` / `add` **都是 0**,严格收紧、只撤不发 —— 而它仍然不该就这么落。
「只撤不发」保证的是**这个杠杆**不乱发 TP,**不保证**它没把别人的杠杆定义改掉。

⛔ **没有去改那两个兄弟文件的帧来让红变绿。** 那是「把红弄没」而不是「把问题弄清」,
而且那两帧不是本组写的。

## 4. ⚠️ 两个量具坑,都在读到任何数之前就踩了,都改了读数

### (1) 一个会**改状态**的合取项,让「先跑哪条腿」变成承重的

宿主的合取式**最后一项**是 `J.TryTakeTpResponseSlot()` —— 它**消耗队伍的 TP 响应名额**。
两条腿在**同一份已加载的 fixture** 上跑,第一条把名额吃掉,第二条读 0,
**而这个 0 跟杠杆没有任何关系**。第一次函数层测量因此报出
「armed 把语料能见证的**每一个**响应都撤了」—— **正是 lanefix 的形状**,
**如果它是真的,那就是放弃这个改动的正确理由**。它是**腿序的赝品**。
改成**每条腿各跑一整趟、每份 fixture 重新 `rf.load`**,并把
`shipped − withdraw == armed` **写成断言**而不是信任循环形状。

### (2) ⭐ loader 的队伍绑定**不跟随**被覆盖的 `GetTeam()`

`tests/mock/replay_fixture.lua` 在 **load 时**就把 `enemies` / `allies`(和建筑表)
闭包成**被加载 subject 那一方**的;**覆盖全局 `GetTeam()` 不会动它**。
`cutoff` 那份普查**不受影响**,只是因为它**手工**从 `UNIT_LIST_ALL` 重建名单;
**本文件调的是出货生产者**,于是就中招:拿对面队伍的英雄当 bot 驱动,
生产者把**他自己的队友**当「敌人」交回来。

⛔ **发现它的不是崩溃,也不是一个离谱的头条数字** —— 是 **§4c**(它的活儿就是「生产者健全性」)
报出 `SAME_TEAM = 6`。**一条为别的理由写下的断言把自己挣回来了。**
改正后行基数 **1306 → 653**,**本报告里每一个数都跟着变了**(旧读数一律作废)。
