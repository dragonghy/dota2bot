## 1. 那条缺陷本来长什么样(每一步都可查,每一步都是真的)

一次普通的 grep 报告:**三个列 0 的函数名同时定义在两个文件里**

| 名字 | base `bots/mode_laning_generic.lua` | override `bots/FunLib/override_generic/mode_laning_generic.lua` |
|---|---|---|
| `GetBestLastHitCreep` | :265 | :167 |
| `GetBestDenyCreep` | :287 | :188 |
| `GetFurthestEnemyAttackRange` | :251 | :214 |

而 base 在 **:30** `dofile` 了 override,**然后才**在 :251/:265/:287 定义自己那三个。
读成一个命名空间,这就是教科书式的覆盖:override 的 `Think`(:109)调 `GetBestLastHitCreep`,
拿到的会是 base 的那份 —— **而两份的合同不同**(base 返回 `(creep, bApproachOnly)` 两个值,
override 返回一个)。于是 override 的调用点会把 base 的「够不到、只能靠近」候选当成
「这一下能补掉」,对一只它打不死的兵按下攻击 = **推线**,正是标准对线里最经典的错误。

**推理链每一环都可核查,而且每一环都是真的 —— 除了前提。**

## 2. 前提错在哪:`game/botsinit.lua:15`

```lua
local newenv = setmetatable({}, {
    __index = function (t, k) local v = M[k]; if v == nil then return globaltbl[k] end; return v end,
    __newindex = M,
})
setfenv(2, newenv)
```

`BotsInit.CreateGeneric()` **重绑定调用方 chunk 的环境**,写入路由到模块表 `M`。
于是在这种文件里,**一个写得和全局一模一样的列 0 定义,落进的是该模块自己的表**。
override 文件第 7 行正是 `BotsInit.CreateGeneric()`。

**执行真实加载顺序实测**(不是读出来的,是跑出来的):
- `dofile(override)` 之后 `_G.GetBestLastHitCreep` **仍是 nil**;`X.GetBestLastHitCreep` 是函数;
- `dofile(base)` 之后 `_G.GetBestLastHitCreep` 才有值,且 **与 `X.GetBestLastHitCreep` 不是同一个对象**;
- 改写 `X` 的成员,`_G` 那份纹丝不动 ⇒ **两个命名空间从不相交**。

**发货代码自己就把这件事写反过来说过一遍**:base 在 :143 通过
`local_mode_laning_generic.GetBotTargetLane()` **走模块表**取 override 的成员 ——
因为那是它唯一存在的地方;全仓 **0 处**按裸名字调它。

## 3. ⭐ 主判据(可复用,超出本主题)

> **命名空间是运行期事实,不是语法事实。**
> `^function Name(` 只说明定义的**形状**,从不说明它写进哪张表 —— 只要树里有任何文件
> 能重绑定自己的环境。凡是把列 0 定义读成「写进同一个命名空间」的审计,量的是
> **这个程序并不具有的那个命名空间**;而且它**朝自信那一侧失效**:它会凭空造出
> 一对彼此永远看不见对方名字的文件之间的冲突,**两边都配着 file:line 证据**。

与本组此前四条同族区分清楚:GH #348 是**顺序**、#368 是**作用域**、#370 是
**未汇报的副作用**、#373 是**闩记错了后置条件** —— 那四条都是发货 Lua 里的缺陷。
**本条不是 bot 的缺陷,是"读这棵树"的缺陷:发货代码是对的,指控它的那次审计是错的。**
这正是它需要一条棘轮的原因 —— **有人重新推导出同一个假结论时,树里没有任何东西会红。**
