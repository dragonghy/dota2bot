## 2. 缺陷 1 —— 承重前提没人写下来(本轮的主产出)

三个 turbo 时钟膨胀站点,各自把 `adjustedTime` 存进**自己** cache 的 `currentTime` 字段:

| 文件 | 倍率 | 表 |
|---|---|---|
| `bots/FunLib/aba_defend.lua:239` | `* 1.65` | `defendGameStateCache`(file-local) |
| `bots/FunLib/global_cache.lua:207` | `* 2` | `globalGameStateCache`(file-local) |
| `bots/FunLib/aba_push.lua:58` | `* 2` | `gameStateCache`(file-local) |

accounting 块的结论(**`global_cache` 那份是全仓唯一活着的膨胀**)成立,**当且仅当三个 accessor
返回三张不同的表**。这条前提**一条断言都没有**。

而让它失效的那次编辑,是这三个函数**最可能挨的一刀**:它们的字段表几乎逐行相同,
「把三份 game-state cache 合并掉」是任何人看一眼都会想做的事。做完之后:

- 三条字面量 pin **照过**、`readers == 2` **照过**、`foreign == 0` **照过**、
  `getGlobalGameState()` 绑定 pin **照过**。

**变异实测**:**M2**(让 `updateGameStateCache()` 返回 `getGlobalGameState()` 的表)⇒
**旧块 0 failures**,只有本轮新加的同一性断言抓到。
**M8**(把三条同一性断言放松成恒真,再重放 M2)⇒ **SURVIVED,设计内** —— 那正是「这条线存在」的证明。

## 3. ⭐ 主判据(可复用)

> **一条「谁读谁」的判据,自己也有一个承重前提:被比较的那些 accessor 返回的是不同的对象。
> 判据升一级(文件同居 → accessor 绑定)不会把这个前提补上,而它失效的方向和原来那次一样危险
> —— 给活着的站点开脱、把死的定罪。凡是靠「这个值属于哪个写者」下结论的地方,
> 对象同一性必须是一条断言,不是一段散文;因为让它失效的那次重构(合并两张长得几乎一样的 cache),
> 恰恰是让每一条现有断言都保持绿色的那一种。**

与 GH #278 的判据 B 同族,**低一级**:B 说「绑定由 accessor 决定,不由同居决定」;
本条说「B 自己还剩一个前提 —— **那些 accessor 互不相同**」。

## 4. ⚠ 本轮方法自伤(M2 揪出来的,不是复查)

这个 driver 的**第一版自己踩了同一条判据**:它另起一次 `dofile('bots/FunLib/global_cache.lua')`
去拿 `getGlobalGameState` —— 那是**第二个模块实例**,带自己的 `globalGameStateCache` local。
于是三条同一性断言**恒真,但是因为错的理由**,而 **M2 从它们旁边走了过去**(第一次 M2 跑出
`33 tests, 0 failures`)。

修法就是判据本身:**accessor 必须从读者手里拿**。`aba_push:43` 把它绑成 file-local
(`local getGlobalGameState = ____global_cache.getGlobalGameState`)⇒ 它是 aba_push 各 export 的
**upvalue**,`debug.getupvalue(Push.GetPushDesireHelper, 'getGlobalGameState')` 拿到的才是
`GetPushDesireHelper` 真正读的那张表的 accessor。改完 M2 立刻被抓。

**这一条写在测试注释里,不是写在报告里就算了** —— 下一个写这类 driver 的人会犯同一个错。

## 5. 缺陷 2 —— `aba_defend` 的 `1.65`:从**沿用**换成**containment 重推**

上一轮的更正是靠量两个 aba_push 站点买到的;`aba_defend` 那一份是用**刚刚被证明会误判的
同一个全仓 `.currentTime` grep** 重新归类的 —— 结论对,拿的是手上**最弱**的证据。

更强的事实(一直在,从没被写出来):**`defendGameStateCache` 从不离开它自己的文件。**

- 全仓 `updateDefendGameStateCache` **6 处提及,全在 `aba_defend.lua`**
  (声明 + 定义 + **4 个调用点**),`elsewhere == 0`;
- **4 个调用点逐个**把返回值绑到一个普通 local(`local gameState = …`),没有任何 export 把表交出去;
- ⇒ 读者集合不是「整个仓库」,是**一个文件**,可以**穷举**而不是搜索。

穷举结果:该文件从自己 cache 上读**恰好 6 个字段** ——
`aliveAllyCount` / `enemyTeam` / `isLaningPhase` / `ourAncient` / `team` / `teamFountainTpPoint`
—— **`currentTime` 不在其中**。这条断言**转红的那天就是那个 `1.65` 活过来的那天**,而且它的
失败信息就是这么写的。

## 6. 缺陷 3 —— 那条 grep 的两个盲区

`grep '\.currentTime'` 是**点号语法**的搜索,看不见:

- `gameState["currentTime"]` —— **M7 实测:旧块全绿**,只有新断言抓到;
- 整表消费(`pairs(gameState)` 等)—— 名字级普查在它面前失去界。

两者当前全仓均为 **0**,现已断言。

## 7. 顺带登记(不是缺陷,是那个诱人重构的价钱)

三张表**互不为子集**:

- `aba_defend` 独家:`teamFountain` / `teamFountainTpPoint`(**它读其中一个**);
- `global_cache` 独家 6 个:`teamNetworth` / `enemyNetworth` / `averageLevel` / `hasAegis` /
  `aliveAllyCoreCount` / `aliveEnemyCoreCount`;
- `aba_push` 自己那份与 `global_cache` **字段逐项相同** ⇒ 它才是最可能被 dedupe 的那一个,
  同一性断言也就**先指着这一对**。

合并会在 `aba_defend` 今天读到值的地方发一个 **nil**。已断言(**M6** 抓)。

另:仓库同时跑**两套 turbo 时钟约定** —— `mode_laning_generic` 的 `1.65` 与 cache 家族的 `2`。
把一个决策在这两层之间挪动的人会继承一个**跑得不一样快的钟**。已登记为断言,不是散文。
