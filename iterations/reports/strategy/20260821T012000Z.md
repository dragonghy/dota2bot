## 4. 第三层结论:动作层**干净**

用 labelled synthetic 授予致命性(唯一不可判的那个 getter,已声明),在真实帧上驱**整张 mode 竞价 + Think**:

| | armed(`l1trade`) | shipped | 非 turbo + armed |
|---|---|---|---|
| `ShouldInitiateLaneKill` | **jakiro** | nil | nil |
| `team_roam GetDesire()` | **0.92** | **0** | **0** |
| Think 发出的指令 | **1 条:`Action_AttackUnit(jakiro, false)`** | **0 条** | **0 条** |

- **0.92 在真实帧上活着**:GH #31 的 `bLaneKillCommit` cap 豁免成立,没有被压回 0.72 悬崖(已断言)。
- **它赢下每一个可驱动的 mode**:唯一非零对手是 `mode_retreat_generic` **0.407**(已断言,数值钉住)。
- **没有 roamstale 那一族的病**:目标不是上一帧的小兵、`targetUnit` 没被 leash/`X.CanBeAttacked` 清掉、
  `IsHeroCore/IsSupport` 动作旗标在位。

⇒ **#77 §3.2 的「它就是在自己那条分支正在出价开打的帧上,什么都不打」不是
`mode_team_roam_generic` 消费路径产的。**

**说不了的那一半(如实登记,按 §0d 口径)**:shipped 侧 WK 的驱动者是 `mode_laning_generic`,
而它在**任何 fixture 上都加载不了**(GH #61,loader 拒绝 `GetLaneFrontLocation`)。
本轮把**跑不起来的 mode 逐个点名断言**(`mode_laning_generic` / `mode_defend_tower_*` /
`mode_push_tower_*` / `mode_rune_generic` / `mode_ward_generic`;`mode_attack_generic` 不定义
`GetDesire`),口径写死为「**在跑得起来的 mode 里**」。所以这一帧能说「沉默不来自这里」,
**说不了「沉默来自哪里」**。

## 5. 记账、不成 gate:候选循环取的是「第一个过门的」,不是「最好杀的」

`J.ShouldInitiateLaneKill` 的目标循环 `for _, hTarget in pairs(tEnemies)` **返回引擎列表里第一个
过门的候选**。这一帧它返回 **jakiro:门槛 399、满机动**;而同一份候选列表里躺着
**juggernaut:160 血(15%)、正被 WK 自己的 hellfire_blast 眩晕住(剩 2.4s)、539u**,
**门槛只要 jakiro 的 1/2.5**。标准打法是集火那个**已经要死的**(条件 (c) 可检索佐证)。

**为什么本轮不推 gate**:这个对比只在「**两个都过门**」的 burst 值上存在,而那个值**只在
labelled synthetic 下存在**(真实那一帧连 jakiro 一个都过不了,见 §3)。照一帧 + 一个合成数
调选靶顺序,正是 `lanefix` −74.5/−88.7 的入口。**沿用本组 `lfcorelane`(2026-08-20T15:30Z)那条
规矩:无 (a) 帧就不 armed。** 已写成 `[recorded]` 用例 + `state.json` 条目,等一份能答出
`GetEstimatedDamageToTarget` 的语料再动。
