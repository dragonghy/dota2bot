## 3. 改动本体

新函数 `TrySwapInvItemForFieldRegen()`(`bots/mode_team_roam_generic.lua`),
机制逐字复用出货的 flask 救援器:

```lua
if not J.IsSoakCandidate('bagtango') then return end
if not J.IsModeTurbo() then return end
```

- ⚠️ **turbo 在这里不是结构性的,所以显式问**。与 `jmz_func` 里那一族不同 ——
  那族的调用者全经过 `J.IsFieldRegenSituation`(首行 `IsModeTurbo`)—— 本函数经
  `ItemOpsDesire` 在**所有模式的每一帧**被调用,**没有 turbo 祖先可继承**。
  漏掉这一行就是在 turbo-only 章程下出货一个普通模式的行为改动。**M2 是这条腿。**
- **恰好一个 id、恰好一个调用点**;追加在 `TrySwapInvItemForFlask()` **之后**,不是插进去
  ⇒ 未 armed 时上面每一个调用逐字节不变。
- **自带节流戳** `SwappedFieldRegenTime`,不碰 `SwappedFlaskTime` —— 共用会让出货救援器的
  节奏取决于本 id armed 与否。
- ⛔ **不读 `J.HasFieldRegenSource`,不依赖 `bagsalve`/`staybag`**:那两个拓宽的是树
  **以为**自己带了什么(读),本条拓宽的是它**够得着**什么(行动)。共用 id 就是
  `staybag` 自己头注记载的那种「摊在调用路径上的 pullcad」。**M5 是这条腿。**
- ⛔ **瓶子故意不在名单里**:它的问题是**充能状态**不是格位,而 `staybottle` 已在读它的
  in-flight 修饰符。**M7 是这条腿。**

**方向由构造固定**:只能把一件消耗品从**用不了**的格子挪到**用得了**的格子;换出哪一件由
出货的 `GetMainInvLessValItemSlot` 决定,它本来就拒绝 `sCanNotSwitchItems` 上的每一件
(aegis / cheese / bloodstone / gem / moon shard / BKB / 莲花)。**加不了任何购买、施法、移动。**
**无抖动**:换进主格后 `GetItemSlotType(cSlot) == BACKPACK` 即为假,下一次轮询是 no-op。

## 5. ⚠️ 诚实边界:本条**不声称**是 #734 那 18.0% STUCK 的全部

证据方向明确相反:**#734 自己举的三个帧例全是 flask**,而 flask **已经有**救援器
⇒ 那个人群里有一部分**另有成因,尚未找到**。本轮登记两条**未验证**假设交下一棒,
两条都需要一次本站点做不到的语料读数,**本 id 都不认领**:

- **(H1) 那 18.0% 可能有一部分是检测器伪影,不是缺陷。** `FindItemSlot` 用**第一个命中**
  回答一个**存在**问句。一个 bot 主格有可用药、背包里**另有一瓶**时,按格扫描的检测器
  把背包那瓶读作 STUCK(「30s 内既没挪进 0-5 也没被喝掉」逐字成立),而这个 bot
  **完全正常**。⇒ 该读数若要支撑结论,需要按「**主格是否已有可用补给**」重新分层。
  已在 #734 追评里作为**对这个量本身的质疑**交回录像组。
- **(H2)** `ItemOpsDesire` 在掉落物竞价上**早退**,而那个 `return` 排在**全部六个**救援器
  调用**之上** ⇒ 地上有值钱掉落的帧会跳过**每一个**救援。

另一条已量到的边界:`GetItemCost` 离线答 0 ⇒ **换出哪一件主格物品不可测**
(`GetMainInvLessValItemSlot` 的比价退化成取第一个可换的)。只有「**存不存在**可换的
一件」这一项是真读数 —— 已钉成断言,免得有人把 `SWAP 6 <-> 0` 读成「它挑了最便宜的」。
