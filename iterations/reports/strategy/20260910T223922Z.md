## 1. 本轮的发现

`bots/mode_team_roam_generic.lua`,`X.SupportFindTarget` 的对线补刀/反补支路:

```lua
local nNearbyEnemyHeroes = J.GetNearbyHeroes(bot, 750, true, BOT_MODE_NONE)
if IsModeSuitHit and bot:GetLevel() <= 8
...
and (nNearbyEnemyHeroes[1] == nil or nNearbyEnemyHeroes[1]:GetLevel() < 10)
```

写在它旁边的**空表腿**(`[1] == nil`)本身就证明这个问句是**存在量化**的:作者已经
花了一整项去区分「这儿没人」和「这儿有个弱的」。表达式实际回答的却是
「**最近的那个**弱不弱」。

**代价**:这一项是一条返回 `BOT_MODE_DESIRE_ABSOLUTE * 0.97`(上前补刀/反补)
的支路的安全半边。当最近的是 5 级辅助、而 12 级劣单站在同一个 750 里时,守卫读成
「安全」,一个被上一项 `bot:GetLevel() <= 8` 限住的 bot 就在高它四级的英雄的击杀
距离内扑向兵线。

### ⭐ 为什么这**不是** `anyhero` 的第二个副本 —— 而这正是本轮最该带走的一条

上一轮 `anyhero` 的 argument 落在**顺序**上:`J.GetEnemiesNearLoc` 按 `GetUnitList`
迭代序 `table.insert`、全程无 sort ⇒ `[1]` 是集合里的**任意**成员。

**这里名单是有序的,而且有序是对的**:引擎明文承诺
(`docs/BOT_API_REFERENCE.md:1229`「All return tables sorted by distance (closest
first)」),`J.GetNearbyHeroes`(`jmz_func.lua:2856`)只过滤、不重排。
`[1]` **确实**是最近的可见敌方英雄 —— **而这个守卫仍然是错的**,因为被量化的谓词是
**等级**,最近的不是等级最高的。

⇒ 一次让引擎开始排序的改动会**修好 `anyhero`**,**碰不到这一条**。
两个 id 因此不同池、不同波,也不许被当成一个捆绑。

这条前提本身被钉成断言(§1b),M11 是它的变异证明:把 loader 的距离排序换成
按名字排序,§1b 立刻红并说出「64 行came back out of distance order …
**Re-argue, do not re-baseline**」。

## 3. 改动(gated,turbo-only,FROZEN-HOLD)

新 id **`lvlany`**。`bots/mode_team_roam_generic.lua` 新增

```lua
function X.NoNearbyEnemyAtLevel(tHeroes, nLevel)
	if tHeroes == nil or tHeroes[1] == nil then return true end
	if J.IsModeTurbo() and J.IsSoakCandidate('lvlany') then
		for i = 1, #tHeroes do
			if tHeroes[i]:GetLevel() >= nLevel then return false end
		end
		return true
	end
	return tHeroes[1]:GetLevel() < nLevel
end
```

调用点由那一整个合取项换成 `and X.NoNearbyEnemyAtLevel(nNearbyEnemyHeroes, 10)`,
**位置不变** ⇒ 短路顺序不变。

⭐ **写成 helper 而不是提前算一个 local,理由是可测的、不是风格**:提前算会在出货
代码根本到不了这一项的调用上求值 `GetLevel()`。**unarmed 一侧逐项就是出货表达式**,
而这一点由 §3b **在每一行被驱动的帧上测出来**,不是从 diff 上读的。

⛔ **FROZEN-HOLD**(OWNER_PRIORITIES P4.2):登记在 `state.json:lvlany_20260910`,
**不请求入集**,不搭任何捆绑的车。
