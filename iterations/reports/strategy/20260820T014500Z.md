## 1. 头号发现:又一条没人声明过的世界断言

上一轮(23:25Z)把 `modifier_teleporting` 补进 fixture 之后,`tpwatch` 只是**越过了第一行**。这轮真去跑它的判据,发现它卡在**第三行**:

```lua
function J.ShouldAbandonTpChannel( bot )
    if bot == nil or not bot:IsAlive() then return false end
    if not bot:HasModifier( 'modifier_teleporting' ) then ... end   -- 上一轮修的
    ...
    if not bot:WasRecentlyDamagedByAnyHero( 1.5 ) then return false end   -- ← 这一行
```

`tests/mock/bot_api.lua` 对未覆盖的 `Is*/Has*/Can*/**Was***` 一律答 `false`。于是**每一个 fixture 里、每一个单位、每一帧**:

```
WasRecentlyDamagedByAnyHero(任意区间) == false
WasRecentlyDamagedByHero / ByTower / ByCreep      == false
```

**`bots/` 下有 670 个调用点读这一族**(`WasRecentlyDamagedByAnyHero` 527、`ByHero` 115、`ByTower` 23、`ByCreep` 12、`ByPlayer` 1;`ability_item_usage_generic` 一个文件就 57 处)。这条断言的意思是「这里没有人最近被任何东西打过」—— 与 §F 记的 `GetTower`、`GetIncomingTrackingProjectiles`、以及上一轮的 `HasModifier` **同一类**。

**`observed.damage` 代替不了**:那一块是**向后看**(t 之后实际发生了什么,ground truth),而这一族读法是**向前看**(bot 在 t 已经知道的事)。方向相反。

### 1.1 修复

**生成器**(`tools/batch_test/replayscope/make_fixture.py`):新增 `--recent-window`(默认 **6.0s**,高于任何调用方要的最大区间 5.0),逐单位输出

```lua
recent_damage = { { dt = 0.5, kind = 'hero', actor = 'npc_dota_hero_lich', value = 5 },
                  { dt = 2.5, kind = 'tower', actor = nil, value = 45 }, ... },
```

四条**故意的、被测试钉死的**约定:

| 约定 | 为什么 |
|---|---|
| `dt` = t **之前**的秒数(正数),按升序 | 读法就是 `dt <= interval`,升序让它可以在第一条越界时 `break` |
| `kind` ∈ `hero/tower/creep/other` | 引擎区分的就是这四个读法 |
| **丢掉自伤** | 这一族读法回答的是「有没有人在打我」;armlet/blade-mail 式自伤会让每一条这样的 guard 因为错的理由变 true |
| hero actor 存**快照名** | 事件流里部分英雄不带下划线(`queenofpain` vs `queen_of_pain`),不 canon 化会**静默丢掉**这些英雄的命中(录像组已知工具坑),而 `WasRecentlyDamagedByHero` 比的是句柄 |

顶层多一个 `recent_window`:**查询区间比它长就答不真**,loader 会夹到窗口而不是静默少报。

**loader**(`tests/mock/replay_fixture.lua`):**只有** `recent_damage` 存在时才安装那四个读法。没有该字段的老 fixture **一行不动**(mock 默认 false 仍然成立,而且是**因为对的理由** —— 没有记录 = 没有命中),回归护栏钉住。

## 3. 缺陷:出价送到了,赢了,然后什么都没发生

`J.ShouldAbandonTpChannel` 只有一个消费方:`mode_retreat_generic.lua:261` → `BOT_MODE_DESIRE_VERYHIGH`(0.9)。注释写的因果链是「retreat 出价赢下来 → 移动指令打断读条」。这要两件事同时成立:

1. 0.9 要赢过 retreat 本来会出的价,**而那个价要输给别的 mode** —— 只有**换 mode** 才会让引擎重新下令;
2. 得有人真下那条移动令 —— `mode_retreat_generic` **只有 `GetDesire()`,没有 `Think()`**(07:17Z 那轮为 `l1xpsoak` 查明的同一事实),移动全在引擎内置实现里,也就是要靠第 1 条发生。

在这一帧上**两条都不成立**。重建当帧**全部 22 个 mode 文件**的出价:

| mode | shipped | armed(`tpwatch`) |
|---|---|---|
| **`mode_retreat_generic`** | **0.75** | **0.9** |
| `mode_laning_generic` | 0.446 | 0.446 |
| `mode_defend_tower_{top,mid,bot}` | 0.1 | 0.1 |
| `mode_push_tower_{top,mid,bot}` | 0.05 | 0.05 |
| 其余(assemble/farm/outpost/roam/roshan/rune/side_shop/team_roam/secret_shop) | 0 | 0 |
| `mode_ward_generic` | `false`(不是数,记录而不强转) | 同 |
| `mode_attack_generic` / `_wip` | 对本英雄**不定义脚本 `GetDesire`** | 同 |

那个 shipped 的 **0.75 是已 promote 的反越塔 guard**,在同一条 guard 链里就在 `tpwatch` **下面六行**。所以 armed 只是把 **0.75 抬到 0.9,重新选举了当选者**。没有 mode 变化 ⇒ 引擎没有理由重新下令 ⇒ 读条不会被打断。

这是总监 §0b 家族的**出价类**变体,**亚型是新的**:此前的四例(#29/#31/#32/#35)都是「出价被下游改掉/够不到」,`ownhalf` 那例是「出价干净、动作全丢」;**这一例是出价完好、赢下竞价、而且什么都没改变,因为它抬的是已经在跑的那个 mode**。

**如实标注的两条局限**:(i) `.dem` 不带每帧 mode(同 GH #27),这个重建覆盖的是**脚本出价**,引擎自带 mode(attack 等)的出价拿不到 —— 测试里显式断言并说明;(ii)「shipped 侧引擎到底会不会打断读条」不是 fixture 能证的,它由第 4 节的观测独立佐证。

## 4. 判据本身也是滞后的(11 局的总体)

按**事件流**(不是 1Hz 快照)重算 11 局里所有满足 `tpwatch` 伤害阈值的读条,共 **8 次**:

| 英雄 | 读条 | 判据首次成立 | **落地前还剩** | 结局 |
|---|---|---|---|---|
| juggernaut | 437.0→440.0 | 438.8 | **1.2s** | 落地,活 103.5s |
| dragon_knight | 255.3→260.3 | 259.3 | **1.0s** | 落地,活 |
| sniper | 513.2→516.2 | 515.3 | **0.9s** | 落地,0.1s 后死 |
| centaur | 343.0→345.4 | 344.9 | **0.5s** | 死在读条里 |
| lina | 649.2→649.8 | 649.8 | **0.0s** | 死 |
| shadow_shaman | 159.5→161.7 | 161.7 | **0.0s** | 死 |
| crystal_maiden | 417.6→421.3 | 421.3 | **0.0s** | 落地,活 |
| witch_doctor | 510.2→511.7 | **从未成立** | — | 死 |

**最早也只有 1.2 秒**,中位 ~0.5s,3/8 只在死/落地那一瞬成立。原因是机械的:「已经掉了 30% 最大血」要靠一次爆发才跨得过去,而能跨过去的爆发在 3.0s 的读条里必然落在后段。**就算第 3 节的接缝通了**,在剩 0.5–1.2s 时放弃读条 = 把一个 27% 血的英雄**留在敌方半场**,而不是送他回家。

**候选侧的观测独立印证第 3 节**:armed 侧 4 次被吃的读条里,有真实窗口的 2 次(jugg 1.2s、sniper 0.9s)**全部跑完了**,第 3 次(CM)只在末帧成立、没有窗口。没有一次被放弃。
