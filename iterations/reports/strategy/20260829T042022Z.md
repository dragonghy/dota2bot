## 2. ⭐ 主判据(可复用)

> **一个守卫的「域」不是它自己谓词的域,而是那个域与它被放进去的那条合取式其余部分的交。
> 当分支自己的阈值恰好压在守卫自己的下限上方一个百分点时,守卫在这个站点上几乎是空操作 ——
> 而它在自己的源码里、在调用点的注释里,都读起来像是那条腿的机制。
> 失效方向是最贵的那一侧:不报错、不掉测试、不丢 promote 判词,只是让这条腿继续被记成
> 「有守卫」,于是没人去找这条腿上真正缺的那个 id。**

**这不是假想**:`stayfield` 后来是为 `撤退:3` 开的,理由写在源码里——
「unlike 撤退:1 above it carries no regen veto at all」。**`撤退:1` 因为「有一个」而被跳过**,
而那一个在它自己的分支上只够得着 1pp。

**第二条约减,而且是更尖的那半**(这条以前没人写下来):在守卫**能改变结局**的那批帧上,
分支其余合取全部为真,而其中三条**逐条否定了守卫内部那个析取的每一支**:

| 守卫 `bHasFlask` 的三支 | 分支里对应的合取 |
|---|---|
| `J.IsItemAvailable( 'item_flask' ) ~= nil` | `itemFlask == nil`(**同一个访问器、同一个参数、同一帧**,`:5228` 绑定) |
| `bot:HasModifier( 'modifier_flask_healing' )` | `not bot:HasModifier( "modifier_flask_healing" )` |
| `bot:HasModifier( 'modifier_tango_heal' )` | `not bot:HasModifier( "modifier_tango_heal" )` |

⇒ 在这个站点上 `bHasFlask` **恒为假**,守卫最后一行 `if not bHasFlask and bot:GetGold() < 90`
**退化成 `bot:GetGold() >= 90`**。
**单读守卫的源码看到的是「身上有回复品 **或** 买得起」;在调用点上它只剩「买得起」。**
这个退化在守卫自己的文件里读不出来,只在调用点读得出来。

## 3. 算术(两个常数之间,不是采样)

```
守卫 (jmz_func.lua J.ShouldStayAndRegen)   : if nHP < 0.18 or nHP > 0.75 then return false end
TP 腿 (ability_item_usage_generic '撤退:1'): if botHP < 0.19 and not J.ShouldStayAndRegen( bot ) ...
走路腿 (mode_retreat_generic GetDesire)    : if J.ShouldStayAndRegen(bot) then  -- 上面没有任何 HP 上限
```

- 守卫自己的带宽 **0.57**;
- 它在 TP 腿上的**反事实域** = `[0.18, 0.19)`,带宽 **0.01** ⇒ **57 倍**;
- 走路腿:从 `botHP = J.GetHP(bot)` 到调用点之间**只有一处 `botHP` 比较**,
  而那一处与 `DotaTime() < 0` 同行(开局前),**在正常对局里够不着** ⇒ 整条带 live。
- 反事实域还要再叠两条:`gold >= 90`(§2 的退化),以及**上一次英雄伤害落在 (3, 8] 秒**
  ——守卫要 `not WasRecentlyDamagedByAnyHero(3.0)`,分支要
  `WasRecentlyDamagedByAnyHero(8.0) or botHP < 0.12`,而 `botHP < 0.12` 在 `[0.18,0.19)` 里不可能。

**归属结论(本轮唯一的对外主张)**:GH #2 给 `tphome` 买到的 promote 判词
(**+51 GPM / +54 XPM / −0.32 deaths,28 局**)**不可能是在 TP 腿上买到的** ——
那条腿最多能挪动一条 1pp 的 HP 缝。**那份效应属于走路腿。**
这是**归属修正,不是正确性质疑**:没有任何读数说这个守卫本身错了。
