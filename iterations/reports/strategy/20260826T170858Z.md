## 2. 缺陷

`bots/ability_item_usage_generic.lua` 买活三段阶梯里,rung 1 与 rung 2/3 之间那道早退:

```lua
if nFullRespawnTime < 60 then
    return
end
```

**60 是普通模式的时长** —— 这是**同一段阶梯里第三个**没有随模式缩放的秒数常量
(前两个:GH #208 的双减、GH #215 的 80)。

### 这条发现不依赖 getter 怎么读 —— 这是它最强的地方

`60` 是**复活秒数**,而 turbo 把**每一个**复活时长乘 `J.TURBO_RESPAWN_FACTOR = 0.75`。

**读法 A(local 名字自称的「完整时长」,意图 =「复活太短不值得买活」)**:把 60 留在 0.75 的世界里,
它选中的英雄集合**严格小于**它被写出来时要选的那个。

**读法 B(有据可查的 remaining 语义,`docs/BOT_API_REFERENCE.md:992`,GH #208)**:

* remaining ≤ R ≤ **75**(= 复活表最大值 100 × 0.75)⇒ 下面两级只在 remaining ∈ [60, 75] 可达
  = **一次死亡最初的 R − 60 ≤ 15 秒**;
* 且**凡 turbo 复活时长 R < 60 的英雄,门在 elapsed 0 就已经为真** ⇒ 下面两级**整场死亡全关**。
  turbo R < 60 ⟺ 普通 R < 80,**是复活表的大部分**。

## 3. 修法

gated **`bbshort`**(turbo-only,`state.json: bbshort_20260826`):

```lua
J.BUYBACK_SHORT_FLOOR  = 60

function J.BuybackShortRespawnFloor()
	if J.IsModeTurbo() and J.IsSoakCandidate( 'bbshort' ) then
		return J.BUYBACK_SHORT_FLOOR * J.TURBO_RESPAWN_FACTOR
	end
	return J.BUYBACK_SHORT_FLOOR
end
```

未 armed **逐字返回出厂的 60**;armed 返回 **45**,而且是**算出来的** —— `[source]` 断言函数体里
不许出现字面量 `45`。复用 `bbfight` 已具名的 `J.TURBO_RESPAWN_FACTOR`,不新造系数。

**GH #207 预检主动做过**:单合取,另一半是 `J.IsModeTurbo()` 模式谓词,**不与 `bbfight` / `bbrespawn` 合取**
⇒ 不属于 `pullcad` 族。armed 的域是在**两个邻居都是出厂读法**上取到的(rung 2 仍是结构性零、rung 3 仍读
R − 2e)⇒ **单独 arm 就打得响**;另有一条**单调性**用例:`bbrespawn` 也 armed 时窗口只会变宽。

**方向单向**:只降一个「挡住买活」的下限 ⇒ 只可能打开一级、永远不可能关掉一级(穷举断言),
并额外钉住它**不许**动上面 rung 1 的 `> 20` 与下面 rung 3 的 `< 40`。
依据 (c):rung 3 的世界条件是「遗迹旁敌人数 ≥ 我方存活英雄数」= **买活的教科书用途**,
而 turbo 买活金更便宜、CD 更短,标准打法只会更宽松。

## 5. ⚠ 判据(本轮主产出):两个互相独立的原因会关掉这条阶梯上的格子,只有一个是这道门的

  把它们算到本杠杆头上,就是 GH #215 判据二那条错误换了一对原因。

  所以控制项**不能靠「把一切都关掉」蒙混过关**(一条只会说「都关着」的控制项证明不了任何归因)。

## 6. ⚠ 第二条判据(方法,非本组独有):并行跑测试会制造假红,因为 gate 文件是全局的

上一轮的门是「受影响面 101 个文件**分 6 段并行**跑完 1131 pass / 2 fail」。本轮照做,读到
`test_bbrespawn_double_subtract` **3 failures**;**顺序重跑同一文件 = 16 tests 0 failures**。

原因是结构性的:这些 gated-fix 测试用**同一个物理文件** `bots/Customize/soak_side.lua` 当 arm 开关,
`load_with()` 写它、`armed()` 删它。**两个进程同时跑就是在同一个开关上打架**,
而失败方向是**假红**(读到别人的 cand 串)。上一轮那 2 条 fail 恰好等于两条已知 trunk 红,
所以**结论没错,但方法能凭空造红**——下一个照抄这条门的人不一定这么走运。

**本轮改成顺序跑**(慢,但读数可信)。这条不落成代码改动(不归本组),记在这里并写进章程 backlog,
供总监决定是否要一条「gate 文件是并行不安全资源」的门。
