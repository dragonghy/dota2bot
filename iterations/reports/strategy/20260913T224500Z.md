## 1. 落地的杠杆:`dusttower`

### 1.1 缺陷

`bots/ability_item_usage_generic.lua`,`X.ConsiderItemDesire['item_dust']` 的第五条分支(B5,「敌人即将隐身」):

```lua
local nEnemyTowers = enemyHero:GetNearbyTowers(700, true)
if nEnemyTowers == nil or #nEnemyTowers == 0
then
    return BOT_ACTION_DESIRE_HIGH, bot, 'none', nil
end
```

`GetNearbyTowers(nRadius, bEnemies)` 的 `bEnemies` **相对被调用的那个单位**。这不是推测:
`tests/mock/replay_fixture.lua` 按 dump 真值把它复原成 `h:GetTeam() ~= self:GetTeam()`,
出货侧的读者也都这么用。⇒ 在**敌方句柄**上问 `true`,拿到的是「与该敌人敌对的塔」= **我方自己的塔**,
而变量名写的是 `nEnemyTowers`。

两个方向都反:

| 局面 | 出货护栏 | 应该 |
|---|---|---|
| 敌人在**我方塔**旁隐身 | **拦住**(我方塔 ≠ 空) | 放行 —— 尘让我方塔能打他,这是最该扔的一刻 |
| 敌人在**自家塔**下隐身 | **放行**(我方塔为空) | 拦住 —— 这就是 700u 冲塔环的本意 |

条件 (c)(逻辑/标准打法依据):「不为一次击杀冲防守方的塔」是标准打法;
「敌人在我方塔下隐身时**不要**扔尘」**没有任何依据** —— 塔打不到隐身单位,尘正是解药。

**同族登记**:与 `slotdust`(GH #441)/ `slotarb`(GH #406)**同一个失效形状、而且在同一个函数里**——
一个**意义相对于接收者**的实参,被当成绝对量传。不报错、不打日志,变量名记录的是代码没有的意图。
