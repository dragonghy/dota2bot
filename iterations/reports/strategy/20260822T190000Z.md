## 1. 缺陷(录像组的三帧 + 本仓库的独立复现)

## 2. 修法(一条子句,追加,gated)

```lua
if J.IsSoakCandidate( 'fieldcreep' )
and bot:WasRecentlyDamagedByCreep( 3.0 )
then
    return false
end
```

三条设计决定,都写进了源码注释:

1. **回看窗沿用英雄子句的 3.0,不是新调的常数。** 这条子句是那条子句缺的另一半;
   `[reverse]` 钉子断言两个字面量相等,**一旦有人调其中一个就转红**。
2. **不需要自己的距离判据。** 小兵/野怪的攻击距离只有几百码 ⇒「三秒内一只小兵打了我」
   本身就携带了英雄那条子句要用 3000u 扫描去重建的归因,**归因强度更高不是更低**。
3. **追加在塔子句之后是刻意的。** 当初把这个函数拆出来时,行为保持的论证写的是
   「下面的子句顺序未变」;**只有追加能让那句话继续为真**。

**刻意没动**:`0.18/0.55` 血量带、1600 环、3000 归因半径、1200 塔环、
`J.HasFieldRegenSource` 的四种回复品。

## 3. 条件 (c):用同一个单位说完,并自带过宽角

回看窗是三秒,所以两边都换算成**三秒内的血量**:

| 三秒内 | 数值 |
|---|---|
| tango(大药) | 21 |
| faerie_fire | 85(一次性,之后为 0) |
| flask(治疗药膏) | ~92 |
| bottle | ~135 |
| **被否那五帧实挨的小兵/野怪伤害** | **14 / 22 / 109 / 129 / 132** |

⇒ tango 五帧全输;仙灵之火和药膏在重的三帧上输。

**分界跟着「谁在打」走**:本语料存活英雄帧上的 282 条 creep 伤害行,
**256 条 ≤24、26 条落在 25–45 的尾巴上**(最大 45)。重的三帧正是那条尾巴
(lion 挨 36–37 一下、viper 挨 43–45),= **营地接触**;轻的两帧是 9–14 的线兵。
**写成「重尾」而不是「双峰」**:直方图不支持双峰(众数在 10–14,中间带 15–24 有 64 条)——
这是本轮对自己第一版措辞的一次订正。

**不是「大药被打断」在起作用**:药膏和 tango **扛得住小兵伤害**(被打断的是敌方英雄伤害),
这恰恰是上游从来没人察觉这个洞的原因。

**自带的过宽角(记下来,不在这里凭空调)**:药膏 vs **单个线兵**那一格,留下来其实是赢的。
要让子句读伤害量级得有野怪/小兵**单位表**,而 fixture 结构上不带 ⇒
**记为下一个杠杆**,不是本轮的第二个变量。

### ⚠️ 另一条把本轮拖长的机制(交总监,值得写进 README)

**这个远程容器在两次工具调用之间会挂起**,所以**后台跑的全套在我等待时几乎不前进** ——
实测 `ps -o etimes` 在 11 分钟墙钟里只涨了 **28 秒**。
第一次全套「卡在 1233 个点不动」看起来像死循环,其实是**容器在睡**。
**做法**:全套要用**前台**的 `Bash` 调用(每次最多 10 分钟)分段等,
`while kill -0 <pid>; do sleep 5; done` 这样一轮一轮推,而不是 `run_in_background` 之后干等。
**顺带一个自伤的小坑**:守候用的 `pgrep -f run_tests.lua` **匹配到守候进程自己的命令行**
⇒ 那个 `until` 循环永远不会退出。**谓词自匹配**,与上一轮那条 pkill 教训同族;
换成 `kill -0 <pid>` 才对。
