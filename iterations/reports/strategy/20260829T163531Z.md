## 0. 一句话

**一个钉子的全部作用是「那份文件的裁定一变就红」;它却把地址写成了那份文件刚刚亲手宣布为不承重的那个坐标(行号)。
于是那份文件加固自己、把 22 个 `line = NNNN` 字段整个删掉的那一刻,钉子不是精度下降,是**永久红**——
而它打印的失败文本是「the census row for this site moved」,**行根本没搬,搬的是寻址方式**。**

失效方向最贵:**红是真的,但它点名要你去改的东西是对的那个**;读者照着失败文本去找「搬走的行」,
找不到,于是把这条归进「又一条语料漂移」,**而它不是**。

## 3. 根因:改址,不是搬行

失败的是 `tests/test_gamemode_world_assertion.lua:1450`
(`[recorded] what a census reading owes the call chain above it`)。
它是一个**跨文件的钉子**:把 `tests/test_level_gate_census.lua` 当**文本**读,
定位「item_purchase_generic 那一行 level gate」的普查行,断言它仍判 `TEETH`。

它的地址是:

```lua
census:find("{ file = 'bots/item_purchase_generic.lua', line = 228, op = '>=', n = 18", 1, true)
```

而 **`87c69bdc`(总监 2026-08-29T07:13Z,GH #221 甲案)把 22 个 `line = NNNN` 字段整个删掉了**,
理由写在被钉那份文件自己的头注里:

> `THE KEY IS THE TEXT, NOT THE LINE (director 2026-08-29, GH #221 option 甲)`
> …… TEN re-anchorings, every one of them resolved by moving the number with
> file/op/n/eff/text/verdict untouched, and not one of them a classification that had actually drifted.

**那次修复是对的,而且它把 census 自己的断言全扫了一遍。它没扫的是「别的文件里按旧 key 引用 census 的钉子」。**
本仓这样的钉子至少这一个,它在 07:13Z 变红,**红了约 9.4 小时**。

### 为什么没人看见

两层叠加:

1. **`test_gamemode_world_assertion.lua` 不带 `[ratchet]`/`[detector]` 标签**,
   而开工自检的快 Lua 腿只跑带标签的那 24 个 ⇒ 每轮都跑的那道门对它**结构性失明**(这正是 #302 §3)。
2. **失败文本把读者指向错的方向**:「the census row for this site moved」。行没搬。
   读者去找搬走的行,找不到,于是归进「语料漂移」那一包。
   **这与本组 2 小时前立的 GH #307 同族**(*「它的失败文本要求你去改那行正确的字」*)——
   两条都是**断言的失败信息描述的是它的代理量,不是它要护的性质**。

## 4. 修法:按被钉那份文件**自己的新 key** 寻址

`tests/test_gamemode_world_assertion.lua` 一处重锚(**纯测试文件,`bots/`/`game/` 零 diff**)。
census 的新 key 是 **(file, 去空白源文本)**,所以钉子也钉这两样:

- 锚 `ROW = "{ file = 'bots/item_purchase_generic.lua', op = '>=', n = 18, eff = 18"`,
  **`gsub` 计数断言 `hits == 1`**(不是 `find` ⇒ 匹配多处的锚**不能**只是「找得到」就算数,M15 那一族);
- 行内断言 `text = 'if bot:GetLevel() >= 18',` —— **末尾那个 `',` 承重**:
  `mode_farm_generic` 那一行的 text 把这一条当作**严格前缀**(全文件该前缀出现 **3** 次,带 `',` 只 **1** 次);
- 行内断言 **`not row:find('line = ')`** —— 钉住「不许把行号 key 拿回来」这条 #221 的裁定本身;
- 行内断言 `verdict = 'TEETH'`(原意保留);
- 头注写明**不要靠加回行号来修这条**。

另修一处真缺陷:原代码 `census:find('{ file = ', at, true)` 的起点是 `at` 本身,
新锚以 `{ file = ` 开头 ⇒ 会**当场匹配到自己**、把 row 截成空串,三条行内断言一起变成空断言。
改为 `at + 1`。**这个坑是重锚引入的,不是原有的**(原锚以 `line = ` 开头,不自匹配)。

### ⭐ 主判据(方法,可复用 —— 而且直接约束 §5.2 的裁定)

> **有一族测试是靠写一个共享的全局路径来 arm 的**
> (`bots/Customize/soak_side.lua`:写 → 跑 → `os.remove`,208 个未标签文件里 **25 个**这么做)。
> **它们之间不是并行安全的** —— 两个进程同时进出同一个文件,彼此把对方的 arm 状态删掉。
> 于是**任何「把套件 fan out 跑快一点」的做法都会凭空造出红**;而**假红与真红对读者完全不可区分**
> (失败文本是正常的断言失败文本,不是 IO 错误),**并且假红的条数随并行度变化** ——
> 同一棵树,`-P 8` 读 9 条红,`-P 1` 读 0 条。

**这条直接给 GH #302 §5.2 的裁定加了一个约束**:把快腿从 opt-in(`[ratchet]`)翻成 opt-out(默认全跑)
**不能靠并行来买回时间**。要么先把这 25 个文件的 arm 路径改成进程私有(临时目录 / 环境变量),
要么全跑必须串行。**本组不自行扩面,只把这个约束交出去。**

> 「现在 229 个 `test_*.lua` 里,有多少个不带 `[ratchet]`,其中多少个此刻是红的?」

**208 个不带标签;其中此刻真红的是 1 个 —— 就是本轮修掉的这一个。**

## 6. ⚠️ 一条会让人读错的量具(本轮踩到并当场更正)

第一次分文件复现时,`test_gamemode_world_assertion.lua` **单独跑输出为空**、
和别的文件一起跑才报红,本组一度写成「**顺序依赖**」(GH #301 那一族)。**这是错读,当轮更正:**

> **测试 mock 把全局 `print` 桩成了 no-op。** 任何在 `dofile` 一个测试文件**之后**用 `print` 汇报的
> 临时诊断脚本**什么都不会打印**,而「**没有输出**」在读者眼里就是「**没有失败**」。
> #302 §1 的复现片段用的是 `io.write`(所以它是对的);**任何人顺手把它改成 `print` 就会得到一片安静的绿。**

改用 `io.stderr:write` 后,该文件**单独跑同样红**,**不是顺序依赖**。
登记为可复用判别:**在被测代码可能桩掉 IO 的进程里,诊断输出一律走 `io.stderr:write`。**
