## 3. ⭐⭐ 头条:`aba_defend` 的 base-threat 续期

`bots/FunLib/aba_defend.lua`,`____exports.GetDefendDesireHelper` 里的基地威胁粘滞位:

```lua
if heroesNearAncient >= 1 then  baseThreatUntil = DotaTime() + BASE_THREAT_HOLD   -- 英雄臂,+4
elseif isBaseThreatActive then
    local creepWeight = WeightedEnemiesAroundLocation(ancient, BASE_THREAT_RADIUS)
    if creepWeight >= 2 then    baseThreatUntil = DotaTime() + 1.5 end            -- 小兵续期
```

TS 源码在它**上面一行**用自己的话写着策略:`heroes start, creeps can only extend`。**两半都不成立。**

**HALF 1 —— 它看不见小兵。** 这就是 `threatcreep` 上一轮登记的 **WALL 1(表)**:
`WeightedEnemiesAroundLocation` 按 `unitState.enemyHeroes` 定价,而那一格是
`GetUnitList(UnitType.Enemies)` **已被 `IsValidHero` 过滤**过的 ⇒ 它自己的
`siege` / `upgraded` / `warlock_golem` / `IsCreep()` 台阶**结构上不可达**,一只小兵从来没有被定过价。

**⛔ 为什么上一轮没看见它 —— 这正是 0NEXT35 那句话的现场。**
`threatcreep` 量过**这个调用点**,并判它是 *provable no-op*。**那句话是对的**,而且**只**是关于
**WALL 2(取整)**的:`math.floor(x) >= 2` 当且仅当 `x >= 2`,对任意实数成立,
`tests/test_threatcreep_lane_tiebreak.lua` 今天仍在驱动它(那条 [arith] 断言**逐字未动且仍绿**)。
**它对 WALL 1 一个字都没说。** 而 WALL 1 在这里不是 no-op。
⇒ **被修好的那一个消费者,恰恰是把剩下的那个从视野里赶走的东西。**

**HALF 2 —— 它真开火的那几帧是在砍短。** 闭式:这条 `elseif` 只在 `heroesNearAncient == 0` 时进,
而 `CountEnemyHeroesNear`(`utils.lua:1077`)数的正是那个和里**唯一可达台阶**所用的英雄集合
⇒ 出厂 `creepWeight` 在这条线跑到的**每一帧都是 0**,例外只有
`now - c.t <= CACHE_ENEMY_AROUND_LOC_HZ`(**0.35s**)那条缓存。
而缓存命中**恰恰意味着**上面那条英雄臂 0.35s 内刚跑过、留下 `+BASE_THREAT_HOLD`(= **+4**)待办;
**这里的赋值是 `=` 不是 max** ⇒ 把 +4 换成 **+1.5**,**把 hold 砍短 2.4 秒**。
⇒ **出厂这条分支只会做两件事:什么都不做,或者做它用途的反面。**

下游不是装饰:`isBaseThreatActive` 把 `ds.defendLoc` 钉在遗迹上,并走
`if lane ~= threatenedLane then return VeryLow end` —— 续期掉了,**全队就从正在被超级兵啃的基地上松手**。
Turbo 里超级兵来得早,这一条的赔率比普通模式高。

## 4. 修法与方向

**一个 id `basecreep`,turbo-only,单独 gate**(⛔ 绝不与 `threatcreep` 合取 —— pullcad 陷阱)。
调用点绑住 `WeightedEnemiesAroundLocation` 的**第二个返回值**(`threatcreep` 已建好的 creep-inclusive 并行和),
并把赋值改成 `math.max`。**`.lua` 与 `.ts` 一起改。**

⛔ **出厂第一返回值、`math.floor`、阈值 `>= 2`、半径 2600、上面那条英雄臂逐字未动。**

**⭐ 为什么是一个 id 不是两个 —— 0NEXT34 §乙 的机械判据(把每一半单独落地,问数值动不动)**:

- **只换 raw 和、保留 `=`**:数值会动,**而且动在这条分支唯一被禁止的方向上** ——
  基地口一波超级兵会把一个**正在生效的**英雄 hold 从 +4 砍到 +1.5。**单独不可发。**
- **只换 `math.max`、保留英雄和**:按上面的闭式,条件除了缓存那几帧恒假,
  而那几帧待办值本来就更大 ⇒ **是个 no-op**。
- ⇒ 两半都不能单独出货,**一个原子,一个 id**。两条都明码标价成变异体 **B2 / B3**。

**方向 —— 单向且是算术的**:`rawCount` 从**未取整的**英雄和起步、只加非负小兵项,
而 `count` 是在那之后才取整 ⇒ **raw ≥ shipped 恒成立** ⇒ armed 只能把条件由 FALSE 变 TRUE;
`math.max` 让它只能把 `baseThreatUntil` 往**后**推。
**armed 永远不能解除 base threat,也永远不能砍短一个 hold。**
⛔ **阈值 2 未动是保守侧**:0.2 单价下一波四只基础兵 = **0.8**,**armed 照样拒绝**;
够到 2 的是**攻城/超级兵**推进(0.5 / 0.6 一只),正是这条分支命名的局面。

**条件 (c)**:标准打法就是「英雄撤了但兵线在啃遗迹时不要松手」,
而**这不是本组新提的策略** —— 它逐字写在 TS 源码那一行注释里(`creeps can only extend`),
本轮做的是让代码答得上它自己已经写下的那句话。
