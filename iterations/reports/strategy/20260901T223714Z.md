## 二、缺陷

`bots/FunLib/aba_site.lua`,`____exports.IsTheClosestOne` —— **野区营地仲裁谓词**,
全仓调用链单线:`mode_farm_generic.lua` 的 `ClosestCamp`(GH #137 立的**唯一**那处)
→ `GetClosestNeutralSpwan` → `IsTheClosestOne`。出厂:

```lua
for ____, id in ipairs(GetTeamPlayers(GetTeam())) do
    local member = GetTeamMember(id)
```

- `GetTeamPlayers(team)` → **player id**(radiant 0-4 / dire 5-9);
- `GetTeamMember(n)` → **team slot 1..5**,越界**答 nil**
  (`docs/BOT_API_REFERENCE.md:223` 逐字写着 "1-indexed … nil if the player slot
  doesn't exist";`tests/mock/replay_fixture.lua` 与 `tests/mock/bot_api.lua` 都按 1..5 实现)。

**两个不是同一个数域**,而 Lua 不会为此抛任何东西。

### 2.1 按侧不同 —— 这正是铁律 4(i) 管的那种量

| 侧 | ids | 落到的 slot | 扫到几个 |
|---|---|---|---|
| radiant | {0,1,2,3,4} | {1,2,3,4} | **4 / 5**,slot 5 从没被问过;**从第 2 步起每一步量的都是另一个英雄** |
| dire | {5,6,7,8,9} | {5} | **1 / 5**;对 pid-9 那个 bot 而言**那就是它自己** ⇒ 空转,恒答 TRUE |

**47 份带 `player_id` 的真实帧 fixture 上逐份复现**:**24 份 dire(扫 1)+ 23 份 radiant(扫 4)**,
armed 每一份扫满 5。所以**在这条上池化读一个撞车率是结构性错误,不是精度问题**。

### 2.2 失效方向朝「开」(连着第三条)

扫得少只会让「没人比我更近」**更容易成立** ⇒ **多个 bot 各自认定同一个营地归自己**。
与 #393 `immguard`、#397 `hpbool` 同侧,与它们之前的七条相反。

### 2.3 它是缺陷不是房规:仓库自己按多数票回答

出厂树全仓 `GetTeamMember` 调用点普查(**91 处 / 26 个文件**):

| 形状 | 数量 |
|---|---|
| slot(`i` / 字面量 1..5 / `i + 1`) | **80** |
| player id(`id` / `playerId` / `playerdId`) | **10** |
| 都不是(见 §四.3) | 1 |

**80 : 10** —— 与 #397 的 **64:6**、#385 的 **249/227/1** 同族。
**两种写法坐在同一批文件里、迭代同一个 `GetTeamPlayers(GetTeam())`,不可能都对。**

## 三、改动:参数化,闸只在一处解析

`IsTheClosestOne(bot, loc, bSlotArb)`;`GetClosestNeutralSpwan(..., bSlotArb)` 只透传;
**闸在全仓唯一那处解析** —— `mode_farm_generic.lua` 的 `ClosestCamp`,
和 `campsel` 用的**是同一个 wrapper**(GH #137 当年把十个调用点收成一个,正是为了让
「没有调用点能漏掉闸」是一个**计数**而不是一句承诺)。两个 id 各带**自己的** turbo 检查,
所以任一条可以单独 arm。

门关 ⇒ `nSlot = id` ⇒ **逐字节等于出厂函数**。`typescript/…/aba_site.ts` 同步。`game/` 零 diff。

**严格子集**:armed 扫的是出厂集合的**超集**,而扫得更宽**只可能找到更近的人**
⇒ **armed 的 TRUE 集是出厂 TRUE 集的严格子集**:只可能让出一个营地,**永远不可能多占一个**。
`[subset]` 在全语料上实测 **46 次翻转,反方向 0 次**(反方向若出现即证伪该论证)。

## 五、⛔ 本轮最该被读的一条(交总监):量具洞

`tests/mock/bot_api.lua` 的 `GetTeamMember(n)` **对任何 `n` 都造一个英雄出来,永远不答 nil**:

```lua
G.GetTeamMember = function(i)
    if i == 1 then return bot end
    return M.MakeHero('npc_dota_hero_teammate_' .. tostring(i), { GetPlayerID = i - 1 })
end
```

⇒ **任何写在那个 mock 上的单元测试,对这条缺陷是结构上失明的** —— 不是没查,是**查不到**。
**这就是 91 个调用点带着 10 处错误、而整套测试一路绿灯的原因。**
只有 `replay_fixture.lua` 的**真实 roster**(按 `player_id` 排序、按下标取)会答 nil ——
所以这条缺陷**只有真实帧看得见**,gate-plumbing 测试在这里连边都摸不着。

本轮把这个洞**棘轮化**(`[instrument]`,断言写成「洞还在」并注明修好后要连同这条一起删),
**但修不修那个 mock 是总监的决定**:它是中心件,改它可能牵动别的断言,
而那是**第二个杠杆**,不属于本工作单元。

与 §CL / GH #329 的教训**同族**:那次是**读数不是局数**,这次是
**「测试跑了」不是「测试看得见」** —— 都是一个满足了形式、丢掉了内容的量。
