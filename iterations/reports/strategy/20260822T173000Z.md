## 1. 缺陷:触发条件和选点互相拆台

`J.ShouldPullNeutralCamp` 的**承重触发条件**是「我方兵线前沿越过中点、压向敌方」——
这是**教科书拉野的适应症**,没有问题。问题在下面的选点:遍历 `GetNeutralSpawners()`,
筛 `camp.team == GetTeam()`,取**离 bot 最近**且 `< 1500` 的那个。

**两条子句互相拆台**:兵线被压出去时,拉野者本人就站得靠前;于是「离他最近的己方营」
**恰恰是深处的远野营**。批测在 283 局上读到的正是这个形状(#117 订正后的数):

| 量 | 值 |
|---|---|
| 开拉时离自家泉水 | 中位 **10,708u**(全图 18,806u ⇒ **57% 处,已越过中点**) |
| 离家 >9,000u 开拉 | **67/115** |
| 两个深野营占 poke 帧 | (3994,-5137) 95 帧 + (-4007,4947) 41 帧 = **51%** |
| 跟随小野最远走出 | 中位 **742u**,而它们离最近线兵还有中位 **1,068u** |
| **连接率** | **≤ 20.3%** |

最后两行是关键:**失败的不是估计量,是拖拽的几何** —— 野点离兵线太远,小野在够到兵线之前
就脱离了。连接不上的拉野**不是差一点的拉野,是纯亏**(开拉后 15s 掉血中位 19pp)。

## 2. 修法:度量从「离 bot 最近」换成「相对我方远古的位置」

```lua
local nMidToOwn = J.GetLocationToLocationDistance( vMid, vOwn )
...
    if camp ~= nil and camp.location ~= nil and camp.team == GetTeam()
        and J.GetLocationToLocationDistance( camp.location, vOwn ) < nMidToOwn
```

候选营必须**比车道中点更靠近我方远古**;通过这一关之后仍然按离 bot 最近排序(新子句**筛**,
旧读数**排**)。`vMid` / `vOwn` 是均衡子句上面**已经解出来的同两个位置** ⇒ **零新引擎调用、
零新失败模式**。

**为什么用「车道中点」而不是总监建议的两条路**:

- **(乙) 按到我方远古的距离升序取第一个**:那会让上路的辅助跑去下路那个离家最近的营
  ——选点必须和 bot 的可达性一起解,而 reach 这一半本轮不动。
- **「camp 比 bot 更靠近远古」(#117 §建议 3)**:**量出来不够** —— bot 中位在 10,708u,
  这条只把 reach 内比他更靠后的营留下,最好也就 ~9,200u,**仍在中点之外**,
  达不到总监验收口径 2 的「中位 < 9,403u」。
- **「camp 在我方半场」(按两座远古比距离)**:**实测差点栽在这上面** ——
  用真实远古坐标(radiant `(-5920,-5352)`、dire `(5528,5000)`)算 #117 那个热点营
  (3994,-5137):离 radiant 远古 **9,916u**、离 dire 远古 **10,252u** ⇒ 它**算 radiant 的半场**,
  这条子句**放它过**,修了等于没修。**中点判据把它拒掉**(9,916 > 7,717)。
  这是本轮最值钱的一次算术:三条听起来都对的几何,只有一条真的咬得住那个营。

## 3. 本地验证:两枚真实帧 + 一枚结构性反证帧(`tests/test_pullcamp_ownside_camp.lua`,11 例)

`GetNeutralSpawners()` 在 930/930 帧上是 `{}`(census 的 STOPPER 2),所以**营地坐标必须声明**

本文件一次都没声明。`GetLaneFrontLocation` 按 GH #61 由用例逐帧声明,车道中点声明为
**该帧两座真实远古的中点**。断言转的每一个量(bot 位置、两座远古、各段距离)都读自真实帧。

- **frame A(缺陷帧)**:`f_260822_063722_lina_tp_home` 的 **witch_doctor(radiant pos5)**,
  站在 **(4589,-5976)**、离自家远古 **10,527u**(68% 处)。声明的营就是 #117 实测的热点
  **(3994,-5137)**,离他 **1,028u**(**在未动的 1500 reach 之内 ⇒ 旧规则会选它**),
  离自家远古 9,916u(**> 中点 7,717u**)⇒ **修法后返回 nil**。
  witch_doctor 是批测里第三多的拉野者(24 episode),这一帧是**真实的同一类站位**。
- **frame B(判别力在这里)**:`f_260819_181742_ss_chase_start` 的 **silencer**,
  离边界只有 **51u** —— **本语料里唯一能让深营与自家营同时进 1500 reach 的真实几何**。
  深营放**更近**(700u)、自家营放更远(1200u),断言**选中的是自家营**,
  并单独断言「深营确实是更近的那个」(否则这枚对照什么都没控)。
  = 总监验收口径 1「**两侧都断言选中的营是哪一个**」。
  另有边界用例:同一帧同一 reach,营在边界内 20u **被选中**、外 20u **被拒**。
- **frame C(不可能造成伤害)**:老 census 的 ogre 帧,`botDepth + 1500 < boundary`
  ⇒ **任何可达营在算术上都不可能是深营**,断言修法在他身上恒等。

**一条自带的诚实声明(写进用例名)**:**frame A 的 nil 不是判别力的证据**。
那一帧 bot 比边界深 **2,811u** 而 reach 只有 1500 ⇒ 绕他一圈**八个方向**的营全会被拒
(已写成断言)。牙齿在 frame B,不在 frame A。这是 0p 那条「整条分支不可达也会跑出干净的绿」
的自查:**一个只会答 nil 的帧,答 nil 不算证据**。

**两条 `[reverse]` 源码钉子**把「一次一个变量」钉成机器可查的:`1500` reach 与
`if J.GetHP( bot ) < 0.5 then return false end` 各一条,**谁把它们和选点一起改就转红**
——否则下一波的连接率无法归因。
