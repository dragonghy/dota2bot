## 1. 缺陷:被当作反驳方的那一行,不是一个来源

`docs/BOT_API_REFERENCE.md` 原文(641-649):

```
### `GetNeutralSpawners()`
**Returns:** `{table...}` -- Table of tables, each containing:
- `team` (int): Which team's jungle.
- `type` (int): Camp type (small, medium, large, ancient).
- `speed` (float): Creep movement speed.
- `location` (vector): Camp spawn location.
- `min` (vector): Spawn box minimum corner.
- `max` (vector): Spawn box maximum corner.
```

三条独立理由说明它**不能**用来否证 shipped 代码:

### (1) 它没有观测过这个 API

| 来源 | 对 `GetNeutralSpawners` 说了什么 |
|---|---|
| Valve 开发者 wiki(两份独立镜像:`pastebin/du8mRjei`、`pastebin/R0ra6Xwi`) | 只在全局函数表里**列了名字**,**零字段文档** |
| ModDota 引擎 dump(`docs.moddota.com/lua_bots/`) | 签名 `GetNeutralSpawners( ) : variant`;引擎自带 help 串逐字为 *"Get the location of all neutral spawners, and what side of the river they're on."* ——**没有字段表** |
| 本仓这一行 | 六个字段 + 每个都带类型标注 |

**Valve 从来没有公布过这个记录的形状。** 本仓这一行比它宣称的来源**知道得更多**,
而这是不可能的。且本文件页首引的是
`Dota_2_Workshop_Tools/Scripting/API` —— **server-vscript 的 API,不是 bot scripting 的**。

### (2) 同样六行逐字出现在一个无关的第三方仓库

`shikyo13/Dota2AI` 的 `docs/BOT_API_REFERENCE.md`(**同名文件**)带**同一条页首 ref**,
其 `GetNeutralSpawners()` 条目六行**逐字相同**(经 raw fetch 核对)。
方向不可考(谁抄谁、还是同一个祖先),但**结论不依赖方向**:
它是**同一份血统**,不是独立确认。

### (3) 它自相矛盾 —— 而且是有规律地矛盾

这是本轮最便宜也最硬的一条,**不需要任何外部来源**:

| 行 | 类型标注 | 同一行的描述 / shipped 代码怎么读它 |
|---|---|---|
| `type` | **`int`** | 描述自己写的是 `small, medium, large, ancient` —— **字符串值** |
| `speed` | **`float`** | `aba_site.lua` `GetCampStackTime` 比的是 `"fast"` / `"slow"` —— **字符串** |
| `team` | **`int`** | 三处 shipped 代码拿它和 `GetTeam()` 比 |
| `idx` | **该行根本没列** | `aba_site.lua` `RefreshCamp` 读了 **4 次** |

**这一行里每一个数字型标注,都紧挨着一个字符串型的描述。**
这是一个**被编出来而不是被读出来**的类型列的指纹。
外加 `idx`:该行不但**类型错**,而且**不完整** —— 一份真的记录 dump 不会漏掉被读 4 次的字段。

## 4. ⚠ 方法自伤两条(本轮各一次,方向都是「把没通过报成通过」)

### (i) 变异夹具用 `git checkout` 还原 —— 它还原掉的是**我自己没提交的改动**

第一批变异跑出来 **两端 CONTROL 都 DIRTY**、五个 doc 变异全 `SETUP-FAILED`,
因为 `restore()` 写的是 `git checkout -- $DOC`,而**被测的 doc 改动还在工作树里没提交** ⇒
第一次 restore 就把本轮的产出**擦掉了**(事后 `git status` 坐实)。
**修法**:还原改成**从 scratchpad 快照 `cp` 回来**,不碰 git。
记成规则:**变异夹具的还原路径,不许经过版本控制** —— 被测对象常常正是未提交的那份。

### (ii) `'#241' in section` 不是一个 pin —— 那个 token 在该节里出现**两次**

第二批 10 变异 **9 抓 1 活**:`MUT[doc drops the #241 cite]` **SURVIVED**,
因为它只删掉了 blockquote 里那一处,而条目顶部还有一处 `See GH #241.` ⇒
成员测试照样为真。**这是 `0SALT`「source pin 只有在字符串于文件内唯一时才是 pin」
的反向同族**:那次是变异打在了没被断言的拷贝上,这次是**断言落在了一个不唯一的针上**。
**修法是换针不是补断言**:改成**两个各自唯一的整句**(`'See GH #241.'`、
`'settled types (GH #241)'`)各 `count(...) == 1`,`UNVERIFIED` 同样改成
`count == 1`(所以**重复它**也会红 —— 已作为变异验证)。

第三批 **12 变异 12 抓**,两端 CONTROL 各一次干净。判定读数一律用**退出码**,
不用 stdout 子串(`0SALY` 教训:`"10 failures"` 含 `"0 failures"`)。全程顺序执行不并发。
