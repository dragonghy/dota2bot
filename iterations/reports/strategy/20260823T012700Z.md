## 一、`itemtrip` 是什么,以及它为什么必须长成这个形状

**缺陷**(录像组 GH #120,283 局):55% 血以上的回家 TP 一共 643 次,逐条
按 `bots/` 的分支归因之后,**76 次(11.8%,0.27/局)没有任何分支能解释** ——
中位血量 81.7%、41/76 全程 1600 环内无敌人、往返中位 40.1 秒。承重帧是
lina `20260822_123136_slot3 t=434.6`:**满血、最近敌人 4212u、快递明明在正常
工作**,她还是回城合成紫怨,**往返 49 秒 ≈ 一局的 8%**。

**为什么没人管**(上一轮的审计,本轮直接用):`BOT_MODE_ITEM` 在本树上是
**引擎自带实现** —— 本树唯一的 item-mode 文件被自己的文件名禁用了
(`bots/--mode_item_generic.lua`),而 8 个 `BOT_MODE_ITEM` 分支站点里
5 个是英雄专属、3 个是**到家之后**的收尾,**0 个拦得住这趟行程**。

**gate 必须是 load-time 的,这是全部的安全论证**:未 armed 时新文件
**根本不定义 `GetDesire`**,引擎没有东西可调,于是保留内置出价 ——
**未 armed 的一局逐字节等于今天这一局**。这个机制不需要任何文档合同:
`mode_attack_generic.lua` 只给 9 个英雄装 `GetDesire/Think/OnStart/OnEnd`,
另外约 118 个照样普攻,`test_tpwatch_channel_bid` 在真实帧上断言过
`#engine_owned >= 1`。**刻意不用**的是
`docs/BOT_API_REFERENCE.md:52` 那条「`GetDesire()` 返回 nil ⇒ 落回内置」——
它在本树上曾经 **0 使用者**,拿它当 gate 会**反向失败**。

## 二、⭐ armed 之后那一半是未知的,而未知被写成了一条可证伪的预登记

armed 时函数长这样:

```lua
function GetDesire()
	if J.IsWastefulItemTrip( bot ) then return BOT_MODE_DESIRE_NONE end
	return nil
end
```

**先说这个形状自带的边界**:它**只可能压低 item mode 的出价,永远不可能抬高**
—— 两条分支一条是 0、一条不是数字。所以最坏情况是「**英雄不去取 stash**」,
**不可能是「英雄更频繁地回家」**。失败方向由构造锁死在安全的一侧,这是本组
愿意在一条未兑付的引擎合同上花预算的**唯一**理由。

在那个界限之内,`return nil` 到底怎么被读**我们不知道**,而两种结果都提前登记:

| 若 nil 落回内置 | armed = 内置出价 **减去** 浪费帧,即设计中的杠杆 |
|---|---|
| 若 nil 被读成 0 | armed = 整局 item mode 关闭,也就是 `--mode_item_generic.lua` 当年**无条件**做的那件事 |

**(a) 核验不需要额外仪器就能把两者分开**:armed 腿的 item-mode 回家行程
**只在 #120 的浪费画像里下降** ⇒ 合同为真;**塌到 ~0** ⇒ 合同为假,
而且从此**为所有后来者兑付掉了**。这条预测**写在文件头注里,先于波次**。

本组不用 mock 的竞价去「证明」这一条:**mock 的竞价不是引擎的竞价**,
拿它当证据正是 0p 那个形状。

## 五之二、⚠️ 写用例时踩到并钉住的一条:**两个 fixture 世界不能同时存在**

`rf.load` 装的是**一整套全局**。边界对照第一版写成「先加载 A、再加载 B、
然后分别问」,结果 axe 的离家距离读出 **15,316** 而不是 4,765 ——
那是他到**对面**泉水的距离:第二次 `rf.load` 把 `GetTeam` 换掉了,
**第一个世界的 helper 于是在第二个世界的参照系里作答**。
修法是每对边界**读完一个世界再加载下一个**,并把这条写进文件注释。
**这不是风格偏好** —— 它安静、可信、且答案完全错误,是本仓库最爱的那种坑。
