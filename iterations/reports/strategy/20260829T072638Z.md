## 2. ⚠ 更值得记的一条:三个红文件只有两个根因,第二份"证据"指着错的对象

开工自检读到 **3 个红文件**(python 2 + lua 1)。**但 `tests/test_selfcheck_lua_leg.py`
不是独立根因**,它是同一条 census 红**经第二条腿的转述**:

它的 case 5 用**整棵工作树的副本(minus `.git`)**当 fixture,而那里的 **"clean" 一直指

5a/5a2/5b/5c 四条一起红,**而它们的失败文本写作**:

> `5a: a clean tree does not report TRUNK RED`

**读起来像「检测器坏了」,而实际发生的是「树红了」。** 修检测器是错的修法。

**⭐ 反事实证据(本轮唯一一份硬读数)**:只重锚那两条 pin、**对该 python 文件零编辑**,
它从 **4 failures → 43 checks / 0 failures**。**一个根因,两个红文件,而第二份报告把矛头
指向了门而不是树。**

**失效方向最贵的那侧**:它给一条红**加上一份看起来独立的第二份证据**(读起来像两个根因,
本轮 #295 的标题就写作「两个独立根因」——**那句话对 odaoe 那一半成立,对这一半不成立**),
同时把注意力引向工具本身。

### 2.1 修法:把 fixture 前提做成代码里的判别位,而不是散文里的豁免

`uncert()` 新增一条通道:baseline 树本来就红时,5a/5a2/5b/5c 报 **UNCERTIFIABLE**、
脚本退出码抬到 **2**,并**点名到底是哪个文件真的红**。

**为什么这不是 GH #171 那个「SKIP 读起来像 PASS」的坑**(这个文件正是为关那个坑写的):
**差在退出码**。那次的 SKIP 是一行毫不起眼的字、**退出码没有区别**,所以读起来就是 PASS;
这条路抬到 **2**,而 `tests/run_py_tests.sh` **已经**把 2 渲染成
`UNCERTIFIABLE ... (did NOT run -- this is not a pass and not a failure)`
——**用的是仓库既有的 0 干净 / 2 没跑成 / 3 有发现,不是我新造的词**。

**判别位在代码里,不在 docstring 里**(这是本组 01:16Z 自己立的判据:
**豁免只活在散文里就不是豁免**):把 leg 点名的文件**用 leg 自己那条命令单独重跑**,
**只有真的单独也红的文件才配降级**。leg 喊红、而它点名的文件单独跑全绿 ⇒
**那就是 leg 自己坏了,仍然是货真价实的 FAIL**。

**B 是本轮真正承重的那条**:它证明这条降级通道**不会吞掉一个真的 leg bug**。
