## 1. 缺陷

`bots/FunLib/minion_lib/primal_split.lua:109`(**发货态**),`AttackUnits` 的出口:

```lua
	if target ~= nil and not target:IsAttackImmune() and not target:IsInvulnerable() then
		return target
	end

	return target
```

**两条臂返回同一个表达式。** 作者把问题问对了,**答案被丢掉** ——
这个免疫过滤器**自诞生起一次都没有筛掉过任何东西**。

## 2. ⭐ 主判据(可复用,超出本主题)

> **一个两条臂返回同一个表达式的分支不是过滤器,是一句注释 —— 只是它还要付一次函数调用的钱。**

**判别特征可数、不需要帧、不需要跑、也不需要理解那个谓词**:
`if C then return E end` 紧跟一个 `return E`。**改动前全仓 3 处**([source S1] 把这条 grep 机械化了)。

### ⚠️ 而它与同族七条**失效方向相反**,这才是它值得单独登记的地方

| | 是什么 | 方向 |
|---|---|---|
| #348 | 顺序(nil 守卫排在它守护的索引之下) | 关 |
| #368 | 词法作用域(`local` 遮蔽) | 关 |
| #370 | 未汇报的副作用 | 关 |
| #373 | 闩记「看过了」不记「找到了」 | 关 |
| #378 | 节流器作用域宽于被节流物 | 关 |
| #381 | 手工字段复制引擎已知之事 | 关 |
| #385 | 以「别的单位」为域的谓词被喂了 `self` | 关 |
| **本条** | **两条臂返回同一表达式** | **开** |

**七条全都朝「关」失效**:一条该发生的分支不发生;而且七条**都不可观测** ——
「没触发」与「被正确地否决了」在任何观察下一模一样。

**本条朝「开」失效**:闸**放行一切**,于是错误答案是一个**积极动作** ——
一条打在打不动的单位上的攻击命令。
**它不是不可观测,它只是没人看**:唯一到达这个文件的英雄是**开着大招的酒仙**([source S6])。

## 3. ⭐⭐ 它是缺陷不是取舍 —— 仓库自己回答了两遍,而第二遍才是关键

**(1) 共享 picker 本来就在做这两条判别。**

`J.GetAttackableWeakestUnitFromList`(`bots/FunLib/jmz_func.lua:3748`),

⇒ 对不可攻击单位 **`return nil` 不是本改动的发明,是仓库自己的 picker 在同一次调用上的做法。**

**(2) ……而三行之后,这个函数把 picker 刚拒绝的东西又放了回来。**
picker 对「候选全不可攻击」答 `nil`,而 `:105` 把这个 `nil` 读成「picker 没有意见」,
于是 `target = enemies[1]` —— **同一个句柄**。

⇒ 手写的这道闸**不是躲在已过滤 picker 背后的冗余第二意见**:
在 `enemies[1]` 兜底之后,**它是不可攻击单位与攻击命令之间唯一的东西,在每一条臂上,包括英雄臂。**

## 4. ⭐⭐⭐ 代价在调用点上收两次,不是一次

`X.MinionThink:65-69` 拿到句柄就 `Action_AttackUnit(target, false)` **然后 `return`**:

- (a) 一条**引擎判定为零伤害**的命令;
- (b) **`ConsiderMove` 整个不跑** —— 它在那个 `return` 之下。

而对**火熊猫**来说 `ConsiderMove` 就是它行为的全部:它自己的技能分支是 `:52-53` 的一个**空 `if`**。
⇒ 二十秒 Primal Split,花在朝一座打不动的建筑挥棒上。

## 5. 改动(门关字节级不变)

**不删那道闸**,把 gated 提前返回**插在它的两条臂之间**:

- **门关**:控制**直接落到出厂的 `return target`** ⇒ 出厂路径不变;

**⚠️ 注意方向**:与 §DB/§DD 不同,**armed 不是严格超集** —— 它会**减少**一条攻击命令。

所以被拿走的那条命令**在信息上是空的**,换回来的是一条真的移动命令。
