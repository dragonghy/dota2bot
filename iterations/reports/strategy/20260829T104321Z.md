## 1. ⭐ 主判据(可复用)

> **一个 presence 谓词(「有没有 X」)被两个消费方以相反极性在同一帧上读时,它的「有」
> 会同时充当两个互相抵消的理由:一边拿它当「可以留下」的依据,另一边拿它当「不必补给」的依据。
> 于是量级最小的那个 X 反而是最坏的:它买下了留守,却又不足以让留守有意义,同时还堵住了
> 唯一能让留守有意义的那条补给路。失效方向最贵:**两个 id 各自都在按自己的声明工作**,
> 没有任何断言会红,而合起来的结果是两条腿互相锁死在最差的那一格上。**

判别方式便宜且确定:**数一个 presence 谓词的消费方,看它们的极性是否相反**。相反,就去问
「这个谓词答 TRUE 的最小实例,对两边分别意味着什么」。

**不是假想**:本仓库这一族的最小实例是 **85 血**,最大实例是 **400 血**,**4.7 倍**,
而两个消费方对它们答**同一个 TRUE**。

## 4. 落地:gated `fieldsip` —— 一个门,**两个消费方对称消费**

`bots/FunLib/jmz_func.lua`(**唯一改动的 `bots/` 文件**;`game/` 逐字节零 diff):

```

                          （单次使用量,与 presence 谓词自己的「一格一口」口径一致）

```

两个消费方:

```
留守  situation ∧ HasFieldRegenSource ∧ IsFieldSipEnough
购买  fieldbuy ∧ situation ∧ ¬( HasFieldRegenSource ∧ IsFieldSipEnough )
```

- **未 armed 逐字退化成出厂表达式**(`A` 与 `not A`),`[reduce]` 在源码层钉住。
- **单向**:armed 只能把留守 TRUE→FALSE、把购买 FALSE→TRUE。
- **⭐ 分区按构造保住**:两边读的是**同一个合取式**的正负两面 ⇒ armed 之后仍然
  **永不同帧为真,也不留下无人认领的帧**。普查上五个「不可能」计数器全 **0**,
  且 `released == now_buys == 21`(**同一批帧改归属,不是被丢掉**)。

  这是 `campvoid`(GH #265)那条主判据**在事前**用一次:
  *「一个修复从表里拿走条目时,所有另外问这张表空不空的谓词必须按同一条规则过滤,
  否则会造出一个任何分支都没覆盖的状态」*。那一轮是**死锁修完之后**才写下这条;本轮是
  **动手之前**照它设计,所以这里没有第二个 `campexit` 要开。
- **刻意不折进 `J.HasFieldRegenSource` 本体**:那个名字是 presence,
  让 magnitude 判据穿 presence 的名字,正是谓词开始不再表示调用点所说的东西的方式。
- **不与 `stayfield` / `stayfield2` / `fieldbuy` / `fieldcreep` / `bagsalve` 任何一个合取**
  (`pullcad` 陷阱),断言明令禁止这五个 id 出现在本谓词体内,`IsSoakCandidate` 恰好 1 次。
- **turbo 是结构性的**:两个消费方都先问 `J.IsFieldRegenSituation`(第一行 `IsModeTurbo`),
  再问本谓词。**调用序是承重的,所以断言的是调用序**,而不是加一条冗余的 `IsModeTurbo`
  ——加了就等于声明调用序不承重。

## 6. ⚠️ 方法自伤两条(都已修,都值得记)

**(甲)`>=` vs `>` 在整个语料上不可分,而它正是读者会当成手误的那个编辑。**
第一轮变异battery 跑完是 **13/14**:`M1` 活下来了。原因是语料最近的两行是 **0.156** 与 **0.360**,
**没有任何一行落在阈值上** —— 空隙让常数不承重,**同一条空隙也让边界不可测**。
补 `[boundary]`:用**两个 shipped 常数推导**出边界血条(`400 / 0.25 = 1600`),
**并先断言这个重构在二进制浮点下是精确的**(不精确就要求重建这一例,而不是删掉它),
再驱动 `exact` / `exact±1` 三点。补完 **14/14**。
⇒ **登记一条:让常数不承重的那个性质,同时也让它的边界测不出来;两件事要分开买。**

**(乙)一条纯注释把兄弟文件的一条普查打红 —— 而那条普查数的是「调用点」,读的是原始文本。**
`test_bagsalve_backpack_source.lua` 有一条断言「`J.HasFieldRegenSource` 恰好 2 个调用点」。
本轮在 `ShouldFieldBuyRegen` 里写了一行注释,**引用了出厂表达式** `not J.HasFieldRegenSource( bot )`,
于是它被数成**第 3 个调用点**,文件转红 —— **一个调用点都没有新增**。
与 08-29T04:20Z 那 14 行纯注释顶掉行号 pin **同族**:*一条检查的 pattern 够到了它的主张覆盖不到的文本*。
**修法是加固不是放松**:给那条普查加 `strip_comments`,并**同一条测试里当场证明加固没有钝化它** ——
往源码里追加一个**真的**调用点仍然读作 3,追加一行**引用调用形式的注释**仍然读作 2。
(**注意方向**:修之前,注释既能**误伤**也能**冒充**;修之后两者都不成立。)
