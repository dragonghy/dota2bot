## 1. 主判据(立法级,可复用,超出本主题)

> **当一个缺陷有两半而只有一半看得见时,看得见的那一半不是更便宜的那一半 —— 它是诱饵。**

单独落地看得见的那一半,产出的 diff **改了源码、过得了评审、读上去像修复**,
而实测**与未修树逐位相同**(0/5932)。

可操作的一半:**凡「补一个实参 / 改一个名字」型的修复,先问
「这个集合是用什么建的键,读的人拿什么问」** —— 两边不是同一个东西时,
元数那一半是装饰。

## 2. 机制:四行,两个互相独立的缺陷

`bots/mode_team_roam_generic.lua`:

```
:1771  if not J.Utils.SetContains(itemName) and ...              -- 读
:1819  if tryPickCount >= 3 and not Utils.SetContains(itemName)  -- 读
:1821      Utils.AddToSet(ignorePickupList, PickedItem.item)     -- 写
:1823  if not Utils.SetContains(itemName) and ...                -- 读
```

对着 `bots/FunLib/utils.lua:1260` 的 `function ____exports.SetContains(set, key)`。

- **(1) 元数 —— 看得见的一半。**三处读只传一个实参 ⇒ `set` 绑到物品**名字**、`key` 绑到 nil。
  `("item_aegis")[nil]` 经字符串元表是一次**合法的读**、答 nil ⇒ 闸恒假。
  **它不抛错**(实测 `shipped_raise` = 0/5932),这正是它一直没人指着的原因。
- **(2) 两套下标空间 —— 看不见的一半。**写存 `PickedItem.item`(**句柄**)当键,
  三处读全按**名字**问。`0SLOT` / `slotarb` 之后**同族第三次**。

## 3. 三条腿的读数(真实 shipped 函数,同一批 5932 个真实句柄 / 117 个名字)

| 腿 | 做什么 | 报「已忽略」 |
|---|---|---|
| `shipped` | `SetContains(name)`,树的原样 | **0 / 5932** |
| `argfix` | `AddToSet(ig, handle)` 后 `SetContains(ig, name)` —— **一行修法** | **0 / 5932** |
| `bothfix` | `AddToSet(ig, name)` 后 `SetContains(ig, name)` | **5932 / 5932** |

`bothfix` 同时是**反真空对照**:三条腿是同一对 shipped 函数、同一批句柄,只换了索引空间,
而它**能**说「已忽略」——在每一个句柄上。⇒ 那两个 0 是读数,不是卡死的探针。
**⇒ 修法是两半一起,否则等于没修。**

## 4. 第二条发现(#452 没有这条):重试循环算出来的 desire 谁也收不到

`ItemOpsDesire` 在掉落物循环里
`if PickedItem ~= nil and GetItemCost(itemName) > minPickItemCost then return RemapValClamped(...) end`,
而它**唯一**的调用点 `GetDesireHelper:271` 把它当**裸语句**调用,把值扔掉。

⇒ 在出厂树里那个 `return` **不是一个 desire,纯粹是一次 skip**。它跳过的是同一函数下面的
**八个家务调用**(`TrySellOrDropItem`、`SwapSmokeSupport`、六个 `TrySwapInvItemFor*`),
**外加 `ConsiderDroppedTime = DotaTime()`** —— 也就是这个函数自己那道 2 秒节流的重新上膛。
又因为 `PickedItem` 是模块级、只在 `OnEnd` 清空,而第 2 节那套放弃机制是死的,
**触发这次 skip 的条件是黏住的**。

两条都钉成 `[source]` 断言,将来的改写会**重新推导**而不是继承本报告的散文。

## 5. 为什么不落地(结构性,不是胆小)

章程第 2 条要求行为改动必须带真实帧 fixture。这段代码做的**决定**在本语料上买不到:
`GetDroppedItemList()` 在 mock 里是 `{}`,dumper 不写掉落物记录 ⇒ **0/1012 活帧**。

但语料**带得起其余每一条前提** —— `ItemOpsThink` 自己那道库存余位闸在 **983/1012**
(97.1%) 帧上成立。**这个对比才是价钱**:缺的恰好是**一个**字段,
所以「买不到」在这里是一句有地址的话,不是一句含糊的没办法。

**诚实边界**(已写进普查文件头与测试头):被驱动的 5932 个句柄来自 fixture 的**库存**,
不是 `GetDroppedItemList()`。它们作证的是**集合管路**(句柄 vs 名字,对库存句柄与掉落句柄
逐字同形),**不是那个决定**。这就是为什么这里用替身合法、而给那个决定用替身不合法。

## 6. 仪器自查:变异台 12/12 CAUGHT,零 NO-OP

三发是这台存在的理由:

- **M8** 让 `argfix` 腿偷偷按名字建键 ⇒ 它**照常跑、照常出数,而那个数是对照组的**。
  于是「一行修法没用」会拿**不是一行修法**的腿去量,而且**反方向**报出来、不吭声。
- **M9** 让对照腿按谁也不问的键建 ⇒ 三条腿全读 0,**内部自洽**,与真读数不可分辨;
  只有反真空断言挡在它和一份已发表的发现之间。
- **M12** 钉最危险的方向:`drop_frames == 0` 是「不许落地」的依据;如果这个 0 能由
  **没去问**产生,那条裁定就是**不可证伪**而不是被测量的。⇒ 普查文件本身也被
  `[source]` 断言钉住:必须真的 `pcall(GetDroppedItemList)`。

本轮**没有** SURVIVED,也**没有** NO-OP —— 每一发都改动了目标文件并被抓住。
