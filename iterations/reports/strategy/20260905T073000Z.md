## 1. 缺陷:一句没有归属的追击读数,住在**出厂**代码里

`J.ShouldStayAndRegen` 是 **PROMOTED** 的(原 soak id `tphome`,28 局 A/B 后转正)——
它**在每一局 Turbo 里都活着**。它的追击子句是:

```lua
if bot:WasRecentlyDamagedByAnyHero( 3.0 ) then return false end
```

**没有归属。** 一发从地图另一头落下的全局大招,和一个站在身上的英雄,在这一行上读数完全一样
⇒ 否决触发 ⇒「留下喝补给」被撤销 ⇒ 一个安全的残血 bot 被放去走回家或 TP 回家。
**这正是 owner 优先项 P2 逐字禁止的那趟路**(owner 原话:「血量低也尽量不要回程」)。

### ⭐ 主判据(立法级,可复用,超出本主题)

> **一个 GATED 家族把某个谓词写对了,不构成它旁边那个 PROMOTED 函数问的是同一个问题。**

对着**同一趟回家路**的 gated 家族(`stayfield` / `stayfield2` / `fieldbuy`,谓词
`J.IsFieldRegenSituation`)**自 2026-08-22 起就是归属式的**,源码原话:

> `-- Attributed danger: someone hit me recently AND is still near me.`

⇒ **缺的不是想法** —— 想法就在**同一个文件里、290 行之外**,用仓库自己的话写着。
缺的是它**停在了实验代码与出厂代码的边界上**,从来没被带过去。

⇒ 可操作:**「这个仓库知道该怎么问」和「这条出厂路径确实在问」是两句话,必须分开读。**
读了 gated 那一半就以为出厂那一半同理,是本节要钉住的那个动作。

与 §EO 是同族的反面:那次是**一个守卫在 helper 里已经跑过了**(论断按 token 集合立、
按求值集合才为真),这次是**一个守卫在隔壁写对了而这里没写**(两个函数在同一文件里
问同一件事、答案不同)。

## 2. 修法:一条合取项,独立闸,方向由构造定死

```lua
if bot:WasRecentlyDamagedByAnyHero( 3.0 )
    and ( not J.IsSoakCandidate( 'stayattr' )
        or J.HasNearbyHeroDamager( bot, 3000, 3.0 ) )
then
    return false
end
```

- **未 armed = 出厂读数,靠短路不靠论证**:第二个操作数在**第一个析取项**上短路,
  否决条件逐字是出厂表达式,**求值顺序也不变**。
- **方向由构造定死**:加一个析取项**只能让否决更难成立** ⇒ armed 的 TRUE 集是 shipped 的
  **严格超集**。这不是注释里的声明,是 `flip_true_to_false == 0` 那条断言(1012 帧驱动实测 **0**)。
- **独立闸,不与任何 id 合取**(`pullcad` 陷阱),已从散文升级成 `STAY_NIDS == 1` 断言。
- **turbo 是结构性的**:函数首行已经问过 `J.IsModeTurbo()`,不重复加。
- 新 helper `J.HasNearbyHeroDamager` **不与出厂兄弟扫描共用代码**:把一个出厂调用点重构成
  共享,会把「一个杠杆」变成「一次出厂行为的重构」(`lanefix` 教训)。

## 3. 域价钱 —— 承重的那个数是 **88**,它说的是「收窄」不是「删除」

109 fixture / **1012 活英雄帧**(`tests/_stayattr_sweep.lua`,两条腿都是**驱动**出来的:
同一个出厂函数、同一帧、只切换一个 soak id,没有任何一处重新实现决策 ⇒ 不会像影子对比那样漂走):

| 量 | 读数 |
|---|---|
| 盲读触发否决的帧 | **95** |
| 其中伤害**可归属**给 3000 内的人(杠杆完全惰性) | **88** |
| 其中**无人可归属**(杠杆的情形) | **7** |
| 整函数 false → true 翻转 | **1** |
| 反方向 true → false | **0**(断言) |
| `ship_true` → `arm_true` | 13 → **14** |

**88 是本次改动最承重的一个数**:出厂那条子句**十次里对九次以上**。所以这是**收窄**,
不是删除 —— 一个「把这行删掉」的修法会同时放掉那 88 帧的真实追击。

7 帧的**互斥四分区**,按函数**自己的子句顺序**取,**数出来不是减出来**(铁律 4(iii)):
翻转 **1** / 血量带外 **2** / **1200 环挡住 0** / 补给子句挡住 **4**。四桶之和 `== 7` 由断言钉住 ——
因为「杠杆在这一帧惰性」和「这个情形很罕见」是两句不同的话,只有具名的桶能把它们分开。

## 5. 诚实边界(四条,写在结论之前)

1. **看不见战争迷雾**:从雾里爆发然后退到 3000 外的敌人,在这一行上与全局大招读数相同 ——

   (说的是「没有一帧让环干过活」,不是「环覆盖了这个情形」)。**这正是 M10 抓不住的
   同一件事**,两处互为证据。
2. **见证帧上最近的敌人是 1,556u 外的 spirit_breaker**,冲刺已转好。他**没有**造成那次伤害
   (该帧 `recent_damage` 只点了 zuus)⇒ 归属扫描**答得对**;但「1,556 且在冲」是这个杠杆
   **不衡量**的真实威胁,因为管它的是原封不动的 1200 环。**作为该帧的事实断言下来,不辩解掉。**
3. **P2 自己钉的 lina 本人整函数不翻转** —— 补给子句(`not bHasFlask and GetGold() < 90`)
   仍然挡着她。而 mock 的 `GetGold` 落在 `^Get -> 0` 兜底上(**GH #495**),**那是一句类型断言
   不是她真实的钱** ⇒ **真实对局里会不会翻,UNKNOWN,不声称**。她那一帧上被证明的是本杠杆
   **自己那条子句**:否决触发,且**没有任何打过她的人在附近**(最近敌人 **6,596u**,
   与源码注释里那个数逐位相同)。
4. **一帧是一个瞬间**。本轮说的是 **t 时刻那个决定**是错的,**不声称**留下的 bot 接下来
   十秒活了下来。
