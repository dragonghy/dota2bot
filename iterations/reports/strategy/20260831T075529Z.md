## 1. ⭐ 主判据:`margin(stayfield2) = S ∧ (¬T3 ∨ ¬T5)` —— 闭式,零语料

`stayfield2` 的**唯一**调用点是 `bots/mode_retreat_generic.lua:236`。它**上一条语句**是

```lua
if J.ShouldStayAndRegen(bot) then
    return BOT_MODE_DESIRE_NONE
end
```

—— `tphome` 的**已 promote、无 gate、每一局 Turbo 都活着**的那条。两者之间**没有任何可执行语句**
(已断言:切片里 `end` 恰好 1 个、`if` 恰好 1 个)。于是 `stayfield2` 只能在 `ShouldStayAndRegen` **返回 false** 的帧上说话。

把两边的子句对齐(两个 HP 带读的是**同一个** `J.GetHP`,已断言,所以不需要换算):

| | S = `ShouldRegenNotGoHome` | | T = `ShouldStayAndRegen` |
|---|---|---|---|
| S1 | `IsModeTurbo` | **==** | T1 `IsModeTurbo` |
| S2 | `hp ∈ [0.18, 0.55]` | **⇒** | T2 `hp ∈ [0.18, 0.75]` |
| S3 | `#heroes(1600) == 0` | **⇒** | T4 `#heroes(1200) == 0` |
| S4 | **归因**的英雄伤害 | ? | T3 3 秒内**任何**英雄伤害 |
| S5 | 1200 内无敌塔 | — | (T 无此子句) |
| H | `HasFieldRegenSource` | ? | T5 主槽大药 / 回复 buff / 90 金 |

**T 的五条子句里三条被 S 蕴含** ⇒

> **`margin(stayfield2) = S ∧ (¬T3 ∨ ¬T5)`**

**这句话的用处是它排除了什么**:**HP 带和距离环 —— 这一族每一次读数都在按它们分层的两个量 ——
永远不可能是一帧落进 `stayfield2` 边际域的理由。** 把 0.55 天花板放宽到 0.70 一帧都不动
(那些帧 T 已经吃掉了);要放到 **0.75 以上**才开始有区别,而**即便那时也仍然只在 `¬T3 ∨ ¬T5` 里**。

**这是对本组自己 GH #342 §3 的更正。** #342 §3 是这样刻画走路腿的:在 `function GetDesireHelper()`
与 `J.ShouldRegenNotWalkHome(bot)` 之间扫**词元** `botHP`,只扫到一处(对人局才走的开局梯子),
于是结论「走路腿上两条边都是活的,`hp>0.55` 在那里是真桶不是伪影」。
**词元扫描看不见一条住在函数调用后面的子句** —— `ShouldStayAndRegen` 读的正是 `J.GetHP`,
带着自己的 `0.75` 帽,只是它写成一次调用而不是一次比较。
(#342 关于 **TP 腿**的结论不受影响,本轮**不重开也不反驳**它;更正的是它对**走路腿**的那一句。)

## 2. ⭐⭐ 而且方向不是这个守卫的名字说的那个方向

`bots/mode_retreat_generic.lua` 的出价函数以

```lua
return Min(nDesire, 1.0)
```

结尾 —— **只夹上界,不夹下界**;而它内部有两处减法(`- 0.25`「周围没人且没塔」、`- 0.75`「对线期、没挨打、没被锁定」,
两个常数从源码 parse,和 ≥ 1.0 已写成断言)可以把和推到零以下。
⇒ **凡是排在这段算术之前、用常数 `BOT_MODE_DESIRE_NONE`(0.0)提前返回的守卫,在任何自然出价为负的帧上都是在把出价抬高。**

实测(下节):`stayfield2` 的 19 帧边际域里 **14 帧是抬高、5 帧是压低**。
**同一条算术逐字适用于它上面那条已 promote、发货中的 `ShouldStayAndRegen` 行。**

⚠️ **诚实边界(已写成 `[limit]`)**:引擎在「所有模式都出价 ≤ 0」时怎么仲裁**不在本仓**,
所以「抬高出价」在这里是**算术**,不是「机器人于是会撤退」。它排除掉的是**反向读法** ——
「这个守卫只会压低本模式的出价」—— 而那正是守卫的名字和注释都在邀请读者做的读法。
