## 1. ⭐⭐ 头条:`J.IsInTeamFight` 只读一张表,而那是**我方**的表

`bots/FunLib/jmz_func.lua:1453`(出厂,逐字):

```lua
function J.IsInTeamFight( bot, nRadius )
	if nRadius == nil or nRadius > 1600 then nRadius = 1600 end
	local attackModeAllyList = J.GetNearbyHeroes(bot, nRadius, false, BOT_MODE_ATTACK )
	return #attackModeAllyList >= 2 -- and bot:GetActiveMode() ~= BOT_MODE_RETREAT
end
```

**闭式,不需要抽样**:唯一那张表的第二个实参是 `false`,即 **`bEnemy = false`** ——
**这个函数体里没有任何敌方项**:没有敌方列表、没有敌方计数、没有 last-seen 读点。
⇒ 「我旁边两个队友在打对面」与「我旁边两个队友处于 attack 模式而这个圈里一个敌人都没有」
**是同一个答案**。后者不是团战 —— 那是五个 bot 推线 / 清野 / 追兵线的样子。

**为什么这不是一个便宜的代理**:它的 **313 个调用点(133 个文件,其中 16 处取反;数法:屏蔽行注释后数 `IsInTeamFight` 的出现,314 次减去定义那一行)**
问的都是「**我周围**在不在打团」,而且各自挑了半径。一个处于 attack 模式的队友说明
**那个队友附近**在打 —— 在 1600 这个半径上,那可以再远 1600。让两者一致的读数
**只有一个**:敌人在**调用方自己的圈**里。

**修法:一个 id `fightfoe`,turbo-only,单独 gate**(⛔ 绝不与第二个 id 合取 —— pullcad 陷阱)。
**⛔ 不发明任何常数**:合取问的半径就是 **`nRadius`,调用方自己传进来、函数自己已经在 clamp 的那一个**。
1600 的 clamp、`>= 2`、那张我方表**逐字未动**。

```lua
	if #attackModeAllyList >= 2
	and J.ShouldTeamFightNeedAnEnemy()
	and #J.GetNearbyHeroes( bot, nRadius, true, BOT_MODE_NONE ) == 0
	then
		return false
	end
```

**⛔ 方向由源码定死,不靠语料**:这条 veto 被 **`#attackModeAllyList >= 2`(出厂答案本身)**
挡在前面 ⇒ armed **只能把出厂的 TRUE 变成 FALSE**,**永远不能**把一个出厂说「不是团战」的帧
说成团战;出厂 TRUE 集合之外的帧**根本到不了第二张表**。

**⛔ 爆炸半径当场写明,不留给以后发现**:313 / 133,**远大于一条分支**,而这正是它
**gated** 出货的理由 —— 未 armed 时 `J.IsSoakCandidate` 是第一个被问的,第二次引擎调用
**根本不发生**,返回的表达式就是出厂那一句。与一天前落在姊妹谓词 `J.WeAreStronger` 上的
`fightstate`(56 个调用点)**同形、同论证**。

**⛔ 一个杠杆**:那条**出厂就注释掉的** `-- and bot:GetActiveMode() ~= BOT_MODE_RETREAT`
(作者自己写下又注释掉的**第二个**缺失合取)**原样留在注释里**;§1 两头都钉:注释必须还在,

## 3. ⭐⭐ 本轮最贵的一条,而且是被**交换腿**抓住的:同一次 load 上做 A/B,量的是缓存

§4 第一版按惯用法在**同一次 load** 上读两个答案:armed 读完,把 `GetGameMode` 翻回 22
再读一次当作 shipped。**那个读数是空的** —— `J.IsModeTurbo` 在首次调用时把答案记进
模块级 `bModeTurboCache`(`jmz_func.lua:13236`),第二次调用返回的是**第一次的答案**,
于是 `shipped` 在**每一帧**上与 `armed` 逐位相同。

⇒ 现场读数是 **`down = 0`**,而 **`up` 也是 0** —— 如果只断言 `up == 0`
(「方向没跑反」),**这一版会绿着过去,并且长得和真的一模一样**。
**抓住它的是交换腿的那半**:`assert(down > 0, '否则另一个方向的 0 什么都不证明')`。

📌 **可迁移句(0NEXT37 备选)**:
**对一个会 memoise 的谓词做「同一次 load 上翻开关」的 A/B,量到的是缓存不是杠杆;
而它的失败形状是【两个方向都读 0】,恰好与「方向完美」不可区分。**
⇒ **规矩**:armed / shipped 两个答案**必须来自两次真实 load**(开关在场 / 开关不在场),
并且**交换腿那一半必须断言非零**。与 0NEXT36 的控制腿是**同族**:
那条管「全抓可能是假阳性」,这条管「全零可能是假的完美」。

**改法**:`corpus()` 改成**两趟真 load**(pass 1 在 `with_candidate` 里,pass 2 在外面
并先跑 `ss.assert_clean`),按 `fixture|hero` 配对后再 tally。
读数:**`down > 0`、`up == 0`、`down == flippable`**(flippable = 出厂 TRUE ∩ 敌方圈空
∩ **gate 对这个 bot 是开的**),外加 `flippable < 46` —— **开关是按侧生效的**,
这一条把「这一趟只 arm 了一侧」也变成被断言的事实,而不是假设。
