## 2. ⭐ 主判据:`nLane == nil` 是一条条件不可达的守卫

`bot:GetAssignedLane()` 只答四个**文档常数**(`docs/BOT_API_REFERENCE.md:1910`):

```
LANE_NONE = 0    LANE_TOP = 1    LANE_MID = 2    LANE_BOT = 3
```

引擎说「这个 bot 没有路」用的是 **`LANE_NONE`,那是数字 0,不是 `nil`**。
`J.ShouldPullNeutralCamp` 里写的却是:

```lua
local nLane = bot:GetAssignedLane()
if nLane == nil then return nil end
local vFront = GetLaneFrontLocation( GetTeam(), nLane, 0 )
local vMid   = GetLocationAlongLane( nLane, 0.5 )
```

⇒ 守卫的条件**不可达**,而它本要拦下的状态径直走进 `GetLaneFrontLocation` /
`GetLocationAlongLane`,当作一个这两个函数解析不了的 lane id。

**⭐⭐ 这不是新观察,而这正是它的分量所在。** 同一个形状从 **20260822** 起就写在
`tests/test_pullcamp_trigger_census.lua` 的第四条 STOPPER 里,原话:

> `bot:GetAssignedLane()` is 0 on 930/930 … **It is not nil, so the `nLane == nil`
> guard passes and a bogus lane id is handed to `GetLocationAlongLane`.**

它当时被归档成一条关于**加载器**的事实(「链子为什么不能端到端驱动」),于是
`bots/` 一个字没改,十八天。**同一句话读成关于守卫的事实,说的就是这条守卫开不了火**
—— 这是 `pullcamp` 这一族**第三次**同类缺陷:GH #13 的视野子句、GH #277 的 800 否决、
本条。三次都是「一条子句从来没被定过价」。

### 读数(1021 活帧,两列分别读字面 0 与读常数)

| 列 | 读数 |
|---|---|
| `lane_nil` | **0 / 1021** —— 已发布的守卫**一帧都开不了火** |
| `lane_none`(`lane == (LANE_NONE or 0)`) | **1021 / 1021** —— 它本要拦的状态每一帧都在 |
| `lane_zero`(`lane == 0`,字面) | 1021 —— 与上一列断言相等 |

### 差分(同一个已发布函数,驱动两次)

| 列 | disarmed | armed(`pullcamp` + `pullnolane`) |
|---|---|---|
| 落到守卫下面那行并 raise | `spnc_raise_lanefront` **18** | `guard_raise` **0** |
| 干净 nil | `spnc_nil` 1003 | `guard_nil` **1021** |
| 返回营地 | `spnc_nonnil` 0 | `guard_nonnil` 0 |
| 差分 | —— | **`guard_closes` 18** |
| **禁止方向** | —— | **`guard_opens` 0** |

两次驱动**各自对全语料闭合**:`spnc_nil + spnc_raise == guard_nil + guard_raise
== frames == 1021`。18 帧逐帧登记为 `GRD` 行(见 manifest)。

**⭐⭐⭐ 判读器是把 STOPPER 3 反过来当仪器用,所以整条差分零声明。**
加载器**拒答** `GetLaneFrontLocation`(GH #61),而那次调用紧挨在守卫下面 ⇒
一次点名 `GetLaneFrontLocation` 的 raise 就是「守卫**放行**了这一帧」的**正面证据**,
同一位置上的一个干净 nil 就是「守卫**拦住**了」的正面证据。
**需要先声明一套 lane 几何才能看见的普查,量的是自己的声明。**

## 4. ⭐⭐⭐⭐ 同轮改了 `tests/mock/bot_api.lua`,而这不是越界

mock 的哨兵表把每个未知 ALL_CAPS 全局**自动编号**,于是 fixture 世界里
`LANE_NONE` 读 **1024**、`LANE_TOP` 1025、`LANE_MID` 1026、`LANE_BOT` 1027。

一个**表达不出「没有路」这个状态**的 mock,**测不了**针对它的守卫;更糟的是
`== LANE_NONE` 在 fixture 世界里为假的**理由与帧无关**。

这与同一个文件**上面三行**已经钉住的 `TEAM_RADIANT` / `TEAM_DIRE` 缺陷**逐字同族**
(哨兵让 `Team == TEAM_DIRE` 恒假,于是每个 Dire 主体被交给 **Radiant** 泉水,
「撤退/后撤到泉水」全指错了地图角)。修法同修法:把四个常数钉到文档值。

**两个方向都断言**(= 文档值,且**不在 >=1000 的哨兵段**),所以将来再哨兵化
**会红,不会变哑**。第一次量出来的形态就是本轮的实测:改之前
`lane_none` 读 **0**(因为 1024 ≠ 0),改之后读 **1021** —— 同一份语料,同一行代码。
