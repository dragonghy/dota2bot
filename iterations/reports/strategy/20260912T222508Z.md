## 2. ⭐⭐ 本轮最该被下一轮读到的三句

### (甲) ⭐⭐ 替换 `os.exit(1)` 的那个守卫,比 `os.exit` 本身重要 —— 因为没有它,**死掉的量具会免费证成本文件最核心的结论**

旧文件在普查子进程没打 `DONE` 时 `os.exit(1)` 退出。转 runner 协议时最容易的写法是**直接删掉它**
(runner 没有这个逃生口),而那样**不是等价改写**:

```lua
C.oc_a_pass_tight == C.oc_a_pass      -- 普查死了 ⇒ nil == nil ⇒ TRUE
```

这一行是整份文件**唯一一个用能工作的量具取到的定价**(GH #760 四个收窄里唯一的那个),
而一个**死掉的普查**会让它**恒真**。即 GH #171 形状:零不是读数,是「没测」。
⇒ 每一个读计数的用例**第一句**调 `census_or_die()`,普查死了就大声红,而不是安静地报 no-op。

**这不是推测,是被钉住的**:新增 **M8** 杀掉普查,**要求失败列表点名的是「no-op 用例」而不仅仅是「census 用例」**
—— census 用例无论如何都会红,**只有 no-op 用例被点名**才能把「守卫在场」和「守卫承重」分开。
实测点名 `FAIL[11]: ... :: [no-op] the tightened pursuit lookback refuses NOTHING`。

### (乙) ⭐⭐ 旧 M5 的**标的**在 runner 协议下不是被换了个记分法,是**整个消失了**,而它消失是因为缺陷被**结构性**修掉

旧 M5 复原的缺陷是:上报走全局 `print`,而 `tests/mock/bot_api.lua:415` 在 fixture 加载时把它设成空函数
⇒ §6 起每一行(**包括 FAIL 行**)被吞,退出码仍是 0。它**动不了退出码**,所以按**完成标记的缺席**计分。

runner 协议下这两半**都没了**:runner 走 `io.write`/`io.stdout:write`(mock 不碰),自己计数自己点名;
「完成标记」在一个不为自己上报的文件里没有位置。
⇒ 新 M5 的标的换成**结构本身**:把私有 harness 装回去(跑自己的用例、打自己的汇总、不 `return tests`),
要求 **runner 自己的 FAIL 行**点名这次违约。实测:
`contract error: the file returned nil, not a table of tests.`

⚠️ **新 M5 故意不用 `os.exit` 那一变体**,尽管原缺陷就是它:变异台是**往被 git 跟踪的文件里写真缺陷**,
一次被打断的运行留下的 `os.exit` 是 GH #418 那个泄漏里**载荷最坏的一种**。
不可上报的那一变体由 `tests/test_run_tests_guard.py` **静态**盖住;
**变异台只能给能被上报的东西记分** —— 这条分工写进了台子的抬头。

### (丙) ⭐ 「§7 那条 print 断言」不能按活体探针写,否则它测的是**跑法**不是代码

旧文件末尾有一条 `print ~= say` 的活体断言(「全局 print 真的被抹了,所以 say 是承重的」)。
照搬进 runner 协议会**随过滤器时红时绿**:runner 把 ~100 个用 fixture 的文件按**字母序**装进同一个进程,
全量跑时轮到本文件,全局 `print` 通常**早已被别人抹了**。
⇒ 改成对 **mock 的源码**断言(`G.print = function() end` 还在),
它说的是**为什么** tests/ 里任何文件都不许用 print 上报,而不是这一次是谁先跑的。
