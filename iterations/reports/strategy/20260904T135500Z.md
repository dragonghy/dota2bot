## 1. 发现

`J.ShouldTpSupportTowerFight`(`midtp` / `suptp` 共用的塔防响应 helper)里,
核心让路的那一行问 `J.HasAvailableSupportResponder( bot )`。该谓词的头注写:

> "Viable responder" mirrors, **member by member, the exact gates** the support would itself
> have to clear inside J.ShouldTpSupportTowerFight … so this **can only REALLOCATE** a response
> to a support, **never DROP one**.

镜像抄了 7 条:活着 / 有效英雄 / pos ≥ 4 / lvl ≥ 6 / TP 或旅行鞋就绪 / 不在团战 / 不在撤退。
**响应者循环还有一条它没抄**:

```lua
and GetUnitToUnitDistance( bot, building ) > 3500   -- 远到只有 TP 才来得及
```

**这一条谓词问不出来** —— 它不收 building 参数。⇒ 一个**站在那座塔边上**的支援
满足其余全部子句、而它自己那一趟 `ShouldTpSupportTowerFight` 会在这一行**把那座塔跳过**。
核心让给它 = **DROP**,不是 REALLOCATE。

## 3. ⭐ 主判据(立法级,可复用,超出本主题)

> **一个「逐条镜像」的安全论证,强度等于镜像的完备性;
> 而它唯一漏得掉的那一条,恰恰是唯一说出「交出去的是什么」的那一条。**

镜像里那 7 条全是**支援单独一个人的性质**;漏掉的那条是**配对的性质**。
**一个不收 building 的谓词按构造问不出配对的性质** —— 而这次仲裁**本身就是一句关于交接的断言**。
⇒ 漏掉的不是「八条里的一条」,是**唯一一条与被断言的那件事同构的**。

**可操作的一半**:凡「A 让位给 B」型的仲裁,先问
**「决定 B 合格的那个谓词,看得见 A 让出去的那个东西吗?」**
看不见 ⇒ 安全论证到此为止,不管剩下几条对得多齐。

与 `campbind`(GH #475)是同一枚硬币:那次**下游一个「最近者」撤销了上游四条否决**,
这次**上游一次「谁合格」的判断从没被告知下游在交接什么**。

## 4. 那句假话出现过的三个地方

1. 源码注释(`jmz_func.lua`);
2. **它自己测试文件的文件头**;
3. **总监的条件性批准**(`state.json:AX.5_strategy5b_midsupyield`:
   "Direction is bounded by construction (can only REALLOCATE …, never drop one) … => approved")。

三处不是抄错,是**同一个论证被复述了三遍**,而支点只有「镜像是完备的」这句自述。

## 5. ⭐⭐ 波次级负控写对了,却回答不了它自己命名的那个问题

`queue.json:strategy-5b` 的 acceptance 里早就写着:

> NEGATIVE control … total tower-defense TP responses must NOT collapse toward 0
> (that would mean cores yield but supports do not pick up = **a DROPPED response**,
> the emergent risk this gated read exists to catch)

**那句话命名的正是本轮的缺陷。** 两件事同时为真:

1. **它从未被买过** —— `midsupyield` 至今不在任何一波的 armed 串里(W6 从没按这条发过);
2. **更要紧的**:它命名的风险**根本不需要一次波次** —— fixture 级就答得出,
   而且答案不是「有没有风险」,是**「定义域的一半」**。

⇒ **一道波次级负控不该花在一个 fixture 已经能回答的问题上。**
与 `0CORP` 的「只能证伪的读数必须在选杠杆之前跑」同族,**方向相反**:
那条管**别做**,这条管**别等**。

## 6. 修法(一次一个杠杆,**故意不开第二个 id**)

- `J.HasAvailableSupportResponder( bot, hBuilding )`:新增合取项
  `GetUnitToUnitDistance( hAlly, hBuilding ) > J.TP_RESPONSE_FAR_FLOOR`;唯一调用点传 `building`。
- 响应者循环里的字面量 `3500` 与谓词**共用新常数** `J.TP_RESPONSE_FAR_FLOOR = 3500`
  (**值逐字节沿用,不是新推导**)。理由:两份拷贝就是两个会再次走散的东西,
  而本条修的缺陷正是一面走散了的镜子。普查把「循环读的是常数名而不是重新内联的字面量」钉成断言。
- `hBuilding == nil` ⇒ `return false`:**说不出塔名的调用者朝「不让路」失效**,而不让路就是出厂答案。
- ⛔ **没有新 soak id**。`IsSoakCandidate('X') and IsSoakCandidate('midsupyield')` 会在任一 id
  promote 当天冻结为 FALSE(`pullcad` 陷阱)。`midsupyield` **从未在任何一波里 armed 过**
  ⇒ 改它的函数体不作废任何一波的读数 —— 这是**能不开 id 的前提条件,不是偏好**。

**方向**:合取项 ⇒ 被接受的支援集合是**严格子集** ⇒ armed 让路的帧**严格变少**
⇒ 只可能推向出厂。正因如此**承重的那一半是阳性对照**:death_prophet 帧必须**仍然让路**,
否则一个「永远答 false」的谓词就能满足全部否定断言,而那是把 id 弄死不是修好。

  `G.FAR_FLOOR` 变 nil,`far` 恒假 ⇒ `sup_far 0 / sup_near 2`,

  ⇒ **一台不能与树意见相左的普查,测的是它自己。**
- **(ii) `[premise]` 那条腿第一版在测空气。** 它只断言 `(bot, nil) == false`,
  而**把 nil 守卫删掉它照样绿**(M6 存活):没有守卫时循环照跑,
  `GetUnitToUnitDistance(hAlly, nil)` 在 mock 下答一个垃圾数,`垃圾 > 3500` 为假,
  于是**用错误的理由得到正确的答案** —— 而那个理由**引擎不认**
  (nil 句柄在一个吞掉报错文本的错误处理器里抛;AGENTS.md「无 bot 侧调试」)。
  改法**不是加断言,是驱动守卫**:换掉距离读数器让它拒绝 nil,守卫必须让它**一次都不被调用**。
  与 #397 的 M2 / #400 的 M4b / `slotarb` 的 M12 **同形,连着第四次**。

## 9. 顺带被一条常设棘轮拦下的一次(值得记一笔)

(`IsSoakCandidate('midsupyield') and IsSoakCandidate('midsupfar')`),

本仓已经有 `'X'` 这个元变量专门用来陈述这条陷阱(`jmz_func.lua:1982`),
