## 1. 第九条世界断言:**「这个世界里,任何地方都没有任何单位」**

`tests/mock/replay_fixture.lua` 的 `GetUnitList` 只回答 `UNIT_LIST_ENEMY_HEROES` 和
`UNIT_LIST_ALLIED_HEROES`,其余一律落到 `return {}`。于是
**`GetUnitList(UNIT_LIST_ALL)` 在每一个 fixture 里都是空的** —— 不是「没有小兵」,是
**连英雄都没有**。

与 `HasModifier` / `WasRecentlyDamagedBy*` / `GetHeroLastSeenInfo` / 建筑那几条同族
(test_set.md §F):**harness 给了一个确定的错答案而不是拒答**,所以测试可以断言错的东西还全绿。

`bots/` 下 `UNIT_LIST_ALL` 精确匹配 **11 个**调用点,其中两个分量极重:

- **`mode_retreat_generic.buildContext()` 的两张英雄表都从它来** ⇒ 每个 fixture 每一帧
  `#nAllyHeroes` 和 `#nEnemyHeroes` 都是 **0**,退却出价里整段「我是不是被人数压制」
  **拿 0 和 0 比**;
- **`J.WeAreStronger(bot, r)`** 在它上面累加双方战力 ⇒ 每个 fixture、每个半径,
  **空队伍对空队伍**。

**修复(restoration,不是 modeling)**:`UNIT_LIST_ALL` 现在返回两队的存活英雄,**包含自己**
(引擎就是这么报的,这正是活着的 bot 的 `#nAllyHeroes` 永远不为 0 的原因)。英雄位置是 dump 的
ground truth。

**故意没伪造、写成断言的部分**:引擎的 `UNIT_LIST_ALL` 还带小兵、建筑、信使、眼、召唤物。
dump 里有小兵(3 秒采样、无路别、无存活位)但生成器不写;**建筑也故意不注入** —— 唯一会捡起它们的
已发布消费方(`buildContext` 的塔威胁子句)要 `GetAttackDamage() * GetAttackSpeed()`,dump 不带。
所以**凡是需要通过 `UNIT_LIST_ALL` 看见小兵/召唤物/塔的断言,读到的仍是空集,必须明说**
(`tests/test_fixture_unit_list_all.lua` 里有一条 `LIMITATION` 用例把这句钉住)。

**没有任何历史结论翻面**:接线前后全量 **714/714**。(但今后关于「附近有几个人」的断言,
必须晚于本次修复才算数。)

## 2. 缺陷本体(gated `retnear`)

`mode_retreat_generic.GetDesireHelper` 里:

```lua
local nEnemyNearbyCount = #nEnemyHeroes        -- buildContext,半径 1600
local nAllyNearbyCount  = #nAllyHeroes         -- 同上,半径 1600
-- ...  bWeAreStronger = J.WeAreStronger(bot, 1600)
local unseenCount = 0
for _, id in pairs(GetTeamPlayers(GetOpposingTeam())) do ...
    if dInfo ~= nil and GetUnitToLocationDistance(bot, dInfo.location) <= 3200
       and dInfo.time_since_seen <= 5.0 then unseenCount = unseenCount + 1 end
end
if unseenCount > #nEnemyHeroes then nEnemyNearbyCount = unseenCount end   -- ← 覆盖
```

覆盖之后,下面两条比较的**左边是 3200 半径的数,右边是 1600 半径的数**:

```lua
if nEnemyNearbyCount - nAllyNearbyCount > 0 then  nDesire = nDesire + 差 * 0.1875 end
if not bWeAreStronger and nEnemyNearbyCount >= nAllyNearbyCount then nDesire = nDesire + 0.25 end
```

**r=3200 是 r=1600 的四倍面积**。所以这个出价偏向「我被人数压制」是**几何造成的,不是局势造成的**:
**站在我 1700 外的队友抵不掉 3100 外的敌人**。而且 3200 已经超出 bot 自己的白天视野(1800)——
宽计数在 1800 以外加进来的每一个敌人,都是**队友**看见的,也就是**离队友近、不是离我近**的那个人。

### 依据 (c)(逻辑/理论)

不是「不该看远处」,而是**做比较的两边必须是同一次测量**。函数里其余每一个量都用 1600
(两张英雄表、`J.WeAreStronger`),只有这一个数被换成 3200 再送进去比。宽视野的危险信号本身是
合理的 —— 它在下面那条「四周什么都没有就减 0.25」里用得**正好**(那条本来就要宽地平线),本轮
**原样保留**。

### 改动

armed 时,**可能替换 nearby 计数的那个数按 1600 取**;宽计数照旧计算、照旧喂给下面那条折扣 ⇒
**只动一个杠杆**。armed **只可能压低或维持**退却出价,不可能抬高。只改 `bots/mode_retreat_generic.lua`
(`mode_*` 没有 TS 源)。

### 没走的那条路

另一种对称化是把**队友那边放宽到 3200**。否掉:`nAllyNearbyCount` 还管着下面
Oracle / Dazzle / Satanic / Slark 那一整块折扣,一动就是好几个杠杆;而且引擎对队友根本没有
last-seen 这个原语(队友对自己人从不在雾里),两边**仍然不是同一次测量**。

### 钉帧

全在 1600–3200 那个环上。5 秒内没有任何英雄碰过它(它在挨小兵打)。

**GROUND TRUTH(记下来,不当论据)**:t=641 起那个 axe 往回走(x 从 −2335 → −3727 → −326),
**t=655 到 t=675 之后一直站在 (−326, 5860) 不动,血 97%**;接下来 5 秒没有任何敌方英雄对它造成伤害

skywrath **188**、slardar **741**,都在 1600 **以内**。近计数 == 宽计数 ⇒ **armed 逐位相同**

**第二帧 `f_260820_043140_luna_ring_bid`** —— **足迹的诚实那一半**:armed 把出价砍掉 0.4375
(0.7767 → 0.3392),**但退却仍然赢下竞价**(该帧第二高只有 0.1)。**出价变低 ≠ 决定变了。**

### 关于 GH #61 的纪律(本轮的正面结果)

按 backlog 第 0z 条的规矩,凡是断言最终出价的用例都要先跑「把 lane front 挪离原点」这个变异。
**跑了,三个不同的非原点位置,结论全部不变**:shipped 仍选 retreat、armed 仍选 laning 0.369,
两个退却出价**逐位相同**(退却 mode 本身不读 lane front)。而且**变异是活的**——它把
`mode_defend_tower_top_generic` 从原点桩下的 0.1275 挪走了。这一条**写成了断言**。

也就是说:**与上一轮的 `defclose` 不同,`retnear` 的最终出价结论不是骑在 #61 的桩上的**,
所以本轮**可以**按 test_set.md §8 申请入集。
