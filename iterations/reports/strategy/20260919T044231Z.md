## 二、缺陷

`bots/ability_item_usage_generic.lua`,`X.ConsiderBuyback`(买活路径 1):

```lua
local nEnemyUnitsAroundAncient = J.GetEnemiesAroundLoc( ancientLoc, 1500 )  -- 返回 NUMBER
local nAllyUnitsAroundAncient  = J.GetAlliesNearLoc(   ancientLoc, 1500 )  -- 返回 TABLE
if nEnemyUnitsAroundAncient > 1 and nAllyUnitsAroundAncient == 0 and nRemainingRespawnTime > 20 then
    bot:ActionImmediate_Buyback()
```

两个**同命名模式**的局部量,**相邻两行**,**同一个位置、同一个半径**,而它们不是同一种东西:
`J.GetEnemiesAroundLoc`(`jmz_func.lua:15614`)返回一个按等级加权的**计数**,
`J.GetAlliesNearLoc`(`jmz_func.lua:474`)返回一张**英雄表**。
于是第二项逐字是 `{} == 0`。

### ⭐ 为什么它从来没有举手:它坐在唯一不会报错的那个运算符上

Lua 5.1 里跨类型的**序**比较抛错,跨类型的**相等**不抛 —— 不同类型直接判不等,静悄悄。
本容器实测(`lua5.1`,报告里这两行是跑出来的不是记住的):

```
({}) == 0   -->  false          -- 没有错误
({}) >  1   -->  error: attempt to compare number with table
```

**一个运算符之隔的兄弟项就是 `>`**,它会在第一帧崩掉;这一项永远不会。
而这棵树的引擎侧错误文本本来就读不出来(AGENTS.md:`error in error handling` 吞掉全部 Lua
错误文本,没有 bot 侧调试)⇒ 即使它抛了也未必有人看见,**而它连抛都不抛**。

### ⛔⛔ 它吃掉的不只是自己那一项

包住它的外层 `if` 是 `J.IsAncientBadlyHurt` —— **已在册的 soak candidate `bbancient`**:
出厂把**绝对 hp** 和 `0.8` 比,同样恒假(那条 helper 自己的 header 写得清清楚楚:
*"buyback path 1 is dead code"*)。
⇒ **arm `bbancient` 打开外层之后,落在本项上,分支仍然不能触发。**
一波只 arm `bbancient` 的测量会读回「测过了,没效果」,**而没有任何东西举手** ——
这正是 AGENTS.md 记在 `pullcad` 名下的失效形状,只不过这次的「第二道恒假闸」
不是一个 gate,是一个类型错误。

## 三、⭐⭐ 本轮买到的可迁移句

> **一个表和一个数比较,不是一个计数 —— 而 `==` 是唯一对此毫无意见的运算符。**
>
> 判据:读到一个**跨类型的相等比较**,先问「这两边真是同一种东西吗」。
> 序比较会替你问(它抛错),相等比较不会。**一个静悄悄的恒假,和一个正确的否定,
> 在源码上逐字一样长。**

配套的第二句,关于**命名**:

> 两个局部量命名成同一个模式(`nXUnitsAroundAncient`)、写在相邻两行、读的是同一个位置和
> 同一个半径 —— **命名的对称恰恰是遮住类型不对称的那块布**。

第三句,关于**断言**(本轮变异台第一遍买来的):

> **一条被支配的断言等于没断言。** M9(调用点改传 `bot`)红了但消息不对,
> 因为为它写的那条断言被前面的语义钉**支配**了:正模式对**任何**不是调用点自己那张表的
> 实参都已失败 ⇒ 那条断言**永远不会触发**。⛔ 处置**不是改 `want`** ——
> 是**删掉被支配的那条**,把该主张里没被支配的那一半(helper 不得自己造表)钉在别处,
> 并把 M9 换成「helper 自己造表」。

- **`lua gate: 440 ran, 0 findings, 0 uncertifiable, 9 unanswered, 5 known-red, 673.6s`**

⭐⭐ **RULING 69 那条「先分支、再 main」本轮被实测证实了一次,而且是从失败那一侧证实的。**
前**两次**我只做了 `pull --rebase` 然后**直接推 main**,两次都在 lua 腿跑完的 ~11 分钟之后被
`cannot lock ref 'refs/heads/main'` 顶回来(main 在这 11 分钟里各被别的组推了一次)——
**每一次都白付 673s**。第三次改成**先推分支、再推 main**:分支那一推付了 673.6s,
