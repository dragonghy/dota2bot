## 1. 头条:代价大的那一半不在核心站点,在 support 站点

上一轮的 `denyreach` 修的是核心对线 Think 的 deny 分支:读 1200 环、**零距离项**、

测**两次**距离。那一轮把第二条代价(分支 `return`,排在 `J.IsLaneFrontTooDeepToHold`

**本轮的发现是:同一个第二条代价,在 support 站点上严格更大 —— 大四倍,而且可以逐个取偏移证明。**

`DoSupportLaningThink` 的 deny 分支是该函数的**第一句**,于是它 `return` 在**四个**后续块之上,
每一个都是有人专门加的决策:

| 被跳过的块 | 它是谁加的 |
|---|---|
| uncontested last-hit | support 在线上唯一的金钱来源(`suplh`/GH #14 的整个立案点) |
| harass 块(及其下 `l5trees` 的离线走位) | 对线压制 |
| `lanefix` 的 screen-the-carry 块 | **终局波被拒之后特意收窄过的那一块**(不许贴身站核心,改成朝自家泉水退 400u) |
| 兵线站位块,末句 `J.IsLaneFrontTooDeepToHold` | mega-bundle 复盘的反过伸夹子(051728 ogre 在 +4217 一个人守被推深的兵线而死) |

而被这条命令带着往兵线深处走的单位是**辅助**:全场血量池最小的英雄,朝敌方兵线走,
去打一次它按时间根本到不了的攻击(300 移速走 1000u ≈ 3.3s,远长于一只 <49% 血、
正在挨打的兵的存活时间)。**条件 (c)** 不需要辩护任何新东西:deny 的窗口是
「对一只**已经在射程内**的兵的一次攻击」,而那正是几行之外的姊妹分支已经在编码的规则。

**修复没有引入新常数,也没有新谓词形状**:`J.ShouldDropOutOfReachSupportDeny` 的本体

## 2. ⭐⭐ 本轮真正该带走的读数:**这个 id 单臂 arm 测到的是结构性的零**

这不是我事先想到的,是**开工自检自己抓出来的**:落地之后

## 3. 两个 id 的独立性,是**量出来的**不是**论证出来的**

树上现在有两条**逐字节相同、只差 id** 的谓词,挂在两个调用点、两个 armed 人群后面。
**结构断言分不出「正确的一对」和「已经悄悄塌成一个杠杆的一对」。** 所以:

- **源码侧两个方向都钉**:姊妹文件断言 support 分支**不点名** `J.ShouldDropOutOfReachDeny`
  (并且确实带着**自己**那个 helper);新文件 1e 断言核心 Think **不点名**
  `J.ShouldDropOutOfReachSupportDeny`。缺任一半,「一个 id 一个调用点」只在一个方向上成立。
- **行为侧 2b 两条交叉 arm 腿**:arm 其中一个 id,**两个** helper 都驱动一遍,
  要求「自己的动(4 drop,非空)、对方的不动(0 drop)」。
- **变异台 M6**(把姊妹 helper 改成 gate 在本 id 上)**只有这两条腿抓得住** ——
  section 1 的每一条结构断言在它之下**全绿**。

**⛔ id 不叫 `supdenyreach`,这不是风格选择**:那样 `denyreach` 就是它的子串。
运行期匹配器是精确相等,游戏侧没问题 —— 但**任何未加锚的 grep**(armed 串、verdict 表、
`state.json`、`test_set.md`)都会把「arm 了这个 id 的波」读成「也 arm 了核心那个 id」,
而 per-id 可归因正是有两个 id 的**全部理由**。`pullcad`(GH #622)的表亲:
**一个读起来像另一个 id 的 id,伤害由读者造成,而且是静默的。** 已写成断言(1f)。
