## 2. ⭐ 主判据:检测器报了 **1** 条,同一个缺陷在树上有 **4** 条

`test_corpus_scale.lua` 的检测规则逐字是「**一个等于今天的 fixture 数的整数字面量**」。

落地第 109 个 fixture 把它瞄准了一个伤害总和 109)。**本轮量到的是同一个性质的另一半 —— 漏报。**

**1/4。**

**⭐ 而这是这一族的第 4 次,前一次就在五天前、由总监修的。**

GH #106(5 文件)→ GH #127(7 文件 / **18 断言**)→ **2026-09-02 总监**修

## 3. 修法:四条全部走 `tests/corpus_scale.lua`,域内计数**一个都不软化**

分母走模块,**发现本身留等号**:

```lua
cs.ratchet(C.live, 1012, 'live hero frames')      -- 每 fixture 求和,只许涨不许跌
cs.corpus(C.fixtures, 'wkreinctr fixture corpus') -- 只许涨,跌破 FLOOR=100 报 SHRANK
```

**⛔ 没有动的:** `C.wk_frames == 36`、`C.ship_true == 24`、`C.arm_true == 10`、
`C.flips == 14`、`C.stop_*`、`C.wk_lv6 == 23`、`C.ship_true_untrained_lv6 == 2`、
`C.pair_ne_arm == 1`,以及全部恒零(`C.raises`/`C.arm_leak`/`C.fight_true`/
`C.site_*`/`C.flip_false_to_true`/`C.pair_ne_arm_in_flipset`)与全部恒等式
(`ship_true - arm_true == flips`、`in + out == pair_ne_arm`、stop 桶求和)。

**理由不是保守,是算术。** `corpus_scale.lua` 的立论是「行为改动表现为计数**下降**,
所以 ratchet 抓得住」——那条论证是对**追加 fixture** 说的,**对变异体不成立**:
本杠杆变异台里 **M6**(`GetLevel() >= 0` 换掉 `IsTrained()`,否决恒真)让 `flips`
从 14 **涨**到 24,**M7**(删掉调用点的 `bot:GetLevel() >= 6`)让 `ship_true_untrained_lv6`
从 2 **涨**到 14。**ratchet 对上涨一言不发。**
把域内计数一并 ratchet 化,就是拿检测器的绿换变异台的洞 —— 那正是本组
01:20Z 那轮在 `pair_ne_arm_in_flipset` 上刚付过一次钱的形状(M15 SURVIVED)。

⇒ **可复用的一条:`ratchet` 只对"重述语料规模"的量成立;对"这是我的发现"的量,
等号是它的量程,再基线化时手工抬,并在注释里说清楚重测了什么。**
这一条已写进三个文件的行内注释,不写进任何新规则(P4.3 的元规则:新增一条必须废除一条)。
