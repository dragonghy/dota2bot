## 1. 根因(一句话):触发器要求「已经站在营地旁边能看见小野」,而把人送到营地旁边正是这个行为本身要做的事

修复前 `J.ShouldPullNeutralCamp` 在授权任何东西之前先问:

```lua
local tNeut = bot:GetNearbyNeutralCreeps( 1400 )
if tNeut == nil or #tNeut == 0 then return nil end
```

即「拉野的人现在能**看见** 1400 内的中立生物」。**站在兵线上的辅助看不见**:野营盒子在树后、
无视野。于是 plan 永远不被设置;而 `mode_roam_generic` 的 Think **只有在 plan 已存在**
(`bot.roamCampPull ~= nil`)时才会走到那条「走向营地」的分支
(`Action_MoveToLocation(bot.roamCampPull)`)——**触发器等抵达,抵达等触发器**。

**这与 2026-08-19 修掉的勾线死分支是同一个形状**(`IsLanePullSafe` 要求 1800 内无敌人,
而 `ShouldCreepPullLane` 要求 1000 内有一个敌人当仇恨源)。**同一个 issue 的另一半**,
一年多没人问出来,因为它不报错、只是安静地返回 nil。

**owner 怀疑的那条不是根因。** `J.IsLanePullSafe` 在**全语料 334/911 帧**成立
(而且语料是按战斗瞬间采样的,和平期只会更常成立)⇒ **它不是死条件**,已成断言。
