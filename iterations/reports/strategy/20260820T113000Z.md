## 3. 缺陷本体

```lua
if bot:DistanceFromFountain() > 4000 then
    if (nEnemyNearbyCount == 0 and unseenCount == 0) and #nEnemyTowers == 0 then
        nDesire = nDesire - 0.25
    end
end
```

* 左半边标定过:1600 内无敌方英雄、3200 内无 last-seen 敌人。
* 右半边 `#nEnemyTowers` 是 `C.enemyTowers1200` ⇒ **1200 内有塔就否决**。塔的攻击距离 **700**。
  一座 1100 外的塔碰不到我;而此刻 3200 内一个敌人都没有 ⇒ **这一帧没有任何东西能伤害我**。
* **作者的原意有物证**:`buildContext` 里算了
  `C.haveEnemyTowerThreat = (1200 内某敌塔 5 秒输出 ≥ 我一半血)`,
  **全仓库三次写、零次读**(`grep -rn haveEnemyTowerThreat bots/ tests/ typescript/` 只有
  声明/复位/赋值三处)。**标定版本被算出来,然后被扔掉;接到消费方的是粗糙版本。**

§0b 家族的**又一个亚型**:不是句柄陈旧、不是计数陈旧、不是两边不同半径 ——
而是**同一个问题在同一个函数里有两份实现,精确的那份没接线**。

## 4. 交付:gated `towerreach`(turbo-only)

armed 时否决只数**够得着我**的塔,半径 **800** —— 这个数不是新发明的:
`RetreatWhenTowerTargetedDesire` 用 800 表示「我正站在敌塔跟前」,`ShouldRun` 用 898。
(700 与 800 实测差别很小:flip 帧 525 vs 500,取更保守的 800。)

**armed 的否决集合是 shipped 的子集** ⇒ 折扣只可能**更常**生效 ⇒
**出价只可能下降或不变,不可能上升**。不新增动作,不碰任何别的出价。**一次一个杠杆。**

**为什么不直接用 `C.haveEnemyTowerThreat`**(那才是作者的意思):塔的
`GetAttackDamage()/GetAttackSpeed()` **不在 dump 里**,任何 fixture 都答不出这个标志,
这个改动就**没有真实帧能验收**。这条局限已经写成断言(见 §7),dump 哪天带上这两个字段它就会 FAIL。

**方向依据 (c)**:塔的仇恨/攻击半径是 700,是 Dota 里最基础的一条硬边界;
「因为一座打不到我的塔在 1100 外,所以放弃地图往家走」不是任何人会打的策略。
在 Turbo 里代价还要更大:均局 ~11 分钟,回家一趟就是一大截地图。

**生效带**:这些帧上 3200 内没有敌人 ⇒ 上面整段「我是不是被人数压制」被跳过 ⇒
退却出价就是血/蓝的函数。对上 `mode_laning_generic` 常见的 0.369:
**armed 在有效血量约 1/5 以下仍然回家**,在**约 1/5 到 1/2 之间**不再为一座够不着的塔放弃地图。

## 6. 负结果 / 取不到的东西(如实记)

* **`ShouldRun:774` 的「空环也算被压制」缺陷,查到了但不能动**。
  `#nEnemyBrracks >= 1 and aliveEnemyCount >= 2 and #hEnemyHeroList >= #hAllyHeroList`
  —— 最后那个子句在**两边都是 0**(周围一个人都没有)时**恒真**,而它把出价推到
  `BOT_MODE_DESIRE_ABSOLUTE * 1.1`(全系统最高、压过一切)。
  白话:**一个人站在敌方兵营边上、周围没有任何敌人,只要对面还有 2 个人活着,就被强制往回赶 2 秒**
  ——每 2 秒重评一次,条件不变就是一把永远打不开的锁。
  **但 5 局 63,350 帧里没有任何一帧把英雄放到敌方兵营 800 以内**:五局全部以
  `economy_10min_cap` 在 ~640s 自终止,只掉了一塔。与 backlog 第 0a 条同一个语料缺口,
  已一并记进 `state.json:corpus_gap_no_base_assault_20260820`,并进 backlog。
* **`RetreatWhenTowerTargetedDesire` 域够但断言不了**:它的两个触发条件分别读
  `nEnemyTowers[1]:GetAttackTarget()` 与 `bot:GetEstimatedDamageToTarget(...)`,
  两者都不在 dump 里。顺带记一条**可疑但本轮不动**的:那条分支把
  `GetEstimatedDamageToTarget`(按 API 文档已是**对该目标**的估计)再喂给
  `botTarget:GetActualIncomingDamage(...)` ⇒ **减伤被算了两次**;
  全仓库 91 个 `GetEstimatedDamageToTarget` 调用点里**只有 2 处**这么写
  (本处与 `hero_dazzle:314`),其余 89 处直接和 `GetHealth()` 比 ⇒ 是**离群写法**不是惯例。
  方向是「更敢越塔」,与本项目已知的死亡问题相反,且无法在真实帧上验收 ⇒ **不动,只记账**。
