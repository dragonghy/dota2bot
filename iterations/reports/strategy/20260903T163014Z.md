## 2. 缺陷与改动

`bots/mode_farm_generic.lua` Think() 的 1s `_farm_repick_at` 心跳,`arbheart` 的释放分支:

```lua
preferedCamp = nil

```

它**从不调** `J.Site.UpdateAvailableCamp` —— 而那是出厂反抢营护栏(同文件 `:899`)走的退役路径。
⇒ 刚放掉的营**仍在 `J.Role['availableCampTable']` 里**,而一行之后的 fall-through
`elseif preferedCamp == nil then preferedCamp = ClosestCamp(bot, availableCamp)` 就在**同一张表**上挑。

改动(**无新 id、无新闸、无新 fixture**):

```lua
J.Role['availableCampTable'] =
    J.Site.UpdateAvailableCamp(bot, old, J.Role['availableCampTable'])
availableCamp = J.Role['availableCampTable']
preferedCamp = nil
old = nil
break
```

**没有**写成 `and J.IsSoakCandidate('slotarb')`:两个候选 id 的合取会在**任一方 promote 当天冻成 FALSE**
(`AGENTS.md` 的 `pullcad`),#456 的验收 1 也是这么建议的。

## 3. ⭐ 主判据(可复用,超出本主题)

> **一个修复的效果可以静默地取决于「另一个毫不相干的 id 有没有 armed」,
> 而我们为「id 之间的耦合」造的每一件工具,看的都是另一个形状。**

`AGENTS.md` 已经有 `pullcad`:**promote 一个 id 会冻死点名它的门**。
那一族里**依赖是写下来的**(写成一个合取项),失败在于 promote 把它删了。
**这里什么都没写下来**:

- `arbheart` **不点名**任何别的 id;
- 它的门是**干净的单一合取**(`IsModeTurbo() and IsSoakCandidate('arbheart')`);
- `check_armed_wiring.py` 说它 **WIRED**;
- `test_gated_helper_nesting_census.lua` 给这个函数的那一行读作 **(W)**,**而且读得对**。

依赖住在**数据**里:一行代码在一张表上留下一条记录,而**另一个毫不相干的 id 有没有 armed**,
决定了下游一个过滤器会不会把那条记录去掉。**没有一件工具会举手。**

⇒ **一般形式:当一个修复的机制是「别再做 X」时,读代码接下来拿这个修复刚改过的状态去做什么。**
`preferedCamp = nil` 不是「把这个营让出去」,是「再问一次」——**而提问的人读的是一张没人通知过的表**。

**顺带清掉的 trunk red(批测台 15:15Z 报告第 ⑩ 条交过来的那条)**:
`arbheart` 落地让 Think 的 outer-id 集合从 `campexit` 变成 `arbheart,campexit`,而钉住的行还写着 `campexit`。
**按手工读了再重钉**,结论 **(W)**,理由写进行内注释:
`J.IsCampSwitchSafe` 只从 `if old then` 那条 switch-to-nearer 臂到达,而 arm `arbheart` 正是把 `old` 置 nil 的那件事
⇒ **arbheart 真正开火的任何一 tick 上那条臂被跳过**,两臂互斥,单 arm `arbheart` 测的就是 `arbheart`,不是 `arbheart AND campdanger`。
**同时登记了确实存在、但方向相反的那个交互**:未 armed 的 `campdanger` 让 `J.IsCampSwitchSafe` 对每个营恒假
⇒ 出厂 switch-to-nearer 分支根本不会开,`arbheart` 的释放是心跳里**唯一**能移动 `preferedCamp` 的东西 ——
**未 armed 的 `campdanger` 让 `arbheart` 更可见,不是更不可见**;`campdanger` 入集或 promote 那天这一行要重读。

## 4. ⭐⭐ 兄弟测试当时在测一张空表,而本轮**只是因为停止打桩**才看见
