## 三、缺陷

`bots/FunLib/utils.lua`,`IsTeamPushingSecondTierOrHighGround`。出厂:

```lua
for _, playerdId in ipairs(GetTeamPlayers(bot:GetTeam())) do
    if IsHeroAlive(playerdId) then
        local teamMember = GetTeamMember(playerdId)   -- 域给 id,访问器要 slot
```

主判据与 §DI / §DJ **逐字相同**;**dire 只够到 slot 5 一个,radiant 够到 slot 1-4**。

**新增的一格(两个兄弟都没有):这个循环带一个守卫,而守卫问的不是它接下来要看的那个人。**
`IsHeroAlive(playerdId)` 问一个玩家,`GetTeamMember(playerdId)` 拿回**另一个**。
armed 之后 `i` ↔ `playerdId` ↔ slot `i` **按构造是同一个英雄**,守卫才真的守着它的对象
—— 所以这个修复**不需要另外改守卫那一行**。真实帧上量到:
**47 份带 `player_id` 的 fixture × 5 步 = 235 步,出厂配错 211 步。**

**失效方向朝「关」,这也是它为什么是协同组的杠杆**:七个调用点**全是 mode 欲望函数**
(`mode_ward` / `mode_rune` / `mode_outpost` / `mode_side_shop` / `mode_secret_shop` /
`mode_roshan` / `mode_laning`),每一个都用 TRUE 去 `return BOT_MODE_DESIRE_NONE`。
够不到队友只会让「本队在推」更难成立 ⇒ **出厂写法把 bot 从高地攻坚里拽去插眼 / 抢神符 /
回泉水买装**。条件 (c) 是标准打法(高地攻坚不分兵)。

## 四、改动(gated,暗态)

参数化 + 闸在**全仓唯一一处**解析:`bots/FunLib/jmz_func.lua` 新增一行包装

```lua
function J.IsTeamPushingHighGround( bot )

		J.IsModeTurbo() and J.IsSoakCandidate( 'slotpush' ) )
end
```

七个 mode 调用点改走它。**闸为什么不在 utils 里(这一条是结构性的,不是口味)**:
`typescript/bots/FunLib/utils.ts` 的文件头**自己规定**它不许 import 任何可能成环的东西,
而 `jmz_func` 第 35 行 `require` 了 utils ⇒ **utils 读不到闸**;
七个 mode 各自解析 = **七个漏掉闸的机会**。所以包装放在上一层,
和 `ClosestDustCarrier` / `ClosestCamp` 同一套纪律。

- 门关**逐字节等于出厂函数**(`[off-candidate equivalence]` 用转写的出厂函数体并排跑全语料 ×2 遍);
- **memo key 随 armed 分叉**(`.. "byslot"`),否则同一秒里先被调用的那条腿会替另一条回答;
  后缀**故意不叫 `slotpush`** —— utils 里不许出现候选 id(`[structure]` 钉住);
- `typescript/bots/FunLib/utils.ts` 同步(`[ts parity]` 钉住);`game/` 零 diff。

**落地时 `test_gated_helper_nesting_census.lua` 当场变红**,报出三对新「门中门」
(外层 `c3`/`outlatch`/`roshgate`,内层 `slotpush`)。按那份文件自己的 (P)/(A)/(I)
三分法**逐条读过**:三条都是 **(P) 参数闸** —— 包装未 armed 时把**出厂答案**交回去,
不是一个会冻住调用者分支的常量 ⇒ 单独 arm 外层 id 测的仍然是外层 id。已入册。
(七个调用点只有三个进册,是因为另外四个 mode 的同一个函数里没有别的门;
那是这份普查「宁宽勿窄」的网,不是本杠杆的性质。)
