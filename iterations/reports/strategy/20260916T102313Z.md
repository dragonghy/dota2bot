## 3. ⭐⭐ 本轮杠杆:`J.HasEnoughDPSForRoshan` 拿人均去撞全队的门槛

`bots/FunLib/jmz_func.lua`,**3 个活读者**都在 `bots/mode_roshan_generic.lua`
(`:132` 给 `initDPSFlag` 上闩、`:167` 是 `roshgate` 的实时复检、`:188` 是人数劣势支)。

```lua
for _, h in pairs(heroes) do
    local dps = attackDamage * attackSpeed * (1 - roshanArmor / (roshanArmor + 20))
    DPS = DPS + dps                      -- 一个累加器 ⇒ 出循环时是【全队】每秒伤害
end

DPS =  DPS / #heroes                     -- ← 出货的这一行:全队总量变【人均】

DPSThreshold = roshanHealth / plannedTimeToKill   -- 【全队】要达到的每秒伤害
return DPS >= DPSThreshold
```

两边本来同量纲、同主体,比较式**如所写即正确**。夹在中间的那一行把左边换成了
**人均**,右边不动 ⇒ **谓词问的是「平均每个队友能不能按时单杀 Roshan」**。

⭐ **为什么这是算术不是口味**:想要保守的作者会抬 `plannedTimeToKill` 或改血量模型
—— 那些**留在同一量纲里**。把比较式的一边除以人数,会让**门槛随着带去的人数一起涨**,
而且方向反了:**人带得越多,这个谓词越说 Roshan 难打。**

**改法(gated `roshdps`,turbo-only)**:除法**保留**,只是在它之前把全队总量存下来,
被比较的值默认仍是**除完的那个**,armed 时换成总量 —— 门后**只有一条赋值**。
⛔ **没动**:`plannedTimeToKill`、护甲模型、只算右键的伤害估计(法术与召唤物仍然不算)。

**方向**:`sum >= sum/n` 对 n≥1 当且仅当 `sum >= 0` ⇒ arming **只能把 NO 变成 YES**,
永不反向。⇒ **负读数不可能读成「杠杆让 bot 不去打盾了」**,唯一可读的是
**它新增的那几次打得不好**。n == 1 时两条腿是同一个表达式(单独钉了一格)。
