## 1. ⭐ 主判据(立法级,可复用,超出本主题)

> **一条 mock 默认值可以被「修好」成一台审查机,因为同一个文件里的两条默认值互相抵消,
> 而它们之间的修复顺序是承重的。**

`tests/mock/bot_api.lua` 按前缀作答:`^Is/Has/Can/Was -> false`,`^GetNearby -> {}`,
然后兜底 `^Get -> 0`。**最后那行不是一个默认值,是一句类型断言**——「凡我没被告知的
引擎 getter 都返回标量」。

`^Is -> false` 挡在 `^Get -> 0` 前面。**先修 `^Is` 那一半,不会浮出新读数,只会静默
删掉帧**(按 GH #492:两桶普查把抛错记成「量过了说不」)。先修 `^Get` 那一半做不到
这件事。⇒ **两次修复有序:`^Get` 在 `^Is` 之前。**

可操作的一半:**给一个 mock 补一条腿之前,先问「这条腿目前挡住了谁」** —— 如果它挡着
的是一处会抛错的消费,那么松开它**不是让读数变多,是让读数变少而且不吭声**。

## 2. 这句类型断言承载多大(量出来的)

109 fixture / **1012 活英雄帧**(与 §EF.1 / §EH 同一语料、同一分母),
**199,364 次真实单位上的 getter 探测**。

| 量 | 读数 |
|---|---|
| `bots/` 下 shipped 代码调用的不同 `Get*` 名字 | **197** |
| 其中**在全部 1012 帧上**都由 `^Get -> 0` 兜底回答的 | **166** |
| mock 已显式引开的(`GetLocation` / `GetIncomingTrackingProjectiles` / `GetActualIncomingDamage` / `^GetNearby` / `handle_getters`) | **5** |

⇒ **它承载的是 fixture 路线的大部分,不是它的一个角落。**

**为什么是探不是读源码**:名字会不会落到兜底,不是 `bot_api.lua` 一个文件的性质 ——
`replay_fixture.lua` 会按帧装 per-unit `__spec`,同一个名字可以在这个单位上由 .dem
回答、在下一个单位上由前缀规则回答。唯一诚实的读法是**在真帧上问真单位**。

## 3. 机制:那道 nil 守卫一次都没守住过

四处 shipped 代码写的是同三行(`jmz_func.lua:2170 / 2212 / 4457 / 10773`):

```lua
local nAbility = <unit>:GetCurrentActiveAbility()
if nAbility ~= nil
then
    ... nAbility:GetBehavior() ...
```

兜底答 **0**,而 **Lua 里 `0 ~= nil` 为真** ⇒ 守卫放行,下一行去索引一个数字。
今天不出事,**只是因为 `^Is -> false` 挡在前面**。

## 5. 「非标量」从 `bots/` 判,不从 API 文档判

`docs/BOT_API_REFERENCE.md` 带总监的出处横幅(GH #241):那里的一行**可以描述意图,
不可以推翻 shipped 代码**。所以三个名字都不按文档写的返回类型分类,而按 **shipped 树
自己怎么消费这个值**分类:

| 名字 | 树里的证据 |
|---|---|
| `GetVelocity` | `jmz_func.lua:12476` 取回,`:12488` 读 `v.x * v.x + v.y * v.y` |
| `GetCurrentActiveAbility` | 四处 nil 守卫之后 `nAbility:GetBehavior()` |
| `GetExtrapolatedLocation` | 当位置参数喂给 `J.GetLocationToLocationDistance`(2 处) |

**这三处消费点都作为 `[source]` 断言钉在用例里**,改写任何一处都会把本文件推红,
于是这份分类是**被重新推导**的,不是被继承的。
