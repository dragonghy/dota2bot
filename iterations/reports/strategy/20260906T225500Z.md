## 2. ⭐ 主判据:同一个函数的两条腿,对补给的态度是 10 比 0

`bots/mode_roam_generic.lua` 的 `ConsiderWaitInBaseToHeal` 是 **SHIPPED 且未 gated**
的回基地 TP 判据。它的条件是一个 `or` 的两条腿:

| 腿 | 触发 | 回复类 modifier 否决 |
|---|---|---|
| **HP 腿** | `J.GetHP(bot) < 0.25` | **10 个** — tango / flask / 化学狂暴 / 分身斧 / 战刃治疗 / **净化之焰** / **致命链接** / **撒旦** / 魂之灵瓮 / 灵龛 |
| **MANA 腿** | `J.GetMP(bot) < 0.25` | **0 个** |

HP 腿那份表**长得就像穷尽**——它连净化之焰、致命链接、撒旦都记得。所以缺的那一味
**不是「表短」**,是**另一条腿从来没有过这个问题**。

于是:**一个已经喝下净化药水的 bot —— 蓝正在到账、在野外、已经付过钱、而且是它
自己按的按钮 —— 仍然被读成「需要回基地补蓝」并 TP 走人。**

**⭐ 开火的正是这条腿,这是读数不是假设。** 1012 活体帧里该函数出厂答 TRUE 的
**6** 帧,**5 帧走 MANA 腿**(两桶相加 == 6,partition 是断言不是叙述)。
钉帧是其中之一,也是本语料对这个缺陷最干净的一句话:

> `tests/fixtures/f_260819_222559_od_eclipse_solo.lua`,**medusa:hp = 1.000
> (满血)、mp = 0.149、`modifier_clarity_potion` 正在跳** —— 出厂说回家。

路径上每一个合取项都是**帧自己的**,零操纵。

**⭐⭐ 施法路径这次是满的,而这正是上一轮拒绝灵龛的理由的反面。**
`urnself` 那轮拒绝把灵龛记进 `J.HasFieldRegenSource`,理由是「引擎的病人循环不返回
调用者 ⇒ **没有可用的施法路径**,数它就是把 bot 按在一个它永远不会喝的东西旁边」。
净化药水反过来:`X.ConsiderItemDesire["item_clarity"]` 在 `J.GetMP( bot ) < 0.4`、
周围无敌人时**自己喝**,**未 gated、每帧跑** ⇒ **modifier 挂着就意味着这个 bot
自己按过按钮**。

条件 (c) 的旁证是**数出来的**(不是打存在标志 —— 上一轮 M6 的教训):item 层
`not bot:HasModifier( "modifier_clarity_potion" )` 共 **3 处**('撤退:3' 与
'回复状态' 两条回城 TP 分支 + 一条不重复喝的自饮否决),`aba_buff` 的
`hero_is_healing` 也有它。

**落地**(在 `J.IsPushing` 那条之前追加,不插入):

```lua
and not (J.IsSoakCandidate('waitclar')
    and J.IsModeTurbo()
    and bot:HasModifier('modifier_clarity_potion'))
```

门是自己那个 `not (...)` 里的**第一个合取项** ⇒ 未 armed 时短路成 `not false` = true,
turbo 与引擎调用**都不求值**。方向**由构造固定**:往合取式上追加否决 ⇒ 只能把
TRUE 变 FALSE,**只能阻止回基地**,永远不可能把一个本来不回家的 bot 送回家。
Turbo **不是**结构性的(此路径上没有任何一处在它之上问过),所以**显式问**
—— 写「结构性」在这里会是假话。
