## 2. ⭐⭐ 结论:**头条不是那个 0,是那个 1**

上一轮(0NEXT11)测的是**走路腿** `stayfield2`:solo margin **19** → live **0**,19 帧全被
`fieldsip` 的量级条款拿走。**把那条读数顺推到 TP 腿,是错的,而这就是本文件的全部内容**:

> **走路腿是「有过域、被 `fieldsip` 拿走」;TP 腿是「从来没有过域」** ——
> 24 个 solo-S 帧里,**23 个被调用点自己的合取吃掉**(`fieldsip` 还没上场),
> 剩下的**那 1 帧**才轮到 `fieldsip` 收走。

📌 **可迁移的一句**:*「真串给这条 id 留了多少域」不是**每族**一个问题,是**每调用点**一个问题。
同一个谓词的两个 wrapper、同一条串、同一份语料,**域是被不同的东西拿走的**,
在任一条上取的读数**都不能迁到另一条**。走路腿的吸收方是一个兄弟 helper;
TP 腿的吸收方是它被丢进去的那条分支的二十几个合取。*

### 2.1 ⭐⭐ 而那 1 帧,就是 owner 优先项 P2 的铁证帧

`margin_solo` 的唯一那帧是 **`f_260822_063722_lina_tp_home` / lina** ——
`jmz_func.lua` 里 `J.ShouldRegenNotTpHome` 上方的注释**逐字描述的就是它**
(seed 888 夜魇,31.8% 血,最近敌人 6,596u,slot 0 faerie_fire,TP 回城落点距泉水 33u,
离场 20.3 秒),也就是 `OWNER_PRIORITIES.md` **P2 的铁证帧**。

真串上它被否掉,而否它的是**算术,不是判断**:

```
J.FieldRegenSipValue(lina) = 85        (item_faerie_fire)
0.25 * GetMaxHealth        = 0.25 * 1088 = 272
85 >= 272  ->  false  ->  IsFieldSipEnough false  ->  S false  ->  wrapper false
```

⇒ **今天的成员串上,`fieldsip` 否掉了 P2 这条优先项当初立案所依据的那一帧。**

⚠️ **本文不说 `fieldsip` 错了**。它在说「一个 faerie fire 救不回 31.8% 血的 lina」,
**这句话是对的**。没人说过的是另一句:**这两条 id 同时在串里,P2 在这条腿上就没有任何东西可买**。
一次正确的收紧可以把另一条 id 的最后一帧掏空;**「收紧是对的」不是「还剩什么」的答案**
(与上一轮的转移条款同形,换了个方向:那里是转移,这里是收紧)。

### 2.2 剩下的 2 个 live-S 帧从来不归这条腿

`live_S` 的两帧 —— `f_071859_qop_salve`/qop 与 `f_260819_222559_od_eclipse_pair`/juggernaut ——
`s_live_blocked_by_branch = 2/2`,两帧都是 **`branch_vetoes_itemFlask`**:
`撤退:3` 自己就带着 `itemFlask == nil`,而这两帧主槽里**有大药**。
⇒ **有没有 `fieldsip`,它们都不是这条腿的域**。这是那个 0 的闭式那一半。

### 2.3 为什么不落杠杆

- **收窄一个空域什么都不动**(0NEXT12 正文把出口 (b) 写成合法产出正是为此)。
- 唯一能把那 1 帧要回来的改动是**动 `fieldsip` 的量级门限**(`FIELD_SIP_MIN_FRACTION` 或
  `FIELD_SIP_HEAL`),而 `jmz_func.lua:6132 / 6203 / 6897` 三处**已经写明**:
  在 `J.IsFieldRegenSituation` / 量级条款里动门限会**同时移动 `stayfield`、`stayfield2`、
  `fieldbuy` 三条** —— **那是 `lanefix` 捆绑的形状**,账单是 gpm **−74.5 / −88.7**。
  ⇒ **不动。** 这是处置问题,归总监。
- **没有为了 4.4 配额造杠杆。**
