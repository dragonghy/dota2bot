## 1. 缺陷:相隔十一行,只有一条分支问距离 —— 而没问的那条读的是更宽的环

`bots/mode_laning_generic.lua` 的核心对线 `Think` 里:

```lua
-- last-hit(~476):读 800 的环,动手前测两次距离
nEnemyCreeps = bot:GetNearbyLaneCreeps(800, true)
if GetUnitToUnitDistance(bot, hitCreep) > botAttackRange
or (moveToCreep and GetUnitToUnitDistance(bot, hitCreep) > botAttackRange * 0.8) then
    bot:Action_MoveToUnit(hitCreep)          -- 够不着就走过去,而不是原地挥空

-- deny(~493,十一行之后):读 1200 的环,一个距离项都没有
nAllyCreeps  = bot:GetNearbyLaneCreeps(1200, false)
local denyCreep = GetBestDenyCreep(nAllyCreeps)
if J.IsValid(denyCreep) then
    bot:Action_AttackUnit(denyCreep, true)   -- 距离?没有。
    return
end
```

选择器 `GetBestDenyCreep` 只过滤血量(`J.GetHP(creep) < 0.49` 且
`creep:GetHealth() <= attackDamage`),**整条路径不读任何位置**。
⇒ **环(1200)是 deny 唯一的界**,而近战射程 150、远程 400–700
——**全游戏没有任何英雄的攻击距离到 1200**。这不是边角情形:它是这条分支的
**整个域,减去一个半径 `GetAttackRange()` 的圆盘**。

### ⭐⭐ 为什么值一个 id(两条代价,第二条才是决定性的)

1. 对 1100u 外的单位发 `Action_AttackUnit` 是**一条带攻击结尾的走位命令**。而 deny
   候选按构造就是**正在挨打的兵** —— 在兵线中段,朝敌方那一侧。300 移速走 1000u ≈ **3.3 秒**,
   远长于一只 <49% 血、正在挨打的兵的存活时间。**deny 到不了,位置先丢了。**
   (条件 (c):标准对线理论里 deny 的窗口是**对一只已经在射程内的兵的一次攻击**;
   把兵追下去 deny 不是一种打法。)
2. ⭐ **这条分支 `return`,而且它排在 deep-front 夹子上面。** 同一个 Think 下面的兵线站位块
   最后一句是 `J.IsLaneFrontTooDeepToHold(bot, target_loc)` —— mega-bundle 复盘专为
   「不许一个人守被推深的兵线」加的守卫(051728 ogre 在 +4217 处死于此)。
   ⇒ **deny 分支走的每一帧,都是那个夹子没被问过的一帧。**
   够不着的 deny 因此不只是浪费一个动作:它是这个 Think 里**唯一一条把 bot 往兵线深处带、
   同时跳过反过伸守卫**的路。这一条源码顺序由 `[ratchet]` 钉住,不是散文。

## 2. 修复:没有引入任何新常数

`bots/FunLib/jmz_func.lua`:

```lua
function J.ShouldDropOutOfReachDeny( bot, hCreep )
	if not J.IsSoakCandidate( 'denyreach' ) then return false end
	if not J.IsModeTurbo() then return false end
	if bot == nil or not J.IsValid( hCreep ) then return false end
	return GetUnitToUnitDistance( bot, hCreep ) > bot:GetAttackRange()
end
```

- **界是 `bot:GetAttackRange()`、算符是 `>`,两者都逐字取自十一行上面那条姊妹分支** ——
  文件自己已经出货的「我从这儿够不够得着这只兵」。**自造的常数是第二件要辩护的东西**
  (GH #788 / #793 / #811 三轮的学费),这里一件都没造。
- 谓词**重读**射程而不信 `botAttackRange` upvalue:后者在 `GetDesire` 里写,
  而 `GetDesire` 提前 return(死亡/无敌/幻象)时它**留着上一帧的值** —— 两个里更旧的那个。
- **方向由构造固定**:调用点追加 `and not ...` 到一个**已经通过**的合取式上,armed 只能把
  TRUE 变 FALSE,**永远不能**把 bot 送向一只它本来没在打的兵。被 drop 的帧**落到下面的
  站位块**,也就是**落到 §1 (2) 的 deep-front 夹子上**。
- **gate 第一句、turbo 第二句**:未 armed 时连一个引擎调用都到不了,出货答案逐字节不变。
  **单 id,不是两个 id 的合取**(`pullcad` 陷阱,GH #622)。

### ⛔ 一个 id,一个调用点 —— support 那条**故意不接**

那个文件里有**两条**无距离项的 deny 分支:核心 Think(~493)与
`DoSupportLaningThink` 的第一支(~356)。**本轮只接核心那条。**

理由不是整洁,是**可归因**:核心 Think **每个 gate 全关时也可达**
(`bCustomLastHit` 的 `local_mode_laning_generic` / pos1+人类 pos5 两个析取项),
support 那条只在 `suplh` / `lanefix` / `lf_support` 下可达。一个 id 跨两个**不同 armed 人群**
的调用点会让 per-id 裁定不可归因 —— 正是 GH #29 重排撤退守卫链要消掉的那个非独立性。

support 站点由测试断言它**仍然没接**(变异台 M5 专打这条),所以**这句话不会悄悄过期**
——它是 GH #767 §6.2「`tparrive` 那条腿故意不动」的同一处理。
