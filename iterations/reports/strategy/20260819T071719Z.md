## 1. 为什么不选路径 1(让锚点真正驱动移动)

路径 1 在本仓库**没有安全接缝**,这是本次的新证据(总监的裁定书里没有这一条):

- `bots/mode_retreat_generic.lua` **只定义 `GetDesire()`,没有 `Think()`**。
  Valve bot API 里,mode 脚本不定义 `Think()` 时,该 mode 的**全部行为由引擎内置
  实现**接管——回泉水路径、TP 回家、传送到 shrine、逃生道具/技能的使用都在引擎那边。
  所以"站在锚点上 hold"不是加一行 `Action_MoveToLocation`,而是要为**整个撤退
  mode 重写 Think**,把引擎那套安全网全部自己实现一遍。
- 而 mode-Think 替换正是 A1 机制分析(`l1xpsoak_MECHANISM_20260731`)判定
  `l1xpsoak` **−50 gpm 的主因**:"the solo −50 is MOSTLY the last remaining
  laning-Think replacement wiring"。零触发英雄反而是最大输家——因为 Think 替换
  连**不触发**的帧也把引擎行为换掉了。撤退 mode 是最安全攸关的 mode,在它身上重犯
  同一个错误,预期损失比 `l1xpsoak` 那次只大不小。
- 另一个可能的家 `mode_laning_generic` 的 Think 替换,就是已经被判死刑的原设计
  (144711 medusa 被追 17s 打死、tp_cd=0 全程没用)。

结论:路径 1 的成本不是"改一个消费点",而是"给撤退 mode 写一套完整的 Think",
且历史证据表明这类改动的期望收益为负。**放弃路径 1。**

## 2. 路径 2 的细化:不改默认,挂新 gate

总监原话是"把退出滞回收进 lanesurv 内部参数",并指出那样"就变成对一个已 promote
默认规则的修改,走的是另一条验收路径"。本组接受方向,但**不接受直接改默认值**:

直接改 `J.ShouldRetreatLaneBurst` 的默认行为 = 在所有 turbo 对局里对所有 bot
**静默**放宽一条撤退规则的退出条件,没有 A/B 可言,也没法归因。所以滞回落在
**新 soak id `lanehyst`** 上:未 armed 时 shipped 判定逐字节不变,armed 时它是一个
可单独测量的杠杆。这符合铁律 3 的版本模型(稳定版 = 所有 gate 关闭的默认行为)。

### 改动本体(`bots/FunLib/jmz_func.lua`,`J.ShouldRetreatLaneBurst`)

- 每个判定为 true 的帧写一次 `bot.laneBurstLastFire = DotaTime()`(纯字段写,
  未 armed 时**没有任何读取方**);
- 基础门槛没过时,若 `lanehyst` armed,则在 **`J.nLaneBurstHysteresisWindow = 2.0` 秒**
  内继续返回 true,前提是:**没有 peel 队友到位** 且 **incoming 仍 ≥ 当前血量的
  `J.nLaneBurstHysteresisFloor = 0.40`**;
- "1100 内敌人清零"走的是更早的 early-out,释放得比滞回更快(威胁真没了就立刻恢复对线)。

### 为什么这条改动有理论依据(验证哲学条件 (c))

`GetEstimatedDamageToTarget(bCurrentlyAvailable=true)` 是**会闪烁**的量:一个技能转好
CD、敌人跨出 1100 二十个单位、蓝量跳一格,相邻两帧的判定就会翻转。撤退 mode 在一帧
赢下 desire 竞价、下一帧输掉,结果是**下了移动指令又取消**——既没在撤退也没在对线。
对阈值附近的二值控制信号加滞回(Schmitt trigger)是标准做法;本仓库在 `l1kite` 路径上
已经用过同一味药(`bot.laneKiteUntil` kite-lock,起因是观察到 181046 CK 反复抖动)。

### 为什么它不会变成"停车刹车"

**刻意做成有时间上限的**,这是与 `l1xpsoak` 那版滞回的关键区别:后者只在状态变化时
释放,理论上可以一直 hold。2.0 秒足够抹平一次闪烁,不足以变成 force-passivity——
那正是 `lf_recover` / `corefarm` / `l1xpsoak` wave 1 被拒的失败模式。
