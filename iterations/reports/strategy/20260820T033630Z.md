## 1. 头号发现:又一条没人声明过的世界断言

```lua

        local info = GetHeroLastSeenInfo( id )     -- ← bot_api: 恒 {}
```

- `tests/mock/bot_api.lua:278` 把 `GetHeroLastSeenInfo` 桩成 `{}`;

## 2. 缺陷:闸门比较的是同一个查询的两份拷贝

`typescript/bots/FunLib/aba_defend.ts:901` 作者自己的注释是 **"a small don't-walk-through-fire guard"**:

```lua
local pathEnemies = jmz.GetLastSeenEnemiesNearLoc(botLocation, 1600)   -- 缓存 500ms
...
if bot:WasRecentlyDamagedByAnyHero(5) and #pathEnemies > #ds.nInRangeEnemy then
    bot:Action_MoveToLocation(向泉水方向 700 + 抖动 120)
    return
end
```

写下来的意思是「**路上**的敌人比**射程内**的多 ⇒ 退一步」。但**两边是同一个查询**:

```lua
ds.nInRangeEnemy = jmz.GetLastSeenEnemiesNearLoc( bot:GetLocation(), 1600 )
```

区别只有**时间**:

- 左边是**同一个查询**按 500ms 分桶缓存在 bot 句柄上;
- 右边写在 `GetDefendDesireHelper` 的**最底部**,下方还有 **7 条提前 return**。其中一条
  ```lua
  if #closeEnemiesDefend > 0 and #closeAlliesDefend >= #closeEnemiesDefend then
      return math.min(0.3, BotModeDesire.Moderate)
  end
  ```
  的触发条件恰好就是 `DefendThink` 会跑的那种帧 —— **900 码内正在打架**。而 `bot._defend` **从不复位**。

所以打架期间右边**冻结在开打之前的值**;若从来没有一次调用走到底部,它就是**初始空表(0)**。**这条比较只可能被「新旧不同」买到,永远不可能被真正的「路况 vs 射程」差别买到** —— 而它一旦为真,就 `return`,把这一帧其余所有 `DefendThink` 分支全部作废。

**家族**:总监 §0b。最近的亲戚是 `roamstale`(状态字段写在提前 return 的出价分支之下,被 `Think` 第一个读)。**亚型是新的**:这里陈旧的不是一个句柄而是一个**计数**,而且它是**和自己的另一份拷贝**比大小 —— 分支写下来的语义**根本无法表达**,不只是指错了目标。

## 4. 域有多大(实测,而不是猜)

三局录像里,「**5 秒内被英雄打过 + 距自家建筑 1600 内 + 1600 内至少一个敌人**」的英雄-帧共 **1437** 个。抽 45 帧驱动真代码:

- 闸门**条件为真**:**32/45(71%)**,其中 **27** 是因为 `nInRangeEnemy` 仍是 0;
- **但 defend 赢下脚本竞价只有 1/45**(就是钉住的那帧)—— 因为一个正在挨打的 bot,`mode_retreat_generic` 通常出价 0.5–1.0,压过 defend;
- 另取 **70 帧随机样本**:defend 赢 26 次,但**没有一次闸门为真**。

**结论要写实**:这是一条**真实的、已发布未 gated 的错误决定**,但**实测足迹很窄**。而且这是**下界** —— 引擎自带 mode 没有脚本 `GetDesire`(GH #27),它们的竞价拿不到。
