## 1. 机制:`GetActiveMode` 结构上不在 fixture 里

`bot:GetActiveMode()` 是 **bot VM 自己的状态**(这一帧哪个 mode 赢下竞价),
不是实体属性 ⇒ 不在 `.dem` 流里 ⇒ 任何 fixture 都不带 ⇒ mock 落到通用回退
`default_for('Get*') = 0`(`tests/mock/bot_api.lua`)。
而 `bots/` 里每一个 `BOT_MODE_*` 名字都走自动常量元表,解析成 **≥1001 的互异 id**。

⇒ **`x:GetActiveMode() == BOT_MODE_任何东西` 在每一个英雄、每一帧、24 个 mode 名、
210 个已发布比较行上,全部恒 FALSE。**(全部已成断言,含 `BOT_MODE_NONE`:
loader 答的 0 正是引擎里 "no mode" 的数值,而 mock 的 `BOT_MODE_NONE` 是 auto-id
⇒ 连「诚实读法」也对不上,两种读法**同向失败**。)

全档实测(94 fixture / 188 团队帧 / **872 英雄帧**):

| 量 | 实测 |
|---|---|
| `GetActiveMode() ~= 0` 的英雄帧 | **0 / 872** |
| `J.IsRetreating` / `IsGoingOnSomeone` / `IsDefending` / `IsPushing` / `IsLaning` / `IsDoingRoshan` / `IsShopping` / `IsFarming` | **各 0 / 872** |
| `J.GetSpecialModeAllies(member, 1400, ATTACK)` 非空 | **0 次** |
| `J.GetProperTarget` 非 nil | **0 / 872** |

最后一行是**第二个独立原因**,单独钉住:`J.IsFarming` 有一条看起来活着的析取支
(proper target 是中立小兵),它**不是这条缺口的幸存者** —— 语料只有英雄和建筑,
没有中立单位。将来 loader 就算学会了 mode,这条谓词仍然不会 fire。

## 4. 一条**不是** harness 假象的读数(记账,不动手)

`GetTeamFightLocation` 拿 `Vector(0,0)` 当空答案,而 **35 个消费方全部只测 `~= nil`**。
在游戏里这条路也够得着,因为两个半径不一致:
`J.IsInTeamFight(member, **1500**)`(引擎口径,**不含自己**)成立,
而 `J.GetSpecialModeAllies(member, **1400**, ATTACK)`(**含自己**)可以为空 ——
两个 ATTACK 队友落在 1400–1500 的壳里、member 自己不在 ATTACK 模式,就是这种情形:
**35 个读者同时收到「团战在河道中心」**。

这条**本 harness 判不了**(要 GetActiveMode),所以它是**候选杠杆 + 前置条件**
(要一次游戏内观察或一份 labelled synthetic),**不是本轮提出的改动**。
源码形状已钉:`GetCenterOfUnits(allyList)` 与 return 之间**没有空表检查**、
两个半径分别是 1500/1400 —— 任何一边动了都会红。
