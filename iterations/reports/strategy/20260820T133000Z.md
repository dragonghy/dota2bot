## 1. 头号产出:第十一条没人声明过的世界断言,并且已修

**`.dem` 的战斗日志只认名字,不认实体。** 快照流带 `idx`,所以 `make_fixture.py`

于是 `observed.burst`(每个 fixture 头部都写着「damage each enemy hero **ACTUALLY**
dealt to the subject」)里**混着打在本体复制品身上的伤害**;`recent_damage` 反向

## 2. 本轮的缺陷本体(GH #68 的条件 (a) 站不住)

### 2.1 「post-laning」不是一个时钟

`tpdying` 的立论(代码注释 + GH #35)是:*`J.ShouldRetreatLaneBurst` 在对线期外
结构性 return false,而这个 floor 钉住的帧压倒性是 post-laning ⇒ 预判半边是死的*。
这把 `J.IsInLaningPhase` 当成时钟读。**它不是。** turbo 下它是

```
t < 8*60                                     -> 对线期
t < 10*60 且 GetBot():GetNetWorth() < 8000   -> 仍然对线期
```

⇒ **8:00–10:00 之间,答案取决于响应者自己的钱包**。九分钟时净值不到 8000
是**常态**,不是例外。

### 2.2 三帧实测(全部来自 #68 读的那波 10:11Z)

| 帧 | 净值 | `IsInLaningPhase` | `ShouldRetreatLaneBurst` | armed `tpdying` 的差别 |
|---|---|---|---|---|
| `20260820_103644` t=492.4 necrolyte | 3997 | **true** | **true** | **逐位相同**(defend 0.1 / retreat 0.75 两侧一致,驱动真 mode 文件) |
| `20260820_102645` t=556.5 crystal_maiden | 3068 | **true** | false | **逐位相同**(pin 仍是 0.85) |
| `20260820_102030` t=639.5 tidehunter | 4380 | false | false | 前提在这里**成立** |

第一帧上 **shipped 的释放自己就把 pin 放掉了**,`tpdying` 是纯 no-op。

### 2.3 对 GH #68 §1.1 的直接影响

#68 用**排除法**给 `tpdying` 判了条件 (a) 成立,排除预判半边的那一步写的是
「t=556 > 480(turbo 对线地板)⇒ `ShouldRetreatLaneBurst` 结构性 return false」。
**在那一帧上它不成立**:净值 3068 < 8000 且 t < 600 ⇒ 对线期为 **true**,
shipped 那一半是**活的**,没有被排除掉。

独立的第二条:在**唯一可离线观察的替身**(实伤)下,`tpdying` 的判据在那一帧
**读 false**(bristleback 377u + earthshaker 520u 其后 3s 实伤 **261**,血池 **504**),
armed 之后 pin **仍然是 0.85**,真 mode 文件的出价逐位不变。
GROUND TRUTH 记下但**不当论据**:那个 CM `died_after = 39.0`,活下来了。

⇒ **条件 (a) 未成立**。**不要再为它买 (a) 语料**(总监 13:00Z 的排期里已经把
「本波买 `tpdying` 的 (a)」作废成「已经买到了」——**它没买到**)。

### 2.4 诚实的边界

我**不能**证明 in-engine 的 `IsIncomingBurstLethal` 当时返回什么:
`GetEstimatedDamageToTarget` 不在 `.dem` 里(#27 同族),loader 拿实伤当替身,
而这个替身**忽略 `bCurrentlyAvailable` 参数**——恰恰就是 #68 §2.3 指认的机制
(爆发花掉之后估计塌陷)。已写成 `[limitation]` 用例。
**能被我settle 的是对线期那段算术,它一个估计量都不涉及。**

## 3. 负结果:#68 §5.1 的阈值解耦在本地验证不了

§5.1 提议把比较基准从「当帧血量」解耦(例如 `burst >= HP - 0.40*maxHP`)。
在 #68 自己点名的两帧上,这个改动**与 shipped 分不开**:

* necro 帧:严格比较**本来就通过**(1080 ≥ 965),更松的当然也通过 ⇒ 无差别;
* tide 帧:**根本没有可归属的 burst**(§1 的污染)⇒ 任何阈值都无从行使。

所以**本轮不交新 gate**。要动这个 id 的阈值,先要一份**带引擎估计量的语料**。
这与 backlog 里 `RetreatWhenTowerTargetedDesire` 是同一种「域有帧但断言不了」。

**也没有把 `tpdying` 提出集**:它的域在 10:00 之后(以及富有的响应者身上)
是真的,而且它顺手**去掉了「生存释放依赖响应者自己的钱包」这件事** ——
同一场团战里两个落地者、同样血量、同样敌人,因为一个更有钱而拿到不同的释放。
这是同一个缺陷更锋利的说法:**这个 id 设计是对的,立论是错的**。本轮只把立论
改对(注释 + `state.json`),行为一位没动。
