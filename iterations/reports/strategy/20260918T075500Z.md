## 二、缺陷

```lua
function J.GetClosestAlly(bot, nRadius)
	for i = 1, #GetTeamPlayers( GetTeam() ) do
		local member = GetTeamMember(i)
		if member ~= nil and member:IsAlive() and member ~= bot
		and GetUnitToUnitDistance(bot, member) <= nRadius
		and not J.IsSuspiciousIllusion(member)
		then
			return member          -- ⛔ 第一个,不是最近的
		end
	end
	return nil
end
```

花名册顺序是**选人的顺序(player slot),不是世界的顺序** ⇒ 这个函数回答的是
「**一个**符合条件的队友」,而**是哪一个由调用方看不见的东西决定**。

⭐ **名字之所以在这里比平常更要紧:调用方不是「读一下」这个结果,而是以它为锚。**
唯一的生产调用点 `bots/mode_team_roam_generic.lua:506`(`ConsiderHelpAlly`)之后
**四件事全挂在这个锚上**:

1. 血量闸 `J.GetHP(bot) >= J.GetHP(nClosestAlly)`;
2. 射程闸 `J.IsInRange(bot, nClosestAlly, 1600)`;
3. parity 数的**那个点**(`J.GetAlliesNearLoc(nClosestAlly:GetLocation(), …)`);
4. 最后提交的那个敌人 —— 正在打**这个锚**的那个。

⇒ **一次任意的挑选同时决定了问题、证据和目标**;而真正被打死的那个队友在 250u 外
**根本没有被考虑过**,只因为某个 player slot 更小的人也在 3500 圈里。

⭐ **不是只有名字这么读**:调用点的变量就叫 `nClosestAlly`;仓库自己的
`tests/test_roamreach_bounded_chase.lua:270` 逐字断言
`assert(J.GetClosestAlly(bot, 3500) == cent, 'the closest ally within 3500 is the Centaur')`
—— 那句散文写的是 **closest**,它为真**只因为那个 fixture 里第一个恰好就是最近的**。

## 三、⭐⭐ 本轮买到的可迁移句(全队)

**一个函数的名字可以是它唯一的规格说明,而当调用方拿它当锚而不是拿它当读数时,
名字错了就不是「命名问题」—— 问题、证据和目标会一起跟着错,
⛔ 而三者一起错的样子和「这个分支本来就该这么判」一模一样。**

📌 **判据**:看到一个 `GetClosestX` / `GetBestX` / `GetWeakestX`,**先读它的循环体有没有
比较,再读调用方拿它干什么**。只要调用方在它后面接的是**一串关于它的谓词**
(而不是把它放进一个集合里),那么选错了谁 = 整条分支讲错了故事,
**而那条分支的每一个断言都仍然自洽**。

⚠️ 本轮的第二句,关于**怎么找到这种函数**:`J.GetClosestAlly` 的生产调用点**只有一个**,
所以它从来没有被第二个读者复核过。⭐ **「只有一个调用点」平时是安全论证
(本轮正是靠它才敢把闸开在函数内部),但它同时也是「没人复核过」的同义词** ——
同一个事实在两个方向上都成立,而只有一个方向会被写进注释。
