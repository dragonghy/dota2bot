## 1. ⭐⭐ 头条:一个对**敌方全队**成立的存在量词,被写成只问**名单前三格**

`bots/mode_farm_generic.lua` 的 `X.IsUnitAroundLocation`(:1124,本轮之前):

```lua
for i, id in pairs(GetTeamPlayers(GetOpposingTeam())) do
    if IsHeroAlive(id) and i <= 3 then
```

它**唯一**的调用点是 :303 的基地告警:

```lua
if X.IsUnitAroundLocation(GetAncient(GetTeam()):GetLocation(), 3000)
then return BOT_MODE_DESIRE_NONE; end
```

即「上一秒内有敌人被看见在**自家遗迹** 3000u 内 ⇒ 别打钱」。

⇒ **名单第 4、5 格的敌人可以站在遗迹上,任意距离、任意新鲜度,这个告警按构造是 FALSE。**

⛔ **引擎里比任何 fixture 更糟,而且是反直觉的那一侧**:`GetTeamPlayers` 报的是
**全部五个 id,死人也在内**,而 `i <= 3` 数的是**名单格**不是活人 ⇒
**前三格三个死队友就把配额吃光**,活着的那两个在遗迹上砸,告警一个人都没看。

### 这不是「按 0NEXT21 的判据找到的」,比那更便宜 —— 它**已经被写下来过了**

`bots/FunLib/jmz_func.lua:9292`,`campdanger` 那一轮的抬头里,**逐字**:

> `J.GetLastSeenEnemiesNearLoc` … carries no `i <= 3` cap, unlike
> mode_farm_generic's own `X.IsUnitAroundLocation`, **which would have asked only
> the first three enemy players**.

**这条发现至今只被写在一条注释里。** 章程第 1 步那句自我批评(「章程文本的缺陷
只登记不改,下一轮原样复发」)对**代码缺陷**同样成立,而这是一例实测。

### 📌 本轮买到的可迁移句(0NEXT21 判据的下一层)

> **「登记」不是「修好」,而一条被登记在别的文件的注释里的缺陷,连**谁该修**都没有。**
> `i <= 3` 被看见时,看见它的人正在写另一个 id 的抬头,于是它变成那条抬头的**论据**
> (「我这个 helper 没有那个毛病」)而不是**工作项**。**一条缺陷被用来论证别的东西之后,
> 它在所有队列里的存在感反而下降了** —— 因为它现在读起来像已经被处理过。
> ⇒ **判据**:读到一条注释拿另一个文件的缺陷当对照时,**立刻去数那个缺陷有没有 id**;
> 没有 id 的对照物就是下一轮的选题,而且它的证据已经有人替你写好了。

### ⭐ 修法:armed 形态不是我发明的,**树里早就出货了**

`bots/mode_rune_generic.lua:676` 是**同名、同体、没有这个 cap** 的同一个函数
(`for _, id in pairs(...)` / `if IsHeroAlive(id) then`)。
⇒ 本轮**零新政策、零新常数**:armed 的农场副本**就是** rune 副本,逐项相同。

落地(**一个 token**):

```lua
local bWholeRoster = J.IsModeTurbo() and J.IsSoakCandidate('siegecap')
for i, id in pairs(GetTeamPlayers(GetOpposingTeam())) do
    if IsHeroAlive(id) and (bWholeRoster or i <= 3) then
```

- **unarmed** = `false or i <= 3`,**就是出货的那个合取项**;
- **armed** 仍然**先**求值 1-3 格 ⇒ armed 的 TRUE 集是出货 TRUE 集的**严格超集**;
- 唯一的调用点把 TRUE 变成 `return BOT_MODE_DESIRE_NONE`
  ⇒ **arming 只能增加「基地有人时拒绝打钱」,永远不会发出出货代码扣住的打钱出价**。
