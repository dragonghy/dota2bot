## 0. 一句话

```
GetGameMode() == GAMEMODE_TURBO   ->  TRUE   96/96 fixture
GetGameMode() == 23               ->  FALSE  96/96 fixture
```

引擎里这两个写法是同一个数(`GAMEMODE_TURBO` 就是 23),`bots/` 里甚至自带补丁
(`if GAMEMODE_TURBO == nil then GAMEMODE_TURBO = 23 end`,两个文件各一条)。
**所以这不是 `bots/` 的缺陷,是 fixture 世界的缺陷**,而且是 mock「帮忙」帮出来的:

1. `tests/mock/bot_api.lua` 把每一个没见过的 ALL_CAPS 全局自动解析成 1001 起的哨兵整数,
   于是 `GAMEMODE_TURBO` = **1149**;**并且因为它从此永不为 nil,`bots/` 自带的那条补丁
   永远不会执行**;
2. `tests/mock/replay_fixture.lua:487` 用 **名字** 声明这个世界是 Turbo:
   `GetGameMode = function() return GAMEMODE_TURBO end` —— 于是它返回同一个哨兵。

两者彼此自洽、共同与 23 不符。**凡是按名字拼的已发布行读到「turbo」,凡是按字面量 23 拼的
读到「不是 turbo」。** 六个文件、九处比较站在错的一边,而且这条裂缝**穿过一个表达式的中间**
(`FunLib/aba_push.lua:171-172`)和**一个表构造式的中间**(同文件 `gameStateCache`:
`currentTime` 按数字造,`isEarlyGame/isMidGame/isLateGame/isLaningPhase` 四个兄弟按名字造)。

## 2. 交给 GH #84 §5 的东西:`228` 退役,并且更正 (甲) 分类表对它的判读

(甲) 把 `item_purchase_generic:228`(`bot:GetLevel() >= 18`)判为 **TEETH**,理由是
「门关着 ⇒ `:272` 的留买活钱整局死代码」。**在 Turbo 里,关着它的不是那个等级常数。**

那道门在 `GeneralPurchase()`(192-363)里面,而这个函数**只有一个调用点**,在 1276 行:

```lua
if GetGameMode() == 23
then
    TurboModeGeneralPurchase()
else
    GeneralPurchase()
end
```

**真实 Turbo 局走的是另一条腿**,整个函数一次都不跑 —— 连同 `t3AlreadyDamaged` 的
**四次写、两次读**(全部在函数体内,已成断言:函数外 0 次)和 272 行的
`cost = itemCost + GetBuybackCost() + GetNetWorth()/40 - 300`。
而 `TurboModeGeneralPurchase()`(366-437)**自己没有任何买活留钱**(逐行断言:
函数体内 `GetBuybackCost` 与 `t3AlreadyDamaged` 各 0 次)。

⇒ **Turbo 的物品采购里根本不存在买活留钱**,原因在等级常数**上面 1048 行**。
把 `>= 18` 调低或删掉,在我们优化的那个模式里**什么都不会变**。

**三条 TEETH 因三个互不相同的原因退役**:

| 站点 | 卡点 | 能不能买 |
|---|---|---|
| `mode_farm_generic:285` | **dumper 缺口**(mode 不在 `.dem`) | 买不到(13:48Z 已撤回) |
| `mode_farm_generic:535` | **语料缺口**(`ShouldRun` 是当帧纯函数) | **能买,请求活的**(#84 §4) |
| `item_purchase_generic:228` | **在 Turbo 里根本不跑** | 没什么可买的,分支本身是错的那条 |

**剩下的活候选是 `ability_item_usage_generic:5749`**(守遗迹 TP,5 项 AND 的另外四项都是活的
Turbo 状态)。建议 §5 下一轮取它。

**顺带**:「Turbo 该不该留买活钱」是一个**真的策略问题**(Turbo 买活便宜、CD 短),
但它是**另一个杠杆**,本轮只记账,不动。

### M4 翻出一个事实错误(本轮最值钱的方法学产出)

本文件第一稿把那 21 次对线出价变化**记在 `FunLib/override_generic/mode_laning_generic.lua:31`
头上**。M4 变异它 ⇒ **只有源码钉子红,一条行为断言都没动**。查下去:那个 override
**只对 `Utils.BuggyHeroesDueToValveTooLazy` 里的英雄 `dofile`**
(`mode_laning_generic.lua:30`),**语料骑的是 `bots/mode_laning_generic.lua:156` 那一份**
(膨胀在 156,阶梯在 242-244,同一个 `GetDesire()` 里)。M4b 变异真正那一份 ⇒ 4 红,含行为断言。
**已更正,并把「哪一份是活的」连同那条加载条件一起钉成断言** —— 因为将来如果那个条件放宽,
语料就会改骑另一份。

### M16:全套跑把我自己的泄漏抓出来了(第二条方法学产出)

第一次跑全套时中间出现一个 `F`。原因是本文件的**诚实探针泄漏**:`GAMEMODE_TURBO` 是普通全局,
`tests/run_tests.lua` 是**一个进程按字母序跑完所有 `test_*.lua`**,而我的 `world(path, true)`
在最后一次调用后把 `GAMEMODE_TURBO = 23` 留在原地 ⇒ **本文件之后的每一个测试文件都在诚实世界里跑**,
也就是把本文件量出来的「21 帧对线出价、18 帧竞价赢家」的位移,**静悄悄地施加到别人写的断言上**。

**这正是本文件在讲的那件事,由本文件亲手犯了一次。** 已修(`unprobe()`,每次 `bid()` 与
每次探针块之后都还原),并且**把「后继者继承到什么」写成断言**(`[premise] the probe does not
follow this file into the next one`)—— 而不是靠注释提醒自己记得清理。

⇒ **给全组补第二条做法**:**凡是用 rawset 全局做探针的用例,必须有一条断言描述「本文件跑完之后
世界是什么样」。** 单文件跑永远发现不了这类问题,全套跑发现了也只会给你一个 `F` 和一个不相干的文件名。

⇒ **给全组补一条做法**:**「变异只让源码钉子变红、行为断言全不动」是一个信号,不是一次通过。**
它多半意味着你钉的那个站点不是语料实际经过的那个站点。上一轮记的两条空断言形状
(M4「断言读的是自己的桩」、M7「重述了常数却没钉常数」)是**测试自己的毛病**;
这一条是**世界模型的毛病**,更值钱也更难看见。本轮 M9 恰好又是上一轮 M7 那个形状的复发,
说明那条规则要当检查项跑,不能当经验记。
