## 缺陷(算术事实,静态可核对)

`bots/mode_team_roam_generic.lua:_divecap_CapForLanePush` 里那行注释写的是
`-- soft ceiling`,代码实现的却是一个**悬崖**:

```lua
if desire > 0.9 then return 0.72 end  -- soft ceiling
```

只有 `> 0.9` 的出价被砍,而且砍到 **0.72 —— 低于整个 (0.72, 0.9] 区间**,后者
原样放行。仍走这条路的四个分支出价全是
`RemapValClamped(J.GetHP(bot), 0, 0.5|0.6, BOT_MODE_DESIRE_NONE, 0.98)`:

| 分支 | gate | 膝点 |
|---|---|---|
| `X.ConsiderHelpWhenCoreIsTargeted` | **无(已发布默认)** | 0.5 |
| `ConsiderHelpAlly` | **无(已发布默认)** | 0.6 |
| `J.ShouldPunishDive` | `punish` | 0.5 |
| `J.ShouldPunishOverchase` | **`overchase`(在 armed 集内)** | 0.5 |

于是**有效出价对血量非单调,峰值在 ~46% 血**:

| 血量 | 原始出价 | 过 cap 之后 | vs 已 promote 的 `lanesurv` 撤退 (0.75) |
|---|---|---|---|
| 100% | 0.98 | **0.72** | 输 |
| 46% | 0.90 | **0.90** | **赢** |
| 43% | 0.843 | **0.843** | **赢** |
| 36% | 0.71 | 0.71 | 输 |

**最没资格打这一架的那个人,是唯一能在欲望竞价里压过撤退、从而被钉在架子里的人。**
而且和 lane-kill 两条分支不同,这四条**都没有** `J.ShouldReleaseLaneCommit`
自释放闸 —— 这正是 wave13 卷宗里写死过的形状(「旧的 0.95 出价压过已 promote 的
lanesurv 撤退 (0.75),把 bot 钉进输掉的换血里」)。

这是 #31 / #29 同一族缺陷的**第三例**:作者在注释里推理的相对出价顺序,被一个
下游变换悄悄摧毁。

## 改动(gated `capmono`,turbo-only,一个杠杆)

在既有的 `if J.IsInLaningPhase() or J.IsPushing(hBot)` 块里,armed 时把悬崖换成
真天花板:

```lua
if J.IsModeTurbo() and J.IsSoakCandidate('capmono') then
    if desire > 0.72 then return 0.72 end
    return desire
end
if desire > 0.9 then return 0.72 end  -- soft ceiling(未 armed 时逐字不变)
```

**只动「悬崖 → 天花板」这一件事,天花板的值 0.72 不动。**

为什么这条和还关着的 `divecap` 可以分开:`divecap` 是**解除**对线期 collapse 的
限制,被刻意留暗的理由是「可能导致过度投入」;`capmono` 的 armed 路径是**纯
min**,只可能**降低**出价,结构上不可能造成过度投入。

## 依据 (c)

1. **仓库内部先例**:总监 09:04Z 对 `l1trade`/`l5combo` 修的就是同一个反常形状
   (他自己的注释里原话:"with the perverse side effect of being non-monotonic in
   HP");wave13 卷宗把「压过 lanesurv 的出价 + 无自释放」实锤为钉死送命的成因。
2. **标准策略**:对一场团战的投入度应当**随生存能力上升**,不可能下降。一个
   43% 血的辅助比满血的自己更愿意扑上去,在任何 Dota 交战模型下都是反的。
   有效出价对血量单调,是**形状性质**,不是调参口味。

## 本地验证(真实帧,`tests/test_capmono_ceiling.lua`,12 例)

锚定帧 **`f_222428_lion_lich_burst`**:Lion 354/823 = **43.0% 血**,t=314.0,
Lich 660u、Axe 800u 压着他,2200 内无队友。录像 ground truth:**Lich 打出 436
伤害,Lion 6.9 秒后死亡。**

这一帧的两个前提是**断言出来的、不是假设的**:
- `J.IsInLaningPhase()` 为真(t=314 < turbo 的 480s 地板)→ cap 在这一帧真的生效;
- `J.ShouldRetreatLaneBurst(bot)` 为真 → 已 promote 的 `lanesurv` 在这一帧真的
  出 0.75 —— 否则「压过撤退」就无从谈起。

12 例覆盖:
- 真实帧 43% 血 → 有效出价 **0.843 > 0.75**(缺陷本体,就在杀死他的那一帧);
- **同一帧**把血量改成满血 → **0.72 < 0.75**(反常倒置,而且恰好跨过撤退出价:
  只有垂死的那个赢);
- armed → 0.72 < 0.75,撤退赢回这一帧;
- **21 点血量扫描驱动真的全局 `GetDesire()`**(只强制了触发器
  `J.ShouldPunishOverchase` 返回该帧真实的 Lich 句柄;出价算术、分支、cap、
  对线期判定全是真代码跑真世界):armed 单调;
- 反向断言:**未 armed 时扫描必须仍然非单调** —— 悬崖哪天被别人改掉,这条测试会
  自己失败提醒 `capmono` 已过期,而不是无声地「通过」;
- 已发布行为围栏:0.98/0.95/0.90/0.84/0.60 五点逐一对上旧语义;armed 路径永不
  抬高任何出价;#31 的 lane-kill 豁免仍然优先;只在对线/推进期生效;turbo-only。
