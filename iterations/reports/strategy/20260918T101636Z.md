## 二、缺陷:第三份拷贝,以及它为什么看起来做完了

`bots/mode_team_roam_generic.lua:1704` 的 `X.IsAllysTarget(unit)`:

```lua
local allies = bot:GetNearbyHeroes(1000,false,BOT_MODE_NONE);
if #allies < 2 then return false end;
for _,ally in pairs(allies) do
    if ally ~= bot and not ally:IsIllusion()
       and ( ally:GetTarget() == unit or ally:GetAttackTarget() == unit ) then
```

这张表以**我**为心、**从不装我**。两行之内它被按「装着我」读了两次:`#allies < 2` 只有在我是
其中一个条目时才是「这里除了我没别人」;循环又花一个词在 `ally ~= bot` 上排一个不可能存在的
条目。⇒ **闸的意思不是「就我一个」,是「最多一个队友」**,它在循环读到之前就把那一个队友的
占用扔掉了。

### ⭐⭐ 本轮买到的可迁移句(它管的是【这条缺陷有人看过了】那一格)

**一个函数可以被点名分诊、被写进棘轮、并且每一行理由都为真,而分诊回答的是关于它的另一个问题;
⛔ 于是这一行分诊读起来就是一个已处理的函数 —— 它比没人看过更难被第二次看见。**

现场三件事同时为真:
1. `soloclaim` 的头注把 **`J.IsAllysTarget`**(半径 800)当判别子,那句话为真且仍钉着;
2. 同一轮的 `tests/test_ring_subject_census.py` **逐字带着 `X.IsAllysTarget` 的行**,
   理由是「16/16 调用点传的是小兵/野怪/塔,语料 0 个非英雄单位」;
3. 那个理由定价的是**圈的主语**(以发问者为心)—— soloclaim 头注明确停在那里的「第二个、
   更大的」缺陷。**闸在那一行里一个字都没有。**

⇒ 两份产物合起来回答了关于这个函数的所有问题,**唯独漏掉隔壁刚刚被回答过的那一个**。
这是 0NEXT42 那句话的更硬形态:第二个站点**被读过**,而「被读过」正是它看起来做完了的原因。

📌 **判据**:修好一条信念之后,不要只问「还有谁长这样」,要问
**「谁的名字已经在某张棘轮表里了、而那张表定价的是哪一个缺陷」** —— 已登记 ≠ 已处理,
而两者在阅读时长得一模一样。

## 三、修法(一次一个小杠杆)

函数体**逐字**搬进 `bots/FunLib/jmz_func.lua` 的 `J.IsRoamAllysTarget( unit )`,闸上开 gate:

```lua
	if #hAllyList < 2
		and not ( J.IsModeTurbo() and J.IsSoakCandidate( 'claimlone' ) )
	then
		return false
	end
```

**为什么搬家**:`X` 是文件局部表,fixture 测试够不到它,而 gate-plumbing 测试不算本地验证
(铁律/章程第 2 条)。mode 文件只剩一行委托,**五个调用点一个没动**;disarmed 与原体逐字同值
(同一张裸引擎表、同一半径 1000、同样四个词、同样两个引擎 getter)。
先例:`helpself` 抽出 `J.GetHelpParityAllyCount`、`helpnear` 把闸开在 `J.GetClosestAlly` 内部。

**不碰**:圈(仍以发问者为心)、半径 1000(改成 800 就变成 soloclaim 修过的那个函数)、
占用判据(两个引擎 getter,不是 `J.GetProperTarget`)、幻象词、任何调用点。
`ally ~= bot` 这个**死词故意留着** —— 它是同一个假信念的另一半,删掉等于抹掉信念存在过的证据
(测试与变异台 M5 各钉一次)。

**方向由源码定死,不靠语料**:闸是 armed 唯一移除的东西,它上方的循环只有 `return true` 或
落到闸本来就会给的同一个 `return false`。⇒ `0` 个队友两侧都 false;`1` 个 shipped false、
armed 可能 true;`>= 2` 闸本来没响、逐字相同。**armed 只能 FALSE→TRUE**;五个消费者全部在
`not` 下把 TRUE 读成「别人已经占了这只兵,让开」⇒ **纯收窄抢刀**,不是放宽。
