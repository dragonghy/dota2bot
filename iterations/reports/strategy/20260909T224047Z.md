## 4. 读数(115 fixtures / **1021** live frames,两条独立的路)

⛔ **先说量具**:这个 helper 的第三个合取项要求 500u 内有敌方兵线,而
**这份语料一帧兵都没有** —— `ow_creeps_zero` **1021** == `ow_live` **1021**
(**测出来的,不是引用的**;`J.IsLaneZonedByEnemy` 的抬头从另一端记过同一件事)。
所以所有**驱动**读数都在一个**声明过的注入**下取得:**在 bot 自己脚下放一只兵**。
这个注入**被 helper 自己的前提界住**,不是编的:任何能通过该合取项的兵线名单都在
bot 的 500u 内,其形心因而也在 500u 内,而 bot 自己的位置正是那个球的**球心**
—— 这是 deepnum 的 vLoc 约定,**外加一个 deepnum 没有的半径界**。
仍然定不了价的是「与 (bot → 我方泉水) 不一致的车道轴」= 未买到的 GH #648/#652;
**§4 最后一行是唯一不依赖轴的读数**。

| 列 | 值 | 说明 |
|---|---|---|
| `ow_live` / `ow_creeps_zero` | 1021 / **1021** | 量具事实 |
| `ow_hp_ok` / `ow_peel_supp` / `ow_target` | 853 / 118 / 288 | helper 自己的合取项,按它的顺序 |
| `ow_reach` | **166** | 语料能回答的合取项全过 |
| `ow_band` == `ow_side_pop_differs` | **39** / 39 | (800,1200] 带内有敌人的帧 = 宽盘人口更多的帧 |
| `ow_side_flips` / `ow_side_same` | **4** / 162 | 侧别真的翻了的帧 |
| `ow_drive_nonnil` / `matches_wide` / `matches_narrow` | 166 / **166** / **162** | **两条独立的路**:驱动 = 宽普查算术,且 162 = 166 − 4 |

GH #648/#652 到位之前,这是唯一**不会被车道轴约定推翻**的读数。

## 5. ⚠️ 代价:**登记,不辩护**

宽普查会让新落点**离正在被戳的那个英雄更近**:`ow_flip_nearer_someone` **4 = 全部 4 帧**,
其中 **2** 帧新落点进了某个敌人的 400u 内(`ow_flip_close400_wide` **2** vs
`_narrow` **0**)。这一列是**唯一一个反对本改动的数字**,所以它被钉住了(变异体 **M11**
把这一列剪掉必须被抓)。

**为什么仍然认为改对了**:poke 名单里**只有一个人**时(对线常态),旧尺子退化成
**「从我正要攻击的那个英雄身边走开」** —— 四个证人在旧规则下离**自己的目标**
**863 / 895 / 922 / 701 u**,即**撤出了骚扰射程**,而这条分支的全部目的是
「让**下一帧**能在无兵仇的位置继续骚扰」。⇒ 旧规则是**反自己意图**的。

⛔ **本轮没有回答、并作为下一格登记的问题**:侧别选定后,**没有任何一处检查落点是否
落进 poke 目标的攻击射程**。这个 helper 从来没问过,本轮**也没有加**(一次一个杠杆),
`GetAttackRange()` 投影本来也是未买到的语料请求(GH #656/#657)。
