## 2. 结论:#250 §4 的第一步在离线仪器上买不到

### 2.1 读数(105 fixtures / 974 alive hero frames,turbo 强制 true + `pullcamp` armed)

| 计数 | 值 |
|---|---|
| `ShouldPullNeutralCamp` 非 nil | **0** |
| 返回 nil | 956 |
| **抛异常** | **18** |
| 其中异常文本点名 `GetLaneFrontLocation` | **18 / 18** |
| `chain_new`(逐条子句算出来的「走到均势子句」的帧集) | **18** |

**`spnc_raise == chain_new == 18` 是同一个合取的两种独立算法**:一边是把子句一条条写出来数,
一边是直接调 shipped helper 接它抛的东西。两者逐位相同 ⇒ 归因不是推测。

### 2.2 ⭐ 主判据(可复用,本轮真正的产出)

> **一条谓词被提议当验收步骤之前,先问它在「将要用来读它的那台仪器」上的值域。
> 已知在那台仪器上是常数的谓词不是测量;而一旦给它挂上二分支解读,
> 仪器就从「回答的东西」变成了「下结论的东西」。**

这是本文件 §1 那套 STOPPER 普查的**配方侧孪生**:那一侧说「语料看不见什么」,
这一侧说「因此不许拿它问什么」。失效方向是**贵的那一种** —— 一条真实归因被以仪器
理由撤回,并且**被报成「测量过了」**。

### 2.3 为什么是常数 —— 归因,不是断言

**不是**(只是)§1 STOPPER 2 的 `GetNeutralSpawners` 桩:**选营循环根本没跑到**。
每一帧要么更早被子句挡掉,要么在**均势子句**上撞 GH #61 的 loader 拒绝
(`GetLaneFrontLocation is unresolved`)。所以要在 fixture 上问 #250 第 1 步,
需要**两处 declaration**(一个分路世界 + 一张营地表),而按本文件 §2 自己的标签,
那就是 **DECLARED-WORLD 测试**:它能演练子句,**不能见证那一帧发生了什么**。

⚠️ 顺带更正一处沿用了 5 天的措辞:§1 STOPPER 2 的注释把「camp-reach loop therefore
selects nothing」当成拒绝原因。今天的读数说更强的话:**那个循环一次都没执行过**。
未改 §1 的断言(它的零仍然为真),只在新增的 §4 里把归因写对。
